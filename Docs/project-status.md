**Items answer back when they are used (THR-719, 2026-07-25).** The last dead half of the item substrate is closed. `attachmentTriggers.ts` was a complete, tested on-use resolver with **zero production importers** — a sword whose tooltip said it snapped on a critical failure had never once snapped. Per the user verdict it was **deleted, not adopted** (wiring it would have built a second resolution path beside `effects[]`); on-use behavior is now the production-wired `action_trigger` primitive, extended four ways: outcome-band events (`encounter_critical_success`/`_at_cost`/`_critical_failure`) mapped from the six-band ladder by `ladderEventsFor` — **widening, not partitioning**, so shipped coarse-band content keeps its exact prior behavior; a seeded `probability` guard rolled *after* every cheap eligibility gate so ineligible triggers never perturb the stream; three item-behavior payload kinds derived from what content actually uses (`condition_grant`, `condition_remove`, `self_remove` — the plan had guessed `possession_grant`/`relationship_delta`, which no entry used, and missed `condition_remove`, which two do); and `narrativeTemplate` prose that reaches the player as an aftermath change. All nine authored `onUseTriggers` blocks ported verbatim across both catalogs; the field, its three types, the resolver and its suite are gone, and the tooltip/detail-view read path now shows what actually fires. **A latent bug caught in the port:** `decayConditions` counts down `ticksRemaining`, not the `durationTicks` that `apply_condition` writes — granting on the wrong field would have minted conditions that never expire, the same silent-death class the ticket exists to end. Contract `attachment-on-use-triggers` 🔴 LEAKED → 🟢 LIVE with both-side symbol evidence. Live seeded CLI: an Amber Phial firing organically — *"The golden sap burns going down, but the Forren's wounds close like flowers at dusk."*

**The reaper stopped eating node_modules (THR-753, 2026-07-25).** The hourly host git reaper's `git worktree remove --force` (and orphan `rm -rf`) followed a worktree's `node_modules` junction into the home tree's one real install and emptied it — the 2026-07-22 ×2 wipes and #203/#207. **Your castings can land crooked (THR-728, 2026-07-25).** A player cast auto-succeeded before any capability, difficulty or shaper was consulted, so the Divine Receipt (THR-727) could only ever report a foregone conclusion — and the authored difficulties on **84 of 138** ascendant-castable templates were computed and thrown away. Casts now roll the same sigmoid→d100 ladder mortals do, with a **safety floor** (user verdict, chat 2026-07-24): a losing roll is caught at `success_at_cost`, so the working always lands but the world can charge for the holding; `setback`/`catastrophe` stay unreachable by construction, and the upside (clean, surge) stays fully earned. Zero-difficulty templates — every `divine.*` soul-verb, the `invest.*` signatures, observation — remain guaranteed as a thematic statement. Push and resist stay mortal. **The plan's one grey zone turned out to be the whole feature:** `computeCapability(graph, ascendantId, reach)` returns **0.018** for every god, because the ascendant node carries `domainAffinities` (2–5, a reach *ranking* weight) and never `domainCapabilities` (10–40, the raw scale the sigmoid consumes) — read literally, 94% of casts land on one band (400-seed measurement), which would have shipped a *flatter* receipt than the auto-success it replaced. The player path now maps affinity onto the raw scale (`ascendantCastRawBonus` → new `computeCapabilityWithRawBonus`), deliberately **not** folded into `computeRawScore` so THR-613's Deepening tier-crossings keep the score they were tuned against (pinned by a test). Live seeded world, real shipped templates: `hex.survey` 66% strained / 25% clean / 7% fortunate / 2% surge, `hex.corrupt_land` 79/14/6/1, `divine.coincidence` 300/300 success, zero hard failures anywhere. UI: one prose risk line on the focused card (*"A perilous working."* — steady/uncertain/perilous, never a percentage); guaranteed cards keep an unchanged face. Rulebook §4 + three wiki pages updated in the same PR. One flag (`PLAYER_CAST_VARIANCE_ENABLED`) reverts the whole thing.
