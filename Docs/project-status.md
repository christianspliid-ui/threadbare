- **Ambition-Driven Strategic Actions — Merchant Proving Slice:** Enabled feature gate, fixed two blocking bugs (strategicState accumulation in phaseAgentDecision, `domainCapability` → `domainCapabilities` property typo), and verified end-to-end with CLI seed 42. Merchants with `ambition_dominate_trade` now generate strategic candidates (survey market, build warehouse, establish trade routes, found guild chapters, maintain monopoly), compete against encounter candidates on the unified decision board, execute graph mutations (sublocations, trade route edges, intelligence properties), and record history. 29 tests across 4 files. Commit: `8706a8db`.
- **Ambition-Driven Strategic Actions Implementation Plan:** Turned the approved strategy-layer design into a concrete implementation sequence. Plan: `Docs/plans/2026-04-09-ambition-driven-strategic-actions-implementation-plan.md`.
- **Ambition-Driven Strategic Actions Design:** Wrote the superseding design for proactive world-shaping agent behavior beside encounters. Design: `Docs/plans/2026-04-09-ambition-driven-strategic-actions-design.md`.
- **Encounter Activity Visibility Fix:** Threaded agents now keep a durable latest-decision snapshot instead of losing their pool link when older telemetry scrolls out of the recent-event buffer. Threads rows now show typed encounter badges even while the agent is still traveling toward the chosen encounter, and HexMap activity markers now use the small silhouette icon set at regional zoom instead of hidden late-zoom reach dots. The encounter-pool modal now supports both the raw ranked chooser order and a grouped template summary, plus a dominance readout for the top priorities, so you can debug both “what will they actually pick?” and “how repetitive is this pool?” from the same surface.
- **Promoted NPC Portrait + HexMap Visibility Fix:** Newly promoted NPCs now get a deterministic `narrativeArchetype` as part of graduation, which restores portrait resolution anywhere that relies on archetype art instead of a bespoke meeting portrait. The HexMap actor adapter also now treats `notable` individuals as map-visible (while still hiding ambient NPCs and army commanders already represented by army signifiers), so promoted NPCs no longer disappear between roster prose and the world map.
- **Legacy Encounter Auto + Threaded NPC Activation:** Legacy threaded encounters now default to auto-resolve instead of surprise popup mode, and GameView only auto-opens true pause-mode notifications. The thread detail activity line now appends the real number of viable encounters the agent chose from, because selected decisions emit the same funnel counts that idle telemetry already carried. Newly threaded ambient/notable individual NPCs are also hydrated up to spotlight as soon as a thread edge is created, so they can actually enter the autonomous encounter loop.
- **Threads Sidebar Hotfix:** Restored the Threads area after the encounter-pool UI slice. `getThreadedNodes()` was still calling a missing portrait resolver for individual actors, which threw during threaded-node aggregation and left only the World Pulse visible. The hotfix switches that branch back to the same shared fail-soft portrait helper used elsewhere in the retinue path, and focused retinue + thread-panel tests now cover the repaired path directly.
- **Threads Encounter Pool Inspection:** Threaded agent rows now surface their latest live encounter pool at a glance with compact `Pool viable / cached` counts, and that pool count is now clickable: it opens a modal with the agent's current ranked encounter list in priority order, highlights the chosen entry, and shows the same live metadata the chooser used (reach pair, encounter type, threat, steps, tick cost, reward, and movement heading when relevant). This makes low-variety deserts and non-moving agents visible in the same Threads workflow you already use instead of requiring DebugPanel spelunking.
- **Encounter Reference Page Sync:** The public `encounters-agents-reference.html` page now matches the live encounter runtime instead of an older design snapshot. It documents the real Phase 2b chooser (static + dynamic candidate merge, awareness/visibility/prerequisite/outgrowth/diversity stages, cooldown/exhaustion filtering, deterministic utility scoring, idle reasons, and forced travel), notes that the threat stage exists but is currently disabled by tuning, and updates the resolution chapter to the shared resolver inputs plus doubles-based crits.
- **Encounter Balance Telemetry Slice:** Encounter runs now record structured decision-funnel telemetry for selected, idle, and forced-travel outcomes, including idle reasons, filter-stage counts, template rollups, location-subtype rollups, and threaded-agent context. The CLI gained `balance idle` and `balance templates`, the debug bridge can export encounter decision summaries directly, and a seeded contract now proves a threaded hero can hit starvation and recover via forced travel. This makes content deserts and encounter dominance much easier to spot without hand-reading raw logs.
- **Meet The First Portrait Persistence Fix:** The First now keeps the authored meeting portrait after the bond is formed. The meeting flow persists `portraitAssetPath` onto the created agent node, and the hex map, retinue panel, and agent detail aggregators now prefer that explicit portrait before falling back to generic archetype art. This restores the circular portrait on HexMapV2 instead of dropping back to a plain dot.
- **Legacy Encounter Resolution Readout:** Legacy encounter scenes now expose the actual test math directly in the Encounter Veil during development. Active steps show the reach being tested, raw difficulty, capability, modifier total, threshold, and projected success odds; resolved steps preserve the rolled value, outcome tier, margin, and near-miss/crit annotations. The legacy engine now stores per-step resolution snapshots so the UI can surface what really happened instead of only the prose shell.
- **Threaded Agent Idle Fix:** Agents with condition-style reward traits that lack `domainContributions` no longer crash domain capability scoring during encounter awareness. The filter pipeline now keeps same-hex/threaded candidates alive instead of fail-softing into permanent `no_candidates_after_filter` idle loops, and regression tests cover both the raw capability scorer and full encounter filter pipeline.
- **Faction Network Visibility & Governance Pass:** Factions now surface as live institutions instead of debug-only metadata. The faction sheet shows leadership, member roster, reputation bars, dominant reaches/domain capabilities, halls, governing seats, controlled holdings, relations, agenda, and a network diagram. Character sheets and thread views now expose faction standing directly. The upkeep loop is less punishing too: slower reputation decay with inactivity grace, stronger upkeep/promotion urgency, reserved faction social slots, faction-linked NPC participation, local faction control over home holdings, and direct faction-targeted Ascendant actions from the faction sheet.
- **Objective Triangle Sync:** The three long-term objective systems now run as one shared loop. Doom chapters and The First's journey phases are synchronized, chapter five is reserved as a climax window, mandates are generated from ascendant remembrance spheres/court shape, and checkpoint results now feed future doom beats through doom debt and counter-omens. UI surfaces updated: top bar, Doom detail, and Mandate detail/tracker now show chapter pacing, journey state, sphere deltas, omen checkpoints, and resolved doom-card consequences. Design: `Docs/plans/2026-04-08-objective-triangle-sync-design.md`.
- **Terrain Texture Lab POC + Vignette Slice 1:** Standalone WebGL playground at `?view=terrain-lab` for experimenting with hex terrain materials outside the live game renderer. Separate Three.js scene + instanced shader preview, six starter recipes (grassland, forest, mountains, dunes, coast, swamp), live controls for noise/warp/banding/color plus perspective camera tilt/bearing/zoom, built-in and imported GLB placement on preview hexes, localStorage persistence, JSON export, and a scrollable left control rail whose cards keep their natural height when the widget stack exceeds viewport height. The first procedural vignette slice is now live in the lab too: slot-aware forest villages with hard-keepout center landmarks, soft-fill ring slots, dense free-fill deciduous tree scatter, clickable landmark targets, overlay debugging (slot anchors / zone rings / filler dots), and console helpers on `window.__TERRAIN_LAB`. The follow-on architecture is captured in `Docs/plans/2026-04-08-procedural-hex-vignettes.md`; the POC note is `Docs/plans/2026-04-08-terrain-texture-lab-poc.md`.
