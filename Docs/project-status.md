Recorded permanently in CLAUDE.md: **Vercel is not a required check and must not become one** — it is not a correctness gate, and promoting it would couple every merge to a third-party service. The fix for silence is a notification path, not a new gate.

**The reaper no longer reaps live sessions (THR-797, 2026-07-26).** The hourly `clean-stale-git.sh` judged a worktree's liveness by **git-admin-dir mtime only** — a signal that stops moving the moment a session finishes pushing, even though its closeout (Linear updates, doc appends, impediment logging) keeps writing files for hours. On 2026-07-26 it removed a still-live session's worktree; because `.claude/worktrees/<name>` sits **inside** the home tree's working copy, deleting the worktree's `.git` file left git discovery to walk *up*, and the session's next `git checkout -b` silently created and checked out that branch **in the home tree** with no error — `pwd` still read the worktree path while `git rev-parse --show-toplevel` had become the home tree. This is the first route in the THR-671/672 family where a live session can author commits onto `main`. **The ticket's stated cause was wrong and the fix it specified would not have worked** — its Done-when called for skipping worktrees merged within N minutes, on the premise that the `:40` run two minutes after the 03:38 merge did the damage. The reaper's own log says the 03:40 run never touched it and the 05:40/06:40/07:40 runs each logged `skipped worktree (live session)`; the removal fired at **08:40**, ~5h after the merge, once the admin mtimes finally aged past `WORKTREE_MIN_IDLE_MINUTES=180`. No sane merge-grace window covers a 5h gap. **The decisive evidence sat inside that single 08:40 run:** the removal `WARN` and a `skipped orphan dir (recent activity)` line name the **same path two lines apart** — the orphan sweep's filesystem probe knew the session was alive, and the worktree pass never asked it. So `is_live` now asks the same question, with the same threshold and semantics (pruning `node_modules`/`dist`/caches so dependency churn cannot masquerade as a session). Two smaller guards ride along: a `WORKTREE_MERGE_GRACE_MINUTES` (90) hold covering the narrower post-merge case the ticket hypothesised, kept as cheap defence-in-depth rather than as the fix; and the branch pass now keeps any branch whose **unregistered-but-still-active** worktree corpse is on disk, closing the second half of the THR-673 chain that deleted `claude/happy-swartz-826e7d` at 09:40 once the partial removal had stripped its `is_checked_out` protection. Verified by a fully neutered dry-run of the real script against the live 24-worktree tree (both live sessions correctly skipped, including this one) plus 8 unit assertions over the new helpers — the decisive one reproducing the incident shape exactly: stale `.git` + a fresh closeout write now reads **live**. Relocating `.claude/worktrees/` out from under the home tree, the other candidate fix, is **not available** — the CC harness owns that path.
