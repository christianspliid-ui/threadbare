**A guard that blocked the exact repair it was built to make safe (THR-880, 2026-07-31).** `.claude/hooks/worktree-write-guard.sh` stops a linked-worktree session from silently writing into the home tree — a real hazard that fired in 4 of 12 hourly runs. It decided "is this the home tree?" by **path prefix**, and the harness places `.claude/worktrees/` *inside* the home tree's working copy, so every sibling worktree's path begins with the home-tree path and was indistinguishable from the thing being guarded against. **The block was the smaller half; the printed remediation was the sharper one** — it suggested a `<session-wt>/.claude/worktrees/<other>/…` nesting that cannot exist, so an agent trusting it either wrote nowhere useful or concluded its untouched target *was* the home tree and opened a spurious #417 patch-and-relocate against a tree nobody had edited. Ownership now resolves against the **registered worktree list**, taking the *longest* matching root — the only rule that gets nesting right, since a sibling path matches both the home tree and its own root. Lexical on purpose: a `Write` may target a path that does not exist yet, so resolving the target's own directory with git is not always available; when the list cannot be read the guard **allows**, matching every other unresolvable branch in a file whose stated contract is fail-soft. **Same structural cause as THR-797** — prefix reasoning about tree identity is unsound for anything under `.claude/worktrees/`, and this was its second instance. The 9-test suite drives the real shipped script against a throwaway repo built with the actual harness geometry, and asserts **both** directions so the fix cannot degenerate into a blanket disable; falsified by reverting the script, which turns both THR-880 cases red while the THR-685 cases stay green. Verified live end-to-end besides: the exact impediment #317 payload now exits 0, and a genuine home-tree slip during this very session's closeout was blocked by the running hook with a remediation path that exists.

**A gate that refused nearly everything it was shown (THR-836, 2026-07-31).** `pull-work` Step 3 demanded three coordination lines — `Suggested model`, `Parallel-safe with`, `Mutex with` — on every candidate's latest comment, with no exemption. Both authors of that block were handoff-path only: the design-session handoff (retired with THR-654) and the orchestrator's T1 **promotion**. The executor files its own deferrals *directly* into `Ready for Dev`, bypassing T1 — so **those issues were born failing the gate**, and it produced one of two outcomes on nearly every pickup: a lost run, or a hand-written reversal re-derived from scratch each time (THR-834/THR-817 zero-comment; THR-804 claimed past it by hand; THR-778 bounced at 05:03 and re-offered at 06:03). The fix separates the two things the gate was conflating. **A block is an artifact of coordination between two parties**; a ticket the lane filed for itself, naming the file it means to change, was never coordinated by anyone, so demanding it is a category error. Step 3 now classifies before deciding: a **self-scoped** ticket (description names a repo path or a backticked file/symbol) is *claimed*, with the executor deriving and posting the three lines under a labelled heading; only an **unscoped** one bounces. **A bounce now also routes** — comment, move to `Todo`, continue to the next candidate in the same run — because refusing without removing from the queue is a spin loop wearing a gate's clothes, which is exactly what re-offered THR-778 hourly until a human moved it by hand. The writer side was closed in the same pass so the derivation is a fallback rather than the norm: CLAUDE.md's Definition of Done now requires the block as the **first comment** on any issue filed straight into `Ready for Dev`, and the orchestrator's rule was widened from "every promotion" to promotions *and* direct filings (its two-write create path produced zero-comment issues with no later step that would ever author one). The rule is **machine-checked, not prose-only**: `classifyCoordinationBlockGap` in `scripts/coordination-block-predicate.ts` is the single predicate both `check:process` and Step 3 cite, reporting `warn` for self-scoped and `error` for unscoped, with 16 tests pinning **both** directions — a predicate that only ever answered "self-scoped" would make the gate vacuous while every test still passed.

**A branch point that could not branch (THR-894, 2026-07-31).** `ActionStepBranch` selects its variant by a recorded `choiceId`, and the only thing that ever recorded one was the retired player-pick (`authoredChoices`) — so a branch authored *today* could only ever resolve down `fallback`, on every seed, forever. The fork existed in the type and nowhere in the world. This generalizes the one shipped personality-driven selector, Meet The First (THR-868), so the **mortal** decides in-encounter forks from who they are, leanable by the god's hand. A branch declares `decidedBy: { axis }` with variants keyed exactly `positive`/`negative`; at the deciding step the engine reads the mortal's **live** axis position (standing profile *plus* accumulated drift), adds the net `poleLean` of the cards the god actually committed, and records the pole through the **existing** choice-history path — so `resolveStepDefinition` reads it as an ordinary choice and no second branch-resolution route exists to drift out of sync. **Generalizing by copying the meeting's summing loop was the obvious move and the wrong one** — that is the `assignAmbitionToActor` failure (THR-885), two implementations of one rule that diverge the first time either is tuned — so the arithmetic was extracted to `encounters/poleLean.ts` and the meeting now *calls* it, its 49 tests green untouched. **The loop closes on drift:** the decided pole writes through `applyDriftMagnitude`, the same accumulator `phaseChoiceResolution` uses, so decay, threshold crossings and the `archetype_drift_register` reveal all see it with no parallel store — a mortal who keeps taking the cunning fork measurably becomes likelier to take it again. **Two decisions are recorded so they are not re-litigated:** the seeded coin is drawn *only* inside the neutral band (drawing it unconditionally would desynchronise two runs differing solely in how convinced a mortal was), and the meta pair `courage_prudence` has no canonical `${reach}_axis` id, so it keys drift on its own pair name — canonical readers simply do not find it, which keeps a *designed* authoring axis decidable rather than an edge case that refuses. **A card's lean counts only on its own axis**, and a deciding step dealing no card on the branch's axis **warns** rather than fails: legal (the mortal decides alone), but far more often it means a card names the wrong axis and abstains silently — the THR-844 shape. Variant keys are validated at build time for the same reason. **Zero content ships here** (THR-883 owns the first choice-designed encounters), so the interface-map row is badged **LEAKED** with its remediation ticket rather than LIVE: a green badge has to mean traffic, not intent (THR-614). Non-vacuous by falsification — the 23-test suite was re-run with the resolution call removed and 9 went red, the 14 that stayed green being the pure-arithmetic and validator tests that correctly do not depend on the wiring.

**Several ways in, one door (THR-898, 2026-07-31).** Direct follow-up to THR-894, which made a fork decidable by the mortal on **one axis, two poles**. That shape is wrong for a route-flavored objective: *The Broken Wheel* lets a mortal bribe the wainwright, intimidate him, or win him over — three courses toward the same door, and no single axis whose two ends are those arms. A branch may now declare `decidedBy: { routes: [...] }`, each route naming a `key`, the `reach` whose capability makes that course natural, and optionally an `axis` + `toward` it also speaks to. **The dominant term is competence, not conviction** — what makes a course someone's is being able to walk it, so capability in the route's reach (read through the *same* `computeCapability` resolution itself uses, not a parallel score) is weighted above axis standing and the god's cards, all four weights named constants. **`BranchDecision` became a union rather than a widened interface**, so a route decision cannot be read as if it had an axis; `isRouteDecision` is the one discriminator and the two modes never share a code path by accident. **The card lean generalized without a second summing loop** — `sumHandLean` and the new `sumRouteLean` are both projections of one `sumOverPlayedCards` helper, which is the THR-885 `assignAmbitionToActor` discipline applied before the divergence rather than after it. Route leans are **unsigned**, because a card arguing for "bribe" is not thereby arguing against "intimidate" — it says nothing about it — and a route-explicit card **abstains from every two-pole decision**, since a route key is not an axis and reading it as one would be the plausible-invisible-load-bearing failure the axis check exists to prevent. Determinism holds the same way: the seeded draw is taken only among leaders tied within `ROUTE_DECISION_TIE_EPSILON`, never on a decided fork. **A winning route that declares an axis drifts the mortal; a pure-competence route drifts nothing** — "they were good at this" is no claim about who someone is becoming. The unleanable warn is now **per route**, because a fork the god can argue for on two of three courses is exactly as steerable as it looks on two and silently unsteerable on the third. **A tuning fact worth recording, since it broke three of my own fixtures before it broke anyone's content:** capability runs through a sigmoid with midpoint 10, so raw scores above ~20 saturate — two routes at raw 30 and 24 differ by 0.003 capability, *inside* the tie band, which means a "clear leader" fixture is silently a coin flip. The authoring range where capability actually separates routes is raw ~4–16, and that is now stated in both the wiring guide and the manual. Falsification per THR-894's pattern: flip the capability ranking → a different route; add one committed card → it crosses; replay the seed → the same route, including in the tie band. Zero content ships here — THR-883 authors The Broken Wheel on top of this.

**A panel that repeated the same three scene facts every run (THR-892, 2026-07-30).** Implements the variance rule Christian approved on the THR-883 mockup review: *a factor line earns its place only if it could have read differently on another run*. A static authored line reads identically every firing, so it cannot inform a decision — it is priced into `difficulty` and belongs in the prose. The panel now **derives** what varies: the actor's capability in the step's reach, plus one line per named world modifier (equipment, terrain, faction, sphere, conditions, divine attention, rule overrides). **The load-bearing constraint was "one read path, never a parallel computation"** — a panel re-deriving its own numbers eventually disagrees with the roll and quotes a factor the roll never applied. So `computeResolutionModifiers` now emits a **named** `contributions` list from the *same* walk that produces its totals, and the lines are a pure projection of it; the three `compute*` functions sum the list they collect, with caps applied by trimming the overflowing tail so the emitted values sum to exactly the previously-returned number (all 30 pre-existing modifier tests pass untouched, both cap tests included). **Omens, doom stage and season derive nothing, and that is a finding rather than a gap** — `forecastAction` reads only `ResolutionInput.actionModifiers`, and no omen/doom/season read exists anywhere in the pipeline that fills it, so a line for them would name a cause the roll never applied; recorded N/A with the read path cited rather than faked. **`carryoverFactorLines` is the one authored factor that survives the rule**, keyed on the band the *previous* step rolled: step 0 never draws one, an unauthored band draws nothing, and a declared delta rides the existing `carryover:<outcome>` channel to both the panel floor and live resolution with **zero** new rng. Sentence templates ship as half-sentences (`'{actor} carries {source}.'`) rather than label/value pairs, which makes canon rule 1 structurally unviolatable instead of merely documented. Every line class carries a **falsification twin** — remove the source, the line must vanish — and the two THR-820 tests asserting the panel is *exactly* the authored set were correctly broken and rescoped. The carryover-forecast test asserts `forecastInput.actionModifiers` rather than the probability, because the capability-0 fixture sits on the 0.05 floor where a +0.1 modifier is absorbed: the floor is real behaviour, it just cannot witness the wiring.
