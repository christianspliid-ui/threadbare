**The merge queue's agent half is in, and the whole change is deliberately inert until one click (THR-946, 2026-08-02).** THR-735 decided merge queue as the structural fix for the `BEHIND` livelock — an armed green PR knocked stale by someone else's merge never merges on its own, and the sweep that drains them loses one merge per advance of `main`'s tip by construction. `ci.yml` now fires on `merge_group`, which is a **hard prerequisite of enabling the queue rather than an enhancement**: without it the required checks never report on a merge group and *every* queued PR stalls until timeout.
