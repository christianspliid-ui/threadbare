**Interface drift is now a checkable class.** THR-717 (2026-07-23) shipped the contract registry + downgrade-only liveness generator: 20 cross-system contracts carry design intent, grep-verifiable symbols, and a badge that can only be *downgraded* mechanically — 🟢 LIVE requires dated human verification, because a naive write+read symbol match would have re-badged both known leaks green. `prebuild` fails if any contract reads LEAKED without a remediation ticket. Design Step 0.7 + a `lint:plan-doc` nag make it binding on new plans; drift-scan S11 seeds one audit ticket/week against the 15 still-unaudited subsystems. Remediation backlog: THR-718…THR-723.

**Economy now answers the god (THR-725, 2026-07-23).** The four granted economic verbs moved prosperity in silence; `encounterScoring.ts` now carries an `economicContextBonus` term (boom/bust × family affinity, data-table-tunable) and `phaseProsperity` seeds themed scenes on any prosperity shock — cause-agnostic, so the verbs, battle aftermath, and future causes all get a story response. Both pre-seeded interface rows are 🟢 LIVE with run evidence. Player-loop link 4 closed.

**Player casts now have a consequence surface (THR-727, 2026-07-23).** A resolved player action finally shows the aftermath the engine already computed: a new `post-resolution` phase (`phasePlayerReceipts`) builds a Divine Receipt and tiers it — a band-accented completion toast for minor casts, a story+technical receipt dialogue (`DivineReceiptModal`) for multi-step / rare / world-shifting ones. Dispatch toasts switched from optimistic-success to initiation phrasing. Closes canon rule 6's missing link (player action → visible consequence → next decision). Outcome variance for player casts is deferred to THR-728.

**Wiki freshness is now a merge gate (THR-730, 2026-07-23).** The Design Reference Wiki freshness contract (THR-585) flipped from an advisory warning to a blocking step inside the required `Test · Typecheck · Build` check: a PR that changes a file matched by a wiki page's `sources` glob without updating the page (or its `payloads`) now fails, unless a commit body carries `Wiki-freshness-exempt: <reason>` (auditable escape hatch, mirrors `Browser-verify exempt:`). `weekly-project-hygiene` audits exemptions and sweeps for uncovered code (8-day lookback). Core-system docs can no longer silently drift.

**The world mints ambitions (THR-726, 2026-07-24).** Ambition assignment used to read only a mortal's own snapshot — a sacked hometown or blighted harvest wrote nothing into what anyone wanted. A minting pass now rides `ambitionTick`'s existing re-eval cadence: it scans graph-native `encounter_outcome` event nodes an agent suffered (`participated_in`) or witnessed (`occurred_at` at their hex), classifies them by tested Reach (`AMBITION_MINTING_RULES`, data), and feeds candidates through the **existing `selectAmbitions` funnel** — so a craven soul mints *flee* where a proud one mints *revenge* from the same ruin, capped at `MINT_MAX_PER_EVENT` per event. Six new funnel-gated `EVENT_MINTED_AMBITION_TEMPLATES` (revenge / protect / flee / rebuild / found / chase-wonder), self-predicate milestones only — `target_agent_eliminated` deliberately avoided (it auto-completes against an unbindable `$`-ref). Provenance rides the `pursues` edge (`mintedByEventId`/`mintedByLabel`); `motiveReceipt.resolveMintedAmbitionProvenance` names the origin so the receipt reads *"vengeance for the bloodshed at Ardenmor Keep."* Both pre-seeded interface rows 🟢 LIVE with run evidence. Live browser (tick 155, seeded): 7 organic mints, 2 receipts naming their origin event. Panel visibility rides THR-721 (knowledge-gated, separate ticket).

**Companies are travelling (THR-74, engine core, 2026-07-24).** The collective layer between lone agents and faction-scale armies now exists: `src/engine/groups/` + `phaseGroups` (Phase 2.34, between agent decision and movement) forms named companies from colocated compatible agents, agrees one shared heading, accrues and loses cohesion on named events, and disbands into persistent history. Zero new node types, edge types or GameState fields - a company is an `actor` node reusing `member_of`/`commanded_by`/`pursues`, with **no `located_at` of its own** (position derives from the leader). 72-tick smoke, seed 42 medium: three companies travelling, members colocated. Content and UI pillars ship as PRs 2 and 3 of the same ticket; `Fixes THR-74` rides the last one. **PR 2a (2026-07-24) made it matter:** `resolveGroupStep` had shipped as a producer with no call site (contract pinned `PARTIAL`), so companies travelled together but still resolved alone. The hook now lives in `resolveUncontestedStep` — the companion best suited to *that step's* Reach acts, the rest assist under a cap, and the action's owner stays the individual so nothing meets a positionless group node. Which encounters a company may take is a **predicate, not a list** (`groupEligibility.ts`, applied once at the registry derivation): swept family + ≥2 steps + ≥1 `iron`/`stone` step + no `heart`/`gold`/`star` step. A looser first cut promoted 127 including `pickpocket`; the tightened rule promotes **63** (encounter 44 / borderland 14 / monster 5). Contract now 🟢 LIVE. Authored content (Seeking Companions, The Parting, party-exclusive delves, the two UATs) remains PR 2b.
