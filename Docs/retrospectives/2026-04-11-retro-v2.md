## Meta-Analysis: How Did We Lose Test Coverage?

Five reinforcing failures combined to let the test suite rot for 8+ days without correction:

### 1. No automated gate — social conventions don't hold

The only enforcement of "npm test must pass" is a bullet point in CLAUDE.md. There is no GitHub Actions CI, no pre-push hook, no test step in the Vercel build command. The deploy pipeline is `vite build` — it checks compilation, not test health.

Social conventions work when the same person writes code and runs tests. In our setup, AI agents are task-focused — they optimize for completing the assigned feature, not for maintaining infrastructure they didn't break. A CLAUDE.md instruction is a suggestion; a red CI check is a wall.

### 2. Brittle count assertions created unnecessary breakage

`encounter-content.test.ts` asserts `expect(ENCOUNTER_TEMPLATES).toHaveLength(154)`. This is a hardcoded count that breaks every time content is added or removed. The test doesn't verify anything meaningful — the game won't break if the encounter count changes. Similar count assertions exist for unified-action rarities and TRACE_CATEGORIES.

These tests create noise that drowns out signal. When the suite is red because of a count mismatch, the agent's rational response is "that's not a real failure" — and from there it's a short step to ignoring the entire suite.

**Decision: Delete count-based assertions entirely.** Keep structural and quality assertions (every template has 2–4 steps, has valid encounterType, has narrative text, etc.). Don't replace with ranges — just remove the count check.

### 3. The scoped verification workaround normalized red

The first time `npm test` went red (#22, April 3rd), the agent logged it and fell back to `tsc --noEmit` + `vite build` + targeted vitest. This worked — nothing broke that session. So the next session did the same. Within days, "npm test is red but that's pre-existing" became the expected state. The impediment log literally says "treat as repo-health baseline signal" five times.

The workaround was reasonable in isolation. The failure was that there was no mechanism to escalate it from "workaround" to "must fix." Each session inherited the red state and passed it along.

### 4. No owner for test health

In the Cowork/Claude Code split, Cowork can't run tests (sandbox limitation), and Claude Code sessions arrive with a specific feature objective. Nobody's job description includes "fix tests that someone else broke." Each session sees the red suite, logs the impediment, and moves on. The impediment log accumulated 7 entries about the same problem with no resolution — perfect documentation of a failure nobody was assigned to fix.

### 5. Content authoring and test maintenance are disconnected

The encounter pipeline skill, attachment pipeline skill, and prose skills all produce content. None of them include "update test assertions" as a step. But even if they did, that would be another social convention. The real fix is making the tests resilient to content changes (delete count assertions) and making test failure block deployment (CI).

### The structural lesson

Every impediment in this log that says "workaround: agents should remember to do X" is a process smell. Documentation and skill updates are social conventions. We are watching them fail. Agents forget to do things in our ways of working — that's not a bug in the agents, it's a bug in the process. The fix is automation: scripts, CI gates, and test designs that make the wrong thing impossible rather than merely discouraged.

**We need to shift capacity from documenting workarounds to building automated guardrails.**
