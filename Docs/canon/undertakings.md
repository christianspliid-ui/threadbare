# Canon — Undertakings

> An undertaking is a long work a mortal chooses on the same board they choose everything else on: a thing built, changed, taken or undone over several ticks, with checkpoints the world rolls and a name the work earns. The player follows a mortal into one; they never pick it for them.

**Step 0 for any undertaking authoring or factory work.** Load this page before `Docs/canon/encounters.md` or the packs. Where this page and the UL disagree, the UL wins (`Docs/ubiquitous-language/Agents.md`, `Encounters.md`).

## Current spec

### The template and its authored seams

`StrategicActionTemplate` (`src/types/strategicAction.ts`) is the whole authored surface. The fields that carry design, in the order the machine gate reads them:

- **Identity** — `id` (`strategic_` prefix), `displayName` (words, never numerals), `verb` (`gather_info | create | change | control | destroy`), `executionMode` (`instant | multi_tick_project | claim_control`), `behaviorFamily`, `reachProfile`.
- **Kind membership** — every authored `multi_tick_project` sits in exactly one kind row's C, U or D column (`src/data/undertaking-kinds.ts`); a row-less `instant` verb must carry a `mutationHint`. (Authored templates only: a cell is its own registration in the object registry, and since THR-1403 the board walks cells.)
- **Counter-play** — a `destroy` verb carries a `motiveGate` (⊆ `MOTIVE_GATE_KINDS`: `rivalry`, `grudge`, `contested_ambition`, `faction_war`), a `harmClass` (`named_death`, `property_destroyed`, `holding_seized`, `network_severed`, `undertaking_abandoned`), and a `targetRule` that can resolve an ownable or commanded thing. **Until a kind can be undone, it is not a kind** — `validateKindRegistry` refuses a row with an empty D column.
- **Cast** — a create/update project declares `cast` slots (`UndertakingCastSpec`): a `must-persist` slot carries `mintRole` and an `identityRequirement`; a reuse slot names `acceptedRoles` (an any-role slot cannot be scarce).
- **Creation** — a `create` verb declares `creationEffects` for at least one outcome band, or a `mutationHint` producing the kind's `objectShape`. A work whose only product is prose is not a work (Law 56's inverse: chips are engine-derived, so the leak is prose claiming state).
- **Bands** — `checkpointDifficulty` and `payoffValue` inside the tier's band (`UNDERTAKING_TIER_DIFFICULTY_BANDS`, `UNDERTAKING_TIER_PAYOFF_BANDS` in `src/data/content-eval/undertakingConstants.ts`, derived from the shipped corpus per tier); `projectDuration` set on every project.
- **Board authoring** — `motivations`: at least `UNDERTAKING_MOTIVATION_MIN_ARITY` (2) distinct `VALUE_PAIRS` members; `payoffValue` present. One currency ranks encounters and undertakings together (`UNIFIED_DECISION_BOARD_MODE = 'live'`, THR-1349); a template with no desire signal scores nothing, silently.
- **Reachability** — the id appears in at least one ambition's `strategicProfile.templateIds` (`src/data/ambition-templates.ts`). The third registration, and the silent one.
- **Register** — `activityProse` and `completionProse` at the encounter standard (Prose Doctrine v2, `Docs/canon/prose.md`): present tense, third person, the agent named, no evasive vagueness, no second person, no numerals, no exclamation marks. Abstraction and intensifiers rank; they do not gate.
- **Tokens** — a template's `activityProse[0]` renders verbatim; a **cell's** lines carry four slots — `{object}` `{owner}` `{actor}` `{place}` (sentence-initial capitals allowed) — filled from the world by `resolveUndertakingProse` (`src/engine/undertakingProse.ts`), which also returns the concepts it named for chips. `STRATEGIC_PROSE_TOKENS` names exactly those tokens; the contract's `tokens` block refuses any other.

### The verb × object model (THR-1392 — **the live model** since THR-1403, 2026-09-08)

The successor to the kind rows, decided 2026-09-03 after a comparative design pass (`Docs/plans/2026-09-03-thr-1392-verb-object-undertakings.md`): an undertaking is a **verb** — **create · change (raise one's own | lower another's) · use · control (claim what nobody holds | seize what someone else does) · destroy · observe** (Christian, 2026-09-03: the four data verbs plus the two the game adds, ownership and yield; `lower`, `seize` and `destroy` are motive-gated) — on an **object the world already has**, named by the world-object catalogue (`Docs/canon/world-objects.md`, THR-1394): Area, Location, Place, Route, Faction, Company, Army, Network, Companion, Item, Power, Condition, Agreement, Standing. **The grid** — every kind × every verb, live cells from the registry, open cells as named decisions, the rest not an object with the reason — is generated: `Docs/canon/undertaking-grid.generated.md` and the served *Undertaking Grid* wiki page (`npm run generate-undertaking-grid`), curated in `scripts/undertaking-grid-dispositions.ts`, which the generator holds to totality so a new semantic or a new kind cannot arrive without its place on the map. Fourteen object types register once each in `src/data/undertaking-objects.ts`: a typed graph shape, the edges that say who holds one (`ownedVia`; an edge object such as a mark is held by its source), a `tierOf` read off the object (defaulting to T2 and tracing `undertaking_tier_defaulted`), the harm class, and what each verb variant does to that type — the graph ops the corpus already had, re-homed under the object. `src/engine/undertakingResolver.ts` is the one resolver: ownership read in one place, the control variant picked from it, the declared semantic dispatched, the object named on `strategic_world_change`; an undeclared cell traces `undertaking_cell_unreachable`, it is never faked. The pipeline carries an **object handle** (`{ kind: 'node' | 'edge' }`) beside `targetNodeId`, the motive gate reads owners through the handle, and the `object` target rule enumerates every object of a type under a cell's ownership rule. **Cells (slice 2):** `src/data/undertaking-cells.ts` synthesises one template per declared (variant, type) — `cell.<variant>.<type>`, `control` as `control_claim` and `control_seize` cells — and an ambition lists the cells it walks in `strategicProfile.cells`, read ahead of `templateIds` through `profileWorkIds` under the `cells` model; a cell with nothing to act on is refused `no_object_in_range:<type>` and traced `undertaking_cell_unreachable` once per world. Verb line-sets: `src/data/undertaking-verb-prose.ts`. **The line on cells (slice 3):** the contract holds a cell to the same ten blocks (membership = the type declares the semantic; reachability = a `cells` registration; no cast floor), `check:undertaking --all` checks packs and cells together, the live proof walks a cell under the `cells` model whatever the flag and reads `mutation_object` off the typed shape, a **cell package** (`{ slug, cell: { variant, objectTypeId }, override, profiles }`) compiles to `applyCellOverride` and registers in the ambition's `cells` (never a kind row; `CELL_OVERRIDE_MAX_PER_CELL` = 3), and the Package View shows *The object* instead of a kind row. **Flag:** `UNDERTAKING_MODEL` (`'templates'` today) — the kind rows, packs and switch below are the live model until the census passes on cells (slice 4), at which point this section replaces them and the retirement list of the 64 is reviewed in chat first. Intelligence is not an object type until it has a reader (THR-1393). **The grid's verdicts (THR-1397, Christian, 2026-09-03):** every admitted cell is decided — `wanted` (yes, the operation named), `later` (a named precondition first) or `no` (absorbed into a cell that exists); the open column is empty, and three standing riders bind every cell — a completed work grows capability in its Reach, wealth is visible on the sheet before any yield cell ships, holding yields passively. Killing a mortal is the plot (`destroy × mortal`, writes `deceased`, a moment before it resolves on a threaded target), cursing is the signed `create × condition`, usurping is a forced succession the phase still arbitrates. **A cell ships with its reader; a wanted cell whose product no phase or surface reads is not built until one does** (THR-1428, from Christian's hyperconnectivity ruling of 2026-09-07 — *"the dynamism of a living organic world is hyperconnectivity"*). The nine readers the live cells owed were built under that rule and their notes now say **Read by** rather than **Owes**: watching writes `knows_of` familiarity and, on a ruin or wonder, a clue whose precision the band decides; a mortal-ruined settlement carries `ruinMagnitude` and joins the delve layer after a decay window; the `holding_income` phase pays a seized route's toll, a freehold's yield and a controlled Location's tithe; a spell's soul-price leaves the `doom` health meter for quintessence, and its exhaustion refuses the next cast. Every `wanted` cell carries a `reader` field, and `generate-undertaking-grid` fails by name on an empty one. **A subsystem is reached in three ways** (THR-1431, from THR-1401's measurement): it **owns** the kind a live cell acts on (`WORLD_OBJECT_KINDS[].owningSystem` → `LIVE-TOUCHED`), or it is the **home of the operation** that cell runs (`REACHED-BY-OP` — the registry's own imports resolve each semantic's engine symbols to a module, a sustained mode resolves through the module that returns its `op:` result, and `scripts/subsystems-registry.ts` houses the module), or it **reads** what another subsystem's live cell leaves (`READS` — `SUBSYSTEM_READERS`). The status word names the closest relation; all three are derived from code, never authored. Counting only the first is what made five subsystems a mortal's work reaches every run — Strategic Projects & Control, Movement & Colocation, Intelligence, Ruins & Delves, Spheres & Quintessence — read UNTOUCHED, which would have under-counted every explorer calling once THR-1403 computes the fourth per-calling gate off this view. A cell that writes the graph inline (`seize_item` moves the `possesses` edge itself) has no op home and adds nothing to the second join; modules that resolve to **no** subsystem fail by name. What stays UNTOUCHED carries its reason in `UNTOUCHED_BY_DESIGN`, held to totality both ways — a bare UNTOUCHED row fails, and so does a reason for a subsystem something has since started reaching.

**The flip (THR-1403, shipped 2026-09-08).** `UNDERTAKING_MODEL` is `cells`. What a mortal sets their hands to is **derived by the division rule** (`src/engine/divisionRule.ts` over the tables in `src/data/division-rule-tables.ts`, THR-1398): the active ambition's category picks the verbs, the mortal's two leading Reaches pick the kinds, Eye adds `observe` on every kind, and the intersection — kept to cells the registry has — is the spread; an ambition profile's hand-listed `cells` add on top and never replace it. The list is rotated by tick and actor so the per-actor cap starves no cell by position, and the per-ambition cap (`STRATEGIC_MAX_CANDIDATES_PER_AMBITION`) no longer applies to a cell — cells enumerate by object, with `UNDERTAKING_MAX_CANDIDATES_PER_CELL` targets each. **The 64 authored templates are absorbed:** under `cells` a profile's `templateIds` are not walked (60 of them ran an op a cell now runs; `strategic_improve_masterwork` and `strategic_commission_quest` retired outright — nothing else named them; `strategic_expose_cache` and `strategic_train_apprentice` leave every profile but keep their definitions, the first as the intelligence-cache kind row's counter-play so the legacy registry gate stays sound, the second because the mentorship initiative starts it by id — mentorship is its own initiative, not a cell, and rides ahead of the spread for the `MENTORSHIP_AMBITION_CATEGORIES`). The definitions and the per-template completion switch stay as the **legacy arm** — the review levers and the contract tests start authored templates by id, and a cell resolves through the one resolver regardless of the flag — so the template model is unreachable from the board and deletable later, not now. Calibration folded in from the census (THR-1402): project verbs run **2 / 3 / 4 checkpoints** by tier (`UNDERTAKING_VERB_DURATION`, 12 / 18 / 24 progress — the documented 18 at T2 restored), lair elites are minted `ambient` and decide nothing, an item's tier falls back to its class (`ITEM_TIER_BY_CLASS`) when unstamped. `npm run census:cells` is the two-seed acceptance instrument on this model — starts, completions, refusal reasons and `undertaking_cell_unreachable` per cell.

**The registry reads the edges the world writes (THR-1436, shipped 2026-09-08).** Who holds an object is one reader's answer, `resolveObjectOwners`: a type's own `ownersOf` first (a Faction's holder is the leader `getFactionLeaderId` already derives; leaderless reads *unowned*, which is what `claim × Faction` waits for), else an edge object's source, else the type's `ownedVia` walk (`accompanies` for a Companion, `possesses` for an Item) — a type declares one of the two, never both. A **Condition** object is one mortal's *bearing* of a condition, the `has_trait` edge, never the shared definition: the cure lifts that bearer's wound and nobody else's, and it is **signed like the blessing** — curing an ally needs no quarrel (`gate_exempt:ally` on the board, `CONDITION_CURE_UNGATED_FOR_ALLIES`) while curing a stranger or an enemy stays motive-gated. A **Standing** object is one ordered pair, read from `reputation_with` when a score exists and from the seeded `relates_to` otherwise (`UNDERTAKING_STANDING_TIER_SENTIMENT_BANDS` tiers the fallback); `hostile_to` is what `destroy × Standing` writes, not an object. Catalog templates (`CATALOG_TEMPLATE_IDS`, derived from the reward and anomaly catalogs) are not Items — instances are. `create × Route` mints the identity node the object is through `mintRouteIdentity`, the lifecycle's own writer, and reports the node. `npm run census:ownership` prints objects · owned · owned by a deciding mortal per kind on a generated world; the CLI's `objects` readout carries the same column.

**Yield and leverage (THR-1439, shipped 2026-09-08).** The map's last band (THR-1399), and the one that opens no new subsystem: four cells that make the economies the other cells already touch worth touching. **`use × Location` is the active harvest** — holding court, taxing a market, drawing a tithe by hand. The lump is the base scaled by the town's prosperity band and by its productive Places (commerce class, capped at four), and it is banked through `bankWealth` — the funnel **extracted from `payHoldingIncome` in the same PR**, so the active harvest and THR-1428's passive tithe stamp one cause vocabulary rather than two spellings of the same idea; the Means tooltip reads the new `draw_yield` cause as *a tithe drawn by their own hand*. **The costs are paid on every band and the lump only on the good ones** — the town loses prosperity and the holder loses standing *with the town* whether or not the work lands, which is what makes a harvest a risk rather than a button; an *absent* band takes the failure arm too, never a silent full success. Once an income interval, by an eligibility cooldown. **`change:raise × Route`** writes a lump of volume onto the lane's `trades_with` edge and restarts its decay clock, because expansion is activity; the toll scales on volume, so raising it raises somebody's income the same interval. **`control:seize × Agreement` is theft**: `retargetEdgeSource` moves the `knows_secret_of` edge from holder to thief — the id stays, so every reader keyed on it survives — and **the holder loses it, never a copy**, or theft would be free. Motive-gated like every seize. **`use × Standing` mints a favour**, gated at Respected rather than at `Accepted` (0.5, the neutral default every stranger carries) — and the standing is spent even when the call goes unanswered, because asking is what costs. **The Agreement kind now has two classes.** Its shape widened to `edgeTypes: ['knows_secret_of', 'owes_favor']` with a liveness discriminator, one handle per ordered pair and the mark winning. An edge object is held by its source — a mark by its holder, **a favour by the one who owes it** — which is right for `seize` and wrong for `use` and `destroy`, so those two carry `ownershipOverride: 'any'` and the eligibility hooks gate per class: a mark is pressed and exposed by its holder, a favour redeemed and forgiven by its creditor. The favour class therefore gets its **whole life cycle** from this one band — minted by `use × Standing`, spent by `use × Agreement` (through `applyFavorRedemptionConsequences`, the writer the encounter path already goes through), forgiven by `destroy × Agreement`. **The eligibility hook gained the world's `tick`**, additively: a cooldown is a precondition about the state of the world exactly as much as a company's cohesion is, and it cannot be read off the graph alone. **And the leverage strand reached the player for the first time:** computed on the card since THR-30, its only renderers were the unmounted `AgentDetailPanel` (impediment #981) and the debug tab, so `BondsTab`'s *Agreements* placeholder became one row per live mark and favour, in words — *taken from* on a stolen secret, *called in* on an asked-for favour, no numerals (Law 4), gated at `known` like the Relationships rows above it.

**The ownership of people-things (THR-1438, shipped 2026-09-08).** Seven cells that change **who commands a group of people** — the band the map ordered third (THR-1399), and the first time a mortal could do anything about a seat. **One command writer:** `setCommander` (`src/engine/groups/groupCommand.ts`) is where a standing command changes hands; it removes the old `commanded_by`, writes one carrying `via` (`formation | promotion | claim | mutiny | coup`), and makes the `member_of` roles agree. The dissolution sweep's `promoteNewLeader` — which used to repoint the edge silently, so a commander's death was a leak rather than a succession — now calls it with `'promotion'`; the three spawn-time writers keep their ids, because they say who a group was *raised* under. **A band is held by its living commander** (`ownersOf` on Company and Army, `ownedVia: []`), so a death opens the seat and `claim × Company` / `claim × Army` can see it. **Two hooks on the object type**, the shape of THR-1436's `gateExemption`: `ownershipOverride` replaces a variant's default ownership rule at cell synthesis — one cell needs it, the candidacy — and `eligibility` states a precondition *about the world* after the ownership rule and before the motive gate, refused on the board as `ineligible:<reason>:<target>` and never silently, failing closed on a throw. **The cells:** claim × Company (a member, or whoever stands where it stands); claim × Army (the army's own faction, and nobody already commanding a host); **seize × Company is a mutiny** — motive-gated *and* refused `ineligible:cohesion_holds` unless the cohesion system already reads the band as *frayed* or *breaking*, so a mutiny is only possible where the world already says the company is coming apart; **seize × Army is a coup**, resolved by the faction and the band, never by the blade; **claim × Faction is a candidacy, not a coronation** — `nominateSuccessor` writes the same `will_succeed` edge an anointment writes and the succession phase stays the one arbiter, gated on the faction being **unseated** (no `leads` edge) rather than leaderless, because `getFactionLeaderId` derives a leader for every faction with members and "leaderless" would have made the cell unreachable by construction; **seize × Faction is a usurpation**, `forceSuccession` running the phase's own seating early, with a grudge and a standing loss on a loss and the live schism op on a critical failure. **Nobody dies in any of them** — killing on purpose is the plot's (THR-1430), and `markMortalDead` is still the only writer of a death. **`seatLeader` is extracted from the phase** (`src/engine/factionSuccessionOps.ts`) and called by it, so there is one seating rather than two that must be kept in step; it must move `leaderSnapshotId`, or the phase reads a usurpation as an exit and re-seats over the top of it. **The succession queue is now ranked:** the god's anointment (`ANOINTMENT_PRIORITY` 10) outranks a notable's heir (5) outranks a mortal's candidacy (1–2) outranks the derived ladder — both anointment writers now stamp a priority, because `pickSuccessor` reads unset as `-Infinity` and any positive candidacy would otherwise have outranked every divine anointment ever written. **Two grudge causes** (`command_seized`, `usurpation_failed`) join `GRUDGE_PROVENANCE` — they are injuries with a name on them, so the deposed may plot back — and `writeGrudge` gained `upgradeCause`, without which none of these three ops would ever have recorded its injury: each is gated on hostility, so an edge usually stands already and the writer's default is to leave it alone. **`observe × Army` is scouting**, which writes familiarity with **where the host stands**, not with the host: `knows_of` is a knower → Location edge and cannot point at an actor. The war readout lists each army's `scoutedBy`. Two measurements corrected the plan in flight: `promoted: true` had one writer and **no readers**, so the rename to `via` repointed nobody; and `USURPATION_STANDING_LOSS` is **0.075**, not the planned 0.15, because `REPUTATION_WITH_MAX_DELTA_PER_OUTCOME` is exactly 0.15 and a 0.15 base doubled on a critical failure was capped straight back — the two failure arms would have been identical and the doubling a silent no-op.

**The dormant kinds II — rings and the plot (THR-1430, shipped 2026-09-07).** Four cells, one dormant kind woken, and the extraction two maps were waiting for. **`create` / `change:raise` / `use` × Network** wake the Network kind, which was registered and mintable by nobody: `createGroup` gains a `kind` and stamps it, so a ring is a group node minted through the one group mint rather than a second shape. **A network must be *seen* by the group phase before it can be told not to travel** — the phase enumerates `GROUP_PHASE_KINDS` (`company`, `network`) for upkeep, cohesion and dissolution and gates only the movement sub-step on `GROUP_KINDS_THAT_TRAVEL` (`company`); the two lists are separate because each half alone is a defect in the other's clothes. `getAllGroups` still defaults to companies alone, so its ~40 callers are unchanged. A ring has no position: reach is measured from *every* living member (`RING_REACH_HEXES`), which is what lets `run_ring` do what one observe would against a target the leader has never stood near. It writes nothing into Stealth or detection pressure — mortal surveillance is not the god's fingerprints (THR-1397). Two findings corrected the plan in flight: recruit affinity reads the Shadow **Reach**, not the darkness Sphere (orthogonal axes — the Sphere reading found nobody among eleven co-located mortals on seed 42), and it is a **preference, not a gate**, because an ordinary NPC carries no capability traits and a hard threshold left a settlement full of people supplying no recruits — this plan's own kill criterion, reached before shipping. **`destroy` × Mortal is *the plot*:** a premeditated killing, never the duel (`destroy × Standing`) or the slaying (a battle). Motive-gated harder than any cell — `PLOT_MOTIVES` admits only `grudge` and `faction_war`, so opportunism never licenses a killing — staged over `PLOT_CHECKPOINTS` named stages, and resolved through **`markMortalDead`, the one funnel every mortal now leaves the world by**. The funnel carries the `death_prevented` ward (an outcome, not an error — the plot resolves *survived*) and the Aspect echo, then writes in the caller's `mode`: `retain` leaves the node with `deceased`, `deceasedTick`, `deathCause`, `slainBy`, `remove` does what the lifecycle's low-reputation death has always done. All three existing writers were repointed with behaviour preserved; whether *every* death should retain is deliberately left to the map, because it moves every node-absence reader at once. The retained body is why the succession phase gained a `deceased` read at **both** leader seams — the anointed edge and the score fallback, since guarding one alone would have re-derived the corpse as leader by standing. A followed target gets a `peril` moment (`interrupt`) after the positioning and the strike defers `PLOT_PERIL_GRACE_TICKS`; the card never names the plotter, and the god answers with levers that already exist. `action.shadow.assassinate` is **retired** — its only effect was a node deletion the chronicle cannot remember and the grievance lane cannot avenge — and `action.gold.commission-assassination` keeps its place and stops deleting, through the new `mark_mortal_dead` graph op.

**The dormant kinds I — powers and conditions (THR-1429, shipped 2026-09-07).** Three cells woke the two seams the readers band left dormant, each with its reader in the same commit. **`create × Power` (`learn_spell`)** gave the Power kind the node shape the registry deferred: one shared `spell`-subcategory trait definition per template, minted at seeding, with `knows_spell` (unlimited — the biography) and `has_trait` (capped by `SLOT_CAPS.spell` — what is carried) pointing at the *same* node, so learning past the cap is *known and not carried* rather than a refusal. The caster gate is THR-1230 ruling 4 composed: a spell-weaver mastery trait, a caster `npcRole`, or Veil at `LEARN_SPELL_CASTER_VEIL_FLOOR`. **`create × Condition` (`inflict_condition`)** is one **signed** cell and the first whose object is made against a person: self or an ally is a blessing from the `#blessing` pool, un-gated; a mortal the actor holds a motive against is a curse from the `#curse` pool with a band-scaled duration; a stranger is refused `no_sign`, and there is deliberately no neutral third outcome — the sign *is* the gate. A curse registers the new `afflicted` harm class, so the cursed may come to want vengeance against a seen culprit. **`destroy × Power` (`seal_power`)** mints the catalog's existing Null-Touched rather than authoring a duplicate suppressing condition: the power stays known and wielded and simply will not answer, which is what makes curing it the counter-play. Its reader — `use × Power` refusing `power_suppressed` — reads the **bearer's own conditions**, never the power's runtime state, because a spell definition node is shared by every mortal who learned it and a per-node flag would seal the whole world at once.

Two substrate corrections were made from measurement rather than from the plan, and are recorded here so neither is re-derived: the caster roles the plan named (`mage`, `hedge_witch`, `sage`) exist in no seeded world — the eleven that do are in `CASTER_NPC_ROLES` — and `domainCapabilities` is a raw 0–100 scale, not 0–1, so the Veil floor is `40`. The tradition shelf keeps its shape (aligned spheres first, sorted, first unknown) but opens to the whole shelf for an **unaligned** mortal under `LEARN_SPELL_UNALIGNED_SHELF_OPEN`: measured at tick 30 on seed 42, 3 of 337 mortals carry any sphere score, so the shelf read literally would have made the cell unreachable for the entire world.

### The kind registry (legacy — the template model's, behind the flag since THR-1403)

The kind rows are the *authored template* model's registration and gate; the live model's registration is the object registry above. They stay for the templates the review levers and the contract tests still start by id. `UNDERTAKING_KIND_ROWS`: eight rows across three tiers — `intelligence_cache`, `leverage_mark`, `masterwork_item`, `chart_find`, `network` (T1); `trade_route`, `place_location` (T2); `warband` (T3). Each row is a CRUD closure: what the kind builds, how it changes, and the motive-gated verb that undoes it, shipped in the same commit. `sublocation` (T2) and `faction` (T3) are **not** rows: their builds exist, their destroys do not, and a row registered against an ambient process would be presence of counter-play rather than counter-play.

### The packs

Seven authored packs under `src/data/strategic-packs/` (merchant, builder, scholar, zealot, court, warlord, wanderer) join `TEMPLATE_REGISTRY` in `src/engine/strategicActionCandidates.ts`. The factory's own output lands in `src/data/strategic-packs/factory/` (slice 3) and joins the same registry.

### The machine gate

`npm run check:undertaking -- <templateId> | --all [--json] [--list-failures]` (`scripts/check-undertaking.ts` over `src/data/content-eval/undertakingContract.ts`). Blocks in the order above; a warn channel that prints and never fails (the Law 56 write-set lexicon, past-tense markers). **No exemptions.** The only escape is `UNDERTAKING_RETROFIT_PENDING` (`src/data/content-eval/undertakingRetrofitPending.ts`): the templates that predate the contract, named once, shrinking only; `undertakingContract.test.ts` fails both a listed template that now passes and an unlisted one that fails. Green is a precondition for a PR existing; CI runs `--all`.

### The pipeline

`.claude/skills/undertaking-pipeline/` — the encounter factory's line, mirrored: a **batch brief keyed on the kind × CRUD grid** (`reference/batch-brief-format.md`; gap-weighted toward empty cells, the mechanical fix before any premise, Christian-approved in chat), draft, a critic loop bounded at two (`agents/draft-prompt.md`, `systems-prompt.md`, `editorial-prompt.md`, `package-prompt.md`, `implementation-prompt.md`), the gate, the live proof, the compiler, the batch report (slice 4). `reference/kind-row-catalog.generated.md` is the grid as data, regenerated by `npm run generate-kind-row-catalog`.

### The write set

`undertakingWriteSet(template)` (`undertakingContract.ts`) — everything a template declares it will change: the `mutationHint` type, the `creationEffects` bands with entries, the `harmClass`, the kind row (a christening; a freehold when `ownable`), the `must-persist` cast, the catalysts. **One predicate, two consumers:** the contract's creation block counts it and the live proof gates its claims on it, so a template that declares nothing is never failed for delivering nothing and one that declares a write cannot pass by delivering none. A third hand-rolled "does it write" test would drift from both — do not add one.

### The live proof

`npm run check:undertaking-live -- <id>... [--seed N]... [--band <band>|none] [--map] [--json]` (`scripts/undertaking-live-proof.ts`; the `encounter-live-proof.ts` sibling). A real seeded world, the review lever starting the template on the first autonomous individual by id, the real `runTick` to a terminal status, every claim read off the harvested trace buffer and the graph — never off the template. Baseline claims `started` · `no_tick_crash` · `terminal` · `moment_started`; delivery claims `checkpoint_rolled` · `cast_bound` · `creation_effect` · `mutation_object` (read by hint type: the `trades_with` edge, the sublocation, the founded place, the company the actor is a member of, `strategicIntelligence`, the possessed artifact, the `knows_secret_of` mark) · `christened` · `harm_recorded`, each gated on the write set. Verdict `proved` / `failed` / **`vacuous`** — nothing failed and nothing was delivered; not green. **The default run pins `success`** (`DEFAULT_PINNED_BAND`): the proof asks whether the declared write set *can* land; how often the dice land there is the census's question. `--band none` runs unpinned. Evidence on `main`: `strategic_cultivate_informant`, `strategic_establish_trade_route`, `strategic_recruit_warband` proved on seeds 42 and 99 (slice 3 closeout).

### The compiler

`npm run compile:undertaking -- <package.json> [--dry-run] [--force]` (`scripts/compile-undertaking.ts` over `src/data/content-eval/undertakingPackage.ts`; `reference/undertaking-package-format.md`). The package is the real `StrategicActionTemplate` plus `slug`, `kind { kindId, role, row? }`, `profiles`, `docComment` — unknown top-level keys refused by name, and the emitted literal is annotated with the real type so `check:typecheck` is the deep validator. It writes `src/data/strategic-packs/factory/<slug>.ts` (prose byte-identical) and `factory/__tests__/<slug>.test.ts`, and registers the export in `FACTORY_STRATEGIC_TEMPLATES` (joined last into `TEMPLATE_REGISTRY`, so factory output never shadows an authored id), the id in the kind row's C/U/D column, and the id in each named ambition's `strategicProfile.templateIds` — all idempotent. **A row-less kind is opened only by its first destroy**, carrying `kind.row`; any other role is refused. The compiled file is the canonical, hand-editable artifact from then on; re-compiling over it needs `--force`. Compile does not run the gates — typecheck, contract, live proof and the emitted test follow it, in that order.

### The batch report

`npm run undertaking:batch-report -- <ids…> [--seed N]… [--brief <path>] [--out <path>]` (`scripts/undertaking-batch-report.ts`; the `encounter-batch-report.ts` sibling). A renderer, not a third gate: it shells `check:undertaking --json` and `check:undertaking-live --json` and renders their verdicts, so it cannot disagree with CI. Leads with the batch table (kind · cell · tier · verb · reach · family · harm · gate · live · two links — the live run on The First and the Package View), then the **kind × CRUD grid** with this batch's additions marked (the variance this line reviews for; a C-only batch is flagged as REVISE trigger 1 in the report itself), the tier / verb / reach / motivation spread, per-template detail with the write set, the prose and every live claim, and the census pointers. Writes `Docs/plans/undertakings/<date>-batch-report.md` by default.

### The Package View

`?view=cms#undertaking-packages?template=<id>` (`src/components/CMS/undertaking-package/`; `?batch=<id>,<id>` compares up to six). One page per template, every block resolved from the registry and the contract, never the graph: identity and the calling its family maps to (`CALLING_BY_FAMILY`); the kind row and the cell this template fills with the row's other cells as links (an empty D cell reads *nothing undoes it*); the board **as words** — `difficultyWord`, payoff relative to the tier band, duration banded (`DURATION_WORD_BANDS`), never the numeral; cast slots; the write set (Law 56's chip-backing list, and *nothing* when it is empty); counter-play (motive gate, harm banded by `HARM_WORD_BANDS`); the prose in the moment card's register; the contract verdict with its warn channel and the ratchet mark. The moment card is unchanged.

### The review levers

`src/engine/undertakingReviewLevers.ts` (the `debugOutcomePin.ts` sibling; works on the deployed build). `?undertaking=<templateId>` — the `?spawn` analog: starts the named template on The First through the board's own candidate helpers and start path, bypassing only `ambition_profile`, `active_cap` and `motive_gate` (`REVIEW_LEVER_BYPASSABLE_GATES`, a closed list), each named on the `strategic_action_started` trace as `bypassedGates` with `startedBy: 'review_lever'`; a destroy prefers an owned target and reports an unowned one; a below-spotlight actor is reported, not hidden. `?outcome=<band>` — the pin, reused: it targets the undertaking's checkpoints when `?undertaking=` is present, `?spawn` wins when both are, and the verdict is `band_landed` / `no_effect_on_band` / `not_reached` (`getUndertakingPinVerdict`). `?forcemoments` — every spotlight mortal is followed and the `started` moment interrupts for the flag's lifetime; unfollowed mortals stay invisible. Headless twins: `window.__DEBUG.startUndertaking` / `pinUndertakingBand` / `getUndertakingPinVerdict` / `forceMoments`; CLI `spawn undertaking <agent|@first> <templateId> [--target] [--band]`, `undertakings`, `follow`, and the `@first` alias (which falls back to the first spotlight mortal in the thread-less CLI world and says so).

### The census

`npm run census:undertakings` (`scripts/undertaking-census.ts`) — undertaking / encounter / idle shares, starts per mortal, variety at a fixed start sample (cross-seed mean), the per-mortal cap, the vendetta share. Review-lever starts (`startedBy: 'review_lever'`) are excluded from its counts.

## Rejected approaches

- **Hand-registration in three files** (pack, kind row, ambition profile) as the way a template becomes real — the compiler registers rows and profiles idempotently (slice 3); a template registered by hand in two of three is reachable by luck.
- **Register-free strategic prose** — the shipped corpus predates the doctrine (28 of 64 fail the register block on introduction); the contract holds new work to the encounter standard.
- **Initiatives as a second pipeline** (THR-1292 §3) — retired; one board, one line.
- **Control upkeep as an undertaking family** (THR-1303) — being deleted.
- **Behaviour families as a player-facing word** (THR-1281 §7b) — the calling is the word; families are authoring metadata.
- **A warband that completes while minting nobody** (THR-1309) — a create verb's product must exist.
- **Exemptions on the gate** — a named, shrinking ratchet instead (ruling 3).
