# THR-1462 — `$here` becomes a chip anchor, so a consequence can link the place it landed on

**Shipped 2026-09-13.** Deferral from THR-1130 batch 3, Encounter Experience.

THR-1446 added `$here` to `SCENE_SENTINEL_FIELDS`, so an aftermath **effect** could
land on the place a scene happens at: `apply_condition` with
`targetLocationId: '$here'` writes a condition onto the shrine. The **chip** side
never gained the sentinel — `classifyAnchorDeclaration` resolved exactly five forms
and refused every other `$`-prefixed string — so the two halves disagreed about what
an author may name. The effect landed the condition on the stones; the chip reporting
it could not point at the stones.

## What changed

- **One rule, two readers.** `resolveSceneHere` moved out of `encounterAftermath.ts`
  into a new `src/engine/sceneHere.ts`, and both the effect binder and the chip
  resolver now import it. A second *copy* of the location walk was the one outcome
  that had to be avoided: a chip resolving `$here` one hop differently from the effect
  it reports would point at the wrong node while passing every gate.
- **Why not `sceneSentinels.ts`.** That module is deliberately pure — *"no graph, no
  state, no fs, and no template"* — so the authoring-time gate can import the
  field→kind table without pulling the runtime dispatcher into a CLI bundle. The walk
  needs a `WorldGraph`. One small graph-reading module beside the pure one keeps both
  properties.
- **`$here` is the seventh anchor form.** `ANCHOR_SENTINEL_HERE`, a `here` form on the
  verdict union, an unconditional classify arm, the sentinel named in the refusal
  message, and a resolve arm reading `resolveSceneHere(…, 'location')`.
- **Neither caller needed widening.** `worldRefResolver` and the encounter-stage
  adapter already pass `graph` and `actorId`, which is everything `$here` reads.

## The tier choice, and why it is not free

`$here` resolves at the **Location** tier on the chip side. The effect field that
motivated the sentinel is `targetLocationId`, whose kind is `location`, so resolving
anywhere else would anchor the chip to a different node than the effect it reports
wrote to — reopening the same disagreement one tier down. An actor standing at a
Place walks up through `resolveToParentLocation`; a test pins `loc-town` while the
actor stands at `loc-shrine`, so the plausible-looking wrong answer is a failure.

## Where the ticket's third Done-when was overtaken

The ticket asked to repoint `shrine_offering.tended_stones`'s **`stateNoun`** to
`$here`. That is no longer the lawful channel, and the rule that closed it landed
*after* this ticket was filed: **THR-1472** (director ruling 2026-09-12, gated by
THR-1480) holds that a `stateNoun` names the **state object** the band wrote — a
condition, an item, an agreement — and never the thing carrying it. A place carrying
a location condition is the carrier exactly as a mortal is. The chip already had a
real state object on its noun (`trait.condition.location.tended_shrine`), so what the
ticket called a workaround is now the rule.

The mechanised half of THR-1472 only lists `$actor` / `$target` / `$cast:*`, so
moving the noun to `$here` would have **passed the gate while breaking the rule's
stated reason** — the quiet failure worth naming.

So the ground is named on the **concept** channel instead, which is where "the object
the sentence is about" belongs and is a first-class anchor (`declaredChipAnchors`
walks it). The tag still reads `BOON · TENDED` and routes to the condition's page, and
*"The stones here"* in the sentence is now a live link to the place. This is the shape
The Beast in the Granary already ships: the noun on the condition, the ground on a
concept.

**One consequence, pinned in a test rather than left to be rediscovered:** the ticket
expected a place **tile**. `stateNoun` takes precedence over `concepts` for the tile
slot, and an `attachment` kind is the documented no-tile path — it has a page, not an
entity visual. So the stones become a live **link** and the chip carries **no tile**.
That is the price of keeping the noun on the state object, and it is the ticket's
actual intent that survives: *"the stones are the object the player would click."*

## The sweep

`shrine_offering` is the corpus's only `targetLocationId: '$here'` effect, so it is
the only chip that could have been proxying one. The other `place`-family chips
(The Beast in the Granary, Standing the Line) anchor `$target` with
`visualKind: 'location'` — correct, because those encounters genuinely target a
location. Nothing else to repoint.
