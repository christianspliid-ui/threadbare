# THR-1187 — the honest agent stops fearing the cunning agent's fear

**Shipped 2026-08-23.** The ticket asked which of two disagreeing files is authoritative for the `honesty_cunning` pole, and framed it as an either/or with different blast radii. The answer turned out to be neither of the two options as stated: a third file settles it, and **both** of the candidates carry the same single inversion.

## What a player was reading

`fearResolver` composes three sources that all key off the sign of the agent's strongest value: `VALUE_LABELS` supplies `{value}`, `FEAR_DESCRIPTIONS` supplies `{fear}`, and the `FEAR_PROSE` body is picked by `${pair}_${pole}`. For `honesty_cunning` the bodies and the fears were both one pole out. Rendered from the shipped tree:

```
[positive → {value} = "Honest"]
  Mira keeps no journal, writes no letters, avoids being alone with people who ask
  direct questions. [...] because Honest, practiced long enough, has left Mira
  uncertain which version is the original.

[negative → {value} = "Cunning"]
  Mira watches the cunning prosper and says nothing. [...] It is that Cunning is
  expensive — and that the invoice arrives in the form of people they could have
  protected if they had been willing to lie.
```

An honest agent described as running tradecraft; a cunning agent described as watching the cunning prosper from outside, and paying a price for refusing to lie. The two bodies fit each other's keys exactly, which is why a one-pole check would have passed on it.

## The decision: `VALUE_LABELS` is authoritative, and both dependants move

The ticket's option 1 was "swap the prose", option 2 "swap `FEAR_DESCRIPTIONS`", with the note that the latter is itself the reverse of what the labels suggest. That note is the whole answer: `FEAR_DESCRIPTIONS.honesty_cunning` was **also** inverted, the prose had been authored against it, and the two agreed with each other while both disagreed with the labels.

`VALUE_LABELS.honesty_cunning = ['Honest', 'Cunning']` cannot be the thing that moves — the axis name fixes which pole is which, and `INTENSITY_VALUE_LABELS` keys the same way. So the file everything else must agree with was never in question, and there is one inversion sitting in two places rather than a genuine disagreement between two candidate sources.

The convention the other eight pairs follow, stated in `FEAR_DESCRIPTIONS`' own doc comment as `[virtue-extreme fear, flaw-extreme fear]`, is sharper than that comment says: **each pole fears the undoing of what that pole is committed to.** Loyal fears betrayal, Traditional fears the loss of the old ways, Preserving fears what they built crumbling, Courageous fears showing weakness, Discreet fears the harm their knowledge causes. Under that rule Honest fears *having to deceive* and Cunning fears *being outwitted* — the reverse of what shipped, and `honesty_cunning` was the only pair breaking its own file's convention.

Doing only one of the two leaves the other wrong, which the falsification arm below demonstrates rather than asserts.

**Blast radius of the second surface, checked before moving it.** `FEAR_DESCRIPTIONS` has two consumers beyond the resolver — `getFearsStrand` (`strands.ts`) and the CMS registry — and both index it by the identical `value >= 0 ? positive : negative` test, so the swap corrects the strand readout and the catalog dump in step rather than moving them independently. No existing test pinned the content: the eight tests over this constant check count, shape, non-emptiness, tone and opening word, none of which can see a pole.

The four bodies per key that THR-625 added were written pole-agnostic and stayed on the keys they were authored for. Only the eight pre-existing bodies moved, so each key still carries six.

## The pin, and why it is three assertions rather than one

The ticket asked for an assertion that stops a future pair drifting the same way. One check could not do it, because the inversion lived in two files and the damage was only visible in a third place — the composed sentence.

- **`strand-content.test.ts`** — a reviewed alignment table pinning each pair's `[label, fear]` pairing as **literals**, asserted whole-record. Written as literals deliberately: a table derived from `FEAR_DESCRIPTIONS` would be the constant on both sides and could not fail. Whole-record `toEqual` means a tenth value pair fails until someone adds a reviewed row.
- **`backstory-content.test.ts`** — a reviewed pole manifest, one distinctive fragment per `FEAR_PROSE` key, asserted present on its own key **and absent from its sibling**. The absent half is what catches a swap, and it doubles as proof the fragment discriminates: a fragment common to both poles fails there rather than passing vacuously. Coverage is asserted against all 18 keys, so a new pair cannot be added without someone reading its bodies.
- **`backstoryResolvers.test.ts`** — the composed line, both poles, swept across eight seeds. This is the only assertion that can see the three sources disagreeing with each other, and running **both** poles is load-bearing: on the shipped arrangement each pole's body was internally coherent, so a one-pole test passes on the inversion.

## Falsified in two arms, and the second is the one that matters

Reverting both data files with the tests in place turns all three assertions red.

The arm worth recording is the **partial** one: restoring the prose fix while leaving `FEAR_DESCRIPTIONS` inverted — which is exactly what shipping the ticket's option 1 alone would have produced — leaves the manifest green and the alignment table and the composed-line assertion **red**. So the pin catches a half-fix, not merely a total revert, and it would have caught the narrower of the two fixes the ticket offered.

## Found in passing, filed rather than fixed

Rendering the lines surfaced a second, independent defect on the same table: `{fear}` substitutes the **whole** fear description with only `Fears ` stripped, while every body is written around `{fear}` standing for the bare noun. The result is ungrammatical on all 18 keys — `the being outwitted of being outwitted`, and `the the loss of the old ways of loss` on `tradition_novelty`. Out of scope here (it is uniform across the table and independent of pole), filed as **THR-1199** with the rendered evidence, both candidate fixes, and the reason the existing placeholder-presence tests are structurally blind to it.
