# THR-1321 — a cast halted `strategic_recruit_warband`, and the cause was neither the cast nor the template

**Shipped 2026-08-28.** [THR-1321](https://linear.app/threadbare/issue/THR-1321/a-cast-on-strategic-recruit-warband-halts-it-completely-13-completions)

## What was wrong

`strategicActionLifecycle`'s phase return built its `strategicState` as a **literal naming
only three fields** — `projects`, `controls`, `history`. `StrategicRuntimeState` has two
more, both optional and both owned by the binder: `mintQueue` and `bindings`. They were
dropped once per tick, silently.

The cost was total. The bind pass enqueues a birth during the `strategic_projects` phase;
`phaseAgentLifecycle` drains that queue later in the *same* tick. But the object holding
the queue was discarded before the valve ran, so the drain always found an empty queue,
no binder mint was ever born, and any cast slot needing one deferred on `awaiting_mint`
until its undertaking timed out. Measured on seed 99: **63 checkpoints, every one
deferred, zero rolls, 334 mint requests queued and not one minted.**

Two things this explains that the filing ticket could only observe:

- **Why both persistence modes measured identically.** The ledger was wiped every tick,
  so `must-persist` and `scene-only` were the same thing.
- **Why `strategic_establish_spy_network` survived the same cast shape.** Its slot binds
  to somebody already standing there and rolls in the same pass, so it never needs
  either field to cross a tick boundary. Only a slot that must *mint* does.

Every sibling return in the module already spread `...currentState`. This was the one
drifted writer.

## The second defect, exposed by fixing the first

With the ledger surviving, the binder's loss machinery went live for the first time — and
immediately over-fired. The `$anchor` slot recorded `boundRole: 'anchor'`, a synthetic
name that is not an `npcRole`, so the role census had never heard of it, `scarcity01`
returned `1.0`, and **every anchor severance scored `singular` and halted its undertaking**
as if the world's last archmage had died.

Fixed at both ends: the sentinel is gone (a roleless anchor now carries no role), and
`singular` requires a role to actually be named. That distinction is the load-bearing
one — a dead archmage still carries `boundRole: 'archmage'` on the ledger row, while a
roleless anchor carries nothing, so the two cases stay separable.

## What shipped

- `strategicActionLifecycle.ts` — `...currentState` spread on the phase return.
- `undertakingBindPass.ts` — anchor role sentinel removed; `singular` requires a named role.
- `warlordStrategicPack.ts` — the `recruit` cast **restored** on `strategic_recruit_warband`.
- `undertakingT3Kinds.test.ts` — the "carries no cast" pin inverted, and asserted on the
  slot's *shape* rather than its presence; a second pin records why `reinforce` stays castless.
- `strategicActionLifecycle.test.ts` — regression guard, verified red without the fix.
- `edgeIntegrity.test.ts` — smoke window 120 → 150 ticks (see below).

## Measurements

All arms confirmed applied before running, seeds 42/99 × 150 ticks, medium — completions
**and** bands standing, because a cast that completes while minting nothing is the same
defect wearing the other face:

| Arm | seed 42 | seed 99 |
|---|---|---|
| cast, no fix (the filed defect) | — | 0 ok / 7 fail, **0 bands** |
| no cast, no fix (shipped baseline) | 15 ok / 0 fail, 5 bands | 15 ok / 1 fail, 9 bands |
| fix, no cast | 8 ok / 1 fail, 4 bands | 10 ok / 4 fail, 8 bands |
| **fix + cast (shipped)** | **12 ok / 0 fail, 9 bands** | **12 ok / 1 fail, 11 bands** |

Same engine, one variable: the cast is ahead on both halves on both seeds.

Undertaking throughput across four seeds at 120 ticks, `origin/main` → shipped:
**395→442, 180→318, 256→472, 378→481** completions. The fix raises undertaking
completions everywhere; it suppresses nothing.

`npm run census:undertakings` — **PASS, all seeds, all gates.** Rolled share 100%
(floor 50%), undertaking share 18.3% / 13.9% inside the envelope.

## The one gate that needed recalibration

`edgeIntegrity.test.ts`'s `trades_with > 0` vacuity guard went red. It was investigated
as a possible regression rather than assumed benign, and it is not one: `trades_with` is a
**rare** family — 1/0/0/0 occurrences across seeds 42/99/7/13 at 120 ticks *on `main`* — and
the extra people born by working mints move the world enough to push its first occurrence
past a 120-tick window. Trade routes still fire: seed 42 writes 5 by tick 250.

The window widened to 150 (the measured minimum that restores it — 180 yields the same
count for ~50% more runtime). **The assertion is unchanged and still falsifiable.** The
test carries a note saying not to raise the number reflexively next time: measure whether
routes fire at all before concluding it is the window.

## Left undone, deliberately

`strategic_reinforce_warband` stays castless, for a reason that is now recorded and pinned
rather than inherited. Its `targetRule` is `{ type: 'group_node' }`, so a cast slot's stage
resolves to a **group**, and a mint placed there gets a group id as its `locationId` —
measured: every mint landed `locationId → actor:group` (4 on seed 42, 1 on seed 99). Those
recruits stand on no hex and are invisible to `buildHexActorIndex`. The undertaking still
completes, which is exactly what makes it worth pinning. Giving that verb a cast needs a
location-tier stage first, which is a binder design question, not a content edit.
