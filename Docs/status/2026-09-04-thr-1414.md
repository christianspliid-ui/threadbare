# THR-1414 — whispers were generated all along; the queue deleted them nine ticks before the UI could show them

**2026-09-04 · Engine + UI · Bug · Project: Action System & Unlocks**

## What was wrong

The THR-1133 attended sweep polled `getOpenModals()` for `PremonitionModal` after *every single tick*
across four seeded runs (~280 ticks) and never saw one. The ticket's own hypothesis was that some gate
early in the chain was false for a debug-spawned NPC.

It was not a gate. A headless probe on a **generated** seeded world — not a fixture — measured this over
200 ticks:

```
[THR-1414 probe] pushed=8 survived-to-display-window=0 | gate verdicts (agent-ticks): not_idle=163 whisper_unavailable=26 already_pending=11
```

Eight whispers were generated. **Not one survived to the tick it was allowed to be displayed.** The gate
chain works; delivery was the defect, and no amount of staring at the gates would have found it.

The mechanism is a three-way contradiction between things that are each individually reasonable:

1. A whisper is born **only while the agent is idle** (`phaseDivinePremonition`, phase 2a.9).
2. It becomes visible `PREMONITION_DISPLAY_DELAY_TICKS` — **10 ticks** — later, and the UI selects on
   `tick >= showAfterTick`.
3. The same phase pruned any queue entry whose agent was **no longer idle**.

`phaseAgentDecision` runs immediately after 2a.9 **in the same tick**, and what it does with an idle agent
is commit them to an action. So the whisper was born at tick *T*, the agent stopped being idle at tick *T*,
and the entry was pruned at *T+1* — nine ticks before the window opened. The feature was unreachable by
construction, and had been since the display delay and the idle-prune first coexisted.

The two phases that merge this same queue disagreed about what makes an entry stale:
`phaseAgentDecision` filters on `eligibleUntilTick > tick` alone; `phaseDivinePremonition` added the idle
test. The sibling's rule was the right one.

## What shipped

**The fix** — `phaseDivinePremonition` now prunes on expiry only, matching `phaseAgentDecision`. Dropping
the idle test costs nothing the design asked for: a whisper's effect is a *decaying scoring bias on the
agent's next decisions* (design doc, 2026-04-04), so it stays meaningful after they pick up work, and
`eligibleUntilTick` already bounds its life. Same probe after the change: **8 pushed, 8 survived**.

**The gate chain is now one exported function.** `evaluatePremonitionGates` returns the first gate that
rejects (`not_an_actor` · `already_pending` · `tier_below_1` · `not_idle` · `whisper_unavailable` ·
`dissolved` · `no_nudge_candidates`) or null. The phase evaluates it and the probe attributes rejections
through it, so a probe that names a gate cannot drift from what production does.

**`window.__DEBUG.forcePremonition(agentQuery, 'whisper' | 'compulsion')`** — the lever THR-1133 pass 5
needs. The two arms are deliberately different because the two premonitions are:

- `'whisper'` builds the real whisper via `buildWhisperPremonition` (extracted from the phase loop, not
  reimplemented) and queues it with `showAfterTick` pulled to the current tick. A force lever that still
  made you wait ten ticks would be the same wait it exists to remove.
- `'compulsion'` **cannot** be built from outside: a compulsion is composed from the agent's actual scored
  encounter candidates, which exist only inside the decision phase. Rebuilding that scoring in the debug
  bridge would be a second implementation free to drift. So it arms a one-shot flag that bypasses the
  court-position and cooldown gates, and the *real* emit site produces a real compulsion on the next
  `tick(1)`. The flag never bypasses the one-live-premonition rule — two stacked offers on one agent is a
  UI state the game never reaches on its own — and the emitter clears it after one use.

## Verification

- Probe: `src/engine/__tests__/premonitionGateChain.test.ts` (heavy lane). It asserts *both* halves —
  whispers are generated, **and** they survive to their display window. The second assertion is the
  regression: it is what fails if the idle-prune or an equivalent returns.
- The probe carries its own vacuity guard (`ticksWithThreadedAgents > 0`), and that guard immediately
  earned its keep: the first run booted `initializeGameStateFromIdentity` alone and had **zero threaded
  agents**, because the `?seeded` route seeds The First in a separate `devSeedTheFirst` step. Without the
  guard the gate tally would have been an empty-population pass reported as a finding.
- `npm test` 19321 passed / 1156 files · `npm run test:heavy` 184 passed / 24 files · ratchet unchanged at
  2930 · `npx vite build` green · CLI smoke tick 30, 489 agents, 58 events.
- `Browser-verify substitution: jsdom-render — unattended run, no startable dev server` (#546).
  `src/components/Game/__tests__/forcedPremonitionRender.test.tsx` renders the shipped `PremonitionModal`
  with a premonition produced by the **real engine builder** — asserting the engine-generated vignette and
  every nudge option it carries appear, plus the closed-modal absence arm.

## Not done here

No wiki page's `sources` covers `phaseDivinePremonition.ts`, so premonitions are documented on no design-
wiki page at all. The ticket's alternative Done-when ("record the reason in the wiki page for
premonitions") was conditional on *not* fixing the gate; the gate is fixed. The `phaseAgentDecision` edit
is a dev-only bypass behind a flag nothing in the simulation writes, so the two pages it trips are carried
as `Wiki-freshness-exempt`, not silently updated.

The THR-1133 pass-5 capture itself still needs an attended session — that was always downstream of this
ticket, which owed it the lever.
