# 2026-10-12 — THR-1812: a chapter step committed on a paused clock stays on screen

**Ticket:** [THR-1812](https://linear.app/threadbare/issue/THR-1812) · plan `Docs/plans/2026-10-11-thr-1806-chapter-answers-on-screen.md` (cold playtest round 3, PC-8).

- **The card.** When a chapter step is committed and the clock will stay paused, the veil no longer closes onto a silent map. It becomes the answering card: "Stayed silent." or "Played: <cards>.", then "The world must turn before this answers.", then **Let the world turn** · Back to the map (`EncounterVeil` `answering` prop). Escape is *Back to the map*. The run button takes focus, so Enter presses it.
- **The run.** The new `useChapterAnswerRun` hook (a pure `stepChapterAnswer` state machine) runs the clock through the hold's existing `runIfHeld()`. When the answer's veil opens, `pauseIfHeld()` sets its return state to paused, so the god who paused stays paused. There is no forced resume. Pressing Pause mid-run turns the run into a waiting answer. The run is capped at `CHAPTER_ANSWER_RUN_MAX_TICKS` (24) and ends with a timeout toast if no answer comes. If the action goes away, a dropped toast says so.
- **The readout.** TIME reads "turning · until <chapter> answers" during a run and "paused · <chapter> answers when time runs" while an answer waits (`SimulationControls` `answerStatus`).
- **Running clock unchanged.** A commit with the clock running closes the veil as before.
- **Evidence.** 14 hook tests drive it with the real `useInterruptAutoPause`, plus 5 veil jsdom tests. Bash-vite and Playwright at 1920×1080 on *The Healer's Oath*: the card appeared; *Let the world turn* opened step 2 by itself with `wasRunningBeforeInterrupt === false`; *Back to the map* showed the waiting readout and Play opened step 3; a running-clock commit showed no card and the aftermath opened by itself. On The First's chapter (`firstunmet`, *The Tavern Brawl*) the card appeared too. `__DEBUG.getChapterAnswer()` reports the state.
