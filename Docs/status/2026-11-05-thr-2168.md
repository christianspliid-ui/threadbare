**A cast's receipt no longer contradicts itself.** Warm playtest round 3 found three faults. All three are fixed. (1) When a dream, conviction or spark lands but finds nothing to take hold of (the `found_nothing` overview), the receipt now carries `tookNoHold`. The dialog's frame line then comes from `RECEIPT_FRAME_LINES_NO_HOLD` and never from the band's "It went as you meant it to". (2) A hex-targeted cast names the place on the hex, or else its terrain, through `receiptTargetName` → `hexPlaceName`. It never names `hex_17_14`. An unknown node id reads as no name, so the "on …" clause is dropped. The Deep Eye's overview now says the reading waits on its reaction. Before, it paid 8 essence for no visible result. (3) The vague Read the Threads line names every count it totals (`vagueGroupSummary`, for example "4 encounters: 2 failed, 2 still unfolding."). Before, it read "4 encounters, 0 succeeded". The debug `fireAction` now accepts a `hex_COL_ROW` target. Tests: `playerReceipts-thr2168.test.ts` (every hex/location card cast on a hex, and every value-drifting cast), `ReadTheThreadsPanel-thr2168.test.ts`.
