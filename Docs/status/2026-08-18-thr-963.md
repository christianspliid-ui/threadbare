# THR-963 — detection pressure stops being priced in essence

**Shipped 2026-08-18.** `baseDetectionDeltaForCost` returned the `CHOICE_ESSENCE_COST_*`
constants — `1 / 2 / 3` — and the value it returned was added to a quantity clamped to
`[0, MAX_DETECTION_PRESSURE = 1]`. Two different quantities shared one set of constants:
essence is a whole-unit resource spend, detection pressure is a normalised fraction. The
smallest write the system could make (`small_breath 1 × 0.8` primary-sphere visibility)
was `0.8`, which already cleared `NOTICE 0.5` **and** `TURN 0.8`; at `1.0` or `1.2` it
cleared `ENCOUNTER 1.0` too and seeded a `shadow.rival_strike` on the spot. "Rivals are
starting to notice → rivals turn → rivals move against you" was unreachable by
construction: zero to saturated in one step, with the three bands crossed in the same
instant.

**The fix separates the quantities rather than dividing one by the other.** New
`DETECTION_DELTA_SMALL / FULLER / DEEP` = `0.15 / 0.30 / 0.50`, genuine fractions on the
pressure scale, sized against the three thresholds and the only sphere-visibility
multipliers the phase produces (`0.8 / 1.0 / 1.2`). A divisor constant would have worked
arithmetically and left the coupling in place — the next reader would still find pressure
priced by an essence constant, which is the shape that produced the bug.

**The ladder now arrives band by band**, and the numbers are pinned as literals in
`detectionPressure.test.ts` rather than read back off the constants (a test that reads the
same constant the code reads is a tautology, and would have passed just as happily on
`1 / 2 / 3`). At neutral visibility from a quiet region: fuller breaths reach *notice* on
the 2nd choice, *turn* on the 3rd, *encounter* on the 4th; small breaths take 4 / 6 / 7;
a deep draught is deliberately loud — noticed at one, saturated at two. The ticket's second
Done-when is pinned as a property rather than an example: a single `small_breath` sweeps
every starting pressure `0.00…1.00` across all three visibility multipliers and crosses at
most one band, which holds because `0.15 × 1.2 = 0.18` stays under the 0.2-wide
turn→encounter gap.

**Six tests fail on a revert**, including the ladder — verified by putting `1 / 2 / 3` back
and running the suite, not by inspection.

**Three suites encoded the defect and had to be corrected, not merely widened.**
`phaseDetectionPressure.test.ts` asserted that one `small_breath` commit emits an
`encounter`-band trace, and the contract test's `4.3` seeded a rival strike from a single
`deep_draught`. Those are the bug written down as expectations; they now assert the
graduated shape instead, and a new phase-level test pins that one small breath emits **no**
threshold trace at all.

**The defect was latent and stays latent.** `pendingChoiceCommits` has no live producer —
measured on `--seed 42 --map medium`, `state.regionalDetectionPressure` is still `[]` after
120 ticks — so nothing in a running game changes today. What changes is that the ladder is
correct whenever a producer is wired, instead of collapsing on its first write.

**Two findings beyond the ticket, logged as impediments #661 and #662.** The wiki-freshness gate went
green on this change while `stealth-rivals-reference.html` — the Manual page whose blurb
leads with region detection pressure — carried three passages the change falsified,
including an accuracy note prefixed *"verified against code this pass — do not 'correct'
back"*, which would have instructed the next reader to restore the wrong numbers. The page's
`sources` globs covered the *dormant* per-actor stealth model and the rivals, and never the
two modules implementing its headline system; both live one directory deeper than the
neighbouring page's `src/engine/encounter*.ts` glob reaches. The page is updated and both
modules added to its `sources`, so the next detection-pressure change trips the gate
normally.

The second (#662) is a tooling trap this session walked into: a Python file write on
Windows CRLF-ifies the whole file, git reports no change because `.gitattributes` forces
`eol=lf` on the way into the index, and `check:generated-freshness` — which compares raw
bytes against `git show HEAD:<path>` — then fails naming the *generator*. Re-running the
generator has no effect and every git-level check agrees nothing is wrong, which is what
makes it cost time.
