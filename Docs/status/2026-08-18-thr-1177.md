# Edge integrity — enforcement at the two generic writer chokepoints (THR-1177)

**Shipped 2026-08-18.** The THR-1176 audit's headline was that the fix is *two chokepoints, not thirty validations*: every edge family in the game reaches the graph through `graphOpExecutor.executeAddEdge` (content-authored `add_edge` ops, endpoints from sentinel resolution) or `strategicGraphOps.createRelationEdge` (which accepted any string at all as an edge type), and neither checked anything. Both now validate the edge type and both endpoints against `EDGE_SCHEMA` before creating, and refuse fail-soft — the op returns its failure shape with a loud `edge_schema_refused` trace, and nothing throws (NFP #4).

That closes the THR-1175 favour defect — a town becoming the debtor on a `owes_favor` edge every consumer reads as person-shaped — for **every family at once**, including content-authored ops whose cast sentinels bind ambient scenery.

## Measured, before and after

Seed 42, medium map, 120 ticks headless — the audit's own conditions, re-run rather than taken on trust:

| | before | after |
|---|---|---|
| total edges | 5,299 | 5,299 |
| `belongs_to` violations | 18 / 315 | 0 |
| unregistered types written | `sacred_route` ×4 | none |
| `EDGE_SCHEMA` families | 44 | 49 |

The identical edge count is the evidence that the guards refuse nothing *legal*: enforcement was added without a single valid write being lost.

## What the schema got wrong, and what that cost

Two rows had drifted, and **the order mattered** — enforcing before correcting them would have broken worldgen on day one:

- **`belongs_to`** was the only family with measured runtime violations, and the writer was right: `historicalCulture.ts` deliberately edges `region → culture`, and the row said `['actor','location']`. Widened.
- **`located_at`** declared a location-only target against a three-tier position model where sublocation targets are contract-legal. It measured zero violations — because the *canonical* sublocation writer mints them as `location` nodes — so the latent half is `strategicGraphOps.createSublocation`, which mints `type: 'sublocation'` and simply did not fire in that run.

Chasing that turned up the more interesting finding: **`'sublocation'` was off the `NodeType` union while being both written and read in production** (`encounterAftermath.ts`, `buildUnifiedEncounterStageModel.ts` both branch on the literal). Three `EDGE_SCHEMA` rows already named it, each a type error parked in the typecheck baseline. The union was what drifted, not the writers — so it was registered, which fixed those three errors for free.

Four families were registered that had never been: `commissions` and `issues` had **live writers** in `phaseFactionActions` and existed in neither the union nor the schema, so every edge they minted was unvalidatable by construction; `knows_spell` and `embodies_spirit_of` were `Record<EdgeType,…>` holes. The two dormant rows say so in their descriptions rather than pretending to be measured.

**`sacred_route` was registered rather than rejected**, against the ticket's stated default. Rejecting would have silently voided an eight-tick strategic project that shipped content already performs, and no existing edge type carries "this actor consecrated a pilgrimage route to this place" — the rewrite would have had to destroy the fiction to satisfy the registry. It has zero consumers, which is a real gap and is now a ticket (THR-1184) rather than a reason to delete authored content.

## The audit was wrong about one thing, and it was worth checking

The audit called the membership helper unguarded. It is not: `resolveFactionNodeId` already refuses anything not faction-shaped, so an individual→individual `member_of` cannot be minted through `joinFaction`. A guard was written there first and had to be **removed** — it rejected the bare `type: 'faction'` node shape the resolver deliberately tolerates, breaking a documented tolerance while adding nothing.

The defect the audit correctly named is reader-side, and that is where the fix landed: `getHighestFactionRank` read `rank` off *every* outgoing `member_of` edge, so a schema-legal individual→individual edge carrying a high rank handed its bearer a permanent leverage advantage sourced from a membership in nothing. It now filters by target shape — accepting all three the repo actually mints, because matching only `actorType: 'faction'` would have silently zeroed every company member's rank. Reader-side on purpose: twelve writers mint `member_of` and only one goes through the helper, and worlds already saved cannot be re-minted.

A `thread` source guard also landed: every consumer assumes the source is the ascendant reaching down, and `actor` is too wide to say so.

## Scope held

Promoting the dev-mode warn to a blanket hard-enforce inside `WorldGraph.addEdge` stays out — that is the machinery plan's warn→enforce ratchet (THR-1157). `trades_with` writes location→location against an actor→actor row and warns during the run; it is a genuine drift, separately ticketed as THR-830, and reaches the graph through neither chokepoint. It was deliberately not "fixed" by widening a row to make a warning go away.

Two deferrals filed: **THR-1183** (sublocations are minted in two incompatible node shapes) and **THR-1184** (`sacred_route` has no consumer).
