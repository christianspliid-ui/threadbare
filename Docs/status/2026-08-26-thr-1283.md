# THR-1283 — the stale-claim sweep no longer destroys the parks it can see are parks

**Shipped 2026-08-26.** Batches four failures of one mechanism in four days (impediments #703, #706, #752, #755).

## What was wrong

A **park** is `state: In Dev` ∧ `assignee: null` ∧ label `Parked`. It is the only shape `keep-work-flowing-cc` matches to surface a question under `## Needs Christian`, so a park that decays stops a director ask reaching the one surface Christian reads — silently, and for as long as nobody notices.

The stale-claim sweep destroyed four of them. Three separate defects, each independently sufficient:

1. **The release path never re-read the `Parked` label.** The detection pass checked it; the pass that actually writes did not. So applying `Parked` *in response to the sweep's own warning* — which is precisely what that warning instructs — did not save the issue. THR-1130 was released at 2026-08-22T12:51:57Z with the label attached, applied and verified five hours earlier.
2. **The sweep released issues with no assignee at all.** It exists to release stale *claims*; a null assignee means there is no claim. It had the fact in hand at the moment it acted — it wrote `previousAssignee: null` into its own trace — and did not use it. A park is the sweep's prime target precisely because a park never moves and so never looks like activity.
3. **The activity check was reading the wrong end of the comment list.** `comments(last: 10)` — but Linear orders that connection newest-first, so Relay's `last: N` returns the N *oldest* nodes. THR-1130 held 12 comments at release time and the grooming comment was the newest, so `last: 10` dropped exactly the two newest and signal (a) could not see it. On any issue with more than ten comments the activity check could not detect recent activity by construction.

Defect 3 was filed as an open lead ("do not assume defects 1 and 2 explain it"). It is now settled, with the arithmetic in a comment at the query.

## What changed

**Engine / infrastructure.** `scripts/stale-claim-sweep/index.ts` gains two release-path guards — `skip-parked` (with a new `phase` field distinguishing the detect and release passes) and `skip-no-claim` — ordered Parked-first, because a real park satisfies both and `skip-parked` is the more specific diagnosis. `labels` joins the `IssueDetail` selection set, since a guard cannot read what is not fetched. The comment and history windows read `first:` and are tunable constants at 50 rather than a hardcoded 10.

**Testability.** The GraphQL transport and the clock are now injectable, and the module has an entry guard. `LINEAR_API_KEY` is an Actions secret with no local equivalent, so before this the only way to run the release path was to let a scheduled run do it against the live board — which is exactly how this went four rounds before anyone could falsify a guard against it. Nine tests in `scripts/__tests__/stale-claim-sweep.test.ts` drive the real `sweep()` through a stubbed transport with a seeded tracked-list, so the release path genuinely executes. Every skip arm is paired with a falsification arm that removes one fixture field and asserts the release *does* fire.

**Process.** `pull-work` Step 3's mutex-liveness table gains the park row: a partner in `In Dev` with `assignee: null` is the **deadlock** row, not the live row — it is awaiting a human, not being built. With it, the partial-reversal rule (a mutex can bind some scope items and not others; the remedy is a split, not an all-or-nothing bounce), the restore-don't-claim rule for a `Parked` issue found in the queue, and the pre-write PR liveness check. The coordination protocol gains a § *The park shape* section carrying park-don't-consolidate, and its description of the sweep is corrected — it claimed the sweep "skips all `Parked`-labeled issues entirely", which was aspirational.

## What is worth remembering

The premise that closed off the fix was written down. Impediment #703 concluded *"the root cause sits in the sweep, which is not repo-side code, so this is a detection-and-repair rule rather than a fix"* — and the sweep is `.github/workflows/stale-claim-sweep.yml` plus `scripts/stale-claim-sweep/`, entirely ours. Three further occurrences were logged as detection-and-repair against a fix that was available the whole time. That row is corrected in place.

The second lesson is about evidence shape. This ticket's Done-when asked for a `workflow_dispatch` dry run showing `skip-parked` and then `released` — unreachable twice over: the workflow pins `ref: main` so a branch dispatch runs the old code, and a dry run emits `dry-run-would`, never `released`. The substitution is recorded in the commit body.
