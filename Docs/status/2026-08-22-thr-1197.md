### THR-1197 — the campaign's spine narrates, and the wiring found its own defect one layer up

**What was wrong.** `MANDATE_MILESTONE_PROSE` — 48 authored strings across the 12 mandate JSON files — had **zero production importers repo-wide**. The loader hard-threw defending it (`mandate-loader.ts:102–107` refuses any mandate JSON missing a prose key), so a content author was blocked from shipping a mandate without writing prose that then reached no player. Meanwhile `phaseMandate.ts` emitted **no `TickEvent` at all** for a stage advance — only sphere pressure — and its one completion event carried a hardcoded `` `Victory! Mandate "${name}" fulfilled!` `` while the authored `completed` string for that same mandate sat unread in the same process. `mandate-content.test.ts` was green throughout on shape-only assertions: the green-tests-on-a-dead-contract pathology the interface map exists to kill.

**Keyed map, not a field on `MandateDefinition`.** The ticket left the modelling call open. Remembrance mandates are generated at runtime by `generateRememberedMandate` and never pass through the loader, so a `milestoneProse` field would be structurally `undefined` on every mandate a live game creates — and a field that is *always* empty reads as "this mandate has no prose" when the truth is "this mandate family has no authored prose at all". The keyed map keeps one source of truth (the JSON) and makes the miss explicit and traceable at the call site via `ResolvedMilestoneProse.authored`.

**What shipped.** New `src/engine/mandateMilestoneProse.ts` is the single production consumer: `resolveMilestoneProse(mandateId, transition, fallback)` normalises the `mandate.` namespace, returns the authored line or the caller's generated text, and never throws (NFP #4). `transitionForStageChange` maps a stage move onto one of the four authored transitions and returns `undefined` for a non-advance, so callers emit nothing rather than a wrong beat; a `setup` → `culmination` jump — reachable when a sphere-growth mandate passes three checkpoints in one tick — reads as the later transition, because that is the threshold the world actually crossed. **Both** evaluators are wired: the sphere-growth path (milestone, completion, failure) and the legacy path (milestone, completion). The milestone event is deliberately **not** gated on `primarySphere` the way the pressure push is — the beat is worth narrating whether or not the mandate carries a sphere to press on.

**The `failed` key has a firing path, and it is the live one.** The ticket flagged it as a possible deferral. It is not: `failed = !completed && state.doomClock.expired` in the sphere-growth evaluator is a real site with a real event, now resolved through the authored string. The *legacy* evaluator has no failure site at all — recorded, not invented.

**The finding that outgrew the ticket.** The wiring is correct and the input is unreachable. Both production writers of `state.mandateDefinition` (`gameInit.ts:328`, `gameInit.ts:475`) call `generateRememberedMandate`, so every live run holds a mandate whose id is *generated* — `mandate.remembrance.{hunger}`. `generateMandate`, the only function returning a `MANDATE_TEMPLATES` entry and so the only route to an id the prose is keyed on, has **zero production callers** (tests only). Live confirmation, seed 42 / medium at tick 60: `state.mandateDefinition.id` → `mandate.remembrance.chaos_energy`, no authored prose, resolver correctly falls back. So the 48 strings are keyed to 12 ids no live game instantiates. This is exactly the shape the ticket anticipated for its `failed` key — *"a key with nowhere to fire is this ticket's own defect class one layer along"* — at the family level, and it is a genuine creative fork (does the run's spine come from what the god *remembers*, or from a named campaign the world *offers*?), so it went to **THR-1198** for a ruling rather than being invented here. The interface-map row is pinned **🟠 PARTIAL** against that ticket rather than the 🟢 LIVE the generator assigns mechanically — the consumer half is real, the producer half does not reach it.

**Falsified.** Disabling the lookup turns 2 of the 3 new wiring tests red; the third stays green because it *is* the fallback test. Expectations are **literal strings transcribed from `dominion-of-stone.json`**, not `MANDATE_MILESTONE_PROSE[key]` on both sides — a constant used as its own fixture is a tautology that passes whether or not the wiring exists. The shape-only assertions in `mandate-content.test.ts` were **joined, not replaced**, by two consumption assertions that go through the production resolver, proving the payload reachable rather than merely well-formed.

**Caught by a gate, worth recording.** The new `mandate_milestone_prose` trace category failed `trace-vocabulary.test.ts` until registered in all four required places (union, `TRACE_CATEGORIES`, payload interface, `TraceEntry` union). The gate did its job: an unregistered category is emitted faithfully and filtered out of the inspector, which would have made the fallback invisible in exactly the situation it exists to surface.
