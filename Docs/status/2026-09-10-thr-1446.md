# THR-1446 — the hand the draw deals is now a hand content can play

**2026-09-10 · Engine · Content · Encounter Experience**

## What was wrong

The Consequence Draw weights `thread` at **≥ 1 in all eight reaches** (iron 3, gold 2,
shadow 2, veil 6, heart 5, eye 3, stone 2, star 8), and the module header says that floor
is the design: every family should be able to surface in any reach. But no authored
encounter could wire `thread` in any of them.

`thread_strengthen` / `_weaken` / `_break` / `_branch` take a literal `ascendantId` and
`mortalId`. Neither field was in `SCENE_SENTINEL_FIELDS`, so `$actor` / `$target` /
`$cast:` could not bind them — and **the ascendant node id is minted per run** as
`asc.<archetypeId>`, so there was no literal an author could ever have written. The
handler looked for a thread edge between two strings that named nothing and skipped with
`thread_mutation_skipped · edge_missing`. Corpus census: zero shipped templates wired any
thread effect, and the one canonical *example* file wrote `'self'` / `'actor'` under an
`@ts-ignore` — a reference illustrating a shape that could never have run.

`place` had the sibling failure. It needs a condition carrying `targetLocationId`, and
`$target` binds a location only when the **card** targets one. Most encounters resolve
self-targeted (`targetId === actorId`, measured in the CLI on `sharpen_blades` and
`shrine_offering`), so the binder's kind check correctly refused and the effect no-opped
**silently**.

The cost was not theoretical: retrofit batch 2 drew both families and had to spend **two**
`consequenceSwap`s against a budget of one, and batch 3's single remaining encounter drew
the same pair.

## What changed

Per the recorded design call (options 1 + 2 + 4; option 3 — zeroing the weights — rejected
as shrinking the palette the header calls the design):

**`$ascendant`** — the player's god, resolved from `GameState.ascendantId`. It is the
first sentinel that names nobody in the scene, and that is exactly why it was missing: the
other four are scene participants and the ascendant is the player, standing outside. It is
the only sentinel that binds `ascendantId`; the kind check refuses the rest, because a
thread whose source end is a mortal is an edge no consumer reads.

**`mortalId` joins the table as its own kind, `mortal`** — `agent` minus the ascendant.
Deliberately a separate kind rather than a narrowing of `agent`: four shipped fields
(`targetAgentId`, `withAgentId`, `counterpartyId`, `debtorAgentId`) bind `$actor` on
divine encounters where the actor *is* the god, and tightening `agent` would have stopped
resolving them (NFP #6). A test pins that.

**`$here`** — the place the scene is happening at, read from the actor's `located_at` and
walked to the tier the field wants: a `location` field resolves up through
`resolveToParentLocation`, a `sublocation` field takes the Place itself. **It hops through
`properties.avatarId` first**, because an ascendant node carries no position of its own —
verified on a generated world (seed 42, medium): `asc.archetype.chaos_0` has
`located_at: none` and `avatar.archetype.chaos_0` stands at `loc.start`. Without that hop
`$here` would resolve to nothing on exactly the divine encounters that motivated it.

**The vocabulary moved to `src/engine/sceneSentinels.ts`**, imported by both the binder and
the gate. Adding a second consumer with a second copy of the field→kind mapping would have
reproduced impediment #725 on purpose — that table has grown six times, and each addition
documented itself *in the table* while the prose enumerations beside it rotted.

**The gate** — `sentinelBindabilityViolations`, wired into the Composition Contract's
`draw` band — fails a sentinel pointed at a field it can never satisfy.

## The gate is narrower than the one first written, and that is the finding

The first cut refused `$target` on a location field when the template's `targetCategories`
did not include `location`. That is the `sharpen_blades` shape exactly, verified dead in
the CLI, and it found **8 violations across the shipped corpus**.

**At least one was false.** `encounter.slice.the_table_that_holds` declares no
`targetCategories` — so the field defaults to `['actor']` — and is nevertheless resolved
against a **town** at runtime; `tableThatHolds-seedChain.test.ts` asserts the resulting
`reputation_with` edge lands on that town, and it went red. The bulk conversion of those 8
sites from `$target` to `$here` was therefore changing live behaviour, and was reverted.

`targetCategories` filters which cards a **player** may aim at a node. It does not describe
what an encounter resolves against when the world spawns it. Whether `$target` is a place
is a **runtime fact no template declares**, so the gate now rules only on what a field can
decide by itself and says nothing about `$target`. A gate that cries wolf is worse than no
gate: it teaches authors to skip the output.

The `sharpen_blades` class is now an authoring choice rather than a trap — `$here` exists,
always resolves, and says what those authors meant.

## Evidence

- `npm test` — **1200 files / 19789 tests green**.
- `npm run test:heavy` — 30 files / 202 tests green. (One earlier run showed a single
  failure in a seeded liveness contract; not reproducible across three subsequent runs and
  untouched by this diff. Logged as a flake, not a regression.)
- `npx vite build` — clean.
- `npm run check:encounter -- --all` — **checked 206, clean 27, failing 0, on ratchet 179**,
  byte-identical to the pre-change baseline. The new gate fires on nothing shipped.
- 30-tick CLI smoke, seed 42 / medium — tick 30, **493 agents**, 57 events.
- New suite `encounterAftermath-thread-place-sentinels.test.ts`, 21 tests, carrying three
  falsifiers: the pre-THR-1446 `'self'`/`'actor'` authoring still skips (so the passing
  case is the sentinels and not the harness); every sentinel but `$ascendant` is refused on
  the divine end; and `$target` is asserted **un**reported, pinning the false-positive
  lesson so it cannot be re-introduced.

## What this unblocks

THR-1130 — the encounter retrofit, and the board's only non-`Deferral` program work —
carries a `blockedBy` on this issue. Batch 3's `encounter.shrine_offering` rolls `thread` 8
+ `place` 4 against a swap budget of one; both are now wirable, so the batch can spend its
swap on fiction.
