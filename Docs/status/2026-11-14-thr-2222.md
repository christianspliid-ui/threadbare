# THR-2222 — two promises the screen kept breaking

**Shipped 2026-11-14.** Thematic Pressure & Living World · Warm playtest round 4.

- **The dropped-answer toast waits for the answer.** `useChapterAnswerRun` called an answer dropped on the tick the step resolved, before the engine posted its answer beat. All three paths now go through one check (`answeredWithoutBeat`): an answer delivered another way ends the record quietly; otherwise the run waits `CHAPTER_ANSWER_DROP_GRACE_TICKS` (2) for the beat, and only then toasts "ended without an answer on screen".
- **Delivered elsewhere counts.** New `isAnswerDeliveredElsewhere`: the chapter's Aftermath (also once read and marked resolved), or a beat for a later step, such as a *Lives on* beat with `autoResolveTick`. Moveless beats are records, not answers. This reverses the THR-1812 review-gate rule that a *Lives on* beat ends the run with the dropped toast; the ticket asks for it to count as delivered.
- **The return card names where the decision waits.** "It opens when you begin" became "Find it under Needs you on the top bar." (`ui.warm_recap.next_held`). Begin still only closes the card; making it open the held decision would mean driving the interrupt queue from the overlay. The ticket allowed either fix, and the reworded line keeps the promise.
- **Evidence.** `npm run gate`: test, typecheck, build PASS. New tests: a step resolving at T with its beat posted at T+1 fires no toast; an Aftermath already delivered fires no toast (running and waiting); a moveless beat still drops after the grace window. The recap test asserts the "Needs you" line. 1920×1080 screenshot of the return card on `?warm=3`; no held decision came up on that seed, so the held wording is evidenced by the jsdom test.
