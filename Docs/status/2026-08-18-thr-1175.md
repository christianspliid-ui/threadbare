# THR-1175 — a town cannot owe a social favour

**Shipped 2026-08-18.** A director probe on the re-passed Grateful Kin asked how the
favour it minted would ever be called in: *"if it is a graph edge, then you must have
created the edge to the town directly? so now the town, sacred grove, owes the favour?
… how would a town and a person interact in a deep social scene?"* It would not, and
could not. `favor_creation` set debtor = `action.targetId` unconditionally; that
encounter targets a **location**; so Sacred Grove became the debtor of an `owes_favor`
edge, and the chip reported it truthfully.

**The defect is not that the edge was off-schema — it is that it was uncollectable.**
`edgeSchema.ts` has declared `owes_favor` as `actor → actor` all along, but the schema
layer only *warns* in dev mode, so the declaration was decoration. The deeper problem is
downstream: every consumer of `owes_favor` is **individual**-shaped. Social leverage reads
a favour only when the creditor targets the debtor in a deep social scene; tension drift
moves sentiment on the debtor's `relates_to` edge; call-in and break fire from
person-to-person interactions. A place is in none of those code paths, so the only code
that would ever touch the edge again was the expiry sweep that deletes it ~80 ticks later.
Real, well-formed, correctly anchored, gate-passing — and inert. This is the THR-1165
lesson one level up: **well-formedness is checkable; reachable consumption was not.**

**Four layers, because the defect had four places it could have been caught.**

*The graph layer refuses it.* One shared endpoint check in `secretGeneration.ts`, two
callers (the THR-1176 audit asked for `createSecretEdge` alongside `createFavorEdge` —
same file, same bare-id pattern, same person-shaped consumers). An `owes_favor` debtor
must be an **individual** actor; a creditor, discoverer or subject need only be an actor.
Refusals emit one loud trace naming which endpoint was wrong and what the node actually
was, because "refused" alone does not tell a content author what to change. Fail-soft
throughout (NFP #4): a refusal returns the caller's didn't-happen value and never throws.
Deliberately **not** narrowed on `knows_secret_of` — a faction subject is legal there and
shipped content relies on it, so refusing it would delete live content to fix a different
family's problem. The guard refuses a *known-wrong* subtype rather than an unknown one:
every real producer sets `actorType`, so faction/culture/god debtors are caught by what
they declare, while an actor node missing the field is malformed data rather than the
wrong kind of thing. Node type is the unambiguous half and is checked strictly — a
location can never pass.

*The authoring layer makes you say who owes.* `favor_creation` gained `debtorAgentId`,
registered in the scene-sentinel table as an `agent` field, so `$cast:<key>` binds the
scene's persistent person and the kind check refuses to bind a location. `$target`
re-states the old behaviour explicitly for encounters that genuinely target people. The
historical fallback to `action.targetId` is **kept**, not removed (NFP #6): removing it
would silently drop favours from shipped content instead of refusing them loudly.

*The gate makes it unauthorable.* `validateFavorDebtors` — the third shape in this
liveness family, after dead grant ids (`validateNudgeGrantRefs`) and empty pools
(`validateRewardDrawPools`). Not a reference that names nothing, not a query that selects
nothing, but a write whose consumers all exist and none of which can fire for the operand
it will receive. The predicate is deliberately "must declare", not "must declare
*correctly*": nothing static can prove where a sentinel binds at runtime — that is the
graph layer's job — but authoring time can insist a choice was made.

*The content stops needing it.* The fiction was never a person-debt. "There is a roof in
this town that opens for them now" is a property of the **place**, and places have carried
conditions since THR-1143. All three Grateful Kin bands now write
`trait.condition.location.standing_welcome` via `apply_condition` + `targetLocationId:
'$target'`, at three intensities (`0.55 / 0.75 / 0.3`) so the crit and fumble bands say
*warmer* and *cooler* rather than teaching the player a second mechanic. The chips'
`visualKind` moved from `'agent'` to `'location'` — the old value was the second half of
the same bug, a location entityId declared as an agent, which is what rendered the
fallback "A" tile in the director's screenshot.

**The condition ships with a live reader, which is the whole point.** `standing_welcome`
is the first location condition a person *earns* and the first that reads positive; the
other five are things that happen to a place. `LocationProfileModal` renders it today, and
THR-1172 (merged two hours earlier) made the chip's location anchor click through to
exactly that surface — so a player reading the ending can open Sacred Grove and see what
they were promised. Asserted in `LocationProfileModal.test.tsx`, including the Law 14
negative. Shipping it without that reader would have been the same defect in a new coat.

**Falsified in both directions, not merely watched.** Neutering the gate predicate reds
three rows by name. Restoring the pre-fix template and re-running the same command reds the
real encounter at its three exact sites — `aftermath.fallback.slice.kin.accept_the_debt`,
`…critical_success.slice.kin.accept_the_debt_well`,
`…critical_failure.slice.kin.accept_the_debt_awkwardly` — and the fixed one is clean. The
corpus regression is pinned by **absence** rather than by "declared", because this scene's
honest shape is a condition: a future edit re-adding a favour here with a plausible
sentinel would pass the general gate while re-opening the exact defect.

**Two type errors were owed and nine were repaid instead.** `secret_discovered` and
`favor_created` had been in `TRACE_CATEGORIES` since THR-30 with **no declared payload**,
so they were absent from the `TraceEntry` union and all five of their emit sites were type
errors sitting in the THR-489 baseline. Declaring `SocialLeverageEdgeTrace` was the actual
fix — the ratchet went **3160 → 3151** rather than 3160 → 3162, and the next author to emit
one gets checked instead of baselined.

**What this does not do.** The director's fix named a second half — a seeded return
encounter, *"the roof actually opens, on screen"* — which is a new full-contract template
in the `encounter.*` namespace and therefore governed by Encounter Factory ruling 2
(agent-drafted brief, Christian-approved in chat, before authoring). An unattended lane
authoring it would bypass that gate, so it is filed as **THR-1182** with the brief step
first. The welcome is honest and visible today; it is not yet walked back into.
