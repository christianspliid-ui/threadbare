# 2026-10-15 — THR-1887: a pickup run checks for a live sibling before every claim

**Ticket:** [THR-1887](https://linear.app/threadbare/issue/THR-1887). On 2026-10-14 the 03:31Z pickup run (killed, then resumed at about 06:45Z) and the 06:45:26Z scheduled run both claimed THR-1839 and built it twice (PRs #2366 and #2367). Engine / Content / UI: N/A (harness process).

- **Most of the fix had already shipped as 65c2ba2d** (impediment #1194). In that commit, pull-work Step 1.6 asks the app (`list_task_runs`) how many pickup runs are active and stands down on two or more, and a resumed session repeats the check. But that check ran only on the resume path and in the Step 0.8 unstick duty. Both runs on 2026-10-14 made a *fresh* claim, so they never reached it.
- **Now the check runs immediately before every fresh or drain claim** (pull-work Step 4 / wrapper step 2, the `tb-opus-pickup` prompt). Each run's row is `running` while it checks, so of two runs that overlap, at least the one that checks second sees two rows and stands down. At most one claims.
- **A resumed run whose last board read is older than 20 minutes starts again from Step 1** (`PICKUP_CADENCE_MINUTES`).
- **The session marker from the ticket is not built.** The run list replaces it. It needs no write, and it does not have to guess whether a session is still alive. Step 1.6 gives the reasoning.
- **PR #2367 is closed unmerged** with a pointer to #2366. Its timeout fix had already shipped under THR-1927 (#2404).
