# THR-1299 slice 4 — the badge, the arc panel, and the follow toggle on both surfaces

**2026-09-02 · code.** Plan doc 5/6 of Proactive Agent Actions ships as six strangler slices. This is slice 4: the moment badge on thread rows, the JourneyTab rebuilt as the arc panel, ambition flavor surfaced, and the follow affordance on the arc panel and the encounter veil. The calling and the Freeholds label are slices 5–6; the ticket stays In Dev.

## The badge — the fourth tense

`momentBadgeModel.ts` + `MomentBadge.tsx` join the family (`encounterBadgeModel`, `threadTugBadgeModel`, `entityNoticeBadgeModel`) and are shaped like the other three, so a thread row reads as one vocabulary in four tenses: about to happen, happening, happened to them, *their long work turned*. It counts every unacknowledged record within `MOMENT_BADGE_RETENTION_TICKS` (48) per mortal — presentation is not a filter, so an interrupt the veil hid and a badge-tier founding both count. Clicking puts the newest record in the same `pendingMoment` slot the interrupt uses, so a badge-opened card and an interrupt-opened card are one surface (Law C1). **Nothing is cleared by the click** (Law 40): in the browser the count read 3 while the card was open and 2 after Acknowledge.

## The arc panel

The "future update" stub is gone. Top to bottom: the follow row (last seen + toggle), **The Work** (each live undertaking as a card — name, dots + `getUndertakingProgressWord`, last band via `stepOutcomeWord`, the halts sentence), **Ambitions** (`IntentSection` gains the template's own first `selectionProse` line as a flavor row under the name — the same line the assignment event narrates with, so sheet and chronicle tell one story), and **The Arc So Far** — `getAgentArc` in `src/engine/agentArc.ts`, assembled from persisted state only: strategic history, completed ambitions, and the moment records still queued. The 48-tick digest is deliberately not a source; an arc outlives it. Time renders through `durationLabel` — *today*, *two days past* — so no numeral escapes and the game keeps its decision not to build a calendar.

## The follow toggle — one state, two surfaces

`FollowToggle.tsx` renders the three-way read honestly: *Not following → Follow*, *Following → Unfollow*, *Followed by bond → Mute*, *Muted → Unmute*. The gesture is decided by the single writer (`unfollowAgent` chooses mute or removal from the state of the world), never by the surface. It sits on the JourneyTab header and, compact, on the EncounterVeil context strip beside the subject's name — both routes through GameView's `handleToggleFollow`, which stamps the trace's `source` as `arc_panel` or `encounter_ui`. Verified: The First read *Followed by bond*, one press made `mutedAgentIds` carry them and the label read *Muted*.
