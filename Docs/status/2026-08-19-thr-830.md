# THR-830 — `trades_with` declared its true shape, and four dead readers woke up

**Shipped 2026-08-19.** Filed as a one-line schema correction. It turned out the wrong line had been read as documentation by four separate consumers, each of which had been walking to a place trade routes have never been.

## The verdict, and the evidence it rests on

The ticket left one thing to settle first: is `trades_with` genuinely polymorphic — in which case declare the union `["actor","location"]` — or is it location-only, in which case narrow and correct the fixtures? The promotion comment set the test: **the union is right only if an actor-sourced producer turns out to be real.**

It is not. Measured, not argued:

- **The live world writes location → location, 100% of the time.** A 120-tick seeded run (seed 42, medium) creates 5 routes and emits exactly 10 `[GraphSchema]` warnings — two per route, both saying `should be "actor", got "location"`. Zero actor-sourced routes exist at any point in the run.
- **`createTradeRoute` (`strategicGraphOps.ts`) is the only producer that lands an edge**, and it takes two location ids by signature.
- **Every actor → actor site in the tree is a test fixture** — twelve files' worth.
- **The one production actor-sourced op writes a third shape.** `action.gold.establish-trade` carries `add_edge trades_with $actor → $target`, and `unifiedCandidates.ts` sets `targetId: locationId` unconditionally (its own comment: *"target is always the location"*). So it resolves to `actor → location`, which **neither** candidate row permits. It is not evidence for actor → actor; it is a separate defect, filed as THR-1188.

So the row is narrowed to `location` on both ends. Widening would have silenced the warning while proving nothing, and it would additionally have *unblocked* those four `action.gold.*` ops to write a shape `tradeRouteMarkers` cannot place on the map and `armySupply` / `battleAftermath` cannot walk. THR-1177 had already flagged that trap in this file's own scope note — *"deliberately not 'fixed' by widening a row to make a warning go away"*.

## The part the ticket did not predict: four readers had believed the row

A wrong declaration does not sit still. It gets read, and code gets built to match it. Four consumers had been reaching for routes on *actors*, and each therefore found nothing in every run since it shipped:

| Consumer | What it was doing | Consequence |
|---|---|---|
| `phaseProsperity.computeTradeTarget` | Walked a settlement's incoming `located_at` to the people standing there, then read *their* routes | **No settlement has ever received a trade bonus.** The arteries the wiki describes fed nothing |
| `proseResolvers.tradeRouteResolver` | Same hop, for prose | Silent in every run since it shipped |
| `sublocation.checkTradeRoutePresentAtLocation` | Same hop, gating Caravan Rest | The `trade_route_present` condition could never be true |
| `phaseEconomicTraits.countControlledRoutes` | Scanned every `actor` node's outgoing routes | Always zero, so trade-baron was unassignable |

All four are repointed to the location tier — which is what each one's own name and doc comment already claimed it did. `computeTradeTarget` also read **outgoing only** on a bidirectional family, so it would have undercounted even on a world that fed it.

Two honest qualifications. **The prosperity bonus is now live but small**: 5 routes over 120 ticks, each expiring, so the mechanism matters more than the current magnitude — it will scale if route creation does. **Trade-baron stays unreachable**, now for an unrelated reason: its only writer of `controlledBy` is `action.gold.tax-trade-route`, one of the four ops THR-1188 covers.

`graphQueries.getTradeRoutes` was **retired** rather than repointed. It read routes off an actor id, had zero production callers, and its only remaining effect was a green test asserting a dead contract.

## The regression guard, and why it needed three parts

The obvious test — the existing 120-tick zero-violations sweep — **cannot make this claim**, and its own scope note said so: it inspects the *final* graph, and these routes expire before tick 120. The family escaped by being absent at the end.

So the harness now records the run as it happens: a `console.warn` capture and a creation-time census that a later removal cannot erase. Three assertions, each blocking a way the other two could pass while saying nothing:

1. routes really were created (else "no warnings" is a world that never exercised the family);
2. no `trades_with` warning fired at creation time — the actual Done-when;
3. no *other* family started warning, so a future row correction cannot be graded on its target family while breaking a neighbour.

Plus a row pin, so nobody re-widens to the union without this failing and having to say why.

**Falsified before trusted.** Reverting the row to `actor`/`actor` with the tests left in place turns **2 tests red** — `expected [ …(6) ] to deeply equal []` and `expected 'actor' to be 'location'`. That is the run separating a guard that proves the change from one that merely survives it.

## Fixtures corrected, not grandfathered

Eight test files carried actor-shaped routes; narrowing would have moved 181 warnings from the world into the suite. All eight are corrected to location → location, and where a fixture existed only to feed an actor-shaped walk, the test was rewritten to the claim that now holds — e.g. *"deduplicates trade edges seen from multiple actors"* became *"counts a route once when the location is both ends of it"*, since a self-loop is the only way a single edge can now be seen twice. Suite-wide `trades_with` warnings: **181 → 0**.

Six files needed nothing — `tradeRouteMarkers`, `armySupply`, `economicVerbs.thr618`, `rivalSchemes`, `economicPower`, `routeEvents` were already location-shaped. Those are the tests written most recently around the real system, which is its own corroboration of which shape is true.

## Evidence

1044 files / **16,964 tests green**; ratchet **3129 unchanged**; `vite build` ✓ 12.24s; 30-tick engine smoke reaches tick 30 with 384 agents and 42 events. Four wiki pages updated in the same PR (settlements-economy, livelihoods, traits-marks, attention-story) — each documents a system whose behaviour genuinely moved.
