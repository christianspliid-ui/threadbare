# THR-2083 — The army-longevity heavy test fits its job again

**Shipped 2026-10-27.** Continuous Improvement. The heavy run on the THR-2082 fix's merge (c5e5a3f7, run 40511962211) was cancelled at the 45-min job timeout with `armyLongevity.heavy.test.ts` still running, so main stayed red and THR-2082 was unverified on CI.

**Cause.** Not a hang and not an engine change. The only diff between 998b05f0 (where the test passed in 872.7 s) and c5e5a3f7 was a test edit in `peopleThingsCells.test.ts`. The cancelled run's runner was ~1.6× slower on every heavy file (`engagementWindow.invariant` 175 s → 276 s, `doomIdentityMilestones` 55 s → 82 s). That stretched the 90-day army run past the job. The test's own 40-min budget sat inside the 45-min job, so the slowness surfaced as an anonymous cancel.

**Measured.** A per-day probe on seed 42 medium: a day costs ~2.5 s at the start and ~13 s by day 80, so days 46–90 were ~70% of the run. Over days 1–83 the map fielded 3–6 armies every day and the largest realm never lost its army, so the second half added nothing either predicate reads. The re-raise predicate is vacuous on this seed at either length.

**What changed.** `DAYS` 90 → 45 (still spans the original failure, 0 armies by day 30, and the 12-day re-raise window). `BUDGET_MS` 40 → 15 min, with its measurement and reason, so a slow run fails by name below the job timeout. `heavy-tests.yml` is unchanged.

**Evidence.** The test alone: 1/1 PASS in 203.6 s locally (was ~10+ min). `npm run gate` PASS (test, typecheck, build, encounter, god-cards, ui-debt, cli-smoke). The Done-when (`Heavy simulation tests` green on the fix's merge commit, which also confirms THR-2082) is settled by CI after merge.
