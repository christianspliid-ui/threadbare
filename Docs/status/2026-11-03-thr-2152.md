# THR-2152 — The essence rail's spend mark draws at the Law 11 glyph floor

**Shipped 2026-11-03.** Onboarding & First-Run Experience. A bug filed by the THR-2149 review gate. No plan doc; the ticket was self-scoped.

1. **`EssenceBlock.tsx`.** The per-row spend mark no longer passes `size={10}` to `DeltaCluster`. It takes the cluster's default, `DELTA_CLUSTER_GLYPH_SIZE_PX` (14). The number of ▼ is how much was spent, so it now reads at the floor Law 11 sets for a glyph that carries meaning.
2. **Test.** `readableSpend.test.tsx` gains "draws the spend mark at the Law 11 glyph floor". It renders a 5-Mind spend and asserts the cluster's font size is at least `DELTA_CLUSTER_GLYPH_SIZE_PX`.

**Browser evidence.** Worktree Vite on port 5297, Playwright at 1920×1080, `?view=game&seeded&size=medium`. `grantAction('whisper_insight')` → `armCard` → `chooseArmedTarget('agent', …)` → `castArmed()` spent 5 Mind (38 → 33). Measured during the flash: the cluster reads ▼▼ at 14px (both inline and computed). The row stays 38px tall, like every other row, with `scrollWidth == clientWidth` (142). It does not wrap. Screenshot: `Docs/evidence/thr-2152/thr2152-essence-rail-1920.png`. Console: 0 errors. UI Laws checked on the rail: 1, 11 (the fix), 13/14 (no new number), 17, 21, 33 (in viewport, no page scroll), 37.

**Finding, filed as THR-2153.** The essence row is 142px wide and has no room for any spend mark. With the old 10px mark, "Mind" was already clipped to "Min…" and the fill bar went to 0px during the 2.5s flash. With the 14px mark it clips to "M…". THR-2148 rewrites this row's balance into "53 / 55" and has to lay the row out again anyway, so THR-2153 is marked to fold into it.
