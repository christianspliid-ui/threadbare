# THR-1306 — the complication that read a missing reputation as ruin (2026-08-27)

THR-1304 closed six birth-path defects and its #4 was `npcGraduation` stamping
`reputationScore = 0` onto a walk-on that had never carried the field — below
`LOW_REP_THRESHOLD` (0.1), so promotion handed the NPC a `DEATH_CHANCE_LOW_REP` roll every
tick thereafter. This ticket is the same defect one file over, filed at the time rather
than widened into that diff.

`src/engine/complicationEffects.ts`'s `reputation_delta` case defaulted a missing
`reputationScore` to **0** before applying the delta. Four other delta-writers in the
engine default it to `DEFAULT_REPUTATION` (0.5) — `orchestrator.ts:1431` and `:1437` on the
actor and target legs, `phaseReputationDecay.ts:22`, and `encounterAftermath.ts` on both of
its paths. This case was the sole outlier.

## Why the 0 was a writer problem, not a cosmetic one

The line beneath the read is a write. `clamp(0 + delta)` was persisted back onto the node,
so a complication carrying any negative delta landed a fieldless agent at or near 0 — under
the deaths loop's own threshold — from a starting point every other reader in the engine
calls neutral. One complication, and the agent draws a death roll every tick for the rest
of its life.

The exposed population is narrow after THR-1304: newborns and graduated NPCs now both carry
the field. What remains is `npcSeeding`'s walk-on actors, whose property bag
(`npcSeeding.ts:275-285`) is `actorType`, `spotlightTier`, `npcRole`, `importance`,
`sphereAffinity` — and no `reputationScore`. Confirmed by reading the writer, not inferred.

## The seam, and why this one

The ticket left the choice to the executor: fix the reader, or have `npcSeeding` write the
field at seed time. It argued the second is broader because it closes the class rather than
one instance.

**Fixed the reader.** The census reverses which one is broader. Every *other* reader in the
engine already defaults a missing value correctly, so seeding the field would repair a
population that nobody else mishandles while leaving the one genuinely inconsistent
call site intact — still wrong for any future producer that writes a sparse actor. Fixing
the reader closes the class in the direction the class actually runs: this writer, every
fieldless population, including ones not yet written. It is also the additive, minimal
change (NFP #6), and it makes the file agree with its four siblings instead of adding a
second convention.

Lazy defaulting is the established pattern here — `agentValidation.ts:229` already treats an
absent `reputationScore` as acceptable, and `phaseReputationDecay` materializes the field
on every individual the first time it runs.

## Evidence

The Done-when required the assertion go **through the deaths predicate**, not by reading
`reputationScore` back off the property bag — the same rule `birthPathDefects.test.ts`
states, and for the same reason: this is a producer and a reader disagreeing about a field,
so a test inspecting what the producer wrote would have passed all along.

`complicationReputationDefault.test.ts` (7 tests) runs `phaseAgentLifecycle` and asks
whether the node survived; death removes the node outright, so absence is the verdict.

The fixture's lethality is asserted rather than assumed. With exactly one individual in the
graph the deaths loop short-circuits for healthy agents and draws nothing, so the first
draw of `mulberry32(seed + tick * 71)` *is* that agent's death roll — seed 42 / tick 62 puts
it at 0.01930, under `DEATH_CHANCE_LOW_REP` (0.02). Two control arms pin it: an agent
already below the threshold dies at that tick, and the same agent at `DEFAULT_REPUTATION`
survives it. Without the first, every "survives" assertion could pass on a tick whose roll
never goes against anyone.

**Falsified before trusted.** Run against the reverted default, 3 of 7 fail — exactly the
three regression arms — while both control arms and both unchanged-behaviour arms stay
green. That split is the point: the test isolates the default, not the tick. The two arms
that pass either way assert the fix does *not* change the rule — an agent genuinely at 0
still dies, and an agent carrying 0.12 that takes −0.05 still falls through the threshold on
its own arithmetic.
