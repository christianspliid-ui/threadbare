# 2026-09-24 — THR-1543: fight block FB7 — the block, the template, advantages, allies, events

**Ticket:** [THR-1543](https://linear.app/threadbare/issue/THR-1543) · **Project:** Physical Conflict · **Plan:** `Docs/plans/2026-09-23-fight-block.md` §11–12 + content · **Pillars:** Engine, Content, UI (the attended forecast, the veil header, the past-step labels).

## What shipped

- **`fightBlock(spec)`** (`src/data/fights/fightBlock.ts`): one nerve step plus up to three clash steps, with the defaults stamped (placeholder difficulty, duration, `continue_weakened`, heart/iron) and default afterimages for all six bands on both roles (a new `nearMissAfterimage` carries "trades blows"). `compile-encounter` pre-expands a package's `{ "fightBlock": … }` step. The terminal rule and "no reward pool on a fight step" are catalog-wide invariants. A terminal fight block is now the third producer of aftermath variant keys (`fight:<result>`).
- **`fight.lair.confront`** ("The Beast in Its Den"): the first fight template. It is spawn-only (no location subtypes), sits at the attended tier and deals the god's hand. It is registered in `MONSTER_ENCOUNTER_TEMPLATES`, and the `fight.` prefix is claimed for the encounter kind.
- **Advantages** (`readFightAdvantages`, pure): old wound, their secret, a favour called, company (capped at three, never the opponent), Storied arms, Blessed, Cursed. Each is a named term on the roll and a factor line on the forecast. Only the handler spends them, through the existing writers: the favour via `redeemFavor`, once per fight, and the secret via the reveal path after the clash it applied to. Neither edge is removed, and an appointment's favour is never touched. Fight steps already skip the company group step, so allies count once.
- **Mid-fight events**: a `requires.inFight` complication requirement, four handler-applied effect types (`fight_momentum`, `fight_clock`, `fight_offer_quarter`, `fight_condition`) and twelve `complication.fight.*` entries. A fight step draws only these, and an ordinary step never draws them.
- **The odds shown are the odds rolled.** The attended forecast now reads `resolveFightStepInputs` and `forecastActionAtScale` (new `src/engine/scaledForecast.ts`), which apply the core's scale step and its post-roll floor. The veil header, the Whisper's next demand, Scene So Far and the chapter archive show the reach and difficulty the step actually tests. The roll's input derivation was extracted (`deriveStepRollInputs`), so a dry-run probe (`previewStepProbability`) uses the resolver's own math.
- **Debug:** `spawnFight`, `getFightState`, `inspectOpponentCard`, `getFightForecastCheck`; CLI `spawn fight`; `npm run calibrate:fights`.

## Evidence

- **Calibration** (400 fights, THR-1531 "Major elite" × "bold guard"): won 2.5% (target 2), broke off 79.0% (79), yielded 0.0% (0), routed 4.8% (5), struck down 13.8% (14). Mean segments 1.25 (1.3). Every class is within 0.5 points. The run is also a standing test (`fightCalibration.test.ts`).
- **Browser** (worktree Vite + Playwright, 1920×1080, `spawnFight` against Nieve, a derived card): forecast threshold equals resolver threshold four ways: plain 30/30, with a card 38/38, at the regional floor 20/20, sub-floor with terrified 20/20.
