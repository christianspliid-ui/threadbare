### 2026-10-04 — THR-1726: the bridge keeper has her name back

**The bug.** The Unsafe Bridge's step prose read "The keeper, , takes two coppers a crossing" on the deployed build while the cast list beside it named Halda Brenn. Riders Behind the Caravan had the same defect ("The caravan master, , says…").

**Root cause.** `resolveSceneCastContext` (`src/engine/proseEnrichment.ts`) capped the `{cast:*}` map at `CAST_CONTEXT_MAX_MEMBERS` (6) by bundle *position*. Both slice bundles compose the wayside and rural setting defaults (three keys each, THR-1567 widened them to rural) *ahead of* their own subject, so the subject was the seventh key and was cut; `enrichProse` then stripped the token to "". The binding, the node and its name were all fine.

**The fix.** The cap now admits by priority — the scene's own bound member, then any bound member, then the scene's own unbound spec, then unbound setting defaults (ties in bundle order) — and the map is still emitted in bundle order. "Scene's own" is any delivery other than `pre-seeded`; every inherited default is `pre-seeded`. A bound node with an empty name now falls through to the authored name (`||`, not `??`). The cap value is unchanged.

**Evidence.** `src/engine/__tests__/sceneCastContextCap.test.ts` (3 tests): a corpus-wide graph-free lock (every declared key any template's prose names is in the cast context with nothing bound — on the pre-fix tree it lists exactly `unsafe_bridge → {cast:bridge_keeper}` and `riders_behind_caravan → {cast:caravan_master}`), a unit lock on the admission order, and a live lock staging the five slice encounters on a generated world and reading the stage prose (no ", ,", no raw `{cast:`). All three fail before the fix and pass after. `npm run gate`: test, typecheck, build, encounter, cli-smoke, test-heavy all PASS. Browser (worktree vite, 1920×1080, `?spawn=encounter.slice.unsafe_bridge`): "The keeper, Halda Brenn, takes two coppers a crossing and swears it holds."; `getOpenModals()` → `["EncounterVeil"]`.
