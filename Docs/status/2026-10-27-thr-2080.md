# THR-2080 — The seeded world no longer ends at tick ~41

**Shipped 2026-10-27.** Thematic Pressure & Living World. Found by the first weekly ux-review (mid-game moments): `?view=game&seeded&size=medium&warm=300` arrived on "Witness Ascendancy, fulfilled".

**What changed.** A sphere-growth Mandate measures growth against a baseline taken at init, before tick 1. Tick 1 mints ~70 sublocations (caravan rests, mines, smugglers' dens) whose sphere bags reach the aggregate on tick 2, and that arrival read as ~19% Mind growth — over half the Mandate with no god acting. Since THR-1381 a fulfilled Mandate ends the age, so the seeded world ended early. `evaluateSphereGrowthMandate` now counts nothing before `MANDATE_BASELINE_SETTLE_TICK` (2, in `game-config.ts`): progress stays 0 and no checkpoint is evaluated. At that tick it re-takes `primaryBaseline` / `secondaryBaseline` from the live aggregate onto the definition (which is in `GameState`, so saves carry it), stamps `mandateState.baselineSettledTick`, and emits one `mandate_baseline_settled` trace. The false comment in `phaseDoomExpiry` is corrected. `devSeedAscendantTestPackage`'s `progress: 0.67` is left as is: tick 1 already overwrote it, and still does.

**Evidence.** `npm run gate` PASS (test, typecheck, build, encounter, god-cards, ui-debt, cli-smoke). New `mandateBaselineSettle.test.ts` (4 tests); `objectiveRuntime.test.ts` fixtures marked as settled worlds. Census with the design lane's `_scratch-2080.ts` on this branch: `?seeded` medium seed 42 is still `playing` at t300 with and without the test package (Mandate 0.50); progress at t2 is 0.000 on CLI seeds 42/99/7 (was 0.71/0.56/0.60).

**Next.** The live warm route (`stoppedEarly: null`) is confirmed by the next deploy + ux-review. Whether the world's own drift should count toward the Mandate is [THR-2081](https://linear.app/threadbare/issue/THR-2081).
