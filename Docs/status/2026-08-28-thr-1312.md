# THR-1312 — every lair in the world had the same name as its loop index

**Shipped 2026-08-28.** Engine + Content pillars. UI N/A by path — no component file
changed; `HexSidebar` already renders `loc.name` verbatim, so the surface improves
without being touched. Deferral filed at THR-1297 slice 6 closeout.

## What was wrong

Both lair writers named their node with a counter:

- `lairSeeding.ts` — `` name: `Lair ${lairIndex}` ``
- `lairEscalation.ts` — `` name: `Lair (spawned t${tick})` ``

Measured on seed 42 / medium / tick 30: **17 of 17 lairs**. Not an edge case and not a
fallback — it was the only naming path lairs had. The escalation form is the worse of
the two, because two lairs spawned on the same tick were *the same string*.

The reason this stopped being cosmetic is THR-1297 slice 5: `wandererStrategicPack`
made wilderness a primary destination for a whole behaviour family, and the field
survey found **700 of 798 idle decisions happening at lairs**. So a surface that was
rarely visited became frequently visited in the same release. And it is genuinely
player-facing — `HexSidebar.tsx:466` renders `{loc.name}` under a "Monster Lair"
header, so a chart verb that christens "The Saltway Ring" (THR-1291, slice 4) was
pointing the player at "Lair 7".

## What shipped

`src/engine/naming/lairNames.ts` — a grammar, not a second namer. `hashSeed`,
`pickFrom` and the seeded-offset collision walk are imported from `workNames.ts`,
where THR-1291 §5 put them; two hash rules would be two namers wearing one name. What
differs is the *keying*: a work is named for what was done (reach + foundation), a
lair for what the place is and what haunts it (terrain family + `dominantSphere`).

`src/data/lair-name-content.ts` — six terrain families spanning the land terrains,
each with its own nouns and roots, plus a root table for all twelve spheres.
Terrain families rather than terrain keys because `TerrainType` has ~22 land members
and naming cares about the shape of the hole in the ground: `dense_forest` and
`jungle` want the same nouns. `Lair` appears in no noun pool — not because the word
is wrong, but because the whole defect was players reading the *category* where a
name should be, and a namer that can emit "The Cold Lair" has kept the habit while
passing the regex.

**The namer seeds its own PRNG off the node id and deliberately does not consume the
caller's stream.** That is what let this land without touching worldgen: the same
seed still places the same lairs on the same hexes, and only their names differ.

## `cleared_lair` keeps its identity, and it is free

The name is written once at creation and never re-derived. That is the whole
mechanism: clearing flips a subtype, reinfestation rewrites the entire property bag,
and neither touches `name`, so "The Choking Snare" stays "The Choking Snare" through
both. A rename on clearing was the other option and is the wrong one — it would erase
the only thing tying the cleared site to the lair the player remembers fighting for.

Two findings while confirming this. First, **nothing in the world ever clears a
lair.** `cleared_lair` is read in eight places — `armyAttrition`, the sidebar's whole
cleared block, the icon registry, the sound key, prose content, the wanderer pack,
and the reinfestation branch — and written only by test fixtures. It is reachable in
principle (`encounterAftermath.ts:3707` sets a subtype from an authored effect) but
no content uses it, and `clearedAtTick` has no writer at all, so the reinfestation
loop iterates an always-empty set. Both directions of the transition are dead, which
also means the tests asserting reinfestation were asserting it from a hand-built
fixture. Not this ticket's to fix — filed as
[THR-1319](https://linear.app/threadbare/issue/THR-1319/lairs-can-never-be-cleared-cleared-lair-has-no-writer-so-the-whole).
Second, because the persistence claim rests
on code *not* doing something, the tests are behavioural rather than a code-reading
claim: a reinfestation and a tier upgrade are each driven for real, and the name is
asserted across them — with the transition itself asserted first, so the name check
cannot pass over a transition that never happened.

## Evidence

Every population-level assertion carries a non-emptiness guard first. "No location
matches `/^Lair \d/`" passes perfectly on a world with no lairs in it, which is the
exact shape that makes a green predicate meaningless.
