# THR-1415 — the dev server stopped watching 199 worktrees it was never meant to see

**2026-09-07 · Infrastructure · Repo Health**

`.claude/worktrees/` sits **inside** the repo root, and Vite's watcher ignores only `.git`, `node_modules`, `test-results` and the cache dir by default. So every hourly lane that created or reaped a worktree fed the dev server roughly 2 × 4.6k root-relative file events, and each worktree's own `tsconfig.json` tripped Vite's *"changed tsconfig file detected … Clearing cache and forcing full-reload"* path. Measured in the THR-1133 attended sweep on 2026-09-04, with 199 directories under `.claude/worktrees/`: `curl http://localhost:5173/src/main.tsx` timed out at 90s and the page body stayed empty.

## What shipped

`vite.config.ts` gains a `server.watch.ignored` carrying `**/.claude/worktrees/**` and `**/.worktrees/**`.

**The one thing worth checking before writing that line was whether `ignored` appends or replaces.** If Vite handed the user list to chokidar in place of its own defaults, this fix would have silently un-ignored `node_modules` — trading a bad watcher for a catastrophic one, on a config change that looks trivial enough to merge unread. It appends: `resolveChokidarOptions` (verified in the installed `vite@7.3.1`, `dist/node/chunks/config.js:16694`) destructures the user's `ignored` out and spreads it *after* `**/.git/**`, `**/node_modules/**`, `**/test-results/**` and the escaped cache dir. Reading the installed source rather than the docs matters here because the answer is version-specific and the failure mode is silent.

`server.watch` is dev-server only — `vite build` constructs no watcher — so the build path is untouched by construction, not merely by observation.

The patterns are lifted into a named `WATCH_IGNORED_WORKTREES` with the incident, the cost and the append-semantics note in a block comment above it. A bare glob array in a config file is exactly the line a future reader deletes as unexplained; the comment is what stops the bug from being reintroduced by tidying.

## What the ticket asked for and did not get

Nothing. Both substantive Done-whens are met, and `Docs/ops/sandbox-limitations.md` carries the entry so the next session reads "the watcher is thrashing" instead of re-diagnosing "the app is broken".

One deviation from the ticket's third Done-when, recorded rather than silently dropped: it asked for `Browser-verify exempt: dev-server watch config` in the commit body. **The browser-verify gate never fires on this diff** — it triggers on `src/components/`, `src/hooks/`, `src/contexts/` and `src/index.css`, and this change touches a root config file and a doc. The line is included as the ticket asked, but it is an auditable no-op, not a live exemption, and the weekly exemption audit should read it that way. The `docs-only` label the ticket said to strip at pickup was already gone from the board.

## The verification worth recording

`npm run classify:diff` returned **docs-only** on the uncommitted tree — and said so itself: *"No committed changes against this base. If your work is still uncommitted, this verdict is vacuous."* It was re-run after committing, where it correctly returns **code**, and the full code-track gate was run on that basis. Worth recording because the vacuous verdict is the one that would have routed a `vite.config.ts` change onto the docs track, skipping tests and build entirely — the tool prints its own warning, and the warning is the load-bearing part.
