# THR-2041 — Every measure:* / census:* script fits one 600 s command with no flags

**Shipped 2026-10-25.** Scripts only (`scripts/`, one `Docs/audits/` reader header). No engine, content or UI change.

**Why.** Long measurement commands ran past the Bash tool's 600 s foreground cap 9 times in 2 days (impediment rows 1211–1214, 1219), each costing ~10 min of re-planning.

**What changed.**
- 10 scripts whose no-flag run passed the cap now default to **seed 42, 600 ticks** (army-census: 50 days): `census:rhythm`, `measure:monopolies`, `measure:unrest`, `measure:prayers`, `measure:undertaking-economy`, `measure:crown`, `measure:crown-wages`, `measure:war-aims`, `measure:army-census`, `measure:realm-membership`. `--seeds` / `--ticks` still pass through. Each prints a one-line cap note on stderr.
- `measure:founding-starvation` with no `--seeds` / `--arms` now measures **one** uncached arm × seed cell and reports (nine calls fill the gate from a cold cache; the verdict path is unchanged).
- Every one of the 38 scripts carries a `Time:` header line: per-seed time at its default ticks on medium, and where a long read (day 60, 90 days) needs more than one command.
- The 25 scripts that already fit keep their defaults, including the deliberate two-seed gates (`census:undertakings`: "so one lucky world cannot carry it").

**Timings (no flags, medium).** Changed scripts, 11 at once on 16 cores: 478–517 s; founding-starvation 577 s (338 s alone). Unchanged scripts, 13 at once: 3–421 s (the slowest is `measure:capability-growth-scales`, three seeds × 300 ticks). `measure:means` (already one seed): 498 s.

**Trade-off.** A no-flag call of the 1080-tick scripts no longer reaches day 60 or day 90. The 90-day read is ~11–22 min per seed and cannot fit one command at all. The header says so instead of hiding it.
