# 2026-10-16 — THR-1962: one word for how far a work has come

**Ticket:** [THR-1962](https://linear.app/threadbare/issue/THR-1962). Engine, Content and UI pillars. Warm playtest round 2, complaint class PC-6.

One undertaking's progress was worded by two tables reading the same number. The thread row said "well advanced", the Journey tab said "Halfway", and only the row knew the work had halted. Now one resolver, `describeWorkProgress` (`src/engine/workProgress.ts`), picks the word, and every surface reads it.

- **Engine.** `describeWorkProgress(project)` returns `{ fraction, progressWord, troubleWord, word, troubled }`. `word` is the trouble word when the work has halted or doubled down, else the five-step progress word, lower-cased. `getAgentStrategicSummary` exposes it as `activeProject.word` plus `activeProject.phrase` (the doing-line now reads `phrase — word`). `summarizeActiveUndertakings` adds `progressWord`. `getProgressLabel` and `PROGRESS_LABEL_THRESHOLDS` are deleted (0 callers in `src/`).
- **Content.** One word table: `UNDERTAKING_PROGRESS_WORDS` (barely begun / under way / halfway / well along / nearly done). Trouble words and tooltip ids unchanged.
- **UI.** The thread row, the sheet's Designs line, the agent card, the Journey tab, the moment card and both debug tables read the resolver's word. A halted work now reads "faltering" on the Journey tab and moment card too, not only on the row. The row's word is its own non-shrinking span: the phrase truncates, the word never does (Law 57). A finished work still shows no word on the moment card.
- **Tests.** `workProgressParity.test.ts` walks one project from 0 to 100% and through the three trouble states, and asserts the row, the panel, the Journey summary and the moment model give the same word at each step.
- **Evidence.** `npm run gate`: test, typecheck, build, encounter, god-cards, ui-debt, CLI smoke and test-heavy all pass. Browser: bash-vite at 1920×1080 on `?view=game&seeded&size=medium`. Kael's row and his panel both read "barely begun", matching `describeWorkProgress` on the live project. 0 console errors.
