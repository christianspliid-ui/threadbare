# THR-995 — the lair that was always too close to itself

**Shipped 2026-08-17.** Adjacent lair spawning has been authored since M2.5 and had never
fired once. The ticket named one reason. There were two, and either alone was fatal.

## The filed cause

`phaseLairEscalation` step 4 asked `lairExistsNearby(..., ADJACENT_SPAWN_MIN_SEPARATION)`
over a lair list that **included the source lair**. Every hex `getHexNeighbors` returns sits
at `|Δcol| + |Δrow| ∈ {1, 2}`, always under the separation of 3 — so a lair was permanently
too close to its own neighbours, all six `continue`d, and `spawnAdjacentLair` had no
reachable call site. Fixed by excluding the source lair by id; the parameter is documented
as load-bearing rather than a convenience, because that is exactly what was forgotten.

## The cause nobody had found

Fixing the guard did not make the feature fire. The CLI sweep the ticket's third Done-when
requires came back **13 lairs → 13 lairs, zero adjacent spawns** — and that measurement is
the only reason the second block was found at all.

Step 4 resolved each neighbour with `findHexNode`, which looks for a `location` node whose
`locationSubtype === 'hex'`. **A generated world contains none.** The map is `state.tiles`,
which is precisely what `seedMonsterLairs` reads when it places lairs in the first place.
So `findHexNode` returned `undefined` for every neighbour of every lair in every real world,
and the loop `continue`d one line after the guard that had just been fixed.

Neighbours now resolve against `state.tiles`, with water excluded for the same reason
`seedMonsterLairs` excludes it — lairs sit on land. The hex-node lookup is retained as an
optional zone overlay and its docstring now states that production must read an undefined
result as "no overlay here", never as "off the map".

**What was lost in the move, stated rather than glossed:** `provinceRoles` is a worldgen
input and never reaches the tick loop, so a neighbour's province role is not knowable at
tick time. The authored "don't push lairs into heartland/capital" rule therefore holds only
through the source-zone gate — spawns still originate exclusively from wilderness/borderland
lairs, and each new lair inherits the source's zone, but a wilderness lair with a heartland
neighbour can now seed into it. Reproducing the original restriction would mean carrying
province roles onto `GameState`, which is a larger change than this ticket.

## The measurement

Seed 42, medium map, headless, no player:

| tick | 0 | 50 | 100 | 150 |
|---|---|---|---|---|
| lairs | 13 | 17 | 29 | 36 |

23 of the 36 are `lair_adj_*`. The run ends at ~t162 when the phase turns to `twilight`.

The curve decelerates (+4, +12, +7) because `ADJACENT_SPAWN_MIN_SEPARATION` saturates, and
separation independently caps one source at a single spawn per escalation — its first
spawn sits 2 hexes from the rest of its own ring. It is geometric-then-flattening, not
runaway.

**Read it as an upper bound.** That sweep cleared **zero** lairs (`cleared_lair` count 0),
so nothing pushed back the whole time. A played world clears lairs, and the reinfestation
path already models the other direction.

`LAIR_ADJACENT_SPAWN_CHANCE` ships **unchanged at its authored 0.15**. The deliberate
choice: this is the first time anyone has been able to observe what the authored constants
do, and re-tuning in the same commit that makes them observable would mean the authored
design is never actually seen. It is a named constant (NFP #1) with a measured rate beside
it now, so tuning it later is a number change against evidence.

## Tests

The old coverage was `expect(() => phaseLairEscalation(state)).not.toThrow()` — which passes
against a working implementation and a dead one alike, and is why five years of deadness
went unnoticed. Replaced with seven assertions, each falsified against the pre-fix build:

- spawns on the neighbour the PRNG selects (**red** before the guard fix)
- separation still blocks a second spawn in the same ring (**red** before)
- separation still blocks spawning near a *different* lair
- no spawn when no neighbour clears the roll
- no spawn onto a hex that is not on the map — the exact shape a generated world presented
- no spawn onto water
- no spawn from a heartland source

The fixture supplies **tiles**, not only hex nodes. A fixture with hex nodes alone would go
green while production stayed dead — the failure this ticket exists to prevent.
