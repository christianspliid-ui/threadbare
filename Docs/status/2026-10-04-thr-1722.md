### 2026-10-04 — THR-1722: a mortal who begins a new-catalogue encounter is announced and recorded

**The bug.** When the planner picked an encounter that exists only in the unified catalogue (`encounter.town.*`, `encounter.slice.*`, `reputation.*` and the rest), the start block in `phaseAgentDecision.ts` built and pushed the unified action, then read `template.name` off the *legacy* lookup for the "begins" news line. For a unified-only template that lookup is `undefined`, so the read threw. The per-agent `catch { continue; }` swallowed it. The encounter ran, but no "X begins Y" line reached the feed and no `encounter_decision` balance event was recorded.

**The fix.** The news line names whichever catalogue resolved the selection: the legacy name first, so templates in both catalogues read as before, then the unified name, then the template id. Nothing else after the branch reads `template`. The catch is not widened.

**Evidence.** New `phaseAgentDecision.unifiedOnlyBookkeeping.test.ts`: a unified-only selection emits one `agent_encounter` "begins" event named from the unified template and records one planner `encounter_decision`. It fails on the old line with the ticket's `Cannot read properties of undefined (reading 'name')`. Headless count with an instrumented per-agent catch (seed 42, medium, 200 ticks; not committed): **103 swallowed throws before, all at this site → 0 after**, from the whole catch. `start_local` counts in balance telemetry are now honest, so THR-1687's guard rail can be re-read.
