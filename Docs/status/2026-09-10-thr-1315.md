# THR-1315 — a reserved kind nothing could route to leaves the vocabulary

**2026-09-10 · Engine · UI · Content Architecture**

## What was wrong

`WorldRefKind` — the one canonical kind vocabulary THR-1212 established, which every
other entity-kind union in the tree is validated as a projection of — carried a `codex`
member that was legal to *name* and impossible to *route to*. `toNavigationTarget`
returned `undefined` for it, `NavigationTarget` had no `codex` arm, and
`resolveWorldRef` short-circuited it before touching the graph.

The blocker was never a missing switch case. The only codex surface that exists is
`?view=codex`, a full-page view swap that tears down the running simulation — so a
chip, notice, or narrative segment that linked there would end the player's run to show
them a reference page. `undefined` was the honest behaviour (NFP #4, Law 21), and the
kind sat reserved with a deferral ticket cited from seven curated catalog rows.

## The ruling

Recorded by an attended design session on 2026-09-10 and implemented here rather than
re-decided: **references may not route to the codex until an in-game codex surface is
chartered, so `codex` leaves `WorldRefKind` now.**

The Codex project ([THR-52](https://linear.app/threadbare/issue/THR-52)) sits at
`Idea` / `Low` and nothing in the queue charters a mid-game overlay. A reserved kind
nothing can route to is a promise with no mechanism, and the standing sunset-by-default
rule deletes such a promise rather than keeping it as a placeholder. If the Codex
project is later chartered, the kind returns with its `NavigationTarget` arm and its
catalog row in the same PR — additive, with no debt carried meanwhile.

## What changed

1. `codex` removed from `WorldRefKind` and from `WORLD_REF_KINDS` (13 kinds → 12).
2. `WORLD_REF_RESERVED_KINDS` is now empty. **The export is kept, not deleted** — two
   readers depend on it (`scripts/generate-world-objects.ts` renders `_(reserved)_`
   from it, and the world-objects coverage test excludes reserved kinds from its
   uncovered set), so an empty list is live machinery rather than dead code, and
   re-reserving a kind stays additive (NFP #6).
3. `toNavigationTarget`'s `codex` case and `worldRefResolver`'s reserved short-circuit
   removed; `NavigationTarget` gains no arm, as the ruling requires.
4. All seven curated dispositions citing the ticket removed from
   `scripts/anchor-catalog-sources.ts`, along with the `CODEX_SURFACE_TICKET` constant
   and the ticket-specific tail on the stale-absence error message.
5. Both generated artifacts regenerated: the anchor catalog carries **zero** `codex`
   mentions (was 8), and `Docs/canon/world-objects.generated.md` drops its
   `| `codex` | _(reserved)_ |` row.

## What the catalog's own gate proved

The bidirectional coverage lint is the reason this could not be done quietly. Each
`absentKinds` row is a claim that a kind is absent *for a reason*, and the lint fails
by name when the claim stops being true in either direction — so removing `codex` from
the spine while leaving any of its seven rows behind fails the build naming the stale
row. `npm run generate-anchor-catalog` now reports `12 WorldRefKinds across 7 consumer
vocabularies; 41 members map to the spine, 3 do not (curated)`.

## Three tests that would otherwise have passed for the wrong reason

**The reserved-kinds test was rewritten rather than deleted.** Its old body swept
`for (const kind of WORLD_REF_RESERVED_KINDS)` — over an empty list that loop passes
vacuously, and would keep passing if a reserved kind crept back in unannounced. The
emptiness is now pinned as an exact value (`toEqual([])`) alongside
`isWorldRefKind('codex') === false`, with the subset invariant kept in its own test so
it is available the day something is reserved again.

**The generator's "leaves codex unspoken" test was vacuous by construction after this
change** — any word never in a union satisfies it. It now pins both halves: gone from
the spine *and* unspoken by every consumer.

**The lint's own falsification arm had to move.** It mutated `NavigationTarget` with
`codex` to prove a stale `absentKinds` row fires. With `codex` off the spine that same
mutation still throws — but from the *undispositioned extra member* branch, a real
throw for the wrong reason, which is exactly the green-for-nothing this file exists to
catch. The arm now mutates with `artifact`, which is absent-with-a-reason today, and
the reason it moved is recorded in the test.

Three drop-log tests used a `codex` ref as a convenient always-drops input; they now use
a malformed `hex` id, the one reference that still drops without consulting the graph.
