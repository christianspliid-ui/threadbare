# THR-1299 slice 1 — following a mortal is one predicate, and it now agrees with the court

**2026-09-02 · code.** Plan doc 5/6 of Proactive Agent Actions ships as six strangler slices. This is slice 1: the follow module, the mute term, and the debug write lever the later slices' constructed proof depends on. The moment card, the badge, the arc panel and the calling are slices 2–6; the ticket stays In Dev.

## The divergence this closes

The orchestrator filed it on the ticket on 2026-08-27, and it was real. Two mechanisms answered "is the player watching this agent?", and a player action made them disagree:

- Every attention predicate — `resolveEffectiveTier`, `phaseAttention`, `encounterVisibility` — keys on the thread edge's `courtPosition`.
- `isFollowedAgent` in `undertakingCheckpoints.ts` tested that the **edge existed**.

`courtPosition` is a property *on* the edge, so going dormant does not remove it. The authored text of `thread.dormant` promises *"their encounters no longer surface as tugs… the thread persists"* — the persisting thread is the point of the action. So every mortal the player had deliberately set down still returned `true`, and their completions, forks, abandonments and complications all resolved `interrupt`. **Dismissing a mortal from your court silenced their encounters and did not silence their undertaking news.** The one gesture for "stop surfacing this person to me" worked on one channel and was inverted on the other.

It was latent only because the moment stream still has no player-facing consumer. It would have gone live the moment slice 3 built one, and it would have presented as *"the interrupts are too noisy"* — a symptom several steps removed from a predicate disagreement, which is a much harder thing to find.

The plan chose option 1: make the follow predicate court-position-aware, so the two agree by construction and `thread.dormant` means what it says.

## The one judgement call: an unstamped thread edge reads as `retinue`

The plan says default-follow is `courtPosition ∈ {the_first, retinue}`. It does not say what an edge with *no* stamp is, and the answer is load-bearing, because not every thread writer stamps one — `encounterAftermath.ts:3943`'s thread-branch effect omits it entirely.

Read strictly, every branched thread would have silently stopped being followed: visible to encounters, silent for moments. That is the same divergence pointing the other way, which would have been a poor trade for closing the first one.

So absent reads as `retinue`, matching `collectThreadedAgents` (`encounterVisibility.ts:415`), whose doc comment already states the convention and which both the visibility phase and the notification threading gate read. One helper, `readCourtPosition`, is the only place the `?? retinue` default is spelled — the seed (`defaultFollowedAgentIds`), the live predicate and the surface read all go through it, so the three cannot drift apart, which is exactly how the original divergence formed.

`dormant` and `watched` are the two excluded positions: the god has either set the thread down or has not reached down yet. Both remain **explicitly** followable through the affordance — the honest reading of "follow any agent".

## Mute is not unfollow

Doc 1 left this deliberately: *"a missing unfollow is a missing feature while a mute-by-default is a bug."* Un-following a default-followed agent cannot be expressed by removing them from a list they were never in, so it needs a negative term — `state.mutedAgentIds`, optional and additive.

A mute drops the **interrupt upgrade only**. The agent's moments still queue and still badge; nothing is hidden, it is made quiet. And `unfollowAgent` picks mute-or-removal from the state of the world rather than from its caller, because a caller that picked wrong is precisely how a mute-by-default ships. Follow state stays off the `thread` edge: court position is the god's standing with a mortal, follow is the player's attention, and overloading one edge with both axes is the bug this shape exists to prevent.

## Tests: the arms that would pass on the old predicate

The court-position matrix is asserted for **all four** `CourtPosition` members, including the two that must come back `false`, plus a guard that fails if the union grows a fifth member without a decision. A table that only checked `the_first` and `retinue` would pass just as well against the old existence-only predicate — which is the regression being closed, so it would have been a test of nothing.

The dormant arm carries a control: the same completion for a `retinue` member still resolves `interrupt`, so `badge` is a falsifying result rather than a broken presenter. One existing test in `undertakingCheckpoints.test.ts` asserted the old behaviour from a `properties: {}` fixture; it now stamps `retinue`, with a pointer to the file that owns the full matrix.

## Browser-verify

`GameView.tsx` is in the diff, so the UI-pillar clause binds. `preview_start` is refused in unattended runs, so the sanctioned `jsdom-render` substitution applies (THR-754) — and here it proves something better than a screenshot would, because this edit renders no face at all. It registers a write lever, and the failure mode worth guarding is a lever that mutates a detached copy: the predicate would flip while every surface reading it stayed un-rendered. Real, and invisible.

`GameView-followBridge.test.tsx` therefore renders the real GameView under `<StrictMode>` and reads follow state back **through the live state provider** after an `act()` flush — the same object GameView re-renders from. It also pins that one press means one entry (StrictMode double-invokes updaters) and that a miss reports its error instead of silently following nobody.
