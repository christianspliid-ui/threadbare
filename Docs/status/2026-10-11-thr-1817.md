# 2026-10-11 — THR-1817: the world map no longer crashes going from empty to built

**Ticket:** [THR-1817](https://linear.app/threadbare/issue/THR-1817) · HexMap bug, no plan doc.

- **Cause.** `HexMapV2` returned early for the empty state ("The world has not yet been shaped.") and only after that declared the two fog label filters (`visibleRegionLabels`, `visibleLocationLabels`) with `useMemo`. On the first render where `tiles` went from empty to non-empty, React saw two more hooks than on the render before and threw (`Rendered more hooks than during the previous render.`). This was latent: the map usually mounts with tiles already present.
- **Change.** Both memos move above the empty-state return. They are cheap and safe on empty input. Behavior on a built map is unchanged.
- **Lock.** `HexMapV2.emptyToFilled.test.tsx` renders the real component in jsdom, empty then filled (inert 2D canvas; WebGL null, so scene init takes its fail-soft path), and asserts no hook is declared after the empty-state return. Against origin/main the test reproduces the crash, and it passes on the fix.
