# THR-1032 — the debug bridge could not name the one actor every review route uses

**Shipped 2026-08-17** · `tb-opus-pickup` hourly lane · project *Encounter Experience*

## What was broken

Two `window.__DEBUG` aftermath accessors failed on the ascendant avatar — the actor
every `?spawn=` review route stages its encounter on. The ticket recorded six spellings
tried in a row (`@hero`, `Vara`, `Vara Enkhet`, `vara`, `hero`, `agent_hero`,
`ascendant`), each answered `No agent matching '<x>'`, which reads as a typo and invites
guessing a seventh.

Both halves are now measured rather than inferred:

- **No `@hero` alias.** The avatar node is `avatar.archetype.chaos_0`; `state.ascendantId`
  is `asc.archetype.chaos_0`. They share no prefix, so every id-shaped guess had to miss.
  The alias is reachable only through the `avatar_of` edge, which no accessor followed.
- **Display-name matching was dead, not merely narrow.** The matcher read
  `node.properties.name`, but `GraphNode.name` is a **top-level** field. Probed against a
  real seeded world: **0 of 290** actor nodes carry `properties.name`. So the name branch
  could never match any actor, which is why the two human-readable spellings failed too.

`consequencesFor` was broken on a different axis: it called `state.graph.getAllNodes()`,
a method `WorldGraph` has never had, so it threw `TypeError` for **every** argument.

## The sweep, and what it found

The ticket asked for the predicate to be re-derived rather than trusted, on the grounds
that two instances found incidentally probably meant more. It did.

- **Six** accessors hand-rolled the same agent matcher, none accepting `@hero`:
  `listAftermathReactions`, `pickAftermathReaction`, `getForeshadowing`,
  `getMotiveReceipt`, `listForeshadowingTraces`, `getAgentAttachments`,
  `getAgentResidence`, `getRelocationIntent`.
- **A third `getAllNodes` call site**, outside the debug bridge entirely: the CLI's
  documented `graph` command. It did not fail soft — it threw an uncaught `TypeError`
  that **killed the REPL process**. Reproduced before the fix, green after.

That third site is what settled the shape of the repair. Three independent callers
already assumed `getAllNodes()` existed, and the edge side has had `getAllEdges()` since
the class was written — so the missing method was the defect, not the callers.

## What shipped

- `WorldGraph.getAllNodes()` — the node-side counterpart of `getAllEdges()`.
- `src/engine/debugAgentResolver.ts` — one resolver for every debug agent selector.
  Accepts `@hero` / `@avatar` (via the `avatar_of` edge, falling back to the ascendant
  node for CLI-shaped worlds), exact id, id prefix, then display name read from **both**
  locations.
- A miss now names what it searched (`Searched 290 node(s) of type 'actor' by exact id,
  id prefix, and display name. For the ascendant's avatar use '@hero'.`) and reports an
  alias failure distinguishably from a wrong id — Done-when 3, and the half that turns a
  six-guess loop into one read.
- All eight accessors moved onto it. `consequencesFor` gained the `{ actorId, error,
  consequences }` shape this file already uses elsewhere; it had zero working callers,
  having thrown on every call since it was written, so nothing could depend on the old one.
  `getMotiveReceipt` became async — `await` it.

## Verification

Full gate green: 1042 test files / 16,705 tests, `vite build` clean, 30-tick engine smoke
to 384 agents. Typecheck ratchet moved **down 3** (3178 → 3175) — the dead `getAllNodes`
call site was carrying them.

Ten new tests run against a **real seeded world**, not a fixture, because a fixture is
blind to this defect by construction: one that invents both sides would supply
`properties.name` and pass against a node shape the engine never produces. Guard
falsified — disabling the alias branch fails 8 of the 10.

`Browser-verify substitution: jsdom-render` was not needed. `preview_start` is refused in
unattended runs (impediments #546 ×10, #574, #648), and the GameView edit touches no
render path — it is a dev-only `useEffect` bridge registration with no JSX or CSS. Instead
Done-when 1 is discharged headlessly by composing the resolver with the real
`resolveAftermathContextForAgent` the bridge calls, asserting the failure mode moved from
the upstream *"no agent matching"* to the downstream *"no pending aftermath for
`<resolved avatar id>`"*.

## Left open

The resolver keeps a `properties.name` fallback that currently matches nothing, retained
because the CLI's own resolver reads both and some older node shapes may still carry it.
Harmless, and cheaper than proving a negative across every node producer.
