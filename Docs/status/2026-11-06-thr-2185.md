# THR-2185 — A rival's move has a place and an answer

**Shipped 2026-11-06.** Warm playtest · round 3, slice 1 of THR-2172. Plan: `Docs/plans/2026-11-06-thr-2172-a-rival-move-has-a-place-and-an-answer.md`.

1. **The raid toast.** `landRivalProbe` returns what landed (`{ placeId, placeName, sphere, tendedBy }`) or null. `rivalProbeMove` raises its `rival_action` toast only on a landing, in `rivalLandingLine`'s words: "The Hollow Warden pressed Death on Iron Glade. Tend it and the next blow breaks." or "…but your seat / thread / claim / anointed faction held it." A throttled or turf-less probe is silent (the `dominion.raid` trace still records it). The flavour-line `rng()` draw is kept and discarded, so the seeded stream is unchanged (a test counts the draws: three on a landing, two without). A landing writes `RivalState.lastPressed`.
2. **Toasts open the place.** Every `rival_action` toast with a target (landing, scheme launch, drain, desecration, crack) carries `refs: [{ kind: 'location' }]`, and `deriveNavigationTarget` opens it. The opened place page lists the god's place cards (Place Thread seen; Claim Dominion only once the held-ground milestone grants it).
3. **Temper.** Starts at `RIVAL_HOSTILITY_START` 0.3 ("hostile"). A scheme beat adds 0.03 and records `hostilityCause = { kind: 'scheme', placeId }`. The god breaking a scheme (stall or fail) adds `RIVAL_HOSTILITY_ON_COUNTER` 0.08 with `kind: 'countered'`. A day with no rise cools 0.02 to the floor (`coolRivalHostility`). Every change emits `rival.hostility_changed`.
4. **Departure from the plan: `RIVAL_SCHEME_HOSTILITY_CEILING` 0.7.** The plan's measure-first note asked for warm-300 on main before tuning. At the end of the warm-up main read **0.95 / 1.00 / 1.00** (all "wrathful"). The first branch build, plan numbers only, read **1.00 / 0.95 / 1.00**. No writer was missing: grep finds no stored writer besides the new ones. The climb is beat count. A rival runs several schemes in a warm-up (24-tick launch cooldown), so a beat lands about once a day, and cooling, which needs a day with no rise, never got one. So a rival's own scheme beats now lift temper only to 0.7 ("aggressive", not past `selectRivalAction`'s `> 0.7` line). Only a counter carries a rival to "wrathful". A capped beat never overwrites a standing counter cause above the ceiling, so a wrathful rival keeps saying why. The `> 0.7` action bias now only picks the discarded flavour line, so the ceiling has no other mechanical effect.
5. **Panel.** The rival's name is a plain disclosure: primary text, no underline, the Chronicle's `disclosure` icon. The open entry adds the cause line ("Toward you: wrathful. You broke its scheme against Iron Glade." / "…, and cooling." / "…, as rival gods are."), with the temper word carrying the `ui.rival.temper` hover. Then "Last pressed {place}, {when}." with the place as a link, and the muted answer line. The lines come from a new pure view, `engine/views/rivalEntry.ts`.
6. **Chronicle names.** `composeDominionChronicle` and the hex drop line name the rival from `rivalDefinitions` (`rivalNameLookup`, `updateDominionDrops(…, rivalDefinitions)`). An unknown rival gets the untended line, never `actor_rival_1`.
7. **Debug.** `getRivalSchemes()` rows carry `hostility`, `hostilityCause` and `lastPressed`.
8. **Interface map:** three contracts (`rival-temper-cause-feeds-rival-panel`, `rival-definitions-name-dominion-drops`, `rival-toast-location-ref-opens-place`). The plan's fourth, `landRivalProbe` → `rivalProbeMove`, is inside one module, which the generator reads as a starving consumer. It is folded into the panel contract.
