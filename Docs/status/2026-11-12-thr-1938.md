# THR-1938 — the authoring-brief floor gate reads only the shape column

**Shipped 2026-11-12.** Continuous Improvement · process tooling. No plan doc; scope from the ticket.

- **The bug.** `npm run draw:packet` prints two columns per slot line — `shape: appointment               system: movement` — and `briefFloorReport` (`scripts/check-authoring-brief.ts`) captured the whole rest of the line, so every shape keyed as e.g. `appointmentsystem:movement`. Every master-everyday brief therefore recorded zero `query_prize` and zero `appointment` faces, and the orchestrator's T3 sweep reported a false floor violation on 10-12, 10-14, 10-15 and 11-12.
- **The fix.** The capture (`SHAPE_LINE`) now stops at the next `<key>:` column or a `[` gloss. It deliberately does not split on "two or more spaces": a long shape id eats the packet's padding down to one space (`shape: danger_confrontation_aftermath system: traits`). The printed-label form (`Query Prize  [any + queried ending]`) still reads.
- **Tests.** Three cases in `scripts/__tests__/check-authoring-brief-floor.test.ts`: a two-column batch with both floor faces passes, the same layout without them names the shortfall (0 / 0), the label-with-gloss form still counts.

**Evidence:** `npm run check:authoring-brief` → "3 batch brief(s) judged, 3 `query_prize` and 4 `appointment` slot(s) authored" (was 0 / 0 on all three). `npm run gate` PASS (test, typecheck, build, encounter, god-cards, ui-debt).
