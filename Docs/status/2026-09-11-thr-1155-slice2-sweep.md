# THR-1155 slice 2, part 1 — every engine consumer resolves a definition through the lookup

THR-1322 built `getFactionDefinition(id, dynamicDefs?)` in `src/data/faction-definition-lookup.ts` so that a faction definition minted during a run resolves exactly like an authored one, wrote the run's definitions into `GameState.dynamicFactionDefinitions`, and mirrored them into a module overlay that `publishDynamicFactionDefinitions` republishes at every game init. That was the door. **It opened onto a wall.**

Measured on `main` before this change: **21 by-id read sites across 12 production engine modules** called `FACTION_DEFINITIONS.get(id)` on the static authored table — `factionReputation.ts` (six), `factionOutcome.ts` (three), `agentDetail.ts` and `factionQuestGeneration.ts` (two each), and one apiece in `factionAmbitions.ts`, `encounterFilterPipeline.ts`, `factionMembership.ts`, `factionMemberWork.ts`, `factionRankBonus.ts`, `npcSeeding.ts`, `phaseReputationTraits.ts` and `socialEncounterGeneration.ts`. A definition that exists only in the run resolves at none of them, so a run-founded faction was shut out of ambitions, quests, rank ladders, reputation and encounter gates — every consumer the lookup was built to reach.

This is a prerequisite for the Realm mint rather than a detour. A Realm's definition is minted at worldgen into the same field by the same path, so without the sweep a Realm would be a generic faction with a nicer name, and slice 2's acted-on Done-when — *a Realm holds an ambition, commissions a quest, fields an army* — could not pass. The plan says the sweep goes first; it does.

## Why it went unnoticed

`encounterFilterPipeline.ts:367` fails **open** on a definition it cannot resolve: no definition means no `joinPrerequisites`, which means no gate. `meetsFactionRankRequirement` fails open the same way, by an explicit `return true // fail-open: unknown faction definition`. A missed read site there does not throw, log, or render differently — it silently *removes* a gate. Combined with founded factions being rare, the failure mode was invisible by construction, which is why the guard that ships with this change is a **shape** tripwire and not only a behavioural one: a re-introduced static read would pass every behavioural test in the corpus.

## What landed

**The sweep.** All 21 sites now call `getFactionDefinition`. The plan fixed the target deliberately: the lookup module's own function returning `null`, not the `factionNetwork.ts:171` wrapper returning `undefined`, so all 21 land on one signature. Three sites hold a `GameState` and pass `state.dynamicFactionDefinitions` explicitly — `scoreEligibleAmbitions`, `phaseFactionReputationDecay`, `resolveForFaction` — per the lookup's own doc comment that a caller holding state should not depend on the mirror. The other 18 take a `WorldGraph` or nothing and resolve through the overlay, which `publishDynamicFactionDefinitions` has already filled at game init.

`worldSeed.ts` keeps the static import and is exempt in writing: it mints *from* the authored roster, which is enumeration, not a lookup. Enumeration consumers that mean *the authored roster* — content-eval chip declarations, sigil coverage — live outside `src/engine` and keep the static map on purpose.

**The tripwire** (`src/data/__tests__/faction-definition-lookup.readsites.test.ts`) asserts the § Engine B predicate over production modules: no module under `src/engine` (excluding `__tests__/`, where five fixtures import the static map deliberately) imports `FACTION_DEFINITIONS` or `ALL_FACTION_DEFINITIONS`, `worldSeed.ts` excepted. Two traps were designed against:

- **It matches imports, not the word.** `factionNetwork.ts` and `monsterFactionSeed.ts` both *name* `FACTION_DEFINITIONS` in comments explaining why they do not read it. A substring match would have failed on precisely the two modules that document the rule.
- **It cannot pass vacuously.** A second case pins that the collector sees >100 modules and that the matcher demonstrably fires on `worldSeed.ts` — the one module that legitimately imports. A collector walking the wrong directory, or a matcher that never matches, would otherwise satisfy the empty-offenders assertion.

Falsified rather than watched green: re-adding a static import to `factionRankBonus.ts` reddens it with `expected [ 'factionRankBonus.ts' ] to deeply equal []`.

**The behavioural evidence** (`src/engine/__tests__/factionDefinitionReadSites.test.ts`) founds a faction through THR-1322's real `foundFaction` path and asserts the rank gate now *gates*: a member at reputation 0.1 is refused the `keeper` tier (`minReputation: 0.4`) and admitted at `sworn` (`0.0`). The control arm is the fail-open path itself, run against the same graph and the same membership with an unresolvable id — it still returns `true`. The two arms differ in exactly one thing, whether the definition resolves, which is the one thing the sweep changed. Asserting the gated case alone would have been green if the gate had closed for any unrelated reason.

## The Done-when this does not satisfy, and why

Slice 2's bullet reads *"a generated-world test founds a faction through THR-1322's path and asserts it now receives an ambition."* The sweep does not produce that, and the reason is content rather than wiring: `foundFaction` builds its definition with `rankTiers`, `questTemplateIds` and `socialTemplateIds` but **no `ambitionWeights` field at all**, and `scoreEligibleAmbitions` reads `def.ambitionWeights ?? {}` and returns `[]` when every weight is absent. A founded order therefore still receives no ambition after the sweep — not because the definition fails to resolve, but because it carries nothing to score.

So the ambition assertion would have been a test of `foundFaction`'s seed content, passing or failing for a reason the sweep does not control. The rank ladder was chosen instead because it exercises the same resolution through a field founded definitions genuinely carry. The ambition half of that bullet is satisfied by the Realm, whose definition is minted with weights — it belongs to the mint commit, not this one. The missing `ambitionWeights` on founded definitions is reported as a finding on THR-1322's thread, per the plan's instruction to report the side-effect rather than widen scope.
