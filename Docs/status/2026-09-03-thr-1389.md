# THR-1389 — one Dijkstra per mortal, not one per destination

**2026-09-03 · engine.** The `groups` phase THR-1385 measured at 81% of a tick (steady 502 ms/tick on seed 42 small, a 4.1 s worst tick) was not the company logic — it was the pathfinder underneath it. `generateMovementCandidates` called `findShortestPath` once per **location node** in the world, 812 calls per company member at tick 120, and roughly 80% of those destinations were unreachable, so each call exhausted the whole frontier before returning null; the frontier itself was a linear scan of an unvisited set, so every one of those runs was quadratic. Repeated for every member every `DECISION_REEVALUATION_TICKS`, that was 169 ms per member and ~2.1 s per re-decision tick. The root cause is algorithmic, so the fix is a refactor of the pathfinder, not another movement model: a per-agent cost matrix cannot replace it because edge cost is agent-aware (traits and range effects at `computeEdgeCost`), and the hop-count distance matrix answers a different question.

## What changed

- **One Dijkstra core, two entry points.** `runDijkstra` prices edges exactly as before (`adjacent` + `contains` via `computeEdgeCost`, roads both ways via `computeRoadEdgeCost`), on a binary heap instead of a linear scan. `findShortestPath` is that run with an early exit; the new `findAllShortestPaths(graph, agentId, startId)` is the same run with no exit, returning every reachable location's `PathResult` keyed by destination — each entry byte-for-byte what the per-destination call returns.
- **Candidates walk the place tier and price after pull.** `generateMovementCandidates` runs one single-source Dijkstra from the mortal's position, iterates `getPlaceTierLocations` (a settlement sweep never meant sublocations — THR-1183), computes pull first and prices the path only for destinations with positive pull.
- **Army objectives read the same map.** `armySpawning` priced every hostile settlement per-destination in a loop; it reads one single-source run now.

Costs are unchanged: the fixture test pins the new core against a verbatim copy of the old algorithm on every relaxation branch (adjacent, contained room, major road, a trail read against its direction, an island), and the heavy test compares every reachable destination on a seeded world at tick 60 for cost and path equality, plus reachability parity, and requires the single-source run to beat the sweep by at least `MIN_SPEEDUP` (10×) measured in the same process — a wall-clock ceiling was tried first and flaked under sibling test load.

## The acceptance (`measure:tick-cost`, seed 42 · small · 200 ticks)

| | before | after |
|---|---|---|
| steady ms/tick (51–200) | 502 | **91** |
| `groups` share of the run | 81.2% (63.8 s) | **2.3%** (0.3 s) |
| `groups` worst tick | 4076 ms | **16 ms** |
| whole run | 79.5 s | **15.7 s** |

Target was `groups` under 30% and no tick over 500 ms; both cleared with room. `agent_decision` (34%, max 76 ms) is now the top phase, which is the shape THR-1385 expected once the pathfinder stopped hiding everything else. The population question THR-1385 raised (368 → 512 agents in 200 ticks) is untouched by this change and stays Christian's.
