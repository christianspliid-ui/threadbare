**Two companions on one bearer shared a name because the picker's last-resort branch was the one path that never consulted the exclusion set — and the ticket's stated cause was the wrong branch.** THR-1420 filed the phonetic generator as the likely culprit, keyed on `cultureId` + `tick` and called with the same pair twice. It could not have been: `mintCompanionName` passes only four arguments to `pickCulturalName`, so `signature` and `cultureId` are `undefined`, `hasSignature` is `false`, and **both phonetic branches are unreachable from the companion path by construction**. Instrumenting the real mint settled it in one run — `usedNames` was built, passed, and correct at *both* mints (`hasThorne=true`, 386 entries) — which falsified the ticket's premise that the set was somehow not reaching the check. The defect is `synthesizeFallbackName`: it returned `pool[index % pool.length]` **unconditionally**, the only branch in the picker that hands back a name without asking whether it is taken. Its ordinal anchor is `usedNames.size`, and that anchor *does not advance* when the colliding name is already in the set — so the second mint computed the same index and returned the same name, deterministically. A sharper detail than the ticket's framing: this was never companion-vs-companion. A probe before any mint measured **an actor already named Thorne** (`PRE:1`), so the very first companion was minted onto a name the world was using; two companions colliding was the visible symptom of a branch that ignored every existing name equally. Repaired at that branch, not with a retry loop in `mintCompanionName` (the Done-when's explicit exclusion): three tiers now walk from the anchor and take the first candidate that is both unused and unbanned — generic pool, then the canon list, then a given-name × epithet composition. The composition tier is not decorative; the live world had exhausted the flat pools *and* all five `FATAL_FALLBACK_NAMES`, so the fixed repro now yields `Veris of the Eastern Road` and `Wynn of the Unnamed Path` — names that read as people rather than placeholders, which is why the tier composes rather than appending an ordinal. **The reason this survived a suite with existing coverage is the fixture shape:** `returns distinct names for small pools` shares one growing `usedNames` set across its calls, so the ordinal advances every iteration and the branch always lands somewhere new. Production does the opposite — `mintCompanionName` rebuilds the set from the graph on every mint, so the anchor is *stationary* between two colliding mints. The new guards pin the production shape (a fresh set per call, same tick) at both layers, and one of them caught an error in its own first draft: asserting `second.has(nameB) === false` contradicts the picker's documented contract that it *mutates* the set with its choice, so the membership question is now asked of a pre-call snapshot.
