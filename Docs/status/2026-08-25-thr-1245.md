### THR-1245 — `draw:packet` rolls the whole batch brief at once (2026-08-25)

**The ask.** Christian, investigating the Encounter Factory's rolled tables in chat: authoring agents should not have to learn every table and roll values by hand per slot — the factory should provide the set of values plus the guidance for using them. After the investigation report: *"just build it all directly."*

**What shipped.** `npm run draw:packet -- <briefSlug>` rolls a complete authoring packet for a batch (default 6 slots). Per slot it composes every existing roll — the plot-hook offers (THR-1147), the five Seed Dice (THR-1224), and the binding consequence hand where a planned template id is supplied via `--ids` (THR-1145) — with **four new capped dice** for the axes the spec's own enforcement-tier table listed as capped but nothing rolled: **reach** (flat, overridable via `--reaches`), **decision shape** (the 7-shape structure catalog), **setting class** (gap-weighted against the live corpus, so an uncovered class like `stronghold` rolls likelier — the same corpus-dependence the hook table already has via `usedBy` damping), and **system target** (maturity-gated per the encounter catalogs §7: mature freely, middling once per batch, deferred at weight 0). Every rolled value prints with its authoring guidance in place — the stake's P2 obligation and closing format, the shape's step contract, the setting's subtype expansion and opening obligation, the system's tier note, the hand's legal effect kinds — and the tail is the ready-to-paste `Rolled constraints` block for the batch brief.

**Caps hold by construction, not by eyeballing.** A face earlier slots rolled to its cap is excluded from later slots' tables; the settlement-or-larger floor is forced on the last slot if still unmet; the hostile cap and the Seed Dice caps ride the same mechanism via a new additive `SeedDiceExclusions` parameter on `rollSeedDice`. The falsification arms are the part worth keeping: a single-slot batch is *always* floor-forced (an unconstrained scale die would roll sub-settlement half the time, so deleting the forcing reddens the test), a 40-seed sweep asserts a stake cap actually bites somewhere (so the sweep cannot be vacuously green), and an all-`iron` human override is *reported* as a violation rather than silently re-rolled — a human call outranks the die, and a cap the human broke is surfaced, not hidden.

**No second sampler.** An unconstrained packet slot draws bit-identically to the single-slot commands — pinned by direct comparison against `rollSeedDice`, `drawPlotHooks`, and `drawConsequenceHand`, not re-derived. This is the drawTable module's own warning ("a second hand-rolled sampler is the drift this exists to prevent") made into a test.

**Tier discipline unchanged.** The consequence hand stays binding (and is only rolled from a real template id, because `check:encounter` recomputes it from the id — slots without ids get the exact `draw:consequences` command to run later); the dice stay capped; hooks stay advisory. Nothing recomputes a finished encounter against the new dice. One canon consequence recorded in `Docs/canon/encounter-catalogs.md`: §7's maturity-tier column is now load-bearing for `packetDice.ts`, so a tier move (still a design-session decision) must move both in one commit — pinned by the catalog-health check's tier census.
