### THR-1245 — `draw:packet` rolls the whole batch (2026-08-25)

**The factory had five tables and no way to roll them together.** Briefing a batch of six
meant knowing every table existed, rolling each by hand per slot, and then eyeballing
whether the six slots *together* honoured caps written down in three documents and
enforced by nobody. Christian's ruling after investigating the rolled tables was blunt —
*"just build it all directly."* One command now does it:

```bash
npm run draw:packet -- <briefSlug> [--slots 6] [--reaches iron,veil] [--ids a,b] [--json]
```

**Four axes the spec already called *capped* while nothing rolled them.** The enforcement-
tier table listed "reach/setting/structure/tone" beside the five Seed Dice, but only the
five had dice. Added: a **reach** die (8 faces, cap ≤2, `--reaches` overrides), a
**decision-shape** die transcribing the spec's 7-shape catalog (cap ≤2), a **setting-class**
die (8 classes, cap ≤2) **gap-weighted against the live corpus**, and a **system-target**
die (14 entries) maturity-gated per `encounter-catalogs.md` §7 — mature freely, middling ≤1
per batch, deferred at weight **0**, which `drawFromTable` treats as absent. The deferred
four stay in the vocabulary rather than being deleted, precisely so the die can say "not
yet" instead of looking like a 10-face table.

**Caps hold by construction, not by retry.** A cap-hit face is dropped from later slots'
tables; the scale floor forces settlement-or-larger only at the last slot that can still
meet it. The obvious alternative — roll, check, re-roll — was rejected twice over: it makes
the packet a function of how many attempts it took (not recomputable from the slug, NFP #3)
and it can loop forever on an unsatisfiable batch, where exclusion simply runs the table
dry and **reports the bust**. Every correction prints the face the unconstrained table
rolled and the cap that bit, so an author who re-rolls a slot by hand can see why it differs.

**Exclusion went into `rollSeedDice`, not into the packet — the load-bearing decision.** A
packet filtering faces itself would have to re-derive the motive and activity sub-rolls off
the corrected opposition, and that second derivation is exactly where a sampler drifts from
the die it copies. `SeedDiceInput.exclude` is additive and a no-op when absent, so an
unconstrained slot is byte-identical to a direct `rollSeedDice` call — asserted in the tests
against the real function, with a `compared > 0` guard so the assertion cannot pass
vacuously by every slot happening to be corrected.

**The setting die follows the corpus, not a list.** Weights are read off the drawable pool
the same way the THR-884 coverage matrix reads it, linear in coverage: the densest class
sits at base weight, an uncovered one at base + bonus (6×), tapering between. Linear rather
than `1/count` because inverse weighting gives an empty class unbounded weight and makes the
second-thinnest indistinguishable from the densest — a batch rolling `stronghold` five times
out of six reads as a bug. On the live corpus today that prints `urban 1.0 · battlefield 5.1
· stronghold 4.6`, which is the skew the die exists to push against.

**Tier discipline is unchanged and that was a constraint, not an oversight.** No template
field was added and nothing recomputes a finished encounter against a rolled shape, setting
or system — the consequence hand stays binding, the dice stay capped, the hooks stay
advisory. Promoting a rolled axis to binding by the back door is the failure
`encounter-catalogs.md` § Coverage defers on purpose. The hand is printed **only** for slots
given a `--id`, because it is seeded by template id: drawing one for an unnamed slot would
be re-drawn, differently, the moment the encounter was named — and an author who had already
written to the first hand would fail `check:encounter` for reasons this command handed them.
Ids the corpus already knows draw off the template's own reach and tier, not the packet's
rolled reach, so a retrofit batch's hand matches the one the gate recomputes.

**The cap tests were falsified before being trusted:** disabling the exclusion path turned
**9 of 39** red, including every per-seed cap assertion and the scale floor. Caps are
asserted across ten seeds rather than one, because a six-slot roll off eight-face tables
usually complies by luck.
