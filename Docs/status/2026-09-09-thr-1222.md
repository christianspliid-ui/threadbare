## What the batch actually had to fix first

The interesting half of this run was not the prose. Three things blocked the
contract and each was found by a gate rather than assumed:

**The raw-entry converter is a field allowlist.** `toUnifiedTemplate` names every
field it copies, and `supportBundle` / `aftermathConfig` / `consequenceDraw` /
`consequenceSwap` were in neither it nor `EncounterEntry`. Authoring them would have
compiled, read correctly, and connected nothing — the same shape as `favorGeneration`
sitting inert until THR-724. Batch 1 never met this because the slice six live in
`src/data/encounters/` and skip the converter. Added as optional passthrough (NFP #6);
every future retrofit in this file depends on it.

**Two drawn consequence families cannot be wired from authored content.** `thread`
takes literal `ascendantId`/`mortalId` with no scene sentinel and has zero shipped
users; `place` needs a `targetLocationId` that a self-targeted camp chore cannot
supply (verified in the CLI — `targetId === actorId`). Both traded to `condition`
with the evidence recorded on the template. That is two swaps against a brief
budgeting one, deliberately: the budget stops authors dodging inconvenient hands, not
provably dead wiring. Filed as THR-1446. The brief's *budgeted* swap —
`membership` on `scout_the_perimeter` — was **not** spent: `membership_change` takes a
faction definition id, so the watch roster wires as drawn.

**A vacuous test was falsified by the first content to reach it.**
`settingClasses.test.ts` asserted step-0 prose *equals* `{frag:opening}`, the
converter's retired replace semantics. `compileOpeningEnvelope` prepends, and has
since THR-932 — but no raw entry authored `openings`, so the loop ran zero iterations
and the stale expectation passed for the wrong reason. Its own comment predicted this
("vacuous … until the first migrated template lands"). Prepend is also correct: the
per-class opening is doctrine v2's P1 arrival and the step paragraph is P2+P3, so
equality would discard the authored spine.
