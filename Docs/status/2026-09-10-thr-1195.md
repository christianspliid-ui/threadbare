# 2026-09-10 — THR-1195: the herald is avatar-class

THR-1194 fixed where the Divine Herald *lands*. This fixes whether anything can *see* it.

The mint in `hex.send_herald` wrote `{ name, archetype: 'herald', isHerald: true }` and no
`actorType`. That single property is what every agent sweep in the game filters on —
`getAgentsAtLocation` keeps `actorType === 'individual'` and drops everything else — so the
herald landed correctly placed, correctly threaded at tier 1, and invisible. The player had
divine attention pointed at something no location view could render.

## The decision, and why it invented nothing

The ticket deliberately refused to guess: *"whether a Divine Herald is an individual — or
wants its own `ActorType`, or should be an attachment rather than an actor — is a design
call about what the thing is, not a mechanical drift correction."* It sat in `Todo` for
sixteen days on exactly that basis, and an earlier promotion was reversed for making the
call unilaterally.

The recorded answer (attended design session, 2026-09-10): the graph already had a shape for
*a thing the god sends into the world that is seen but not autonomous* — **the avatar**.
`ascendant.ts` types the avatar `individual` and links it to the ascendant with `avatar_of`;
`phaseAgentDecision` excludes every `avatar_of` source from the autonomous decision loop. So
the herald takes the same two marks and inherits the same standing: visible to every sweep,
never a Maslow agent, never picking its own destinations. No new `ActorType`, no new node
type — the load-bearing "no inventing node types" rule holds because nothing is invented.

## What the code confirmed before the change was written

Two things had to be true for *avatar-class* to be a real answer rather than a convenient
one, and both were checked against the source rather than assumed:

- **`avatar_of` is `many-to-one` in `EDGE_SCHEMA`**, so a second edge to the same ascendant
  is the shape the schema already sanctions, not a squeeze past a singleton.
- **The decision loop reads it through the plural `getAvatarsOf`**, not a `[0]` pick, so the
  exclusion covers a herald the day it exists.

The one place *avatar-class* could have leaked somewhere unwanted is `phaseMovement`, which
computes `isAvatar` per actor and gates three behaviours on it. All three sit inside
`if (movementState && movementQueue.length > 0)`, and Case 2 — an agent with no queue — is a
bare `continue` since destination-picking moved to `phaseAgentDecision`. A herald never
acquires a queue, so the herald is inert there. Worth stating because the alternative reading
("the herald might start announcing *Your ascendant has arrived*") is the plausible-sounding
failure this change does not have.

## The finding worth carrying forward

`avatar_of` is plural in the schema and plural in the decision loop, but **roughly eight
consumers still take `getIncomingEdges(ascendantId, 'avatar_of')[0]` to mean *the player's
avatar***: fog of war (`visibility.ts` ×2), `hexZoom.getLineOfSight`, `avatarMove`,
`phaseInteractionDepth`, `gameInit` ×2, `debugAgentResolver`, the debug bridge, and
`useAvatarData`. `revelationEmitter.getAvatarId` has the same shape by node order.

They all still resolve correctly, and for a reason rather than by luck: the avatar's edge is
wired at world init and the herald's at runtime, and `getIncomingEdges` preserves insertion
order. That is a **correct-by-ordering** invariant, which is a weaker thing than a
correct-by-construction one. It is now locked by a test that exercises it through a real
reader — fog-of-war line of sight from an avatar deliberately parked on a *different* hex
from the herald, so if the herald's edge were ever picked the two verdicts would swap. The
durable fix, should a second avatar-class thing ever be added, is a shared
`getPrimaryAvatar` those eight call sites route through; that is a wider change than this
ticket, and is recorded here rather than filed, per the process-work throttle.

## Verification

Four new tests, 30 in the file. Each states **both polarities** against a **populated**
fixture, because the ticket's own evidence was `getAgentsAtLocation(loc) → []` and an empty
sweep passes an "is it absent?" assertion for free:

- The herald is returned by the sweep, **and** an ordinary villager is too (so a pass cannot
  come from the sweep having been widened to return everything), **and** a faction at the
  same location is not (so it is still a filter).
- The herald is absent from the decision population, **and** passes the tier test on its own
  (so it is genuinely the `avatar_of` edge doing the work, not a tier accident), **and** the
  villager still reaches the loop.

Both arms falsified rather than assumed. Stripping `actorType` alone reds exactly the two
behavioural tests and nothing else; stripping `avatar_of` alone reds the exclusion test and
the avatar-displacement guard while the sweep test stays green. Each assertion fails for the
one change it claims to guard.
