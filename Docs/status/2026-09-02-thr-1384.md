# THR-1384 — the heavy lane: world-simulation tests leave the PR gate

**2026-09-02 · infrastructure.** Thirteen test files that build a world and drive it for 50–300 ticks were 89% of the test suite's CPU on the required check (1,452 s of 1,629 s on run 33653898091), and as a merge gate they had produced more false reds — a heavy file timing out on its own slowness and blocking an unrelated PR — than genuine catches. They now run **after** the merge.

## What changed

- **A fourth vitest project, `heavy`.** `scripts/vitest-test-partition.ts` routes on a `// @vitest-lane heavy — <reason>` docblock tag, and enforces it: `isMechanicallyHeavy` scans every test file for a world build (`initializeGameState*`) driven ≥ `HEAVY_TICK_THRESHOLD` (50) ticks in one case — numeric loop bounds, `while` bounds, and the `runTicks(state, n)` / `runTickBatch(state, n, …)` idioms, resolved through the file's own numeric constants — and the partition test fails if such a file is untagged. Twenty files carry the tag: thirteen by the mechanical predicate, seven by measured CI duration (≥ 10 s) with the measurement as the tag's reason. The tag regex is line-anchored, because the partition's own test quotes the tag in a string and an unanchored scan routed that test into the heavy lane on first contact (impediment #960's shape).
- **`npm test` runs the three fast projects only.** `npm run test:heavy` runs the fourth; `npm run test:all` is the old whole-suite command. The required `Test · Typecheck · Build` job keeps its name and its `npm test`.
- **A non-required workflow, `Heavy simulation tests`** (`.github/workflows/heavy-tests.yml`): every code push to `main` (docs paths ignored, the same six as `ci.yml`'s predicate), nightly at 03:17 UTC, and on dispatch. Registered in `Docs/ops/scheduled-tasks-registry.md`.
- **Its conclusion is read** (the THR-834 lesson). `scripts/check-workflow-health.ts` gains a second membership predicate — every workflow with a `push:` trigger on `main` — judged on push runs by *how long `main` has been red*: `red` inside `PUSH_LANE_RED_GRACE_HOURS` (24) sets `needsSession` so the hourly briefing carries one health line and a session logs the impediment row; `red-stale` past it sets `needsChristian`. The nightly cron is covered by the existing scheduled-workflow predicate for free.
- **The local rule.** `Docs/canon/verification-gates.md` step 8 and CLAUDE.md's gate summary: an engine-touching diff owes `npm run test:heavy` locally before push — the executor's machine is now the last place a heavy-only regression is caught before `main`.

## What is lost, stated plainly

A heavy-only regression lands on `main` before it is detected — at the next code push or the nightly — and its fix is a follow-up PR rather than a blocked merge. Among the twenty files are the strategic liveness gates (`decisionBoardLiveness`, `undertakingCheckpointLiveness`) and three content-art coverage tests; a PR that breaks one of those now learns it after the merge. The ticket's measurement is why that trade is taken: three of the five red test steps in the last 200 PR runs were heavy files timing out, against two genuine catches.

## Evidence

Measured at closeout, recorded in the Linear completion comment: the local fast-suite duration, the local heavy-lane duration, and — the Done-when the ticket sets — three consecutive PR-event runs of the required check with `Run tests` ≤ 480 s, one green heavy run on `main` via push and one via dispatch, and the probe reading a green and a red.

THR-835 (required check at 80–90% of its cap) is superseded: the ratio it asked to watch is answered by moving the cost out of the job rather than by watching the job approach its budget.
