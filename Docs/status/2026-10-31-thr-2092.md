# THR-2092 — The origin and drive pictures stay solid at rest

**Shipped 2026-10-31.** Onboarding & First-Run Experience. `FragmentCard` dimmed the un-hovered picture with `opacity: 0.55`. Once THR-1989 put the stirring backdrop behind the origin row, that opacity let the backdrop's shards show through the bench, the battlefield and the ledger room.

**Fix:** the picture dims by brightness only, so it stays opaque in every state. The new `FRAGMENT_IMAGE_BRIGHTNESS` constant in `src/components/Remembrance/FragmentCard.tsx` holds the three values: selected 1.15, hovered 1.05, rest 0.45 (close to the old 0.55 × 0.75 look). The transition now runs on `filter` only. The edge masks are unchanged. The drive row uses the same card, so it gets the same fix.

**Evidence.** `src/components/Remembrance/__tests__/fragmentCardOpaque.test.tsx` has 3 jsdom tests: rest, hovered and selected are each opaque and use the expected brightness. `npm run gate`: PASS (test, typecheck, build, encounter, god-cards, ui-debt). The browser check ran on worktree Vite :5263, reaching the origin screen from `?account=fresh&size=medium` → New World. The tree probe passed. At 1920×1080 all three cards computed `opacity 1, brightness(0.45)` at rest, and the hovered card computed `brightness(1.05)` while the others stayed at 0.45. The console showed 0 errors and nothing scrolled. In the screenshot the centre of each picture is clean. The backdrop shows only through the intended soft fade on the bottom and side edges.

**UI Laws checked:** 1, 13/14, 17, 21, 33 (fits one 1920×1080 viewport, no scroll), 37, 41 (transition narrowed to `filter`), 45 (caption colour unchanged, `captionContrast.test.ts` passes).
