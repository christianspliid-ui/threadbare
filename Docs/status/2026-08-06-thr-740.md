**A comment described the intended state, the code did the opposite, and the comment had been describing it for long enough that nobody re-read it (THR-740, 2026-08-06).** `codexRegistry.ts` line 66 read "Import the canonical ACTION_ART registry so codex thumbnails stay in sync with the ActionCard without duplicating entries" — and line 68 declared its own 79-row `ACTION_ART` copy directly beneath it. THR-727 had extracted the canonical lookup to `Game/actionArt.ts` for `ActionCard`/`DivineReceiptModal`/`AscendantBeatModal` and left this one behind, so every new card art needed two edits or the codex silently drifted. **The consolidation is behaviour-neutral and that is what made it safe to do mechanically**: the diff run before deleting anything proved the codex copy was a strict *subset* — 79 rows against 87, zero keys unique to it, zero paths disagreeing — so nothing could be lost, and the 8 canonical-only keys are the legacy bare divine aliases (`dream`, `omen`, …) that no codex entry id ever hits. Checked rather than assumed: those 8 do not collide with `ITEM_ART_BASE`, which matters because `ACTION_ART` spreads *last* into `ITEM_ART` and a collision would have silently repointed an item plate. **The regression guard is the deliverable, not the deletion** — a one-line consolidation reverts the moment someone pastes a second map back, so the test asserts exactly one file under `src/` declares `ACTION_ART`, falsified against the pre-fix tree (it names both files and fails). Its two companions pin the drift itself: every codex action thumbnail equals `getActionArt(id)`, and one probe per action family. All three carry non-empty-population guards, because the sampled-entries assertion passes vacuously if the catalog ever stops resolving. **A verification trap worth carrying forward:** the browser probe that was supposed to prove the duplicate was gone used `/ACTION_ART\s*:/` against the Vite dev server's module source — but Vite serves *transformed* TS with the type annotation stripped, so it read "clean" for both files including the one that legitimately still declares the map. It was a false negative dressed as evidence; the corrected probe matches `:` or `=` and discriminates properly (logged as impediment #437).
