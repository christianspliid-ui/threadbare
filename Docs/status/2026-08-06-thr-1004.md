**The rule was broken upstream of the component, so the component rendered the violation faithfully (THR-1004, 2026-08-06).** Director review, second statement of the same law: *"the fundamentals of presenting the game concepts that are manipulated in the aftermath … are not presented with the images and links and tooltips that we usually do. i shouldn't have to repeat this."* His screenshot also carried `0.04 star growth`, `+0.050`, `star.positive tally shifted by +1.00` and `left 1 reward, 3 skill shifts` — magnitudes to two decimals and a raw internal key, on a mortal-facing surface. **The chip module was not the culprit and its header said so** ("sentences are authored prose") — true of the authored half and false of the game, because roughly half the change set is engine-*derived* and those producers were emitting debug-grade template literals that the surface then drew faithfully. Fixed at the source: `engine/aftermathWords.ts` now owns every derived sentence, bands each delta the way `difficultyWord` already bands its own, and resolves `star.positive` through the reach vocabulary; the numbers stay on the trace. **The second half is that a surface cannot honour the UI Law by parsing English**, so the producer declares what it named — `EncounterAftermathChange.concepts` — and the chip attaches the tooltip, the entity tile and the link from that. The link is routed by *kind*: `onSelectEntity` opens a faction or artifact sheet, because handing an artifact id to the agent drawer is a dead link that looks live. `resolveUnifiedReward` was widened to return the instantiated node id, which is what turns the prize chip from a name-hashed fallback tile into the item's own art plus a working link. **Encoded so it stops needing to be said**: the Law is now a named checklist item in `frontend-ui` §7 and in `Docs/canon/design-governance.md` § UI pillar, with the two failure modes named in Anti-Patterns.
