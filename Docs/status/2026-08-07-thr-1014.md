**The delivery machine was stopped for 17 hours by a failure no probe could express, and the fix for the previous outage was itself trapped inside it (THR-1014, 2026-08-07).** THR-1013 taught `check:actions` to see a run that *hangs*; this is the strictly worse case where **no run is created at all**, and a run-list detector is blind to it by construction — a list that stops growing looks exactly like a quiet hour, so the verdict, decided by the newest completed run, reads a stale-but-clean window and answers `healthy` with full confidence. Filed off two PRs measured silent at 20:06Z on 08-06; by 11:12Z on 08-07 the silence had run **17 hours** and spread to four (#1329, #1328, #1327, #1325) — #1329 being THR-1013's own fix, so the remedy for the previous class could not ship because of this one. **The diagnosis narrowed it to a single link:** the last `pull_request`/`push` run created anywhere was 18:04Z, while `workflow_dispatch` (20:05Z) and `schedule` (03:07Z) both ran green and every silent head carried a normal `vercel` suite — so commits, webhooks, workflow file and runner pool were all healthy, and only the event → run-creation path was dead (Actions `enabled`, all four workflows `state=active`). **Recovery was applied before implementation, as a technical verdict:** an empty commit to each head created a suite in **4 seconds** and drained all four; two merged within the hour, ending the stall. That is also the sharpest case for the detector — every one of those 17 hours was pure loss against a one-line fix nobody knew to run. **The fix is a `dispatch-silence` verdict keyed on the check-suites API rather than the run list**, the absence being diagnostic precisely *because* the same commit carries a Vercel suite. It overrides only `healthy`/`recovered`/`transient` — the three verdicts a silenced PR falsifies — so `billing-block`, `stalled` and `unknown` are never masked by a lesser finding; and `standDown` stays false for the `stalled` reason, since no suite means the required check never reports and nothing untested reaches `main`. **Unlike a stall it does not clear on its own**, which the summary states outright and is why it stays a separate verdict. Live proof both ways: `dispatch-silenced=0` post-recovery end to end, plus a live check that the two API shapes parse against real responses.
