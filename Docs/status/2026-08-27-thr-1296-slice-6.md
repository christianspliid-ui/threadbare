# THR-1296 slice 6 — the encounter opt-in (2026-08-27)

The closing slice. Slices 1–5 built the binder and gave it one consumer: a ledger, a
scored board, a mint valve, a bind pass before every checkpoint, and banded creation
effects. All of it served **undertakings**. Slice 6 hands the same board to
**encounters**, one template at a time.

## What the opt-in is for

The recon (THR-1289) measured `EncounterSupportBinding.persistence` as written 60+ times
across the shipped corpus and read by **zero** engine consumers. A template could declare
that a cast member must persist and any reaper would take them silently. Meanwhile
casting itself was a first-match scan: the first body at the placement whose `npcRole`
appeared in `reuseNpcRoles`, with no weight given to whether the player had ever met
them.

A template setting `useScoredBinder: true` changes both. Its actor specs route through
`resolveBinding` — the same five-weight board undertakings cast from, weighing story
ties, identity fit, distance and role scarcity, and able to *modify* a blank field to
make a local fit rather than minting a stranger. And a resolved `must-persist` spec is
written to the binding ledger, so housekeeping defers on that person and a narrative
reaper's kill is traced as a severance instead of vanishing.

## The exemplar, and why that one

`encounter.border.one_body_short`. Its `survivor` key is what
`encounter.border.standing_the_line` binds the crossing person under — a *sequel*
callback. "The same person is still there" was already doing narrative work in that
template's own doc comment, and getting no enforcement whatsoever. It is the one place in
the corpus where the gap between what `must-persist` claimed and what it did was already
load-bearing fiction.

## Three things worth recording

**The golden test is the kill criterion, and it was falsified before it was trusted.**
The plan is explicit: if un-migrated templates move at all, stop and surface. So the
golden test asserts an un-flagged template resolves byte-identically with and without a
binder context — same bindings, same world fingerprint, no ledger row. A golden test
passes trivially if the route never fires, so it ships paired with a falsifier that binds
*different people* down the two paths, plus a controlled arm: with the flag check removed
so the route always ran, both golden tests failed and the other six passed. A guard that
has never failed is not yet evidence.

**A nullable return conflated two different answers, and the fallback ate a real
verdict.** The route first returned `EncounterSupportBinding | null`, with the caller
falling back to the legacy resolver on `null` — sensible fail-soft. But `null` meant both
"the board could not run" *and* "the board ran and its answer was: nobody suitable". The
second one silently fell through to the legacy first-match scan, which would then bind
**the very candidate the board had just declined**, with no ledger row, reading as a
successful bind. The fix is a three-outcome result (`bound` / `unresolved` / `no_answer`)
where only a genuine `binder_error` retries on legacy. The comment describing the intended
behaviour and the code implementing it had disagreed — which is the failure shape slices 4
and 5 each hit from a different direction.

**The delivery gate belongs *in* the board, not after it.** A spec whose `delivery`
forbids materializing must not have its mint decision rejected post-hoc: that throws away
a board that may have held perfectly good reuse rows, because preferring the mint row is a
*preference*, not a veto — slice 4 measured commodity roles preferring mint ~99.8% of the
time even with a role-matched local standing at the stage. `BinderContext.mintAvailable`
already exists for exactly this ("the caller owns the queue, so it owns this bit"), so the
gate is computed first and handed in, and the board returns the best real candidate
instead.

## What is honest about the evidence

The route has **no live-run trace yet**, and the interface-map row says so rather than
badging LIVE. Measured at seed 42 / medium: 120 ticks produced 91 encounter actions
across 52 distinct templates and **zero** firings of the exemplar, so
`strategicState.bindings` held no `enc_*` rows. The evidence is 8 unit tests against the
real board and the real shipped template, both guards falsified — genuine, but not a live
run.

Relatedly, `debugEncounterTools` supplies no binder context at either of its call sites
(the module imports no `SimulationRuntime`), so `?spawn=`, `?forceencounters` and the CLI
`spawn encounter` review a migrated template through the *legacy* path — different casting
from live play. That is one template today and grows with every migration, so it is filed
rather than widened into this slice: **THR-1305**, which carries the live proof with it.

Engine smoke is byte-identical to slices 3, 4 and 5 (386 agents, 52 events at tick 30) —
the neutrality evidence.

## THR-1296 is complete

Six slices: registry + removal hook, scored board + census, born-real mint path + valve,
the bind pass, remote anchor + creation effects, and the encounter opt-in. The owed defect
ticket carrying the recon's pre-existing birth-path evidence is **THR-1304**.
