# 2026-09-27 — THR-1629: a duel's double kill keeps both deaths' grievance nodes

**Ticket:** [THR-1629](https://linear.app/threadbare/issue/THR-1629) · **Project:** Physical Conflict · **Found by:** THR-1628 (duel calibration re-gate) · **Pillars:** Engine (the outcome-node writer). Content N/A (no encounter or catalog entry changed). UI N/A (engine-only evidence per THR-688 rule C).

## What was wrong

When both duellists died in the same step, the fight ending wrote an outcome node for each death. Both ids came out as `evt_und_fight_<actionId>_<tick>`, because the id named the action and the tick but not the victim. The second write threw `Duplicate node ID`, the writer's fail-soft catch swallowed it, and the second death got no outcome node. Its harm never reached the dead mortal's living bonds (THR-1536's grievance route).

## What shipped

- **The id carries the victim when it must.** `createUndertakingOutcomeNode` builds a non-undertaking (fight / battle) id through `nonUndertakingEventNodeId`. The first victim of an action in a tick keeps the bare id, so every single-death id is unchanged. A later victim of the same action and tick gets `_<victimId>` appended.
- **Fixture.** `duelE2.test.ts` runs a real double kill through `onFightEnded`: two outcome nodes, each naming its own victim and culprit, and no `UndertakingOutcomeNode` warning. It fails without the fix.

## Result

`npm run calibrate:duels -- --seed 7 --duels 40` prints no `Duplicate node ID` line.
