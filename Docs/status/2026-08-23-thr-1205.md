# THR-1205 — the bond chip stops arguing with itself

**Shipped 2026-08-23.** Colour and arrow on an aftermath consequence chip are now one signal from one field, and the Grateful Kin welcome states the place it applies at instead of leaving it to the flavour sentence.

## The contradiction

The chip had **two independent authored channels free to disagree**: `toneFor()` read `polarity` and mapped `'mixed'` through `isCost()` to tone `'loss'` (red), while `deltaClusterFor()` read `direction: 'gain'` and drew an **up** triangle in that same red. So `slice.kin.a_cooler_welcome` rendered a red rise. Verbatim, on the screenshot:

> it is red, and with a red arrow up, signifying bad? arrow up or down? i am confused

Never a content bug: **any** `mixed`+`gain` chip rendered that way by construction, and a second band had the same authoring.

## The rule: direction wins, polarity is the tiebreak

`toneFor` now derives tone from `direction` wherever one exists; `polarity` survives only for direction-less chips — all pre-THR-1082 content, unchanged (NFP #6). A weaker-than-hoped gain is a *smaller green* cluster, never a red one; a real cost alongside a grant is two chips, or it stays in prose.

The rule sits **above** the `toll`/`wound` clause deliberately — those kinds only classify from a costing polarity, so a toll declaring a rise is the contradiction being made unrepresentable. Corpus-checked before reordering: of 513 authored changes carrying a polarity, **zero** toll/wound chips declare a rise, so nothing shipped changes and everything future is constrained.

## The second half: state the effect, not the mood

`BOND · A STANDING WELCOME` names a mechanic with no referent; the place was reachable only by reading the italic sentence — *"it is again hidden in prose, which for these particular game effect chips is the opposite of the design … so e.g. improved reputation in sacred grove (green arrow up)"*.

- **The adapter enriches the state noun** (one line), so an author writes `a standing welcome at {target}` and the tag *and* the cluster's spoken label name the place. Display text only — `resolveIcon` still reads the raw ref, so tile and link resolve off `entityId` and cannot disagree with the tag.
- **The four band chips declare a magnitude.** They previously declared none, so every band drew a single triangle: warm and fumbled were indistinguishable at a glance, and only prose told them apart. New band constants sit beside the intensities the reactions write — 3 / 2 / 2 / 1 marks.

Law 56 holds and was not rebuilt: every band writes `trait.condition.location.standing_welcome` onto `$target`, the Location Profile renders it, the chip's anchor clicks through (THR-1172/1173). What failed was the chip's *statement* of the write.

`a_standing_welcome_dearly` moved `mixed` → `gain` rather than splitting: what that band cost was an evening of being talked about, and **no write backs it**, so a SCAR chip would be scene prose in a chip's frame. Its cluster stays at 2 like the plain success — the band writes the same intensity, and shrinking it would imply the welcome was diminished.

## Guards, and the one that was nearly vacuous

**Adapter, exhaustive** — every kind × polarity × direction (8 × 4 × 4) through the real adapter. Reverting `toneFor` reddens it with **21 named offender combinations**.

**Corpus** — walks every authored change from `UNIFIED_ACTION_TEMPLATES` + `LOCATION_BRANCHING_ENCOUNTER_TEMPLATES`, found structurally (by a change's own required fields) so a renamed container cannot silently empty it, with a non-vacuity assertion at the head. **The obvious version was vacuous and was replaced:** "no built chip has a loss tone beside a gain arrow" is now true of *every possible input*, so it would pass forever without reading the content it claims to guard. What can still drift is the **authoring** — the adapter resolves a disagreement silently in direction's favour, so `polarity: 'loss'` beside `direction: 'gain'` yields a coherent green chip that is the opposite of what the author meant. The predicate asserts they agree, and rejects `mixed` wherever a direction is declared. Falsified by name.

**Surface (jsdom)** — the four bands rendered through `EncounterVeil` from the real template: arrow direction, mark count, `--veil-gain-rgb` present and `--veil-loss-rgb` absent, tag text, `aria-label`.
