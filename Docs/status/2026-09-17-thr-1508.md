# THR-1508 — the faction network diagram's nodes click and hover

*Deferral from [THR-1460](https://linear.app/threadbare/issue/THR-1460), filed under the
Browser-verify contract's "a pre-existing violation gets filed with its law number".
Product defect on the FactionSheet: four kinds of world object drawn as inert text.*

## What was wrong

`FactionNetworkGraph` draws a 520×260 SVG with member (Agent), hall and control
(Location) and army nodes, and every one named a real world object as plain `<text>`:
no click, no cursor, no tooltip, no router. The same agent's name was a link in the
Leadership section directly below, on the same sheet. Laws 21, 1 and 17, all four kinds.

## The call the ticket asked to settle in the plan: SVG-native

The description priced the wrinkle honestly — the shared `Tooltip` and the ref router
are DOM affordances, so this was either an SVG-native treatment or an HTML overlay
re-housing the labels. **SVG-native**, because both affordances already reach into SVG:

- `Tooltip` takes `as="g"` (the hex-map overlays use it), so a node hovers its concept
  by wrapping the node group — no portal gymnastics, the popup already portals.
- The router opens a *card* from any element; it needs a DOM anchor only for the hover
  card. A click is a click.

An HTML overlay would have had to track a `viewBox` that scales with the sheet's width
for eight labels. Nothing was re-housed.

## What shipped

**UI** (`src/components/Game/FactionSheet.tsx`):

- `NetworkNode` takes an optional `entityRef: WorldRef` and `tooltipId`. With a router
  in scope the node's `<g>` is `role="link"`, a tab stop with Enter and Space, the
  shared `.focus-ring`, and a click that calls `router.open(ref, 'card', { via:
  'entity-link' })` — never a per-node `onOpen` prop. The name gains the `EntityLink`
  underline in dim gold, so eight of them do not read as eight active states.
- **Fail-open is the designed state, not a broken one.** No router (style guide,
  isolated render) or no ref → the name paints exactly as before: no role, no stop, no
  cursor, no underline. Asserted in its own arm, per the Done-when.
- The **faction core does not link**: this sheet *is* the faction's surface, and a card
  for it over its own sheet is a second answer to an open question (Law 25). It hovers.
- A hall may be a Place inside a settlement; the node uses `location` for both tiers
  because the `sublocation` row routes to the same card and the same sheet.
- **Deliberately not wired:** the router's dwell *hover card*. The tooltip is this
  surface's Tier-1 hover (Law 20); a second floating answer beside it is the thing
  THR-1490 removed elsewhere.

**Content** (`src/data/ui-content.ts`): six registry entries — `ui.faction_core`,
`ui.faction_leader`, `ui.faction_member`, `ui.faction_hall`, `ui.faction_control`,
`ui.faction_army` — one per concept word the sublabel prints. They explain how the
faction *holds* the thing, not what the thing is; the place's own kind stays under
`location.*`. All under Law 18's 200 characters, `ui.faction_member` chains to
`{{ui.standing}}`.

**Engine:** N/A — the summary already carried every id and role the nodes needed.
