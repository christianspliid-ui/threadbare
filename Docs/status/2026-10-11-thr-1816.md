# 2026-10-11 — THR-1816: Escape closes the topmost surface only

**Ticket:** [THR-1816](https://linear.app/threadbare/issue/THR-1816) · UI bug, no plan doc.

- **Cause.** Every overlay hung its own `keydown` listener on `document`, so one Escape reached all of them. With a character sheet open over the EncounterVeil, the veil underneath closed on the same keypress (and the ActionDrawer below it too).
- **Change.** One escape registry, `src/components/shared/useEscapeLayer.ts`: each open surface registers a layer ranked by its stacking band (Law 35), ties broken by later registration; one shared listener runs only the top layer. `Modal` (every modal consumer), `EncounterVeil` (`ENCOUNTER_VEIL_Z` = 50), the sheet's attachment overlay (sheet z + 1), the map detail panel (`ESCAPE_LAYER_Z_PANEL` = 10) and the `ActionDrawer` (40) are on it. `Modal` gains `closeOnEscape` (default true); PremonitionModal, whose `onClose` deliberately ignores Escape (THR-1711), opts out so it does not swallow the Escape meant for the drawer beneath it (review-gate round 1 finding). Other ad-hoc Escape listeners (Dropdown, Tooltip, SettingsPanel, ScryOverlay…) are unchanged.
- **Lock.** `useEscapeLayer.test.ts` (band order, tie order, hand-down, fail-soft) and an EncounterVeil test: a modal over the veil takes the first Escape, the veil the second. Browser: `getOpenModals()` `[ActionDrawer, AgentProfileModal, EncounterVeil]` → Escape → `[ActionDrawer, EncounterVeil]` → Escape → `[ActionDrawer]`.
