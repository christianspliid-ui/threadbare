# 2026-09-18 — THR-1514: the live proof and the census decide seed consumption off state

**Ticket:** [THR-1514](https://linear.app/threadbare/issue/THR-1514) · **Project:** Content Architecture · **Pillars:** Engine (additive), Content N/A, UI N/A.

## What was wrong

`check:undertaking-live` let the *absence* of a `content.query_empty` trace decide its
`catalyst_seeded` fail branch — "the seed was consumed … but no action names it and no query
trace survived" — and that sentence authored a false Medium engine bug
([THR-1510](https://linear.app/threadbare/issue/THR-1510), "silent state-write drop") that was
promoted and claimed before a pickup run spent ~35 minutes falsifying it (impediment row 1049).
`check:content-model-census` read the same ring once at tick 200 and reported `undertaking_catalyst`
at 0 / 0 on a run where the state shows seeds spawning there.

## What shipped

**A seed ledger, off state** — [`scripts/seed-consumption-ledger.ts`](../../scripts/seed-consumption-ledger.ts).
Every path that consumes a seed in `evaluateEncounterSeeds` writes one `TickEvent` whose id is the
seed id plus `_spawned` / `_family_ready` / `_expired` / `_orphaned`. The ledger observes the state
after every `runTick`, registers each pending seed with its site (`seedQuerySite`) and whether
resolving it runs a content query at all (a direct `templateId` does not), and reads the suffixed
event when it leaves. A seed gone with no event is the only *unknown*, and it is reported as unknown.

**The live proof** — `catalyst_seeded` now ranks its evidence: the ledger's consumption event,
then the spawned action's `spawnedFromSeedId`, then whatever `content.query_*` trace survived the
ring (a detail, never a verdict). The wither branch reads
`resolved empty at undertaking_catalyst — judged at anchor <loc> (<subtype>), then feet <loc> (<subtype>)`
off the seed's own `resolutionLocationId` and the target's `located_at`. Discarded seeds name
their reason. No fail branch converts trace absence into a consumption claim.

**The census** — the two seeding sites are counted off the ledger (one per seed that spawned or
withered — exact), every other site off the ring and labelled `ring` (a floor). A new
`Seed consumption (state)` block and `--json` fields `seeds` / `ring` carry the recount.

**Found on the way: the per-tick harvest both proofs used never worked past the first eviction.**
The ring renumbers ids contiguous after every eviction (`traceBuffer.emitTrace`), so a harvest
keyed on `id > lastSeen` collects nothing once the ring has filled. `getTraceEmitCount()` (monotonic)
and `getTraceBufferSize()` are added to `src/engine/traceBuffer.ts` — additive, two exports — and
[`scripts/ring-harvest.ts`](../../scripts/ring-harvest.ts) polls on the count and tallies what it
provably missed (`evictedUnseen`). With it the seed-99 route proof reads 3 checkpoints rolled and
2 moment traces where it read 1 and 1 before; the traces were there, the harvest had stopped.

**A premise corrected.** The ticket (and row 1049) says a medium world emits more traces per tick
than the ring holds, so mid-tick traces are evicted before any tick-end read. Measured with the
fixed harvester on seed 42 / medium / 200 ticks: **51,069 traces harvested, 0 evicted unseen**
(~255 per tick). The undercounts had two causes, neither mid-tick eviction: a single read at tick
200 sees the last 2,000 of 51,069, and the id-keyed harvest stopped at the first eviction. The fix
stands either way — state is authoritative, the ring rows are labelled floors with a measured
eviction count — but the doc text now says "a burst inside one tick *can*", not "does".

## Measured

- **Seed-99 `cell.create.route`** (the ticket's repro): `catalyst_seeded: pass — #consortium_errand
  resolved at undertaking_catalyst → mct.quest.caravan_escort (state.tickEvents
  catalyst_cell.create.route_agent_garrison_culture_0_20_spawned at tick 23; 1 query_resolved
  trace(s) survived the ring)`. Verdict off state; the trace is a footnote.
- **Seed-99 `cell.create.location`**: `catalyst_seeded: fail — #fellowship_errand resolved empty at
  undertaking_catalyst — judged at anchor loc_hamlet_13_20_20 (hamlet), then feet loc_68 (fort); the
  family has no member either place accepts (state.tickEvents …_family_ready at tick 23)`. That is
  the [THR-1515](https://linear.app/threadbare/issue/THR-1515) residue, named from state.
- **Census, seed 42 / medium / 200 ticks** (the Done-when recount): `encounter_seed` 21 resolved /
  18 empty, `undertaking_catalyst` 3 / 6, both `state`-sourced; 112 seeds observed, 59 spawned,
  44 withered, 0 expired, 2 orphaned, 7 pending at the end, **0 left unexplained**. An independent
  probe — a plain loop over `state.tickEvents` with no ledger import — returned the same 21 / 18,
  3 / 6, 112 observed, 7 pending, 0 unregistered. The ring beside them saw 45 / 18 and 8 / 6: a busy
  target re-asks its query each tick, so the ring counts *executions* where the state counts
  *seeds*; the empties agree exactly because a withered seed is consumed on its first ask.
  `step_reward_pool` reads 252 off the per-tick harvest where the ring-at-end read 8.
