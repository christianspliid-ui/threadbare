# THR-1051 — the effect key is gone from the aftermath chip, and the sweep that removed it found the real population lives somewhere else

**Shipped 2026-08-11.** The PRIZE chip of `enc.letters_of_introduction` told the player *"The **content_grant** fires: Patron's Backing is active."* It now reads *"Patron's Backing, now — {cast:patron}'s name answering for the bearer at each tier the seals record."* Law 14 clean on the reported surface.

## The sweep returned one, and that is the finding

The ticket was explicit that the named instance was "the entry point, not the scope", so the predicate — an engine identifier inside an authored `detail`/`label`/`intent`/`overview` string under `src/data/encounters/` — was re-derived rather than trusted. Across **34 files and 1,123 prose-field strings (73k chars)** it returned **exactly one hit: the one already reported.** The population in the ticket's stated scope was the entry point.

That result is the shape a vacuous probe takes, so it was falsified before being believed: the same scan with its `{placeholder}` skip disabled returns **4 distinct snake_case tokens corpus-wide** — `content_grant` plus `reference_contact`, `maren_ironhewn`, `torve_ashgrip`, the last three all sitting inside `{cast:…}` in `flawed-steel.ts` and resolved at render. A scan seeing 73k chars of prose and four tokens is measuring; a scan seeing none would have been broken.

**Re-running the same predicate across all of `src/data/` is what found the real population**, on a surface the ticket did not name — the `description` field of a `UnifiedActionTemplate`, which renders on the action card and in the Codex:

* `unified-action-templates.ts:1429` — *"The agent gains a **knows_clue_of** edge"*: a raw graph edge type, plus `edge` itself as engine vocabulary.
* `unified-action-templates.ts:2216` — *"**v1** raises divine presence sharply … spawning the embodied **place_spirit** actor **is filed as a follow-up**"*: past the raw identifier, this narrates the *development backlog* to the player. A player reading an action card is handed a release note.

Both are out of this ticket's stated scope and were **filed as THR-1085 rather than absorbed** — with a predicate, and with the reason it is not a duplicate of THR-1075, which covers the same class on `ACTION_TECHNICAL_EFFECTS` and whose `effectSourceFor()` predicate cannot reach these strings.

## No regression gate, deliberately

Four further apparent hits were false positives, and they are the reason: all four were `label:` on `hidden_mark` effects, where snake_case is **correct** because the field is an internal mark id, not prose. `label` serves double duty in content files — player-facing reaction text *and* engine identifiers — and there are **33 `hidden_mark` effects inside `src/data/encounters/` alone**. A regex gate over authored prose would therefore false-fail on legitimate future content, against a swept population of one. CLAUDE.md's sunset rule puts the burden of proof on *keeping* a gate rather than removing one, so the durable artifact here is the predicate and its reproduction, recorded on both tickets, not a new standing check.

## The risk was the replacement, not the removal

The new clause introduces `{cast:patron}` into a `detail` field — which is the same defect class, one field over, that THR-1050 fixed the day before. Verified rather than assumed: `patron` is a **declared** key in this template's `supportBundle` (`key: 'patron'`, `patronSpec`), `buildAftermathConsequences` receives `enrich: (text) => enrichProse(text, ctx)` from `buildUnifiedEncounterStageModel:685` with a context built by `resolveSceneCastContext`, and `proseEnrichment.ts` documents the invariant that a declared key always resolves — pinned by an existing assertion, *"resolves `{cast:<key>}` to the member name"*. An **undeclared** key would have stripped silently and shown the player a deleted name, which is precisely how THR-1050's third layer nearly shipped looking fixed.

**Done-when substituted, and stated rather than skipped.** The ticket asked for a browser pass on `?spawn=enc.letters_of_introduction`. The change touches only `src/data/`, which is not a browser-verify trigger path, so per THR-688 Rule C this is Content-pillar work accepted on headless evidence. The CLI confirms the edited branch is reachable — spawned on seed 42 / medium, the formal-channel aftermath fires with its `formal_react_*` reactions — but it **cannot** verify the enrichment, because `aftermath list` prints authored strings unenriched and shows `{cast:patron}` raw by design. That trap is logged as impediment #535; the render path is proven by the wiring above instead.
