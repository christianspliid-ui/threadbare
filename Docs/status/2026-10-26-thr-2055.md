# THR-2055 — Read the Threads tells a missed chapter truthfully

**Shipped 2026-10-26.** Cold playtest round 5, PC-6 / PC-3. A First's chapter that played while the player was away showed in Read the Threads as "Unknown — Resolved successfully", her sheet's story said a lost exchange "was fair enough to hold", and the dormant court listed names twice.

**What changed.**

- **The name.** One helper, `digestAgentName` (digestBuffer), reads `properties.name`, then `node.name`, then "Someone". Every digest writer uses it (phaseAttention, orchestrator, unifiedActionResolution, castTargetChanges). Agents carry their name on `node.name`, which the missed-tug entry never read.
- **The result.** The missed-tug entry is written when the tug lapses, usually before the chapter resolves. It no longer claims `success: true`. If the action has already resolved it carries the band; otherwise it is filed `unresolved` ("Still unfolding") and `unifiedActionResolution` settles it with the real band via `settleDigestOutcome` when the action resolves. Curated-out entries likewise. The chapter is named from its template instead of "Missed Encounter" / "Curated Out".
- **The band.** `DigestEntry` gains optional `outcomeBand` and `unresolved`. The story digest picks its line with `digestEntryWon` (the band wins over `success`) and skips unresolved entries; Read the Threads prints the aftermath's own phrase (`digestOutcomeLabel` → `outcomePhrase`: "It faltered", "Won, at a price"). An at-cost win stays a win, as the aftermath tells it.
- **Once each.** The dormant court is grouped by agent (`oneEntryPerAgent`); Missed opportunities by chapter.

**Evidence.** `npm run gate` PASS (test, typecheck, build, encounter, god-cards, ui-debt, CLI smoke). 13 new tests: `digestOutcome-thr2055.test.ts` (name fallback, unresolved filing, band carry, settling, band-keyed line, de-duplication) and `ReadTheThreadsPanel-thr2055.test.tsx` (jsdom render: "Elara … It faltered.", "Still unfolding.", each dormant name once). Browser-verify substitution: jsdom render; a lapsed First chapter is not reachable on demand in an unattended tab.
