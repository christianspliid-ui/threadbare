**The `Modal` primitive learned to hold focus, and 22 surfaces became keyboard-conformant without any of them changing.** Law 50 — *"opening an overlay moves keyboard focus into it, Tab cycles within it while modal, and closing returns focus to the invoking element"* — was implemented nowhere: grep `Modal.tsx` for `focus` returned zero hits, so every consumer was non-conformant in exactly the same way. THR-1031 found this while composing `Modal` into `EmergenceDilemmaModal` and correctly filed it against the primitive rather than the consumer, which is also the settled answer to THR-1024's "decide the overlay fix shape once": fix focus once, never per consumer, because N component-level traps would themselves be the Law 26/27 defect. Re-derived at pickup, the membership is **22 files** importing `shared/Modal` — the fix is one file and its test. **The non-obvious part is a render-ordering trap that would have shipped a silent no-op.** The panel does not exist on the render where `open` first flips true: the mount effect sets `shouldRender` a render later, so an effect keyed on `[open]` alone runs against a null ref, focuses nothing, and never re-runs. Gating on `[open, shouldRender]` is what makes the move-in real, and the test that proves it passes only because of that gate. **The trap is panel-scoped rather than document-scoped**, which is what makes nesting work: both modals portal to `document.body`, so an outer panel is not an ancestor of an inner one and never sees its keystrokes — a document-level listener would have had two traps fighting over one Tab. Focus restore closes over the invoker in the same effect that moved focus in, so Escape, backdrop click and the close button all restore identically; it is guarded on `isConnected` for the case the invoker unmounted while the overlay was open, which is not hypothetical — a list row that opens a sheet and is then filtered out of its own list. **The browser pass found the strongest case by accident:** `CreditsModal` has exactly *one* focusable control, so first and last are the same element and Tab has nowhere to go — precisely where focus escapes to the page behind without a trap, and where it now holds in both directions. Verified keyboard-only at a real 1920×1080 on two consumers with a wrong-tree guard (`panelHasTabIndexMinus1`), Settings and Credits, each through the full contract: focus enters, Tab reaches the last control, Tab wraps, Escape returns focus to the invoker — `focusReturnedToInvoker: true` on both, zero console errors or warnings. 6 of the 7 new assertions were falsified against the un-widened primitive; the 7th is a fail-soft guard that is vacuous against the old code by construction, since the old code never restored focus at all, and it is reported as such rather than counted as evidence. **One thing deliberately left alone:** `role="dialog"` and `aria-modal` sit on the *backdrop* element, not the panel — arguably the wrong node, but moving them would change the accessible tree for all 22 consumers and break the backdrop-click contract its own test pins, which is a separate decision and not this ticket's. 987 files / 15,588 tests green, ratchet unchanged at 3450, build clean.
