# THR-1349 — the contraction the envelope cannot see (third pass; cutover still not flipped)

**Date:** 2026-09-01 · **Issue:** [THR-1349](https://linear.app/threadbare/issue/THR-1349/the-decision-board-has-no-variety-term-a-live-board-writes-zero-trade) · **Status:** gate shipped, ticket re-scoped to `Todo`

## The question this pass was sent to answer

The second pass left exactly one: *is a live board's idle share real idleness or busy agents miscounted, and does the encounter family lose volume it should keep?* Its suspect was a feedback effect in which agents committed to multi-tick undertakings stop generating candidates and read as idle while actually being busy.

**The suspect is falsified. The loss is real, and it is larger than the idle share suggested.**

## What was measured

Seed 42, medium, 150 ticks, instrumented on `decision_board_comparison`:

| | live |
| -- | -- |
| idle verdicts whose agent held an **active** strategic project | **0** of 522 |
| idle verdicts from a board with **no entries at all** | 466 of 522 |
| idle verdicts from a non-empty board below `BOARD_SCORE_FLOOR` | 56 of 522 |
| agents that decided / that ever idled | 36 / **14** |
| worst idlers, ticks idle out of 150 | 73, 71, 69, 63, 46, 46, 43 |

No busy agent is ever counted idle — a committed agent cannot be, because the loop's `busyAgentIds` skip runs long before the board is scored. Idleness is instead **concentrated**: 14 of 36 deciding agents, several idling half the run, and 466 of their 522 idle verdicts are boards with zero candidates of *either* family.

## The mechanism — a self-reinforcing contraction

Undertakings are what produce world content; world content is what generates candidates. A live board starts fewer undertakings, so less content exists, so fewer candidates are generated, so fewer undertakings start. Measured across both arms:

| | shadow (shipped) | live |
| -- | -- | -- |
| seed 42 — starts / distinct templates | 892 / 54 | **567** / 46 |
| seed 99 — starts / distinct templates | 891 / 48 | **495** / 39 |
| seed 42 — undertaking / encounter / idle share | 20.7% / 61.1% / 18.2% | 33.4% / **34.1%** / **32.5%** |
| seed 99 — undertaking / encounter / idle share | 15.5% / 71.4% / 13.1% | 32.7% / **35.0%** / **32.3%** |
| `trades_with` edges (seed 42 / 99) | 1 / 0 | 0 / 0 |

The encounter family loses **44% of its share** and idleness nearly doubles — and **every §4 criterion reads green on both seeds in both arms**, because they are a floor at `BOARD_ENCOUNTER_SHARE_FLOOR = 0.15` and a ceiling at `BOARD_IDLE_SHARE_CEILING = 0.40`, wide enough to contain a thriving world and a contracting one alike. This is the third instance of the failure class the ticket was filed on.

## Shipped — `CENSUS_UNDERTAKING_START_FLOOR = 700`

A throughput gate on `scripts/undertaking-census.ts`, separate from the variety gate beside it. `CENSUS_DISTINCT_TEMPLATE_FLOOR`'s own note refused to be raised to ~41–44 to separate the cutover arms, on the grounds that it would then fail on *throughput* while naming *variety* — the vacuity shape this file has shipped twice. The answer to a gate that cannot name its own failure is a second gate that can, and the measurement above is why: 39 distinct templates over 495 starts passes the variety gate as readily as 48 over 891.

Sized on the shipped configuration, which is stable to within one start across two unrelated seeds (892 / 891), giving ~21% headroom.

**Guard falsified rather than assumed.** PASS on the shipped `'shadow'` arm at 892 and 891; FAIL on the `'live'` arm at 567 and 495 — on both seeds, while the variety gate beside it passes on all four arms.

## The two red acceptance tests, characterised

Both were re-measured this pass. Neither is evidence the board is broken, and neither was adjusted:

- **`edgeIntegrity` — "writes trade routes"**. Under a live board `strategic_establish_trade_route` reaches the board 8 times, is never ranked first, and carries a `desireMultiplier` of `0.0112` — the `MINIMUM_DESIRE` floor — against a healthy EVT of `0.0387`. Under `'shadow'` the same board ranks it **nowhere at all** (0 appearances in the top‑N) while contest B starts it 6 times. Routes exist today only because contest B never reads desire, i.e. the world's one trade-ambition holder builds routes he does not want. The second pass settled that this mismatch is *correct*, so the assertion is measuring a contest-B artefact. The route economy's own home is THR-1348.
- **`lairClearing` — "reinfests cleared lairs"**. Cleared lairs move 3 → 2 between arms; the failing subset needs at least one cleared lair with `sphereScore ≥ 4`, and the shipped arm has exactly one (scores `[6, 1, 1]` → `[1, 0]`). It is an n=1 guard that will flip on any world-shifting change, in either direction.

## Why the flip still does not land

Not because of the two red tests — both are miscalibrated guards, stated above with their measurements. Because the cutover's principal measured effect is a **36% loss of undertaking volume and a 44% loss of encounter share**, and shipping a cutover whose main consequence no gate can read is the exact failure this ticket exists to prevent. That gate now exists; the flip lands when the arm passes it.

`UNIFIED_DECISION_BOARD_MODE` stays `'shadow'`; contest B, `STRATEGIC_ENCOUNTER_SCORE_BRIDGE` and the strategic clamp are untouched — they go in one commit with the flip or none.
