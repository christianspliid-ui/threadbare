# THR-1244 — Being wounded became an event, so wards can answer it

**2026-08-26 · Powers & Item Generation · Engine pillar**

Stage 6 of the effect-vocabulary activation program, and the last of its three trigger families
with no source event. `damaged` and `healed` have been in the `EffectEvent` union since the
primitive architecture landed, read by the `damaged`/`healed` reactive triggers, the
`on_damaged`/`on_heal` stack triggers and the `take_damage` expiry event. Nothing raised either.

**Why nothing raised them is the interesting part.** This was not a missing call — it was
missing *by construction*. The game has no per-agent damage model, so there was no hit-point
subtraction to hang a raise on, and an audit that grepped for a producer and found none would
have been correct and useless. The answer was not "wire it" but "decide what, in this game's own
vocabulary, being hurt is". It already had a word: a wound is a **condition with a countdown**,
and recovering is that countdown running out. So inflicting a harmful condition raises `damaged`
and lifting one **early** raises `healed`, from all three aftermath condition writers through
`src/engine/effects/conditionProxyEvents.ts`. Because step-outcome effects dispatch through the
same `applyEncounterAftermathReaction` (THR-783), a lost tavern brawl now fires the bearer's
wards with nothing extra to author.

**Natural expiry deliberately raises nothing**, and that absence is the load-bearing half:
waiting out a bruise is not being healed, and a proxy keyed on "a condition went away" would
fire every ward in the world on every `decayConditions` sweep. It is enforced by *where the raise
lives* — `conditionDecay.ts` does not call the module — not by a check that a later refactor
could relax.

**Three corrections the plan doc needed**, recorded there rather than absorbed silently. The
named "wound/disease/curse subfamily" **does not exist**; the live vocabulary is the `#negative`
tag, so the predicate reads that instead of a phantom field. `conditionDecay.ts` is listed among
the raise sites and is precisely where the raise must *not* go, since it is the natural-expiry
path the stage's own definition excludes. And there are **three** aftermath writers, not one:
`condition_attachment` is the kind every shipped `trait.condition.wounded` in the tavern package
actually authors, so wiring only `apply_condition` would have left the busiest infliction path
silent while the stage read as done — this program's signature failure.

**Found by driving a live world, not by reading the plan:** a **fourth** writer,
`actionTriggerPayloads.ts`, is live (observed at t24 of a seed-42 medium run) and still raises
nothing — and the conditions it grants sit in two other catalogs tagged topically (`#cursed`,
`#curse`) with no polarity at all, so `anomaly_vault_curse` would read as *not harm*. Wiring the
site without reconciling the vocabulary would turn an honest absence into a live-but-silently-
wrong classification, so both ride **THR-1257** together. Deferred rather than folded in because
it is a real signature change: `applyActionTriggerPayloads` takes `WorldGraph`, not `GameState`,
and its orchestrator caller sits inside the `runningEffectStates` threading loop where a direct
write is discarded at end of tick.

**Evidence.** 1085 files / 18158 tests green; ratchet unchanged at 3009; build clean; 30-tick
smoke reaching tick 30 with 384 agents. Non-vacuous by falsification rather than by assertion:
each of the four guards was disabled in turn and each failed exactly its own test and no others
(harm gate 2, person gate 1, the `condition_attachment` raise 1, the `removedCount` gate 1), and
adding a raise *into* `conditionDecay` fails exactly the natural-expiry silence test — the
assertion the whole "early" half rests on.
