# THR-1064 — the stone set is not inverted; 37 of the other 39 are

**2026-08-10.** The ticket asked for a design decision to be implemented: the five `AX-STONE-*` templates read backwards against `preservation_transformation`, and Christian ruled **option 2, "flip the label"** (Discord 2026-08-09 15:12Z, recorded on the ticket 15:57Z). The gate was satisfied and the remedy approved. It was not implemented, because the premise it rests on is false — and applying it would have broken content that is currently correct.

## What the ticket asserted, and what the code says

The ticket's table reads `| pole a (the - shift) | pole b (the + shift) |` and then states *"Under the pair, pole `a` is **preservation** and pole `b` is **transformation**."* That identification is inverted. `AxiologicalProfile` is signed the other way, and four independent sites agree:

* `src/types/agent.ts:5-6` — *"Convention: +1.0 = virtue/first pole, -1.0 = flaw/second pole."*
* `ARCHETYPE_NAMES` — `preservation_transformation: { positive: 'Guardian', negative: 'Shaper' }`
* `src/engine/encounters/poleLean.ts:19-22` — *"Positive weight = pole `'a'` = … the **first-named pole** … the `+1` direction in `AxiologicalProfile`."*
* `src/engine/meetingEncounter.ts:596-598` — `const shift = writtenPole === 'a' ? magnitude : -magnitude;`

Nothing negates in between: `applyAxiologicalShifts` does `result[key] = clamp(result[key] + shift)`.

So the `-0.3` shift is the **second** pole, not the first. Read that way the stone set is right:

| choice | content | shift | pole written |
| -- | -- | -- | -- |
| `a` | laugh, admit it, be taught | `-0.3` | transformation — being changed |
| `b` | *"Pride preserved is a wall … keeps the self intact"* | `+0.3` | preservation |

The ticket quotes that same sentence as its clinching evidence, reading it as *"pole `b`, labelled transformation"*. Pole `b` is labelled **preservation**, and pride preserved is preservation. The evidence supports the opposite of the conclusion drawn from it.

## Why stone reads wrong from a distance

Two inversions cancel. The header records `Stone: humility_pride → preservation_transformation`, and that rename mapped humility→preservation when humility is semantically the *transforming* side. Separately, the library writes the first-pole choice with a negative sign. Stone is the one reach where both apply, so it lands correct while the other seven land wrong.

## The real defect, measured

Iterating the real library rather than reading a doc:

```
converted templates with a `test`: 40
choice-a carries a NEGATIVE shift: 37
```

`AX-IRON-01` choice `a` is the mercy choice by its own text, `gateTags: ['heroic_origin', 'mercy_shown']` and `traitSeeds: ['unyielding_compassion']`, and writes `{ 'mercy_ruthlessness': -0.3 }` — which moves the profile toward **Conqueror**. Showing mercy makes an agent more ruthless, on 37 of 40 templates.

There is a second, independent half. The converted `test` blocks bind pole letters to the **choices** (`AX-STONE-01`'s `poleLean: 'a'` cards all argue choice `a`; `cleanA` is choice `a`'s prose) while the engine binds them to the **profile**. Where choice `a` is negative — the same 37 — the formative path and the legacy choice path write **opposite** directions for the same narrative outcome, and neither path can see it alone.

Filed as **THR-1071** (High), with both halves, the reproduction, and the two candidate remedies stated as non-equivalent.

## What shipped here

Comment-only, in `src/data/meeting-dilemma-library.ts`. The five stone `test` blocks carried notes from THR-875 asserting the set was backwards and pointing at `TODO(THR-1064)`; those notes are now measurably wrong and would have sent the next reader down the same path. ## Disposition
