# THR-2242 — the pre-bonded First has a meeting record

**Shipped 2026-11-16.** Thematic Pressure & Living World. No plan doc (the ticket's § Fix is the plan).

- **The bug.** `devSeedTheFirst` wrote the thread edge with `meetingChoiceRecord: null`. With no record, `passesFoundingGate` lets only gateless outcomes through, and `vanishing` is the only one. So on the seeded route (`?view=game&seeded`, warm playtests, expert sessions, every headless census) every Return ended in Vanishing, whatever the Ordeal did.
- **The change.** `src/engine/gameInit.ts`: new `buildDevFirstMeetingRecord` writes a record a real heart-primary meeting could have produced. It reads two real library choices (`DEV_FIRST_MEETING_CHOICES`: `AX-HEART-01`/`ax-heart-01-a` and `RC-HEART-02`/`rc-heart-02-a`, which fit the seeded First's loyal and merciful profile) and copies them the way `applyDilemmaChoice` copies a live choice. Founding-gate tags: `devotion_seed`, `duty_over_desire`, `mercy_shown`. Reaches heart/shadow (archetype key `heart_shadow`), the ascendant's primary sphere. A missing template is skipped, never thrown. `sparkVisionId` stays empty, as `buildMeetingResult` writes it with no vision, so the seeded First gets no vision path (`firstPath.ts`): that would be a separate change.
- **The test.** `src/engine/__tests__/devFirstMeetingRecord.thr2242.test.ts` (4): the record's choices are real library choices; no vision path; founding gates pass an outcome besides `vanishing`; `resolveReturn` gives different outcomes for `broken` and `triumph`, and `triumph` is not `vanishing`.

**Evidence.** `npm run gate` PASS (test, typecheck, build, encounter, god-cards, ui-debt, cli-smoke). Agency census on the branch: seed 42 played (Ordeal `triumph`) now ends `loyal_ascension`; the five `broken` arms end `vanishing`, which the gates allow (Broken closes Loyal Ascension; Vanishing outscores Sacrifice). Verdict: the player mattered on 2/2 measured seeds; seed 7 was not measured because its arms hit the 540 s budget when run in parallel.
