# THR-1077 / THR-954 — the coordination layer got simpler instead of getting another ticket

**Shipped 2026-08-10, directed by Christian in chat** ("please take another look at the setup based on this analysis and simplify if possible"). The trigger was an ordinary hourly PM run whose own output made the case: 35 items ready for dev of which 32 were low-priority process cleanup and zero were feature work, nine green health probes, a standing-asks file where Christian's actual asks started at line 685 of 1047 — and the run's contribution to fixing this was to file another process ticket.

## What changed

- **`.claude/skills/keep-work-flowing-cc/SKILL.md` rewritten, 440 → ~150 lines.** Same essential behavior (Discord inbox → board scan → probes → brief → publish → ping), but the seven per-probe essays collapsed into one uniform treatment table, and the incident archaeology moved to where it already lives — git history and the tickets. The rewrite also *fixed a real drift*: the scheduled-task prompt ran `check:workflows` while the skill file never mentioned it; the probe (which caught the 88-of-88 red sweep) is now in the skill, and the prompt is a pointer instead of a duplicate.
- **The briefing leads with one ask.** Six parallel "go play the game" asks read as a chore list and none of them happened; the format now forces a choice of the single most valuable ask, with the rest as one-liners.
- **`Design/user-actions.md` cut 1047 → ~50 lines** (THR-1077): standing asks first, a ≤10-entry resolved tail, nothing else, ~150-line cap enforced by the skill. History stays in `git log -p origin/ops`.
- **The substantive-change publish gate retired for the briefing lane** (THR-954). Decision recorded on the ticket: its premise (protecting `main`'s tip) died with THR-947/THR-983, `ops` commits are free, and the gate demonstrably suppressed a factual correction for an hour on 2026-08-10 because its digest keys on one file while gating two. The orchestrator's report-lane use is **retained** — "a no-op run writes no file" still earns its keep there.
- **CLAUDE.md § Process-work throttle** (Christian's direction): scheduled lanes stop filing process/infrastructure tickets — findings go to the impediment log, the weekly retro is the single promotion point; and probes/gates/rules **sunset by default** after six weeks without a real catch, with the burden of proof on keeping.

## Why the root rule instead of five prompt edits

The materiality bar (2026-08-08) constrained what *qualifies* as a process ticket; nothing constrained *who files*, so the lanes — which inspect themselves and always find more — kept minting. One rule in CLAUDE.md binds every session including scheduled ones and explicitly supersedes stale "file findings" wording in lane prompts; aligning each prompt's text is left to the weekly retro, which now has the authority to delete rather than accrete.
