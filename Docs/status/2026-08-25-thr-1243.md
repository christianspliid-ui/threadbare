### THR-1243 — the aura reaches resolution (2026-08-25)

**A finished module with nobody calling it.** `src/engine/effectAura.ts` shipped complete
and tested — hex distance, faction filtering, per-reach aggregation — and had **zero
production importers**. `resolveAuraModifiers` appeared in exactly two places in the whole
repo: its own definition, and its own test. Stage 5 of the effect-vocabulary activation
program (`Docs/plans/2026-08-25-effect-vocabulary-activation.md`) wires it into
resolution-time modifier collection.

**Why it was never wired, which is the interesting part.** An aura is the only resolution
modifier sourced from an agent *other than the one being resolved*. Every other channel —
equipment, traits, spheres, rule overrides — is a walk from the acting agent outward, so
each had an obvious place to hang. An aura has none: it needs to know who is standing
nearby. The tempting home was the tick loop, and that is an O(agents²) proximity scan every
tick to compute a number almost none of those agents will read before it goes stale.

So it resolves **lazily, for one agent, at the moment a step actually resolves** — the only
moment the number is read. `collectAuraEffectsNear` is the same walk as the existing
collector with the distance test moved *before* the attachment walk: resolving a position is
one edge lookup, walking three attachment edge types and every attached node's `effects`
array is several times that, so the expensive half now runs only for agents standing within
`AURA_MAX_RADIUS`.

**Two bounds doing different jobs.** `AURA_STACKING_CAP` (3) bounds how many emitters may
speak — one emitter counted once however many aura items they carry, strongest first, ranked
deterministically so the survivors do not depend on graph node order. `EFFECT_MODIFIER_CAP`
then clamps how loud the answer may be. Both are needed: the cap alone would let three
enormous auras run away, and the clamp alone would let a crowded capital decide a step
through sheer attendance, so the identical encounter would read differently in a city than
in a hamlet for reasons no player could see or influence.

**One judgment call, recorded.** The plan's constants table asked for a new
`AURA_RADIUS_HEXES = 1`. `AURA_MAX_RADIUS = 2` already existed, already clamped every aura
in `collectAuraEffects`, and was already load-bearing in shipped tests. Minting a second
radius name that disagreed with the first is precisely the duplicate-spelling pathology
stage 4 of this same program exists to remove, so the existing constant was used and the
plan's row folded onto it. `AURA_STACKING_CAP` is genuinely new and was added.

**The content half: an unnamed number is not allowed to move a roll.**
`deriveContributionLines` silently drops any contribution whose `kind` has no authored
sentence. A new `aura` kind with no prose would therefore have tilted the roll while
rendering nothing — the exact failure the factor panel exists to prevent. So
`DERIVED_FACTOR_SENTENCES` gained an `aura` pair, naming **the emitting agent** rather than
the item they carry: "Having Kael Thornweaver near steadies her". The acting mortal does not
own that banner and cannot see it; crediting it as gear would be a lie about whose it is.

**Falsified rather than assumed.** Forcing the distance test true fails exactly one test
(the out-of-range drop); deleting the `aura` prose pair fails exactly one other (the factor
line). Two failed, fifty-one passed — so the tests hold the wiring and the naming, not the
aggregator that was already green before this ticket.

**Reach note, stated plainly:** no shipped catalog entry authors an `aura` effect yet. This
makes the primitive real so content can use it; it does not, by itself, change any encounter
already in the game. Capability 24 in the systemic wiring guide is the author-facing half.

**Gates:** 1075 files / 17,820 tests green (one `scripts/__tests__` contention flake on the
first run — passes in isolation in 642ms against a 5s timeout, green on full re-run),
ratchet **3010 unchanged**, `vite build` ✓, engine smoke reached tick 30 with 384 agents and
42 events. `Browser-verify exempt: engine-only change, no UI-pillar files touched.`
