# THR-1142 — `agent_relocation`: encounters can send people somewhere

**Shipped 2026-08-16.** First member of the consequence-palette expansion (plan doc
`Docs/plans/2026-08-16-consequence-palette-expansion.md` § Primitive A).

## What landed

An aftermath effect kind that moves people — a departure, an exile, a pilgrimage.
Until now nothing in the effect vocabulary could move anyone, which is the gap the
THR-1141 Law 56 census kept walking into: endings like "Maret Departs", "East Is
Theirs" and "He Left First" *described* movement that nothing caused, so their
chips claimed state no write backed.

Default `travel` mode writes a `relocationIntent` on the agent node and stops. The
decision phase reads it through `computeRelocationIntentBonus`, which adds
`RELOCATION_INTENT_SCORE_WEIGHT / (1 + hexDistance)` to encounter candidates near
the destination — the same additive channel and the same shape as Draw Together's
convergence pull (THR-74). Nobody teleports; the mortal walks there through the
ordinary movement system and the journey stays visible on the map. `instant` mode
retargets the `located_at` edge now, for scene logic, through the same
`rebindLocatedAt` the CLI's `move agent` uses — one position-write path, not two.

Arrival (hex-granular) and TTL expiry both clear the intent in the decision phase
and trace it, so nobody walks forever. `residence: 'set_destination'` stamps
observed residence *on arrival* via THR-822's `observeResidence`, never predicted
ahead of the agent.

## The reader shipped with the write

The plan's standing rule — *"every write has its reader live in the same PR"* — is
the whole point of the primitive, and it nearly shipped hollow. The first version
of the test suite asserted the pull by calling `computeRelocationIntentBonus`
directly, and **passed with the scoring term reverted**: 37 green tests over a
write no system consumed. The fix was an integration arm that drives the real
`scoreAndSelect` and asserts the board re-ranks; that arm fails when the term is
removed, which is what makes the wiring claim true rather than asserted.

## What the measurement changed

Proved on the real `initializeGameState` → `runTick` pipeline (seed 42, medium),
not a fixture: destination candidate `0.0101` → `0.6985` with the intent set, agent
closed **26 → 20 hexes over 60 ticks** with the intent still live.

The same probe found the primitive's real shape, which the plan did not anticipate:
because the pull attaches to *encounter candidates*, it steers hard toward a
destination that has something happening and only weakly toward an empty one — one
agent aimed at a quiet settlement drifted 6 → 12 hexes *away*, the rest of the
board simply outvoting a 0.07 lean. That is a property of steering through the
encounter board rather than adding a second mover (the thing the plan explicitly
ruled out), so it is documented in the module header and the wiring-guide row
rather than patched, with the design question filed as THR-1148.

  Done-when unreachable.
