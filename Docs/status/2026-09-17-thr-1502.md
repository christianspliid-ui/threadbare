# THR-1502 — `getActivitySummary` had no caller; verdict (b), delete

**Date:** 2026-09-17 · **Pillars:** Engine · Content-N/A (no authored content touched) · UI-N/A (one call-site argument dropped in a hook, no render changes)
**Issue:** [THR-1502](https://linear.app/threadbare/issue/THR-1502/getactivitysummary-has-no-production-caller-its-only-renderer-was-the)
**Plan doc:** none — the ticket body was the spec, a two-arm disposition fork.

Deferral filed by [THR-1492](https://linear.app/threadbare/issue/THR-1492) when deleting `AgentDetailPanel` exposed that `src/engine/activitySummary.ts` had lost its only renderer. The ticket asked for a verdict, not a prune: **(a)** wire a reader if an actor's current action is something a surface should say, or **(b)** delete the module with its test and apply the same predicate to `agentDetail.ts`'s `activeUndertakings` projection.

## The verdict is (b), and the reason is that (a) already exists

The question "what is this mortal doing right now" is answered on a live surface today, through a different producer:

- `src/engine/deriveLocationActivities.ts:549-552` picks each actor's first unresolved `UnifiedAction` and turns it into an `AgentActivityThread` — a familiarity-gated **prose** line, with the step folded in as words — read by `HexTooltip` and `LiveLocationBar`.
- The agent sheet shows drives through `ActiveIntent` (`IntentSection`) and undertakings through direct `summarizeActiveUndertakings` calls in `JourneyTab.tsx:176` and `useAgentInteraction.ts:209`.

`getActivitySummary` derived the same fact as a **numeral** — `stepLabel: "Step 2/3"` and a `progressFraction` for a progress bar — which is the shape UI Law 14 forbids on the sheet. Wiring it would have shipped a second, worse reader of a fact the game already states in words. So it went, with its unit test: seven cases of green coverage over a function nobody called.

## What went, and the one thing that stayed

| Residue | Disposition |
|---|---|
| `src/engine/activitySummary.ts` + `src/engine/__tests__/activitySummary.test.ts` | Deleted. |
| `AgentDetail.activeUndertakings` field and its assignment in `getAgentDetail` | Deleted — same predicate, same answer. Every reader of undertakings calls `summarizeActiveUndertakings` directly with the strategic state it already holds. |
| `getAgentDetail`'s optional `strategicState` parameter | Deleted with the assignment that was its only use; `noUnusedParameters` is on in both tsconfigs, so leaving it would have been a net-new ratchet error. The one production caller passing it (`useAgentInteraction.ts:139`) drops the argument. |
| `summarizeActiveUndertakings` and `ActiveUndertakingSummary` | **Kept.** Three live readers. The dead thing was the *copy* of that projection on the detail record, not the projection. |
