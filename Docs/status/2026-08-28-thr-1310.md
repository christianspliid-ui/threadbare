# THR-1310 — strategic works now look for somewhere near to do themselves

**Shipped 2026-08-28.** Engine pillar (Content/UI N/A — no authored content changed, no
surface renders target selection). Deferral filed at THR-1297 slice 6 closeout.

## What was wrong

`findValidTargets` resolved a `location_subtype` target rule by scanning every location
in the graph — 731 on a seed-42 medium map, 876 on seed 99 — filtering by subtype, and
keeping the **first eight in worldgen insertion order**. Insertion order is identical for
every agent alive, so the shortlist did not depend on where the agent stood: every mortal
pursuing the same ambition proposed the same distant site, and the matching site over the
next hill was discarded before `travelPenalty` could ever score it.

The rule is shared by **all seven strategic packs — 53 templates** — so this was a shared
seam, not a wanderer-pack quirk. Measured before the fix, mean actor→target hex distance
was **13.19** (seed 42) and **13.37** (seed 99) on maps whose whole width is a few dozen
hexes.

Every unit test stayed green throughout and structurally could not have caught it: they
assert the ops write correctly *given* a target, which they always did.

## What shipped

`orderTargetsByProximity` sorts a scanned target set by hex distance from the acting
agent **before** the cap is applied, so the cap keeps the nearest N rather than the
oldest N. Applied to all four graph-scanning rules — `location_subtype` (the live
defect), plus `any_location`, `sublocation_type` and `actor_with_trait`, which share the
shape prophylactically since no shipped template names them yet. `colocated_actor` is
capped by the same named constant but deliberately not reordered: every candidate there
already stands at the same location.

Three design choices worth recording:

- **Ordering, not a second penalty.** Distance still gets *priced* exactly where it was,
  by `travelPenalty` in the scoring phase. A hard exclusion radius was rejected: it would
  have been a second uncalibrated distance term, and on a sparse map it could empty a
  target set the scan had legitimately filled — turning a targeting fix into a liveness
  regression.
- **Unresolvable hexes sort last, never drop.** Same reason. A node with no resolvable
  hex is still a legal target.
- **Caps preserve their shipped values** (8 for `location_subtype`, 5 elsewhere), now as
  the named `STRATEGIC_TARGET_SCAN_CAPS` record (NFP #1). The sweep re-points *which*
  targets survive, never *how many*, so the golden comparison has one variable in it.

## The finding that corrects the ticket's own premise

THR-1310 expected that once targeting was proximity-aware, the wilderness chart verbs
could be restored to `requiresLocation: true` — the presence gate THR-1297 slice 5 had to
switch off to keep the `chart_find` kind alive. **Re-measured with the fix in place, they
cannot.** The wanderer family still reports **0/115 rolled on seed 42 and 0/31 on seed
99** at `true` — 100% `actor_absent`, the same total inertness as before the fix.

The reason is that proximity and presence are different claims. `isActorAtStage` demands
the agent *be at* the site; nothing in the engine moves an agent toward its undertaking's
stage, because that mover is doc 3's binder and has not shipped. Targeting was never the
whole cause — it was the visible half of a two-part gap.

So the chart verbs keep `requiresLocation: false`, now on sharper evidence than slice 5
had: not "we cannot tell why presence starves this kind" but "presence starves it for a
reason a targeting fix provably cannot reach". The wanderer pack's header comment, which
predicted the opposite, was corrected in the same commit rather than left to ship
falsified. Re-measure when the binder lands (TODO(THR-1294)).

## Evidence

**Golden comparison** (both arms in one process against the same world, 53 templates ×
200 actors = 10,600 pairs per seed):

| | seed 42 | seed 99 |
|---|---|---|
| target sets emptied by the sweep | **0** | **0** |
| templates whose mean distance got worse | **0** | **0** |
| mean actor→target distance | 13.19 → **7.33** | 13.37 → **7.14** |
| median actor→target distance | 13.00 → **7.00** | 13.00 → **6.00** |
| old/new set overlap | 42.9% | 38.7% |

The wilderness verbs the ticket named move furthest: `strategic_chart_the_wilds`
16.04 → 4.90 (seed 42), 16.73 → 5.61 (seed 99).

**Liveness gate** (`npm run census:undertakings`, the Done-when's ≥ 50% rolled): 94.7% →
**93.8%** on seed 42, 95.0% → **98.6%** on seed 99. Holds on both.

**Not fixed here, and pre-existing:** the census's `undertaking share in [0.1, 0.35]`
gate fails on seed 99 both before (8.3%) and after (7.3%) this change. That is the
THR-1301 cutover gate, not this ticket's; it is reported rather than quietly absorbed.
The 1pp move is a real consequence of re-pointing 53 templates, not noise — the sim is
deterministic.

**Regression test:** `src/engine/__tests__/strategicTargetProximity.test.ts`, 8 tests,
built far-first so "first N by insertion" and "nearest N" are disjoint sets. Falsified
under a controlled arm that restores the pre-fix slice: **5 of 8 go red**, and the 3 that
stay green are precisely the ones asserting preserved behaviour (liveness fallback,
`travelPenalty` pricing, null-hex fallback). A test that merely asserted "returns some
targets" would have passed through the entire broken state, which is how the suite missed
this in the first place.
