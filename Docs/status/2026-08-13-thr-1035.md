# THR-1035 — the Chapter Ledger stops naming the engine's enum at the player

**Shipped 2026-08-13** · `tb-opus-pickup` hourly lane · [THR-1035](https://linear.app/threadbare/issue/THR-1035/chapter-ledger-renders-the-raw-internal-outcome-key-eg-success-at-cost)

## What was wrong

One template literal, in [`ChapterLedger.tsx`](https://github.com/christianspliid-ui/threadbare/blob/main/src/components/Game/ChapterLedger.tsx):

```ts
statusLabel: `resolved · ${r.outcome ?? 'unknown'}`,
```

`r.outcome` is a `UnifiedActionOutcome` — the engine's seven-value enum — so the ledger row
read `Vara · resolved · success_at_cost`. A direct Law 14 violation ("no raw internal keys,
ever").

## The part that made it worth more than a find-and-replace

The words already existed, and they were **one click away from the defect**.

`ChapterView` — the detail surface the ledger row opens — has carried an authored lexicon
since THR-571 U1: `success_at_cost` → *"won, at a price"*, `critical_failure` → *"it broke"*.
But it lived as a component-local `const FINAL_OUTCOME_LABEL` inside `ChapterView.tsx`, so the
*row* could not reach it. The player therefore got the enum in the list and the prose in the
detail, about the same chapter, from the same field.

So the fix is a hoist, not an invention: the lexicon moved to `engine/aftermathWords.ts` —
the module whose own header already declares itself "the *only* place the question is
answered" — and both surfaces now read from it. Authoring a second vocabulary for the ledger
would have shipped the visible half of the bug while leaving its cause (two copies, one
unreachable) in place, and guaranteed the two would drift.

The hoist also closed a **second, latent instance one branch away**: `ChapterView` resolved
its own label as `FINAL_OUTCOME_LABEL[finalOutcome] ?? finalOutcome`, whose fallback is the
raw key. Unreachable today because the map is total over the union — but it is the exact
defect being fixed, armed and waiting for the eighth band. `outcomePhrase` replaces it with
Law 14's actual fallback clause: humanise, warn once, never the key.

## What changed

| File | Change |
|---|---|
| `src/engine/aftermathWords.ts` | `OUTCOME_PHRASES` (the hoisted THR-571 lexicon, typed as a **total** `Record` over the union so a new band fails the typecheck rather than reaching a player) + `outcomePhrase()` with humanise-and-warn-once fallback, and a `resetOutcomeWarnings()` test seam |
| `src/components/Game/ChapterLedger.tsx` | `resolvedStatusLabel()` — exported so it is directly testable; an outcome-less chapter now says just `resolved`, not `resolved · unknown` |
| `src/components/Game/ChapterView.tsx` | Reads the hoisted lexicon; the raw-key fallback is gone. The **tone** map stays local — colour is that surface's business, vocabulary is not |
| `src/engine/__tests__/aftermathWords.test.ts` | Vocabulary gate: every band resolves, no phrase is its own key or carries an underscore, absent → `null`, unknown → humanised + warns once |
| `src/components/Game/__tests__/ChapterLedger-outcomeLabel.test.tsx` (new) | **Renders the real component** and asserts `container.textContent` for all seven bands |

`resolved · unknown` was dropped deliberately: an archived chapter without an outcome is a
real state, and the old string answered a question nobody asked.

## Verification

`npm test` 999 files / 15,954 tests green · ratchet unchanged at 3447 · `vite build` clean.
No engine-behaviour file touched (vocabulary + component only), so no 30-tick smoke owed.

**Both new suites were falsified** by reverting the call site to its pre-fix form — 4/4 red
each time, reproducing `resolved · success_at_cost` exactly.

**Browser-verify substitution: jsdom render assertions on the real `ChapterLedger` — the
1920×1080 pixel capture is owed.** `preview_start` is refused in unattended runs
(impediment #546, fourth occurrence), so no sanctioned capture route terminates at a URL.
Honest here by #546's own scope test: the change swaps one label string for an equal-length
or shorter one inside an existing text node, so no layout moves and the paint/overflow/
z-index failures only pixels catch are structurally absent.

The substitution was **rewritten mid-run**, which is the reusable lesson. The first version
asserted the pure label function — and would have passed unchanged had the component computed
the right string and rendered a different one. For a bug that was *entirely* about what
reached the surface, that is logic-layer evidence dressed as surface-layer evidence. #546's
workaround now carries the sharpened rule: **assert the rendered DOM of the real component,
never the helper it calls.**

**UI Laws judgment** (`Docs/design-system/laws.md`): **Law 14** is the ticket and is now
satisfied on both surfaces, with a real fallback rather than a raw-key one. **Law 13**
(words, not numerals) unaffected by this diff — but see below. **Laws 1 / 17 / 21**
(image / tooltip / link) N/A: the status label is a state descriptor, not a game concept, and
gains no dead affordance. **Law 37** N/A — no interaction states changed.
