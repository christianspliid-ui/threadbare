# THR-1916 — Land-page hero art: the plateau and the lair

**Shipped 2026-10-20.** The land page now opens with a picture of the land (plan `2026-10-14-thr-1876-the-inspector.md` § D10).

**What the player sees.** A plateau shows its own landscape: a flat tableland that ends in cliffs above a misty valley. Before, it borrowed the green hills. A land that holds a lair shows the lair's own picture: a cave mouth strewn with bones, with eyes in the dark. Before, it borrowed the camp. Every other land shows its terrain's landscape. Before this ticket, the land page drew the fallback tile for every land, because it gave the image resolver no terrain.

**How.** Two new pre-baked images: `public/concept-art/plateau.png` and `public/concept-art/locations/lair.png`. Each was generated with the existing set's image as a style reference. `CONCEPT_ART_REGISTRY` gains a `plateau` entry, and the hills entry no longer claims the plateau. `LOCATION_ART_MAP` gains `lair`. `getOwnLocationConceptArtUrl` returns a subtype's own art, or null where `getLocationConceptArtUrl` returns the camp fallback. `landHeroArt` (`src/engine/views/subjects/subjectPage.ts`) picks the hero. A lair listed under *In this land* comes first. Otherwise it is `pickConceptArt` on the tile's terrain and the land's locations, and with no terrain it is null, which draws the designed fallback tile (Law 4). The header VM carries the result as `visual.src`, and `SubjectHeader` passes it as `knownSrc`. The Inspector lab gains the rows "Land — a plateau" and "Land — a lair's".

**Terrain check.** Every terrain resolves to an image that exists. Volcano, glacier, lake, river, dead forest and reef still borrow a neighbour's picture: filed as [THR-1998](https://linear.app/threadbare/issue/THR-1998).

**Decisions (veto invited):** on the land page, a lair outranks the terrain.
