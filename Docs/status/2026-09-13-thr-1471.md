# THR-1471 — `classify:diff` prints the browser-verify route reminder

**Shipped 2026-09-13.** The rule *"decide the browser-verify route at claim, not at the
capture"* now reaches the session as **output** on the one script every code-diff run
already executes before choosing a gate track.

## Why this, rather than a third place to write it down

The rule was already written twice — `Docs/canon/verification-gates.md` § Browser-verify
and `.claude/skills/pull-work/SKILL.md` Step 3 — and fired at neither placement.
Impediment row 1011 recorded it **×4** on 2026-09-10: a run implemented THR-1452 in
full, ran suite / ratchet / build / CLI smoke, and only then hit the `preview_start`
unattended refusal at the capture, with the implementation already complete and every
other gate green. The class tail runs rows 546 (×13), 574, 638 (×12), 683 (×13). The
2026-09-06 retro had already moved the rule *closer* to the binding moment; that was the
second placement, and it did not fire either.

So the next rung is not a better sentence in a better file — it is output the session
cannot not-see. `npm run classify:diff` (THR-917/THR-988) is the natural carrier: every
code-diff session runs it, and it runs *before* the gates, which is the last moment the
route still costs nothing to choose.

## What changed

- **`scripts/docs-only-predicate.ts`** — `UI_PILLAR_PREFIXES` (the four prefixes CLAUDE.md
  § Definition of Done names), plus `isUiPillarPath` / `uiPillarPaths`. A named constant
  rather than an inlined list at the one call site, so the membership rule is tunable in
  one place and shared with its test (NFP #1).
- **`scripts/classify-diff.ts`** — `UI_PILLAR_REMINDER`, printed after the "Owes the full
  gate" line when any changed path is UI-pillar, followed by the offending paths. Also
  surfaced as `uiPillar` in `--json`. The human report moved into an exported pure
  `renderClassification(files, base)` so the reminder is assertable on the **output a
  session sees**, not on the source that produces it.
- **`Docs/canon/verification-gates.md`** — one paragraph pointing the clause at its new
  mechanism, so the rule and the thing that surfaces it reference each other.
- **`scripts/__tests__/classify-diff-ui-pillar.test.ts`** — 23 assertions: the reminder
  fires per UI-pillar prefix, on a mixed diff, and names the evidence contract; it stays
  silent on engine-only and docs-only diffs; and the membership predicate rejects
  `src/index.ts` and `src/hooksUtil.ts`, the two paths a sloppier prefix test would
  swallow.

## It is output, not a gate — deliberately

Nothing fails on the reminder and the failure mode is unchanged. It is also a **theory
test** (2026-09-12 retro § Patterns to Watch): if the class recurs *after* this ships,
discoverability was never the failure at any layer, and the next rung is a hard gate —
which needs a director-level cost/benefit call first, not an executor's.

## Evidence

Falsification arm run before shipping: suppressing the guard (`&& false`) failed 6 of the
23 assertions, so the guard is load-bearing rather than decorative. End-to-end both ways —
the reminder fired on a real historical UI commit (`ac2b84fe`, touching
`src/components/Game/encounter-stage/`) and stayed silent on this ticket's own
scripts-only diff. `npm test` 20320/20320, ratchet `OK — 2848, unchanged`, `vite build`
✓, `check:predicate-copies` OK.

This diff touches `scripts/` and `Docs/` only — **not** the UI pillar — so no
browser-verify evidence is owed for it.
