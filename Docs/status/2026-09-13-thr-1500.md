The last four callers of `openAgentProfileForId`. [THR-1477](https://linear.app/threadbare/issue/THR-1477) built the working primitive and repointed the encounter veil; [THR-1461](https://linear.app/threadbare/issue/THR-1461) repointed the premonition. These four were measured and deliberately left, because each is its own surface with its own evidence to capture.

## The defect, once

`openAgentProfileForId` is a bare `setProfileModalAgentId`. The card the sheet renders, `agentInfoCard`, is memoised on `selectedAgentId` ([`useAgentInteraction.ts:194`](https://github.com/christianspliid-ui/threadbare/blob/main/src/components/Game/hooks/useAgentInteraction.ts#L194)), and `GameView` gates the mount on `profileModalAgentId && agentInfoCard`. So a caller that sets only the profile id gets **nothing** when no mortal is selected — a dead click that looks live (Law 21) — or the **previously selected** mortal's sheet under the asked-for mortal's id (Laws 1 and 33).

| Site | Surface | Why the selection is usually wrong there |
|---|---|---|
| `GameView.tsx:5063` | champion chip in the HUD | any threaded row can carry a chip; the champion need not be selected |
| `GameView.tsx:5165` | the sheet's own cast / companion links | the selected mortal *is* the sheet already open, so the link read as inert |
| `GameView.tsx:5188` | `ChapterLedger` entity links | the ledger is an archive of *other* people's chapters |
| `GameView.tsx:5421` | authored-moment overlay | a moment arrives for a **followed** mortal, which is exactly the not-selected case |

All four now use `openAgentSheetForId`. `GameView.tsx:2022` (`__DEBUG.openAgentSheet`) is untouched, as the ticket instructs: it calls `gotoAgent` first, so its selection is already correct by the time the profile id is set — right by ordering rather than by design, and not this bug.

## Judgement call 1 — the cast links move the selection, and that is the decision

`onOpenEntity` on `AgentProfileModal` navigates *between* sheets while one is open, so the swap is not a pure one: `openAgentSheetForId` also moves `selectedAgentId` and closes the drawer behind the modal.

**There is no variant that moves the card without moving the selection.** The card is memoised on `selectedAgentId`, so a card for the companion cannot exist until the selection is theirs. The only alternative was re-keying that memo on `profileModalAgentId` — a wide change to the drawer's card for one link's sake, and the drawer genuinely wants the selection's card.

Moving the selection is also the truthful state: the player is now reading this mortal, so closing the sheet should leave the world on them rather than on whoever they arrived from. The test **pins** it (`expect(selectedAgentId).toBe(SUBJECT_ID)`), so a later change has an expectation to argue with rather than a silent assumption to trip over.

## Judgement call 2 — honoured, and it leaves a real tension

Not routed through `refRouter.open(ref, 'sheet')`. The router's agent arm is `handleAgentSelect`, which opens the ActionDrawer at z 40 — correct for a notification click-through, wrong for a control behind or above a modal (measured in THR-1461).

Worth recording because it is not free: **Law 21's 2026-09-12 amendment (THR-1490) says routing is no longer per-surface judgment and `useRefRouter` is the only thing that decides what a name opens** — while this ticket forbids the router for these four, for a measured reason. Both are right about their own half; what is missing is a router arm that opens an agent's *sheet* without the drawer. That is a design pass, not this fix, and it is reported rather than invented here.

## Tests — four composed blocks and one wiring guard

`src/components/Game/__tests__/surfacesOpenNamedMortalSheet.test.tsx`, 9 assertions.

One block per surface, following the premonition pattern: the real hook, the real component, and `GameView`'s own `profileModalAgentId && agentInfoCard` gate **copied verbatim rather than simplified** — the gate is why the *wrong* sheet rendered instead of no sheet, so a harness mounting the modal on the profile id alone would test a surface the game does not have. Each block selects a different mortal first, because that prior selection is the whole defect and a capture without it proves nothing.

Each carries a **falsification arm** that restores the shipped prop and reproduces "named the subject, showed the other one" — without it, a green assertion could equally mean the harness never held two distinguishable mortals.

**The guard is the part that catches a revert.** Each composed block hands its surface the opener directly, so none of them fails if `GameView` alone is reverted; mounting `GameView` whole to close that gap is not viable (it boots the world). So the wiring is asserted against the source: no JSX prop in `GameView.tsx` may be assigned the bare `openAgentProfileForId`. That predicate is **measured, not assumed** — against `origin/main` before the fix it matched exactly 4 sites, which is precisely the four the ticket enumerates, and 0 after. `GameView.tsx:2022` is a *call*, not a prop assignment, so the ticket's named non-member is excluded by construction rather than by an exception list that would rot. Falsified by restoring one prop: the guard fails and names the offender.
