# THR-1507 — concept words in Codex detail rows hover, in every section, the same way

**2026-09-16 · UI · Content-N/A · Engine-N/A** · Deferral filed by [THR-1495](https://linear.app/threadbare/issue/THR-1495) · [THR-1507](https://linear.app/threadbare/issue/THR-1507/codex-detail-rows-carry-no-concept-tooltips-law-17-on-every-section)

## What the defect was

`CodexEntry.details` rows are `{ label, value, tooltipId? }`, and the Undertakings section was the only mapper that ever set `tooltipId`. Every other section — the seven action mappers, possessions, conditions, agreements, resources, and the four kinds THR-1495 chartered — painted its detail values plain, so a reach name, a Sphere name, a scale word or the essence price sat on the panel with no hover (Law 17). The ticket's real question was structural: a row's `tooltipId` covers the **whole** value, and values like *a slight edge in Gold, a faint edge in Heart* name two concepts. Tagging only the single-concept rows would have left two tooltip vocabularies inside one panel, which the ticket rightly called worse than uniform absence.

## The ruling — spans, not rows

Two shapes were on the table: **(a)** mark concept spans inside a value, or **(b)** restructure rows so each names one concept. **(a) was chosen**, and the ruling is recorded where the ticket asked — in `CodexDetailPanel`'s doc comment. It is Law 2's own shape (*the producer declares the concepts, the surface never parses English*) and the aftermath chip already implements it as `EncounterAftermathChange.concepts`, so the Codex gets a second instance of one pattern rather than a pattern of its own. (b) would have made sections read worse for the renderer's convenience: a companion's *good for* is one sentence, not two rows.

The new module `src/components/Codex/codexConcepts.ts` carries the shape and its three rules:

- **A concept is declared only when the registry resolves it.** `reachConcept` / `sphereConcept` / `scaleConcept` return `null` for `reach.time`, `reach.life` (no world-model node) and a `sphereAffinity` of `void`, so the panel never draws a dotted underline that opens nothing (Law 21).
- **The span text is the value's own resolved word**, passed by the mapper from the same display vocabulary the value was built with; `conceptRow` drops a span the value does not contain and warns once.
- **Matching is first-occurrence substring in declaration order** — the same algorithm as `applyConceptDecorations` on a consequence chip. A homonym stays where the producer left it: the two cards keyworded *Veil* never hover as the reach.

The whole-value `tooltipId` survives as the single-concept shorthand, and `detailConcepts` folds it into the same list, so the panel has exactly one render path. Undertakings did not change shape.

## What now hovers

| Section(s) | Row | Concept |
|---|---|---|
| Divine · Hex · Place · Artifact · Company · Thread · Mortal | Reach | `reach.<key>` |
| same | Sphere | `sphere.<key>` |
| same | Scale | `ui.card.scale.<key>` — the hand's own vocabulary |
| same | Cost | `ui.essence_cost` (whole value) |
| Conditions | Domain Effects | one `reach.*` span per reach named |
| Possessions | Reach Bonus | same (no catalog population today, wired anyway) |
| Resources | Sphere affinity | `sphere.<key>` |
| Companions | What they are good for | one `reach.*` span per reach lent |
| The Repertoire | How you hold it | the Sphere a signed or attuned card names |

**Out of membership by the ticket's own predicate** — rows whose words the registry has no entry for: rarity tier, slot, loss condition, agreement type and effect, resource class, ambition category, a card's keyword, a legendary artifact's *Workings* (activated-effect names have no tooltip route). They paint plain, which is the designed fallback, not a dead link. Registering those vocabularies is a separate content question.

## The guard, and what it caught

`__tests__/codexDetailConcepts.test.tsx` pins three things: every declared concept resolves and lies inside its value (across the catalog, non-vacuous at >300 declared); the panel paints the spans (jsdom render of a two-reach condition, an action, a companion, a signed card, an undertaking, and an agreement that must paint **no** span); and — the part that stops the recurrence — a sweep of every row of every entry for the registry's own concept words, each hit required to be declared. The sweep is the guard, not the surface (Law 2); it is falsified against an injected undeclared row, and its two excuses (prose rows, the `Veil` keyword) are each pinned as real excuses rather than holes.

**The sweep found one real thing on first run:** `divine.afflict_bless` keys on the reach `life`, which has no world-model node and shares its word with the Sphere. The row correctly declares nothing; the sweep now derives the unbacked-reach set from `TOOLTIP_BACKED_REACHES` and excuses it on a `Reach` row only — the same word on a `Sphere` row is still reported.

**Also fixed in passing, seen in the capture:** the panel's close control painted the six literal characters `✕` — a JSX text node does not decode escapes. Now `{'✕'}`.
