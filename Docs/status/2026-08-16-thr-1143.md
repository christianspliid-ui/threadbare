# THR-1143 — Location conditions: timed, readable states on places

**Shipped 2026-08-16.** Second member of the consequence-palette expansion
(`Docs/plans/2026-08-16-consequence-palette-expansion.md` § Primitive B), following
THR-1142's `agent_relocation` on the director's fixed ladder.

## What landed

An encounter ending can now change a **place**, not only the people standing in it:
a pass closed for the season, a town under a plague scare, a square under watch, a
blighted harvest. Five starter conditions ship under `trait.condition.location.*`,
and an aftermath reaches them through an additive `targetLocationId` on the three
existing condition effects.

## The finding: most of this was already built

The plan anticipated widening `decayConditions` to walk non-agent carriers. It did
not need widening — it walks `has_trait` **by edge type**, never by source node
kind, so a condition on a place already expired through exactly the right path.
The same held for gating: `buildLocationTargetContext` has always read a location's
`has_trait` edges into `traitIds`, so `requiredTargetTraits` worked against places
and had simply never had any content to match. And `has_trait.sourceNodeType` has
listed `location` since the edge schema was written.

So the honest description of this ticket is **a dormant capability activated**, not
a system built — the THR-614 shape. What was genuinely missing was the *authoring
surface* (no effect field named a place), one reader (movement), and the player
surface. The work concentrated there instead, and the tests were written to prove
the untouched parts really do carry it rather than assuming they do.

What the decay loop *did* need was an honest name: its result called every carrier
`agentId`, which misreports a closed pass as a person. `carrierId` is now the field,
with `agentId` kept beside it as a deprecated alias so no existing reader moved.

## Two readers, because a write nothing reads is hollow

Law 56 at world scope. Both ship in this PR:

- **Template gating** — verified, not built: a location under `festival` becomes
  eligible for festival-gated templates, and stops being eligible when it lifts.
  The test falsifies in both directions, because a gate that only ever passes is
  not a gate.
- **Movement tax** — new. `LOCATION_CONDITION_MOVEMENT_TAX` maps a condition id to
  a multiplier on the cost of entering that place. `pass_closed` is ×8 and
  deliberately a **soft** block: a hard one can strand an agent whose only road home
  runs through the pass, and a stranded agent is a dead corner of the simulation
  (NFP #4). The tax lifts by itself on expiry because it reads the edge — there is
  no second lifecycle to keep in step. `under_watch` carries no tax on purpose:
  being watched changes what you can *do* somewhere, not how long the walk takes.

## UI

`LocationProfileModal` lists the place's active conditions with their remaining term
in words — "four days", "until it lifts" — each hoverable through the existing
`attachment.*` tooltip registry, which resolved the new ids for free once they
joined `CONDITION_TRAIT_DEFINITIONS`. The section does not render at all when a
place carries none (Law 25); most places carry none.

One refactor fell out of it: `durationLabel` was marked module-private to the Codex
but is the same reading a place's remaining season needs, so it moved to
`engine/aftermathWords` (the module that already owns "band it at the source") and
the Codex re-exports it. Copying would have made two ladders for one quantity.

## Two bugs found on the way

- `condition_attachment` decided "does this wound the actor?" from `!effect.targetAgentId`
  — absence read as the actor. An effect naming a *place* leaves that field unset, so
  a wound on a town would have promoted the encounter tier for an injury nobody took.
  It now compares the resolved target id.
- The encounters wiki carried a `Caveat (THR-809, open)` saying condition definitions
  were never seeded, ~3 weeks after THR-809 shipped. The palette census had already
  found conditions among the least-used effect families partly on the strength of the
  same stale line in the wiring guide. Corrected in both.

## Deliberate non-goals

No hex-map badge for a conditioned place (kept out of hexmap scope; a separate design
if wanted). No encounter-type *bias* from a location condition — that stays the omen
system's job, because two bias channels would drift. Hex-*coordinate* targeting
(`buildHexTargetContext`) builds no trait list and so does not gate on conditions;
settlement/waypoint/hex **nodes** do, which is the plan's scope.
