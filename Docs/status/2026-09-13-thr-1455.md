# THR-1455 — the Area says how wide it is and what it is, in words

**Date:** 2026-09-13 · **Pillars:** UI · Content-N/A (no authored content added or edited; the vocabulary is display data, not a content catalog) · Engine-N/A (no engine module touched — the new module takes a type-only import from `regionDetection`)
**Issue:** [THR-1455](https://linear.app/threadbare/issue/THR-1455/hexsidebar-renders-the-areas-raw-featuretype-key-and-a-bare-hex-count)
**Plan doc:** none — the ticket description is the spec.

Filed in passing while [THR-1155](https://linear.app/threadbare/issue/THR-1155) made the Area a first-class referenceable object. The one surface that shows an Area's detail was still spelling its type as an engine key:

```tsx
{props.regionData.hexCount ? <div>{props.regionData.hexCount} hexes</div> : null}
{props.regionData.featureType ? <div>{props.regionData.featureType}</div> : null}
```

A raw magnitude (Law 13) stacked directly on a raw `snake_case` enum (Law 14), two lines apart, on a mortal-facing card face.

## Where the ladder went, and why not into the component

`src/data/geo-word-bands.ts` — the module THR-1451 created for exactly this, whose own header records the reason: a reading banded privately inside one component is the shape Law 3 exists to prevent (`HexDetailView` banded elevation/temperature/moisture, and the same numeral stayed live on `InfoPanel` and the hex tooltip because nobody could find the first ladder). `HexSidebar` is the **only** player-facing reader of either value today — checked, not assumed — and that is the moment to put a ladder where a second reader can find it, not after a second one appears.

## The duplication that was left alone on purpose

`FEATURE_LABELS` already exists **twice** — `engine/regionNaming.ts` (typed, exhaustive) and `engine/hexGrid.ts` (loose) — with word-for-word the same ten entries the new vocabulary uses. The ticket noted this and suggested the resolver might already be written.

It is not, and merging them would be a defect. Those tables are **name fragments**: they feed `generateRegionName`, which composes `"Grey" + "Mountains"` into an Area's actual stored name. Sharing one table would mean that retuning a *display* word silently rewrites every generated Area name in a saved world. Same words today, different jobs — the coupling is the hazard, not the duplication, and the new module says so where a future reader will hit it.

## Bands measured, not guessed

`AREA_SIZE_WORDS` is tuned to the range the game actually produces, read off generated worlds rather than off the type:

| map | n | min | p50 | max |
|---|---|---|---|---|
| small | 4 | 50 | 59 | 100 |
| medium | 12 | 9 | 36 | 150 |
| large | 18 | 6 | 83 | 192 |

Five rungs across 6–192 (`Small` / `Modest` / `Wide` / `Vast` / `Boundless lands`), so the common medium-map band is not the only one a player ever sees. The last rung's threshold is `Infinity` — `geoWord` already bands any ascending ladder, so the count reuses the one banding function rather than growing a second; its `GeoBand` doc now states the unbounded-top case instead of only the 0–1 one.

`areaFeatureWord` follows `ruin-words.ts`'s Law 14 fallback path exactly: resolve, else best plain English + `console.warn` once per key per session, never the key. The record is typed `Record<RegionFeatureType, string>` so an eleventh feature type is a **compile error here** rather than a leaked key on the surface — the loose `string` on `HexRegionData.featureType` (read back off a property bag) is handled at the function boundary.

## Evidence

Five jsdom cases, and **each was falsified before being trusted**: reverting the two lines to the raw render reds exactly the four that depend on the fix, while *"omits both lines when the Area carries neither reading"* correctly stays green, because it asserts absence and never depended on the resolver. Each positive assertion is paired with a negative — `expect(getByText('Mountains'))` alongside `expect(textContent).not.toMatch(/mountain_range/)` — since a test that only proves the word appears would still pass with the key printed beside it. The warn-once arm renders twice and asserts the call count does not move.

Suite green (1261 files, 20404 tests), ratchet **2848 unchanged and baseline NOT refreshed**, build green. No CLI smoke — no engine file in the diff.

`Browser-verify substitution: jsdom-render — unattended run, no startable dev server.` The route was forced rather than chosen: `preview_start` refused outright (*"Dev servers can't be started from unattended sessions"*), which shuts the Playwright route with it, since that route presumes a running server.
