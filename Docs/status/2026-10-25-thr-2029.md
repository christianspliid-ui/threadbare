# THR-2029 — an echo heir's seeded kin tie no longer counts as a tie earned in play

**Shipped 2026-10-25.** THR-1843 seeds an echo's heir at world creation and gives it one kin tie to a co-resident. `writeKinTie` stamped that pair `origin: 'echo'`. Spotlight promotion (`npcGraduation`, THR-1630) counts every `relates_to` edge whose origin is not `'worldgen'`. So at tick 0 the heir (already a notable) and its kin partner each held two "earned" edges, and one real tie in play made either a spotlight decider instead of three.

**Change.**
- `src/engine/seedEchoes.ts`: `writeKinTie` writes `origin: NOTABLE_ORIGIN_WORLDGEN`, the THR-1589 tie shape the plan asks for (THR-1813 plan, Decided 6). The heir keeps `notableOrigin: 'echo'`.
- `src/engine/npcGraduation.ts`: the earned-tie predicate is now the exported `isEarnedTie`, reading the named constant instead of a `'worldgen'` literal. Behaviour unchanged.
- `src/data/account-content.ts`: the `ECHO_ORIGIN` comment no longer claims the kin tie carries it.

**Evidence.** `seedEchoes.test.ts` finds the heir's tie by the id `writeKinTie` gives it, asserts both directions read `origin: 'worldgen'`, and asserts `isEarnedTie` counts 0 earned edges for the heir and for its kin partner at tick 0. `npm run gate` code track (engine): test, typecheck, build, encounter, god-cards, ui-debt and cli-smoke all PASS. Nothing in `src/components/` changed, so no browser evidence is owed.
