# THR-1305 — the debug encounter tools reach the scored binder (2026-08-27)

THR-1296 slice 6 shipped the `useScoredBinder` opt-in and wired exactly one caller:
`phaseAgentDecision`, the live decision path. `debugEncounterTools` supplied no
`EncounterBinderContext` at either of its call sites, so a migrated template reviewed
through `?spawn=`, `?forceencounters` or the CLI was cast by the **legacy** first-role-match
resolver and wrote no ledger row — content review of a migrated encounter was reviewing a
different casting than players get. The slice-6 commit filed this itself rather than
widening the closing slice.

The fail-soft was never the problem. No context ⇒ legacy path ⇒ never a crash is correct
and stays. What was missing is the context.

## The premise had a third call site in it

The ticket says the two `debugEncounterTools` sites "are what `?spawn=`,
`?forceencounters` and the CLI `spawn encounter` travel". Two of those three are right.
The CLI does **not** route through `debugEncounterTools` — it calls
`prepareEncounterSupportBundle` itself at `scripts/cli.ts:1639`, a site added by THR-698
whose own comment claims spawned encounters "bind cast exactly like the decision-phase and
browser debug paths". That claim was true when written and stopped being true at slice 6.

Fixing only the two named sites would have left the ticket's own evidence path — "spawn the
exemplar, read the ledger" — running the legacy resolver, and the cheapest live proof is
exactly the CLI. All three are wired.

## One assembler, not four copies

The context is a narrow struct on purpose (`encounterSupportBundle` imports neither
`SimulationRuntime` nor the strategic state, and says why). So somebody has to put the
three pieces together, and with four callers that assembly is a rule worth having once:
`binding/encounterBinderContext.ts`. `phaseAgentDecision`'s inline copy now calls it, so
this is a net removal of duplication rather than a tripling of it.

The rule it owns: **both the runtime and `strategicState` must exist, or there is no
context at all.** The second half is the one that invites a bug. `getBindings` tolerates an
absent strategic state by returning `[]` (NFP #4/#6), so an assembler skipping that check
would still produce a well-typed context — one whose ledger is a fresh local array that
nothing owns. Rows would be written to it and dropped on return while the call reported a
successful bind. A silent write to nowhere is strictly worse than the legacy path, which at
least binds honestly without a ledger.

## The bug found while wiring it

The debug entry points take an agent **query** (`@hero`, a partial name), not a node id.
Passing that query straight through as the context's `actorId` type-checks and is silently
wrong: `binder.ts` skips the candidate whose node id equals `request.actorId`, so a query
string matches nobody and the self-exclusion stops working — the spawning agent becomes
eligible to be cast as **their own fellow survivor**. The tool resolves the agent, so the
tool stamps `agent.id`.

This is not hypothetical. The controlled arm that stamps the query instead fails with
`expected 'agent_1' not to be 'agent_1'` — the agent cast as their own support.
