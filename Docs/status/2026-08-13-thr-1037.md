# THR-1037 — the Crossroads accept branch is reachable; the report was a coin, not a bug

**Verified 2026-08-13.** THR-1037 asked whether *A Bargain at the Crossroads*' `negative` (accept) branch — the one carrying the Full Moon `encounter_seed` — is actually reachable after THR-979's fix, or whether that fix was incomplete. Four browser playthroughs had landed on the `positive` (refuse) branch every time with byte-identical aftermath prose, and no SEED chip ever appeared.

**Verdict: not a defect.** The accept branch is reachable, it resolves in live play, and its seed plants. The four identical runs are a deterministic-coin artifact of the review avatar, and the ticket's own hypothesis (a) named it correctly.

## Why four runs looked identical

`CROSSROADS_FORK` declares `decidedBy: { axis: 'tradition_novelty' }`, so the fork runs in pole mode:

```
netLean = profileLean + cardLean
netLean >  +0.05 → 'positive' (refuse)
netLean <  −0.05 → 'negative' (accept)
otherwise        → coin: rng() < 0.5 ? 'positive' : 'negative'
```

The reports were taken on `?spawn=`, which stamps the balanced test avatar — and `applyBalancedTestAvatar` sets **every** value axis to `0` deliberately, its own docstring saying forks then "resolve from the seeded coin". So `profileLean === 0`, and with no card *counted* on the deciding step `netLean === 0` lands inside the neutral band. The coin is seeded, so an identical call sequence draws the same side every run — which is exactly "byte-identical aftermath text every time".

The neutral avatar makes the profile lever unusable by construction. That leaves cards, and cards were never the thing under test.

## Live confirmation

A CLI sweep on seed 42 takes the *other* side of the same coin:

```
choiceHistory: [{ stepIndex: 0, choiceId: "negative",
                  choiceText: "The moment found them undecided.",
                  interventionType: "agent_decided", tick: 1 }]
```

`"The moment found them undecided."` is verbatim `applyPoleDecision`'s **coin** string (`'They chose as they are.'` is the conviction one) — so this run reached the accept branch by the coin falling the other way. Its aftermath then offered `slice.crossroads.carry_the_promise`, and the seed planted end-to-end:

```
templateId: "encounter.slice.full_moon_collection"
seedLabel:  "A promise made at the crossroads falls due at the full moon."
eligibleAfterTick: 134   (planted tick 2 + SLICE_FULL_MOON_DELAY_TICKS)
```

Note the seed planted **without any manual aftermath pick** — `pendingEncounterSeeds` already held it before one was made. The path is autonomous, not dependent on a player selecting the reaction.

## What was actually missing: the card half of the test

`sliceForkAftermathResolution.test.ts` proved both endings reachable from `profileValue` alone, with `activeNudges` never set and `cardLean` always `0`. That is the half a reviewer on the sanctioned avatar can never use, and asking only it is how the gap survived THR-979.

Five tests added to the same file, driving the real `applyAgentDecidedBranches`:

| Test | What it pins |
|---|---|
| one card strikes the bargain | neutral profile + `a_taste_for_wonders` → `negative` by **conviction**, seed present |
| the opposing card refuses | neutral profile + `old_stories` → `positive`, **zero** seeds (falsification half) |
| a card overturns standing | profile `+0.2` flips to `negative` once the card is played |
| an abstaining card | `second_sight` carries no `poleLean` → `cardLean === 0`, falls to the coin |
| no card → coin | `netLean === 0`, both poles reachable — THR-1037's four runs, pinned |

Each card test passes an rng pointing at the **opposite** pole, so a card that decides the fork is proved to decide it *against* a disagreeing coin rather than merely alongside an agreeing one. The card weight is `0.35` against a neutral band of `0.05`, so a single card decides by conviction and never consumes the coin.

## Seed-chip rendering

Already covered — `sliceAftermathConsequences.test.ts:139` asserts `kindLabel === 'SEED'` for this template's ending (THR-971). No new UI evidence owed, and the coordination block agrees: *"CLI/headless sweep per the ticket's own Ask — no browser pillar required."*

## Noted, not fixed

The CLI's `aftermath pick` does not guard against re-applying an aftermath that already auto-resolved: picking `carry_the_promise` after auto-resolution planted the same `seedId` twice (`BEFORE_PICK=1`, `AFTER_PICK=2`). That is a debug-tool observation reached through a debug command — I did **not** establish that a player can reach a double-apply in real play, so it is logged as impediment #553 rather than filed as an engine defect on a reachability I have not shown.
