# THR-1048 — the last raw enum on the encounter veil

**Shipped 2026-08-17.** The legacy (non-nudge) choice card printed
`supportive` / `coercive` / `withdrawn` verbatim in its meta row, beside
`&#9670; 2 essence`. Law 14 — no raw internal keys, ever — with nothing
between the engine's stance enum and the scene.

## The ticket was half-decayed, and the half that survived was the gate

THR-1048 filed two violations. The first, `+3% success` / `+15% success` on the
card face, **was already gone**: THR-1121 deleted the percentage branch from
`ChoiceBlock` when it retired the odds-buying mechanic the number reported, and
THR-1124 gated the one remaining `formatSignedPercent` caller behind the
designer view. Neither ticket names THR-1048, so
`git log origin/main --grep="THR-1048"` found nothing and the upstream check
correctly said not-shipped — the decay is invisible to an id-grep and only the
source shows it (impediment #647).

That does not cancel the ticket, because Done-when 1 asks for a **machine gate
over the rendered choice block**, not for a fix. A defect fixed by a neighbour
with no regression lock is a defect waiting to come back, and this neighbourhood
is busy: THR-1010, 1041, 1121 and 1124 all landed in `EncounterVeil.tsx` inside
two weeks. The lock is what shipped.

## The Law 14 half, and a second violation the audit missed

`ChoiceBlock` rendered `{choice.interventionType}`. The fix bands it at the
source — `engine/interventionStanceWords.ts`, the way `supportRoleWord` bands a
cast member's role and `aftermathWords` bands a delta — so the adapter produces
`stanceLabel` and the surface renders words:

| enum | rendered |
| -- | -- |
| `supportive` | lend strength |
| `coercive` | press them |
| `withdrawn` | stand back |

Verb phrases rather than adjectives because the row reads as the god's own move,
and Law 42 permits second person for the god's own actions. It also keeps
`withdrawn`'s existing `fate decides` rider reading as a consequence — *stand
back · ◆ 0 essence · fate decides* — rather than a synonym for the tag beside it.

A **table, not a derivation**, which is the opposite call from `supportRoleWord`
and deliberately so: support roles are open-ended authoring keys where a table
goes stale the first time an author adds one, while this union is three values
fixed in a type. The table exists to change the part of speech, which no
derivation over `supportive` can do.

**The second violation was not in the ticket.**
`buildUnifiedEncounterStageModel` set `intent: choice.interventionType` — so the
card's *main italic line*, the sentence the player reads first, was the bare enum
rather than a dim tag. It is unreachable today (the branch runs only when a step
has no `authoredChoices`, and that is the sole thing that ever fills
`notification.choices`), which is why a browser audit could not see it and why
this is recorded rather than headlined. Fixed to `choice.text`, matching the
sibling adapter.

## Which adapter was actually live

Worth stating, because it decides whether this was a real defect or dead-code
tidying. `phaseEncounterVisibility` overwrites `notification.choices` with the
authored hand, **each card keeping its `interventionType`**, under no tier gate.
A `watched`-tier encounter routes to `buildSimpleEncounterStageModel` rather than
the unified adapter (`GameView` returns `null` for `unifiedTemplateForStage` at
that tier), and that adapter passed the enum straight through to the model. So
the raw key reached the veil on the watched path. The gate drives that adapter,
not a hand-built model, for exactly this reason.

## Gates

Both Done-when gates are render-time, not source-shape — the offending literal
never appears in `EncounterVeil.tsx` at all (the file says
`{choice.interventionType}` and reads clean), so the `encounterVeilLaws`
source-gate pattern could not discharge them. Every gate first asserts the choice
block rendered: a veil with no choices trivially contains no `%` and no enum, and
would have gone green through the entire period the violation shipped.

Falsified in both directions rather than assumed:

- restore `{choice.interventionType}` → 3 tests red, including the live-producer one
- reintroduce `+${Math.round(boost * 100)}% success` → the Law 13 gate red

The forbidden strings are written as literals. Importing the stance union or
reading the vocabulary table would make the gate agree with whatever the code
decided, including a regression that starts printing keys again.
