# THR-1284 — the encounter counter had no producer on the path every encounter takes

**Date:** 2026-08-26 · **Project:** Thematic Pressure & Living World · **Pillar:** Engine

`balance summary` printed **"Encounters: 0 attempted, 0 completed, 0 abandoned"** on runs
that had recorded hundreds of `start_local` decisions. Reproduced before touching
anything, seed 42 / medium / 60 ticks: `Encounters: 0 attempted` against
`start_local=60` and `Steps: 141 attempted`.

**The counter, the summary reader, and the CLI line all worked.** What was missing was a
producer. The only `encounter_resolved` emit in the tree sat in the legacy progress block
in `orchestrator.ts` — and no live decision reaches it: `start_local` builds a **unified**
action from the encounter template, so resolution runs through
`unifiedActionResolution.ts`, which emitted `step_resolved` and `action_resolved` and
never the encounter half. Every encounter-throughput reading was a structural false zero,
on the instrument balance and KPI verdicts are read from. The field survey that filed this
nearly misread it as "encounters don't run".

**The discriminator is the load-bearing half.** `action_resolved` already counts *every*
unified action — divine interventions and strategic verbs included — so it cannot double as
the encounter counter, and the fix is not "emit one per action". The subset test is
`isEncounterAction`, imported from `chapterArchive.ts` rather than re-derived: it is the
same predicate the chapter archive uses to decide what is worth keeping as a chapter, so
the instrument and the ledger now agree on what an encounter *is* instead of drifting
apart behind two hand-rolled id tests. The legacy emit is left exactly as it stands — this
is the missing unified half, not a replacement (NFP #6).

**One thing the fix corrects on the way past.** The legacy emit read `encounter?.threatRating`
— a field `UnifiedActionTemplate` does not have — so every legacy encounter banded
`'unknown'` and `completionByBand` was a single dead row. The unified emit derives the band
from `rarityTier` through `RARITY_TO_THREAT`, the same mapping the encounter cache, the
event node and the stage model already share.

**Measured after (same seed/map/ticks):** `Encounters: 58 attempted, 35 completed,
23 abandoned` against `start_local=60` — the two-encounter gap being actions still in
flight at tick 60. `Fail-forward share` moved 0.0% → 60.3% in the same run, having been
divided by a zero denominator.

**Non-vacuous by controlled arm, not assertion.** Disabling the emit reddens **4 of 6**
tests, the 2 that pass being the deliberate controls (the live-content vacuity pin and the
non-encounter absence). Emitting *unconditionally* — removing only the discriminator —
reddens exactly **1**, the non-encounter arm. The vacuity pin exists because
`isEncounterAction` resolves against the real encounter libraries: a fixture id would take
the non-encounter branch and pass for the wrong reason, so the test asserts up front that
its chosen id is live content.
