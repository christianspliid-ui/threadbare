# 2026-10-14 — THR-1886: one table files every player action (Law 58)

**Ticket:** [THR-1886](https://linear.app/threadbare/issue/THR-1886). A player action under a new id-prefix took six edits, and two of them failed silently. Engine N/A (build tooling and data). Content: no new content, and no action changed category. UI: the Codex and the designer action catalog read one shared table.

- **One table.** New `src/data/action-categories.ts` holds `ACTION_CATEGORY_RULES` (id-prefix → category, first match wins, rule order = Codex entry order) and `ACTION_CATEGORIES` (label and catalog facet per category, closed over `ActionCategory`).
- **Both readers import it.** `scripts/generate-action-catalog.ts` drops `categoryFor()` and its thread-id set. `codexRegistry.ts` drops its eight prefix arms and its seven action `catDefs` rows. The Codex keeps a closed `ACTION_CATEGORY_GLYPHS` record and an `ACTION_ENTRY_MAPPERS` record, so a new category without a glyph or mapper is a type error. The glyphs stay in the Codex so the UI-debt ratchet's data-glyph count does not rise. THR-1885 moves them onto the icon registry.
- **An unknown prefix fails and names the file.** `uncategorisedActionMessages()` returns *add `<prefix>` to src/data/action-categories.ts*. The catalog generator throws on it at prebuild, and `action-categories.test.ts` proves the message on a fake `zzzfake.*` template.
- **No category moved.** A fixture pins 188 ids → (catalog facet, Codex category), captured before the move. `public/action-catalog.generated.json` regenerates byte-identical, and the Codex entry order is unchanged.
- **Kept as is:** `invest.*` is in the Codex and not in the designer catalog, which is how it was before. `DESIGNER_CATALOG_EXCLUDED_PREFIXES` now records this in the table, so it is no longer a silent `null`.
