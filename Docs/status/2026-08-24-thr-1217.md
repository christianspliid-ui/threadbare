**The Done-when's own assertion was wrong, and the corrected form ships instead.** It asked
that `git check-ignore -v <path>` exit **non-zero**. It cannot: with `-v` git exits 0
whenever any pattern matches, **including a negation**, and prints the negated line — so the
`-v` form returns 0 both when the re-include works and when the file is still ignored,
conflating exactly the two states the check exists to separate. Dropped `-v` and added a
control arm: the corpus exits 1 (not ignored), `Design/fonts` exits 0 (ignored), same
command shape. A re-include that silently fails to match is now distinguishable from one
that works, which was the Done-when's stated intent.
