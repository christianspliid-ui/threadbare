# THR-1392 slice 3 — the line on cells (and THR-1300 closes)

**2026-09-03 · engine + content + UI.** The undertaking line — contract, gate, live proof, compiler, batch report, Package View — reads verb × object cells the way it reads authored templates, so a cell is held to the same ten blocks, proven on a seeded world the same way, overridden through the same compiler, and reviewed on the same surface. THR-1300 shipped its slices 1–4 earlier this week and its slice 5 (the pilot batch of six authored templates) was superseded by this model; this PR carries its closing keyword.

## What the line learned

- **The contract** (`undertakingContract.ts`). A cell's identity is its `cell.` id; its kind membership is the registry — the object type must declare the variant, or the resolver could never complete it; the `object` target rule counts as ownable for the counter-play block; a `found` cell's product is its declared semantic, not a hint; its numbers are checked against the default tier's bands (the board re-scales them on the resolved object); its reachability is an ambition's `cells` list; the cast floor does not apply — the object handle is the identity the floor guards, and a cast goes on an override when a cell earns one. `undertakingWriteSet` gains `object`, so a cell's write set is never empty. **All 22 cells pass all ten blocks**; the corpus gate (`check:undertaking --all`) now checks packs and cells together: 86 checked · 27 pass · 59 on the ratchet · 0 unlisted.
- **The live proof** (`undertaking-live-proof.ts`). The review lever walks a cell under the `cells` model whatever the flag says, so a cell is provable before the flip. `mutation_object` reads the **history entry** the completion wrote (`graphOps` carry `<op>:ok`), durable state like the per-hint claims' graph reads — the first draft read the resolver's trace and measured nothing, because the completion tick emits thousands of traces before the completion phase and the 2000-ring had already evicted it. No per-hint switch was added; christening accepts a cell's created node.

- **The compiler** (`undertakingPackage.ts`, `compile:undertaking`). A **cell package** is `{ slug, cell: { variant, objectTypeId }, override, profiles }` — no template, no kind. It resolves to `applyCellOverride(cellId, slug, override)`: a new template that keeps the cell's verb, object type, rule, gate, harm and tables and replaces only what the override names (display name, prose, cast, creation effects, mode, duration, catalysts, reach). The emitted module is the *call*, not the flattened template, so a later retune of the verb tables reaches every compiled override. It registers in the factory aggregate and in each named ambition's `cells` (opening the list when absent), never in a kind row. `CELL_OVERRIDE_MAX_PER_CELL` refuses a fourth override on one cell — a fourth is a pack again.
- **The batch report** gains a verbs × objects grid beside the kind × CRUD grid, with the batch marked; a cell reports its variant as its column.
- **The Package View** shows *The object* for a cell instead of a kind row: variant × type, the graph shape in words, who holds one, whose it may be aimed at, the base cell for an override, and the type's other cells a click away (Law 21); the write-set block names the semantic. Cells sit in the index beside the packs.
- **The interface map** gains `undertaking-object-types` (registry + resolver; UNVERIFIED-OK until the flip, deferral THR-1392).

## What the proof found, and what changed because of it

The first live run of the cells was the whole point of putting them on the line, and it found three things a unit test could not. **A completed cell never reached the resolver:** `executeInstantMutation` gated the resolver on `UNDERTAKING_MODEL === 'cells'`, so under `templates` a cell the lever started ran its checkpoints, recorded a harm, and mutated nothing. The flag now gates enumeration only — a cell that is running resolves as a cell, whatever the board is walking. **`found` cells targeted existing objects instead of a site:** `found × route` enumerated route identity nodes and found none in range. Each type now names its site rule (`FOUND_SITE_RULE` — the settlement a room is built in, the far end a route opens to, the actor for a masterwork or a company), and the candidate carries the site as its handle. **The world takes sites:** on seed 42 the first actor the lever accepts is a mercenary commander besieging Bitterbury, and the siege razes the hamlet at tick 23, mid-project. A `found` whose site is gone now lands where the builder stands (`foundSite`: the place of the work, the handle, the durable origin, the actor's current location, in that order); a route whose far end is gone fails honestly; a verb on an object that is gone refuses `object_gone` — correct, and a slice-4 refinement is to bind the object as must-persist cast so the project fails by name at the next checkpoint instead of completing into a refusal.
