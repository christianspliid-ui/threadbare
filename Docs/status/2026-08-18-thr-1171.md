# THR-1171 — a grief the sheet never carried, and the gate that could not see it

**Shipped 2026-08-18.** `apotheosis-ascension.ts` attached `trait.condition.grieving`
from its `critical_failure` band. That id was in no catalog. The `condition_attachment`
arm in `encounterAftermath` looks the node up, misses, emits `template_missing` and
`break`s — fail-soft by design — so the write did nothing while the chip above it went
on reporting the grief. A UI Law 56 breach inside the ticket that was fixing UI Law 56
breaches, on the game's Influence capstone.

**The file's own comment is why it survived.** It stated the reasoning explicitly —
*"the conditions are chosen from the live catalog, not minted: … `trait.condition.wounded`
/ `trait.condition.grieving` already exist"* — and the claim was half true. `wounded`
existed. `grieving` did not. A sentence that reads as checked is what stops the next
reader from checking it, so the comment is now corrected in place rather than deleted:
it records what it got wrong and why the claim looked safe.

## Option 1, because two authors reached for the same missing word

The ticket offered two legitimate fixes — define the condition, or repoint to a live one
and move the grief into the band `overview` (the workaround THR-733's company drama took
under the same constraint). Taken: **define it**. Two independent encounters reaching for
the same absent word is a vocabulary gap, not two authoring slips, and the shipped set of
six had no word for a loss with no body to bury. `trait.condition.grieving` is now a real
definition with `CONDITION_GRIEVING_DURATION = 72` (6 game days — the longest of the
personal set, because the others are things that happen *to a body* and wear off as it
recovers, and this one happened to a life).

Its `domainContributions` are `heart -0.08, eye -0.05` and deliberately **not** `iron`:
grief takes the attention off the room and the steadiness out of dealing with people, and
it is the absence of a body penalty that separates it from `wounded`. It is declared with
`satisfies` rather than the `as` cast the six older entries use — the location set already
made that switch, and the cast is precisely what let the header's claim go unchecked.

## The real defect was the gate's traversal, not the missing id

`validateNudgeGrantRefs` already checked `condition_attachment` against
`CONDITION_TRAIT_DEFINITIONS`. It had done so the whole time the defect was live. It
walked **`step.nudges[].grants` and nothing else** — so the entire aftermath surface went
unswept, and the corpus test reported green about three of the four places an effect can
be authored.

The fix is a delegation, not a new checker: the sweep now walks `allTemplateEffects`, the
same traversal the `reward_draw` gate uses (aftermath variants, `byOutcome` bands, step
success/failure metadata, cards). The two gates can no longer disagree about what
"shipped content" means. `DeadNudgeGrantRef` loses `stepIndex` + `nudgeId` for a single
`site` string — those two fields could only *address* a card, which is exactly why the
sweep could only *walk* cards; a shape that cannot name an aftermath reaction guarantees
aftermath reactions go unchecked.

**Falsified before trusted.** Breaking the new definition's id turned the corpus test red
naming both real sites by name —
`aftermath.negative.critical_failure.apotheosis.pause.stand_outside` and
`aftermath.fallback.critical_failure.…` — which is the ticket's "two chips", confirmed
rather than assumed. Reverted, green.

**The corpus assertion was vacuous and said so.** Its own comment read *"the shipped
corpus … currently authors no card grants at all, so on its own it would pass against an
empty population and prove nothing"* — an accurate self-description that stayed true, and
green, straight through this defect's life. The widened sweep now checks hundreds of refs,
and `expect(report.checkedRefs).toBeGreaterThan(0)` pins the population so the emptiness
can never come back unannounced.

## One defect found by the new test rather than by review

The aftermath regression test — a template whose only dead ref sits in a `byOutcome` band,
the exact shape the old walk could not see — crashed instead of failing: `allTemplateEffects`
pushed `['fallback', config.fallback]` unconditionally and dereferenced it one line later,
so a template with variants and no fallback threw a `TypeError` **out of a gate**.
`check:encounter --all` would have aborted mid-corpus rather than reporting, and the
liveness sweep would take the whole test file down with it. Both entries are filtered now
(NFP #4). A gate that crashes on unusual-but-legal content is worse than one that misses
it — it makes the content look like a tooling failure.

## Scope held

The membership predicate turned up two further off-vocabulary ids, both **out of the
shipped pool** and both left alone deliberately: `trait.condition.consecrated` in
`examples/example.shrine_consecration.ts`, and `trait.condition.location.watched` in a
test fixture (the real id is `under_watch`). Neither is registered in
`UNIFIED_ACTION_TEMPLATES`, so neither can reach a player — and the gate now covers
everything that is. `example.betrayal_multi_target.ts` named `grieving` and became correct
for free.

Three net-new type errors were **fixed, not baselined** (ratchet 3160 unchanged).
