# THR-2013 — a gift's card line toasts once

**Shipped 2026-10-24.** Bug, filed by the 2026-10-23 weekly retro (impediment row 1207).

**What was wrong.** The settle path (`resolvePendingBeat`) raises the `beat_cards_*` event once. The doubling was in routing. `useNotifications` routed every event in each new `tickEvents` array. `tickEvents` resets only at the next tick, and a write between ticks (the next gift resolving, a mark revealing) appends to the current array. So the new array still carried the gift's event, and it was toasted a second time under the same id. The player saw "A new card is yours: Breath of the Sphere." twice and React logged a duplicate-key error. The debug drain (`dismissBeats`) hit it every time. On a player path it happens whenever a second between-tick write follows a gift before the clock moves.

**What changed.** `selectUnroutedEvents(previous, next)` in `src/engine/notificationRouter.ts` returns only the events a previous routing pass has not seen, compared by object identity. The spread keeps the same event objects, and a fresh tick's events are new objects even when an id repeats. `useNotifications` routes only those. The router itself is unchanged.

**Evidence.** `src/components/Game/hooks/__tests__/giftToastRoutedOnce.test.ts`: one `beat_cards_*` event per gift on the settle path, and one toast across the between-tick re-render. The hook arm fails on the unfixed hook. Browser (worktree Vite :5283, tree-identity probe true, 1920×1080, `?view=game&seeded&size=medium`): fire the Thing Left Behind, `dismissBeats`, fire a pool beat, `dismissBeats` with no tick between. Result: one "Breath of the Sphere" toast, 0 duplicate-key errors. The only console error was the TTS health probe on :3001, which is unrelated. `npm run gate`, code track: all PASS.
