# THR-2207 — Stay the Unmaking, and the Doom rate stops compounding

**Shipped 2026-11-14.** Thematic Pressure & Living World. Plan doc: `Docs/plans/2026-11-13-thr-2202-give-both-clocks-a-verb.md` (slice 2).

- **Compounding fixed first.** `phaseDoom` used to fold every `doom_rate_multiplier` into a copy of the clock and write its `tickModifier` back to state, so an active multiplier compounded every tick. Before: a 0.5 multiplier held for 100 ticks advanced the clock **about 1 tick**. After: **50**. The multiplier is now an argument, `advanceDoomClock(state, rateMultiplier)`. It scales one tick's advance, is clamped at `DOOM_RATE_FLOOR` (0.1), and is never stored. `doomWakesAtBond`'s ×10 floor test relied on the bug: ×10 folds to the ×3 cap, so its loop went from 60 to 200 ticks.
- **Stay the Unmaking** (`divine.self.stay_the_unmaking`). A sustained self card that is a generic milestone gift. It costs `DOOM_STAY_COST` up front and `DOOM_STAY_UPKEEP_PER_TICK` each tick, both from the primary pool. It is a new `ControlSpec.ownerRuleOverride`: the control effect lives on the god (`SELF_CONTROL_HEX`), and `phaseControlEffects` keeps a persisted `doom_rate_multiplier` override on the god for exactly as long as the effect is active (`syncControlRuleOverrides`). That override is 0.75, or 0.9 on a crooked landing. `phaseDoom` reads it through the shared reader, with no new path. It is non-stacking and traced as `doom.stay_applied`.
- **The gift.** `beat.milestone.the_first_stage` fires once the clock stands past stage 1 after the bond. It is keyed on state, so a busy beat slot only delays it.
- **The notice.** `PopupItem.eventType` (set by the router) tells the host a Doom notice. `doomStayNotice` adds "Stay the Unmaking slows it. Holding it draws on your Mind essence every day." and a "Stay it" button while the card is held and not active, or "You are holding it back." while it is active. "Stay it" opens the god page, whose Act row holds the card. The ActionDrawer the plan named was retired by THR-1911, and there is no focus-a-card lever, so the drawer opens unfocused.
- **The upkeep chip names the pool that pays it** on every sustained god card ("light upkeep from Mind"), through `WheelSlot.upkeepSphere`.

**Evidence:** `npm run gate` PASS (test, typecheck, build, encounter, god-cards, ui-debt, cli-smoke). `doomStayTheUnmaking.test.ts` (17 tests) covers:
- 0.5 for 100 ticks → 50 ± 1;
- held clean for 240 ticks → 180 ± 2 (an unheld run → 240), with a primary drain of 0.15 × 240;
- a crooked landing → 0.9;
- a dry purse lapses the hold and frees the rate;
- the second hold is refused;
- the notice's three faces;
- the milestone enqueues at stage 2.

So `doomStayNoticeRender.test.tsx` renders the composed path instead: a real `doom_escalation` event through `routeNotifications`, then `doomStayNotice` on a real god, then `EventPopup`. **Review gate (THR-1691).**
- Round 1 confirmed three findings, all fixed:
  - A self-held lapse event carried the off-map hex, so the visibility filter hid "Your purse ran dry…". Self-held events now carry no hex.
  - The generic per-tick control push landed on the god's own node and credited the Mandate. Self-held effects now skip it.
  - `doom.stay_applied` misreported the rate when the floor binds. It now reports the clamped step over `tickModifier`.
- Round 2 confirmed two more, fixed after the round cap:
  - The Threads ledger listed the hold as "Hex (-1, -1)". `getSustainedControlNodes` now skips self-held effects. Side effect: there is no Release row for Stay yet; the hold ends when the purse runs dry.
  - `phaseJourneyBeat` rebuilt last tick's progress from `tickModifier`. The clock now records `lastStep`, and the journey reads it.
- Those two fixes have not been reviewed, so the PR stays unarmed for a fresh review cycle (review-gate step 8).
