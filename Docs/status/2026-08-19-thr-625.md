# THR-625 — Backstory strata prose expansion

**Shipped 2026-08-19.** The content follow-on to THR-612, and the first pass to give the strata tables a density floor that can fail.

## What shipped

**228 new variants across all 12 tables — 459 → 687 lines.** Every one of the 113 keyed entries went 4 → 6 (`TURNING_POINT_PROSE.preservation_transformation`, which already carried 5, went to 7), and the one flat table `DECISIVE_NATURE_PROSE` went 6 → 8. The ticket asked for "2+ variants per key"; the delivery is uniform rather than opportunistic, so the floor below is a single number rather than a per-table table.

Register is baseline plainspoken per THR-609 — subject first, concrete nouns, one dry line — and matched to each table's own tone comment rather than to a house average. `SURFACE_ORIGIN_PROSE` stays third-person hearsay (*"Two households in {culture} both claim {name} as a guest that season. The dates overlap."*); `STORY_ARC_PROSE` stays fatalistic (*"The {arc_phase} in {name}'s thread is not a warning. Warnings imply the option of turning."*); `SURFACE_SPHERE_PROSE` keeps its longer manifestation cadence.

## The gate was the load-bearing half

`validateKeyedTable` asserted `length >= 2` while every key already shipped **4**. Left there, it would have passed whether this ticket delivered 228 lines or none — a green run that is evidence of nothing, on the one ticket whose entire deliverable is density. The floor is now pinned to what actually ships (`MIN_VARIANTS_PER_KEY = 6`, `MIN_DECISIVE_NATURE_VARIANTS = 8`), and the two per-table `>= 3` assertions and `FEAR_PROSE`'s own inline `>= 2` were raised to the same constant so no weaker duplicate survives to launder a regression.

**Falsified rather than assumed.** Reverting `backstory-content.ts` alone, with the test file left raised, turns **14 tests red** — `AssertionError: expected 4 to be greater than or equal to 6`. That is the run that distinguishes a gate which proves the change from one which merely survives it.

Three authoring constraints from the handoff held, and two of them were structural rather than a matter of care: the per-key placeholder assertions use *"at least one template per key"* semantics, so adding variants to keys whose existing lines already satisfy `{culture}`/`{archetype}`/`{basis}` cannot dilute them below the floor. `SURFACE_SPHERE_PROSE` stays at **8** keys — the Creation Spheres — and was not "corrected" to 12; the suite pins that length, and Foundation keys would author prose the resolver can never draw.

## One live defect fixed, one filed rather than fixed

`SURFACE_SPHERE_PROSE.life` carried `{life}` — a placeholder `replacePlaceholders` in `backstoryResolvers.ts` is never handed, since the sphere resolver passes only `name` and `sphere`. It reached the player as literal braces. Fixed to `{sphere}` in passing: one token, unambiguous, in a line this ticket was expanding anyway.

The second one was **not** fixed, and the reason is the finding. `FEAR_PROSE.honesty_cunning_positive` renders with `{value}` = **"Honest"** — `pole` and `valueLabel` derive from the same sign test — while its four pre-existing lines are about practising deception (*"the deception, if discovered, will define everything that came before it"*). Its `_negative` twin renders as **"Cunning"** over lines about being visibly *bad* at deception. The two bodies fit each other's keys. Every other pair checked is aligned, so it is one pair, not a convention error.

It was left alone because a second file disagrees: `FEAR_DESCRIPTIONS.honesty_cunning = ['Fears being outwitted', 'Fears having to deceive']` pairs Honest→outwitted, which is what the prose was evidently written against — and that array is read by `src/engine/strands.ts` and the CMS registry, so flipping it moves a second player-facing surface. Which file is authoritative is a content-authority judgement, not an executor's unilateral edit inside a content-expansion ticket. Filed as **THR-1187** (Medium, with its coordination block), including the caution that the existing suite passes either way — placeholder, density and distinctness assertions are all blind to a pole inversion. The 4 new lines authored for those two keys are deliberately **pole-agnostic** and read correctly whichever way THR-1187 lands.

## The third evidence item had nothing to run

The ticket asked to *"verify with the prose-QA scorer where the tables are swept"* — and the strata are **not** swept. `collectAuthoredProse.ts` declares its corpus in its own import list (`unified-action-templates`, `social-scene-templates`, `spell-templates`, `omenTemplates`, `starter-attachments`, `reward-attachment-catalog`); no backstory table is among them, and `grep -rn backstory src/engine/content-eval/` returns nothing. After this pass the strata are **687 authored lines** — the largest authored-prose surface outside the register scorer's reach, which is an awkward place for the shard most likely to drift lyrical. Recorded as impediment **#687** rather than reported as a scorer pass that never read these lines, and left unfiled per the process-work throttle: retro material, not a ticket.
