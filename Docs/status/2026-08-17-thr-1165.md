# THR-1165 — the mark had the wrong man

**Shipped 2026-08-17** · [THR-1165](https://linear.app/threadbare/issue/THR-1165/two-dollarcast-sentinels-resolve-to-nothing-at-runtime-the-caravan) · project *Encounter Experience*

Filed as "two `$cast:` sentinels resolve to nothing." The premise turned out to be wrong,
the conclusion right, and the real defect worse than the one described — so the
measurement, not the fix, is the substance here.

## The premise was false and the corpus was still broken

The ticket's mechanism was: `vertical-slice.ts` declares exactly one `supportBundle`, so
the other templates' `$cast:` sentinels name keys nothing declares and resolve to
`undefined`. Checked directly, every named key **is** declared —
`encounter.slice.riders_behind_caravan` carries `keeper`, `traveler`, `outrider`. A
whole-catalog sweep for the ticket's literal predicate (a sentinel whose template does not
declare the key) returned **0 hits across all 683 templates**.

`withDefaultSupportBundle` is why: it merges a setting-class cast onto any template that
declares no bundle of its own. Had the gate been built to the ticket's predicate, it would
have shipped green over the entire defect.

The keys are declared. They bind nothing, for a different reason —
`default-support-bundles.ts` states it outright: *"defaults are bind-only."* Every default
spec is `delivery: 'pre-seeded'`, which attaches an NPC the world already placed and
materializes none. So the binding exists only when a matching role happens to be standing
there. Measured on seed 42, the caravan encounter spawned with `supportBindings: []` and
its `bond_change` wrote nothing.

## The half that is worse than a missing write

When a bind-only key *does* bind, it binds the scenery, and the scenery is the wrong
person:

| Site | Sentinel | What it actually names |
|---|---|---|
| `unsafe_bridge` | `$cast:keeper` | the wayside default's hermit, "Wayside Keeper" |
| `riders_behind_caravan` | `$cast:keeper` | the same hermit — not the caravan master |
| `swindler_found` | `$cast:trader` | the urban default's ambient "Market Trader" |

The third is the sharp one. A `hidden_mark` labelled *"Sells deeds to land that was never
his"*, aimed at `$cast:trader`, does not mark the swindler the scene is about — it brands
whichever honest merchant was in the square, discoverable later by exactly the
investigation and merchant content the mark exists to feed. That is not a missing write.
It is a false fact about a real person, and it is strictly worse than writing nothing.

**Three sites, not the two filed.** `unsafe_bridge` was outside the ticket's list and
carried a code comment asserting the opposite of the truth — *"`$cast:keeper` is a cast
actor the template declares and the world instantiates."* Re-deriving the predicate rather
than trusting the filed sites is what found it.

## What shipped

**Engine** — `castTargetViolations` in `compositionContract.ts`, scoped to effect kinds
that write a durable fact **onto a person** (`bond_change`, `hidden_mark`,
`attachment_grant`, `membership_change`, `agent_relocation`). It rejects an undeclared key
*and* a key whose spec is bind-only. Runtime behaviour is deliberately unchanged: an
unresolvable sentinel still fails soft (NFP #4). NFP #4 governs behaviour, not silent
authoring errors, so the fix belongs at the gate.

**Engine/tooling** — `scripts/check-cast-targets.ts` + `npm run check:cast-targets`, over
the **whole catalog**. Same population reasoning as `check:chip-anchors` (THR-1164):
`check:encounter --all` sees only the `encounter.` prefix, 191 of 683.

**Content** — the three templates now cast their own subject, composing the setting
default with a materializing spec: `bridge_keeper`, `caravan_master`, `swindler`. Composed
and appended, never replacing the default, so ambient cast keeps its binding order.
Fictionally this is also the right shape — a scene's subject is cast by the scene, not
borrowed from the furniture.

**UI** — N/A. THR-1164's `resolveAnchorDeclaration` already drops an unresolvable `$cast:`
rather than rendering a dead link.

## Evidence

Gate falsified both directions: red on the three shipped sites (exit 1) before the repair,
`0 failing / 683 checked` (exit 0) after. Runtime confirmed in the CLI on seed 42 —
`supportBindings: []` before, and after, `caravan_master` bound to a materialized node
(`reused: false`).

The static gate cannot prove a write lands, which is the entire lesson of this ticket, so
`encounterAftermath-cast-writes.test.ts` drives the **real shipped reactions** through
`applyEncounterAftermathReaction` and asserts the graph: the bond edge and both marks land
with the binding present, and are absent with `supportBindings: []` — the measured pre-fix
state — including an explicit assertion that the swindler's mark never falls back onto the
hero. 16 new tests total.

Full suite 1038 files / 16,666 tests green, ratchet 3178 unchanged (no baseline refresh),
build clean, smoke tick 30 / 384 agents. First full-suite run showed
`scripts/__tests__/impediment-id-allocation.test.ts` red at 5555ms; it passes in isolation
at 384ms and is unreachable from this diff — worker-contention flake, triaged per CLAUDE.md
§ Known Sandbox Limitations, and the rerun was clean.

## Note for the next author

The two gates now read the same sentinel for different questions and can disagree, which
is intended: `check:chip-anchors` asks whether a chip's *referent* could resolve, and a
bind-only key passes it because it names a real declared cast member.
`check:cast-targets` asks whether a *write* has a reliable target, and the same key fails.
A chip anchored to `$cast:x` beside a bond written to `$cast:x` is one authoring decision;
if you change the spec, check both.

Two of THR-1164's 29 swept chips are now worth re-pointing from the carrier fallback to
these newly-cast people, which is the strictly better anchor. Not done here — it is chip
work, not target work, and belongs with the next anchor pass.
