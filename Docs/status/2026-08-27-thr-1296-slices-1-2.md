# THR-1296 — The binder, slices 1–2 (registry + hook + scored board)

**Date:** 2026-08-27 · **Issue:** [THR-1296](https://linear.app/threadbare/issue/THR-1296/the-binder-proactive-agent-actions-plan-doc-36) · **Plan:** `Docs/plans/2026-08-27-thr-1296-the-binder.md`

The first two of the plan's six slices. Both are additive and consumed by nothing yet — the bind
pass that calls them is slice 4 — so this PR deliberately does **not** carry `Fixes THR-1296`
("sequential PRs welcome; only the closing PR carries the keyword", plan § Notes for the executor).

## What landed

**Slice 1 — the persistence ledger and its detector.** `EncounterSupportBinding.persistence` has
been authored 60+ times across the shipped corpus and read by **zero** engine consumers since it
was introduced; a template could declare a cast member must-persist and any reaper would take them
in silence. Now:

- `src/engine/binding/bindingRegistry.ts` — the ledger (`strategicState.bindings`, additive and
  serializable) plus a runtime-owned reverse index. `broken` is terminal and triggers a re-bind;
  no scorer ever reads it, which is the THR-1286 lesson (dead records poison scorers) answered by
  construction rather than by discipline.
- `WorldGraph.onNodeRemoved` — one optional hook on `removeNode`, the sole funnel all ~25 deleting
  call sites already pass through. One seam covers every reaper including the two that bypass the
  lifecycle entirely (`battleAftermath`'s commander kill and sublocation destruction) and any
  reaper not yet written. Guarded: a throwing observer degrades to the unset case rather than
  taking the tick loop down.
- **Housekeeping defers, narrative reapers proceed loudly.** `checkDissolutions` takes an optional
  `isBoundStage` predicate and skips a bound stage, traced. A siege razing one is unaffected — that
  is a story, not a chore.
- **Lazy validation catches both shapes of gone** (`!getNode || isAgentGone`), which is the only
  detector available for soft deaths that remove no node, so no hook can ever fire for them.

**Slice 2 — the scored board.** `src/engine/binding/binder.ts` replaces first-match reuse with five
weighted terms; `roleCensus.ts` makes scarcity a Set lookup on a version-keyed lazy rebuild rather
than an O(all actors) scan per slot per step.

## Two findings worth carrying forward

**`'agent'` is not a `NodeType`.** People are `type: 'actor'` + `actorType: 'individual'`. Written
the obvious way, the census would have scanned for `'agent'`, found nobody forever, and reported
every role as maximally scarce — which does not throw, does not fail a type check at the call site,
and surfaces only as mysterious over-minting. `phaseEconomicChronicle.ts:97` has this bug live on
`main` today; logged as impediment #834, not fixed here (out of scope for this diff).

**The first-guess mint weight was degenerate.** As specified, the mint row took `BINDER_MINT_BASE`
*plus* scaled full credit on every axis it trivially satisfies, so it beat reuse even for a scarce
role — one mode winning regardless of the world, exactly the failure the plan's kill criteria name.
Reformulated so the constant is load-bearing (base + scarcity + distance); the scarcity term now
demonstrably steers both directions, pinned by a two-arm test that differs only in population.
