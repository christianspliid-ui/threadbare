# THR-1304 — the six birth-path defects (2026-08-27)

THR-1296's recon measured six defects in the **ambient** births block and its plan doc
deliberately refused to fix them in that diff, filing them as one ticket instead. The
binder's mint path (`mintInhabitant`) was written not to inherit any of them, and the
divergence between the two birth paths was pinned by tests — so this ticket is the older
path catching up to the newer one.

All six are closed as real defects. None was closed as not-a-defect.

## Five of the six are one failure shape

A producer and a reader disagreeing about a field, silently, with nothing crashing. That
is why the Done-when insisted every test assert **through a reader**: a test inspecting
the property the producer writes would have passed against the broken code and proved
nothing at all.

**#1 — the culture key.** The newborn's `belongs_to` edge carried `strength: 0.6`. It was
the only `belongs_to` writer in the engine spelling it that way; every reader reads
`culturalStrength`. The interesting part is that the readers disagree about the *default*,
so the same child read two opposite ways depending on who asked: `getActorCultures`
defaults 1.0 and reported **fanatical** inheritance, while `culturalTraits`,
`culturalProse`, `culturalTension` and `insiderBeatDetection` default 0 — under the
`silent` cutoff, so no cultural traits at all. Nobody read the 0.6 that was written. Now
`culturalStrength: BORN_CULTURAL_STRENGTH`, a named constant at 0.6, which lands in the
`strong` band: a child is born *into* a culture but has not yet lived it.

**#4 — reputation on graduation.** `npcGraduation` stamped `reputationScore = 0` when the
field was missing, which it always is on a walk-on seeded by `npcSeeding`. Every other
writer in the engine seeds `DEFAULT_REPUTATION`, and every reader defaults a *missing*
value to the same — so the stamp made graduation actively worse than leaving the field
alone. 0 is below `LOW_REP_THRESHOLD` (0.1), the deaths loop's own predicate, so promoting
a walk-on to notable handed it a `DEATH_CHANCE_LOW_REP` roll every tick from that moment
on. Nothing in graduation intends to mark an NPC for death.

**#5 — the capability scale.** The block wrote `0.1 + rng() * 0.4` into a field
`computeCapability` reads on the sigmoid's *raw* scale (midpoint 10, k 0.4). Worldgen
mortals carry 10–40 there; `domainCapability.ts`'s own doc comment says so. So every
mortal the world birthed read as **~2% capable in all eight Reaches** and forecast
*doomed* on essentially any step. That floor was close to self-sustaining: nothing
rewrites `domainCapabilities` after birth, and the only way up is `applyEncounterGrowth`,
which accrues an experience trait and accrues it fastest on success. Now
`generateRoleCapabilities(rng, archetypeAffinity, 'notable')` — the same generator the
mint path uses — with the affinity taken from the archetype the block already rolled, so a
born mortal leans the way its archetype does. Draw-count neutral: eight `rng()` calls
before, eight after (NFP #3).

**#3 — the strategy spelling.** `npcGraduation` and `returnEngine` wrote `'tit_for_tat'`.
The canonical spelling is `'tit-for-tat'`: it is the `CooperationStrategy` union member,
the entry in `COOPERATION_STRATEGIES` and `VALID_COOPERATION_STRATEGIES`, the key in the
game-theory weight tables and the backstory pools, and the label the UI looks up. The
underscore matched none of them. In `returnEngine` the line carried an
`as CooperationStrategy` cast, which is precisely what stopped the compiler saying so —
dropping the cast is part of the fix, because without it the wrong spelling does not
build.

## The other two are reachability

**#2 — the validator that could not fail.** `validateAgentIntegrity` skips checks 2–8 for
any individual whose `spotlightTier` is not `spotlight`, because ambient and notable NPCs
are seeded with sparse property bags and would report an error apiece. Newborns are
written `spotlightTier: 'ambient'` — so the births block's validation call returned
"valid" after the node-exists check alone, whatever the property bag held, and the
`emitTrace` branches beneath it were unreachable by construction.

The fix is an opt-in `{ fullValidation: true }` rather than a change to the skip. A caller
that has just written a complete bag knows better than the tier does, and the births block
is exactly that caller; the sparse-NPC population the skip protects is untouched.

**#6 — the siting argument nobody passed.** `phaseAgentLifecycle`'s third parameter is the
content-rich birth-siting cache, and the only production call site — `orchestrator.ts` —
passed `undefined` for the parameter's entire life. So `BORN_LATER_PREFER_CONTENT_LOCATIONS`
(shipped `true`) gated a branch nothing could enter, and born-later mortals were sited
across every location in the graph rather than the ones carrying encounters for them.

Fixed in two places on purpose. The orchestrator now forwards `runtime?.encounterCache`,
which is readable at the call site; and the phase *also* resolves the cache off the
`runtime` it already receives when no argument arrives. The second is what stops this
recurring — a unit test on the branch passes whether or not any caller forwards it, so
relying on call sites to remember is what made the branch dead in the first place. The
cache is read from the runtime rather than the module-level legacy pointer, per CLAUDE.md's
per-session cache-ownership rule.

## Evidence

The new suite (`birthPathDefects.test.ts`, 11 tests) was run against **reverted sources**
to prove it is not vacuous: 8 of 11 failed, with exactly the predicted symptoms —
`expected 1 to be 0.6` (#1's 1.0 fallback), `expected 'fanatical' to be 'strong'` (#1's
reader split), `expected true to be false` (#2's ignored option), `to include
'tit_for_tat'` (#3), `expected 0 to be greater than or equal to 0.1` (#4's death
candidate), `0.0217 > 0.2` (#5's sigmoid floor), and `expected 'loc-harbour' to be
'loc-backwater'` (#6). The 3 that pass either way are the control arms and the guard that
a well-formed newborn survives the battery it now actually gets.

Two tests that pinned the defects were updated rather than deleted, and say so inline:
`npcGraduation.test.ts` asserted `reputationScore).toBe(0)` and
`cooperationStrategy).toBe('tit_for_tat')`.

The Done-when's third clause holds: `mintInhabitant`'s 17 tests are green and its file is
untouched.

Full suite 1112 files / 18507 tests green; typecheck ratchet unchanged at 2974 (no
baseline refresh); build clean; 30-tick smoke reached tick 30 with 377 agents — grown from
368, so births fired — and 49 events.

## One correction made in passing

A first draft of the #5 comment claimed "nothing grows `domainCapabilities` after birth",
which is literally true and misleading: capability *does* grow, through
`applyEncounterGrowth` writing an `encounter_experience_<domain>` trait whose edge level
`computeRawScore` adds on top of the base. The comment was rewritten before commit. The
defect's severity is unchanged — arguably worse, since growth rewards success and a mortal
two orders of magnitude below its peers rarely succeeds.
