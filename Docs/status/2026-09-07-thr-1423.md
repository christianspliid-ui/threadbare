# THR-1423 — the tick readout sweep, and why the predicate found three sites the ticket's grep could not

**2026-09-07 · UI · Bug · Encounter Experience**

`4 ticks remaining` fails two UI Laws at once: the bare integer is a raw magnitude (**Law 13**), and a tick is an engine unit with no player-facing display name anywhere in the game (**Law 14**). THR-1421 fixed one instance of this on the companions row and deliberately left the siblings to this sweep. `durationLabel` — which already ships, converts by the game's own `TICKS_PER_DAY`, and spells its count out so no numeral escapes — is the sanctioned reading, so this was implementation, not a ruling.

## The sweep found eight sites, not five

The ticket listed five and was careful to label them *"what it matched on 2026-09-07"*, stating its membership as a predicate per THR-688 rule A: *"every call site rendering `ticksRemaining` / `ticksLeft` as a numeral on a player-facing surface."* That distinction earned its keep immediately. The grep the ticket supplied — `"ticks remaining\|ticksLeft"` — is a **filter, strictly narrower than the predicate it stands for**, and it under-matched three real violations:

* **`DoomClockDetail.tsx:190`** — `Ticks Remaining` with a bare `${ticksRemaining}`. Missed because the grep is case-sensitive and the string is capitalised. This site also spelled the engine unit into the row **label**, so Law 14 was failing twice on one row; the adjacent `Ticks Elapsed` carried a raw `24 / 96` pair.
* **`FactionSheet.tsx:365`** — `({n} tick{s} remaining)`. Missed because the pluralisation interpolation (`tick{… ? 's' : ''}`) splits the literal the grep was looking for.
* **`AttachmentDetailView.tsx:133`** — `${ticksRemaining} / ${totalTicks} ticks`. Missed because the string contains no "remaining" at all.

Shipping only the five would have left Done-when #1 — *"No player-facing surface renders a raw tick count"* — literally unmet, while every stated checkbox read as done. This is the generalisable point: **a regex offered as a way to find a predicate's members is not the predicate**, and when the two are allowed to drift the count silently becomes the contract.

The ticket's `AttachmentsTab` line reference (`:226`) had also drifted to `:235` — THR-1421's merge shifted it. Same row.

## What shipped

All eight now resolve through `durationLabel`. Two readings needed a choice rather than a swap, and both avoided inventing anything:

* **`DoomClockDetail`'s elapsed row** was an `x / y` tick pair. Both halves are durations, so it reads `four days of eight days` — `durationLabel` applied twice, not a new language. Both row labels drop the word `Ticks`, which was the Law 14 half living in the label.
* **`AttachmentDetailView`'s Duration section** was likewise `x / y`. The pair is the same quantity the row's `ProgressBar` already draws, so the reading keeps only the remaining term — which is what the section title asks for.

`ReadTheThreadsPanel`'s cooldown renders only while `onCooldown`, so its count is always ≥ 1 and `durationLabel` never has to read a zero as `one day`.

## What was deliberately not done

**Two percentages were split out rather than banded — THR-1424.** `AgentInfoCard`'s `strengthPct` is named in the ticket's own Done-when #3. Sweeping the predicate turned up its twin: `DoomClockDetail`'s progress `pct` at line 169, the identical class on a surface already being edited. Both are filed together.

The reason this is a **Law 15** ruling and not an implementation choice is that a percentage has *no sanctioned numeric alternative*, unlike a tick count. `durationLabel` works because a duration converts into a unit the player already reasons in; a unitless proportion has none. Both obvious answers are pre-blocked: keeping the numeral is the violation, and banding to a word ladder is explicitly the wrong turn per the Law 13 amendment of 2026-08-12 (Christian's verdict on `grew steadily` — *"how can a player use that word to gage anything"*), a ruling `durationLabel`'s own docstring records.

The `AgentInfoCard` test carries an arm asserting the percentage **is still present**, so the split is pinned as deliberate rather than forgotten. When THR-1424 lands, that arm should fail and be tightened — a deliberate tripwire, not an oversight.

**Adjacent tick fields were left alone and filed as THR-1425.** `ticksAgo`, `durationTicks`, `ticksActive`, `tickLimit` and the divine receipt's elapsed count are the same Law 13/14 violation on player-facing surfaces, but they are *different fields* outside this ticket's stated predicate, and not all are remaining terms — `ticksAgo` and `ticksActive` are elapsed quantities, for which `durationLabel` is not automatically the right reading. Widening into them would have been a scope decision dressed as a sweep.

## The verification worth recording

**Every arm was falsified against the branch its fixture actually exercises.** The ticket carried an explicit instruction on this, learned the hard way on THR-1421, whose first falsification mutated a branch its fixture never took — so the test passed against a deliberately broken renderer and looked like proof. Here all eight call sites were reverted together and the suite re-run: **all eight surface arms went red**, plus the repaired `AttachmentDetailView` assertion. The fixture-guard arm stayed green, correctly — it pins `durationLabel` itself, which the revert did not touch.

**Three fixtures were invented before they were real, and the render caught each one.** The `as unknown as` cast is what let them through, which is precisely its hazard: `attachmentsFull` is not a field (both tabs read `card.afflictions`); a `curse` subcategory is gated behind `intimate` knowledge in `ProwessTab`, so a cursed fixture would have rendered an empty tab and passed **vacuously**; and `DoomClockStage.events` is read as `stage.events.length` with no guard, so a `{}` stub threw. Each failure was a component refusing an invented shape — the argument for asserting against real components rather than hand-rolled markup.

**The FactionSheet fixture hit the collectives trap.** A faction node is `type: 'actor'` with `properties.actorType: 'faction'` — *not* `type: 'faction'`. `getFactionNetworkSummary` returns `null` on any other shape, and the conclave block lives inside the `summary`-gated half of the sheet, so the wrong node type renders an empty sheet **without erroring**. That is the failure mode worth naming: it does not crash, it quietly draws nothing, and an arm written against it would have passed on a surface that rendered no conclave at all. Both traps are documented inline in the fixture.

Each arm asserts three things, and the third is load-bearing: the element carries **no digit at all**. Pinning only the expected phrase would pass against a renderer printing `four days remaining (48 ticks)`.
