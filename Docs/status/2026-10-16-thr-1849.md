# 2026-10-16 — THR-1849: a hamlet founded inside a people's own lands takes their heartland

**Ticket:** [THR-1849](https://linear.app/threadbare/issue/THR-1849) (Deferral from THR-1839). Engine pillar; Content and UI N/A (no new prose; the hex culture panel already reads heartland vs fringe from the edge).

Since THR-1839 a settlement founded during play took the nearest culture as a **fringe**, even two hexes from that people's capital, because the province map existed only during world generation. Such a hamlet read "<Culture> fringe" and the heartland readers (holy places, census) skipped it.

- **Engine.** Worldgen now stamps each hex of a living culture's province with `HexTile.provinceCultureId` (`stampProvinceCultureOnTiles`, called from `gameInit` right after `seedWorld`; same membership rule as the worldgen heartland pass; a lost culture's ruin-land is not stamped). The runtime pass `assignFringeCultureToFoundedPlaces(graph, maxHexes, tiles)` gives a place founded on a stamped hex current + historical links at full strength, exactly what a place seeded there at tick 0 carries. Outside every province the fringe rule is unchanged. The heartland branch runs even when the scenario keeps the fringe off, as worldgen's heartland pass does. The `founded_place_culture` trace now names each link's `kind`.
- **Decision recorded:** a runtime heartland link does **not** feed Realm holding. Realm holding reads `controls` edges (minted at worldgen, moved by conquest and oaths), never `belongs_to` culture.
- **Evidence.** 5 new tests in `src/engine/__tests__/foundedPlaceCulture.test.ts` on a generated world: every seeded heartland place sits on a hex stamped with its own culture; a founded hamlet on a province hex gets both layers at 1.0 and joins `collectHeartlandPlaces`; outside a province it still takes a fringe; the heartland applies with the fringe off; the in-tick path works. Gate: test-heavy, CLI smoke, typecheck and build pass.
