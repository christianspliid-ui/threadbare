# THR-1452 — the calendar had three clocks, not two, and one of them was a slider that moved nothing

**2026-09-10 · Engine · UI · Game Design · project Encounter Experience**

THR-1426 stepped over this deliberately: a wrong-number defect, not a Law 13 reading question, and
one whose fix is a decision that wants its own evidence. The ticket named two clocks. The sweep
found **three**, and the third is the one that mattered most.

## The ruling

**The engine's clock is canonical.** Recorded in `src/types/temporal.ts` beside the code, in
`turn-structure-reference.html` for the reader, and here.

The reasoning, so it is not re-derived: **the season was never in dispute.** It is already the
engine's and already on screen. Adopting the top bar's `tick / 120` divisor instead would have had
to *move the season* to rescue a year nobody had validated, and it would have made a season 2½
in-game days at `TICKS_PER_DAY = 12`. Adopting the engine's is a pure read of a value the tick loop
already computes, and it changes no simulation behaviour: the sweep found `clock.season` has exactly
**one** production reader (the top bar) and `clock.year` had **none** — computed every tick, read by
nobody, while the surface that displays a year derived its own.

Treated as a technical verdict rather than a chat gate. The ticket framed it as a design call, but
it resolves against something already agreed and already shipped — the season on screen — so there
was no creative fork to put to Christian. The veto stands open if the 360-tick year is wrong as
*pacing*; that is a separate question from which clock the display reads.

## The third clock

The ticket's two were `TemporalController` (90-tick season, 360-tick year) and the top bar
(`tick / 120`). The live path is neither. `orchestrator.ts` spelled the arithmetic inline:

```ts
const newSeason = Math.floor(s.tick / 90) % 4;
const newYear = Math.floor(s.tick / 360);
```

Two magic literals that **ignored `s.clock.ticksPerSeason` entirely** — so
`DEFAULT_TICKS_PER_SEASON`, exposed in the CMS with a `[10, 500]` range and captioned *"Affects
pacing of seasonal events"*, moved nothing at all. That is precisely the hazard the ticket warned
about (*"a tunable that silently desynchronises the year is the same defect again with a slider on
it"*) sitting in the tree already, and it is an NFP #1 violation in its own right. The tunable now
works because the orchestrator reads it off the live clock.

`TemporalController` turned out to be **dead in production** — `src/engine/simulation.ts`, its only
importer, is imported by nothing outside its own test. It was left in place (NFP #6) but repointed at
the shared conversion, so it cannot drift into being a fourth clock while nobody is looking.

## The shape of the fix

One function, `deriveSeasonAndYear(tick, ticksPerSeason)`, in `src/types/temporal.ts` — chosen over
either engine module because both `engine/temporal.ts` and `engine/gameInit.ts` needed it and the
types module is the one neither could cycle against. Three call sites that each spelled the
arithmetic themselves now call it, which is how they drifted apart in the first place. The two
independent literal `90`s collapsed to one: `DEFAULT_TICKS_PER_SEASON` is now an alias of
`TICKS_PER_SEASON`, and a test pins them equal so they cannot separate again.

Fail-soft (NFP #4): a zero, negative, `NaN` or `Infinity` `ticksPerSeason` falls back to the constant
rather than rendering `year NaN`.

## Verification

Both readers were **falsified by reverting them**, not watched going green:

- reverting the orchestrator to the two literals reddens the live arm — `expected +0 to be 1`;
- reverting `useSimulation` to `tick / 120` reddens both UI arms — `expected 4 to be 2`, the
  threefold divergence itself.

The live arm is a *multi-year* run of the real `initializeGameState → runTick` pipeline made
affordable by the tunable it exists to test: at 3 ticks per season a year is 12 ticks, so 26 ticks
crosses two year boundaries and cycles all four seasons. That short season is also the falsification
— under the old literals the whole run sits at season 0 / year 0 regardless. The arm confirms its
own perturbation (`deriveSeasonAndYear(26, 90)` is asserted to be `{0, 0}`), so it cannot pass by
happening to match the default.

The retired divisor is asserted as a **disagreement** rather than as a restatement of the surviving
formula, so reintroducing it anywhere cannot satisfy the guard by coincidence.

One intermediate suite run failed a single unrelated arm in a `resetDecisionCache` fixture — the
known-unstable baseline (THR-489), no such call in any file this change touches, and the clean run
above confirms it.

`Browser-verify substitution: jsdom-render` — unattended scheduled run, `preview_start` refused
(#546/#574). The substitution renders the **real `SimulationControls`** on both of its tiers, driven
by the value the **real `useSimulation` hook** produced, so it covers the whole chain the defect
lived in: engine clock → hook → rendered text. At tick 990 the compact tier reads `winter · year 3`
and the full tier `winter` / `Year 3`; both assert the retired `year 9` is absent. Console output
across the render: worldgen validation noise only (`Ocean fraction too low`, `Drainage guarantee
violated` — pre-existing on the small map, also present in the CLI init), nothing from the
components. This establishes the text reaching the surface; it does not cover paint or overflow.

**UI Laws checked:** 13 and 14 (the subject — a year is a magnitude the player reads, and it was
reading the wrong one), 1 (the concept carries its presentation — season and year are one readout and
now say one thing), 17, 21, 33, 37. No layout, z-index or interaction surface moved.

## What this does not change

THR-1426's ruling stands, and `laws.md` now says so explicitly rather than resting on the defect.
That ruling's premise was that the game has no calendar to date a row against; a season and year that
agree with each other still place no *individual tick*, so a list row's reading is still "how long
ago". The amendment records the fix and reasserts the ruling in the same breath, because the
reasoning paragraph would otherwise read as false to the next person who checks it.
