# Guidance governance — a direction change now has to remove the old guidance (THR-1253)

**2026-08-26** · [THR-1253](https://linear.app/threadbare/issue/THR-1253/guidance-governance-a-manifest-gated-single-authority-chain-doctrine) · plan: [`2026-08-25-thr-1253-guidance-governance.md`](https://github.com/christianspliid-ui/threadbare/blob/main/Docs/plans/2026-08-25-thr-1253-guidance-governance.md)

Rulings land in the canonical chain; agents obey the *operative* chain — the prompts, briefs,
exemplars and vault samples they load first. Measured 2026-08-25: three director-level prose
register rulings sat in `Docs/canon/prose.md` while every operative surface kept teaching the
retired mode, and the pipeline drafted against inverted rules for weeks. Nothing forced a
direction change to sweep its own restatement sites, so the ruling PR could end with the old
guidance still live. Layer 1 (single authority + pointers) shipped in THR-1251; this is layers
2 and 3.

**Layer 2 — change-time enforcement.** [`Docs/guidance-manifest.json`](https://github.com/christianspliid-ui/threadbare/blob/main/Docs/guidance-manifest.json)
declares, per doctrine, the **authorities** that define it and the **dependents** that restate
it. `npm run check:guidance-freshness` fails a diff that edits an authority without touching
every dependent, naming the untouched ones — unless a commit body carries
`Guidance-sweep: <doctrineId> — <disposition>`, the auditable "checked, deliberately unchanged"
hatch. Scoped by doctrine id on purpose: an attestation for one doctrine must not waive another.
Dependents carrying frontmatter also declare `validated_doctrine: prose@2`; that half is
**advisory always**, because forcing a stamp mechanically recreates exactly the date-bump theater
`last_validated_against` already demonstrated.

**It ships advisory, deliberately** (THR-899: a false-positive gate damages the thing it protects,
and a brand-new dependent list is where false positives live). The flip is filed with its date —
[THR-1256](https://linear.app/threadbare/issue/THR-1256/flip-checkguidance-freshness-from-advisory-to-blocking-after-its-burn),
reviewed on/after **2026-09-08** — and the date lives in `GUIDANCE_GATE_MODE` in the script, so
the burn-in cannot become permanent by inattention. It runs in **both** CI jobs, not only
`Docs gates`: a PR editing canon *and* one source file classifies as code, skips that job, and
would otherwise never be swept — which is the shape a doctrine change usually has.

**Layer 3 — the recurring semantic audit.** `/guidance-audit` encodes the 2026-08-25 audit as a
repeatable three-partition procedure (skills / Docs / vault), reading authorities **live** and
never embedding doctrine text — an embedded baseline is itself a copy that drifts, the disease
being treated. It exists because a gate structurally cannot see the failures that matter most:
a dependent that was *touched* and still teaches the old rule, two live surfaces contradicting
each other with no diff between them, or a doc a newer doc has silently replaced. `retrospective`
Step 5d triggers it when any doctrine version has moved since the last retro, or monthly — the
version integers make that trigger cost one comparison. Findings land as impediment rows; the
retro stays the single promotion point, per the 2026-08-10 throttle.

Gate demonstrated firing: a deliberate unswept edit to `Docs/canon/prose.md` produced `WARN` in
advisory and `FAIL` (exit 1) in blocking, naming all three untouched dependents; reverted.

**Sunset:** gate, stamps and retro step enter the standing six-week presumption — renewed at
retro by citing a catch, else deleted.
