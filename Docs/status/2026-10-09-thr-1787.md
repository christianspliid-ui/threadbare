# 2026-10-09 — THR-1787: the warm start arrives with the opening already played

**Ticket:** [THR-1787](https://linear.app/threadbare/issue/THR-1787) · **Found by:** warm playtest round 1, 3/3 testers read the gift chain at arrival as the tutorial repeating

- **The no-choice gifts settle before the first warm tick.** `runWarmStart` (`src/components/Game/hooks/useWarmStart.ts`) calls a new `settleOpening` dependency once, under suppression and before the first chunk, with `WARM_START_SETTLED_SPINE_BEATS` (the seat, the thing left behind, the first word). GameView routes it to the new engine helper `settleOpeningSpineBeats` (`src/engine/ascendantBeat.ts`). The helper settles Beat 0 first if it is still at the cursor, then each gift strictly in cursor order through `settleSpineBeatAsPlayed`. The seat is placed at The First's tick-0 settlement, so the god earns from it through the warm-up. Each gift has one call to action and no alternative, so nothing is decided for the player.
- **"A Path Opens" still waits.** It is a real 1-of-3 choice and is never listed; it is the one arrival decision.
- **Trace and copy.** `beat.settled_as_played` gains reason `warm_start`. Only Beat 0 writes the "thread already holds" line; the seat and the artifact announce themselves through their existing gift-placement lines. The catch-up screen adds `ui.warm_start.held`: "Anything that needs your choice has waited for you."
- **Fail-soft.** A refused or throwing settle leaves the rest of the gifts to be offered normally after arrival; the `[warm-start] done` line records `openingSettled` and `openingSettleFailed`. Plain `?seeded` is unchanged.
