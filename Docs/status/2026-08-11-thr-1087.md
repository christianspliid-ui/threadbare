# THR-1087 — the Discord doorbell gate is code now

**Shipped 2026-08-11.** [THR-1087](https://linear.app/threadbare/issue/THR-1087/the-discord-doorbell-gate-is-prose-in-three-disagreeing-places-and-its)

`keep-work-flowing-cc` step 7 decides whether to ring Christian's phone. That rule lived in prose in three places which had drifted apart, so every hourly run rebuilt it from first principles and reached a slightly different answer.

The skill said to hash *the rendered ask lines*. The out-of-repo method note said to hash *the briefing frontmatter's `needsChristian:` key list* — which no longer exists, since THR-954 retired the publish gate that owned it. So the documented input was unobtainable, and the documented fallback was the one the method note itself twice argues is wrong: the brief is rewritten hourly by design, so hashing its prose rings on wording churn. Four incidents in six days sit in `kwf-last-ping.derivation`, including a stale hash that would have fired **a duplicate doorbell 56 minutes after the real one**, and a run that "nearly misfired", caught only by reading the previous brief back from `ops` and diffing membership by hand.

## What shipped

`scripts/check-ping-gate.ts` (+24 tests) and `npm run check:ping-gate` — the same remedy `check-substantive-change.ts` applied to the publish gate.

The load-bearing choice is **what it compares against**. The obvious build diffs consecutive runs; that is what the hash file did, and why the removal-only rule had to be bolted on in English and remembered each hour. This compares against the set as of **the last ping that actually sent** — the only thing describing what Christian has already been shown — so the rule falls out of the data model: an ask that **joins** rings, an ask that **leaves** does not, nothing else moves the baseline. A removal-only diff needs no special case, and a *sequence* of removals cannot erode the baseline, because removals never advance it.

Identity is the key, not the prose, so rewording never rings and promoting an ask to the lead is not a change; to force a doorbell on a materially changed ask the lane rotates its key. State advances only on an explicit `--record pinged` after the DM is accepted, so a failed send stays retryable.

## Verification

Full suite 989 files / 15625 tests green; typecheck ratchet 3450, unchanged; `vite build` clean. Beyond the unit tests, the shipped script was replayed against the real 2026-08-11 18:00Z run and **independently reproduced that run's hand-made decision** (`silent`, removal-only, `linear-signed-out` departed), deriving a hash byte-identical to the one computed by hand that evening.

State moved to `~/.claude/channels/discord/kwf-ping-state.json`, seeded through the script itself rather than hand-written. `kwf-last-ping.hash` is deleted; `.method` and `.derivation` are kept, tombstoned, as the incident record — a future run reading that directory is told not to derive a method from it.
