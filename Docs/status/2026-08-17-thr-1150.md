# THR-1150 — faction standing that actually moves

**Shipped 2026-08-17.** Deferral of THR-1144, which hit this wall building `membership_change`, bridged it locally, and filed the general case rather than change an unrelated effect's behaviour inside its own PR.

## What was broken

`applyFactionReputationGain` matched memberships with `e.target === factionId` — a faction **node** id. Every authored `faction_reputation_gain` passes a **definition** id: `'mercenary_company'`, `'temple_of_spheres'`, `'underking_court'`, `'rangers_brotherhood'`, `'lorekeepers_covenant'`. That is the id every faction content file carries, and the only one that reads naturally to an author. `factionSeeding` keys the node `faction_def_<definitionId><chapterSuffix>`.

So the authored value matched no node and no edge target, and **every faction-standing consequence in the shipped game was a no-op**. An ending that said the Company thought better of you changed nothing about what the Company thought of you.

Measured on a real seed-42 world, same encounter, same tick — the ascendant's membership after `mc.join`:

```
before   [{"target":"faction_def_mercenary_company_0","reputation":0.05,"role":"sellsword"}]
after    [{"target":"faction_def_mercenary_company_0","reputation":0.15000000000000002,"role":"sellsword"}]
```

`0.05` is the join baseline. The authored `+0.1` on both of `mc.join`'s reactions had never once landed.

## Why it survived

The dispatcher's `newRank === 'none'` sentinel did `break` **silently** — "skip silently per plan doc fail-soft table". Fail-soft was right; quiet was not. A corpus-wide dead effect emitted nothing anyone could grep, so it took a different ticket walking the same field to notice, and the check that *would* have caught it (`getNode(effect.factionId)`) failed one line earlier and traced `faction_not_found` on an id the content had always carried — which reads as bad data rather than a bad lookup.

The no-op now names itself: `failReason: 'not_a_member'` or `'faction_not_found'`. Fail soft, never quiet (NFP #2).

## The fix

Resolution moved out of the three `membership_change` ops' bodies and into `bindFactionDefinitionIds`, a bind pass composed after the two existing sentinel passes — so a `$target`-bound faction arrives as a node id and resolves to itself. It covers **all seven** faction-carrying effect kinds, not only the one measurably dead: the other six have no authored definition ids today, so for them it is prevention, but the trap is identical and the cost is one table row each.

Widening-only by construction. `resolveFactionNodeId` tries the exact node id first, so the three pre-existing node-id callers — `processFactionEncounterReputation`, `factionOutcome`, `chosenFactionPowers` — resolve to themselves and nothing that worked stops working. That is pinned by its own test arm, not asserted.

`applyFactionReputationGain` also resolves internally, so the fix holds for callers that never pass through the dispatcher at all.

## The test that would have caught it, and the one that didn't

The pre-existing suite passes today and passed before the fix, because its fixture hand-builds `faction.adventuring-guild` and authors *that same id* back at the effect — a world shape `factionSeeding` never produces. A dead corpus stayed green behind a fixture that invented both sides.

So the proof runs `initializeGameState(seed 42, medium)`, takes a real seeded `faction_def_*` node and a real member off the graph, and fires the effect with the id the content files write. It asserts the premise first — the seeded node id contains the definition id, **and** the definition id resolves to no node — so the fixture cannot quietly stop testing the thing.

Falsified by reverting: 1 of 3 red on the seeded-world suite, 4 of 6 on the unit suite. The arms that stay green in both are the deliberate controls — the premise assertion, the explicit-node-id widening arm, and the already-tracing `faction_not_found` path.

## Content

No content edits. The sweep found all five authored ids name real definitions, so the resolver fixes the whole corpus as-is. That is a fact about today's corpus rather than a property of it, so `factionEffectIds.lint.test.ts` pins it: a deep walk of `UNIFIED_ACTION_TEMPLATES` for all eight faction-carrying kinds, failing on any id naming no `FACTION_DEFINITIONS` entry. A typo would otherwise resolve to nothing and silently no-op again — the exact failure this ticket exists to close, one layer up. It carries a population guard, because a `<=` over an empty walk is the vacuous pass such a lint most easily becomes.

**Balance:** deliberately not retuned. These amounts (0.05–0.2) were authored to fire and have never fired; changing them in the same pass would mean tuning against numbers nobody has observed in motion (NFP #7). The decay phase already counters gain. Worth a read once the retrofit lands.

## Rider

`faction_reputation_gain` joined `EncounterAftermathEffectTrace.effectKind`, so all four traces in that arm emit unlaundered. The THR-1065 cast ratchet correctly refused the new trace at 111; the answer was to remove three casts rather than raise the ceiling, and it is re-pinned 110 → **107**.

## Evidence
