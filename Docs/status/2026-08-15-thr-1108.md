# THR-1108 — the ascendant bar's two hover-tooltip timers clear on unmount

**Date:** 2026-08-15 · **Lane:** `tb-opus-pickup` · **Worktree:** `serene-easley-8a22ad` · **Issue:** [THR-1108](https://linear.app/threadbare/issue/THR-1108)

## What shipped

The two sites THR-1106's sweep found now clear their pending-tooltip timer in an unmount cleanup:

| File | Site | Window |
| -- | -- | -- |
| `src/components/Game/ascendant-bar/IdentityStrip.tsx` | `useDelayedHover` | 450 ms |
| `src/components/Game/ascendant-bar/HooksBlock.tsx` | `Chip` | 600 ms |

Both armed on `onMouseEnter` and cleared **only** on `onMouseLeave` — a handler that never fires when the pointer leaves *because the element unmounted*. The ascendant bar re-rendering, or a chip list changing inside the delay window, is exactly that, and the callback then ran `setShow` on a torn-down component. Each fix is the same effect the ticket specified, matching `src/components/shared/Tooltip.tsx:330`, the in-repo reference implementation.

The `IdentityStrip` fix lands inside the `useDelayedHover` hook rather than at its four call sites, so every `HoveredTerm` on the strip — sphere, name, archetype, quintessence — is covered by one cleanup.

## Four tests, and the two that matter are falsified

The Done-when asked for a test per site that arms the timer, unmounts inside the window, and asserts `vi.getTimerCount() === 0` — with a pre-assertion that the timer was armed at all, so it cannot pass vacuously. `src/components/Game/ascendant-bar/__tests__/hoverTimerCleanup.test.tsx` carries that, and adds a **premise test per site** that goes one step further than THR-1106's:

- hover → assert exactly one timer pending **and the tooltip still hidden**;
- advance the delay → assert the tooltip copy is now on screen.

That second assertion is what ties the counted timer to the tooltip specifically. Without it, `getTimerCount() === 1` only proves *some* timer exists, which a future unrelated `setTimeout` in either component would satisfy — the cleanup test would then keep passing while measuring the wrong thing.

Falsification was run, not assumed. With both cleanups removed:

```
× clears the pending tooltip timer on unmount instead of firing into a torn-down strip
  AssertionError: expected 1 to be +0
× clears the pending tooltip timer on unmount instead of firing into a torn-down chip
  AssertionError: expected 1 to be +0
Tests  2 failed | 2 passed (4)
```

Both premise tests stayed green, which is the point: the failure is isolated to the cleanup, not to the harness. Restored, all four pass.
