# THR-2194 — a burst of same-kind toasts reads as one toast with a count

**Shipped 2026-11-12.** UI Visual Overhaul — Design System v1 · weekly UX review (Mid-game table, two weeks running). No plan doc; scope from the ticket. Law 49.

- **Producer declares the burst kind.** `NotificationDirective` gains an optional `group: { key, headline }` (`ToastGroupDirective`, `src/types/notification.ts`). The notable-agenda crack toast (`src/engine/notableAgendas.ts`) declares `NOTABLE_AGENDA_CRACK_TOAST_GROUP` (`src/data/notable-agenda-config.ts`): key `notable_agenda_crack`, headline "{count} rulers' agendas come due". The rival god's scheme toast, also `rival_action`, declares no group, so it still shows on its own.
- **The router folds.** `routeNotifications` folds a grouped toast into the newest still-showing toast of the same key — in the same batch or an earlier one, so a warm start's catch-up and a few close ticks both fold. The host becomes a new object (the prior state is never mutated): line = headline with the count in words ("Three"), `count`, `groupMembers` (each member's own line, target and actor), expiry extended, moved to the newest slot. An expired host starts a fresh toast. Exact-repeat collapse for ungrouped toasts is unchanged.
- **The stack opens the list.** `ToastStack` shows a grouped toast (2+ members) with a disclosure glyph instead of the ×N badge (the line carries the count). Clicking opens the list (`aria-expanded`, `toast-group-list`); each line with a place or person opens it and dismisses the group; a line with neither is inert. Opening calls `onHold` → `useNotifications.handleHoldToast`, which sets the toast's expiry to Infinity so the list does not vanish mid-read.

**Evidence:** `npm run gate` — test, build, encounter, god-cards, ui-debt, cli-smoke PASS; typecheck FAIL +2 on the first run (missing return-type field), fixed, ratchet OK 2658 unchanged.
