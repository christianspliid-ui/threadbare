### THR-1210 — the word `reputation` now has one definition, and the other five are named (2026-08-24)

The director's ruling landed as a mechanism under THR-1206: **reputation is the social score
that modifies interactions between a and b**, read through one API. This ticket is the other
half — the UL entry that fixes the word. Until today the glossary defined **none** of the six
mechanisms wearing it, which is how they were able to disagree for as long as they did.

**Arbitration: Agents, not Encounters.** Reputation is a property of the social graph between
actors — its four legs are `member_of`, `reputation_with`, `relates_to`, and a default. None of
them is encounter machinery. `Encounters.md` already holds the encounter-facing surface as
`[[BOND]]` ("who now stands with or against the character — a companion joining them, faction
standing, personal reputation"), so that entry now See-Alsos `[[Reputation]]` and closes with a
pointer to *"the quantity a standing move actually writes"*. One concept, defined once, reached
from both shards.

**Five entries, not one.** A single `Reputation` entry would have left the other five
mechanisms exactly as undefined as they were, and the failure this ticket exists to close is
*collision*, not absence. So the cluster is: **Reputation** (canonical, the pairwise score),
**Reputation Tally** (canonical — what a mortal is becoming known *for*), **Reputation Score**
(canonical — one-sided world renown), and two `Status: deprecated` entries, **`reputation_set`**
and **`standing_welcome`**. The deprecated pair get full entries rather than a note inside
`Reputation`, because the README Term Index only surfaces entries — burying a retirement in
prose reproduces THR-806, where 16 shard terms were invisible to any session that loads only
the index. All five are in the index, the two dead ones marked *deprecated* in their gloss.

**Every claim in the ticket was checked against the code before it was written down**, and one
addition came out of it. The neutral default `REPUTATION_WITH_DEFAULT` is `0.5`, and
`bandOf(0.5)` is `Math.min(4, Math.floor(0.5 * 5))` = tier 2 = **`Accepted`** — so a gate
written as `{ atLeast: 'Accepted' }` is cleared by a stranger who has never met you. That is a
gate that never rejects, it was the live defect corrected inside THR-1182 hours earlier, and it
is precisely the kind of thing a glossary exists to stop the *next* author rediscovering. The
`Reputation` entry now states it in the definition rather than leaving it to be re-derived from
two constants in two files.

Also verified rather than transcribed: all four legs read **outgoing** edges only
(`getOutgoingEdges(aId, …)`), which is what makes the score directional; only the `edge` leg is
written through `adjustReputationWith`, so a write against a faction you belong to cannot mint a
second competing standing; `ReputationTallyKey` really is `` `${ReachDomain}.${'positive'|'negative'}` ``;
`reputation_set`'s handler is still live in `encounterAftermath.ts` (retired from *authoring*,
not deleted — the entry says so, so nobody prunes it); and `standing_welcome` really does have
zero writers, its definition and duration constant surviving only for saved worlds.

**Dashboard refreshed: 129 → 134 terms across 8 shards.** All five new See-Also links resolve —
the seven `unresolved_see_also` warnings the generator prints are pre-existing and untouched.
One dead link was caught and fixed *before* insertion: the draft's `[[Condition]]` matches no
UL entry, and now reads `[[Trait Category]]`, which does.

**Docs-only, and closed out on the docs track.** `git diff --name-only origin/main | grep -vE …`
returns empty — the regenerated `src/data/ul-dashboard.generated.json` is one of the two
doc-excluded artifact paths (THR-922), which is exactly the case that exclusion exists for.
Gates 3b, 5 and `check:impediment-ids` only; no `npm test`, no `check:typecheck`, no
`vite build` owed or run on a diff with no code in it.
