# THR-1045 — `check:encounter`, the Encounter Factory's machine gate

**Shipped 2026-08-09.** Encounter Factory implementation item 2 (plan:
`Docs/plans/2026-08-08-encounter-factory-workflow.md`, approved with rulings
2026-08-08).

One command — `npm run check:encounter -- <templateId> | --all` — running the
whole quality stack over an encounter: the new **Composition Contract**
validator (steps, hand, setting envelope, cast, rewards, aftermath, systems
quota, images), then the register detectors, card-grant liveness, an enrichment
token dry-run, and forecast-band arithmetic. Every failure names its block and
the plan section the rule is written in, so a red gate is answerable without a
search. Wired into CI's `Test · Typecheck · Build` job.

**Ruling 3 is honoured literally: there is no exemption mechanism.** The single
escape is `RETROFIT_PENDING`, a per-template ratchet in
`src/data/content-eval/retrofitPending.ts` that only ever shrinks. Its tests bite
in both directions — a template off the list that fails is new rot, and a listed
template that has started passing is a stale entry the list must drop.

## What the first sweep found

All **191** `encounter.*` templates fail the contract today, which is the
composition audit's finding (THR-1039) turned into a number. Templates failing
each block: aftermath 191, setting 183, systems 182, hand 178, tokens 154, cast
146, rewards 53, register 43, images 13. The ratchet is seeded with all 191, so
the gate's live job today is to hold the line on template #192.

Two findings were filed rather than absorbed:

- **THR-1052** — 27 distinct card `imageTag`s across 13 shipped encounters name
  no image-library row. The render path is fail-soft (category generic → glyph),
  so the author picked art and the player has been seeing the generic, with
  nothing to surface it. `generic.time` is almost certainly a rename that left
  its references behind (`generic.time-slow` exists).
- **THR-1053** — the plan requires `concepts` on every aftermath change (Law 2);
  `EncounterAftermathChange.concepts` documents itself as absent on authored
  changes (THR-1004). `concepts` is authored nowhere in the corpus, so this one
  rule is a large share of why the ratchet holds everything. The gate follows the
  plan, being the later and explicitly ruled decision, with a `TODO(THR-1053)` at
  the site.

## Two changes beyond the runner, both forced by it

**The golden exemplar is retrofitted to the full contract** and is the gate's
green case — `npm run check:encounter -- fixture.encounter.swollen_ford` exits 0.
It gained a cast binding, a banded `aftermathConfig` (success / failure /
critical_failure, meeting ruling 7's floor) with `concepts` on every change, and
six dead `imageTag`s repaired. Deriving the green case from the format's own
worked example — rather than authoring a fixture to satisfy the validator — is
what keeps the falsification tests honest: each red case removes exactly one
block from a template that otherwise passes.

**Second person is now scoped to the narrative field classes**, mirroring what
THR-899 did for vagueness. The rule exists so a scene never addresses the
*mortal* as "you"; `interactive` text is rules text addressed to the
**player-god**, and the locked card format asks an `effectLine` to say plainly
what the god does ("You thin the overcast…"). Counting that flat failed
correctly-authored cards by construction — including the exemplar. Measured
delta: register failures 47 → 43, and 3 templates still fail second person, so
the detector kept its teeth on narrative prose rather than being switched off.
Pinned both ways in `vagueness-scope.test.ts`.

## Scope notes

- `validateTraitRefs` is **not** in the stack. It is a graph-wide sweep over
  every content surface and cannot name a block for one template; its
  per-template sibling `validateNudgeGrantRefs` is what the gate composes, and
  the graph sweep keeps its home in `__DEBUG.validateTraitRefs()`.
- The Images block is narrowed against plan §1, which asks for a "step
  illustration tag": `ActionStep` has no image field — only
  `UnifiedActionTemplate.illustrationUrl`, a path rather than a library id. The
  checkable rule is therefore card tags resolving plus a declared
  `illustrationUrl` being public-absolute.
- `--all` is defined by id prefix, not directory. Most of the corpus lives in
  `encounter-content.ts` rather than `src/data/encounters/**`, so a path-scoped
  population would have swept a third of what exists.
