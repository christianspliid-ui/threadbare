# 2026-09-25 — THR-1550: monsters named and counted right (Fight on screen F1)

**Ticket:** [THR-1550](https://linear.app/threadbare/issue/THR-1550) · **Project:** Physical Conflict · **Plan:** `Docs/plans/2026-09-23-fight-on-screen.md` (slice F1) · **Pillars:** UI (the lair block, World Pulse, the monster tile, the debug accessor) · Engine N/A (reads only) · Content (one tooltip entry, `ui.lair_monster`).

## What was wrong

- The hex sidebar's Monster Lair block printed the elite's raw node id (`Elite: elite_lair_0_50`), which broke Laws 14 and 21.
- World Pulse's "Active Agents" counted every `individual` actor, including lair monsters and retained dead mortals.
- A monster drew the person tile: a knowledge-gated silhouette, or an initial letter where a surface passed `kind: 'agent'` (chips, the hex drawer's "Agents present" row).

## What shipped

- **`buildLairMonsterCardModel(graph, lairId, tick)`** (new, `src/components/Game/lair/`): `{ lairId, lairName, monster: { id, name } | null }`. The row holds only a living monster with a name of its own. A dangling or slain elite gives `null`, so the row is omitted and a raw id never renders. F4 extends this model.
- **The lair block** shows the monster's portrait tile and its name as a link that opens its sheet, with the new `ui.lair_monster` tooltip. GameView builds the cards for the focused hex's lairs, memoized on `worldVersion`.
- **World Pulse** counts living, non-monster individuals only (`countLivingMortals`, `src/components/Game/worldPulseCount.ts`).
- **The `monster` EntityVisual kind:** `deriveKind` returns it for an `isMonster` node. The resolver refines an explicit `agent` on a monster node to `monster`, and so does the chip icon resolver, whose returned kind drives the tile. v1 art is the shared `monster` portrait; the glyph fallback is ☠. It is not knowledge-gated (Law 8). The veil routes a `monster` chip link as an agent. A styleguide sample was added.
- **`window.__DEBUG.getLairMonsterCard(lairIdOrName)`** returns the model.
- The anchor-catalog pin now lists `monster` as a fourth render-time refinement of `agent`, as the plan decided.

**Beyond the ticket's list:** the refinement sits in the one resolver, not only in the chip collaborator, so the hex drawer's "Agents present" row draws the monster too. That row showed "R" for Ryx in the live check. The agent sheet has no graph, so it is unchanged, as the plan says.

## Evidence

- `src/components/Game/lair/__tests__/lairMonsterF1.test.tsx` (16 tests): the card name and five fail-soft cases; the sidebar has the link, no `elite_` in the DOM, and no row when the elite does not resolve; the World Pulse count is 2 of 5 individuals; kind derivation and explicit-`agent` refinement; no knowledge gate; a chip on a monster gets the monster portrait.
- Live check (seeded, medium, tick 60): `getLairMonsterCard('lair_0')` gives the monster Ryx, the sidebar link reads "Ryx", there is no `elite_` in the DOM, and World Pulse shows 505, which is 515 individuals minus 10 monsters and the dead. Clicking the link selects `elite_lair_0_50`.
