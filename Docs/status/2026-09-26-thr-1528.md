# 2026-09-26 — THR-1528: The ground remembers its battles (Blood-soaked, slice 1)

**Ticket:** [THR-1528](https://linear.app/threadbare/issue/THR-1528) · **Project:** Thematic Pressure & Living World · **Plan:** `Docs/plans/2026-09-24-thr-1528-blood-soaked-ground.md` · **Pillars:** Engine + Content; UI through existing surfaces (location page condition row, place MEMORY), no component change.

## What shipped

1. **A battle leaves a record.** `resolveBattle` now calls `recordBattleFought` (`src/engine/battleRecord.ts`) after the aftermath and before it removes the battle node. The call writes:
   - one `battle_fought` Event on the battle's outer-tier Location (a siege at its town);
   - a `participated_in` edge from each surviving commander, with the outcome read from the resolution, so a mutual destruction is `lost` on both sides;
   - a `lastBattleTick` stamp on the place.

   `applyAftermath` returns a `BattleAftermathSummary`. The record's sentence reuses the war news' `battleOutcomeSentence` and adds "… took X by siege."
2. **The fifth location trait, *Blood-soaked*.** It is minted by `phaseLocationTraits` from `readBloodshed`, which counts the battle records inside a ten-day window and never reads `deathCount`. The rule table gained three optional fields (`read`, `sustainTicks`, `chronicleSignificance`); the four scalar rules set none of them. Its readers are the movement tax (avoided, like Haunted) and a pool row (`#combat`, `#loss`, `#fear`, `#iron`). There is deliberately no step row. The mint line uses the shared 0.4, because the war news already tells the battle.
3. **Place MEMORY tells the battle** inside the window, with the day in words ("That was today" / "a few days ago").
4. **Inspection:** `__DEBUG.getBattleRecords()`, CLI `battles`, and the `battle_recorded` trace. `getLocationTraits` and CLI `traits` also report `bloodshed`.

## Evidence

- Unit tests: `battleRecord.test.ts` (14 arms, run through the real `resolveBattle`) and `phaseLocationTraits.test.ts` (7 new arms). The falsifying arm: twenty deaths and no record never mint the trait and write no counter.
- CLI, seed 42 medium, run to t182 (the run stops at the twilight phase change): 13 battle records across 4 places, and *Blood-soaked* held on 3 of them.
- Census (`census:location-traits`, 150 ticks):
  - seed 42: `blood_soaked` MOVES, 4 places;
  - seed 99: FLAT, peak 5 places, 6 mints, 2 releases.

  Read against the plan's kill criteria: it is minted on both seeds, and the peak of 5 places is far under a quarter of the settlements. `#combat`, `#loss` and `#fear` read 0% at both marked and unmarked places, because the encounters that resolve rarely carry those tags. That is the same corpus-reach limit Welcoming shows.
- The plan's "Crystalspire siege ~t158" no longer happens on seed 42: the world has drifted since the plan was written, so the CLI evidence names the places that did see battle instead.
