# THR-1417 — the step navigator's dots get a real identity

**Shipped 2026-09-06.** The encounter veil logged `Each child in a list should have
a unique "key" prop` on every open. The ticket, filed from the THR-1133 attended
pixel sweep, read that as `StepNavigator` mapping its dots without a key.

It was not. `StepNavigator` has keyed its dots on `step.stepId` since the component
was written, unchanged across three commits. The key *evaluated to* `undefined`:
`buildGateDutyEncounterStageModel` wrote `step.id` straight into a non-optional
`stepId`, and gate-duty steps carry no `id` — `ActionStep` declares neither `id`
nor `name`, the authored steps supply neither, and nothing stamps them at build
time. React words an undefined key exactly as it words an absent one, which is
what aimed the report at the consumer instead of the producer.

A three-arm reproduction settled it in one run: **well-formed → silent**,
**undefined → the reported message**, **duplicate → a different message**
(`Encountered two children with the same key`). Only the undefined arm matches
what the veil logged.

## What changed

- **Producer (the defect).** `buildGateDutyEncounterStageModel` now derives
  `stepId = step.id ?? \`step-${index}\`` and
  `stepLabel = step.name ?? \`Step ${index + 1}\`` once per step. Both fallbacks
  are the conventions already in use — the two sibling adapters key on
  `step-${index}`, and `buildSimpleEncounterStageModel` labels on `Step ${i + 1}`.
  Positional keys are correct here: the step list is fixed-length and never
  reordered, so index identity *is* step identity.
- **Consumer (defence).** `StepNavigator` keys on `step.stepId ?? \`step-${i}\``,
  so a future producer's omission cannot silently cost every dot its identity
  across re-renders.
- **`stepLabel` came with it, and that widened the ticket.** It is the same
  `undefined`-into-a-non-optional-field defect in the adjacent line of the same
  expression, and it renders: `EncounterVeil` prints `entry.stepLabel` as the
  replay header, so a gate-duty step used to open its replay under a blank
  heading. Fixing one and leaving the other would have shipped a known-broken
  sibling and required a second PR touching the same two lines.

## Why two layers, and why that is not belt-and-braces

The hazard with a defensive outer guard is that it masks falsification at the
owning layer. Both layers are therefore falsified independently, and the arms were
run rather than asserted: reverting the adapter fallbacks reds the producer test
**while the component test stays green** (proving the guard does not hide the
regression); reverting the component fallback reds only the component's
undefined-input test. Neither can cover for the other.

## Verification

`npm test` 1158 files / 19330 tests green. Typecheck ratchet **down 5** — the
repair removed type errors rather than adding them, since the two guarded locals
replace eight unchecked `step.id` / `step.name` reads. `npx vite build` clean.

Browser-verify went the `jsdom-render` route: `preview_start` is refused in
unattended runs, and the run hit the exact anti-pattern the gate doc names — the
route was decided at the capture rather than before claiming a UI-pillar ticket
(impediment #546, now 19 recurrences). The substitution asserts the rendered
faces: three distinct dot controls survive an undefined `stepId`, and the replay
header prints its label. That second assertion is scoped honestly in the test — it
proves the render, not the produced value, which the producer test owns.
