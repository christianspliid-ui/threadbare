**Escape and Space now do what the player meant.** Warm playtest round 3 found three faults. Escape did not put an armed card down while its tooltip was showing. Escape did not close a rival's hover card. Space started the clock and also pressed the focused Doom item. (1) The escape registry (`useEscapeLayer`) has two new layer options. A `transient` layer is a popup that comes from the pointer: tooltips and the hover card. A `throughTransient` layer is a mode the player is in: the armed card. One Escape closes every transient layer above the topmost solid layer. It runs that solid layer only if it is `throughTransient`, so one Escape now hides the tooltip and disarms the card. A tooltip over a dialog still closes alone (Law 23, `Overlay.test.tsx` unchanged). (2) `useRefRouter` registers the open hover card as a transient layer (`HOVER_CARD_ESCAPE_LABEL`, band `Z_BAND.tooltip`). (3) `useTopBarHotkeys` leaves Space alone when the event is `defaultPrevented` (the Doom item's own handler) or its target is a control with keyboard focus (`isActivatableTarget`, `:focus-visible`). A button that only has focus from a mouse click keeps the old behaviour: Space runs the clock. Tests: `escapeThroughTransient.thr2167.test.tsx`. Evidence: `Docs/evidence/thr-2167/disarmed-after-one-escape-1920.png`. Before Escape, the escape layers read `[tooltip 70, Armed card 65]`. After one Escape they read `[]` and `getArmedTargets()` returns null. (THR-2167, 2026-11-05)
