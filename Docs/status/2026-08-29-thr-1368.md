# THR-1368 — the ninth Reach leaves the world model

`src/data/world-model.json` shipped nine `reach.*` nodes against a canon of eight.
THR-1345 closed faction `reachWeights`, THR-1359 closed the rest of `src/`, and both
stopped at this boundary for the same reason: the display maps in `aftermathWords.ts`
and `codexRegistry.ts` are keyed by **world-model node suffix**, not by `ReachDomain`.
Deleting the rows while the node shipped would have made a live node paint as a raw
key; deleting the node while the rows shipped leaves the mismatch pointing the other
way. They had to move together, and now have.

## What moved

`reach.flesh` and its `rel.aligned-with` edge are deleted. The four `action.flesh.*`
nodes are **migrated, not deleted** — their `properties.reach` and `rel.belongs-to`
edges now point where `src/data/action-template-content.ts` has pointed all along:
heal → Gold, diagnose → Eye, cultivate → Gold, plague → Shadow. TB-075 Phase 1
redistributed these actions in TS and left `world-model.json` behind; this change
makes the two agree rather than inventing a new destination.

Their **ids keep the `flesh` string**, deliberately. `action-technical-effects.ts` and
`action-template-content.ts` both key on them, so the ids are stable identifiers, not
Reach membership — and the ticket explicitly warned off a lexical remap.

`trait.mastery.battle-hardened` boosted Iron and Flesh. Flesh there modelled veteran
hardiness — "3+ military engagements survived" — which canon routes to **Stone**
(endurance), so the modifier and its `rel.boosts` edge moved there rather than being
dropped.

`time` and `life` are **explicitly left**. They are display words for keys that never
had a `reach.*` node, already excluded from `TOOLTIP_BACKED_REACHES` so they offer no
dangling tooltip id. They are the other half of the nine-vs-eleven mismatch, not
residue of the retired Reach, and this ticket's predicate is Flesh.

## Two dead gates found while proving the Done-when

The Done-when asked for `npm run validate-model` green. It was green — because it was
a **no-op**. Its CLI block guarded on ``import.meta.url === `file://${argv[1]}` ``, which
cannot match on Windows (backslashed `argv[1]` vs `file:///C:/...`), or on a `.ts`
suffix the bundled `.mjs` does not carry. A controlled arm confirmed it: a dangling
edge to the deleted `reach.flesh` passed. The `/tmp/` outfile was broken the same way
— esbuild wrote `<cwd>/tmp/…` while node resolved `C:\tmp\…`.

`scripts/generate-vault.ts` carried the identical dead guard, which is *why* the real
vault still holds `Domains/reach.flesh.md` and an `Actions/Flesh/` folder: the
generator has not run on this platform.

Both are fixed by matching the entry **basename**. That choice is load-bearing, not
cosmetic: `generate-vault.ts` imports `validateWorldModel`, so esbuild inlines the
validator into that bundle too. An `import.meta.url` comparison — the first fix
attempted here — fires inside the vault generator's bundle and `process.exit`s it
before its own main runs. A basename distinguishes the two bundles; a URL cannot.

`playtest`'s `/tmp` path is fixed alongside `validate-model`'s, being the same
one-line defect in the same file.

## Evidence

`validate-model` now genuinely runs, and the arm proves it has teeth: the dangling
edge fails it (exit 1) and the shipped tree passes (exit 0, 35 pre-existing orphan
warnings). `generate-vault --dry-run` plans 252 files with no `Actions/Flesh/` and no
`Domains/reach.flesh.md`; the four action pages land under Gold, Eye and Shadow.
`Domains` and `Actions` are owned folders, wiped before write, so the stale vault
pages clear on the next real run.

`worldModel.test.ts` asserted `toHaveLength(9)` and failed, which is the change being
observed. It now pins the exact eight-name set plus a negative on `reach.flesh` — a
length check alone passes a rename, and `toContain` alone passes a tenth Reach.
`tooltipResolver.test.ts`'s `resolves reach.flesh` is **inverted** rather than deleted:
the retirement is the thing under test, and a removed case would prove nothing.
