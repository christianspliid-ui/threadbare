# 2026-10-14 — THR-1927: heavy tests get CI-sized time budgets

**Ticket:** [THR-1927](https://linear.app/threadbare/issue/THR-1927). `heavy-tests.yml` on `main` failed 16 of 18 runs from 2026-10-12 20:27Z. Every failure was a timeout and no assertion failed. Engine pillar is test budgets only. Content N/A (no authored text). UI N/A (no rendered surface).

- **Lane default.** `vitest.config.ts` gives the `heavy` project `testTimeout: HEAVY_DEFAULT_TEST_TIMEOUT_MS` (60 s). Every heavy file builds a world and runs ticks, so a test left on vitest's 5 s default is a latent red main on the shared CI runner. This covers the ticket's sweep step once for the whole lane, not file by file.
- **`debugTickBatch.test.ts`.** New `SHORT_BATCH_TIMEOUT_MS` (60 s) on the five tests that run real ticks. The 10-tick trace test took about 5.9 s on CI against 5 s.
- **`doomIdentityMilestones.test.ts`.** `MILESTONE_SMOKE_TIMEOUT_MS` goes from 15 s to 60 s. The file took 77 s for 8 tests on CI run 38592965062, and the 40-tick persistence test takes 9.8 s solo. This supersedes PR #2367's 45 s (the THR-1839 duplicate build).
- **`chapterArchive.test.ts`.** The 26-tick archive run moves from a bare 20 s to `ARCHIVE_TICK_RUN_TIMEOUT_MS` (60 s). The sweep found it was the only other short explicit budget in the 49 heavy files.
- **Not made cheaper.** Each test's tick count is what it asserts: 10 ticks for one trace per call, and 30 + 10 ticks for the 0.10 milestone crossing and then its persistence.
