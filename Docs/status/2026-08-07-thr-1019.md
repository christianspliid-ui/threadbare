**Browser-verify got a sanctioned lever for the game's own interrupts (THR-1019, 2026-08-07).** The Definition of Done makes browser evidence binary, and the interrupt design — correctly, per THR-934, THR-1005 and THR-1017 — keeps making beats *more* interruptive. The two needs collided seven times in one week (impediments #385, #427, #445, #446, #447, #453, #455), each run spending 5–15 minutes rediscovering the same hand-rolled loop: find `[role="dialog"]` with `aria-label^="Ascendant beat"`, click its single button, wait, repeat. `window.__DEBUG.dismissBeats()` and `suppressBeats(true)` replace it.

**The load-bearing detail is the one the hand-rolled loop got wrong, and it is not the clicking.** `resolvePendingBeat` *refuses* a `selection` beat that arrives without a choice — it returns `resolved: false` and leaves `ascendantBeats.pending` exactly where it was, with the message *"needs a choice from [...]"*. So a dismissal that merely closes the modal silently no-ops on precisely the beats that are hardest to click past, which is what "fragile against beats with multiple choices" meant in the ticket. `selectDefaultBeatChoice` picks the definition's first grant for a `selection` beat and `undefined` for every other kind, where the engine grants the full set and ignores the argument. The regression test is an A/B on that single decision: the naive arm asserts the beat *survives*, the helper arm asserts it retires with exactly the chosen grant. Falsified against a deliberately regressed helper — 2 of 10 tests go red, including the retire arm — so neither arm can pass vacuously.

**Routing, not clicking.** Each surface goes through its own React handler and therefore through the engine's beat state machine, so the lever holds regardless of which component renders the beat and cannot drift the way a DOM selector does. The drain runs in passes with a re-render between them, because a successor beat only becomes observable after React commits — a loop inside one closure reads stale state and misses the chain. Bounded by `DEBUG_DISMISS_BEATS_MAX_PASSES` (12); hitting the bound returns `exhausted: true` rather than throwing (NFP #4), and one surface whose handler throws is recorded and stepped past rather than stranding the rest.

**Scope is deliberately narrow, and that is the "must not weaken the game" boundary.** It clears ascendant beats (entered modal + offer banner), journey vignettes, story beats and premonitions. It does **not** touch the encounter veil, Meet-The-First, choice sets, emergence dilemmas or divine receipts — those are what a verification run is normally there to observe, and clearing them would destroy the capture it came for. A test pins both halves of that membership so the set cannot quietly widen. Suppression is off by default, and `suppressBeats(false)` restores normal behavior — verified live, with a beat fired afterwards interrupting exactly as before.

**Measured on the ticket's own route** (`?view=game&seeded&size=medium&spawn=encounter.slice.unsafe_bridge`, 1920×1080). The negative case first: with only the veil open, `dismissBeats()` returned `dismissed: 0` and left it standing. Then `beat.spine.a_path_opens` — a three-choice selection beat — was fired over the veil, reproducing #445 exactly. One call returned `dismissed: 3, passes: 4, exhausted: false, remaining: []` in **29 ms**: the beat chained twice more on resolution, which is #453's "dismissing one beat advances to the next", and the drain caught all three while the veil survived intact. With `suppressBeats(true)` two further beats were fired and *neither ever surfaced*; the encounter was then committed and driven with `__DEBUG.tick(12)` (`stoppedReason: 'completed'`) straight to its **Aftermath**, no interrupt intervening. That is the ticket's first Done-when end to end, using only `__DEBUG` calls.

**Note for whoever reads the captures:** this change composes no new UI. The surfaces exercised — beat modal, veil, aftermath — are pre-existing and unmodified; the change adds a dev-only bridge path and is tree-shaken in prod. The Law 37 chrome THR-1003 shipped is visible holding across the veil→aftermath pair in the captures (same title, same subject strip), and the aftermath's essence readout renders a clean integer rather than THR-1006's raw float on this route.
