# THR-1382 — the design-staging bound now counts liveness, not occupancy

**Shipped 2026-09-02.** `ORCH_MAX_IN_DESIGN` is `1`, and `In Design` had held two items — THR-1002 (unassigned, 14 days) and THR-790 (assigned to Christian, 17 days) — for two full retro windows. Because the bound counted *occupancy*, the orchestrator's T2 design-staging tier was barred every run ("jammed for twenty-one runs straight"), and nothing in the machine could clear it: the stale-claim sweep was hard-scoped to `In Dev`, so no timeout of any kind watched `In Design`. The build shelf reached zero on 2026-08-30 and was still zero on 09-01.

## What shipped

**The predicate.** An `In Design` issue is excluded from the bound when it carries `Parked`, **or** when it has no assignee and no activity for more than `ORCH_IN_DESIGN_STALE_DAYS` (7). It is stated once in `.claude/skills/orchestrator/SKILL.md` § *Which `In Design` items count*, mirrored in `Docs/ops/scheduled-task-prompts/tb-orchestrator.md` (the copy that actually runs), and implemented executably as `classifyInDesignItem` in `scripts/stale-claim-sweep/index.ts` — with each surface pointing at the others, so the three cannot drift silently.

The two stale arms are deliberately asymmetric. Excluding an *unassigned* dead item is the repair. An *assigned* stale item is **warned but still counted**, because a bound that silently stopped counting a person's staged work would let the lane stage a second item on top of it; its exit is `Parked`, a human's deliberate act, which the first arm then honours.

**The sweep gained a fourth pass, and it is the only one that cannot write.** It classifies every occupant of the column and posts a staleness warning naming the age and the right exit — both exits for an unassigned item, `Parked` only for an assigned one, never implying demotion. It never touches state, assignee, or labels. `In Design` has no claim to release, and an unassigned item there is a *stage*, not a park, so the `In Dev` release semantics must not be copied across — that inversion is exactly what THR-1283 had to undo.

**T3 now reports the split**, so the staging budget's state lands in a run report rather than only in a comment nobody reads. A `0 live` line is printed deliberately: it is the signal that T2 is free, and its absence is indistinguishable from a tier that did not run.

## The finding that would have shipped this as a no-op

THR-1382 proposed `updatedAt` as the activity signal. It is wrong for this column, and the proof arrived while implementing it: **Linear bumps `updatedAt` when an issue is merely *referenced* by another issue's relations.** THR-1382 was filed at `2026-09-02T09:22:57.769Z` and cross-linked THR-1002 and THR-790 as related. Both came back from the API carrying that same timestamp, to the millisecond — 14 and 17 days of not being touched, erased by the act of filing the complaint about them.

An `updatedAt` predicate would have classified both as `live` on day one and changed nothing, while every test built on a synthetic fixture passed. Activity is instead the newest of the two signals only a human working the issue can produce: the newest comment, and the newest state transition — which, for an issue *currently* in `In Design`, is its entry into the column. That is what makes the numbers match the board.

The fixtures now set `updatedAt` to *now* while the age is carried by the transition, so the two signals disagree maximally and only the correct one produces the expected verdict. A fixture that let them agree would verify a fiction.

## What this does not do, stated plainly

**T2 is not unblocked yet, and cannot be by this ticket.** With THR-790 still assigned it counts against a bound of `1`, so staging stays barred until someone applies `Parked` to it — which the sweep's next run now asks for by name. The ticket's own item 5 forbids touching THR-1002/THR-790, and its item 3 sets `Parked` as THR-790's correct shape; mutating it is the grooming lane's remit and Christian's call. THR-1002, the genuinely dead one, stops barring immediately. So the ticket's claim that items 1–3 make both "stop blocking staging on their own" holds for one of the two, not both — the assigned one needs one human act, by design.
