# THR-1049 — the third limbo tree, closed by deletion

**Shipped 2026-08-17.** Five prototype surfaces under `src/components/Game/Encounter/` had
been mounted only in `StyleGuide.tsx` since Phase C1/C2/D2. THR-1041 was asked to wire or
retire them, reused their *patterns* in the live veil, and left the components themselves
untouched — deliberately, and on the record. This ticket answered the fork.

## The verdict: displaced, not awaiting wiring

The ticket allowed three answers per component — built ahead of its wiring (file a wiring
ticket naming the producer), displaced by the encounter-stage rewrite (delete with its
test), or wanted-but-blocked-on-content. **All five came back displaced**, and in each case
the displacing surface was already shipped and player-reachable:

| Prototype | Live surface that overtook it | Evidence |
|---|---|---|
| `EncounterScreen` (+ `EiraHeroPanel`, `CapabilityStrip`) | `EncounterVeil`, mounted in `GameView.tsx` | The shell is a full-screen three-zone grid; the encounter surface that shipped is a modal veil. The promised "full data wiring in Phase F2" never came because the design moved. |
| `CastRail` / `CastTile` | `CastStrip` inside `EncounterVeil.tsx` (THR-1041) | THR-1041 borrowed the uppercase section label, the role line and the reduced-opacity treatment, and **rejected** `CastTileData` because `sphereLabel` / `sceneDisposition` / `relationshipToHer` / `fallbackSentiment` have no producer in the live stage model. |
| `OutcomeForecastBand` | `NudgePhaseShell`'s forecast readout | `buildNudgePhaseModel` → `useNudgeHand` → `hand.forecast.tier` / `.word`. The live path renders the same qualitative tier the prototype was built to render, and `NudgePhaseShell` is mounted from `EncounterVeil`, `BondBeat` and `FormativeTestBeat`. |
| `EffectRegistration/` (10 landings) | Consequence chips in `EncounterVeil.tsx` (THR-971 / THR-1082) | The chips state the same registrations — kind, category, tone, icon tile — without animation. The landings' props are authored phrase pairs (`oldPhrase` / `newPhrase` / `tail`, e.g. *"iron · he marks her now"*) that nothing produces. |

The audit's own framing anticipated a different answer for one of them: `OutcomeForecastBand`
was listed among four "resolve-but-never-render" blocks, with the fate-image band ladder
called content-less, so its verdict looked likely to be *wanted, blocked on content*. It was
not. The band ladder gap is real and stands, but it belongs to the **fate image** rows, not
to this component — the forecast this component would draw has had a live producer and a
live renderer since WS2.

## Why the deletion reaches past the five named files

`EiraHeroPanel` and `CapabilityStrip` were not in the ticket's scope list. They are in the
diff because they are the exclusive dependency closure of `EncounterScreen`: `EiraHeroPanel`
had two importers (`EncounterScreen` and the styleguide section that mounts it), and
`CapabilityStrip` had exactly one (`EiraHeroPanel`). Deleting the shell and leaving those two
behind would have converted them from styleguide-only to test-only — creating the limbo this
ticket exists to end, one level down. `useEffectSequencing` is in the diff for the same
reason.

## What was deliberately *not* pruned

Two orphans are left standing, each recorded rather than folded in:

- **`playRegistrationCue`** (+ its `ENCOUNTER_REGISTRATION_*` semitone table) lost its only
  caller when `EffectRegistration/_shared.tsx` went. The audio subsystem is a separate
  cluster with its own tests, and whether to keep the cue for a future registration surface
  is a judgment, not a consequence of this deletion.
- **`AFTERMATH_ANIMATION_SETTLE_MS`** was already unreferenced at this ticket's base commit
  (`git grep AFTERMATH_ANIMATION_SETTLE_MS c8d69574 -- src` finds nothing outside its own
  declaration), so it is a pre-existing orphan, not one this pass created.

Both, plus the six modules the census found that this ticket's scope did not name
(`AscendantHand`, `ThreadOverlay`, `DetailPage/openDetailPage`, `EncounterChoiceCard`,
`MoralAxisTilt`, `useThreadReveal`), are filed as
[THR-1167](https://linear.app/threadbare/issue/THR-1167) with the census attached.

`AscendantHand` deserves its own line: it has **zero** non-test importers — not even the
styleguide — and its test survived this pass, because the shared
`AscendantHandCastRail.test.tsx` was split rather than deleted (the CastRail half removed,
the four AscendantHand tests kept and the file renamed). That leaves a green snapshot suite
on a component nothing mounts, which is the same pathology this ticket cleaned up. It is
named explicitly in THR-1167 rather than left for a grep to rediscover.

## Verification

Full suite **1035 files / 16,658 tests green**; typecheck ratchet **down 12** (3175 → 3163),
baseline refreshed; `vite build` clean. The three kept AscendantHand snapshots were rewritten
under the new describe name and diff as **key renames only** — no rendered output changed,
which is the evidence that splitting the test did not alter what it asserts.

Law 29 is unaffected: `styleguideSync.test.ts` keys on `src/components/shared/`, and none of
the deleted components were shared primitives, so removing their styleguide sections does not
drop a required entry.

**Browser-verify exempt: deletion-only change to components with no live mount.** Every
deleted module's sole non-test importer was `StyleGuide.tsx` or another deleted module — the
census is in the closeout comment — so no player-facing surface changes. `preview_start` was
refused in this unattended run in any case (impediment #546/#574 family).
