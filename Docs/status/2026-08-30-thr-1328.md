# 2026-08-30 — THR-1328 · Three named closeout flakes fixed at source, one of them misdiagnosed

The 2026-08-28 retro named three tests whose reds were costing ~15–40 min/week of closeout triage and had blocked an armed PR for 41 minutes. All three are fixed. Two came out differently than the ticket predicted, and the difference is the point.

**`worktree-write-guard` — not a path bug, a wrong-interpreter bug.** The ticket (and impediment #756) read the `/bin/bash: C:UserschrisDevProjectsThe…` exit-127 signature as backslashes being eaten by bash, and prescribed a POSIX path conversion. The path was never the cause. `bash` on a **PowerShell** PATH resolves to `C:\Windows\System32\bash.exe` — the **WSL** launcher, which ships with Windows and sits ahead of Git Bash — and WSL resolves paths against a Linux root, so it cannot open a `C:\…` script in any spelling. Under the Bash tool (Git Bash first) the *same commit* passed 9/9, which is precisely why CI stayed green while every local run went red. The test now derives Git Bash from `git --exec-path` and spawns that; it skips loudly if no usable bash exists. Verified under the exact PowerShell PATH that reproduced the failure: **9/9 red → 9/9 green, then 10/10 consecutive runs clean.** A POSIX conversion alone would have fixed nothing.

**`coastline-integration` — the assertion was measuring GC, not the coastline.** Impediment #871 recorded a 516.77 ms overshoot against the 500 ms gate as a 3.4% shared-runner excursion and deliberately left the threshold unwidened pending a second occurrence. Measured here on an idle machine, standalone, 15 samples × 3 runs: median **101.54 / 100.64 / 108.69 ms**, max **528.02 / 525.60 / 618.24 ms**. The distribution is tight at ~100 ms with a long tail clearing 500 ms in roughly 2 of every 15 samples — so the single-sample form was failing ~13% of the time *before any CI contention was applied at all*. The shared runner was never the cause and a wider threshold was never the fix. The budget is unchanged at 500 ms; it now asserts the **median of 7 runs**. That respects the standing objection in `src/testing/testTimeouts.ts` — which names this exact case as the thing its hang-detector constants must not silence, because raising it would hide what it exists to measure — while making a single excursion, however large, structurally unable to fail it. A genuine regression still moves the median.

**`impediment-id-allocation` — the prescribed fix, applied, plus the siblings item 1 asked for.** The git-shelling describe and its hook now carry `SUBPROCESS_TEST_TIMEOUT_MS` (30 s) instead of vitest's 5000 ms default; `check-wiki-freshness` already named this file as the sibling its own per-repo fixture starved. Two more untimed shell-out siblings were swept in under the same item: `vision-audit`'s `CLI exit codes` (which spawns `node --experimental-strip-types` per case — the most expensive shell-out shape in `scripts/__tests__/`) and `impediment-dashboard-artifact`'s `git ls-files` block.

Scope held at three files per the coordination block's recorded answer — `debugTickBatch` was taken separately by THR-1352 and is not re-scoped here. The triage protocol in `Docs/ops/sandbox-limitations.md` now records that these three stopped being live examples, with the warning that a red in them is henceforth more likely real; the doctrine note in `testTimeouts.ts` keeps its rule and adds the general form: **when the signal is real but the sampling is not, fix the sampling.**
