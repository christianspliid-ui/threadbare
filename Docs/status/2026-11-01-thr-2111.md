# THR-2111 — a faction holds its members in regard

**Shipped 2026-11-01.** UI Visual Overhaul — Design System v1. Found by the THR-2098 review gate.

**What changed.** The faction page's "Reputations they hold" row read `faction.properties.reputations`. Nothing in `src/` writes that property, so every live faction showed the quiet line, "They hold no one in regard yet." The row now reads the faction's real regard: each member's `member_of.reputation`, which joining a faction, faction encounters and decay already move. Members show most-regarded first, at most eight, as chips. Each chip carries the member's name, the shared reputation word (distrusted, unknown, accepted, respected, revered) and a link to their page. Respected and up reads warm, distrusted reads cold, and both thresholds are named constants. Memberships with no reputation, such as army → faction, are skipped.

**Executor decisions.** Option 1 of the ticket: feed the row from the live store rather than retire it. "How they hold her" still reads the same unwritten property for the god and keeps its fallback prose. The god is never a `member_of` source, so its standing needs a different source. That is out of this ticket's scope.

**Evidence.** A new test in `artLedDressing.thr2098.test.ts` builds memberships with the real `joinFaction` and `applyFactionReputationGain`. It asserts the order, the words, the sentiments and the links. The faction test in `detailPageGenerator.test.ts` now raises standing through the real writer. Live: on seed 42 medium at tick 200, 18 of 78 faction pages show a non-empty row through `generateDetailPage` (for example, "hold of Witness Skyfield: Huwhu · revered"). `npm run gate` passes.
