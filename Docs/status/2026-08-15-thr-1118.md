# THR-1118 — the ascendant bar's hover tooltips come from the one registry, and two raw keys leave the surface

**Date:** 2026-08-15 · **Lane:** `tb-opus-pickup` · **Worktree:** `infallible-wozniak-e65e78` · **Issue:** [THR-1118](https://linear.app/threadbare/issue/THR-1118)

## What shipped

Five hover panels in `src/components/Game/ascendant-bar/` moved off two bespoke implementations onto the shared `Tooltip` primitive, and both Law 14 leaks were closed.

| Site | Was | Now |
| -- | -- | -- |
| `IdentityStrip` portrait | `HoveredTerm` + `SPHERE_COPY` | `Tooltip id={\`sphere.${primarySphere}\`}` |
| `IdentityStrip` name | inline copy in JSX | `Tooltip id="ui.ascendant_name"` |
| `IdentityStrip` archetype | `ARCHETYPE_COPY` lookup | `Tooltip id="ui.ascendant_archetype"` |

`resolveTooltip` gained a `quintessence.*` prefix routing to `BAND_TOOLTIP` — Law 3's "extend the resolver" rather than a second lookup path. `ui-content.ts` gained `ui.ascendant_name` and `ui.ascendant_archetype`. `useDelayedHover`, `TermTooltip`, `HoveredTerm`, the chip's hand-rolled timer, `.chipTooltip` and its `fadeInChip` keyframes are all deleted.

## Two findings that corrected the ticket's premise

The ticket assumed the archetype title was already an `archetype.*` concept and that `ARCHETYPE_COPY` was live copy. Neither holds, and both were checked before writing code rather than assumed from the ticket.

**`ARCHETYPE_COPY` was dead on every run the game has ever had.** It was keyed `Witness` / `Shaper` / `Keeper` / `Breaker` and read as `ARCHETYPE_COPY[identity.archetypeTitle]`. An ascendant's `archetypeTitle` comes from `ARCHETYPE_TITLES` in `ascendant-content.ts` — 96 generated, sphere-keyed flavour strings, every one prefixed "The " (`The Unblinking`, `The Thread-Singer`), none of them one of those four words. The lookup returned `undefined` always and the component silently rendered its generic fallback. Deleted, with the reasoning kept at the site so it is not re-added.

**Routing the title through `archetype.*` would have been a dead link that looks live** (Law 21's named anti-pattern). That prefix resolves via `getArchetype`, which searches `NARRATIVE_ARCHETYPES` — `tragic_hero`, `fallen_mentor` — a *different* vocabulary belonging to agents, not to ascendant titles. `archetype.The Unblinking` resolves to `null`. So the concept behind the title is registered as `ui.ascendant_archetype` and the generated title stays the hover trigger's own text. A test pins both halves of that reasoning, so a later "fix" toward the more canonical-looking id fails and says why.

## Law 14 — the two raw keys

The sphere eyebrow (`Sphere · ${identity.primarySphere}`, rendering `mind` / `entropy`) had no equivalent on the shared primitive and went with the bespoke panel it belonged to, so the enum is gone by construction rather than by patch.

`HooksBlock`'s `p.name ?? p.label ?? node.id` fall-through is replaced by `resolveChipLabel`, which returns a bucket-keyed plain-English stand-in (`An unnamed mark` / `clue` / `vow`) and warns once per node id. The bucket had to move ahead of the label in `extractChips` — the fallback names *what kind of thing* it is, so it cannot be resolved before the row is known. The warn is what makes this a fallback rather than a cover-up: the chip stays readable for the player while the missing name stays findable for us.

## Tests

`ascendantBarTooltipConformance.test.tsx` — 10 assertions, and the Law 14 absence checks carry falsification guards, since "the bad string is gone" is worthless against a surface that never rendered. The enum test asserts the sphere tooltip is *open* first, asserts the surface has text at all, and asserts the forbidden pattern matches the string it exists to forbid.

`hoverTimerCleanup.test.tsx` (THR-1108) retargeted rather than deleted: the hand-rolled timers it pinned are gone and the guarantee now lives in `Tooltip`'s own unmount cleanup, but the tests assert it on the **composed surface**, so a hand-rolled hover re-introduced here fails there. Its premise assertions earned their keep across the rewrite — the shared primitive listens on `onPointerEnter`, not `onMouseEnter`, so the old `fireEvent.mouseEnter` calls arm nothing, and without the premise guards all four unmount tests would have passed green and vacuous.

`tooltipValidation.test.ts` gained `quintessence` to its valid-prefix set, the three sampled band ids, and a test 3b walking all six bands for the Law 18 ≤200-char gate. Test 3 iterates `UI_TOOLTIPS` only, so copy behind a non-`ui.*` prefix is outside it by construction — which is how this copy sat unmeasured while inline. Routing copy into the registry only puts it under the gate if the gate is told to look.

## Browser-verify: jsdom substitution, and here it is *not* sufficient

`preview_start` was refused with the standing unattended string, which also shuts #499's Playwright route. Logged as impediment #597 at #580/#593/#596's **inadequate** pole, not #586's adequate one.

This diff repositions panels: the old ones were absolutely positioned inside their trigger (fixed 260px/220px, z-40 and z-50, tinted left border); the primitive portals to `document.body`, positions `fixed` with viewport-aware flipping and edge clamping, caps at 280px, and sits at z-70+. Placement, width, chrome and stacking all changed, so overflow, flip behaviour, edge clamping and the viewport contract are reachable by construction. The 14 jsdom assertions prove every face is present and wired; they can say nothing about where any of it lands. The pixel pass is filed as [THR-1127](https://linear.app/threadbare/issue/THR-1127) per THR-1109's precedent rather than left to evaporate.
