# THR-1086 — The Apotheosis converts off `authoredChoices` (WS5 complete)

**Shipped 2026-08-11.** Implements the THR-866 design decision
([plan doc](../plans/2026-08-11-thr-866-apotheosis-nudge-conversion.md)). Closes the
Nudge Model's WS5 conversion: **no shipped encounter authors `authoredChoices` any more.**

## What changed

`encounter.apotheosis.ascension` — the Influence capstone, and the last place in the game
where the god pressed a button and received an ending — is now a `decidedBy` pole fork on
`sacrifice_survival` (Star's bound value pair). The player leans with a seven-card hand on
the threshold step; the **mortal** answers Martyr or Survivor; the dice decide how it goes.

Both steps had `difficulty: 0`, justified in the file as *"the choice is the point, not a
roll"*. Once the choice is not the player's that justification is spent, so the roll now
carries the branch the original director verdict named and the first implementation could
not afford: **"unmade"** — a mortal frame that opens and does not hold. Four endings per
pole (`critical_success` / `success_at_cost` / `failure` / `critical_failure`) layer over
a base `success` ending via `byOutcome` (THR-969).

## The two calls worth recording

**Where the grant sits.** The ticket left this open between the Martyr variant's upper-band
`byOutcome.reactions` and that override's `changes`. Reading the types settles it against
both: `EncounterAftermathChange` carries no `effects` field, so "promote to `changes`"
grants nothing, and a reaction is a click the player would never decline in front of an
irreversible world-write. It rides the Martyr step's **`successMetadata.effects`**
(THR-783) — same dispatcher, same vocabulary, same tracing, no click. This also makes the
gating exact: the split is `isStepSuccess`, so the lower bands are the unmade ending by
construction, and `applyAftermathOutcomeBand` cannot drop the grant by replacing
`reactions` wholesale.

**`fail_action` on both pole steps.** An unmade apotheosis *is* a failed action. Without
it `computeFinalActionOutcome` folds a failed final step into `success_at_cost`, which
would have made the `failure` band unreachable and `?outcome=failure` diverge.

## One thing the verification caught

Five consecutive live draws all landed Survivor — which is exactly what a fork that never
fires looks like, because `fallback` *is* the Survivor variant and
`fallback: { ...WITHHOLD_AFTERMATH }` renders byte-identical prose. No browser observation
can tell those apart on any number of draws. `src/engine/__tests__/apotheosisForkReachability.test.ts`
settles it against the real engine by reading the recorded `choiceId`: both poles reachable
on conviction, both reachable by committed cards from neutral, each reaching its own ending.
The skew was population, not a defect — but the schema could not have told us that.
