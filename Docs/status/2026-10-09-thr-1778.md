# 2026-10-09 — THR-1778: "Return to the world" closes the aftermath with one click

**Ticket:** [THR-1778](https://linear.app/threadbare/issue/THR-1778) · **Found by:** warm playtest round 1, 3/3 testers (and 2/3 in the dry run)

Closing a chapter's aftermath no longer bounces the player back into the same aftermath.

- **Cause.** "Return to the world" resolved only the notification on screen. The chapter's final step notification is held back only while its aftermath is unresolved (THR-1005's `isStepNotificationSupersededByAftermath`). Once the aftermath resolved, the step notification became openable again. The auto-open scan then reopened it against the resolved action, which shows the aftermath again.
- **Fix.** `resolveNotificationsOnAftermathAcknowledge` (`src/components/Game/encounterNotificationRuntime.ts`) resolves the acknowledged record, every record pinned to the same action, and every unpinned record of the same agent and encounter. When the acknowledged record carries no `actionId`, it uses the veil's action id. A record pinned to a *different* action stays pending, which keeps the THR-1777 rule.

**Evidence.** Four unit tests in `GameView-unifiedNotifications.test.ts`: the bounce is reproduced when only the aftermath resolves, and the queue is empty after acknowledge. In the browser at 1920×1080 on `?firstunmet&spawn=tg.senior.jewel_heist`, one click on "Return to the world" left `getOpenModals()` at `[]` across 8 further ticks, with all four heist records resolved.
