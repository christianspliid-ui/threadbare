# THR-1297 slice 4 — the work namer, christening & the failure register

**Shipped 2026-08-27.** Fourth of six slices on plan doc 2/6 of Proactive Agent Actions
([plan doc](https://github.com/christianspliid-ui/threadbare/blob/main/Docs/plans/2026-08-27-thr-1297-action-library-works-holdings-naming.md) §5).
Slices 1–3 landed the group discriminator, the kind registry + motive gate, and the `owns`
edge; this one gives a finished work its name.

## What changed

**One namer, two grammars.** `groups/groupNames.ts` already *was* the ruled design — bound
entities, additive flavor lexicons, eager rendering, a correct `possessive()` — so "never a
second namer" is settled by moving its primitives to `src/engine/naming/workNames.ts` and
making it the first caller. The company **grammar** deliberately did not move: folding
companies onto the work patterns would have re-rolled every company name in every existing
world, a player-facing rename with no ticket behind it. A differential golden against a
byte-copy of the old implementation pins that they did not shift.

**Christening.** A completed undertaking earns a proper name assembled from what it touched
— the bound ground, the leading reach of the work, the founder's culture — replacing the
working possessive it wore while underway. Live on seed 42: 93 christenings in 150 ticks,
producing *The Deepset Granary of Thornhaven*, *Miriel's Surveyed Research Circle*,
*Elior's Auspice Shrine*. Only nodes the undertaking **created** are renamed; the plan's
"created/target" was narrowed because renaming the *target* would rename a pre-existing
settlement because someone built a warehouse in it.

**Names outlive owners.** `transferHolding` never renames, `razeHolding` retires the name
into the site's `nameEchoes` (where "The Second Saltway" comes from), and
`refreshHoldingFaceNames` closes the stale-face gap slice 3's checkpoint predicted — a face
minted at grant time kept the pre-christening name.

**The failure register.** A *visible* failure writes a named scar onto its site
("Corran's Folly"); a clean one writes nothing. Structurally unreachable from the CLI — a
CLI world has no thread edges, so no undertaking is ever watched — so it is proven by unit
test rather than by asserting an absence in a 167-tick run and calling that evidence.

**The trailing-s bug, fixed at the renderer.** Seven shipped templates spell `{actor}'s`
inline and the old renderer substituted the raw name, so "Silas" became "Silas's". Matching
`{actor}'s` as a unit fixes every template at once with no content edit; the two legacy
hand-rolled copies of that string now share the one renderer.

## Three findings the live run caught and the unit tests could not

1. **"The StandingHouse"** — a concatenating `{root}{noun}` pattern, mush because every root
   is a capitalised standalone adjective. Every unit test passed: they asserted non-blank and
   token-free, which "StandingHouse" is. Removed, and a legibility guard over a 200-name
   sample now falsifies at 55 offenders.
2. **Christening lost the kind.** "Rill's Research Circle at Ardenmor Keep" became "The
   Ardenmor Keep House", because `createSublocation` stamps `sublocationTypeId` while the
   reader looked for the settlement-shaped `locationSubtype`. A generic family noun on a
   specific thing is a clarity regression, so the thing's own noun now rides the earned
   grammar: *The Deepset Workshop of Ardenmor Keep*.
3. **A separate christening trace evicted another category's samples.** It reddened
   `decisionBoardLiveness`'s frozen-desire pin on a diff authoring no `motivations` at all —
   the test drains a per-tick ring buffer that overflows (impediment #822's class), so extra
   volume changes which samples survive. The name now rides the completion trace that
   already fires, which is what the plan's tracing section asked for.
