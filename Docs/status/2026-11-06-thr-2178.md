# THR-2178 — Chapters say whether they wait for the god

**Shipped 2026-11-06.** Warm playtest · round 3. Decided by the design lane on THR-2174 (veto window closed 2026-11-05T23:45Z).

1. **One predicate.** `chapterOffersPlayerMove(template, choiceHistory?)` in `engine/playerStepHold.ts` is true when any step, with branches followed (or their fallback when there is no history), passes `stepOffersPlayerMove`, the predicate the hold already reads. It fails soft to `true`. `chapterWaitWord(graph, actorId, template, choiceHistory?)` returns `waits` or `theirs_alone` on a live "Asks you" thread. It returns nothing for a "Lives on" or dormant thread, an unthreaded mortal, a routine template or a missing one. With the THR-2140 skip switched off, every chapter reads `waits`.
2. **The word, before.** The live chapter's Ledger row carries `waitWord` (`LedgerRow` → `LedgerRailChapterRow`). The Chronicle's Ledger tab, the Chapter Ledger reader and the Stage header draw it after the title, through one component (`components/Game/ChapterWaitWord.tsx`): **Waits for you** in gold, **Theirs alone** in the secondary tone. The copy and hover text live in the tooltip registry as `ui.chapter.waits` and `ui.chapter.theirs_alone`. Only live rows carry the word; a resolved chapter says it in its Aftermath instead.
3. **The line, after.** `EncounterStageAftermathModel.aloneLine` is set only when the chapter's word is `theirs_alone`. The Aftermath shows it above the overview: "This chapter was {name}'s alone. Nothing in it waited on your hand." (`CHAPTER_ALONE_AFTERMATH_LINE`). It never shows on a chapter where a step offered a move.
4. **The Oracle probe: no hold bug.** On `?view=game&seeded&size=medium&spawn=reputation.eye.the_oracle_consulted`, The Oracle Consulted opens on step 0 with a hand, the clock held by the Stage (`getClockHold` → `held: true, holder: "The Oracle Consulted"`). After the Stage was set down (Escape), `await __DEBUG.getPlayerHolds()` read `{ templateId: "reputation.eye.the_oracle_consulted", stepIndex: 0, live: true }`. After `__DEBUG.tick(30)` it still read `stepIndex: 0, heldTicks: 30, live: true`. Step 0 holds, so the tester's report is a misreading and no code was added. Probe trap for the next reader: `__DEBUG.tick(n)` runs past the Stage's *clock* hold, so ticking with the Stage still open advances the chapter. Only `playerHold`, which is set when the Stage is set down, models a player who looked away.

**Evidence (1920×1080):** `Docs/evidence/thr-2178/` has three captures: the Stage header reading "The Healer's Oath · Theirs alone", the Aftermath opening with the alone line, and the Ledger tab row reading "Theirs alone". The Oracle row read "Waits for you" (DOM `[data-testid=chapter-wait-word]`), and `getView('ledgerRail')` gave `rows[0].waitWord === 'theirs_alone'` for The Healer's Oath. Heal the Sick itself is not a Ledger chapter (`isEncounterAction` is false), so `encounter.healers_oath` stands in as the Heal-the-Sick-shaped chapter.
