# THR-2233 — no journey vision is lost

**Shipped 2026-11-15.** Encounter Experience · decided by the design lane on THR-2232.

- **Journey beats catch up.** `shouldBeatFire` (`src/engine/journeyEngine.ts`) now fires the current phase's next unplayed beat whenever the Doom has *reached* its threshold, not only on the tick it was crossed. A Road of Trials crossing that landed while a vision was still waiting used to be lost for good (3 of 6 measured runs lost one); it now fires on the first free tick. One beat per tick, in order; the phase's `beatHistory` count stays the index, so nothing fires twice; a beat whose phase has ended is not caught up.
- **The Ordeal force-fire runs before the catch-up**, so the Ordeal always precedes the Return. As a result, once a force-fired Ordeal is answered, the Return now follows on the next tick (before, a First whose Ordeal was forced never got a Return vision).
- **Evidence.** New tests in `journeyEngine.test.ts` (pending-vision crossing, two-threshold jump, ended-phase handover, reached-not-crossed) fail on the old code and pass now. `npm run gate`: PASS (test, typecheck, build, CLI smoke).
- **Not done here:** the six-run probe re-measure (about 20 min per run, over the lane's command cap) → THR-2239.
