# THR-1212 slice 6 — the `followOnTags` retirement (and the close of the ticket)

**The last slice of the shared-anchor-machinery ticket, and the only destructive one.** Slice 4's consumption ledger found `clearance_gate_tag` unprompted and classified it `write-without-consumer`; this slice deletes what it found.

## What came out

The whole convention, not the field the plan named. A grep-derived predicate (THR-688 rule A) found it in **14 files**; the plan's pinned line numbers named 4 of them. Four declarations, four write paths, one reader:

- **Declarations** — `ClearanceGateConfig.followOnTags` (the authored seed), `ClearanceGateTransitionRule.addFollowOnTags`, `ClearanceGateRuntimeState.followOnTags`, `ClearanceGateTransitionRecord.addedFollowOnTags`.
- **Writers** — the config seed, the transition-rule merge in `clearanceGate.ts`, the `clearance_gate_tag` aftermath effect, and gate duty's branch `successTags`/`failureTags`. The last two were outside the plan's list entirely.
- **Reader** — `gateFollowOnSentence` and the `future_hook` chip reading *"A follow-on thread was seeded"*.
- **Authored content** — four `addFollowOnTags` in civic-guard content, three `clearance_gate_tag` effects in guild content, one arcane-circle effect, one result-band tag.

`future_hook` as a chip kind is untouched — `encounter_seed` still produces it. One producer died, not the vocabulary.

## The deletion removes its own evidence, and that is the correct shape

The plan told slice 6 to cite the ledger row as its tombstone. Ledger membership is **derived from the effect-kind union**, so deleting the member deletes the row: the ledger now reads **44 effect kinds + 44 GraphOps = 88 rows, 0 write-without-consumer**, down from 45/89/1.

That is not a loss of evidence, but it does move where the evidence lives — into this doc, the changelog, the wiring-checklist row, and the sources file's header, which keeps the worked example in the past tense because a design whose only worked example has been deleted still has to be able to say what it was.

## The guard the deletion nearly weakened

The ledger's old assertion was `expect(dead).toEqual(['clearance_gate_tag'])`. The honest post-retirement form is `toEqual([])` — which **also passes** on an empty corpus, on membership that stopped being derived, and on a `classifyRow` that returns nothing. Shipping that alone would have replaced a real check with a vacuous one, in the ticket whose entire subject is gates that pass over nothing.

So "zero" ships beside the two things that make zero mean something: a **population guard** (both unions non-empty) and a **membership guard** (`effectKinds` must not contain the retired id, so reintroducing the effect fails by name). The classifier's ability to return the class is proved separately on **synthetic** rows in the pre-existing `class is derived, never authored` block — deliberately uncoupled from any live member, so it survives this retirement and every future one.

**Falsified, with the arm confirmed applied first.** Re-adding `clearance_gate_tag` to the union failed 4 tests by name — including `expected [ 'reputation_score', …(44) ] to not include 'clearance_gate_tag'` — and exited 1. Reverted; revert confirmed green at 22/22.

## Two findings

**The ledger row's own note was wrong on a detail.** It said three tag conventions (`#watch_trusted`, `#papers_flagged`, `proven_master`) "rot in one field". Two do. `proven_master` sits on an effect-shell **result band**, whose `ResultBandConfig` type `src/types/contentShells.ts` does not declare at all — `effectShellRuntime.ts` imports it from there and gets nothing. All three were dead writes, so the ruling to delete stands; the "one field" framing does not. That module's broken import surface is pre-existing red-baseline breakage and was left alone.

**The four authored `clearance_gate_tag` effects in guild and arcane-circle content carried no `runtimeId`.** The handler falls back to `action.clearanceGateIds?.[0]`, and those templates declare no gates — so those writes had been skipping with `no_runtime_id` since they shipped. Dead writes inside a dead field.

## Orphans swept

`touchedClearanceGateStates` (the effect was its only writer, so the flag would have been permanently `false` and the gate-state write unreachable), its `nextClearanceGateStates` buffer, `gateRuntimeId` and the now-unused `action` parameter of `buildEncounterAftermathReactions`, and `EffectShellGateTransitionTrace.followOnTagsAdded`. That trace interface has **no emitter anywhere** and was deliberately left in place — pruning a never-emitted trace is dead-code work outside this predicate.

## Verification

`npm test` 1128 files / 18837 tests green (exit 0, unpiped, redirected to file); ratchet **2973 unchanged** — no baseline refresh, so THR-976's re-run obligation does not apply; `vite build` 14.77s; engine smoke tick 30 / 377 agents / 50 events.

**Browser-verify substitution: jsdom-render — unattended run, no startable dev server.** `preview_start` was refused (*"Dev servers can't be started from unattended sessions"* — impediments #546/#574), so the screenshot route was unavailable and the decision was taken before the capture rather than at it. In its place: the encounter-stage and `EncounterVeil` suites, 25 files / 426 tests green, real components rendered through the real adapters; an added absence assertion pinning that no face of the gate-duty model carries the retired chip title; and a **shipped-bundle check** — neither `A follow-on thread was seeded` nor `clearance_gate_tag` appears anywhere in `dist/`, while the sibling title `The checkpoint changed state` **does**, which is the positive control proving the absence is real rather than a grep that matches nothing.

A tightened regex was part of that: the gate-duty aftermath test accepted `/night will keep travelling|follow-on thread/i`, an alternation loose enough that a stale follow-on value would still have matched. Pinned to the one real answer, verified empirically rather than guessed.

**UI-Laws judgment** (`Docs/design-system/laws.md`): Law 1, 13/14, 17, 21, 37 checked on the aftermath surface as composed. No violation introduced — the change *removes* a chip that announced a promise with no mechanism behind it, which moves the surface toward Law 21 (no affordance drawn for something that does not exist) rather than away from it. No new affordance, no new state, no dead link.
