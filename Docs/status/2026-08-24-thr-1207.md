# THR-1207 — dead reputation-tally keys drained to zero

**Shipped 2026-08-24.** Deferred from the THR-1206 reputation unification; plan doc
`Docs/plans/2026-08-23-thr-1206-reputation-unification.md`, § The two content sweeps.

## What was wrong

`reputation_tally` records what a mortal is becoming **known for**, and the aftermath
handler writes only `<reach>.positive|negative`. Every other key is traced once,
rate-limited, and dropped. **171 of 518 authored tally writes (33%), across 78 distinct
keys, were landing on keys the engine refuses** — the arcane circle, thieves guild and
civic guard lines worst at roughly twenty dead writes each. Every one of them was an
encounter telling the player they had earned standing while nothing in any reputation
mechanism moved.

The leak survived as long as it did because the *surface* looked healthy:
`describeTallyKey` rendered a readable sentence (`record of guild work`) for keys the
handler had already refused to write.

## What shipped

Every off-axis key re-authored to the mechanism its fiction meant. **None was deleted
to make the gate go green** — that is the way this sweep could have passed while
removing authored consequence, and it is worth stating that it did not.

| Group | Count | Became |
|---|---|---|
| Guild work — `ac.*`, `tg.*`, `cg.*`, `ag.*` | 62 writes, 21 keys | `faction_reputation_gain` on the guild the file is about |
| Army command — `army.command.*` | 9 writes, 7 keys | `iron.positive`, or `iron.negative` for strain and disbandment |
| Company / mentorship / road standing | 36 writes, 3 keys | `heart.positive` / `heart.negative` |
| Narrative one-offs | ~64 writes, 47 keys | the reach-polarity key their scene bands to |

`TALLY_KEY_RATCHET` is **empty**. `aftermathWords.ts`'s free-form branch is documented
as a defensive fallback for pre-sweep saved worlds rather than a second production
shape, and the `SUGGESTED_TALLY_REPLACEMENT` hint map's `hearth.positive` — a typo for
the `heart` reach, i.e. a hint naming a key as invalid as the one it replaced — is
fixed.

## Two judgment calls, both departures from the plan's default mapping

The plan mapped place/community-shaped keys (`slice.road_repute`, `company.standing`,
`route.*`, `community.refugee_welcome`) to the new `reputation_with` effect, and
company keys to cohesion. Both were reconsidered against the code:

- **`reputation_with` would have re-created the defect at several sites.**
  `targetLocationId: '$target'` binds only when the target really is a place-tier
  location (`nodeMatchesSceneField`); anywhere else it stays unresolved and the handler
  refuses the write. The thirteen `slice.road_repute` sites span six scenes, several of
  which target a person. Using it there would have swapped a *discarded* write for a
  *refused* one — the same defect in newer clothes. All of these are the actor's renown
  carried between scenes rather than one town's opinion, so they band to `heart`.
- **Cohesion is not reachable from authored aftermath at all** — there is no cohesion
  effect kind — and would in any case record the company's health rather than the
  member's name, which is what the fourteen `company.standing` sentences claim.

Amounts for the guild conversions are `0.05 / 0.1 / 0.2`, matching exactly what the
seven already-correct faction files use, so no balance change was smuggled in as a fix.
Those files also carry `reputationReward` metas, so the per-step award path and the
aftermath award coexisting is the shipped norm, not something this sweep introduced.

## Evidence

Full gate green: 1056 test files / 17291 tests, typecheck ratchet unchanged at 3014,
`vite build` clean, `check:encounter --all` OK, 30-tick CLI smoke to tick 30 with 384
agents, wiki-freshness OK across 24 pages.

New gate: `src/data/content-eval/__tests__/guildReputationRewrite.test.ts`. The two
existing gates would both have stayed green if the sweep had credited the wrong guild
or deleted the writes, so this pins that each file credits its own guild, that the
amounts stay on the shipped scale, and — end to end through
`applyEncounterAftermathReaction` against a seeded-shaped world — that a real shipped
reaction moves `member_of.reputation`. Falsified by pointing civic-guard's writes at
the thieves' guild: two assertions go red, including the end-to-end one.

## Follow-on worth knowing

`changes[]` chips carrying `kind: 'reputation_tally'` are a *display* shape with no
`key`, so they sit outside this gate entirely — the corpus walk only counts effects
with a string key. They were left alone here. Where a chip's backing write moved to
`faction_reputation_gain`, the chip still names a reputation and is now more accurate
than before, not less.
