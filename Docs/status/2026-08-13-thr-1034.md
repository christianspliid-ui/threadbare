# THR-1034 — every essence balance the player reads is a whole number

**Shipped 2026-08-13.** Project: Encounter Experience. Pillars: UI (Engine N/A — no producer
changed; Content N/A — no authored copy changed).

## What was wrong, and why the reported instance was already fixed

THR-1034 was filed against `◆ 192.60000000000005 essence` in the nudge-stage chrome. That
**specific** readout was fixed three days later by THR-1006 (`c601bc17`), which correctly
identified `EncounterVeil.tsx` as the true producer, shipped
`src/components/shared/formatEssence.ts`, and routed its three diamond readouts through it.

But THR-1034 is a **predicate, not that instance** — *"any player-facing essence-balance render
that skips whole-number rounding"* — and THR-1006 fixed the surface it was reported on rather
than the class. A sweep of every essence render under `src/components/` found the class still
open in three balance readouts and three cost readouts, all bypassing the module built to own
exactly this.

The one that mattered was a genuine live defect of the reported shape:

```
ReadTheThreadsPanel:  Available: {essenceAvailable} essence
                   →  "Available: 192.60000000000005 essence"
```

That is not a hypothetical. It is reproduced verbatim in the falsification run recorded below.

## What changed — six call sites, one owner

| Site | Was | Now | Why |
|---|---|---|---|
| `ReadTheThreadsPanel` "Available:" | raw `{essenceAvailable}` | `formatEssencePool` | **Live defect.** Raw pool float reached the screen |
| `InterventionConfirm` "have {N}" | `Math.round(availableEssence)` | `formatEssencePool` | Whole, but **rounds a balance** — `191.9` displayed as `192`, a number the player cannot spend |
| `ScryOverlay` "Available:" | `Math.floor(essencePool[…])` | `formatEssencePool` | Behaviour-identical; removes the last inline copy of the rule so it cannot drift |
| `ReadTheThreadsPanel` option cost | raw `{opt.cost}` | `formatEssence` | Latent — routed for single ownership |
| `InterventionConfirm` cost | `Math.round(essenceCost)` | `formatEssence` | Latent, but **rounding a cost is the worse bug**: `Math.round(0.05)` is `0`, and a card priced `0.05` would advertise itself free |
| `JourneyVignetteModal`, `PremonitionModal` ×2 | raw `{essenceCost}` | `formatEssence` | Latent — routed for single ownership |

No new abstraction: every edit points an existing call site at the existing THR-1006 module,
whose docstring already states the rule each site was re-deriving. Balances floor
(`formatEssencePool`, Law 13's whole-number exception); prices round (`formatEssence`, because
an authored fraction is real and flooring it would promise a free card).

**Only the first two change what a player sees.** The other four are integer-valued today
(`SECONDARY_SPHERE_DISCOUNT = 1`, authored costs integral), so they are latent rather than
manifesting — routed because the module's whole purpose is that two surfaces quoting the same
pool cannot disagree, and stated here as latent rather than dressed up as fixes.

## Scope held deliberately

- `ScryOverlay`'s `Math.ceil(reassignmentCost)` is **left alone** — ceiling a *required* cost is
  a deliberate "you need at least this much", not the balance rule.
- `OddsPips`' `Math.round(cost)` is **left alone** — that is the pip-count vocabulary, not a numeral.
- `AscendantSheet` (prose descriptors) and `EssenceBlock` (fill bar) already render no numeral.
- `ChronicleEntryCard`'s `.toFixed(2)` is **quintessence**, an orthogonal axis, not essence.

- ✅ Falsified in the direction that matters (below).

## Why the test is a component test

The helper was already pinned by value in `shared/__tests__/formatEssence.test.ts` — 10 green
tests — and **not one of them could fail while three call sites bypassed the helper entirely.**
That is precisely how this class survived a fix that named this exact defect. The new tests
render the real components and read the DOM, so they fail on the thing that actually broke: the
call site not reaching the formatter.

Both vacuity traps THR-1006 recorded are closed on purpose:

1. **The fixture is genuinely fractional.** THR-1006's first verification sampled a pool at
   `190`; an integer renders identically with and without a formatter, so the assertion passed
   against a value incapable of failing.
2. **Each assertion is falsifiable** — each case also asserts the output *differs* from
   `String(RAW_POOL)`, the literal string the defect put on screen.

Falsification (reverting `ReadTheThreadsPanel` to raw interpolation) produced the reported
defect exactly, then was reverted:

```
AssertionError: expected '…' to contain '192 essence'
Received: "…Available: 192.60000000000005 essence…"
```

The floors-not-rounds case independently goes red on `Math.round`, pinning the
`InterventionConfirm` half.
