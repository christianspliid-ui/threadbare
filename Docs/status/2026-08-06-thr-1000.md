**A 400-seed loop was measuring a value the seed cannot move, and the only thing that surfaced it was someone else's PR going red (THR-1000, 2026-08-06).** `playerCastBalance.test.ts`'s `castDistribution` rebuilt a full `WorldGraph`-backed `GameState` **inside** its `SEEDS = 400` loop, and three of its five callers read only `capability` / `probability` — both computed pre-roll, before `resolveActionShared` touches the rng, which decides only *which outcome* a cast lands on. So 399 of every 400 casts in those tests recomputed a constant. **The cost is invisible while it passes**, which is why it was found the expensive way: the 8-call inertness test sat at 113% of the 5s vitest default, PR #1313 added a test file and four JPEGs, and it failed twice in a row (5646ms → 6132ms — re-running made it *slower*) as the sole red in a 14910-test run, holding an armed auto-merge that could never fire. Fixed by hoisting the fixtures and adding `castReadout`, a single-resolution helper for the pre-roll reads; **the assertion is untouched** — same four difficulties, same two scales, same `new Set(probabilities).size === 1` — it just costs 8 casts instead of 3200, and the difficulty range is deliberately not narrowed to buy time because its width *is* the property. **The deliverable is the guard, not the speed-up.** The change rests on a claim about where the rng enters, and a load-bearing claim argued only in a comment is the shape this repo keeps getting burned by: `preRollStable` now goes false if any seed ever reads a different capability or probability, and a new test pins `castReadout` to the loop's own value with a full-seed-count non-vacuity check. Injection-proven both directions — perturbing one seed's capability reddens the stability flag, pointing the readout at the wrong cell reddens the equality plus two downstream tests. **Hoisting was proven neutral by measurement, not argument:** all 7 cells return byte-identical capability, probability and outcome counts on both trees, which is the check that would have caught a mutating resolver had `PLAYER_CAST_PUSH_ENABLED` not been `false`. Whole file 16ms against ~7s; the target test 0ms against 5646ms. Deliberately **not** fixed by raising the timeout — that hides the next test to reach the cliff instead of removing it.
