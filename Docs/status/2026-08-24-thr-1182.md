### THR-1182 — the standing welcome finally pays off (2026-08-24)

The Grateful Kin has told the player for months that a town keeps a door open for them.
THR-1175 made that honest (the write reached the *place* instead of minting a favour owed
by a town) and THR-1206 made it the right noun (`reputation_with`, the one social score).
Neither made the world act on it. `encounter.slice.the_table_that_holds` is the half the
director's fix named second: *"the roof actually opens, on screen, as an encounter."*

**The scene**, from the brief Christian approved in chat 2026-08-24 ("The Table That
Holds", drawn from `hook.unlikely_alliance` under the game-design-first authoring order).
Two families in the town have stopped speaking, riders are on the fen road tonight, and the
traveler is the one person both camps will sit with. Step 0 (Heart) is whether the table
holds; the fork is the mortal's own answer on `courage_prudence` — stand the causeway as
one body (Stone), or empty the fen-side steadings before dawn (Eye).

**Both review agents flagged the same risk and it shaped the design:** step 2 is
combat-adjacent and the corpus has no nudge-native combat vocabulary. So neither variant is
a fight. The riders are weather — the courage path is numbers, footing and nerve in a
narrow place; the prudence path is seeing which barn stays shut and which household is told
to walk. Movement, wounds, hard choices, which is vocabulary the game already has.

**The gate had to be `Respected`, and that is arithmetic rather than taste.**
`REPUTATION_WITH_DEFAULT` is `0.5`, which `getReputationWord` bands as **`Accepted`** — so
the obvious-looking `{ atLeast: 'Accepted' }` is cleared by a stranger who has never been to
the place. It would have been a gate that never rejects, which is this ticket's own defect
class one layer along. `Respected` (≥ 0.6) is reachable off the Kin's warm band alone
(0.5 + 0.12 = 0.62). The test pins that distinction directly: it asserts the refusal at a
town with no history **and** asserts that `Accepted` would have passed there, so the
evidence is about the band this template picked rather than about the machinery.

**Three corrections to the ticket as written, each recorded at the site:**

1. **The gate field.** The description asked for `requiredTargetTraits:
   ['trait.condition.location.standing_welcome']`. THR-1206 left that condition with zero
   writers, so authoring it would have gated on something nothing produces. Uses the
   re-specced `requiredReputationWith` instead — this is its first content user.
2. **No authored seed chip.** The description asks for one per band; this file's own
   aftermath header (rule 2, THR-971) says a planted seed already renders its own chip and
   re-authoring it as a `future_hook` is a double-source. The later structural rule wins.
3. **Done-when 4's constant.** It asked the seed delay be pinned against
   `CONDITION_STANDING_WELCOME_DURATION` (120 ticks). That constant governs the retired
   condition. The welcome no longer *expires* — it **fades**, so the real window comes from
   `REPUTATION_WITH_DECAY_PER_TICK` and `REPUTATION_WITH_PRUNE_EPSILON`, and the binding
   band is the **fumbled** one: `(0.04 − 0.02) / 0.001` = **20 ticks** before the edge is
   pruned. The warm band's window above `Respected` is `(0.12 − 0.10) / 0.001` = 20 too.
   `SLICE_TABLE_DELAY_TICKS = 12` (one game day) sits inside both, and the fiction agrees —
   the riders are coming tonight.

**Seeded from all three Kin bands, restated three times on purpose.**
`applyAftermathOutcomeBand` replaces `reactions` **wholesale**, so the two crit bands that
author their own reaction would silently drop a seed planted only on the base reaction. One
shared `SLICE_TABLE_SEED` constant, referenced three times, so a delay cannot drift between
copies. `inheritContext: true` carries the source action's `targetId`, which is how the
return visit lands at *this* town rather than a town-shaped one.

**One defect found in my own draft and fixed before shipping.** Both `critical_success`
bands originally authored the deepened welcome and the prize as **two reactions**. A run
applies exactly one, so the band would have paid out half of what the economy promised,
whichever half the player picked. Merged into one reaction carrying both writes.

**Evidence.** `check:encounter -- encounter.slice.the_table_that_holds` clean on the first
run at four systems (cast, rewards, conditions, reputation), zero exemptions, **not** on the
retrofit ratchet; `--all` reports `failing 0` across 196. Full suite **1058 files / 17,316
tests green**; ratchet 3014 unchanged; `vite build` ✓ 11.29s; 30-tick smoke to tick 30 /
384 agents / 42 events. The live proof is `tableThatHolds-seedChain.test.ts`, which drives
the *real* path — the shipped reaction object through
`applyEncounterAftermathReaction`, then `evaluateEncounterSeeds` — and shows the edge
landing on the town at band `Respected`, the seed ripening at exactly `+12` and not at
`+11`, and the gate opening there and refusing at a town with no history. Both new gate
groups were **falsified**: setting the band to `Accepted` and the delay to 25 turns them red
with the intended messages.

Content + engine pillars, so no browser capture is owed (THR-688 rule C). The CLI could not
supply the live proof — `spawn encounter @hero <id>` makes the *agent* the action target and
`$target` is kind-checked, so the location-shaped write is correctly refused on that path,
and this build's CLI has no location-targeting spawn (impediment #724).
