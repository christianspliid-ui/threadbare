### THR-1185 — the authoring brief stopped ordering authors to write the rejected model (2026-08-24)

`Docs/authoring-brief.md` is the compiled preamble the encounter pipeline tells every draft
agent to read **first** — the skill says to prefer it over the full source. Its Sections D and E
had sat on the pre-THR-772 model for months. Section D described player choices as the
**god-verb menu** ("whisper, send vision, steady, strengthen, withdraw") and told the editorial
agent to reframe offenders as *divine intervention*. Section E trigger 7 required
*"per-step approach cards"* — **the rejected authored-futures model** — which the live skill's
own trigger 14 then rejects. An agent obeying the brief literally would spend its drafting
budget authoring the thing the pipeline was about to throw away.

Both blocks are hardcoded string constants in `scripts/build-authoring-brief.ts`, and both cite
*"Source: encounter-pipeline SKILL.md"* while the live SKILL.md no longer says either thing. So
the brief was a stale snapshot presenting itself as current, on the one surface guaranteed to be
read.

**The reason it survived is the part worth keeping.** `npm run check:authoring-brief` was green
and would have stayed green forever — it compares the brief's stamped hashes against
`AUTHORING_BRIEF_SOURCES`, which lists the wiring guide and the direction doc and nothing else.
The constants are not a declared source, so no freshness gate could see them. The ticket said as
much and warned the next session not to read a passing check as evidence.

**What the ticket did not know: the fix as written could not have been applied.** Its scope was
"reword the two constants, then `npm run build-authoring-brief`, and commit the regenerated
brief". But `main()` short-circuits on those *same two source hashes* — rewording a constant
leaves both unchanged, so the generator prints `brief is up to date — no changes written` and
exits 0. The regeneration step produces nothing. `check:generated-freshness` then passes too,
because the generator it runs also writes nothing, so disk still matches the commit. Three
gates, all green, all structurally blind to the same input.

So the constants were put **under** the identity rather than beside it.
`AUTHORING_BRIEF_HARDCODED_SECTIONS_HASH` hashes Sections D and E together, gets stamped into
the brief header as a third source line, and is compared by both `main()`'s short-circuit and
`check-authoring-brief.ts`. A reword now invalidates the cached brief exactly as editing a
source doc does. This is the minimal version of the ticket's own "consider extracting them from
SKILL.md at generation time" — it keeps the hardcoding the generator's comment deliberately
chose (no skill-file read at generation time) while removing the blind spot that choice cost.
`extractHashesFromBrief` reports a pre-THR-1185 two-stamp brief as `sectionsHash: null`, which
compares unequal and therefore regenerates rather than silently accepting the old shape.

**The guard was falsified before it was trusted**, in three arms: clean tree → *up to date*;
third stamp tampered to forty zeroes → *stale — source(s) changed: generator sections D/E
(scripts/build-authoring-brief.ts)*, naming the right source and not the two innocent ones;
restored → *up to date*. A gate nobody can make fail is not evidence.

**Section E now carries the live list through trigger 25**, not 8 — including the composition
rules (4–8 cards, four distinct spheres, an ungated common option), the band-coverage and
`effectLine` rules, and trigger 14 itself, whose wording is the direct replacement for the old
trigger 7: *a player-facing option that instructs the mortal rather than exerting the god's
influence… range is not the test: a dream, an omen, a kindled desire are lawful; "tell them to
run" is not*. Section D takes the live framing verbatim, ending on **"Influence, never
authorship"** and *"a hand is an offer, not a toll gate"*.

**A second staleness surfaced on regeneration and is fixed in passing:** the wiring guide's hash
had moved (`e065a969…` → `780aff21…`), so the committed brief was also behind a declared source —
nobody had regenerated since 2026-07-21. That drift *was* visible to the check, which had been
reporting it as a warning that exits 0; the brief is now current against all three inputs.

**Eight new tests, and they are written with literal strings rather than by re-reading the
constants** — a constant-on-both-sides assertion would pass whatever the constant said. Each was
falsified against the old committed brief via `git show HEAD:Docs/authoring-brief.md`: all three
"must be absent" strings are present there and all three "must be present" strings are absent, so
every assertion discriminates. Reverting the constant turns them red.
