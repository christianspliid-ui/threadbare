# THR-2221 — the map no longer follows Kael on every chapter

**Shipped 2026-11-14.** Thematic Pressure & Living World · Warm playtest round 4.

- **Two movers, not one.** The ticket named the Stage camera (pan on every open, re-centre on close). The live trace (a setter on the canvas's d3 `__zoom`, with stacks) found a second, larger one: the HexMapV2 scene-build effect re-runs whenever `locations`, `anomalies`, `realmProjection` and its other inputs change — on a running clock, every few ticks — and each rebuild re-applied the **opening view**, which centres on the First. That snapped the camera back to Kael between chapters, with no Stage open.
- **Scene rebuild keeps the camera.** The cleanup stores the d3 transform (`keptCameraRef`); a rebuild of the same grid restores it instead of `applyOpening`. The opening view now applies only on the first build (or a new grid size).
- **Stage open.** `useStageCamera` skips `centerHexesAt` when every framed place is already inside the Stage window (`frameAlreadyInWindow`: the whole hex, half a hex width inside each edge). The camera reports `stayed`. A place outside the window is framed as before.
- **Stage close.** The camera never moves. The THR-2056 middle-third re-centre is retired. It cannot drift now, because only off-window places are framed and the frame puts them inside. THR-2166's `closeCamera.playerMoved` stays as a record.
- **Hover.** `centerHexesAt` re-raycasts the hex under a still pointer when a pan ends (cut, end or interrupt), so the hover tooltip lands after a programmatic pan.
- **Evidence.** `useStageCamera.test.tsx` (11 tests): an in-window focus never calls `centerHexesAt`; close never calls it; two chapters at one place frame once. Browser at 1920×1080 (bash-vite :5263, Playwright, tree probe `frameAlreadyInWindow` / `keptCameraRef`): across `__DEBUG.tick` runs, two encounter beats opened `mode: "stayed"` with the camera centre identical before and after, no close moved the camera, and no tick moved it outside a Stage.
- **Not covered by a unit test.** The rebuild restore lives inside the WebGL scene effect; it is evidenced by the browser trace only.
