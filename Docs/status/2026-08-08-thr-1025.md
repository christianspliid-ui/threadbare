**`$actor` was missing from the aftermath sentinel vocabulary, so three seeded slice encounters were being planted on a phantom agent.** The stderr line the T3 sweep caught — `Source node not found: $actor`, 51 times in a 900-tick seed-42 run — was framed as a lost `participated_in` edge, and the ticket's named suspect was a content file writing `targetAgentId: '$actor'` on `encounter_seed` effects. The content was not wrong. `$actor` is the established reference token everywhere else in the codebase (`resolveRef` in `src/types/graphOp.ts` maps it for every GraphOp), so authoring it was reasonable; what was wrong is that `bindAftermathSceneTargets` — the pass that binds sentinels on *every* aftermath effect before dispatch — knew only `$target` and `$cast:<key>`. `$actor` fell through the `continue` and survived as a literal seven-character string, and the consumer's `effect.targetAgentId ?? actorAgentId` fallback could never catch it because a non-empty string is not nullish. **The damage was larger than the edge.** `evaluateEncounterSeeds` spawns the follow-up encounter with `actorId = seed.targetAgentId` and never checks the node exists, so all three affected reactions — the swindler, the grateful kin, and the full moon's promise — were planting real, running `UnifiedAction`s onto an agent that does not exist. Every graph write those actions attempted failed silently down the fail-soft path; the missing history edge was the one that happened to log. The fix widens the vocabulary at its three wiring points (the constant, the bind pass, and the `unresolvedSentinel` predicate that `bond_change` uses to tell an unbound sentinel from a real id) rather than patching the three call sites, so the seven content sites authored this way — and any future one — resolve correctly by construction. A second guard at the spawn site discards a seed whose target is not a live node, with a trace carrying `discardReason: 'target_agent_missing'`, which closes the class: an unbound sentinel and a target that simply died between plant and eligibility now both terminate as a narrative event instead of a phantom. The regression test was **falsified before it was trusted** — 4 of its 7 assertions fail on the pre-fix tree, and the 3 that pass both ways are the fail-soft cases that were always correct. Sweep stderr went 51 → 0 with the verdict unchanged (`PASS — apex holders at tick 900: 13`). One net-new type error was accepted rather than cast away: the new trace carries `agentId`, which `getTracesForAgent` and the debug bridge both filter on, and the error is the known `Omit`-collapses-the-union defect behind the 3477-error baseline (THR-489) — dodging it with a double cast would have hidden the debt and cost the trace its per-agent visibility, which is the inspectability this ticket exists to restore.
