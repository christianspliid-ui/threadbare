# THR-2093 — The meeting's test prose and helps/hinders panel get a dark backing

**Shipped 2026-10-31.** Onboarding & First-Run Experience. In a Meet-The-First formative test, the god-voice line and the setup paragraph were drawn straight onto `ComicPanel`'s scene art, whose only scrim fades out toward the top, so the prose crossed bright windows with nothing behind it. The paragraph had no width cap either, so on a wide window each line ran about 54% of the screen. The helps/hinders panel below (`nudge-test-panel`) was backed by an almost transparent 0.015 white.

**Fix:** a new shared constant, `READING_BACKING` in `src/components/shared/readingBacking.ts`, sets a void-coloured backing (`rgba(10,10,15,0.93)`) with a 6px backdrop blur. `FormativeTestBeat` wraps the god voice and the setup in one `formative-reading-block`, capped at `--measure-prose` (34em), with named padding, radius and gap constants. `NudgePhaseShell`'s standalone test panel uses the same backing and keeps its gold border. The alpha is 0.93, not the ticket's suggested 0.75–0.8, because Law 45 sets it. Over pure-white art, the god-voice line (`rgba(212,168,122,0.7)`, kept as it was) measures 4.54:1 at 0.93 and would drop to 3.35:1 at 0.8. `BondBeat` already sits on a solid `#0a0a0f` ground with no scene art, so its prose needed no change. Its test panel picks up the shared backing, which looks the same there.

**Evidence.** `src/components/MeetTheFirst/__tests__/readingBackingThr2093.test.tsx` has 3 jsdom tests: the backed block is capped at the measure and holds both paragraphs, the panel uses the same backing, and every text tone holds 4.5:1 over white art. `npm run gate`: PASS (test, typecheck, build, encounter, god-cards, ui-debt). The browser check ran on worktree Vite :5297 via Playwright, from `?view=game&firstunmet&size=medium` → Reach Down → Solenne → formative test. `getMeetingState()` reported `beat: testing, usingFormativeTests: true`. At 1920×1080, the block and the panel both computed `rgba(10, 10, 15, 0.93)` with `blur(6px)`. The block's max-width was 612px (34em), drawn at 489px under the 0.8 fit zoom. The commit bar's bottom edge was at 1044 < 1080. At 2560×1440, the block was 688px (34em at the larger type step) against roughly 1400px before, and the commit bar's bottom edge was at 1392 < 1440. The console showed 0 errors. Nothing scrolled at either size.

**UI Laws checked:** 1, 13/14, 17, 21, 33 (one viewport at both sizes, hand and commit bar on screen), 37, 45 (4.5:1 over white art, pinned by test).
