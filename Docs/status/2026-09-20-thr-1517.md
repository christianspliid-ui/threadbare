# 2026-09-20 — THR-1517: the multi-tick arms in orchestrator.test.ts carry an explicit timeout

**Ticket:** [THR-1517](https://linear.app/threadbare/issue/THR-1517) · **Project:** Continuous Improvement · **Pillars:** Engine (test harness only — no production file changed), Content N/A, UI N/A.

## What was wrong

Four arms in [`src/engine/__tests__/orchestrator.test.ts`](../../src/engine/__tests__/orchestrator.test.ts)
drive `runTick` in a loop — 30 ticks, 25 ticks, 10 ticks, and the complete play → twilight →
harvest → new-cycle loop. None declared a timeout, so each ran against vitest's 5000ms default.
On the CI runner the 25-tick arm measured 5247ms, 5386ms and 5430ms on three consecutive days
(impediment row 1054), sitting on its own ceiling and resolving on runner speed: PR #1968 failed
at 14:26Z, passed at 15:11Z and failed again at 16:10Z on the same tree. Six armed PRs went red
in four days on diffs that touched no engine file, and THR-1516 — the only in-flight work on the
board — sat shipped-and-green for over two hours without landing.

## What shipped

A named constant, `MULTI_TICK_TIMEOUT_MS = 30_000`, at the top of the file, with the rule stated
as a predicate in its doc comment: any arm whose body calls `runTick` more than once passes
`{ timeout: MULTI_TICK_TIMEOUT_MS }` as its options; single-tick arms and arms that call one
phase function directly keep the default on purpose, so a borderline arm elsewhere in the suite
still surfaces. The four arms that match today's predicate carry it. The 20-iteration loop in the
rival-actions arm calls `phaseRivalActions` directly, not `runTick`, so it is outside the rule
and measures 7ms.

The ceiling is derived, not picked: local isolated-file durations are 725ms / 570ms / 548ms / 3ms
for the four arms; the worst CI figure is 5430ms, about 9.5× local. Thirty seconds is ~5.5× the
worst observed CI figure and ~40× the worst local one — large enough that runner speed no longer
decides whether a green tree merges, small enough that a genuine hang still fails inside a CI
job's budget. The global `testTimeout` is unchanged: `git diff --name-only -- vitest.config.ts`
is empty.

## Proof

Isolated file run after the edit: 23 passed, the four arms at 1776ms / 1223ms / 6ms / 1142ms
while the full suite ran concurrently — a live demonstration that contention alone can
double-to-triple an arm's duration. `npm test`: 1274 files / 20612 tests passed, exit 0.
`check:typecheck` OK, 2840 unchanged from baseline. `vite build` green in 24s. Heavy lane and
CLI engine smoke recorded in the commit body.
