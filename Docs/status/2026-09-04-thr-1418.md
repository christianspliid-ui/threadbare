# THR-1418 — `terrainPipeline` had no pipeline; the tuning group now reads the live one

**2026-09-04 · Engine + UI · Bug · Project: Thematic Pressure & Living World**

## What was wrong

`src/engine/terrainPipeline/` contained exactly two files — `types.ts` and its own test. No passes, no
orchestrator, no caller. Its only non-test consumer anywhere in `src/` or `scripts/` was the CMS tuning
panel, `src/components/CMS/tunableConstants.ts`.

The live worldgen path is a different module tree: `hexGrid.ts` constructs `WorldGenPipeline` from
`src/engine/worldgen/`, whose passes read `src/engine/worldgen/constants.ts`, and `worldGenData.ts`
supplies the river/lake limits `riverGeneration.ts` and `lakeGeneration.ts` import.

So the panel group titled **World Generation — Terrain**, described as *"Continent placement, tectonics,
elevation, climate, rivers, lakes, and regions"*, offered 22 dials that changed nothing. THR-1409 had
just fixed the four rows in that group which *did* have a live counterpart to re-point at; this is the
remainder, which mostly did not — the terrainPipeline design models continents and fault lines, and the
live pipeline is noise-field + province flood-fill and models neither. That made the fix a judgement
about what the surface should promise, not a rename, which is why it was filed separately.

## What changed

**`src/engine/terrainPipeline/` is retired wholesale.** Once the panel stops importing it, nothing in
the tree reads it. Its five interfaces (`HexGenCell`, `WorldGenConfig`, `FaultLine`, `LakeCluster`,
`GeoRegion`) had no consumer but its own test, and two more — `WorldGenData` and `RiverPath` — were
name-duplicates of live types in `worldGenData.ts` with *different shapes*, which THR-1409 deliberately
left in place. Retiring the module removes that trap rather than documenting it a second time.

**The `worldgen-terrain` group is rebuilt from the live pipeline's own constants.** Every row now reads
a declaration a worldgen pass or generator imports — verified per constant, not assumed:

| Old row | Decision | Live target |
|---|---|---|
| `FAULT_COUNT_MIN` / `_MAX` | re-pointed | `RIDGE_COUNT_DEFAULT` — pass02 lays ridges, not faults |
| `FAULT_CONTROL_POINTS` | re-pointed | `RIDGE_STEP_VARIANCE` + `RIDGE_MIN_LENGTH` / `_MAX_LENGTH` |
| `TEMP_BASE_RANGE` | re-pointed | `TEMP_LATITUDE_WEIGHT` |
| `WIND_DIRECTION` | re-pointed | `PREVAILING_WIND_ANGLE` |
| `MOISTURE_COAST_BONUS` | re-pointed | `MOISTURE_COASTAL_BONUS` |
| `RAIN_SHADOW_FACTOR` | re-pointed | `RAIN_SHADOW_PENALTY` |
| `RIVER_SOURCE_COUNT` | re-pointed | `RIVER_SOURCE_COUNT_MIN` / `_MAX` |
| `GREAT_LAKE_CHANCE` | re-pointed | `GREAT_LAKE_COUNT` — a count, not a probability |
| `REGION_SIZE_MIN` / `_MAX` | re-pointed | `PROVINCE_MIN_SEED_DISTANCE` / `PROVINCE_MAX_HEXES` |
| `CONTINENT_COUNT_MIN` / `_MAX`, `CONTINENT_RADIUS_MIN` / `_MAX`, `MOISTURE_BASE`, `LATITUDE_EQUATOR_ROW` | **removed** | the live pipeline models no such thing |
| `LAND_TARGET_MIN` / `_MAX` | **removed** | `SEA_LEVEL` already renders in `biome-classification` |
| `ELEVATION_MOUNTAIN_BASE` | **removed** | `RIDGE_PEAK_ELEVATION` already renders there |
| `MOUNTAIN_SPINE_WIDTH`, `ELEVATION_FALLOFF_RATE` | **removed** | `RIDGE_FOOTHILLS_HEXES` already renders there |
| `ELEVATION_NOISE_AMPLITUDE` | **removed** | elevation noise already renders in `worldgen-noise` |

The second removal reason is the one worth naming: six rows *did* have a live counterpart, but that
counterpart is already a row elsewhere on the same panel. Re-pointing them would have replaced a dead
dial with a duplicate one — a different defect of the same family, not a fix. The group description was
rewritten too; a group heading is a promise the surface makes, and *"Continent placement, tectonics"*
was a false one.

## How it is held

`src/engine/__tests__/worldgenConstantOwnership.test.ts` gains a third guard that **generalises** the
THR-1409 spot-check: for *every* row in `worldgen-terrain`, resolve `sourceFile` to a live module and
assert the rendered value is identity-equal to that module's export. An unrecognised `sourceFile` fails
rather than being skipped — a row pointed at a module nothing generates from is the whole defect, so it
must not fall through the filter. Two falsification arms guard the guard: the group must render more
than ten rows (an empty group would make every assertion vacuous), and both live modules must actually
be exercised (a regression confined to one would otherwise pass).

Falsified before being trusted: re-pointing one row back at `terrainPipeline/types.ts` **with a
numerically matching literal** — precisely the shape of the original defect — turns the new guard red
while the old spot-check stays green. That is the measurement showing the generalisation adds coverage
rather than restating it.

`Browser-verify substitution: jsdom-render — unattended run, no startable dev server` (impediment #546,
15th occurrence; `preview_start` returned *"Dev servers can't be started from unattended sessions"*).
The render assertions run the real `ConfigManager` over the real `TUNABLE_GROUPS`: each re-pointed row
paints its live value and owner file, and a whole-panel render (`ConfigManager` starts every group
expanded) asserts all 22 retired names and the dead module path are absent — with a falsification arm
proving the panel painted at all. The substitution is structurally honest here: rows are *deleted* from
an already-scrolling group and no row is re-laid-out, so the failure classes only pixels catch —
overflow, z-index, off-viewport paint — cannot be introduced by removing table rows.

**Seed invariance**, the load-bearing Done-when, is discharged by measurement rather than by argument:
a terrain census (per-type hex counts + river/lake counts) over seeds 42 and 99 at medium and large is
byte-identical before and after. No live constant's value moved; this is a surface change.
