# THR-1212 slice 1 — the `WorldRef` type, its adapters, and a resolver that admits when it drops

**Shipped 2026-08-27.** First slice of wave-1 design A (shared anchor machinery). Additive; no consumer migrated.

## What landed

One canonical way for anything in the game to name a game-state object, and — the half that matters — a live resolver that records every time a reference resolves to nothing.

- **`src/types/worldRef.ts`** — `WorldRefKind` (13 members) and `WorldRef`. **The** kind vocabulary: seven live entity-kind unions disagree today (the graph says `actor` where every UI layer says `agent`; `faction` is type-illegal in `TargetCategory` and ships through `as unknown as`), and slice 2's catalog lint will validate each of them as a projection of this one. Deliberately **import-free**, because it becomes a membership source the catalog generator parses, and a generator that must resolve an import graph to read a union breaks when an unrelated module moves.
- **`src/types/worldRefAdapters.ts`** — hub-and-spoke translations to the four existing wire shapes (`NavigationTarget`, `EntityVisualRef`, `EncounterAftermathConceptRef`, the narrative-segment quadruple). Every adapter is partial and fails soft; `undefined` is the contract, not an error path.
- **`src/engine/worldRefResolver.ts`** — `resolveWorldRef`, delegating sentinel grammar to `resolveAnchorDeclaration` rather than copying it (one rule read three times, THR-1164's explicit design), plus the drop log behind `__DEBUG.getWorldRefDrops()` / `clearWorldRefDrops()`.
- **39 unit tests**, written against the real unions and a real `WorldGraph`.

## The three decisions worth recording

**Adapters got their own module.** The plan doc left colocation as an executor call. Separating them keeps `worldRef.ts` dependency-free for the generator, and stops UI-facing imports being pulled into a module that is on its way to becoming high-impact.

**No trace is emitted, deliberately.** The resolver fires from render-time consumers; a trace per rendered chip would drown the buffer it shares with the tick loop. NFP #2 is served through the debug bridge instead — a ring buffer capped at `WORLDREF_DROP_LOG_MAX` (200), evicting oldest first.

**The drop log is the point, not a nicety.** A reference that fails to resolve *should* fall soft to plain text (NFP #4, Law 21) — correct behaviour, and therefore invisible. That invisibility is exactly how THR-1165's two hollow `$cast:` sentinels type-checked cleanly while naming a caravan that was never in the world. A test pins that asymmetry directly: two identically well-typed refs, one real and one hollow, and only the hollow one lands in the log.

## Two bugs the gates caught before they shipped

Both were in work written this session, and both are the kind that pass a casual read:

- **`parseHexRefId('4,')` returned `{col: 4, row: 0}`** — a real, wrong hex. `Number('')` is `0` and `Number.isInteger(0)` is true, so the guard let it through. Empty parts are now rejected before conversion. My own test caught it, which is the argument for sweeping the malformed range rather than one example.
- **A test fixture invented the tooltip id `trait.patient`**, which resolves to nothing. The Law 17 gate scans test files too and flagged it. Replaced with a registered id — an invented one would have become a dead underline the moment anyone copied the fixture into content.
