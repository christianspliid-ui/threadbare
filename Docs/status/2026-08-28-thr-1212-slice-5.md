# THR-1212 slice 5 — the gate that runs against a world

**2026-08-28** · Wave-1 design A, shared anchor machinery · item 5 of 6

Slices 2–4 built generators: they read source, derive membership, and fail by name. All three can be green while the content is broken, and THR-1165 is the proof — two `$cast:` sentinels passed every compile-time and authoring-time check while the caravan they named was never cast, because the template's `supportBundle` was bind-only and the binder produced `supportBindings: []`. **A static type is necessary and never sufficient** (THR-1160). This slice is the sufficiency half: the third row of the typed-seam contract table, and the only gate in the ticket that builds a world and asks whether representative content resolves to anything that is actually there.

## What it does

`src/engine/__tests__/contracts/worldRefNoOpGate.contract.test.ts` builds a seeded world through the real `initializeGameState` → `runTick` pipeline (seed 42, small, 20 ticks), stages each template's cast through the real `prepareEncounterSupportBundle`, runs every declared chip anchor through `fromConceptRef` → `resolveWorldRef`, and asserts the id that comes back names an object that is really there.

The staging is the load-bearing choice. Bindings come from the function the engine calls at spawn, not from a hand-built map — an invented map supplies both sides of the question and could never have caught THR-1165.

`declaredChipAnchors` is a new export on `compositionContract.ts`, reading through `aftermathFaces` — the same walk clause 2 and slice 3's `chipsWithoutReferent` use. A second walk drifts, and two populations that stop describing the same corpus is this ticket's own subject in miniature. It dedupes by `changeId::entityId` rather than by `changeId`, because one change can carry a `stateNoun` *and* several `concepts` naming different objects, and collapsing to the change would hide every anchor after the first.

## The two vacuity guards

This test's failure mode is passing over nothing, and the opportunity is right there: **665 of 698 templates declare no anchor at all**, so a walk that silently returned `[]` would satisfy every assertion in the file.

1. **Population asserted per form, not in total.** The corpus is lopsided — 63 `attachment_template` literals against 23 `$cast:` anchors — so a total-only guard is discharged by the literals alone while the class that actually broke in THR-1165 sits at zero and nobody notices.
2. **`EXPECTED_FORMS` is closed.** A form appearing in the corpus with no disposition in the test fails by name rather than being skipped — the `assertEveryMemberAnnotated` pattern the anchor catalog uses. `artifact` (THR-1275) is listed and authored by nothing yet; when content authors one, that shows up as a count, not a silent skip.

## Measured

33 templates declare **189 anchors**: 63 `attachment_template`, 49 `$actor`, 30 `$target`, 24 `$faction:`, 23 `$cast:`, 0 `$artifact`. Zero unclassified. Zero literals unresolved. Zero faction definitions absent from the seeded world — all three the corpus names (`civic_guard`, `holy_order_dawn`, `mercenary_company`) have live chapters. Zero cast keys the binder failed to bind.

**The THR-1165 class is currently clean**, which is what a guard looks like as opposed to a sweep. Existence is checked across both id spaces the resolver legitimately returns from: a sentinel resolves to a per-world graph node, an attachment-template literal passes through unchanged to a node in `attachmentTemplateIndex` that is committed content and not in the world graph at all. Checking only the graph fails all 63 literals; checking only the index passes any string the graph never heard of.

## Falsified twice, with the perturbation confirmed first

The check impediment #872 exists for. Retargeting `encounter.slice.bargain_at_crossroads`'s chip anchor from `$cast:stranger` to `$cast:keeper` — a key its `supportBundle` **does** declare and the binder never produces, which is the THR-1165 shape exactly — failed by name (`supportBundle bound no 'keeper' in a real world`) and exited 1; reverted, revert confirmed. Deleting one entry from `ANCHORS_WITHOUT_VISUAL_KIND` failed the enumeration assertion; reverted, revert confirmed.

## One finding, enumerated rather than tolerated

Seven declared anchors carry an `entityId` and **no `visualKind`**, so `fromConceptRef` returns `undefined` and they never reach a resolver at all. `visualKind`'s own doc comment says *"Absent ⇒ neither is drawn"* — so the author did the work of naming the referent and the player gets nothing for it.

No existing gate is about this. It is **not** a dead link (Law 21 holds — no affordance is drawn), and it is **not** a clause-2 violation (the declaration is well-formed and `classifyAnchorDeclaration` correctly passes it). It is an anchor authored into a field its own surface ignores.

Pinned by name as `ANCHORS_WITHOUT_VISUAL_KIND` and filed as [THR-1317](https://linear.app/threadbare/issue/THR-1317/seven-chip-anchors-declare-an-entityid-with-no-visualkind-an-anchor) with its coordination block as first comment (THR-836). A ceiling was rejected: it would let one be fixed and a different one appear with the gate none the wiser. The list is a `toEqual`, so a fix that does not update it fails by name — the coupling is deliberate.

## Wiring

No `ci.yml` step: a vitest contract test runs inside `npm test`, already a step of the required `Test · Typecheck · Build`. Naming the job matters — slice 3 found `check:chip-anchors` had been running *nowhere* since it shipped, and the check that avoids repeating that is saying which job the gate runs in rather than assuming one.
