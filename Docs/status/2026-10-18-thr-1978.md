# THR-1978 — no run starts without a First

**Shipped 2026-10-18.** Cold playtest round 4: a tester took the title screen's "Advanced World Setup" link, which goes `worldgen` → `selection` → `playing` and never creates the remembrance identity. Meet The First mounts only with that identity, so the run had no First, "Centre on my First" found no one, and the location drawer still offered a "Meet The First" card that could not open. Fix direction (a): the link renders only in dev builds (`import.meta.env.DEV`, the guard the UL entry got in THR-1601), so a player build reaches play only through New World → remembrance. Every surface that offers the card now asks `canOpenMeetTheFirst` / `offersMeetTheFirstCard` (`src/components/Game/meetTheFirstCard.ts`), which require an identity — the location slot row and the Inspector place page's Act row both drop it on an identity-less dev run.

Regression: `StartPage.advancedSetup.test.tsx` (jsdom: player build hides the link, dev build keeps it) and `meetTheFirstCard.test.ts` (no identity → no card). Evidence route: jsdom render, per the claim comment (structure-shaped Done-when).
