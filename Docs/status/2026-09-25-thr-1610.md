# 2026-09-25 — THR-1610: the cold playtest becomes a loop

**Ticket:** [THR-1610](https://linear.app/threadbare/issue/THR-1610) · **Project:** Onboarding & First-Run Experience · **Pillars:** all N/A (a harness that plays the deployed build from outside; no engine, content or UI change).

## What shipped

- **Harness** under `scripts/cold-playtest/`, lifted from the plan's appendices. `config.json` holds every tunable. `personas.json` holds the fixed story/veteran/skimmer set, and `player-brief.md` is brief v1. `run-player.ps1` starts one cold `claude -p` tester outside the repo with Playwright-only tools. `run-round.ps1` runs all personas in parallel and writes `round.json`. `extract.mjs` turns a transcript into `log.md` + `summary.json`.
- **Executor additions to the appendix:**
  - `run-round.ps1` takes a `-Label` (a dry run writes `round-N-dry-run/`, so it never takes the directory the real round N needs).
  - It records the deployed commit in `round.json`.
  - It extracts a timed-out tester's partial transcript, so the tester reports `incomplete`, not `no-summary`.
  - It prunes screenshots beyond `keepRoundsWithScreenshots`.
- **`cold-playtest` skill** (`.claude/skills/cold-playtest/SKILL.md`): lane / attended / dry-run modes, the four gates, verify-before-file classification, cross-round tracking, report + scorecard publish to `ops`.
- **`tb-cold-playtest` lane:** prompt mirror plus a registry row at cron `37 10 * * *`. **Not yet registered.** An unattended pickup run does not create standing scheduler config, so an attended session registers it from the mirror.
- **`keep-work-flowing-cc`** step 2.6 now folds `cold-playtest-round-*` reports.
- The round-1 milestone and `cold-playtest` label descriptions point at the plan and skill.

## Evidence

- `extract.mjs` on the round-1 veteran baseline reproduces `verdict: "maybe"`, `neverUnderstood: 12`, `surprises: 10`, `firstQuitAtAction: 63`.
- One dry-run round against the deployed build (`1a0d803e`): **usable 3/3**, verdicts story no / veteran maybe / skimmer no, met The First 0/3. Every candidate maps onto an open round-1 ticket. The report is on `ops` as `Docs/ops/cold-playtest-round-2-dry-run.md`.
- **Appendix bug caught by the dry run:** PowerShell variables are case-insensitive, so the appendix's `$round = [ordered]@{…}` wrote into the `[int] $Round` parameter and killed the script after all three testers had finished. Fixed (`$roundInfo`). A new `-SummarizeOnly` switch recovered the run's `round.json` without paying for the testers again.
