### 2026-10-03 — THR-1717: delivery velocity step 1 — lean sessions, one-shot gate, back-to-back pickup

**Every session in this repo starts 25% lighter, the gates run in one command, and the pickup lane no longer sits idle half of each hour.** Director-directed (Christian, attended chat 2026-10-03). Plan: `Docs/plans/2026-10-03-delivery-velocity.md`.

- **Context diet.** `.claude/settings.json` now disables eleven plugins with no Threadbare use and denies twelve claude.ai connectors plus three user MCP servers (`deniedMcpServers` — `disabledMcpServers` is not honoured for these, probe-verified). Headless turn-1 context in a worktree: **112k → 84k tokens**, tools 1,195 → 192, with Linear (68 tools), GitHub, codesight, Playwright and Discord kept. Every model turn re-reads that baseline, ~100 turns per pickup run.
- **`npm run gate`.** One command that classifies the diff with CI's own predicate and runs the owed track in parallel — code: test ∥ ratchet ∥ build ∥ encounter gate (∥ CLI smoke on an engine diff), then `test:heavy` alone; docs: impediment ids ∥ plan-doc lint — and prints one verdict line per gate, logs in `.cache/gate/`. `--final` runs the two tree-diffing gates last. Measured: code track ~80 s (135 s serial), engine track 218 s (~290 s serial), and a 7-line verdict instead of 1,400+ lines of vitest in the session's context. Two vitest suites never share the machine: together they stretched the fast suite 73 s → 139 s and timed out five tests.
- **Hooks.** The worktree write guard is one Node process (`worktree-write-guard.mjs`; the `.sh` is a shim so its regression suite runs unchanged): 223 → 115 ms standalone and ~7 → 2–3 processes per edit, which is what made it time out (fail-open) 93 times in two days. The DoD commit/push hooks were deleted: their matchers (`Bash(git commit*)`) never matched, so they never ran, and the push hook's `project-status.md` check would have blocked every push had they ever started to.
- **Back-to-back pickup.** `tb-opus-pickup` cron `0 * * * *` → `*/20 * * * *`. The scheduler never overlaps runs of one task (a held slot fires the moment the live run ends), so this is an idle gap of at most 20 minutes, never a second claim.
- **Also fixed:** `simulationHarness.test.ts` drove a real world on vitest's 5 s default and timed out at 5.7 s under load; it now uses `WORLD_SIM_TEST_TIMEOUT_MS` (the THR-1015 class).

**Corrected along the way.** An early reading of the transcripts blamed slow `git commit` calls (48 s median) on the commit hook; they were compound commands chaining the 87 s freshness gate, and the hook never fired. Edits' 2 s median is mostly the harness's per-hook process start (~0.7 s), not the guard's own work.
