# 2026-08-29 — THR-1330: the hook chip's link half, and the tile it deliberately does not carry

**Ascendant bar → Hooks.** THR-1307 repointed this block off `has_attachment` — an edge type with no writer anywhere in the repo — and onto the live carriers. That made three rows of chips reachable for the first time in the game's history, and reachability is what put them under Law 1: *every game concept the player sees carries its image, its tooltip, and its link.* They had the tooltip. They had neither of the other two, and nobody had noticed, because until THR-1307 no chip had ever reached a screen.

## The verdict, per kind

The ticket asked for a stated verdict on each of the three rows. The answer turned out not to be three verdicts but **one rule applied three times**, which is the better shape: a chip links when, and only when, the concept it names resolves to a sheet.

The decider is `attachmentDetailFromNode` — the same classifier `resolveAttachmentTemplateDetail` runs for the aftermath consequence chip (THR-1120). Nothing is special-cased per row:

* **Conditions → link, no tile.** `subcategory: 'condition'` is inside `ATTACHMENT_TRAIT_SUBCATEGORIES`, so a condition resolves and opens `AttachmentDetailView` through the same `setAttachmentSheetId` the encounter ending uses. The chip re-acquires `role="button"`, `tabIndex`, and now Enter *and* Space — the pre-THR-1307 handler answered only Enter, which `role="button"` had been promising to screen-reader users for as long as the affordance existed.
* **Clues → fail-open plain text.** `clue` is deliberately outside that set; there is no page. Law 21's fail-open, reached by the probe rather than by a hand-written rule that could drift from the sheet.
* **Vows → fail-open plain text.** An agreement is edge state. `edge.id` is not a node id, so there is nothing for the sheet to draw, and the terms the player wants are already on the chip's tooltip.

The probe is per-chip, not per-row, and that distinction earns its keep immediately: an authored `category: 'mark'` trait buckets into the Conditions row but is *not* an attachment subcategory, so it fails open like a clue. A rule reading "conditions link" would have given it a dead link that looks live — the exact thing Law 21 names.

## Why no image, on any of them

THR-1120 already ruled on this representation class and the ruling is load-bearing rather than incidental: `EntityVisualKind` **excludes** `attachment` on purpose, and `buildUnifiedEncounterStageModel`'s `resolveIcon` skips the kind — *"an attachment has a page but no entity-visual family … it takes the link tier and no tile, which is the documented fail-open path rather than a wrong glyph."* An attachment's art lives on its own template node as `props.image`, and `AttachmentDetailView` draws it there.

Measured before deciding: **0 of 214** attachment templates across `condition-trait-content`, `reward-attachment-catalog`, `starter-attachments` and `anomaly-reward-catalog` carry an `image`. So a tile on these chips would be the fallback glyph on every single one, and getting even that would mean handing `resolveEntityVisual` a borrowed kind — the hand-plumbed second lookup Law 3 exists to forbid. Same class, same verdict as the aftermath chip. Law 1 is satisfied by the link, not by inventing an image for a class that has none.

## The cursor was lying too

`.chip` set `cursor: pointer` unconditionally. THR-1307 removed the `role`/`tabIndex` half of the false advertisement and left this half behind — so every inert chip still claimed to be clickable in the one channel the player reads *before* committing to the click. The cursor now comes from whether the chip actually resolved a destination, so the advertisement and the behaviour cannot disagree.

`Browser-verify substitution: jsdom-render — unattended run, no startable dev server` (the sanctioned #546/#574 route).
