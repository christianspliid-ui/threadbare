**A contract test failed CI on a PR touching zero `src/` files, so the change under test could not have caused it — one ~18-minute gate cycle plus the diagnosis, lost (THR-1015, 2026-08-07).** The cause is margin, not correctness: `agent-decision-pipeline` runs 3277ms locally against a 15s timeout (4.6x), but that run's suite took 353s against ~70s local, and 3277 × 5 = 16.4s clears the limit almost exactly. **The class is wider than the ticket's one file** — this session's own full-suite run went red on `threaded-agent-balance`, a different file carrying no explicit timeout at all and silently inheriting vitest's 5000ms default; it measures 1553ms alone and timed out past 5000ms in-suite on the same machine, a 3.2x in-suite slowdown before any CI variance applies. So the qualifying predicate is **local duration × ~5 against the value in force**, which caught five tests across three files. Option 2 of the ticket's three (split the perf assertion from the correctness one) was ruled out by reading the code rather than the test name: `PIPELINE_TICK_BUDGET` is a count of *simulation ticks* — "within tick budget" means "encounters appear inside 50 ticks" — so there is no wall-clock assertion to split out and the timeout is purely a hang detector. Option 3 (pin into the isolated pool) would grow the list THR-949 exists to shrink. Values moved into two named constants carrying the measurements that justify them (NFP #1), retiring all twelve hardcoded literals so the next heavy test copies a named constant rather than minting a thirteenth magic number: `WORLD_SIM_TEST_TIMEOUT_MS` (120s, builds a world and runs ticks) and `HEAVY_IMPORT_TEST_TIMEOUT_MS` (30s, first case absorbs a dynamic import). The second exists rather than reusing the first because `traitPredicate`'s first case is 2096ms against 33 siblings at 0–1ms — import cost, not simulation — and labelling that world-sim would mislead the next reader. **Non-vacuity: a raised timeout cannot be falsified the usual way**, so the constant was injection-proven — setting `WORLD_SIM_TEST_TIMEOUT_MS` to 1 reddens exactly the four tests referencing it, each with "Test timed out in 1ms", then restored and re-verified.
