# THR-992 — the shared seed pool held entries that were not seeds

**Shipped 2026-08-08.** Engine pillar only; Content and UI are N/A (no authored content, no player surface).

## What the ticket asked for, and what was actually there

`phaseRouteEvents` de-duplicated one live seed per route with a bare
`pending.some((s) => s.seedId.startsWith(seedPrefix))`. The ticket had measured the
live pool on `seed 42 / map medium` at tick 132 and found entries whose `seedId` was
`undefined` — `undefined.startsWith` throws, `phaseRouteEvents` has no internal `try`,
and `runRegisteredPhases` turns that into a `tick_crash`: the whole route-event scan
produces nothing for that tick. Reachable only when a world has both a `trades_with`
web *and* a malformed pool entry on the same scan tick, which is why it had not
surfaced in the seed-42 world (whose route set is empty at that tick).

The ticket's second Done-when asked for a verdict on whether the **producer** of those
undefined ids was itself a defect. It is, and it turned out to be the more interesting
half — so the fix landed on both sides.

Every non-test producer of a `PendingEncounterSeed` builds `seedId` from a template
string, so the grep for the producer came back empty-handed. Reproducing the
measurement instead of trusting it (Debugging Protocol: verify the noun before the
verb) showed why: the malformed entries carried **7 keys where a real seed carries
9–13**, and no `sourceEncounterId` either. They were not `PendingEncounterSeed`
objects at all.

```
{"id":"catalyst_strategic_recruit_warband_130","templateId":"encounter_warband_rivalry",
 "targetAgentId":"agent_mc_cmdr_0","sourceActionId":"proj_strategic_recruit_warband_...",
 "plantedTick":130,"eligibleAfterTick":133}
```

`maybeSeedCatalyst` in `src/engine/strategicActionLifecycle.ts` declared
`const seed: PendingEncounterSeed` and then wrote `id` and `sourceActionId`, omitting
`seedId`, `sourceEncounterId`, `sourceReactionId`, `priority` and `seedLabel`. That is
a compile error, and it has been one all along — it sat inside the ~3478-error red
typecheck baseline (THR-489), which is exactly the failure mode a red baseline has:
the type system had this exact defect written down and nobody could see it.

## The damage, which was wider than one throw

A catalyst seed still *spawned* — it carries `templateId` and `targetAgentId`, which is
all `evaluateEncounterSeeds` needs — so nothing looked broken. What it lost was
everything the missing fields carry:

- **Inspectability (NFP #2).** Every trace on the seed path (`encounter_seed_triggered`,
  `encounter_seed_family_matched`, `seed_context_inherited`) logged `seedId: undefined`,
  and the two player-facing narrative events for a discarded seed read
  `"A planted thread withered before it could take root: undefined"`.
- **Fail-soft (NFP #4).** Every present and future consumer that reads `.seedId`
  inherited the hazard. THR-626 hit the same entries in `armySupply.ts` and guarded
  there; `routeEvents.ts` was the next one along, and `economicPower.ts` survives only
  because it maps ids into a `Set` rather than calling a string method on them.

## The fix

**Consumer** (`routeEvents.ts`) — the guard the ticket asked for, kept because the pool
is written by many producers and defence in depth is the point:

```ts
const hasLiveSeed = (s: PendingEncounterSeed): boolean =>
  typeof s.seedId === 'string' && s.seedId.startsWith(seedPrefix);
```

**Producer** (`strategicActionLifecycle.ts`) — a well-formed seed. `sourceEncounterId`
takes `candidate.candidateId`, which is the provenance `sourceActionId` had been
carrying, so no information is dropped in the correction. The two magic numbers became
named constants (NFP #1): `STRATEGIC_CATALYST_SEED_DELAY_TICKS = 3` (was a bare `+ 3`)
and `STRATEGIC_CATALYST_SEED_PRIORITY = 0.6`. The seed id now includes the actor,
because two agents can complete the same strategic template on the same tick and an id
that does not identify is the class of defect being fixed.

## Evidence

The regression test was **falsified before it was trusted**: with the guard reverted it
fails with the ticket's exact `TypeError: Cannot read properties of undefined (reading
'startsWith')`, and it asserts more than "did not throw" — the route is still scanned,
still plants, and the malformed entry is carried through rather than eaten.

The producer fix is proven on the live world rather than by inspection. Same command,
same tick, before and after:

| | pool size | `typeof seedId === 'string'` | catalyst labels |
|---|---|---|---|
| before | 7 | 5 | *(none — `seedId` and `seedLabel` absent)* |
| after | 7 | **7** | `the wake of Recruit Warband`, `the wake of Establish Research Circle` |

Full suite 971 files / 15300 tests green; build clean; 30-tick engine smoke reaches
tick 30 with 383 agents and no thrown exceptions. The typecheck ratchet went **down 1**
(3478 → 3477) — the producer fix removed a real error rather than adding one — and the
baseline was refreshed and re-run as the last action before push, per THR-976.
