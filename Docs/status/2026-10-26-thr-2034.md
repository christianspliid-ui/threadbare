# THR-2034 — The Return's archetype reads match: the Usurper bypass and the archetype bonus count

**Shipped 2026-10-26.** Engine only (`src/engine/returnEngine.ts`, `src/types/returnEngine.ts`, `src/types/trace.ts`). Content N/A (no prose changes); UI N/A (the Return vignette renders whichever outcome wins).

**Why.** The Usurper archetype bypass and `archetypeDefaultScore` compared `meetingRecord.archetypeId` against `primary_secondary` keys, but the narrative bond path writes the display name (`'Phantom'`). In live play the bypass never fired and no archetype got its `ARCHETYPE_DEFAULT_BONUS`.

**What changed:**
- `archetypeKeyOf(record)` returns `${primaryReach}_${secondaryReach}` from the THR-2009 record fields; saved worlds without them fall back to `archetypeId` (as-is when already a key, through a reverse `ARCHETYPE_NAME_MAP` lookup when a display name), else `''`.
- `executeReturn` passes the key to the founding gates and `resolveReturn`; the display name still goes to prose. The `return_resolution` trace gains `archetypeKey`.
- `USURPER_BYPASS_ARCHETYPES` drops `schemer` / `trickster` / `fallen_noble` (no candidate ever carried them). The four affinity lists move to the exported `ARCHETYPE_TRAJECTORY_GROUPS`, unchanged in content.
- **Balance change:** live Firsts now get the +1 archetype bonus, and Shadow-primary Firsts can reach Usurper without its tags. Pinned in `returnArchetypeKey.thr2034.test.ts` (record built through `buildNarrativeResult`; a `shadow_shadow` First gets the trickster bonus; every listed key exists in `ARCHETYPE_NAME_MAP`).
