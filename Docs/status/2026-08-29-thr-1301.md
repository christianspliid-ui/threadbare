# 2026-08-29 — THR-1301: the cutover gate that passed while the world stood still

**Current focus:** the unified decision board's §4 cutover. The flip did **not** land. What
landed is the live branch (implemented, inert), and two defects in the gate that was
supposed to authorise the flip.

## The blocker THR-1301 was filed on is gone

THR-1292 slice 6 measured the §4 gate and it failed on seed 99 — 4.1% undertaking share
against a `[0.10, 0.35]` floor — because an undertaking's board score carried no
personality signal at all: both inputs to its desire multiplier were pinned. THR-1297
slice 5 authored `motivations`; THR-1302 replaced the frozen ambition boost with an
ambition-centrality term. Re-running the same census confirms both landed:

| | seed 42 | seed 99 |
| -- | -- | -- |
| undertaking share (was 11.9% / **4.1%**) | 17.4% | 13.7% |

All three criteria pass on both seeds. The gate THR-1301 was waiting on is open.

## Two gate defects, found by flipping and measuring instead of flipping and shipping

**1. `BOARD_SCORE_FLOOR` was a units error.** It shipped as `0.08`, documented as
"deliberately equal to `STRATEGIC_SCORE_FLOOR`". That constant gates a weighted score
normalised to `[0, 1]`; board score is `EVT × desire × temperament`, whose median winner on
seed 42 is **0.0006**. The two were never the same currency, so `0.08` landed at roughly
the 92nd percentile of the quantity it gated. Measured, against a legacy idle baseline of
28.7%:

| floor | idle | undertakings started | checkpoints |
| -- | -- | -- | -- |
| `0.08` | **91.8%** | 30 | 73 |
| `0.001` | 64.2% | 503 | 619 |
| `1e-6` | **30.3%** | 586 | 618 |

The corrected value is an epsilon, not a knob: board score is expected value per tick, so
any *positive* EVT beats standing still and the honest threshold is zero.

**2. The gate could not see it.** At `0.08`, with 2646 of 2882 seed-42 decisions idling, the
census reported **`idle 0.0% — PASS`** on every criterion on both seeds. `boardFamily` was
`board.winner?.family ?? 'idle'` — idle only when the board is *empty*, never when its
winner fails the floor — while the live branch idled on both. The gate and the behaviour
disagreed about what idle means, and the gate was the blind one. The floor is now applied
once, and the telemetry and the cutover read the same resolved winner;
`decisionBoardLiveness.test.ts` pins the two channels together.

## Why the flip still did not land

With the floor corrected the §4 criteria pass — seed 42 undertaking 33.4% / encounter
33.8% / idle 32.8%, seed 99 21.1% / 43.6% / 35.3% — and the flip is still wrong. The
criteria read the share *between* families and say nothing about composition *within* one.
Under a live board, `trades_with` edges written over 150 ticks on seed 42 go from non-zero
to **zero**: `strategic_establish_trade_route` takes zero board wins and is never generated.
Three world-simulation tests fail on the content loss, with every criterion green
throughout.

Board score carries **no variety term**. Plan §4 states the legacy scorer's components
"survive as candidate-generation features feeding EVT inputs"; `varietyPenalty` in fact
lands in `finalScore`, which the board never reads. At cutover the variety mechanism is
dropped rather than relocated.

That is a design change with its own balance envelope, so it is its own slice:
[THR-1349](https://linear.app/threadbare/issue/THR-1349/the-decision-board-has-no-variety-term-a-live-board-writes-zero-trade),
which carries the flip and asks for a composition gate in the census — because shipping
behind a gate blind to this class is how it would land twice.

## Shipped here

- `BOARD_SCORE_FLOOR` corrected to `1e-6`, with the sweep recorded on the constant
- One floor-aware verdict feeding both telemetry and the live branch; new `boardFamily`
  field on `decision_board_comparison`; parity pinned in `decisionBoardLiveness.test.ts`
- The `'live'` branch implemented and inert — idle re-keyed to the board, winner resolved by
  `BoardEntry.candidateIndex` (never by template id: two candidates for the same template at
  different locations score differently, and an id lookup executes the wrong one while both
  rows print identically)
- Deterministic tie-break on the board sort (NFP #3)
- `decisionBoardModeGuard.ts` deleted with its test — it warned that `'live'` was declared
  but unimplemented, which is no longer true
- `graphOpExecutor.tradeVerbs.test.ts` selects a place-tier location through
  `isPlaceTierLocation` rather than a bare `type === 'location'` test, which since THR-1183
  also matches sublocations

`UNIFIED_DECISION_BOARD_MODE` stays `'shadow'`. Contest B and
`STRATEGIC_ENCOUNTER_SCORE_BRIDGE` stay with it — in shadow, contest B is the only thing
that selects an undertaking, so deleting it before the flip stops undertakings happening at
all. The three go in one commit or none.
