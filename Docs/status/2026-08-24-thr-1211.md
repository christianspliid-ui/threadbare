# THR-1211 — four reputation-adjacent dead reads

**Shipped 2026-08-24.** Deferred out of the THR-1206 reputation unification, which recorded
these four rather than fixing them. Three needed a change; the fourth had already been
resolved by a sibling ticket and needed a verdict instead.

## What each one turned out to be

**1. `past_crime` was unreachable by construction.** The branch read
`relates_to.properties.reputation`. Nothing writes that property — the edge carries
`sentiment`, `strength`, `basis`, `trust` — so the read was always `?? 0`, the test was
`0 < 0`, and no mortal in any world has ever borne that secret. One of the eight secret
types was decorative. It now reads `getReputationWith`, the one social score between two
parties (THR-1206), and fires when the subject stands below neutral with a party outside
their own factions. That function returns the neutral default when nothing covers a pair,
so an agent with no standing anywhere still does not qualify — the branch stayed selective
rather than flipping to always-true, which was the risk worth checking.

**2. `reputation_walk_bonus` had no consumer — not, as the ticket framed it, no producer.**
Nine faction definitions author values for it on their upper tiers, making it the
*most*-authored of the three `FactionRankBonusType`s. `factionRankBonus.ts` shipped
application functions for the other two and described this one as "(future)", so none of
those authored numbers had ever moved a result. Wired into `reputationWalk` step 8b, once
per faction the source shares with a path intermediary rather than once per hop — the bonus
means "your guild network vouches for you", a property of the shared membership, and
per-hop accumulation would multiply a flat authored value into the clamp.

**3. The two rank reads disagreed, but not for the reason the ticket gave.** The stated
mechanism was decay drift. It is not: both write paths rewrite `rank` on every tier change,
so a decaying member stays consistent. The disagreement is **minted in** and never heals,
because `rank` is only ever rewritten on a tier change. `npcSeeding` writes `rank: 0.1`
beside `reputation: 0.12` (and `0.16` beside `0.22` for leadership roles), both inside the
entry tier — that is every seeded faction NPC, from tick 0. All four readers now go through
`getDerivedMembershipRank`, which computes the tier index from `reputation` and keeps the
cached value only where no `FactionDefinition` resolves (armies, bands, splinter/drift
memberships — which the gate does not see either).

That fallback closed a live `NaN` nobody had filed: `armySpawning` writes `rank: 'army'`, a
**string** in a numeric field. `?? 0` does not catch a string, so the walk's
`rank × FACTION_RANK_TRUST_BONUS` poisoned `clamp(raw + distortion + NaN)` for any trust
path routed through an army.

**4. Already resolved — no change, deliberately.** The item was blocked on THR-1207, which
merged as `52654f74`. Its sweep drained the last off-axis tally writes *and* rewrote
`describeTallyKey`'s docstring to record the right disposition: the free-form branch stays
as a defensive fallback for pre-sweep saved worlds (NFP #4), with authoring gated at
`check:encounter` and `tallyKeyCorpus.test.ts`. The ticket asked to "trim it to valid keys
once that sweep drains". Doing so now would delete fail-soft coverage for exactly the saved
worlds it exists to serve, so the verdict is recorded rather than the trim performed.

## Verification

Full gate green: 1059 test files / 17337 tests, typecheck ratchet unchanged at 3014, build
clean, 30-tick engine smoke reaching 384 agents. The 14 new tests in
`src/engine/__tests__/reputationDeadReads.test.ts` were falsified three ways — reverting
item 3 reds exactly its 4 tests, reverting item 1 reds its 1, reverting step 8b reds its 1 —
so none of them is a guard that cannot fail.

The item-2 tests deliberately go past reachability: proving the bonus is *visible* to
`getAgentFactionBonuses` was true before this ticket too and still moved nothing, so the
walk-level arm compares two runs differing only in the source's tier and asserts the delta
equals the authored value.
