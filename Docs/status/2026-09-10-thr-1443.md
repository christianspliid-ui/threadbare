# 2026-09-10 — THR-1443: the precheck learns whether the board can be read at all

**Shipped.** `scripts/session-precheck.ts` now probes Linear reachability and emits a
`linear=` token in its `fingerprint` line, beside `rg` / `git` / `test` / `cu` / `nm` /
`freshness`.

## Why

Every pickup invariant is Linear-mediated — `save_issue(assignee, state:"In Dev")` *is*
the claim — so a lane whose board is dark must report rather than work. On 2026-09-06
both documented paths were down at once and four lanes across three hours each
rediscovered the same outage independently, at their first mutation, after booting and
orienting (impediment rows 973 ×5, 974).

The cost was never the outage; the lanes behaved correctly and each produced a report.
The cost is that **from the board's side an outage looks exactly like a quiet queue**.
This moves the discovery to the first tool call, where it costs a line instead of a run.

## The design point that shaped the probe

A CC lane reaches Linear through the **MCP connector**, which this script cannot see.
`LINEAR_API_KEY` is what seven *scripts* use. The two are independent, and on the home
machine the key is routinely unset while the connector is perfectly live — which was the
state of this very implementation run, claiming THR-1443 through a healthy connector
with no key present.

So a probe that reported "no key" as a red would have hard-stopped the session that
built it. `nokey` therefore means only *this script had no credential* and never gates a
run. What stays load-bearing without a credential is **reachability**: a healthy
endpoint answers an unauthenticated POST with a 401, which is exactly what separates "up
but unauthenticated" from the 2026-09-06 shape.

## Vocabulary

| `linear=` | Meaning | Action |
|---|---|---|
| `ok` | Authenticated board read succeeded | Proceed |
| `nokey` | Endpoint answered; this script has no `LINEAR_API_KEY` | Proceed — the normal home-machine state |
| `noauth` | Endpoint answered and rejected the credential | Confirm with one board read; if it fails, report, do not claim |
| `unreachable` | No answer within the timeout, or a 5xx | The 2026-09-06 shape. Report; do not claim |
| `unknown` | Probe could not classify what it got | Carry on; confirm at first board read |

`unreachable` is deliberately its own token rather than folded into `unknown` as the
ticket's third Done-when sketched. Item 2 of the ticket leaves the vocabulary to the
executor, and collapsing the two would blur "the board is down" (actionable) into "I
learned nothing" (not) — the single signal this ticket exists to surface.

## Evidence — all four degraded arms demonstrated, not asserted

```
linear=nokey        0.34s  this machine as-is, endpoint live, no key
linear=noauth       0.33s  same wire 401, credential supplied and rejected
linear=unreachable  4.00s  blackholed endpoint, bounded exactly, exit 0
linear=unreachable  0.03s  DNS failure, fast-fails rather than burning the budget
```

The `nokey` / `noauth` pair is the discriminating one: identical 401 from the same
endpoint, different token, decided solely by the credential the caller held.

A controlled arm confirms the guards are not vacuous — collapsing `nokey` into `noauth`
reds exactly the three tests that assert the distinction and nothing else. 17 new tests,
49 in the file.
