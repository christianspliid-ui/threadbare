# THR-1196 — `hex.spark_encounter`'s `occurred_at` edge carries its tick

**Shipped 2026-08-22.** Engine pillar. Content Architecture.

## What was wrong

`hex.spark_encounter` mints a `divine_spark` event node and joins it to the first location on
the hex with an `occurred_at` edge. `EDGE_SCHEMA.occurred_at` lists `tick` in its
`requiredProperties`; the op carried no properties at all.

The recipe had the tick in hand the whole time — the generator takes it as a parameter and
writes it into the *event node's* properties on the line above. Only the edge was left bare.

## Why it survived

This defect is a **warning, not a refusal**. Unlike the `possessed_by` op THR-1194 fixed —
where the schema chokepoint rejected the op and the artifact reached nobody — the malformed
edge here reaches the graph. So every visible signal read healthy:

```
[GraphSchema] Edge "occurred_at" missing required property: "tick" (edge edge_occurred_at_5)
spark allSucceeded: true | errors: []
occurred_at edges landed: 1
```

`allSucceeded: true`, one edge landed, zero errors — and a warning on a console nobody reads.
The blast radius is correspondingly small: a consumer reading `edge.properties.tick` on a
divine spark got `undefined` rather than nothing at all.

## The gate, widened to the predicate

THR-1194 shipped a standing guard asserting every hex-action `add_edge` names a *registered*
edge type. `hex.spark_encounter` passed it — `occurred_at` is registered — and then tripped
the schema row one layer down. The guard was checking the outer layer only.

It now checks the full schema row: for every `add_edge` a hex recipe emits, every entry in
that edge type's `requiredProperties` must be present. That covers the ticket's membership
predicate rather than the one member that happened to be noticed. A sweep of the other hex
recipes' edge types (`possesses`, `contains`, `located_at`, `thread`, `has_trait`) confirms
all five declare `requiredProperties: []`, so `occurred_at` is the predicate's sole member —
the guard is now the thing that would catch a sixth.

Two execution-level tests sit alongside it, following this file's established discipline of
reading the graph back rather than asserting the op array: the landed edge carries `tick`,
and the cast produces no `[GraphSchema]` warning.

## Falsification

Every new assertion was run against the reverted recipe, not only the fixed one:

- the widened op-level guard fails naming `{ recipe: 'hex.spark_encounter', edgeType:
  'occurred_at', missing: ['tick'] }`
- the landed-edge test fails
- the console test fails, with the real `[GraphSchema]` warning visible in the run output

All three pass with the fix in place. A gate that has not been run against the defect it
exists to catch is not evidence it would catch one.
