# THR-1499 — `$realm` becomes a chip anchor, so a realm standing chip can link the Realm it moved

**Shipped 2026-09-16.** Deferral from THR-1454, Thematic Pressure & Living World. Direct sibling of THR-1462, which closed the identical gap for `$here`.

THR-1155 shipped `$realm` on the **effect** side: `faction_reputation_gain` with
`factionId: '$realm'` is the realm-court family's whole spine, and it works. The
**chip** side never gained the sentinel — `$faction:<defId>` takes a *shipped*
definition id checked against `ALL_FACTION_DEFINITIONS`, and a Realm's definition
is minted per world as `realm.<cultureId>` over a generated culture, so no literal an
author can write is ever in that set. All eleven standing chips across the three
realm-court encounters therefore anchored the *state* (`court standing`, a lawful
named anchor) and none could link the crown. The one faction class whose name is
drawn on the map was the one no chip could reach.

## What changed

- **One rule, two readers.** `resolveSceneRealm` moved out of `encounterAftermath.ts`
  into a new `src/engine/sceneRealm.ts`, and both the effect binder and the chip
  resolver import it. The Realm a chip links is the Realm the effect landed on, read
  from the same `realmProjection` the border mesh draws — never from the town's
  holder, which may be a guild, an order or a monster faction.
- **Why not `sceneSentinels.ts`.** That module is deliberately pure so the authoring
  gate can import the field→kind table without pulling the runtime dispatcher into a
  CLI bundle. The lookup needs a graph and the political map, so it sits beside
  `sceneHere.ts` as a second small graph-reading leaf.
- **`$realm` is the eighth anchor form.** `ANCHOR_SENTINEL_REALM`, a `realm` form on
  the verdict union, a classify arm, the sentinel named in the refusal message, a
  resolve arm reading `resolveSceneRealm(…, 'faction', realmProjection)`.
- **Gated like `$artifact`, not waved through like `$here`.** `ClassifyAnchorOptions`
  gains `bindsRealm`; `chipAnchorViolations` computes it off the binder's own field
  table (`SCENE_SENTINEL_FIELD_NAMES` × `SENTINEL_REALM`) and `check:encounter`
  refuses `$realm` on a template whose effects never bind it.
- **The projection reaches the resolver as a thunk.** `ResolveAnchorContext` and
  `WorldRefResolutionContext` gain `realmProjection?: RealmProjectionThunk`;
  `buildChipAnchorResolver` takes it as a third argument; both stage adapters accept
  it in their args and `GameView` hands them the projection `useSimulation` already
  holds. Lazy, so an ending with no realm chip never pays for the map.
- **Content.** The eleven `court standing` chips in `court-summons.ts`,
  `border-levy.ts` and `tithe-demanded.ts` (and their packages) now declare
  `entityId: '$realm', visualKind: 'faction'` on the `stateNoun` — the same shape a
  guild chip uses with `$faction:<defId>`. The court-summons header that recorded the
  gap for the next author now records the fix.
- **Docs.** Canon sentinel table gains `$realm` and `$area` rows plus a chip-side
  paragraph; the wiring guide's anchor-form list goes from five to seven; the anchor
  catalog's Nation row flips from 🕳️ gap to 🔗 linked and its Standing row names both
  faction forms; the encounters manual gains its entry.

## Where the noun sits, and why it differs from THR-1462

THR-1462 put `$here` on the **concept** channel because THR-1472 holds that a
`stateNoun` names the state object and never its carrier, and a place carrying a
location condition is the carrier. A `faction_reputation` chip is the one case where
the two coincide: the standing *is* the state, and its page is the faction sheet (the
anchor catalog's own Standing row). So `$realm` goes on the `stateNoun`, exactly as
`the-garrisons-price.ts` anchors `$faction:mercenary_company` there, and the tag
draws the Realm's tile as well as linking its sheet.

## Fail-soft, pinned

On ground no Realm claims, resolution returns nothing and the chip stays the named
anchor it was (NFP #4, Law 21). The no-op gate contract test pins that against an
empty map, and picks its actor **from the map** rather than taking the first agent on
faith — whether anyone stands on claimed ground is a worldgen fact, and resolving
every realm anchor against `agentIds[0]` would have turned a coincidence into a
verdict.
