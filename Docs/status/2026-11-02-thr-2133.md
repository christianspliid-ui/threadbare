# THR-2133 — The warm start states the wait it will keep

**Shipped 2026-11-02.** UI Visual Overhaul — Design System v1. Found by the weekly UX review (moment *Mid-game table*).

The catch-up screen promised "This takes a minute or two." while 300 ticks took 331 s on the deployed build. The fixed promise is gone: the screen now reads "This can take several minutes." and a new line under the season progress states the time left from the pace measured so far — "Working out how long this will take…" for the first 20 ticks, then "About 2 minutes left." (whole minutes, rounded up), then "Almost there." for the last 20 seconds.

**The estimate.** Tick cost grows as the world fills (~0.2 s a tick in the first season locally, ~0.43 s in the third), so a flat average undershot — it read "Almost there" for the last 88 s of a 105 s run. `estimateWarmRemainingMs` models the cost as a linear ramp fitted from the mean pace and the last 40 ticks' pace, integrates it over the ticks still to run, and leans long by `WARM_START_ESTIMATE_MARGIN` (1.15). `smoothWarmRemainingMs` lets the shown time rise at once but never fall faster than real time, so one quick window cannot flash "Almost there" mid-run. All thresholds are named constants in `useWarmStart.ts`.

**Measured (local dev build, `?view=game&seeded&size=medium&warm=300`, 1920×1080):** "About 2 minutes" at 4 s (105 s left), "About a minute" at 54 s (55 s left), "Almost there." from 95 s, arrival at 109 s. Every stated wait was kept.

**Not done here.** The warm-up itself is no faster; the CLI-vs-browser per-tick gap at `WARM_START_CHUNK_TICKS = 1` is still unsplit.

**Test.** `warmStartRemaining.thr2133.test.tsx`: the model (flat, ramp, heavy-first-ticks fallback, guards), the smoothing, minute rounding, and a jsdom render of the overlay with no fixed duration left in it.

**Browser evidence.** 1920×1080 screenshot of the overlay mid-run reading "About 2 minutes left."; console 0 errors; `typeof window.__DEBUG === 'object'` with one `warm-start-overlay` mounted. UI Laws judgment: Laws 1/17 (copy from the tooltip registry), 13/14 (season words and real-world minutes, never a tick count), 21 (one new line inside the existing S-tier card), 33 (card fits the viewport, nothing scrolls), 37 (existing type tokens), 54 (the wait is a designed state that now keeps its promise) — all hold.
