# THR-1494 — the first sentence on the scene screen is a sentence

**Deferral from [THR-1478](https://linear.app/threadbare/issue/THR-1478)** (the header merge), which moved the factor lines **above** the prose and so promoted two producer defects to the first thing a player reads under the agent's name:

| testid | rendered before | rendered now |
| -- | -- | -- |
| `nudge-factor-skill:eye` | `Vara is oracle in eye.` | `Vara is an oracle in Eye.` |
| `nudge-factor-authored:0` | `threads shifting` | `The threads are shifting.` |

Both are producer defects. `NudgeBalance` renders `factor.text` verbatim by design and is not touched — THR-1478 settled the rendering side, and a patch there would have hidden the defect on every other surface reading the same lines.

## Why one template could not be right

The tier vocabulary in `DOMAIN_WORD_SCALES` **mixes word classes**. Thirty-four of the forty words are adjectives (`formidable`, `shrewd`, `revered`); six are nouns — `magnate`, `phantom`, `channeler`, `seer`, `oracle`, `masterwork`. English puts an article in front of one kind and never in front of the other, so `{actor} is {word} in {reach}` is not a template with a bug in it: it is a template that cannot be correct for both halves of its own vocabulary at once. `eye` was the reach that happened to be on screen; the same shape was wrong for `gold`, `shadow`, `veil` and `stone` at their top tiers and had been since the line was written.

So the fix is **two templates and a classification**, not a patched string:

- `DOMAIN_TIER_WORD_FORMS` (`src/data/domain-words.ts`) classifies every tier word, keyed by the lowercased word. `'adjective'` means *no article*; **any other value is the article itself** (`oracle: 'an'`, `seer: 'a'`). Storing the answer rather than deriving a/an from spelling is deliberate — a vowel rule is wrong for *a unicorn* and *an hour*, and a table that holds the answer cannot be wrong at all.
- `DERIVED_SKILL_SENTENCE` keeps the bare shape; `DERIVED_SKILL_SENTENCE_ARTICLED` is its noun counterpart. `deriveSkillLine` picks between them off the classification.
- The reach now renders **title-case**, matching the reach chip the same stage draws (`buildNudgePhaseModel`'s `reachLabel`). "in eye" read as somewhere Vara was standing; "in Eye" reads as the domain she is skilled in, and the sentence and the chip beside it now name the domain the same way.

**The classification is drift-proof by construction, which is the point.** It is keyed by the *word*, not by reach-and-tier index, and the test asserts key-for-key parity in both directions against the live scales. Rename a tier word and it has no classification and the suite reddens; delete one and its entry is an orphan and the suite reddens. A content manager cannot quietly reintroduce "is oracle" by editing the vocabulary, which is exactly how this defect would otherwise come back.

## `threads shifting` — a shared default, not authored content

The ticket asked which half this was, and it is neither of the two the ticket guessed. It is **not** content authored on `encounter.slice.swindled_family`, and it is not a generator bug: it is `DEFAULT_FORECAST_FACTORS`, the fallback pool an encounter falls through to when its beat authors no `forecast_factors`. The adapter reaches it via `adaptUnifiedActionTemplateToEncounterContract`, so **every** encounter with no authored forecast factors rendered the same fragment — the swindled family was not special, it was just the review route.

It lives in 25 files: the shared `encounter-contract-builder.ts`, the engine adapter, and 23 encounter packs that each carry a copy-pasted inline adapter with their own local copy of the constant. All 25 now read `'The threads are shifting.'` — a sentence, still neutral, still claiming no direction, which is the constraint on that slot (the pool is a bare string tuple with no sign, so the adapter colours it `neutral`; claiming a polarity there would invent information the encounter never stated).

## Evidence

The guards are split along the seam they defend:

- **Producer sweep** (`src/engine/encounters/__tests__/skillFactorLineGrammar.test.ts`) — all eight reaches × all five tiers off the **live vocabulary**, not a fixture, because a template broken for `eye` is broken for all eight and a test pinning one string would have passed the whole time the other seven were wrong. Plus the parity arms above, and an explicit **anti-vacuity arm**: the live vocabulary must contain at least one noun form, or the article branch never executes and every other assertion in the block would pass against the defective template too.
- **Rendered face** (`src/components/Game/encounter-stage/__tests__/NudgeFactorLineGrammar.test.tsx`) — the real `NudgePhaseShell`, fed by the real `buildNudgePhaseModel`, asserting the DOM text a player reads. The fallback arm omits `factorLines` entirely so the adapter takes the contract path, and guards its own non-vacuity by asserting an `authored:*` line was actually produced before checking it.
- **Falsification, run and reverted:** with the producer restored to the single template and the bare reach key, **4 of the 8 producer arms go red**, reproducing `Vara is oracle in eye.` verbatim. The guard fails against the defect it was written for.

Suite green (1251 files, 20308 tests), `test:heavy` green (32 files, 212 tests), ratchet **2872 unchanged and baseline NOT refreshed**, build green, 30-tick CLI smoke tick 30 / 486 agents / 63 events.

`Browser-verify substitution: jsdom-render — unattended run, no startable dev server` (the impediment #546/#574 shape; `preview_start` refused this scheduled run outright). The change touches no `src/components/`, `src/hooks/`, `src/contexts/` or `index.css` path and so does not trip the UI-pillar trigger on its own — the render evidence is here because the ticket's own Done-when asked for the rendered face, and that is the sanctioned capture when no dev server can be started.

## Noted, not fixed

`Vara is a masterwork in Stone.` is now grammatical and still reads oddly — "masterwork" is a thing made, not a person who makes them. That is the **vocabulary**, not the template: `DOMAIN_WORD_SCALES.stone[3]` has said `Masterwork` since the scales were written, and it renders in every stat readout in the game, not only here. Re-authoring a tier word is a content decision with reach well past this ticket's scope, so it is recorded here rather than changed in passing.
