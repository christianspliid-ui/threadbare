**A run-founded faction now renders as itself (THR-1322).** THR-1309 restored the producer for `GameState.dynamicFactionDefinitions` — `strategic_found_order` charters real orders mid-run — and the UI could not see a single one of them: `data/faction-definition-lookup.ts` built its map once at module eval from the authored tables, so a chartered order's `founded_<actor>_<tick>` id resolved to `null` in the faction sheet, the sigil registry, every `faction.*` tooltip and the hex map's coat-of-arms roster. Every path is fail-soft, so it drew a nameless, heraldry-less, motto-less fallback and nothing threw. **A parameter could not close it:** `Tooltip` calls `resolveTooltip(id)` with no context by design, `getFactionSigilUrl` is a pure id→URI function, and `ArmyLayer` enumerates the roster inside a Three.js scene build — none can be handed a `GameState`, so threading would have fixed the sheet and left the map and every hover still dead. The run's definitions are therefore **mirrored** into the shared lookup, written where the state field is written (`foundFaction`), rolled back where that write rolls back, republished wholesale at `initializeGameState`, and cleared at the session boundary alongside `clearTimelines()`/`clearRewardHistory()` — a projection of state, never an authority, which is what keeps a module-scope store on the right side of the session-owned-caches rule. `factionNetwork.getFactionDefinitionForNode` had the same defect one layer down and read the static table directly; it now delegates to the same lookup, so the two cannot disagree — the exact drift that file was extracted to prevent. Measured on live worlds rather than fixtures: **4/4 orders chartered organically over 150 ticks on seed 42, and 4/4 on seed 99, resolve their name, motto, theme colour, three-tier rank ladder and sigil through the UI path**, with `in authored tables: false` on every one — which is the old lookup's answer, printed beside the new one. 13 new tests, each built on an id `foundFaction` actually minted and each carrying the controlled arm that the id is unresolvable before the charter, because an assertion written against a seeded fixture id verifies the path that was already correct and reports success.
