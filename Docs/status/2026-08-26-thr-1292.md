# THR-1292 slice 1 — value-pair vocabulary repair

**2026-08-26 · Engine · Thematic Pressure & Living World**

Plan doc 1/6 of the Proactive Agent Actions carve-up ships in slices; this is slice 1 of six,
the load-bearing prerequisite the plan puts before the prioritization board (§4).

## What was wrong

`AxiologicalProfile` is keyed by `ValuePair`, and every consumer reads `profile[pair] ?? 0`.
That `?? 0` means a pair name outside `VALUE_PAIRS` does not throw, does not warn, and does not
show up anywhere — it scores zero, for every agent, forever, while reading as perfectly good
shipped behaviour in the source file. Three families had drifted out of canon:

- **Authored content (~50 entries)** — `tradition_progress` (29), `justice_mercy` (19),
  `tradition_change` (2), `order_freedom` (1) across `encounter-content.ts` and four
  `src/data/encounters/` files. The plan named the first three; `order_freedom` was found by
  running the membership predicate rather than trusting the snapshot list.
- **`SPHERE_DRIFT_MAP`** (`encounterScoring.ts`) — nine of twelve rows named `mercy_ambition` /
  `tradition_progress` and were inert. The three that *were* live (order / matter / time) carried
  a sign **opposite to their own intent comments**, because the author's mental axis ran
  ambition-positive while canonical `loyalty_ambition` is loyalty-positive.
- **`WANDERLUST_PAIR`** — `'tradition_progress'`, so the whole travel discount was dead. Its sign
  convention already matched canon, so only the name changed.

## What shipped

Every legacy spelling swept to canon, `SPHERE_DRIFT_MAP` re-expressed pair-by-pair at the polarity
each row's own comment asked for, and a catalog-wide lint
(`src/testing/__tests__/valuePairVocabulary.lint.test.ts`) that fails the build if a non-canonical
motivation reappears. The lint scans the **source tree** rather than a `*_TEMPLATES` export: there
are well over a dozen such exports and only some feed `UNIFIED_ACTION_TEMPLATES`, so an
export-based guard would have passed the day a new content file landed in an unlisted catalog —
the same partial-coverage failure the vocabulary itself suffered.

This is a **behaviour change, not a rename**: a lopsided world-soul now genuinely bends its
mortals' values, a novelty-leaning mortal genuinely ranges further, and ~50 encounters now
contribute real desire signal. That activation is exactly what the plan asks for — converging two
scorers onto a half-dead personality signal would have made the board's temperament weights
fiction.

## Executor calibration decisions (recorded per plan § Grey zones)

- **`entropy` → `mercy_ruthlessness` at −1** (toward ruthlessness), not `loyalty_ambition`. The old
  row read `mercy_ambition +1 // +ambition (ruthlessness)`; under a canonical vocabulary that
  parenthetical has a real home, and it gives the mercy axis a proper opposition (`life` +mercy /
  `entropy` −ruthlessness) instead of one lone entry. Retune freely if §4 shadow scoring shows it.
- **`order_freedom` → `loyalty_ambition`**, on the in-repo precedent that `SPHERE_DRIFT_MAP`
  already binds *order* to `loyalty_ambition`'s loyalty pole.
- **`justice_mercy` → `mercy_ruthlessness`** per the plan's named target. Worth flagging: the
  legacy name tagged an *axis of concern*, while `computeDesireScore` is signed and so needs a
  *pole*. Those encounters now read as appealing to merciful agents.
- **`apotheosis-ascension.ts`** kept its deleted `tradition_change` deleted. A prior ticket removed
  it rather than repair it precisely because activation was out of that ticket's scope; this sweep
  repairs authored motivations, it does not re-author removed ones. Restoring it is a content call
  for plan doc 2. The stale comment there now says so.
