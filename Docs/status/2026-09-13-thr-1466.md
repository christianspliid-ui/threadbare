# THR-1466 — an appositive `{cast:*}` needs a name to apposit

*"The keeper, **The Keeper at the Crossing**, takes two coppers a crossing and swears it holds."* Three of the five slice parents introduced their cast member with an appositive and the token resolved to a definite noun phrase restating the role the sentence had just given.

## Neither branch the ticket offered is what landed

The handoff framed a two-way fork — **A**, cast NPCs get personal names engine-side; **B**, authored prose stops using the appositive — and recommended A. One measurement retires both.

`resolveSceneCastContext` renders `boundName ?? spec.spawnName`. So the string on screen is, when the key is unbound, **exactly the authored `spawnName`** — and the corpus already disagrees with itself about what a `spawnName` is for. Of the **eleven** appositive sites corpus-wide, **seven were correct the whole time**:

| Encounter | key | authored name |
| -- | -- | -- |
| The Border Levy | `sergeant` | Bram Oskell |
| The Crown's Summons | `herald` | Sef Aldwin |
| Standing the Line | `survivor` | Ilme Fenn |
| The Broken Seal | `rival` | Idren Kall |
| The Unclaimed Relic | `claimant` | Orin Vask |
| The Sign Over the Ruin | `witness` | Neven Arbeck |
| Toll of Blades | `serjeant` | Soren Vance |

Seven personal names across seven encounters is not a coincidence; it is the house convention, and it settles the rule. **Branch A would override a deliberately authored `spawnName`** and break the THR-713 contract that an unbound key renders it byte-identically — the one thing that sweep established. **Branch B would rewrite eleven sentences, seven of them correct**, to dodge four bad strings, and would delete a prose form that works everywhere the convention is followed.

So the fix is the third thing: **a contract between the two sides.** An appositive `{cast:*}` is allowed exactly when that key's authored name is a personal name. A deliberately anonymous cast member keeps the title form, and *its* prose gives up the appositive instead.

## Four sites, three different dispositions — and that is the point

- **`bridge_keeper`** → `Halda Brenn`, **`caravan_master`** → `Ferrin Oake`. Title-form names with no authorial reason to be; the appositive stays.
- **`stranger`** keeps `The Stranger at the Crossroads`. Its spec comment says the name *"keeps the register of the scene, which never tells you what he is"* — the anonymity **is** the encounter, so renaming him would have been a fix that broke the thing it touched. The prose moves the token into the subject slot instead: `'{cast:stranger} waits under the dead tree — no horse, no pack, no mud on his boots.'` That reads correctly whether the key binds or not, which is the test of the rewrite.
- **`keeper`** (The Table That Holds, the fourth instance the ticket flagged as needing cover) **was already `Hesta Ryle` and already rendered correctly.** Reported rather than "fixed" — the ticket inferred it from the prose shape without resolving the spec.

`The Paper-Seller` (the swindler) is title-form and **deliberately left**: it is a sobriquet, it is never used appositively, and it collides with nothing. The gate's predicate is the collision, not the name, so it passes — which is the difference between a rule and a style ban.

## The gate is the deliverable

Fixing four strings by hand leaves the trap armed, which the ticket said and is the reason this is not a three-line diff. `appositiveCastNameCorpus.test.ts` sweeps every registered template for the appositive shape and fails on a title-form name, with the failure naming the template, the path, the key and the offending string, and offering both exits.

Two design choices in it, both against the rot mode of the sibling sweep it sits beside:

- **The collector deep-walks the template** rather than naming prose fields. The four live sites are in `steps[n].narrativeTemplate`; an eleventh is in an aftermath `changes[].detail`. A field list would be a snapshot that rots the moment someone authors prose in a twelfth place (THR-688 rule A).
- **It checks the authored name, not the bound one,** and says so. A `reuseNpcRoles` bind may substitute a live NPC's name — itself a personal name, correct in the same slot. Authoring is the side that drifts; binding is not.

Anti-vacuity and falsification arms both present, because every assertion is a loop and an empty population would satisfy the rule for free: the population is asserted non-empty, `>5` appositives spanning `>3` templates, with both motivating keys present *and* resolving to a spec; `TITLE_FORM` is asserted to catch all four retired names and spare five real ones; `APPOSITIVE_CAST` is asserted to match the appositive form and **not** the subject form the stranger was rewritten into — without that arm a regex matching everything would pass the rule unfalsifiably.

**Red baseline confirmed on the real corpus**, not just the synthetic arms: reverting `bridge_keeper` to `'The Keeper at the Crossing'` reddens exactly the rule and reproduces the ticket's reported string verbatim —

```
encounter.slice.unsafe_bridge steps[0].narrativeTemplate uses {cast:bridge_keeper}
appositively, but that key's spawn name is "The Keeper at the Crossing" — a role
restatement, not a name. Either give the spec a personal name, or drop the appositive.
```
