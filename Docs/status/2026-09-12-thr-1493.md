# THR-1493 — the place the scene is *about*, told apart from the place the agent is standing in

*Deferral from [THR-1476](https://linear.app/threadbare/issue/THR-1476)'s corpus sweep (prose rule 7b), filed rather than rewritten there because the honest prose-only rewrite would have deleted the premise [THR-1182](https://linear.app/threadbare/issue/THR-1182) built the encounter around.*

The Table That Holds opened with `'{name} returns to {location}, the town that keeps a door
open for them.'` Every word of that is a claim, and two of them were false.

`{location}` enriches to `ctx.currentLocationName`, built from `getAgentLocation` — the
agent's **current** position. This scene arrives by seed: `SLICE_TABLE_SEED` fires
`SLICE_TABLE_DELAY_TICKS` (12) after The Grateful Kin, and an `encounter_seed` has no
spatial field, so it lands wherever the traveler has drifted to. The `reputation_with` edge
the parent wrote is real — it just sits on a different town than the one the opening named.
So the scene pointed at whatever place the agent happened to be standing in and called
*that* the town that keeps a door open for them.

## The fork the ticket left open, and why arm A got cheaper on inspection

The ticket offered arm **A** (read the inherited target) and arm **B** (wait for the
appointment primitive, [THR-1479](https://linear.app/threadbare/issue/THR-1479)), and costed
A as needing "the enrichment surface to expose the target". Reading the surface, most of
that was already there:

- `resolveSceneTargetContext` has always handled a **location-kind** target and returns its
  name — the `{target}` token would have resolved a town correctly on day one.
- `resolveSeedInheritance` (THR-697) already carries the parent's `targetId` onto the
  spawned action, re-validated against the live graph.
- The live stage adapter passes `activeAction.targetId` into `gatherNarrativeContext`.

So the target was reaching the enricher the whole time; the *opening* simply read a
different field. Arm B was not available anyway — THR-1479 is still in design.

**What genuinely was missing is the fallback, and that is the whole of the engine change.**
Bare `{target}` falls back to `'the other party'`, which is correct for a person and absurd
for a place, and the fallback is not hypothetical: a dead inherited target falls back to
self-target, and `resolveSceneTargetContext` returns `undefined` for a self-target. So the
one path that most needs a place name is the path that had none.

## `{target:place}` — the place the scene is about

One new token in `proseEnrichment.ts`:

```ts
tgt?.kind === 'location' ? tgt.name : ctx.currentLocationName
```

It is the only place token that is **true on both of an encounter's two arrival paths**.
On the organic draw the target *is* the place the scene stands in — the same node
`requiredReputationWith` is checked against — so it agrees with `{location}`. On the seeded
path it is the parent beat's town, which `{location}` cannot name by construction. And it
degrades to a place rather than to a person, covering both ways the target can fail to be
one (dead inherited target → self-target → no target block at all; or an agent-kind target).

It narrows rather than redefines: bare `{target}` on an agent-kind target still names the
agent, asserted in the test so the two tokens cannot quietly collapse into one.

## A confirmation from the surface the player actually looks at

`buildUnifiedEncounterStageModel` derives the stage's `locationLabel` from
`activeAction.targetId`, not from the agent's position. So the encounter header had been
showing the **inherited town** all along, on the same screen where the opening named the
drifted-to place. The change makes the prose agree with the header rather than contradict
it — which is a second, independent reason `{target:place}` is the right field, and it is
the reason this is not merely a wording preference.

## The openings

Both lose the journey verb, because no effect performs the journey — that was the THR-1476
sweep's actual finding, and it is not repaired by naming a different town:

- rural — `'{name} is inside the door {target:place} keeps open for them, and the room is already divided.'`
- urban — `'The door {target:place} keeps open for {name} lets them into a room already taking sides.'`

What survives is exactly what the graph can vouch for: a named town, and a standing with it.
The traveler being in the room is the scene's own present tense — the same arrival every
P1 opening in the file narrates, and not the thing the sweep flagged.

THR-1182's premise is kept intact: the town that keeps a door open calls in the one traveler
it thinks well of. It is now the *right* town.

## Evidence

`src/engine/__tests__/targetPlacePlaceholder.test.ts`, three arms against a **generated**
world (seed 42, medium) — a fixture would have invented both of the two nodes this is about,
and would have passed whatever the enricher did with them. The archetype and cosmology come
from `generateArchetypes(4, 42)` and `createBalancedCosmology()`, the same two calls
`npm run cli -- --seed 42 --map medium` makes, so no field is invented behind a cast.

The falsification arm is inside the test rather than only in the session log: `{location}`
must still render the *current* place on the very same context, so the assertion cannot
survive the two tokens collapsing. Confirmed by perturbation — deleting the new replace
reddens all three arms from the right branch (the residual strip blanks the token: *expected
'' to be 'Ardenmor Keep'*).

## Scope deliberately not taken

The ticket's defect §3 notes that a `templateId` seed skips the eligibility filter, so the
scene can land at a town the traveler has no standing with. That is **not repaired here**,
and it is not a prose defect: it is the seed path's documented relationship to
`requiredReputationWith`, affecting every seeded encounter with a gate, not this one. The
change makes the opening name the town the standing is *recorded against*; it does not
assert the band is met. Worth its own ticket if the slice wants seeded gates enforced.
