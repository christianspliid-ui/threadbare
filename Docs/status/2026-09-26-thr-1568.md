# 2026-09-26 — THR-1568: items that promise a burst when struck now give it

**Ticket:** [THR-1568](https://linear.app/threadbare/issue/THR-1568) · **Project:** Powers & Item Generation · **Plan:** none (the ticket carries the fix) · **Pillars:** Engine. Content N/A (no catalog entry changed; the fix makes the shipped entries true). UI N/A (`Browser-verify exempt: engine only`, per the Done-when).

## What was wrong

A `reactive` effect whose nested effect was a reach modifier — *"when attacked, Iron +0.03 for six ticks"* — was handed to `executeEffect` when it fired. The executor lists every modifier shape as "handled by effectResolver" and does nothing, and the resolver returned 0 for `reactive` without looking inside. So every such item fired and gave nothing.

## What shipped

- **Reaction windows** (`src/engine/effects/reactiveWindow.ts`). Firing a modifier-shaped reaction opens a window on the attachment's runtime state (`reactiveWindowTicksRemaining`, its own field so it cannot collide with a top-level `duration` on the same item). `effectTick` counts it down; the resolver's `reactive` arm reads the nested value while it is open.
- **Window lengths:** `duration` → its `ticks`; `decay` → until it reaches its limit, fading as it goes; `passive` / `permanent` → the reaction's own `duration` if authored, else the cooldown × `REACTIVE_UNTIMED_WINDOW_COOLDOWN_FRACTION` (1.0). Floor `REACTIVE_WINDOW_MIN_TICKS` (1). A nested duration's `destroyOnExpiry` is ignored — the burst ends, the item stays.
- **Executor routing:** fired reactions carry `mode: 'window' | 'execute'`; both raise sites (`raiseEffectEvent`, `phaseDoom`) skip `executeEffect` for windows via `shouldExecuteReactive`. Executor reactions (spawn, cascade, resource_manipulate, …) are unchanged.
- **Cooldown** unchanged: a raise inside it opens no new window.
- **Wiring guide:** Capability 23 gains item 5, what a nested modifier does.

## Census (shipped reactive-with-modifier entries)

19 entries across the reward and starter catalogs, each proven through the window path in `reactiveWindow.test.ts`: thornwood staff, hollowfang, hazel switch, petrified ironwood glaive, chainmail hauberk, mantle of the unremembered, the woven sky, ember sigil, the weeping icon, steppe mare, hearthbound hound, dawnfeather kestrel, deep stab wound, healer's touch, earthblood vigor, death-marked, bloodward, whispering eye, plague-touched.

Two of them key on triggers with **no producer** (`blessed`, `cursed`): they open their window correctly when raised, but nothing raises those events yet. Recorded in the wiring guide.
