# 2026-10-05 — THR-1743: the intent judge reads what the player will read

**Ticket:** [THR-1743](https://linear.app/threadbare/issue/THR-1743) · **Project:** Continuous Improvement · **Pillars:** process only (skills, plan template, one new list). Engine, Content and UI are N/A because no game code changes.

## Why

Christian directed this in chat on 2026-10-05. Across 92 judged plans, 4 of 412 intent-judge findings touched player legibility. Meanwhile the cold playtests kept finding exactly that: unreadable resources were filed in round 1 (THR-1607) and recurred in round 2 (THR-1713).

## What shipped

- **Dimension 12, *Player legibility*,** in `.claude/skills/intent-judge/SKILL.md`. It applies to UI-pillar plans and is scored as follows:
  - **VIOLATION** when there is no `### Player-facing text`, or the text is described but never quoted.
  - **GAP** when a surface is missing, a row has no exact words, a complaint class the plan touches goes unanswered, or there is no predicate playtest signal.
  - **Aggregation:** a VIOLATION joins rule 4 (Revise). The new rule 5 makes **any GAP on dimension 12 return Revise**, so a lone GAP cannot pass as Allow.
  - It is a separate dimension rather than an extension of dimension 3 (wiring). Wiring asks whether a surface is connected; this asks whether the player understands it. A separate row also keeps the score countable.
- **`Docs/ops/player-complaint-classes.md`:** the canonical list. It is seeded from rounds 1 and 2 with seven open classes, PC-1 to PC-7: unexplained resources and terms, hidden rolls, developer text, acting for the player, piled-up rows, one fact told two ways, and no direction. Each class says what a plan touching it owes. A § Lifecycle section sets the add, recur, retire and re-open rules. The file stays on `main` under the ops README predicate (rule 3).
- **Plan template:** the UI pillar gains `### Player-facing text` (surface, exact words, class touched, how the player understands it) and `### Playtest signal`.
- **`cold-playtest` skill:** the new step 8b updates the list after every non-dry round through a docs-only PR.
- **`design-governance.md` Step 8.5** names the new check.
