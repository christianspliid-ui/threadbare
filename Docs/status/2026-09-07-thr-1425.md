# THR-1425 — the elapsed-term sweep, and the one reading `durationLabel` gets wrong

**2026-09-07 · UI · Bug · Deferral · Encounter Experience**

THR-1423 fixed every *remaining* term. This ticket is its sibling on the **elapsed** and **duration** fields — `ticksAgo`, `ticksActive`, `durationTicks`, `tickLimit`, and the divine receipt's elapsed span. Same two laws (**Law 13** raw magnitude, **Law 14** engine vocabulary), different fields, and — this is the whole of the ticket — **not the same reading**.

## The design call: why `durationLabel` was not enough

The ticket flagged this as a decision rather than a swap, and it was right to. `durationLabel` floors at `one day`:

```ts
const days = Math.max(1, Math.round(ticks / TICKS_PER_DAY));
```

For a **term** that floor is correct — an agreement with three ticks left is still meaningfully a day of standing, and rounding it to nothing would under-report a live commitment. For an **elapsed span** the identical floor states something false: a schism that reformed three ticks ago did not reform `one day ago`, it reformed today.

So a sibling ships beside it, `elapsedLabel`, differing in exactly that one respect:

```ts
export function elapsedLabel(ticks: number): string {
  const t = Number.isFinite(ticks) ? Math.max(0, Math.floor(ticks)) : 0;
  if (t < TICKS_PER_DAY) return 'less than a day';
  return durationLabel(t);
}
```

**`less than a day` rather than a band.** The Law 13 amendment of 2026-08-12 rules out answering *"how much?"* with an adverb ladder — Christian's verdict on `grew steadily` was *"how can a player use that word to gage anything"*. `less than a day` is not an adverb: it is a bound stated in the same unit the rest of the ladder uses, so a player reads it against `four days` on the next row without translating.

**One function, not one per preposition.** It composes into every phrasing the call sites needed without owning any of them — `${elapsedLabel(n)} ago`, `held ${elapsedLabel(n)}`, `took ${elapsedLabel(n)} to resolve` all read as English at both ends of the range. The ladder is the reading; the preposition belongs to the sentence. Above a day it delegates, so there is still exactly one days/weeks ladder in the codebase and a `TICKS_PER_DAY` retune moves both readings together (UI Law 3).

## The sweep found seven sites, not five

The ticket listed five and stated its membership as a predicate per THR-688 rule A — *"every player-facing surface rendering any tick-denominated field as a numeral"*. That distinction earned its keep again. Two more real violations sat in `ThreadDetailView.tsx`:

* **`ThreadDetailView.tsx:914`** — `${ticksRemaining} tick${…} until the crisis settles`. This is a `ticksRemaining` site, so it was in **THR-1423's** membership too and that sweep missed it — to the *same* failure mode THR-1423 recorded for `FactionSheet`: the `tick${n === 1 ? '' : 's'}` pluralisation interpolation splits the literal the grep searched for. The identical trap caught the identical way, one ticket later.
* **`ThreadDetailView.tsx:987`** — `Schism Reformed — {ticksSince} tick{…} ago`, the `ticksAgo` shape under a different field name.

A third string in the same banner, `resolves at tick ${resolutionTick}`, was an absolute engine timestamp; it is now `the reckoning is already set`, and the banner no longer takes a `resolutionTick` prop at all.

The generalisable point, restated because it keeps paying: **a regex offered as a way to find a predicate's members is not the predicate.** Two consecutive tickets have now had their supplied grep under-match, and both times the count would have become the contract.

## What was deliberately not done — THR-1426

Done-when #2 read *"no player-facing surface renders a tick-denominated numeral"*, which taken literally sweeps in two more classes. Both were left, and filed:

* **Absolute tick timestamps** — `t{entry.tick}` in `ChronicleEntryCard` and `AgentDetailPanel`, `Tick {n}` in `MandateDetail`, `WorldPulse`'s tick row. A point in time, not a span. Converting one needs a **calendar** the game does not have; `AscendantSheet`'s `tickToNarrativeAge` bands the world's *era* and cannot say when one row happened relative to the row above it.
* **Per-tick rates** — `regen {n}/tick` in the attention top bar, `Cost:`/`Income:` in `HexChronicle`. A rate, whose numerator is a resource quantity in its own right. THR-1008 already banded exactly this shape on `ThreadsPanel`'s sustain row; whether that generalises, or whether persistent chrome falls under Law 13's ratified pool-balance exception, is a ruling.

Widening into either would have been a scope decision dressed as a sweep — the same call THR-1423 made when it filed this ticket.

## The verification worth recording

**Every arm was falsified against the branch its fixture actually exercises.** All seven call sites were reverted together and the suite re-run: **all six surface arms went red, plus both receipt arms**. The two ladder-only arms stayed green, correctly — the revert did not touch `elapsedLabel` itself — as did the instantaneous-working arm, whose zero-tick branch the revert preserves. The files were then restored and diffed byte-for-byte against pre-revert copies.

**Every elapsed arm renders both a sub-day and a multi-day value.** `elapsedLabel` delegates to `durationLabel` above a day, so an arm exercising only the multi-day branch would pass identically against `durationLabel` — proving the numeral is gone while proving nothing about the reading that was chosen. The floor *is* the difference this ticket makes, so it is the difference the guard has to be able to see.

**`ticksAgo` is derived, not a field, and three gates hide it.** There is no override prop — `getAgentStrategicHistory` computes `currentTick − entry.tick` — so the only honest fixture drives the real derivation. The first draft invented a `strategicHistoryOverride` prop that does not exist. Three separate gates then have to be satisfied at once, each failing *silently*: the card computes nothing unless `strategicState`, `graph` **and** `tick` are all supplied; the whole Designs block is nested inside `strategicSummary && (…)`, which is null when the agent has no project, control **or** history; and `history` is filtered on `actorId === card.id`. Any one wrong renders no Designs section at all and every arm passes vacuously. The arm now asserts `getByText('Designs')` first, so an empty surface fails as an empty surface rather than as a wording mismatch.

**The HexChronicle fixture sets `perTickCost: {}` deliberately** — a populated cost row renders its own digits two lines above the assertion, which would let a `not.toMatch(/\d/)` arm fail (or pass) for a reason that has nothing to do with `ticksActive`.
