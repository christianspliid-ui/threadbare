# THR-1065 — the orphaned trace-payload class is closed

**Shipped 2026-08-15.** Twenty payload interfaces declared a `category` literal and were never members of the `TraceEntry` union. Because `getTraces()` returns that union, `trace.category` narrowed to the literals its *members* declare — so `trace.category === 'forecast_computed'` was a TS2367 "no overlap" error, every reader laundered it through `as string`, and every emit site needed `as unknown as` to compile.

## What landed

**`DistributiveOmit` / `TraceEntryInput`** (`src/types/trace.ts`). Plain `Omit<A | B, K>` is not a union of omits — it resolves `keyof (A | B)` to the keys A and B *share* and collapses to one object type carrying only those. Applied to a ~200-member `TraceEntry`, every category-specific field (`encounterId`, `finalTier`, `channel`) became an excess property. The distributive form preserves discrimination, so a faithful payload type-checks as itself.

`summary` is optional on the input type **and only there**. `normalizeTraceEntry` has always synthesized one (`summary` → `message` → `type:action` → `trace:<category>`), so the runtime already tolerated its absence — while `TraceEntry` keeps it required for every reader. That is what let fifteen interfaces which never declared a `summary` join the union without growing a field their emit sites do not send, and it is the specific blocker THR-928 stopped at.

**The twenty joined the union.** The five in `trace.ts` already extended `TraceBase`; the fifteen under `src/types/traces/` now do. They are named one-by-one rather than via the `EncounterExperienceTraceEntry` / `MentorshipTraceEntry` aggregate aliases, because the ratchet that guards them scans the declaration at source level — an alias would satisfy the compiler while leaving the gate blind to which interfaces are covered. `TickHealthTrace` and `TickCrashTrace` are among them: the two traces a crash investigation reaches for first.

**Measured: 3448 → 3208 typecheck errors, −240.** The distributive omit alone accounted for −101, which was the checkpoint the ticket demanded before touching anything else (its filing comment: *"If it moves up, stop and report"*).

## The casts, and what they were hiding

117 `as unknown as` casts sat at emitTrace boundaries. Five came out where the payload proved correct; `src/types/__tests__/trace-cast-ratchet.test.ts` now pins the remaining **112 as a ceiling that may only fall**, so the count falls as a ratchet rather than in one all-or-nothing diff — the sequencing the ticket asked for.

Two casts were **kept, with reasons**, because removing them exposed genuine divergence between emitter and interface — which is the whole argument for the ratchet:

- `ForecastComputedTrace.factors` is declared `string[]`; the hand-filter phase sends an `EncounterForecastFactors` object.
- `HandFilteredTrace` declares only counts; the same phase has always also sent `playableTemplateIds`, `dimmedTemplateIds` and `hiddenTemplateIds`.

Both are filed as [THR-1117](https://linear.app/threadbare/issue/THR-1117/two-emittrace-payloads-diverge-from-their-declared-interfaces-the). Each needs a decision about what the trace should *contain*, which is a different question from the type wiring this ticket was scoped to.

## Why it mattered

Not the `as string` in the title. The cost quoted on the ticket is THR-1082's, which raised the committed typecheck baseline 3447 → 3450 rather than drop fields from three new traces, in a file already carrying 141 errors of this class: *"the alternative was removing inspectability to satisfy a gate."* Every engine change adding a trace to those twenty types faced the same fork between NFP #2 and a green ratchet. That fork is gone, and the baseline moved 240 the other way.
