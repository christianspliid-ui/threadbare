# THR-1313 — a no-op ternary in settlement naming, and its twin the ticket did not know about

**Shipped 2026-08-28.** Engine pillar only. Content N/A — no name string changed, proven
by golden comparison. UI N/A by path — no component file touched. Browser-verify exempt:
engine-only change, no UI-pillar files touched. Deferral filed at THR-1297 slice 6
closeout, recorded in its recon record as *"`worldSeed.ts:370-374` no-op prefix ternary"*.

## What was wrong

`src/engine/worldSeed.ts` chose a settlement name through two branches, and **both**
tested `suffix.startsWith(' ')` and then rendered the same template either way:

```ts
if (usePrefix) {
  name = suffix.startsWith(' ')
    ? `${prefix} ${root}${suffix}`
    : `${prefix} ${root}${suffix}`;   // identical
} else {
  name = suffix.startsWith(' ')
    ? `${root}${suffix}`
    : `${root}${suffix}`;             // identical
}
```

## The finding — the ticket's premise was wrong, and that is the whole answer

THR-1313 framed this as an open question with two readings, and instructed: *"Read the
`else` branch's two arms to see what distinction it draws, then decide. **Do not collapse
the ternary without answering that.**"* It expected the sibling branch to encode the
intended behaviour, hedging with *"presumably does distinguish"*.

**It does not.** The `else` branch's arms are byte-identical too. There is no sibling
encoding an intended form, because neither branch encodes one — so the instruction to
read the sibling has no answer, and the ambiguity the ticket was filed to resolve
dissolves rather than being decided.

That settles it as reading (b) — dead scaffolding — and it settles it on stronger
evidence than reading (a) could ever have been given, because reading (a) required a
correct sibling to have existed somewhere. Nothing has been shipping subtly wrong.

## Why no distinction was needed in the first place

The separator is carried by the **suffix data itself** (`LOCATION_SUFFIXES`), and the two
classes are deliberate:

- settlement tiers are agglutinative — `hamlet: ['bury','ton','wick',…]`, `city:
  ['city','polis','haven',…]`
- place tiers lead with a space — `camp: [' Camp',' Rest',…]`, `tower: [' Tower',' Spire',…]`,
  `shrine: [' Shrine',' Altar',…]`

So plain concatenation is already correct for both: `'Wolf' + 'ton'` → `Wolfton`, and
`'Wolf' + ' Pastures'` → `Wolf Pastures`. Both appear in the seed-42 world. A
`startsWith(' ')` test has nothing to do because the data has already answered the
question it would ask — which is why the ternary could sit there identical-armed for so
long without anyone noticing a wrong name.

## What shipped

Both ternaries collapsed to their single form, with a comment recording *why* there is no
separator branch — so the next reader does not re-file this as a missing distinction:

```ts
if (usePrefix) {
  name = `${prefix} ${root}${suffix}`;
} else {
  name = `${root}${suffix}`;
}
```

**PRNG safety is the load-bearing property.** `suffix.startsWith(' ')` consumes no `rng()`,
so removing it cannot shift the seeded stream — worldgen output is byte-identical, not
merely equivalent. Had the removed expression drawn from the stream, every downstream
world object would have moved and this would have been a worldgen change wearing a
cleanup's clothes.
