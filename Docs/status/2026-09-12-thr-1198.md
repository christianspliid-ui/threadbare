# THR-1198 — the campaign spine narrates in the voice of what the god remembers

**Shipped 2026-09-12.** The mandate milestone prose had a correct resolver, two live
wiring sites, a trace, and no reader: THR-1197's 48 authored strings were keyed to the
12 template mandate ids, and nothing in a live game instantiates a template mandate.
Every stage transition since that wiring landed took the fallback branch.

## The ruling

The fork was genuine — does a run's spine come from *what the god remembers*, or from
*a named campaign the world offers*? Ruled 2026-09-11 for remembrance, under Christian's
standing delegation: every run opens with the remembrance flow, the god's Hunger is the
identity the player chooses, and the mandate is derived from it. A named campaign would
be a second way of choosing what a run is about, competing with the choice the player
already made. Option 2 declined.

## What shipped

**Content.** `src/data/mandate-remembrance-prose.ts` — 96 authored lines across two
tables, keyed to the two ids `generateRememberedMandate` actually mints:

- 12 Hungers × 4 transitions — the identity path (`gameInit.ts:512`), what every real
  playthrough holds.
- 12 Spheres × 4 transitions — the identity-less path (`gameInit.ts:306`: the CLI, and a
  bare `?view=game`), whose id is `remembrance.{primary}_{secondary}`.

The second table is keyed on the **primary sphere, not the pair**. The pair form's key
space is 132 ordered pairs, which could not be authored honestly or kept true; the
primary is what the mandate is named for and what the god is asked to raise, so 12 rows
cover all 132. The Hunger table takes precedence, because what the god *wants* is a
better beat than which sphere is rising.

**Engine.** `resolveMilestoneProse` gained an explicit two-step chain — exact id, then the
sphere family — taking `primarySphere` from the live `MandateDefinition` rather than
parsing it out of the id, so a future Hunger named after a sphere cannot collide. The
result now carries the winning `key`, and `phaseMandate` traces it, so a run narrating
from the sphere family is visible as such instead of indistinguishable from an exact hit.

**Retirement.** `generateMandate` — the only route to a template-mandate id, with zero
production callers — is gone, with `mandateGenerator.test.ts` and the one test in
`mandate-integration.test.ts` that exercised it. The 48 template prose strings went with
it: a template's prose describes that template's own region-count conditions and could not
be re-keyed onto a sphere-delta mandate without being rewritten. Four `MANDATE_*_WEIGHT`
constants that weighted only that selection were retired from `game-config.ts` and from
both CMS surfaces — a tunable that moves no number is a dead control that reads as live.

The 12 template JSONs **survive** as a catalogue: they still feed the CMS browser and the
`mandate.*` tooltip resolver. Only their unreachable half was removed.

## Deviation from the handoff, recorded

The handoff named both test files for deletion. `mandateGenerator.test.ts` was wholly
about the dead contract and is gone. `mandate-integration.test.ts` also covers
`evaluateMandate`, `advanceMandateStage` and `evaluateCondition` — all three live, all
three called from `phaseMandate.ts` — using the templates as the only fixture carrying
graph-condition stages. Deleting the file would have removed live coverage, which is the
opposite of what "no green tests on a dead contract" asks for. Only the dead test was cut.
