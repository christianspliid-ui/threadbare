# THR-1240 — the executors succeeded and the world kept nothing

*Stage 2 of the six-stage effect-vocabulary activation program (THR-1239 → THR-1240 → THR-1241; THR-1242/1243/1244 behind their blockers). Plan doc: `Docs/plans/2026-08-25-effect-vocabulary-activation.md`.*

## What was wrong

`executeAlterTerrain` and `executeModifyRules` have always worked. Both build a fully-formed `ActiveTerrainOverlay` / `ActiveRuleOverride`, hang it on `ExecutionResult`, and return `success: true`.

Every consumer read `result.mutations` — which both executors leave **empty** — applied the (zero) graph writes, and dropped the other two fields on the floor. So `alter_terrain` blighted nothing, `modify_rules` overrode nothing, and both reported success every time.

This is the failure mode the interface map exists to catch and the one static analysis is worst at: the write site exists, the read site exists, a symbol grep is green on both halves. The deadness is *value-level* — `mutations` is populated for twenty-odd other primitives and empty for exactly these two, so the shared consumer loop looked complete and was not.

## What changed

**The destination.** `GameState.activeTerrainOverlays` (hex-keyed via `hexKey(col,row)`) and `GameState.activeRuleOverrides` (agent-keyed). Keyed rather than flat because stage 3's consumers are hot paths — movement cost per step, awareness range per encounter scan — and a flat array makes every one of them a scan. Deliberately GameState and not node properties: an overlay is transient rule-state, not a world fact.

**One apply path.** The drain went into `applyExecutionResult`, and `phaseDoom`'s duplicated inline mutation loop was migrated onto it rather than left as a second copy. That is the actual repair: the bug was not that someone forgot to handle two fields, it was that *two* call sites each independently handled a subset of a result and nothing made the subset visible. There is now no call that applies part of an `ExecutionResult`.

**Expiry.** One world-level pass in the orchestrator's effect-tick phase, running every tick regardless of whether any actor bore an effect — an overlay outlives the agent that cast it, so a per-agent walk would strand it. Emptied keys are dropped rather than left as `[]` buckets that accumulate for the run.

**One stacking fold.** `foldRuleOverrideValues` decides the semantic once per key family: multiplicative for `*_multiplier`, additive for `*_bonus`/`*_modifier`, boolean-OR for `death_prevented`, first-wins for string/struct. Exported, because stage 3's eleven owning sites must fold identically whether the value arrived from an attachment or from the persisted collection — two folds for one key is exactly the drift it prevents.

Multiplier folds clamp symmetrically into `[1/3, 3]`. The downward direction is the one that matters: nothing bounds how many attachments an agent may carry, and an unclamped `0.0001×` movement-cost multiplier does not slow movement, it stops it.

**One read path.** `getActiveRuleOverride` now optionally folds the persisted collection in alongside the attachment-declared effects. Its only existing caller passes an additive key and is unaffected. One semantic change worth naming: the neutral return for a `*_multiplier` key is now `1.0`, not `0` — as a multiplier, `0` means "annihilate the quantity", which is the opposite of "no override active".

## What this does *not* yet do

The catalog's own `alter_terrain` entries (`artifact-templates.ts`) sit behind artifact activation, which is still dormant. The live producer today is a reactive nested effect — reachable because THR-1239 raised the events. **Stage 4 is what puts catalog content on this path**, by migrating `create_barrier` onto `alter_terrain`. Stage 3 wires the eleven rule-override consumers at their owning sites; this stage deliberately stops at the store.

Said plainly: the plumbing is connected and proven, and the taps that feed it open in later stages.

## Evidence

`npm test` → 1074 files / 17780 tests passed (+1 file, +21 tests — exactly the new suite). `check:typecheck` ratchet 3012 → **3010**, two fewer, from deleting `phaseDoom`'s duplicated cast loop. `npx vite build` green. Engine smoke reached tick 30 with 384 agents and 42 events.

The coverage is falsified, not assumed: disabling the single drain line fails **exactly** the two end-to-end tests and no others (2 failed / 19 passed). The suite drives the real executors rather than hand-built overlay literals — a fixture that constructs its own `ActiveTerrainOverlay` and asserts the store kept it would pass identically against the broken build, because the break was never in the store.
