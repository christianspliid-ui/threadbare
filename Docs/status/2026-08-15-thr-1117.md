# THR-1117 — two emitTrace payloads reconciled with their interfaces

**Shipped** 2026-08-15 · project *Continuous Improvement* · labels `Deferral` `Engine` `Improvement`

THR-1065 made the twenty orphaned trace-payload interfaces `TraceEntry` members and gave
`emitTrace` a distributive input type. Two casts in `phaseAscendantHandFilter.ts` could not
then be removed, and were retained with a one-line reason each because reconciling them was
a decision about what the trace should *contain*. This is that decision, and it went one way
for one payload and the other way for the other.

## `HandFilteredTrace` — the interface was missing three fields, so it gained them

The emitter has sent `playableTemplateIds`, `dimmedTemplateIds` and `hiddenTemplateIds`
since the trace was authored; the interface declared only the counts (`totalDeckSize`,
`playableCount`, `dimmedCount`, `hiddenCount`, `rarePulses`). Declaring them is the fix
rather than dropping them, on NFP #2: this is the surface that answers *"why was this card
not playable?"*, and a count cannot answer it. `dimmedTemplateIds` carries the
`HandFilterPrereqCode` that gated each card — `cost_unavailable`, `sphere_prereq_missing`,
`bond_tier_too_low`, `place_gated` — which is the whole diagnostic value.

`hiddenTemplateIds` is declared `string[]`, not the structured shape the ticket described.
The emitter sends bare ids there and is right to: `HandFilterHiddenCode` has the single
member `target_mismatch`, so there is no varying reason to carry. The interface now says
what is sent rather than what was assumed.

The prereq-code import is `import type` from the engine, following the rule the file already
states for its deliberate `TraceBase` cycle — erased at build, so the types → engine
direction never reaches the module graph.

## `ForecastComputedTrace.factors` — already correct, and the ticket's fix would have broken it

The ticket asserted `factors` was declared `string[]` while the emitter sends an
`EncounterForecastFactors` object, and prescribed declaring the latter. That is wrong, and
the ticket's own instruction — *"confirm which shape the trace inspector and any log-export
consumer actually read first"* — is what proves it:

- The emitter sends `computeForecast(...).factors`. `OutcomeForecast.factors` is `string[]`,
  built by `sanitizeFactorPool`, which trims, drops non-strings and de-duplicates. The
  declaration matched the payload all along.
- `ForecastFactorsInspector` reads `.length` and `.map`s each entry into a React child as a
  string. `string[]` is exactly its contract.
- The quoted `TS2322: Type 'EncounterForecastFactors' is not assignable to type
  'readonly string[]'` is **real, and at line 151** — the *call* to `computeForecast`, where
  the authored beat tuple `readonly [string, string?, string?]` flows into
  `ForecastBeatInput.forecastFactors: readonly string[] | undefined` and the optional slots
  make the element type `string | undefined`. It is a pre-existing baseline error with
  nothing to do with the trace, and it is still there, still baselined.

So `factors: string[]` stands, with a comment recording why it was checked and left — the
next reader inheriting the finding rather than "fixing" it back. Logged as impediment #603:
a compiler error quoted in a ticket is evidence that something is wrong, never evidence
about which line is wrong.

## The two casts were themselves the two errors

Removing them dropped the typecheck **3184 → 3182**. The baseline recorded 4 errors in
`phaseAscendantHandFilter.ts` and 2 remain, both pre-existing and untouched (the line-151
tuple variance above, and a TS2367 `sublocation` comparison at line 78). The casts targeted
`Omit<TraceEntry, 'id' | 'timestamp'>` — the collapsed shape THR-1065 *replaced* with the
distributive `TraceEntryInput` — so each retained cast had become a type error in its own
right, laundering a payload into a type the emitter no longer accepts. The now-orphaned
`TraceEntry` import came out with them.

This is a genuine decrease, not the THR-1128 pathology: `node_modules` is healthy here (the
full suite ran 16,277 tests), the drop is 2 of 3184 rather than a collapse to zero, and it
is nowhere near the 50% `SUSPECT` ratio that gate now refuses.

The emitTrace cast ratchet is re-pinned **112 → 110** with its history line extended.
