## What this slice did

Christian's directive of 2026-08-06 carried three complaints. **The third is fixed and shipped**; the first two are substrate-only so far.

### The feedback complaint, fixed (*"when you play one you don't really get feedback"*)

The Divine Receipt was wired end to end — phase registered, modal mounted, `aftermathSummary` written unconditionally. The plan's diagnosis-first instinct was right, and the measurement found the gap is the toast's **content**, not its tier: `decidePresentation` sends 28 of the 30 beat-grantable templates to the toast tier, and the toast message was unconditionally `` `Your ${template.name} ${outcomeBandWord(band)}.` `` — the template's *internal* name and one band word. The `overview` the resolver had already built, and the modal had always shown, was discarded. So the feedback existed, was wired, and reached the player as *Your Bless Harvest held.* on ~93% of casts.

The toast now carries the overview's first sentence, falling back to the band's frame line. Two things were found doing it:

- **The toast message had never been asserted by any test.** That is why the sentence survived every suite. Four arms now pin it.
- **The enricher *strips* an unresolvable placeholder rather than leaving it visible**, so `{cast:subject} walks away unharmed.` arrives as `walks away unharmed.` — no `{` to detect, subject eaten, opening lowercase. That fragment class is what the plan's kill criterion names, and it is much likelier than a visible token, so the guard is on the opening character rather than on the brace. Measured, not reasoned: the first version of the test asserted the brace and failed.

`toastOverviewUsed` rides the existing `player_receipt` trace (registered on the interface, not duck-typed), so the fallback *rate* — the kill criterion's actual threshold — is measurable rather than asserted.

### One card face

`src/components/shared/CardFace.tsx` is the nudge card's ten-zone stack extracted verbatim; `NudgeCard` is now a thin adapter over it. The extraction's only proof is that the nudge card's DOM did not change, so the snapshot was **written and committed first** (`368402c8`), eight arms, one per optional zone — and it passes unchanged.

That pin caught two faithfulness defects, both mine, both of which would have shipped silently:

- The provenance zone's accessible name is the producer's assembled `text`; my primitive re-composed it from the parts. A screen reader and a sighted reader must not get two independently-built sentences. (The pin's *first* baseline was itself taken from a fixture omitting that required field — it was re-taken against the unmodified component before the extraction landed, so the baseline is a real pre-change DOM.)
- `designerLine` had to become a `ReactNode` to keep the nudge line's exact node structure.

### The engine readout the card rewrite will consume

`castForecastProbability` turns a cast into the probability the roll will use, and the slot now carries `forecastTier`, `scaleWord` and `upkeepWord` — words, with the numerals left behind the designer view. Nothing renders them yet; `__DEBUG`/`listActions` sees them.

The invariant is pinned **against `computeResolutionThreshold` itself** across the measured capability × difficulty × scale range, not against numbers re-typed in a test. That pin immediately earned itself:

> **`castForecastProbability` must not reuse `effectiveCastDifficulty`.** That helper early-returns `0` for an unpriced step, because its job is *"may the card claim a risk?"*. But the resolver does not skip the scale offset for an unpriced step — at `cosmic` it **adds** `+0.10`. So a zero-difficulty cosmic working really does roll harder than the god's bare capability, and a readout built on the presentation helper would have quoted capability flat, overstating the odds on exactly the scale where the stakes are highest. Caught at cap 0.2 / diff 0 / cosmic: 0.2 vs 0.1. The plan's "a zero-difficulty step is `fated` by construction" is true at `personal` and `local` only, and the docstring now says so.

### Detection risk, retired — and a live bug found behind it

`detectionRisk` has left `WheelSlot` with every write and read. The card's `{X}% risk` zone could never render (the only live builder hardcoded `0`, the zone was gated `> 0`) while `ActionCard.test.tsx` asserted `10%` against a fabricated fixture — a green test on an unreachable path. Both are gone.

**The concept did not go with it.** The `computeDetection` verdict the ticket asked for: **live** — `useAgentInteraction:428` → `executeIntervention` → `computeDetection`, so the eight authored `INTERVENTION_DEFINITIONS` values stay. And the grep that established it turned up a read the plan's list had missed: `InterventionConfirm` was being fed `slot.detectionRisk`, i.e. the hardcoded zero, so **the intervention-confirm popover has been quoting "0% risk" on interventions whose authored risk runs to 0.6** while the roll used the real value. It now reads the authority directly.

### The overlay the agent hand was skipping

`AGENT_INTERVENTION_TEMPLATES` spread its source arrays raw, so the `ACTION_TECHNICAL_EFFECTS` overlay reached `UNIFIED_ACTION_TEMPLATES` and not it: **0 of 44** carried `technicalEffect`. Since the agent hand is where most casts happen and the drawer's Effect block is gated on that field, that block — and the THR-728/998 cast line nested inside it — never rendered there at all. Both registries now run one named `withTechnicalEffectOverlay`. **Measured after: 44/44.** Pinned by comparing the registries rather than by a count, because a count rots on the next template *and* would still pass if both regressed together — which is how this arose; plus a non-vacuity arm, since the comparison is over the intersection (44/44 today).

## What remains, and why it is a second pass

The visual half — `ActionCard` rewritten onto `CardFace`, the drawer's fan replaced by the card row, one Cast button, the ~33 authored effect lines, the `castHintLine`/`riskHintLine` retirement, the tooltip ids, `GameView`'s `resolvedBands` — is one coherent change whose Done-when is a **1920×1080 browser capture asserting no numeral, no percentage and no raw key anywhere in the drawer.** Splitting that across a commit boundary would mean shipping a half-converted card; doing it in a run that cannot start a dev server would mean verifying the most visual change in the ticket by substitution. It is the next pass's work, and the foundation it needs is now on `main`.

The slot's three new fields are deliberately unconsumed in the meantime: additive, inspectable, and harmless (NFP #6).
