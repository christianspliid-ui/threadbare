# THR-1307 — the ascendant's hooks had a reader pointed at nothing

**Shipped 2026-08-28.** Project: Continuous Improvement. Pillars: UI (Engine/Content N/A —
no engine or content change; the producer already existed and was already correct).

## The finding, and the verdict

`HooksBlock` and the `AscendantBar` count beside it both walked
`graph.getOutgoingEdges(ascendantId, 'has_attachment')`. Three things were true of that
edge type, and all three had been true since the block was written: it is not a member of
`EdgeType`, it has no `EDGE_SCHEMA` row, and nothing anywhere in the repo has ever written
one. `src/data/__tests__/graphOp-patterns.test.ts` has documented the gap since the
graph-op migration — *"wounds must use `has_trait`, not `has_attachment`"* — and still pins
the absence.

So the loop iterated an empty array in every world that has ever run. The Conditions, Clues
and Vows rows were unreachable code, the count beside the section header was structurally
zero, and the bar rendered *"No marks, clues, or vows."* forever. The ticket asked which of
three things this was, and named the third as the one worth ruling out explicitly, because a
surface that renders nothing looks exactly like a surface whose data merely happens to be
empty this run.

**The verdict is repoint — the producer exists and always did.** `devSeedAscendantTestPackage`
(`src/engine/gameInit.ts`, the function `?view=game&seeded` calls) writes exactly these three
rows onto the ascendant node and has for as long as the block has been dark:

| Row | Carrier | What the seed writes |
|---|---|---|
| Conditions | `has_trait` → trait node, `subcategory: 'condition'` | Veiled · Thornmarked · Unforgotten · Cold of Eye |
| Clues | `has_trait` → trait node, `subcategory: 'clue'` | Whisper of the First Fall · Rumor: The Sunken Vale · The Thornweaver's Third Name |
| Vows & Bonds | `relates_to` edge carrying `agreement` properties | Pact: Thornweaver · Oath: The Still Hour · Debt: The Grey Seer · Bound: The Watching Tower |

Those are the same three families `getAgentAttachments` reads for the character sheet, so the
bar and the sheet now agree on what the player holds rather than disagreeing in silence.

## What the repoint uncovered

Two defects had been sitting in unreachable code, invisible precisely because nothing reached
them. Both are fixed here, because making the chips render is what releases them.

**`resolveChipLabel` read the wrong field.** It resolved `node.properties.name`, and a
`GraphNode` keeps its name **top-level**. Every seeded condition and clue would have rendered
the Law-14 fallback (*"An unnamed mark"*) and warned once about a name that was there all
along. The property spelling is kept as a secondary read, because authored content uses it.

**The chip advertised a control that does nothing (Law 25).** `role="button"`, `tabIndex={0}`
and an Enter handler were unconditional, while `HooksBlock` passes no `onOpen` at all —
a keyboard-focusable control that silently does nothing. The affordances now render only when
a handler is supplied. The hover explanation, which is the chip's real Tier-1 affordance, is
untouched.

One further law bound the code being added rather than the code being uncovered. The vow
label's unnamed-content fallback interpolated `agreement.type`, putting the raw enum on the
surface as `debt with The Grey Seer` — Law 14. It now takes a display word
(`AGREEMENT_TYPE_WORD`), and an unrecognised type takes the bucket's plain-English stand-in
rather than a word invented for it.

## Count and chips are one walk now

`extractChips` is exported and `AscendantBar`'s `hookCount` is derived from it. The count
previously ran its own `getOutgoingEdges(…).length` — counting *edges* where the block renders
*bucketed chips*, so a header reading "4" above three chips was reachable the moment either
side started working. A `bestowed` power rides the same `has_trait` family and is deliberately
not a hook; the count drops it exactly as the block does, and a test pins that.

## Evidence

Tests are written against the **real producer and the real reader** — a real `WorldGraph`,
seeded by `devSeedAscendantTestPackage`, rendered by the real component. That is what makes
the repoint falsifiable: revert the reader to `has_attachment` and every positive assertion
goes red, because nothing puts an edge of that type on a graph for it to find. The empty
state is asserted separately, so *"the chips render"* is a claim about this world rather than
about the component always rendering.

Typecheck ratchet 2957 → **2954**, a net decrease of 3 — the baseline error the ticket named
(`HooksBlock.tsx(119,63): Argument of type '"has_attachment"' is not assignable to
'EdgeType | undefined'`) is gone along with two of the same shape. Baseline refreshed.

`has_attachment` survives in `src/` only as two deliberate guards: the
`graphOp-patterns.test.ts` assertion that it is *not* an `EdgeType`, which is what keeps the
phantom out, and one premise assertion in the new test proving the seed writes none. Deleting
either would remove the guard rather than the ghost. No reader remains.

## Filed, not fixed

**Law 1 — the chips carry a tooltip but no image and no link.** Every game concept the player
sees carries its presentation: image, tooltip, and link where a page exists. These chips are
concepts (conditions, clues, agreements) and until today none of them rendered, so the gap has
never been live. It is now. Filed rather than folded in, because giving a condition chip an
`EntityVisual` and a route into the attachment surface is design work on the bar's anatomy,
not part of pointing a reader at the right edge.
