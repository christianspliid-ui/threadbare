# 2026-09-29 — THR-1674: a journey's goal is the encounter here, not a twin in another town

**Ticket:** [THR-1674](https://linear.app/threadbare/issue/THR-1674) · **Project:** Thematic Pressure & Living World · **Pillars:** Engine (arrival commitment in `phaseAgentDecision.ts` + `decisionBoard.ts`); Content N/A (no authored data changes); UI N/A (engine only — `Browser-verify exempt: engine only` per the ticket).

## What was wrong

A mortal who walked to an encounter and found it gone on arrival committed to *any* copy of the same template on its board — the legacy commit scaled every copy, and the unified board's fallback ("none at the destination → every instance carries it") did the same. A copy in the town just left won, and the mortal walked back. The arrival was logged `journeyGoal: kept`, so the decision trace hid it: `dropped` read 0 on every seed.

## What changed

- **One instance carries the goal: the one here.** "Here" = the journey's destination, or a location on the arrival hex (awareness is hex-granular). The cap-stage flag, the legacy commit and the board's `arrivalGoal.locationId` all name that instance.
- **No copy here → `dropped`.** Copies elsewhere compete on their own scores, with no commitment.
- `decisionBoard`: `arrivalGoal.locationId` now binds strictly; the "every instance" fallback survives only for a goal given without a location. The THR-1668 test that pinned the fallback is inverted.

## Evidence

- Re-chase probe (all mortals, attended medium world, 150 ticks): arrival decisions that re-picked the goal template at another hex — main: 3 in 23 seeds (1, 14, 19); after: 0 on seeds 1, 14, 19, 42, 99, 11, 7, 123.
- `first-encounter-gate` 42,99,11,7,123 @150: all PASS, gaps 24/14/16/28/23 — identical to main, so THR-1639's rhythm holds. (On today's main the five seeds already passed: THR-1663/1670/1671 moved the worlds off the seed-42 round trip, so the gate alone no longer reproduces the defect — hence the probe.)
