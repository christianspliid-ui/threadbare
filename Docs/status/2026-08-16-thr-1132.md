# THR-1132 — `check:encounter-live` stops failing gate-clean content (2026-08-16)

**Stage 4 was asking a question one run cannot answer.** `systemConnections()` reports what a template declares *anywhere* — across every outcome band and every aftermath reaction — and the live proof asserted all of it must arrive on a single run that rolls one band and applies one reaction. Everything authored off that path read as a missing block. Measured baseline on THR-1131's six: **1 proved / 5 failed**, every ✗ an artifact. After: **6 proved / 0 failed**, and corpus-wide **55 → 81 proved, 95 → 59 failed, zero templates regressed** out of `proved`.

**The scoping rule is per-reaction, not per-run, and that distinction is the whole fix.** A new `systemSurfacesForOutcome()` in the Composition Contract walks the same authoring tree `systemConnections` does — one predicate, two consumers, per that module's own rule — and tags each connection with where it sits: reachable on the rolled band, carried by named reaction *ids*, or authored on a band fate did not roll. An earlier revision passed a boolean "some reaction fired" and reported `swindled_family`'s seed as a **failure** on a run where the engine had autonomously applied a different reaction; ids are what tell `leave_them_to_it` from `make_the_town_haunted`. Claims off the run's path now report `not_declared` **with the reason on the row** — `seed rides reaction(s) …; this run applied '…'` — because a skip that says why is inspectable and a skip that vanishes is how a sweep goes quiet.

**Reactions now actually fire, and the engine is usually the one firing them.** `processAutonomousAftermath` applies a reaction for any non-hero actor, and the ascendant is not in its hero set — so it had already run by the time the proof looked, and the resolver's THR-1112 refusal (`alreadyApplied`) was being read as "no reaction fired", scoping away the very claims the pick exists to prove. The proof now reads that refusal structurally and recovers *which* reaction fired from the engine's own `reaction_selected` trace rather than re-deriving a personality-aligned rule that would drift within a month.

**`cast_bound`'s root cause is the harness, and the diagnosis is unambiguous.** The ascendant carries **no `located_at` edge at any tick** — measured 0 through 12 in a seed-42 medium world — so `resolveAnchorLocationId` exhausted its options and anchored the support bundle on the *ascendant's own actor node*. `findExistingActorSupport` then looked for NPCs standing "at" an actor, found none, and every `pre-seeded` spec resolved to `null`; `bargain_at_crossroads` passed alone because its `stranger` spec is `lazy-materialize-on-trigger` and ignores the anchor. The engine is not at fault and both live callers already anchor properly — the debug spawn path refuses outright with *"has no location anchor for encounter testing"*, `phaseAgentDecision` passes `sel.entry.locationId`. `anchorAscendant()` now stands the ascendant at a deterministically chosen, populated, authorable location.

**A second layer sits behind it, and it is data, not code.** Even correctly anchored, the `wayside` default bundle reuses `hermit`/`wanderer`/`pilgrim`/`ranger`/`hunter`, and worldgen seeds **none of those anywhere in the world** — the eight populated `camp` locations hold the military-outpost roster (`commander`, `quartermaster`, `mercenary`, `guard`, `scout`). That is not a defect to fail on: `default-support-bundles.ts` states the rule itself — a bind-only default that finds nobody "stays unresolved … which is the honest outcome rather than a spawned prop". So `cast_bound` now separates a **template-authored** bundle (a promise the encounter makes, still a hard fail) from a **family default** (an opportunistic attach, reported `not_declared` with its reason), via `hasOnlyDefaultSupportBundle()` comparing spec identity. The dead-vocabulary question is filed as impediment #610, not silently absorbed.

**A fourth false-fail surfaced once the first three cleared.** `grateful_kin` promises its reward as a `favor_creation` on the reaction that fires; the applier writes a favor **edge** and a trace and never touches `aftermathSummary.changes`, which is the only place `reward_node` looked — so an arrived reward read as missing. `PERSISTENT_EFFECT_KINDS` counts 24 such kinds and almost none produce a change entry. Arrival now also accepts the effect's own trace, filtered on `success !== false` so a skipped effect is still a failure and the check cannot pass vacuously.

**Scope note.** The diff is infrastructure only — no content changed. An exploratory pass added `concepts` to `snow_on_the_pass` and `riders_behind_caravan` before it emerged that neither is in THR-1131's batch (its six are bridge, kin, family, swindler, crossroads, full moon); both remain on `RETROFIT_PENDING` for THR-1130's cadence and the edit was reverted rather than pre-empting that batch. One test did change: `compositionContract.test.ts`'s red example pointed at whichever shipped template was currently worst, which made it hostage to every content improvement — it now builds a synthetic non-compliant fixture, the repair the file's own comment anticipated.
