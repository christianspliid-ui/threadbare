# THR-857 — the possession vocabulary stops having two of itself

**Shipped 2026-08-22.** Filed as five content sites writing `subcategory` values outside the seven-member `PossessionSubcategory` union. The five were real and are rewritten. The part worth reading is why the gate that stops them recurring is a test rather than the type gate the ticket asked for.

## What was wrong, measured

A seeded medium world at tick 60 holds 145 artifact nodes. Six of them could not be keyed:

- `intelligence` ×3 — `reward_intelligence_shrine_map`, `reward_intelligence_trade_route_dossier`, and the encounter graph-op clone in `rival-shrine-betrayal.ts`
- `talisman` ×1, `charm` ×1 — the two Content Primitive Proof Pack entries
- **and two nodes carrying no `subcategory` at all** — `artifact_0` and its reward-instance clone

The last pair is the half the ticket asked to identify and had not yet traced. The producer is `seedWorld`, which mints 1–2 named world artifacts per game ("The Crown of Echoes", "Griefender", "The Aegis of Dawn", "The Soulweaver", "Voidthorn", "The Lantern of Stars") with `sphereAffinity`, `locationId` and `echoOrigin` and nothing else. A world-legendary therefore rendered a blank plate and — because `resolveSlotTag` returns `undefined` with no subcategory to map — sat in `uncategorized`, which has no cap. It was free to hold.

## The five sites, and the slot consequence that comes with fixing them

Rewritten to the values the shipped art-alias table already encoded, which is the reading the codebase had committed to: `intelligence` → `tomes_scrolls` (the three are a map, a dossier and a map — they are documents), `talisman`/`charm` → `relics_talismans`.

**This is not behaviour-neutral, and that is the point.** None of the five carries an explicit `slotTag`, so an off-union subcategory missed `SUBCATEGORY_TO_SLOT_TAG` and dropped to `uncategorized`. They now resolve into real, capped slots — `tome` (cap 2) and `ring` (cap 2). Five items that bypassed the slot system now compete for space in it, which is the slot system working rather than a regression, but it is a live change: an agent holding two tomes and the Trade Route Dossier can now overflow, and the Dossier is `stealable` rather than `permanent`, so it is not pinned against being dropped. Pinned in the test file with literal slot names rather than left to surface after merge.

The seeded world artifacts get the same treatment via a name → subcategory record typed against the name tuple, so a seventh artifact name fails to compile until it is categorised. That is the one place in this change where a type gate genuinely holds the line.

**`SUBCATEGORY_ART_ALIASES` retired.** Its own comment named this ticket as the reconciliation owner. With the five sites canonical it has no live input, and leaving it would keep a side door open through which a future off-union value could be made to look like it works — which is exactly how a second vocabulary grows. No saved-game concern: the tree persists audio and UI preferences only, no world state, so nothing on disk carries the old raw values. The test that asserted the aliases resolve now asserts the retired values return `null`.

## Why the gate is a test, when the ticket asked for a type gate

The ticket's wording was *"make the union load-bearing so a future stray fails the type gate rather than rendering blank."* That cannot be done for this class, and the reason is in the three shapes that actually produced the six strays:

1. **Catalog literals** — `reward-attachment-catalog.ts` carries **116** `as PossessionNodeProperties` assertions. An assertion is not a check; it also silences the ~4 extra properties several entries carry (`intelligenceType`, `targetRegion`, `detailLevel`). Removing them so an array annotation could check the union would surface an unknown number of unrelated pre-existing errors across 116 entries and move the ratchet, for a Low-priority deferral.
2. **Encounter graph-ops** — `add_node` carries `properties` as `Record<string, unknown>` by construction. No type can reach it.
3. **`seedWorld`** — built inline in a `graph.addNode` call.

Only shape 3 is closeable by types, and it is closed. A type gate covering shapes 1 and 2 does not exist. So the recurrence gate is `possessionSubcategoryVocabulary.test.ts`, with one arm per shape:

- **Authored catalogs**, swept whole (`REWARD_POSSESSIONS`, `TREASURE_MAPS`, `STARTER_POSSESSIONS`, `ANOMALY_SIGNATURE_ARTIFACTS`). This arm is not redundant with the live world: tick 60 instantiates a handful of ~120 catalog entries, so a stray on an entry that happens not to spawn sails past a runtime-only check.
- **Encounter graph-ops**, scanned from source, because there is no importable value to assert over.
- **A live seeded world**, which is the arm that found `artifact_0` and which no authored table could have.

Each arm carries a non-vacuity guard, because every assertion in the file is satisfied by an empty population.

**Falsified before trusted.** Reintroducing one stray per shape — `talisman` in the catalog, `intelligence` in the encounter op, and deleting the `seedWorld` assignment — turns exactly those three tests red and names the offending entry in each failure message. The other nine stay green, which is the corroboration that the arms are independent rather than three views of one check.

## The question the ticket asked and this change answers

*Should `intelligence` become a canonical eighth subcategory?* No, and the content is the argument rather than the process: the three items are a shrine map, a trade-route dossier and a copy of the first. They are scrolls. Their `#intelligence` tags and their `intelligenceType` / `targetRegion` / `detailLevel` properties are untouched, so the intelligence *system* is exactly as it was — only the slot-and-art vocabulary is unified. Three items whose physical form is "document" is a thin case for expanding a seven-member union, and expanding it is a `UL-proposal` rather than an execution pass, so no proposal was filed.
