# THR-1319 — lairs could never be cleared, so half the lair system was unreachable

**Shipped 2026-08-28.** Engine pillar. Content and UI N/A **by path, not exemption** — the
sidebar's Cleared Lair block, the cleared icon and fill colour, the sound key and the
`cleared_lair` prose were all already authored and merely unreachable, so they start
rendering without a component or content file being touched. Deferral filed at THR-1312.

## Three independent blocks, stacked on one branch

`cleared_lair` was read in eight places and **written by nothing** outside test fixtures,
so no lair was ever cleared in a running world. `clearedAtTick` had no writer either —
which is what made this more than a dead enum member, since reinfestation gates on
`tick - (clearedAtTick ?? 0)` and fixing the subtype alone ships a lair that reinfests the
instant it falls.

**The third block would have made the fix look like it worked.** The reinfestation sphere
gate read `LAIR_SPAWN_SPHERE_THRESHOLD 60` against a hex *location node*, and a generated
world contains **none** — measured, 0 hex nodes against 768 tiles — so the score fell back
to `0` and `0 < 60` blocked every pass. Same fault THR-995 fixed for adjacent spawning, in
the one caller it left behind, with `findHexNode`'s own docstring already warning about it.
It now reads the lair's own accrued `sphereAffinity`, the entity escalation has always
aimed its pressure at, re-scaled to `LAIR_REINFESTATION_SPHERE_THRESHOLD 4` against a
measured range (legendary reaches 9 by t200, minor ~1). That is also the better fiction:
what seeps back is how deeply *this site* was steeped when it fell, and a cleared lair
stops accruing, so the value freezes at its clearing.

## What shipped

`src/engine/lairClearing.ts`. `clearLair` is the single writer and sets subtype,
`locationType` and `clearedAtTick` in one call — one chokepoint makes the pairing
structural rather than a rule each future caller must remember. It leaves `name` alone, so
THR-1312's persistence rule holds for free. `resolveLairClearing` runs inside
`phaseLairEscalation`: mortals whose position resolves to a lair's hex press it,
accumulating `clearingProgress` against `LAIR_CLEARING_RESISTANCE` (minor 4 / major 8 /
legendary 14), between 3 and 6 challengers per press. Deterministic, no PRNG.

## The mechanism was chosen by measurement, not by the property name

`clearedByFactionId` reads like an army was intended, and the first design followed it.
**The world holds 1 army against 36 lairs** — that path would have been a writer with no
live caller, this ticket's own defect rebuilt one layer down. Mortals are the abundant
signal: 18 on 2 lair hexes at t120.

Presence is tested at **hex** level, and that was load-bearing: at the lair *node* all 10
occupants were the lairs' own `isMonsterElite` bosses and not one was a mortal. A first
pass filtered on `isMonster` — a property no producer writes — which would have counted
each lair's garrison toward its own fall (impediment #903).

Gradual rather than one-shot makes escalation **positional** instead of merely temporal: a
den beside a village breaks while still minor; a den in country nobody walks escalates
unopposed.

## Evidence

Tests drive a **real generated world**, never a hand-built cleared lair — the pre-existing
tests passed while nothing could write the state they asserted, because they supplied both
sides of the transition. The five existing reinfestation fixtures were repointed off their
hex nodes; every suite-level assertion carries a vacuity guard.

Seed 42 / medium / t150 — 3 lairs cleared at ticks 25, 125 and 150, each keeping its name,
one still steeped enough (score 6) to be eligible to seep back:

```
{ name: 'The Cattle Diggings', at: 25 }  { name: 'The Crumbling Waste', at: 125 }
{ name: 'Failing Drift',       at: 150, score: 6 }
```

18894 tests green (1133 files); **ratchet 2967 → 2957, down 10**; build 10.47s; smoke tick

## Two notes for whoever picks up the thread

**`clearedByFactionId` is live but rarely paid.** The credit path works and is unit tested,
but on seeds 42 and 99 every mortal on a lair hex was unaffiliated, so organic clearings
record no faction. Designed behaviour — an unaffiliated clearing is a real clearing with
nobody to credit — not a gap, but the field still has no organic writer.

**The ratchet win was incidental.** `faction_ambition` had sat in `TRACE_CATEGORIES` since
TB-062 with no declared payload, so all 35 emit sites were errors cast past with `as`.
Declaring `FactionAmbitionTrace` — the THR-1175 fix — removed 10 baseline errors instead of
adding 2.

**`systems-inventory.md` now badges Spheres & Quintessence 🟠 DORMANT, and that subsystem
is not dead** (impediment #904). The badge is a keyword match against trace categories from
a **single** seed-42 / 120-tick run, and that subsystem's only trace surface is
`saturation_tick` — emitted solely for locations already carrying `magicalSaturation`,
which headlessly comes only from two zealot verbs completing. `sphere_pressure` is
threshold-gated and fired **0 times both before and after** this change; two of its four
phases emit nothing at all. So ACTIVE was always an accident of one rare downstream
producer. Removing 3 lairs diverges the world ~10% across nearly every category, which
moved that producer out of the window. Proven live by controlled arm: `saturation_tick`
fires **167×** on seed 99 and **40×** at 150 ticks on seed 42, with this change applied.
The row is committed as generated because the file defines DORMANT as "wired, no matching
output observed" — true of that run — but the robust fix is to union badge tokens across
two seeds, which touches all 26 badges and is not this ticket's.
