# 2026-09-19 — THR-1513: classify:diff reads the working tree pre-commit, and the pickup lane runs it on code diffs

**Ticket:** [THR-1513](https://linear.app/threadbare/issue/THR-1513) · **Project:** Continuous Improvement · **Pillars:** Engine N/A (tooling script), Content N/A, UI N/A.

## What was wrong

THR-1471 (2026-09-12) made `npm run classify:diff` print the browser-verify route reminder on
UI-pillar diffs, as a theory test for the route-decided-at-the-capture class. It never fired in
the ordering it was built for (impediment row 1042 ×3): the classifier diffed
`origin/main...HEAD`, which is empty before the first commit — exactly when the route decision
is owed — so pre-commit it printed `docs-only (0 changed)` and the reminder silently did not
render; and the `tb-opus-pickup` prompt named the script only inside the docs-only drain's
mis-tag guard, so a code-diff run never invoked it at all. A recurrence tally on a reminder
that cannot render is evidence of nothing, and was about to invite a wrong hard-gate escalation.

## What shipped

**Working-tree fallback** — [`scripts/classify-diff.ts`](../../scripts/classify-diff.ts). When
the commit range is empty the classifier reads the working tree: tracked edits against `HEAD`
plus untracked paths from `git status --porcelain --untracked-files=all` (an untracked new file
under `src/components/` is the very case the fallback exists for, and `git diff HEAD` cannot see
it). The header names the source — `read from the WORKING TREE, N uncommitted` — with a preview
caveat that the committed range is what CI classifies; `--json` carries `source`. The committed
range wins whenever it is non-empty. A doubly-empty read is named vacuous, mentioning both
sources. `selectFileSet`, `parseUntrackedPaths` and `mergeFileSets` are pure and exported.

**The reminder points at the claim-time rule.** The path list cannot see a Done-when-shaped
obligation (THR-1494 owed browser evidence with zero UI-pillar paths), so the UI-pillar reminder
now says the route is decided at claim from the ticket's Done-when (verification-gates.md
§ Browser-verify, route decision rule), and a code diff that touches no UI path prints a one-line
note saying the rule is Done-when-triggered rather than path-triggered — silence never reads
as "nothing owed".

**The pickup lane invokes it.** The live `tb-opus-pickup` prompt and its mirror
[`Docs/ops/scheduled-task-prompts/tb-opus-pickup.md`](../ops/scheduled-task-prompts/tb-opus-pickup.md)
carry a step-4 line naming `npm run classify:diff` before the gate track is chosen and before the
first commit. [`verification-gates.md`](../canon/verification-gates.md) § Browser-verify records
that both delivery defects are fixed and the theory test's tally counts from today; the pull-work
Step 3 parenthetical no longer says the reminder cannot fire pre-commit.

## Proof

Done-when, run live on this branch with nothing committed: an untracked
`src/components/__thr1513_probe.tsx` produced `classify:diff — code (base: origin/main...HEAD is
empty — read from the WORKING TREE, 6 uncommitted)` followed by the full UI-pillar reminder naming
that path; `--json` reported `"source":"working-tree"` with the path under `uiPillar`. Without the
probe the same tree printed the Done-when route note instead. Tests:
`scripts/__tests__/classify-diff-ui-pillar.test.ts` 35 passed (11 new pin the precedence, the
porcelain parse, the merge, and the rendered header). Full suite 1273 files / 20602 tests green;
`check:predicate-copies` OK (4 copies agree); ratchet unchanged at 2848; `vite build` green.
