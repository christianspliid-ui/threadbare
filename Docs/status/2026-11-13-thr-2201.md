# THR-2201 — make the purse bite: the two rule fixes ship; the tuning goes back to the design lane

**Shipped 2026-11-13.** Dominion — Player Power Progression. Plan doc: `Docs/plans/2026-11-13-thr-2201-make-the-purse-bite.md` (slice A). Laws 36, 37, 19.

- **Rule fix 1 — the discount goes to the god's own spheres.** `homeSpheresFor(gameState)` (exported from `buildNudgePhaseModel.ts`) returns the bought spheres, primary first, through `getSpherePoints`. It feeds a new `discountSpheres` field on `NudgeHandContext`, the card models and `totalNudgeCost`. Executor decision: the discount list is kept **separate** from `accessibleSpheres`, which is also `buildNudgeHand`'s `sphere_locked` gate. Narrowing that list would have withheld every unbought-sphere card, where the plan's own sample shows them in hand at full price.
- **Rule fix 2 — a sphere-less card pays from bought spheres only.** `essenceReader(pool, homeSpheres)` sums only those pools, and `spendNudgeEssence` takes an optional `payableSpheres` (primary first, then by buy). `GameView.handleCommitNudges` passes `phase.payableSpheres`. Meet The First passes nothing and keeps the whole-pool spill (P4).
- **Cost scale seam.** `NUDGE_ESSENCE_COST_SCALE` (`nudge-constants.ts`) and a `costScale` parameter on `effectiveNudgeCost` / `totalNudgeCost` / `buildNudgeCardModel` / the hand context. The default is 1, and the meeting path never passes it. **Shipped at 1.**
- **Debug bridge.** `getEncounterNudges` prices through the same helpers and now reports `cost` (effective), `authoredCost` and `homeSpheres`.
- **Census.** `npm run census:essence-scarcity` (promoted from `proto/thr-2201-essence-census`): it runs seeds 42, 99 and 7, each as a played run and a `--no-play` run in parallel child processes, and prints the P1–P3 verdict. P3 counts tiered threads only, because the seeded artifact thread has no `tier` and fails upkeep every tick whatever the pools hold (pre-existing; flagged as a separate task).

The re-decision (predicate thresholds or a different lever) goes back to the design lane on THR-2201.
- **Rulebook §7** states both rules. §6 is unchanged, because no economy number moved.
- **Review gate round 1** confirmed one finding: narrowing the model's `availableEssence` to the home sum made `useNudgeHand`'s pooled guard dim an unbought-sphere card its own pool could pay. Fixed: `availableEssence` stays the pooled total; the home reach is enforced by `buildNudgeHand` and the commit. Regression test added. **Round 2** confirmed one more: on a run with no sphere identity (legacy archetype), `payableSpheres` was set with no `budgetSphere`, so the hand could select two sphere-less cards that the narrowed commit refused. The fix limits the home-sphere rules to identity runs, in both the stage and the bridge, and adds a regression arm. That fix came after the two-round cap, so the PR was parked unarmed with an `open=1` receipt (THR-1735).
- **Review cycle 2 (the unstick run)** confirmed one finding: the census charged a sphere-less card with the commit's spill onto other bought spheres, but `useNudgeHand` lets the player pick one only while the primary can pay (THR-1706), so the census counted and played cards the hand dims. The census now charges sphere-less cards to the primary only on identity runs, and rulebook §7 says the hand's rule. Round 2 was clean. **The tuning table above was measured before this fix**, so its P1/P2 shares are lenient. The design lane should re-run `npm run census:essence-scarcity` before it re-decides.
- **Tests.** `src/engine/__tests__/purseBite.thr2201.test.ts` (14: no discount on an unbought sphere and the card stays in hand; a sphere-less spend never draws on an unbought pool; the meeting spill is unchanged; `homeSpheresFor` ranks and falls back; the scale multiplies before the discount, free stays free, a non-finite scale is treated as 1, a meeting card is unscaled). `purseBiteHand.thr2201.test.tsx` (3): a jsdom render of the real `buildNudgePhaseModel` → `NudgePhaseShell`, and a `useNudgeHand` arm proving a selected home card does not dim an Order card the Order pool can pay, and a legacy no-identity arm.
