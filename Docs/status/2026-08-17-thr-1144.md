# THR-1144 — a single person can join, leave, or rise in a faction

**Shipped 2026-08-17.** Third member of the consequence-palette expansion (plan doc `Docs/plans/2026-08-16-consequence-palette-expansion.md` § Primitive C), after THR-1142 (`agent_relocation`) and THR-1143 (location conditions).

## What changed

`membership_change` — the first effect kind that can move **one person** in, out, or up a faction. The bulk verbs (`faction_splinter` / `faction_absorb` / `faction_dissolve`) could already migrate members wholesale, and `faction_reputation_gain` could move an existing member's standing, but nothing could make someone a member who was not one. So an ending that recruited you said so in prose and wrote nothing — the Law 56 hollowness the THR-1141 census kept finding.

Three ops. `join` is idempotent by contract, so a replayed encounter cannot silently reset someone's seniority. `leave` removes the edge. `rank_delta` moves `rank`, clamped to `[0, FACTION_RANK_MAX]`.

The write goes through a new `src/engine/factionMembership.ts` in the **same edge shape** `processFactionJoinOutcome` writes — same id, same property set — so a card-made member is byte-identical to a quest-made one and `graphQueries`, `socialLeverage`, `agentDetail` and `factionReputation` see no difference.

## The reader shipped with the write

The rank half would have been hollow without it. THR-805 found the `faction_rank:` predicate dead and declined to build on it: `buildPredicateContext` read `agentNode.properties.factionRank`, which **nothing in the engine writes**, so `ctx.factionRank` was permanently 0 and every `faction_rank:` gate permanently false.

Two changes revive it. The context builder now reads the highest numeric `rank` across the agent's `member_of` edges — where rank has always actually lived — and the predicate parses a **float** rather than an integer. That second half matters more than it looks: `MemberOfEdgeProperties.rank` declares its scale as *"0 (recruit) to 1 (leader)"*, so `parseInt` left authors exactly two usable thresholds on a continuous scale. `parseFloat('2')` is still 2, and no authored predicate existed anyway, so nothing changed meaning.

THR-805's stated reason for rejecting the gate — that the edge's rank is "normalized 0–1" and conflicts with integer tiers — was half right. The scale really is 0–1; the fix was to stop reading it as integers, not to route around it.

**Falsified both ways, which is the whole point.** A test asserting only "below-rank agent is blocked" passes against a gate that never fires. Reverting the context builder to the node property leaves the BLOCKS arm green and turns the ADMITS arm red — verified by actually reverting it, 4 failures of 29. The at-rank arm promotes the agent *through the new write path*, so the write and its gate are proven to share one scale rather than two.

## Two defects found on the way, both filed rather than folded in

- **THR-1150** — every authored `faction_reputation_gain` in the game is dead. Content names the *definition* id (`'mercenary_company'`); `factionSeeding` keys nodes `faction_def_<definitionId><chapterSuffix>`. `applyFactionReputationGain` matches on `e.target === factionId`, never matches, returns the `'none'` sentinel, and the dispatcher skips **with no trace at all** — which is why it survived. This primitive hit the same wall and bridged it with `resolveFactionNodeId` (node id wins, then a `factionDefId` scan preferring a chapter the agent already belongs to, else the lowest id so the pick is deterministic), but scoped that resolver to the new kind only rather than changing an unrelated effect's behaviour in this PR.
- **THR-1151** — three readers (`journeyEngine`, `proseEnrichment`, `returnEngine`) test `rank >= 3` against that same 0–1 scale. Permanently false. Test fixtures use integers 1–5 throughout, which is exactly why it reads as correct everywhere.

## Two of my own bugs, both caught by driving the real thing

Neither was visible from the unit tests, and both were found in a seed-42 CLI run:

- `chronicle: true` pushed only to `tickEvents`, which is per-tick and gone next tick. Every other event-emitting effect in this dispatcher writes **both** feeds; `recentEvents` is the rolling buffer the chronicle and notification surfaces actually read. A chronicle flag that announced nothing. Now guarded by a test asserting both feeds.
- The chronicle line looked the faction's name up by the *authored* id, which is not a node — so it printed `The Unchained has joined mercenary_company.` The resolved node id is now threaded back through the result and used for naming and traces: `The Unchained has joined The Iron Wolves.`

## Content

`mc.join` — "Signed to the Company" — is the exemplar, and it was not a contrived one. It is a join encounter that is **not** any definition's `joinEncounterTemplateId` (only `ag.join` is), so `processFactionJoinOutcome` never fired for it and its reputation gain no-opped on a non-member. The chip claimed a membership nothing wrote. Both of its reactions now carry the `join`, and the chip is backed by the edge it always described.
