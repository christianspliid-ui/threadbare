# THR-1212 slice 2 — the membership spine and the coverage lint

**Shipped 2026-08-28.** Second of six slices on wave-1 design A (shared anchor machinery). Plan doc: `Docs/plans/2026-08-27-shared-anchor-machinery.md`. Slice 1 (`WorldRef`, adapters, the resolver that drops) merged as PR #1678.

## What landed

`scripts/generate-anchor-catalog.ts` now reads `src/types/worldRef.ts` as its **membership spine** and checks every other entity-kind vocabulary in the tree as a projection of it. Seven consumer unions are registered — `EntityVisualKind`, `EncounterAftermathConceptRef.visualKind`, the narrative segment's `entityKind`, `ChangeItem.nounEntityKind`, the adapter's structural mirror, `NavigationTarget`'s arms, and `EntityNoticeAnchorKind` — and the generator fails **by name** on four drifts: a member the spine cannot express, a spine kind dropped without a reason, and either kind of stale disposition row.

The stale-row direction is the half that makes this self-correcting rather than a comment that rots. A row saying *"`codex` is deliberately absent"* fails the moment `codex` stops being absent.

## The measurement the design asked for

The plan named its own kill criterion: *if the coverage lint produces more curated-exception rows than mapped rows, the normal form is fiction.* The live answer is **41 members map to the spine, 3 do not** — `avatar`, `npc-role`, `unknown`, all three render-time refinements of `agent` rather than things anything can reference. The hub holds.

That ratio counts *extras*, not *absences*, and the catalog says so in the rendered totals. Counting absences would have fired the criterion mechanically — 7 unions × 13 kinds is 91 cells, and a two-member union like `EntityNoticeAnchorKind` produces 11 absences by arithmetic — so a per-cell reading would have condemned the design for the crime of having narrow projections, which is what a projection *is*. The question the criterion actually asks is whether the spokes name things the hub cannot express; that is the extras column. Recorded as a comment on THR-1212 rather than settled silently, per the plan's instruction that a kill-criterion question goes to Linear.

## Two things the work found

**`NavigationTarget` could not be read by the existing parser, and would have failed quietly.** Its arms carry semicolons *inside* the braces (`{ kind: 'agent'; agentId: string }`), so the established `[^;]*` union parser stops partway through the first arm and returns `['agent']` — a one-member union, reported with total confidence. Every coverage check downstream would then have been computed against a union that does not exist. A brace-depth parser replaces it, and the wrong answer is pinned as a test rather than described in a comment, so the reason the second parser exists cannot be forgotten and refactored away.

**One new guard is narrower than it first appears, and the code now says so.** `assertMirroredUnionsAgree` was written to catch one of the four chip/segment unions falling behind the others — the drift three doc comments in `src/` claim is impossible while nothing checked it. A controlled arm showed it does not do that job: because all four specs share one disposition record, the coverage lint already fails first (adding `army` to the adapter mirror alone throws inside `assertKindUnionCoverage`). What the mirror guard uniquely owns is the case where all four move *together* and `CHIP_UNION_MEMBERS` — the only written record of the canonical spelling — is left stale. Its doc comment, its test and the wiring checklist all state that precisely. A guard advertising reach it does not have would have been the same failure as the three unchecked "pinned" comments this slice replaced.

## Verification

The guards were **falsified, not merely written**. Adding a `codex` arm to `NavigationTarget` in the live tree fails the generator by name and exits 1 — the exact contract promised to THR-1315 in its coordination block, proven as a controlled arm and reverted. 45 tests on this file (up from 21), full suite 18,783 green, ratchet 2973 unchanged, build 10.39s.

An earlier attempt at that arm **silently did not apply** — a `node -e` replacement inside a double-quoted shell string whose needle never matched — so the generator succeeded and read exactly like a vacuous guard. Logged as impediment #872; the lesson is that a controlled arm owes a diff check before its result is believed, since "the guard did not fire" and "the arm was never applied" are indistinguishable from the exit code alone.
