# THR-1249 — Play Profile, Dealt Hand, Deal Declaration enter the glossary

**2026-08-26 · Encounter Experience · Docs pillar**

Three canonical entries in the Encounters shard for the vocabulary the dealt-hand program
introduced, plus their index lines and See-Also wiring. The UL wins on terminology disagreements,
so these are what the engine, content and rulebook copies now conform to.

**Written against shipped code, not the plan doc — and that mattered.** The coordination block
promoted this ticket as *leading* the implementation ("do not wait for either"), but THR-1247 and
THR-1248 both merged the same evening, so by pickup the terms described live code. Writing from
`Docs/plans/2026-08-25-thr-1247-dealt-hands.md` would have shipped a wrong entry: the plan's
first-cut `DealContextTag` roster (*"the 8 reaches + `social | peril | craft | journey`"*) is not
what landed — `craft` shipped as one of the eight reaches and `labor` shipped as the fourth
situation word. A glossary that copied the list would have been wrong on the day it was written.

**So *Deal Declaration* is defined by its closure property, never by its members** — the judgement
the orchestrator's promotion asked for, now with the divergence as evidence rather than a
prediction. The durable half is *closed, not free-form*; the roster lives in
`src/types/unifiedAction.ts` and the entry says to read it there. The same discipline shapes the
other two: *Play Profile* is pinned as **data that becomes a Nudge and is not one** (the same
numbers reach a hand by two routes — authored onto a step, or minted from a profile), and *Dealt
Hand* carries the three distinctions that were live confusions in the design chat — a dealt card
is an ordinary `[[Nudge]]` downstream of assembly (anything branching on a `dealt.` id violates
the design), **dealt never means random** (score-and-select, zero PRNG, replayable), and it is not
the rejected fixed-action-count model, since the fill sits *inside* the open 4–8 window.

**Evidence.** Docs-only track per the handoff block and confirmed by `npm run classify:diff` —
`Docs/ubiquitous-language/{Encounters,README}.md` plus the regenerated
`src/data/ul-dashboard.generated.json`, which is doc-excluded by THR-922 exactly so a UL edit does
not pay the code gate. Dashboard regenerated rather than hand-edited; all three terms resolve in
it (shard `encounters`, slugs matching the README anchors, status canonical) with **zero** new
See-Also warnings, and the back-references land both ways — Nudge 4→6, Repertoire 4→6, Band
Fragment 3→4. The seven remaining warnings are pre-existing and name none of these terms.
