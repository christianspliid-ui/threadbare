# THR-1038 — 15 mercenary templates had an aftermath in a schema nothing reads

**Shipped 2026-08-08.** Project: Content Architecture. Pillars: Content, Engine (UI: N/A).

## What was wrong

15 templates in `src/data/mercenary-encounter-content.ts` declared an `aftermathConfig` that was not a `BranchAwareAftermathConfig` at all. It carried none of the three fields the type declares required — no `branchOnStep`, no `variants`, no `fallback` — and instead held a bare `reactions` array:

```ts
aftermathConfig: {
  reactions: [
    { kind: 'reputation_tally', domain: 'iron.positive', weight: 0.6 },
    { kind: 'recent_event', label: 'road_patrol', delay: 0 },
  ],
},
```

`resolveAftermathVariant` then fell through to `config.fallback` (`undefined`) and `applyAftermathOutcomeBand` read `byOutcome` off it, throwing on **every** resolved action. The tick loop's fail-soft envelope (NFP #4) swallowed the throw, so nothing was ever red — and the authored aftermath on all 15 templates reached nobody. The same silent-death class as THR-989 and THR-1012.

## The schema question, settled

The ticket required deciding which schema is real before touching anything, because the two answers are different work. Settled by grep, direction **(2) — dead shape**:

- **Nothing reads `aftermathConfig.reactions`.** `grep -rn "aftermathConfig\.reactions" src/` returns zero hits.
- **Everything reads `aftermathConfig.fallback.reactions`** — `ascendantBeat.ts:636`, `collectAuthoredProse.ts:137`, `reach-signature-content.ts`, `contentInvariants.ts:107`. One level deeper than where these 15 put theirs.

The field names were wrong too, which the ticket's framing did not anticipate. `EncounterAftermathReaction` is `{ id, label, intent?, effects[] }` — a *wrapper*. What these templates held in `reactions` were `EncounterAftermathReactionEffect` objects, and every one of their keys was misspelled against the real union: `domain`/`weight` for `key`/`delta`, `label`/`delay` for `message` on `recent_event`, `hidden_mark` missing its required `category`, `encounter_seed` using `delay` for `delayTicks` and omitting `seedLabel`, `faction_reputation_gain` using `factionDefId` for `factionId`. So this was not a config one level too shallow; it was an older vocabulary preserved whole.

## What shipped

**Content** — all 15 rewritten to the canonical no-fork shape (`branchOnStep: 0`, `variants: {}`, `fallback`), matching the shipped civic-guard pattern. Every authored effect's *intent* is preserved and translated into the real field names, and `reactions[0]` on each template carries the complete original effect set, because `chooseAlignedReaction` falls back to index 0 for unattended agents — so background behaviour is exactly what the author originally wrote, now actually firing. Each template also gains a second god-facing reaction (an alternative read of the same scene, usually trading the iron tally for an `eye`/`shadow` one plus an `intelligence` record), which is additive (NFP #6) and gives `chooseAlignedReaction` a real choice to align against instead of a single option. Voice held to the file's bible — contract, clause, split, ground, keeping the word; never glory.

**Engine** — `resolveAftermathVariant` now substitutes an exported `EMPTY_AFTERMATH_VARIANT` when no base resolves, so a malformed config degrades instead of throwing (NFP #4). Deliberately empty rather than apologetic: a placeholder sentence would ship prose no author wrote. The harden alone would have been the wrong fix — it converts a loud-but-swallowed throw into a quiet nothing — so it lands together with the structural gate below, which is what actually reports the defect.

**Testing** — `unifiedTemplateAftermathReachability.test.ts` gains a corpus sweep: every template's config resolved at **every** `UnifiedActionOutcome` plus the no-outcome case, with the outcome list exhaustiveness-guarded by a `satisfies Record<UnifiedActionOutcome, true>` so a new band cannot silently escape coverage. Plus a structural gate (every `aftermathConfig` carries its `fallback`), a population guard enumerating the 15 repaired ids explicitly rather than counting — a count would also be satisfied by `mc.army.raise`, which lives in the army set and was always well-formed — and a falsification test pinning that the shipped malformed shape now fails soft rather than throwing.

The gates were falsified before being trusted: run against the pre-fix data file, the structural gate fails and names all 15 by id. Note the resolver sweep *passes* on pre-fix data once the harden is in — which is exactly why the structural gate exists and why shipping the harden alone would have buried this deeper.

## Evidence

Full suite **972 files / 15322 tests green**. Typecheck ratchet **DOWN 15**, 3477 → 3462 — one removed error per repaired literal, the cleanest available confirmation that direction (2) was the right call and that these were type errors hiding inside the red baseline (THR-489) the whole time. `npx vite build` clean. 30-tick CLI smoke at seed 42 / medium: tick 30, 383 agents, 47 events, outcome ladder healthy.

## What is *not* done, and why

The ticket's last Done-when asked that the endings be eyeballed through `?spawn=<id>&outcome=<band>`. **They could not be.** Spawning any `mc.*` template crashes the encounter stage before it reaches the aftermath: `buildUnifiedEncounterStageModel` reads `template.narrativeTemplates.initiation` unguarded, and no mercenary template declares `narrativeTemplates` — they carry step-level `narrativeTemplate` strings instead.

Attributed rather than assumed: the crash reproduces **identically on the pre-THR-1038 tree**, verified by stashing this change and re-running the same four-line repro. It is an older, unrelated defect that this work merely gave someone a reason to trigger. Filed as **THR-1040** (Todo, coordination block posted) with the repro, the four unguarded call sites, and a recommended direction.

So these 15 endings are proven to resolve correctly at the engine level — authored prose, changes and reactions, across every outcome band — and remain invisible in the UI until THR-1040 lands. Two silent-death layers on the same templates; this ticket removed the inner one.
