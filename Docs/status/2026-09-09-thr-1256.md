# The guidance gate's flip review flipped it the other way (THR-1256)

**2026-09-09** · [THR-1256](https://linear.app/threadbare/issue/THR-1256/flip-checkguidance-freshness-from-advisory-to-blocking-after-its-burn) · plan: [`2026-08-25-thr-1253-guidance-governance.md`](https://github.com/christianspliid-ui/threadbare/blob/main/Docs/plans/2026-08-25-thr-1253-guidance-governance.md)

`check:guidance-freshness` shipped **advisory** on 2026-08-26 with a fortnight's burn-in and a
flip review booked into code (`GUIDANCE_GATE_MODE.flipReviewAfter`) so the burn-in could not
become permanent by inattention. The review came due. It retired the gate.

## What the window measured

The gate is a pure function of (files changed vs merge-base, commit bodies over that range), so
the advisory fortnight was replayed deterministically over every PR merged into `main` since
2026-08-26 rather than read out of 200+ CI logs — same inputs, every PR, no sampling.

| | |
|---|---|
| PRs merged in the window | **228** |
| Authority edits on `main` | 33 commits across 14 of the 16 registered authority files |
| PRs touching an authority with ≥1 dependent untouched | **32** |
| …waived by a `Guidance-sweep:` attestation | 3 |
| …**flagged** | **29** |
| Of the 29, false positives (genuinely owed no sweep) | **~20** |

Step 3 of the ticket's decision procedure — *a gate with no opportunity to fire has not burned
in* — does not apply. The gate had 33 opportunities and took 29 of them.

## Why they were false positives, and why the manifest could not be fixed

The ticket's decision tree assumed a false positive means **the dependent lists are wrong**. It
did not. The lists are fine. The defect is one level up, in the **arming trigger**: the gate
armed on *an authority FILE appears in the diff*, and four authority files are edited by
routine, non-doctrinal work **as standing policy**:

| Authority | Edited by | Standing rule that requires it |
|---|---|---|
| `Docs/canon/interface-map.md` | every PR adding or repointing a cross-system contract | CLAUDE.md § Definition of Done |
| `Docs/canon/rulebook.md` | every feature appending its `[IMPL]` row | the rulebook's own `[IMPL]/[DESIGN]/[OPEN]` convention |
| `Docs/canon/verification-gates.md` | gate and test-lane maintenance | it *is* the gate law |
| `Docs/canon/engine.md` | slice records for shipped engine work | round-4 doctrine |

So the gate flagged, among others: eight PRs that appended one `[IMPL]` paragraph for a shipped
ticket, a weekly retro that added two lines of gate law, a PR moving two test files to the heavy
lane, the first composed-hand encounter, and — with some symmetry — THR-1253's own shipping PR.

**No dependent-list edit could have removed these.** The untouched counts were repeatedly
**N/N** — 13/13, 16/16, 19/19, the entire list. Trimming a list to silence them means emptying
it, which is retiring the doctrine, not fixing it. Since the "fix the manifest, then re-measure"
branch could only have spent a second fortnight arriving here, the review went straight to the
recurrence clause of [THR-1253 § Kill criteria](https://github.com/christianspliid-ui/threadbare/blob/main/Docs/plans/2026-08-25-thr-1253-guidance-governance.md):
*if it recurs after that, the gate design is wrong: retire it and keep only stamps + audit.*

Flipping to blocking would have red-gated **29 of 228 merges (~13%)**, roughly two-thirds of them
spuriously — precisely the THR-899 pathology the burn-in existed to detect. The burn-in worked.
It is only a failure if you assumed the answer in advance.

## What shipped

- **Both CI steps removed** (`Docs gates` and `check`), each replaced by a comment carrying the
  measurement, so nobody re-adds the step without meeting the evidence.
- **The blocking mode is gone from the code**, not merely unused — `FreshnessMode` is now
  `"report-only"`, the `--blocking` flag and `GUIDANCE_FRESHNESS_MODE` env path are deleted, and
  there is no `process.exit(1)` left. Retiring by convention would have let a future one-line CI
  edit re-arm a measured-wrong design; re-arming now costs a code change, and a code change gets
  read.
- **`GUIDANCE_GATE_MODE` records the verdict** — `outcome: "retired"`, `outcomeOn`, and an
  `outcomeReason` carrying the measurement, satisfying the ticket's second Done-when. The test
  block that used to assert *"the burn-in names a review date"* now asserts the review resolved,
  that it resolved no earlier than the date it was booked for, that the reason states the cause,
  and that no blocking path survives in the source.
- **The script survives as an on-demand report.** `npm run check:guidance-freshness` still
  computes the sweep correctly and still honours `Guidance-sweep:`. It just cannot fail a build,
  and nothing runs it automatically. Its finding text now tells the reader the actual decision:
  *if this edit changed the doctrine, sweep and bump the `version`; if it recorded shipped work,
  nothing is owed.*

## What governance is now

Nothing was lost that was working. The chain is smaller and armed on the right signal:

`Docs/guidance-manifest.json` → **a deliberate doctrine `version` bump** → the retro's Step 5d
trigger (which already compares versions, not diffs) → `/guidance-audit`.

A version bump cannot false-positive on routine maintenance the way a file touch did: it is an
author declaring that direction moved. And the audit reads for the four drift shapes a diff
matcher never could see anyway — a dependent touched and still teaching the old rule, two live
surfaces contradicting with no diff between them, a doc silently superseded, a vault page outside
CI's reach. Those were always the failures that mattered; row 1 of that table has now joined
them rather than replacing them.

`.claude/skills/guidance-audit/SKILL.md` and `.claude/skills/retrospective/SKILL.md` were both
updated to say so — each described the gate as a live CI half, which is the drift this whole
doctrine exists to prevent, and leaving it would have been a small joke at the project's expense.

## Handed to the retro

The stamp report currently emits **~101 rows**, most of them *"no frontmatter block, so no stamp
surface"* — informational by design, but a shape nobody can act on. The stamps and this skill
remain under the standing six-week sunset presumption; that count is the observation their
renewal should be judged against. Recorded in the manifest's `SUNSET` note, not filed as a
ticket (2026-08-10 throttle: the retro is the single promotion point).
