# THR-1164 — the corpus anchored, and a gate that can see all of it

**2026-08-17 · Encounter Experience · Content + Engine + UI**

THR-1153 shipped the route a chip's referent travels to reach the player, and split
the two things that had to arrive together: the **corpus sweep** and the
**anchor-resolution gate**. Law 56 has no exemption mechanism, so clause 2 reds every
unanchored chip the moment it lands — a gate arriving ahead of its own sweep is a red
build, and a sweep arriving without its gate is a state nothing holds. This is both.

## What landed

**The declaration form.** Most anchors are literal and mean the same thing in every
world — an attachment's template node. The ones that cannot be are authored as
sentinels: `$actor`, `$cast:<key>`, `$faction:<defId>`. A faction node is minted per
world and chapters of one order share a definition, so there was no number an author
could write for *The Dawn*, which nineteen shipped chips name. The static classifier
and the runtime resolver live in **one file on purpose** — split, they drift, and the
drift presents as a chip that passed the gate and rendered a dead link.

**Clause 2 and its runner.** `chipAnchorViolations` sits beside `chipBackingViolations`:
clause 1 asks whether a write fired, clause 2 asks what it was *about*. `check:chip-anchors`
runs it across the **whole catalog, 683 templates**. That population is the point —
`check:encounter --all` is scoped to the `encounter.` prefix (191 of 683), so a rule
living only there is blind to all 19 `hod.*` chips, which is over 40% of this ticket's
own worklist.

**The sweep: 48 chips across 17 templates, now zero.** Nineteen `hod.*` chips took one
decision applied nineteen times. The remaining 29 were sorted individually against the
shipped anchor catalog.

**The resolver, wired.** `buildUnifiedEncounterStageModel` holds the graph, so it passes
`resolveAnchor` down to `buildAftermathConsequences`, which resolves each ref **once**
per change and uses the result for every tier — noun link, tooltip, and tile. Resolving
per-consumer instead would let the tile and the link disagree about what the chip points
at. An anchor that resolves to nothing is **dropped**, returning the noun to plain text:
an unresolved `$actor` reaching the surface is a live link to a node id no world contains,
which is strictly worse than no anchor at all.

## The two design gaps, surfaced rather than waived

Law 56's no-exemptions posture means a chip class with no possible anchor is a gap to
report, not an exemption to add. Both were confirmed real, and neither was closed by
deleting director-approved content.

**G1 — a spawned artifact has no declaration form.** `spawn_artifact` mints from a
*category* at reaction time, after the veil closes, so there is no template node to point
at and no instance id at render. The catalog's clarification 1 explicitly ratifies such
objects as legal anchors, so these five chips *ought* to be anchorable and provably are
not. Pinning a concrete `templateId` would close it mechanically and was rejected: the
parcel's contents being unknown **is the fiction**. Closing it properly means a
`$spawned:<reactionId>` form resolved after resolution.

**G2 — `intelligence` has no row in the anchor catalog.** It is real, inspectable state
backing roughly eight `path` chips, and the catalog classifies no member for it.

Both were sorted the same way, and the rule generalises the catalog's own clarification 2:
**when the written object has no authorable id, anchor its carrier and name the carrier in
the sentence.** A piece of knowledge, a scheduled return, a debt, and a parcel not yet
minted are all reached through the person carrying them — who is real, resolvable, and
whose sheet is where the player will actually find the thing. Each such noun took a prose
pass so the carrier is named rather than implied.

## One invariant collision, and the fix is the better reading

`slice.pass.a_night_that_held` was first anchored to `trait.condition.exhausted`, the
condition its band writes about. The THR-1120 suite caught it: that band **removes** the
condition, and the rule is that a chip may only link an attachment its own band *grants*.
Linking it would have opened the page for a thing the mortal no longer has — a live link
telling the opposite of its own sentence. Re-anchored to the carrier.

## Falsification

The load-bearing run is the population trap, measured on the same defect:

```
                                    stripped hod chip   restored
check:chip-anchors (683 templates)   exit 1  ← reds     exit 0
check:encounter --all (191)          exit 0  ← blind    exit 0
```

A prefix-scoped gate reports success over a defect it cannot see. Exit codes captured
unpiped — a piped run reports `tail`'s status, not the gate's.

At the adapter, four assertions pin resolution both ways: a sentinel resolves to the
node id the world minted, an unresolvable one is dropped rather than shipped, an omitted
resolver passes refs through unchanged (so every pre-existing caller renders identically),
and a concept anchor resolves alongside the noun so tile and link agree. At the veil, a
resolved faction noun opens the faction sheet and the raw sentinel provably never reaches
the host.
