# THR-839 — the impediment log's Impact column got a gate, and a corrected diagnosis

**Shipped 2026-08-08.** `tb-opus-pickup` hourly run.

## What the ticket said, and what was actually there

THR-839 was filed 2026-07-28 describing "roughly **30 rows**" whose Impact cell had been shifted right by an unescaped `|`, and recommended "**B first**" — a lint that stops the bleeding — with the row repair as a separate mechanical pass.

Measured at pickup, 11 days later: **481 table rows, 355 canonical, 126 outside the documented vocabulary.** Not 30, and not one defect. The set is three unrelated causes that had been collapsed into one:

| Kind | Rows | Cause | Repair |
|---|---|---|---|
| `overflow` | 7 | unescaped `\|` *before* the Impact column shifts every later field right | mechanical — escape it as `\|`, which renders identically |
| `short` | 11 | row authored with fewer than the 10 documented columns; no Impact cell exists | needs the author's knowledge |
| `vocabulary` | 108 | columns correct; value from the **severity** scale (`Low`/`Medium`/`High`/`Small`) | per-row judgment |

The dominant class is 108 rows the ticket does not mention at all, and it is **not corruption** — those rows are correctly aligned. `Low`/`Medium`/`High` is a severity scale; the documented one (`.claude/skills/impediment-reporter/SKILL.md`) is **time-lost**: `S` <2 min, `M` 2–15 min, `L` 15+ min, `Blocked`. Those are different axes, so `Medium → M` is a guess, not a translation — and several rows carry the figure in their trailing clause and contradict it. **#311 reads "Medium — ~25 min to reconcile", which is `L` by the documented rule.** A blind mapping pass would have written a wrong number into 108 rows and made them look authored.

Two findings that shrank the problem rather than growing it:

- **11 more rows overflow but are not defects.** A stray `|` in the *Session* column changes nothing, because `parseTableRow` already rejoins everything from column 9 on (`cells.slice(9).join(" | ")`). Classifying on a bare cell count would have inflated the reported backlog by 60% and sent a fixer at rows that are fine. This is a test case, not a comment.
- **The genuinely-shifted class is 7 rows, not 30.**

## What shipped

`findImpactAnomalies` in `scripts/impediment-log.ts` classifies every table row whose Impact cell is outside the accepted tokens, carrying its kind, source line and the raw cell. `scripts/check-impediment-ids.ts` — the file that since THR-922 "owns every assertion about the live corpus", and which is blocking in CI on *both* the code job and the `Docs gates` job — reports them and fails on any row not already in `KNOWN_IMPACT_ANOMALIES`.

**The allowlist is a closed set, not a count** (THR-688 rule A). Repairing a row shrinks it; a new offender fails CI on the PR that writes it. A snapshot number would have rotted exactly the way this ticket's own "~30" did — which is the argument for the shape, made by the ticket itself.

The gate also prints its backlog on **green** runs. A gate that only speaks when it fails is how 126 rows stayed invisible for 11 days while the ticket describing them sat in the queue.

## Why the repair was not done here

Deferred to **THR-1027** with all three classes measured and their per-class repair rules written down, per the ticket's own "B first" recommendation. Two of the three classes need reading, not transforming, and the ticket is explicit that no entry text may be paraphrased.

The cost of leaving it: `retro-draft.ts` maps `Unknown` to 0 minutes, so all 126 rows contribute **zero** estimated time to every retrospective draft — a 26% blind spot in the one signal the retro uses to rank friction.
