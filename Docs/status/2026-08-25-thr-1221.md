### THR-1221 — the border-perils batch: six new encounters through the full factory line

The Encounter Factory's first **new-authoring** batch (every prior run was a retrofit), against the brief Christian approved in chat on 2026-08-24. Six encounters in a new `encounter.border.*` family: The Unclaimed Relic, One Body Short, The Toll of Blades, The Sign Over the Ruin, Standing the Line, The Garrison's Price. Stage 3 green 6/6, Stage 4 live-proved 6/6, vacuous 0, nothing parked, no encounter needing a third critic loop.

**Resumed from a checkpoint, and the resume itself was gated.** Impediment #743 — logged the hour before by a run that correctly *stood down* — records that `pull-work`'s resume path has no liveness check on the predecessor, so an hourly lane that outruns its own interval is routed to "resume" a branch a live session is still committing to. Both of its reads were run before anything was touched: the branch tip was 2h07m old **in UTC** (`%ci` prints `+0200`, and comparing that string against `date -u` is the trap that nearly swallowed the near-miss), and the predecessor's worktree had zero file writes in 60 minutes. Idle on both, so the takeover was safe. Its `node_modules` junction was stripped non-recursively *before* the worktree was released, so nothing could follow it into the home install.

**Stage 4 was failing 1 of 6, and the encounter was right — the gate was wrong, twice over.** `toll_of_blades` failed `condition_applied`: *"declared a condition effect on this run's path but none applied."* Two independent causes, each the gate asserting a promise nobody made. A `remove_condition` lifts a condition only *if* the target carries one and traces `success: true` having removed zero edges otherwise — nothing owed, so nothing missing. And `failureMetadata` fires on its own step's failure: seed 42 rolls a pure `near_miss` history here (step outcomes `near_miss, success_at_cost`), which aggregates to a success-side band with **no step failing**, so the `exhausted` mint on step 1 provably never fired. The surfaces model is right to keep a `continue_weakened` `failureMetadata` band-agnostic — a failed step really does land on a success-side band — it simply cannot know which step outcomes a run rolled. That is runtime knowledge, so the caller now passes `anyStepFailed` in.

`reachableConditionWritesCannotFire()` answers both over the *same* `locatedAuthoring` walk `systemSurfacesForOutcome` uses, so no second hand-rolled "where is this authored" predicate can drift from it. Skip-only and band/reaction aware: one reachable `apply_condition` on a path that could fire returns `false` and keeps the claim strict. **Measured against the whole corpus rather than asserted:** across all 202 templates the new skip fires on **exactly one** — the false positive it was written for.

The same claim carried the mirror-image blind spot, fixed here too. `reward_node` reads **both** authored changes and the effect's own trace (THR-1132's lesson); `condition_applied` read only the authored changes, so a condition arriving via a step-metadata or reaction effect — which leaves `changes` untouched entirely — read as missing. It now reads both, counting only *additive* kinds, because admitting `remove_condition` as arrival evidence would be the laundering the rest of this avoids.

**Then the full suite went red on three files, and all three were ours.** Each reproduces in isolation, so none is a worker-contention flake; `origin/main` checked out in the same worktree runs the same three at 47 passed. (1) **Five of six encounters would have shipped without their opening paragraph** — only `standing_the_line` wrapped its template in `compileOpeningEnvelope`, and the corpus guard's loop throws on the first offender, so one red name was hiding five. (2) The anchor-catalog test still asserted `location: 'named'`, the pre-THR-1172 claim commit `50e65f49` had already corrected; verified against `src/types/unifiedAction.ts:237` before the test was touched, not taken on trust. (3) A real **`TickEvent` id collision** in `src/engine/secretsFavorsConsequences.ts` — `secret_revealed_${revealer}_${subject}_${tick}` is not unique, measured duplicating `secret_revealed_elite_lair_8_50_npc_221_200` on tick 200; React keys the chronicle list on it, so duplicates render doubled or dropped rows. The id now carries the recipient and the secret's own identity, with no counter, so the same seed still mints the same id.

Item 3 touches `src/engine/`, which the ticket expected to stay untouched — recorded rather than worked around, since the collision is a genuine invariant violation the batch merely surfaced, and the 30-tick smoke was run accordingly.
