# THR-1431 — the subsystems × verbs view sees every way a mortal's work reaches a system

**2026-09-07 · Engine (generator + canon) · project Thematic Pressure & Living World**

THR-1427 shipped the subsystem × verb view on a single join — `WORLD_OBJECT_KINDS[].owningSystem`, a subsystem is reached when a live cell acts on a kind it *owns*. Five subsystems own no kind and so read UNTOUCHED although a mortal's work reaches every one of them each run. The view now asks three questions instead of one, and the UNTOUCHED count falls **17 → 6**.

## The three joins

1. **Owned kind** → `LIVE-TOUCHED`, unchanged.
2. **The operation's home module** → `REACHED-BY-OP`.
3. **A reader** → `READS`: the subsystem appears in `SUBSYSTEM_READERS` for a LIVE-TOUCHED subsystem.

Precedence is strongest-first, so the status word names the closest relation. All three derive from code; none is authored.

## The op join could not be built the way the ticket described, and the ticket said what to do about it

The ticket's plan was "each live cell's `op` names a graph op … resolve each op's module". **It does not.** `LIVE_CELL_NOTES[].op` is a descriptive label, not a symbol: of 26 distinct op strings, **seven — `ruin_settlement`, `conduct_trade`, `plant_schism`, `reinforce_group`, `seize_item`, `destroy_item`, `cure_condition`, `expose_mark`, `raise_warhost` — do not exist anywhere in `src/`** under any casing. A resolver keyed on them would have silently resolved two-thirds of the grid and failed the rest by name. Checked before building, per the verify-the-noun-before-the-verb protocol.

What the join reads instead is the code the ticket actually wanted: the registry's verb **semantics**. Each cell's entry in `src/data/undertaking-objects.ts` is parsed out of the source, the engine symbols it references resolve through that file's own `../engine/*` import statements, and `subsystemForModule` houses each module. A sustained **mode** has no semantic function, so it resolves through the module that *returns* the op result — the `op: '<mode>'` literal, the producer pattern every graph op uses. `op: 'claim_control'` appears in exactly one module (`strategicGraphOps.ts`); the dispatchers that merely *name* the mode (`phaseAgentDecision`, `undertakingResolver`, `strategicActionLifecycle`) carry `case` labels and comments instead, and are excluded by construction. That distinction is load-bearing: every cell passes through the resolver, so counting mentions would have marked every subsystem reached and produced a view that says nothing.

**Parsing runs against the file on disk, not `Function.prototype.toString()`.** The generators run through `esbuild --bundle`, which may rename colliding identifiers, and a renamed symbol would fail `\bsymbol\b` silently.

## Two findings the build surfaced

**A cell that writes the graph inline has no op home, and that is not drift.** Three do — `seize_item` and `destroy_item` move the `possesses` edge themselves, `expose_mark` its own. The first cut failed them by name. The failure condition is now the honest one: modules found that resolve to **no** subsystem is drift (an unhomed module); *no module at all* means the operation is inline and the cell contributes nothing to this join, already counted by the owned-kind one.

**The parser lost 22 of 42 live cells to comments.** Nearly every registry entry is preceded by a `//` line explaining the cell, and those lines sit inside the entry's own slice, so the comment became part of the key and every commented cell went unrecognised. This is the silent class the map exists to catch — the view would have kept rendering, exit zero, and quietly reported the old answer. It failed loudly only because the generator fails by name on a live cell it cannot see.

## The count diverged from the Done-when, deliberately

The ticket predicted "the UNTOUCHED count drops to the eleven by-design rows". **Measured: six.** THR-1401's hand triage classified eleven as by-design, but five of those eleven are already named readers of live cells in `SUBSYSTEM_READERS` — Encounters & Dilemmas, Attention/Chronicle, Mandate, Doom Clock & Journey, Ambitions & Undertakings — and Personality & Emergent Traits is reached by op (`cure_condition` runs in `traits.ts`). The mechanical join disagrees with the hand count, and the join is the thing being built. Predicates, not counts (THR-688 rule A): the predicate — every UNTOUCHED row prints its reason, held to totality both ways — is satisfied, and the number is whatever the code says.

**One of the six is recorded as a gap, not a design choice.** Omens & Atmospheric Pressure is untouched because the foreshadowing layer reads world events but not undertaking outcomes; its entry says so in those words and names THR-1432, the sibling ticket that files the reader. When THR-1432 lands, the entry goes stale and the generator says so by name. `UNTOUCHED_BY_DESIGN` is total in both directions — a bare UNTOUCHED row fails, and so does a reason for a subsystem something has since started reaching. The second half is the one that matters: without it a reason outlives the gap it explains.

## One authority for module → subsystem

`domainOf` moved from `generate-systems-inventory.ts` into `scripts/subsystems-registry.ts` — the module extracted for exactly this reason, whose header warns that two registries naming the same subsystems differently "is exactly the drift this repo keeps paying for". The inventory generator now imports it rather than keeping a copy, and `subsystemForModule` joins it, returning `null` for the `CROSS_CUTTING_DOMAINS` (`phase`, `game`, `unified`) THR-1407 already carved out. `generate-undertaking-grid.ts` gained an entry guard (the catalog generator's `process.argv[1]` pattern) so the test can import its builders without regenerating the map on import.

## Falsified, not asserted

Each of the three reach paths is pinned **and** falsified by removing its source, against the real registry rather than a fixture — a fixture asserting both sides of a join only verifies itself:

- **owned kind** — World Generation is LIVE-TOUCHED; demote the live cells of the kinds it owns and it is not.
- **op module** — Personality & Emergent Traits owns `trait`, which carries no live cell, and is reached *only* through `cure_condition` in `traits.ts`; remove that reach and it falls all the way to UNTOUCHED.
- **reader** — Spheres & Quintessence reads `use × Power`'s soul-price; demote Attachments' live cells and the reader stops counting, because a reader is only reach while what it reads is live.

Every falsifier moves a status that is non-default before the perturbation, so a no-op perturbation fails the assertion rather than passing it.

`Spheres & Quintessence` also needed its structured reader entry added: the `use × Power` cell's `readBy` prose already documented that the soul-price becomes a `QuintessenceEvent` consumed by `phaseQuintessence` (THR-1428 R4), but the machine-readable entry was missing — which is precisely why the subsystem read UNTOUCHED while its own cell note said otherwise.
