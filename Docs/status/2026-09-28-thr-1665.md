# 2026-09-28 — THR-1665: the hex tooltip sits above the map's labels

**Ticket:** [THR-1665](https://linear.app/threadbare/issue/THR-1665) · **Project:** Thematic Pressure & Living World · **Pillars:** UI (the map overlays); Engine: N/A (no simulation change); Content: N/A (no prose or data).

## What was wrong

The hex hover tooltip hardcoded `zIndex: 10`. The label overlays had made up their own values: region names 20, location names 21, and the agent pulse 18. So a region name drew over the tooltip and cut through its trade-route lines. Hovering Great Silverhold (24, 20) under "MARCH OF SHADOW-KEPT SHADE" showed it. The HexMapV2 container did not create its own stacking context either, so labels at 20–21 also competed with the HUD layer (20) outside the map. That is UI Law 35.

## What shipped

- **`MAP_OVERLAY_Z`** (`src/components/HexMapV2/overlay/mapOverlayZ.ts`) holds the map-overlay band (10–19) from the stacking table. The order, bottom to top, is agent pulse 11, region names 12, location names 13, hex tooltip 15. All four overlays read their z-index from it, and none has a literal any more.
- **The HexMapV2 container sets `isolation: isolate`.** The bands order the overlays among themselves and cannot outrank the HUD.
- **`Docs/design-system/layout-zones.md`**: the "Map overlays" row now lists the sub-bands and names the constant.
- **`mapOverlayZ.test.ts`**: the tooltip is above every label, every value stays in 10–19, the labels keep their order, no overlay file has a literal `zIndex`, and the container is isolated.

## Verified

Checked in the browser at 1920×1080 on `?view=game&seeded&size=medium&nofog`, at tick 50 via `__DEBUG.tick(50)`. Hovering (24, 20) opened the "Great Silverhold–Horseford Road" tooltip, and it covers "MARCH OF SHADOW-KEPT SHADE". Both route lines read clean. The console showed no errors.
