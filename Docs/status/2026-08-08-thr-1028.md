That is every non-trivial PR, not a race. **`npm run impediment:next-id` widens the observation window to where the unmerged rows actually live:** one above the highest `#` across the working tree *and* every local and remote ref — `refs/heads/*` catches a sibling worktree's committed branch (worktrees share one object store), `refs/remotes/*` catches `origin/main` and every pushed PR. Measured on this repo: 95 refs, 53 distinct versions of a 1 MB log, 2.2 s. Refs are deduplicated by blob sha through a single `cat-file --batch-check` first, because reading each blindly would mean ~95 MB of process output to answer a question about one integer. **A content-derived key was declined for the second time** (THR-881 first): the `#N` format is load-bearing across ~500 rows and ~25 prose cross-references, and widening the scan buys the invariant without the migration. **What it cannot do is stated by the tool rather than left to be rediscovered.** Sequential integers have no collision-free allocation without a coordinator, and this is not one: two branches that each append and *neither commits* before the other allocates still collide. The residue ships as a named constant the CLI prints, the skill documents, and impediment #460's rule 2 now records — Done-when 3 permits recording a partial close, and pretending otherwise is how a "solved" class comes back. **The detection half of the predicate was fixed too, then narrowed on measurement.** The ticket's membership predicate is "exposed to a collision it did not cause **and cannot detect locally**", so the allocator also reports ids this tree claims that the merge target claims for a *different* impediment. Scoped to `refs/remotes/origin/main`, the branch this will actually merge into, it reports zero on a clean tree and would report the real ones. Allocation still takes a max across *all* refs, where a stale branch is free because its number can only be lower. **Proven through real git, not narrative.** The Done-when asks for a scripted two-branch fixture, and a narrative argument that a ref scan "would" see the sibling branch is exactly the assertion that was wrong before — so the test builds a throwaway repo, carries the real `merge=union` driver in its `.gitattributes`, and drives two lanes cut from one base: lane A mints `#481`, lane B's own tree still stops at `#480`, and the fixture asserts the **old** rule would have minted `#481` again before asking the new one to separate them.
