# 2026-10-02 — THR-1691: the automatic code-review gate

**Ticket:** [THR-1691](https://linear.app/threadbare/issue/THR-1691) · **Project:** Continuous Improvement · **Directive:** Christian, 2026-10-02 (attended chat) · **Pillars:** Engine N/A, Content N/A, UI N/A (process tooling; no game surface).

## What shipped

Code PRs can no longer arm auto-merge without a review. Before `gh pr merge --auto --merge`, the `review-gate` skill runs two subagents. A cold reviewer sees only the diff and the rubric — never the ticket, plan or PR body — and is told to assume defects exist. A second subagent then tries to refute each finding, and only confirmed ones survive. The author fixes or rebuts what survives, for at most two rounds. The result is a receipt, plus a PR comment that is the durable record.

The PreToolUse hook `.claude/hooks/review-gate.sh` enforces it, with its logic in `scripts/review-gate.ts`. It **denies** a merge on a code diff unless one of these holds:

- a clean receipt exists for the head;
- a clean receipt exists for an ancestor whose delta to the head is docs-only;
- the PR's comments carry a clean marker for the head;
- a commit body carries the exemption line.

Docs-only diffs pass untouched. If the gate itself errors, it allows the merge with a loud warning and a log line rather than stalling every lane.

## Evidence

- **Hook fixture runs:** 30/30 in `scripts/__tests__/review-gate.test.ts`. They drive the real `.sh` against a throwaway repo and cover every Done-when case: no receipt denies, stale receipt denies, open finding denies, docs-only allows, clean receipt allows, exempt line allows. They also cover:
  - a receipt carried across docs and across a main merge;
  - the armed-PR push, including `git -C <dir> push`;
  - a missing PR head, and a remote head that is ahead of the local one;
  - multi-line calls and quoted mentions;
  - fail-soft.
- **Caught before ship by its own demonstration:** an MSYS-style `cwd` (`/c/Users/…`) made every `git -C` call throw from node, so the gate fail-softed into *allow* on the real branch. The fix normalises the path, and a regression test covers it.
- **Caught by its own review:** two rounds on this PR's own diff found 9 bypasses, and the verifier confirmed all 9. All are fixed and tested.
  - Round 1 (4): the worst was a push to a PR that already had auto-merge armed merging unreviewed, because no `gh pr merge` ran.
  - Round 2 (5): the worst were the second line of a multi-line call never being parsed, and `git push -u origin HEAD` looking up a branch literally named HEAD.
  - That count is why the gate is shipped as blocking and hook-enforced: a self-review that writes "verified" would have missed every one.
- **Baseline backtest:** the ten code PRs before this one ([#2160](https://github.com/christianspliid-ui/threadbare/pull/2160), [#2158](https://github.com/christianspliid-ui/threadbare/pull/2158), [#2157](https://github.com/christianspliid-ui/threadbare/pull/2157), [#2156](https://github.com/christianspliid-ui/threadbare/pull/2156), [#2155](https://github.com/christianspliid-ui/threadbare/pull/2155), [#2153](https://github.com/christianspliid-ui/threadbare/pull/2153), [#2152](https://github.com/christianspliid-ui/threadbare/pull/2152), [#2151](https://github.com/christianspliid-ui/threadbare/pull/2151), [#2150](https://github.com/christianspliid-ui/threadbare/pull/2150), [#2148](https://github.com/christianspliid-ui/threadbare/pull/2148)). The reviewer found 4 issues in 3 PRs; the verifier confirmed **4 of 4**:
  - #2151: two high (THR-1696 — a phantom visit stamp, and a missed visit cools the wrong ruin's lead).
  - #2157: one high (THR-1697 — Under Watch never expires).
  - #2153: one medium (THR-1698 — an apex card line never reaches the UI).
  - The other seven PRs came back clean. This is the number the six-week renewal compares against.
