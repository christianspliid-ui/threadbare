# THR-1470 — the UL dashboard reads the leading status word; the annotation becomes a note

**Date:** 2026-09-17 · **Pillars:** Engine (build-time generator) · Content (UL README recount convention) · UI (`?view=ul` detail pane)
**Issue:** [THR-1470](https://linear.app/threadbare/issue/THR-1470/ul-dashboard-generator-status-parser-drops-annotated-status-values-10)
**Plan doc:** none — the ticket body was the spec, filed by the 2026-09-12 retro from impediment rows 958 and 966.

`generate-ul-dashboard`'s status parser exact-matched bare enum words. `**Status:** canonical` parsed; `**Status:** canonical (seated by THR-1380 …)` degraded to `unknown`, emitted *two* warnings (the unrecognized-value one, then — because the degraded status was `unknown` — the "No `**Status:**` line found" one), and the term rendered status-less. The annotated form is the better authoring — it records when and why a term was seated — and it was losing to the parser, which was pushing the convention backwards.

## What changed

- **`parseStatusValue`** (exported, unit-tested) implements the ticket's membership predicate: a value that *begins with* a status word — followed by end, whitespace, `(` or a dash/colon — parses to that status. The remainder, with one leading separator and one whole-value parenthetical pair stripped, is the new **`statusNote`** field on `ULTerm` (`null` for a bare status). `canonical-ish` and `weird-status` stay `unknown`. `SCHEMA_VERSION` stays 1 — additive field, no consumer breaks.
- **`retired` joined `ULTermStatus`.** The Encounters shard had carried `**Status:** retired (THR-108; …)` since THR-1339 and the README tally counts it as its own row, while the parser degraded it — a real status the dashboard could not show. Both `STATUS_COLOR` mirrors got a slate-blue entry, distinct from `deprecated`'s red because the README treats them as separate rows.
- **The "No line found" warning keys on the line's absence**, not on the degraded status — an unrecognized value is now one warning.
- **`ULDetailPane` renders the note** beside the status badge in tertiary text (`data-testid="ul-status-note"`), backtick spans as `<code>`. The term table keeps its badge-only column — one channel per row.
- **README footer recount** now reads `grep -hoE "^\*\*Status:\*\* [A-Za-z]+" … | sort | uniq -c`, which counts the leading word so annotated and bare forms tally as one row, and names the annotated form as the recommended one.
