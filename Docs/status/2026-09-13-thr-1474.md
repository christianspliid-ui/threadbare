# THR-1474 — the aftermath page, read as one text

**Shipped 2026-09-13.** Infrastructure · Content. Project: Encounter Experience.
Plan: none — the ticket body is the spec.

## What was wrong

Christian, on the first sitting with the THR-1220 slice: *"I am wondering if we
even have a holistic test of all the aftermath text, where the agent reads all
the text on the page together, and makes sure there is no repetition, verbosity,
or conflict in the prose? that should catch it."*

Verified in the pipeline, the answer was **no**, and the gap was structural rather
than an oversight. Every stage read the aftermath one *field* at a time:

- the editorial critic's gate 4b reads **seams** — opening→spine, spine→band;
- `check:encounter` runs **per-field** detectors;
- live proof checks that declared blocks **arrive** in a running world, not how
  they read together.

So the page as a player meets it — overview, then every chip's caption in
category order, then the reactions underneath — was never assembled anywhere and
therefore never read. That is how the Snow on the Pass overview and its
`EXHAUSTED` chip came to tell the same fact twice with every gate green.

## What shipped

**One assembly, three readers.** `src/data/content-eval/aftermathPage.ts` builds
the page once, off `compositionContract`'s existing `aftermathFaces` walk (THR-1473
exported it and made it carry each face's resolved `overview`), and three callers
read it rather than each deriving their own idea of what a page is:

1. `pageOverlapFindings` — the machine arm, printing `[page]` lines into the warn
   channel `check:encounter` already has.
2. `renderAftermathPage` — the batch report's new *The aftermath as a page*
   block, per ending.
3. The editorial critic's **Page read** step (prompt § 6b, REVISE trigger 35).

**The pairs are partitioned, not doubled.** THR-1473's `chipSentenceProblems`
already reports overview ↔ chip with a message written for it, and both checks
print into the same channel — so the page arm deliberately skips that one pair
and owns every other: chip ↔ chip, chip ↔ reaction, overview ↔ reaction,
reaction ↔ reaction. This is the one place the implementation reports less than
the ticket's letter asked for; coverage of the pair is unchanged, only the
reporter is, and the alternative was telling an author to fix one sentence twice.
Pinned by a test that asserts the pair is reported exactly once, by the
`[chip sentence]` arm.

**Doctrine in four places, because the rule binds at four moments.** Spec
§ Consequence Draw **rule 1c** (the authority — rules 1 and 1b price a chip
against its own overview and cannot see the rest of the page); SKILL.md REVISE
**trigger 35**; editorial prompt **§ 6b** + gate question **11b**; draft prompt
bullet + gate question **11b**, so authors write the page rather than the fields.

## What the machine can and cannot see

An n-gram overlap is a **lower bound on retelling, never a proof of its absence**
— the caveat `CHIP_OVERVIEW_OVERLAP_RUN_WORDS` already carried. Two residues are
out of its reach *by construction*, and both are now the critic's:

- a **paraphrase** repeats the fact in fresh words and shares no run;
- a **contradiction** shares no words with what it contradicts, ever.

That asymmetry is why the doctrine half is a *reading step* and not a fourth
detector, and it is stated in each of the four doctrine surfaces so no stage
mistakes a green `check:encounter` for an answer.

## Falsification

Each pair kind has a fixture that must go **red** and a controlled twin that must
go **green**, differing only in the words under test — because a page check that
reported nothing at all would pass any assertion that the migrated slice is
clean. The threshold itself is falsified too: a three-word shared run must stay
silent, or the red arms prove only that *some* overlap fires and not that four is
the bar. 20 tests.

The duplicated `AFTERMATH_PAGE_CATEGORY_ORDER` (content-eval must not import the
React adapter into CLI checks) is pinned against the adapter's own
`CONSEQUENCE_CATEGORY_ORDER`, so the copy cannot drift silently — drift would
surface only as a batch report whose page order disagrees with the screen, the
exact class of error this module exists to stop.

## One refactor, and why it was not additive

`normaliseWord` / `wordsOf` / `wordRuns` **moved** out of `doctrineV2Checks.ts`
into a new leaf `proseWords.ts` rather than being copied. An n-gram overlap check
is worth exactly as much as the agreement between the two sides doing the
splitting, so a second splitter would have been a second answer waiting to drift
from the first — the same argument `aftermathFaces` carries in its own header.
The leaf has no imports, which is what lets both readers depend on it without
either depending on the other.
