# 2026-10-06 — THR-1767: the power-progression model lives in the repo

**Ticket:** [THR-1767](https://linear.app/threadbare/issue/THR-1767) · **Plan:** `Docs/plans/2026-10-05-thr-1745-player-power-progression-models.md` · **Pillars:** Engine (tooling, no runtime change); Content N/A (no content); UI N/A (headless script).

## Why

The THR-1745 economy analysis was produced by a scripted-player model that existed only in a session scratchpad. The Dominion prototype tickets need it as a shared, re-runnable measuring stick.

## What shipped

- `scripts/power-progression-model.mjs` (Node, no dependencies, no PRNG). Engine constants are copied, each with its `src/` file cited beside it. The scripted player's parameters are named at the top. Four economies are named configs (`asis` = Model 0, `holdings` = A, `threads` = B, `spheres` = C), plus an empty `dominion` slot. It prints the per-phase table and the ticks-between-growth table for each.
- `npm run model:power` (`-- --model <key>`, `-- --events`, `-- --check`). `--check` asserts every table and cadence line printed in the THR-1745 plan doc and exits 1 on drift.
- One line in `Docs/ops/dev-quickstart.md`. The plan doc now points at the script instead of the scratchpad.

## Measured

`npm run model:power -- --check`: Model 0, A, B and C all reproduce the plan doc's tables to the printed precision, and the cadence lines match (Model 0: card ~94, thread ~134, source ~119 with the first at tick 206, sphere 300, depth ~124).

## Model quirks kept for fidelity (named in the script)

- Depth-tier events take the tick of the previous logged event (`DEPTH_EVENT_USES_PREVIOUS_EVENT_TICK`). The plan's depth cadence numbers depend on this.
- Upkeep is all-or-nothing: an unpaid tick debits nothing and does not count toward promotion. Consecrate is never charged. Find and claim are paid from an off-sphere pool. All source income lands in the primary sphere.
