# THR-1296 — The binder, slice 3 (born real, through the valve)

Third of the plan's six slices, continuing from the slices 1–2 checkpoint. Like those, it is
additive and no simulation travels it yet — nothing *enqueues* a mint until the bind pass lands in

## What landed

**The gap this closes is measured, not asserted.** The recon (THR-1289) read what
`materializeActorSupport` writes when an encounter needs a person the world does not have, and
every omission has a named consequence:

| omitted | consequence |
|---|---|
| `axiologicalProfile` | invisible to every value-scored system; blank identity forever |
| `domainCapabilities` | fails **every** reach floor — cannot act, cannot be scored |
| `locationId` | on the map, absent from `buildHexActorIndex` |
| `narrativeArchetype`, `cooperationStrategy` | no disposition, no prose voice |
| `bornTick`, ambitions | no age, nothing they want — a prop, not a person |
| culture-phonetic naming | a verbatim `spawnName` with no provenance |

So a minted innkeeper could stand in the tavern they were minted for and be unable to take part in
the scene. `src/engine/binding/mintInhabitant.ts` writes the full birth contract instead —
**reusing the existing generators rather than inventing parallel ones**: `generateAxiologicalProfile`
(the birth generator), `generateRoleCapabilities` + `ROLE_WEALTH` (the graduation generators, on the
scale `computeCapability`'s sigmoid expects), `pickCulturalName`, `assignInitialAmbitions` +
`assignAmbitionToActor` (the THR-885 extracted single writer). A second copy of any of them would
be a generator to keep in step, which is the drift shape this plan refuses everywhere else.

**Two things the mint does that neither existing spawn path does.** It writes the `located_at`
edge *and* the denormalized `locationId`, closing the hex-index defect by construction; and it
calls `touchStructure`, so a runtime mint finally invalidates the encounter cache, the distance
matrix and the UI's structural memo (recon defects #4/#9 — today neither mint path touches
anything). It also joins the place culture on `culturalStrength`, the key every reader actually
reads; the births block writes `strength` instead, which is why *its* newborns read as
culture-less. That one is left alone deliberately — it belongs to the pre-existing birth-path
defect ticket the plan asks for at closing, not to this diff.

**The valve.** Mints are queued (`strategicState.mintQueue`), never immediate, and drained by
`phaseAgentLifecycle`'s births block: up to `BINDER_MINT_BUDGET_PER_TICK` (1) per tick, inside the
existing no-death-this-tick guard, and counted against the same one-per-tick shape — a mint this
tick means no ambient birth this tick. That is the THR-814/THR-162 lesson made mechanical rather
than remembered: an unmetered spawn path is how a large map reached ~1010 agents by tick 72. **The
budget is the deliverable.** If mint counts ever exceed it the routing is wrong; raising the
constant to make the count fit is the failure, not the fix. Queue-before-valve also dissolves the
phase-ordering problem the recon raised — decision runs before lifecycle within a tick, so a
request made at T is born at T or T+1 and the waiting checkpoint binds once the mint exists.

**Determinism, stated precisely.** Ids are `mint_<projectId>_<castKey>` — instance-unique by
construction and seed-deterministic because a project id already is. The mint's rng derives from
the *request*, `mulberry32(seed + hash(projectId + castKey))`, never from the tick, so a slow tick
changes **when** someone is born and never **who**. A test drives the same request at tick 10 and
tick 40 and asserts the two people are identical down to the capability map. Draw-count neutrality
holds the other way too: with an empty queue the valve performs no graph write and consumes nothing
from the phase's own rng, which the seed-42 smoke confirms by reproducing slices 1–2's numbers
exactly (386 agents, 52 events at tick 30).

## Two structural moves worth naming

- `generateAxiologicalProfile` **moved** from `agentLifecycle.ts` to a new `agentGeneration.ts`.
  Unchanged — same draws, same order — but the mint needs it, and importing it back out of
  `agentLifecycle` would have made a cycle with the valve call. `generateRoleCapabilities`,
  `ROLE_WEALTH` and `DEFAULT_WEALTH` are now exported from `npcGraduation.ts` (no cycle there).
- `BindingIdentityRequirement` is now an **alias** of `UndertakingIdentityRequirement` in
  `src/types/strategicAction.ts`. The mint request has to carry the same three fields through the
  queue, and a types module must not reach into the engine for them. One definition, two names,
  no drift.
