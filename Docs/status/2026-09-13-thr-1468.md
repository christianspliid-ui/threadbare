# THR-1468 — every slice encounter authors the ending it can reach

**Date:** 2026-09-13 · **Pillars:** Content · Engine-N/A (no engine file in the diff) · UI-N/A
**Issue:** [THR-1468](https://linear.app/threadbare/issue/THR-1468/two-of-the-five-slice-parents-author-no-failure-band-a-pinned-failure)
**Plan doc:** none — the ticket description is the spec.

Pinning `?outcome=failure` on two of the five slice parents returned, as a console warning:

```
[?outcome] The encounter ended on "failure" as asked, but no variant authors that band
— the ending on screen is the base ending, not a "failure" one.
```

## The decision the ticket wanted, and the answer

The ticket filed this as a finding, not a bug, and asked for a *stated* decision: author the missing bands, or record that these two catalog shapes deliberately have none. The case for "deliberately none" was semantic — A Bargain at the Crossroads is a Personality Fork and The Swindled Family an Opt-in Complication, so refusing or declining is a **branch**, not a failure.

**The structure does not support that reading, on three independent counts:**

1. **`failure` is a reachable action outcome on all four.** Every branch step carries `failBehavior: 'fail_action'` — `CROSSROADS_ACCEPT_STEP`, `CROSSROADS_REFUSE_STEP`, `FAMILY_GUIDE_STEP`, `FAMILY_PASS_STEP`, `KIN_STEP`, and Full Moon's single step. Nothing about these shapes keeps the band from being reached.
2. **Each already authored distinct failure prose one layer down.** Every one of those steps has its own `failureAfterimage` — *"The word came out hedged, and the stranger accepted the hedge with a smile that said it did not matter."* An author who thought a step-level failure meaningless here would not have written that sentence, twice per fork.
3. **Same-shape siblings in the same file author the band.** The Swindler Found has the identical fork shape (`positive`/`negative`, `continue_weakened` → `fail_action`) and authors `failure`; so does The Table That Holds. The Grateful Kin's single-`fail_action`-step shape is The Unsafe Bridge's, which authors `failure`. The absence cannot be a property of the shape.

The conflation is fork-vs-step: the **fork** picks the branch, then the **branch's own step** resolves on the full ladder. Giving the word badly is not the same event as declining to give it.

## The membership was wrong in both directions

The ticket named two parents. Its re-check comment then said *"the ticket names the wrong parents"* and corrected Snow on the Pass. **Both readings were off, and the re-check's correction was the one that was mistaken:** Snow on the Pass authors `failure`, which is exactly what the ticket's own inventory table already recorded — the comment's measurement agreed with the table it was contradicting.

The comment was nonetheless right about the important thing: state a predicate and re-derive. Done — but not by the browser walk it proposed. The cheap correct measurement is **`authoredOutcomeBands()`** in `src/engine/debugOutcomePin.ts`, the function the `[?outcome]` console line reports from. Run headlessly over all nine slice templates it gives the complete inventory in one pass, with no pin, no flake, and none of the step-ordering traps the comment warns about:

| Template | `failure` before |
| -- | -- |
| `unsafe_bridge` · `snow_on_the_pass` · `riders_behind_caravan` | yes |
| **`bargain_at_crossroads`** | **no** |
| **`full_moon_collection`** | **no** |
| **`swindled_family`** | **no** |
| **`grateful_kin`** | **no** |
| `swindler_found` · `the_table_that_holds` | yes |

Restricted to the five *parents*, the ticket's named pair is exactly right. But the predicate covers the whole chain, and there it catches two sequels nobody had walked. **Four templates, six bands** — the two forks need one per path.

## What was authored

| Where | Shape | Why that shape |
| -- | -- | -- |
| `bargain_at_crossroads` / `negative` | `overview` + `changes` | Base reaction carries the `attachment_grant` and the Full Moon seed |
| `bargain_at_crossroads` / `positive` | `overview` + `changes: []` | The offer fading is not a write; base repute gain survives |
| `full_moon_collection` / `fallback` | `overview` + `changes` | Base reaction spawns the gift — a badly *stood* exchange still hands over the parcel |
| `swindled_family` / `positive` | `overview` + `changes: []` | Both seeds must survive: hope is intact, so word of the kindness can still travel |
| `swindled_family` / `negative` | `overview` **only** | Declining writes the same things however the walk went; what a failure changes is how the evening sat, and an evening is prose |
| `grateful_kin` / `fallback` | `overview` + `changes` + **`reactions`** | The one that must author its own — see below |

**`applyAftermathOutcomeBand` substitutes `reactions` wholesale**, so five of the six deliberately author no `reactions` at all: a band that did would silently drop the promise grant, the gift, or the sequel seeds its path exists to plant. The Grateful Kin is the exception and must author its own, because the base reaction writes `SLICE_KIN_WELCOME_DELTA` (the plain-success door) — inheriting it would have a fumbled thanks open the door exactly as wide as a well-stood one. It writes `SLICE_KIN_WELCOME_DELTA_FUMBLED`, the same floor `critical_failure` writes: the ladder has three rungs for four bands and *"kin are stubborn"* is the stated floor, not a per-band curve. `SLICE_TABLE_SEED` is restated there for the wholesale-replacement reason.

No new tunable constant was needed — every delta and magnitude band the six use already existed and is named (NFP #1), and the change is purely additive (NFP #6).

## The gate, and one count turned into a predicate

Done-when 3 asked that the rule be written where the next author meets it. It is a test — `vertical-slice.test.ts` § *every encounter authors the failure band (THR-1468)* — with a ~30-line header stating the rule, recording what the filing sweep got wrong, and answering the deliberate-absence argument so it is not re-litigated. Three assertions: the predicate over all nine templates; a **falsification arm** that strips the band from one template and confirms the predicate rejects it (without it, the gate passes identically whether `authoredOutcomeBands` reads band keys or returns a constant); and a pin that the five inheriting bands author no `reactions` while the kin band writes the fumbled delta and restates the seed.

It shares `authoredOutcomeBands` with the diagnostic deliberately — a gate computing authorship its own way could pass while the console line a reviewer reads says the opposite.

**One existing test had to be repaired, and the repair is the interesting part.** THR-1182's *"is planted from all three Grateful Kin bands"* asserted `expect(seeds.length).toBe(3)`. The kin `failure` band restates the table seed, so it read 4 and failed — while the invariant it guards was perfectly intact. The count was a snapshot of how many bands existed when THR-1182 shipped, and it also could not distinguish the case it exists to catch (one *particular* site forgetting the seed) from a site being added. Rewritten per THR-688 rule A as a predicate over planting **sites**: every site that authors its own `reactions` must restate the seed, the base reaction covers the rest, with an anti-vacuity floor. It now *catches* a future band that forgets the seed instead of rotting on one that remembers.

## Deferred, with its brief

[THR-1509](https://linear.app/threadbare/issue/THR-1509/authored-band-coverage-is-measured-per-template-but-reached-per) — **`authoredOutcomeBands` unions across variants, but a player is only ever on one.** So a band authored on `positive` counts as authored for a player resolving on `negative`, who gets the base ending. `swindler_found` is the sharp case: its two paths author **disjoint** sets, so the union reads as full four-band coverage while each path is missing two — and a reviewer pinning that band is told *"Showing the authored critical_failure ending"* while looking at the base one. The diagnostic does not merely stay silent there; it reports the opposite of what is on screen.

Deferred rather than fixed because the fix needs a design call — whether coverage is `failBehavior`-derived per variant, a union contract, or (cheapest and an improvement under any of them) a variant-aware diagnostic. The ticket's predicate is template-level, matching the diagnostic's own granularity, so tightening it is a separate scope with its own engine review.
