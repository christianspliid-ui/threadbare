# 2026-09-23 — THR-1534: band casualties and commissioned killings ask the "will not die" ward

**Ticket:** [THR-1534](https://linear.app/threadbare/issue/THR-1534) · **Project:** Physical Conflict · **Pillars:** Engine (Content N/A: no content changes; UI N/A: no surface reads the ward). **Plan:** none — unambiguous defect with a stated fix.

## What shipped

`markMortalDead` reads the `death_prevented` ward only when its caller passes a rule-override context. Two of its four production callers passed none, so a mortal the god had warded still died as a band casualty or to a commissioned killing, with no event and no trace.

- **Band casualty.** `applyCasualty` (`src/engine/groups/bandOpposition.ts`) takes an optional `RuleOverrideContext`. `applyContestConsequences` builds it from `state` in the same shape the plot uses. A warded victim yields no casualty that contest, and nobody else is picked in their place. The contest still costs cohesion and writes the grudge. The `warded` branch that was dead code is now live.
- **Commissioned killing.** `GraphOpContext` gains an optional `overrideCtx` (additive). `executeMarkMortalDead` passes it to the funnel. All three production builders that hold `GameState` fill it: the two in `unifiedActionResolution.ts` (graph-only step ops, hex-action ops) and the per-tick control-effect ops in `phaseControlEffects.ts`. With no context the op behaves exactly as before (fail-soft).
- No new trace. The contest trace already records the casualty, and the op result already records success.

All four `markMortalDead` callers now honour the ward. The Physical Conflict fight framework will be the fifth.
