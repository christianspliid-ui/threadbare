# 2026-08-29 — THR-1359: retired-Reach residue outside `reachWeights`

THR-1345 closed `flesh` in faction `reachWeights`; the sweep that ticket required found the retired 9th Reach still keyed into roughly ten further production sites, untriaged. This is that triage, and it changed the ticket's own premise twice.

**The candidate list was short because its grep was.** The ticket swept `--include=*.ts`, so three `.tsx` display maps never appeared: `AgentInfoCard.tsx`, `ThreadDetailView.tsx` (whose comment read *"8 reaches after flesh removal"* directly above a 9th `flesh` key) and `ArchetypeCard.tsx`. The better membership predicate turned out to be the typechecker's own error set — it also surfaced two sites the key-pattern grep structurally cannot see, because there `flesh` is a *value* in a Reach-typed position rather than a key.

**Two sites were live, not inert.** The ticket's "why it is Low" reasoning — readers iterate `REACH_DOMAINS`, so a stale key is dead weight — held for eight sites and failed for two. `reward-attachment-catalog.ts`'s **Battle Salve** granted `+0.10 Flesh` on each of three charges, so a shipped consumable did nothing when used; it is now `stone`, which the item's own `censusTag` already declared and which is the canon migration target for body-and-endurance content. `orchestrator.ts`'s `SPHERE_TO_DOMAIN` mapped `life → flesh` inside the live `phaseDilemmaDetection`, feeding a non-`ReachDomain` into `computeStakes`; remapped to `heart`, the pairing `scry.ts` already asserts. That remap is behaviour-identical today — `computeStakes` special-cases only gold and iron — and is recorded as such rather than claimed as a fixed bug.

**`revelationEmitter.ts` was the actual hole the ticket predicted.** Its `REACH_TO_VALUE_MAP` was annotated `Record<string, string>`, and the substring fallback beneath it casts `Object.keys(map) as ReachDomain[]` — so a stale key there was reachable and would have written a retired Reach into an agent's revealed-knowledge record. Narrowed to `Record<ReachDomain, string>`, which makes that cast honest.

**Three sites are deliberate legacy mappings and were kept with the reasoning written down.** `world-model.json` still ships nine `reach.*` nodes — `reach.flesh` among them, with six edges — and `aftermathWords.ts`/`codexRegistry.ts` are keyed by world-model node suffix, not by `ReachDomain`. Deleting those rows would not remove a retired Reach; it would make a node that still exists render as a raw key, against a `TOOLTIP_BACKED_REACHES` set pinned by `tooltipValidation.test.ts`. Measured: no live action template declares `reach: 'flesh'`, so they render nothing today and are the fail-open path if one ever does.

**Why `tsc` never stopped any of this:** every one of these excess-property errors *did* fire, and sat recorded in `typecheck-baseline.json`, where a recorded error is a permitted error indefinitely. The count moved 2942 → 2929 with zero net-new. New guard `assertValidAttachmentReaches` reads the values the graph will actually carry — falsified by two tests that reconstruct the exact shipped Battle Salve and rations shapes and assert the guard rejects them.

**Left alone, deliberately:** `flesh` in test fixtures. Cleaning two of them unmasked unrelated optional-property assignability debt whose only cheap fix was `as` fixture casts — a known anti-pattern here — so those two were reverted and the residue is filed rather than papered over. The root residue, `reach.flesh` and its four `action.flesh.*` nodes in `world-model.json`, is a data migration with vault-generation blast radius and is filed separately.
