### 2026-10-03 — THR-1705: a name in a hex's people list opens that mortal, and the hand says who it will hit

**The bug.** Cold playtest round 2: all three testers clicked a name in a hex's people list and saw only a highlight. The row called `handleAgentSelect`, which moves the cast target and opens the drawer but sets no thread node, so the right panel never changed. One tester then cast Piercing Gaze with The First on screen, and it landed on the mortal clicked minutes earlier. The drawer threw its `targetName` away, and GameView only filled it for retinue members anyway.

**The fix.** The hex panel row now uses `handleThreadNodeSelect(id, 'agent')`, the opener the map and the Hex Chronicle already use, so the mortal's detail panel opens. The ActionDrawer shows "Casting on <name>" beside Cast, on the layer tabs' dark pill so it reads against the map, and leaves the line out when there is no name. GameView now names any selected mortal, falling back to the graph node's name when the target is not in the retinue.

**Evidence.** `hexRowOpensAgentSheet.test.tsx` runs the real hook, the real `HexDetailView` and the real `ActionDrawer`: a row click sets the thread node and the selection, and the drawer reads "Casting on Thessa" for a stranger. Source guards pin the GameView wiring. Two new ActionDrawer arms check the line appears, and is left out when there is no name. Browser check on `?view=game&seeded&size=medium` at 1920×1080: clicking Vara's row opened Vara's panel, `getActiveUIState().selectedAgentId` was `avatar.hunger.witness`, and the drawer read "Casting on Vara". No console errors. Screenshot: `Docs/evidence/thr-1705/hex-row-opens-sheet-drawer-names-target-1920x1080.png`.
