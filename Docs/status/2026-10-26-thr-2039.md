# THR-2039 — A tavern query seed reaches the tavern

**Shipped 2026-10-26.** Found by the design lane while deciding THR-1929.

**What changed.** A seed resolved by query (`#tavern_night`) or by a legacy family (`tavern`) now accepts the mortal's own Place type where they stand, as well as the Location-tier subtype. All ten tavern members gate on `sublocation-type.tavern`, which no Location carries. Before, the query path judged only the town, so the family withered even inside the tavern. `src/engine/encounterSeeding.ts`:

- `gateAcceptsPlace` is the one gate test, shared by `templateAcceptsWhereTheyStand` (THR-1929's templateId path), `eligibleAt` (the query path) and `matchFamilyTemplate` (the family path).
- `JudgedLocation` carries `sublocationTypeId` at the feet only. A distinct resolution anchor stays Location-tier. When the anchor is the town the mortal stands in, the two collapse into one judgement and the mortal's Place counts there too.
- This only widens: a template eligible before stays eligible. A query with no fitting member still withers.

**Evidence.** `npm run gate`: PASS (test, typecheck, build, encounter, CLI smoke). New `src/engine/__tests__/encounterSeeding-tavernQuery.test.ts` (5 tests): in a tavern Place the query spawns a tavern member and `content.query_resolved` traces a candidate count above 0. At the market district of the same town it withers with `content.query_empty`. An anchor on the same town counts the tavern, a distinct anchor does not, and the legacy `tavern` family fires in the tavern.
