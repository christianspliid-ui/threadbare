# CI/CD tweak ledger

Append-only. Every harness change that is meant to move a flow number gets an entry here **before** it ships: what changed, the measured reason, the hypothesis (metric, direction, target) and the revert condition. The weekly `tb-cicd-review` lane (`cicd-review` skill) judges each `open` entry against `Docs/ops/cicd-metrics.tsv` and closes it as `kept` or `reverted`. Verdicts: `too early` (< 15 ticket PRs merged since), `improved`, `no effect` (2 judged weeks inside the noise, so it's a revert candidate), `regressed` (2 judged weeks the wrong way, so revert).

Baseline noise (4 weeks 09-12 → 10-03, before either entry below): merges/day 7.7–13.0, catch-up 6.6–13.3 %, slow > 60 min 3.7–10 %, peak concurrent 2–3.

## 2026-10-23 — Step 1.6 reads the tail of a recent `succeeded` pickup run
- Status: **withdrawn before ship (2026-10-23).** The review gate's round-1 reviewer found that nothing makes a pickup run call `wrap_up`. Spot reads confirmed it: the 10-21 20:51Z stand-down's tail ends in its closing text with no `wrap_up`, and the 10-23 21:25Z run's tail reads only `[result] done (success)`. A missing `wrap_up` therefore does not mean a run is alive. Each silent stand-down would have made the next run stand down, and the lane would have stalled until the 60-min silence bound. Nothing shipped. The underlying finding stays open for next week: no agent-readable signal yet separates "waiting on a subagent" from "finished".
- Drafted change (not shipped): `.claude/skills/pull-work/SKILL.md` Step 1.6. For every other `tb-opus-pickup` row with `status: "succeeded"` and `last_activity_at` within `PREDECESSOR_SILENT_MINUTES` (60), call `mcp__ccd_session_mgmt__list_events(session_id, limit: 3)`. A tail with no `mcp__ccd_turn__wrap_up` call counts as an active run; a `list_events` error counts as active (fail closed).
- Why: 14 overlapping pickup pairs in 50 runs on 2026-10-21, 10 of them after THR-2003 had made every gate fit the foreground. Subagents always run in the background, so a run waiting on its reviewers shows `succeeded`. The second runs stood down only on a guess. A pre-THR-2003 overlap of the same kind let the 06:49Z run claim THR-1960 while the 05:53Z run held THR-1937 `In Dev` (WIP 2), and let the 08:25Z run redo 26 min of gate and review on PR #2510.
- Hypothesis: no claim or push while another pickup run is alive: zero duplicate builds, zero WIP-2 claims, zero push collisions between pickup runs. Overlapping rows will still appear, because the scheduler still starts a run when the turn ends; they should now stand down on the check, not a guess. Count from `list_task_runs` and the overlapped runs' summaries. No TSV column.
- Revert if, over 2 judged weeks: the tail read stands the lane down while no other run is alive (a finished run whose tail lacks `wrap_up`, so the next runs stall until the 60-min silence bound); or `list_events` is unavailable to unattended runs, so the check always fails closed.
