## How a round starts

Christian says, in chat, some variant of *"run context-cleanup round N"* (or names the layer). One session runs the whole round: audit → his calls → sweeps → registration. If he is present, calls resolve in chat mid-round (round 1 shipped same-day this way); if the audit runs unattended, park at the end of Phase B with the calls in the report and let the hourly briefing surface them.

**Session setup:** `EnterWorktree` (never work in the home tree); junction `node_modules` from a verified-healthy donor per `Docs/ops/sandbox-limitations.md` (probe `.bin/vitest`, `New-Item -ItemType Junction` as its own call, strip with `[System.IO.Directory]::Delete($path,$false)` at closeout); run `node --experimental-strip-types scripts/session-precheck.ts`.

## The six phases

### Phase A — Audit (the `/guidance-audit` protocol, applied to a layer)

1. Invoke the **`guidance-audit`** skill and follow it. Read `Docs/guidance-manifest.json` first — a round's layer may already be partially registered (prose is; round 1 added identity-vision / cosmology / coordination-process).
2. **Build the yardstick live**: read every file in the round's *Authorities* column below, in full, this session. Write 10–16 numbered operative rules — specific and checkable, never vibes. Note each authority's version/date. Age is a search hint, never evidence.
3. **Partition the corpus** (the round's *Corpus* column) into 2–4 partitions that each fit one careful reader — typically *skills*, *repo docs*, *vault* — plus a bounded discovery grep so the audit finds what nobody registered. Dispatch **one Explore subagent per partition, in parallel**, each given: the yardstick verbatim, its file list, and the verdict vocabulary `CURRENT | DRIFTED (quote mandatory) | INTERNALLY-CONTRADICTORY (quote both sides) | DELETE-CANDIDATE (name the live replacement) | NOT-AUDITED (why)`, plus a **ranked pollution list ordered by blast radius** (how early/often agents load it), not severity. A verdict without its quote is not a finding — ask again. Absence is explicit: a failed partition reports `not audited`, never silence.
4. **Audit the always-load core of the layer yourself** — the highest-blast-radius files deserve the orchestrator's own eyes, and you need them read for Phase C anyway.
5. **Every grep excludes `.claude/worktrees/**`** — stale full-tree checkouts return old copies of the very rules under audit (impediment #918).
6. Expect and record **stale stale-lists**: round 1 found `Docs/canon/cosmology.md`'s warning list 100% false (every row long-fixed, the live pollution unlisted). Verify every "X is stale" claim in canon before repeating it; the fix list is part of the round.

### Phase B — Report and the calls

Merge into one report keeping two questions apart: *is this surface wrong?* (edit) vs *should this surface exist?* (tombstone/delete). Publish as an artifact with Rule-Zero links (repo files → GitHub blob URLs pinned to `main`; vault files → labeled vault paths). End with **Christian's calls** — only genuine creative forks (naming, meaning, depth-of-rewrite); everything that records an already-made decision is presented as *will ship, veto welcome*, per the 2026-08-12 agreed-outcome rule. No open questions parked in docs — ask in chat.

### Phase C — Ship (on his go)

1. **File the round's tickets** in Linear (project: Continuous Improvement, priority High, the audit artifact + his verbatim approval quoted in each description — `human gate satisfied via chat review <date>`). Typical shape, 4–6 tickets: one retirement/correctness sweep, one deletion/tombstone pass, one dedup-to-pointers pass, one vault pass, one structural move if a big always-load file needs a diet. **Create them in Todo (or straight to In Dev for the one being worked) — never Ready for Dev mid-round**, so the hourly pickup lane cannot collide with the session. `blockedBy` relations encode the file-overlap order.
2. **Work them serially, one In Dev at a time**: branch per ticket **from fresh `origin/main` after the previous PR merges** (a branch switch reverts working files — on overlap, edit only disjoint files until the prior PR lands, then `git merge origin/main` into the branch and finish). Ship each with `gh pr merge --auto --merge` and move on; docs-only PRs land in ~1–2 min, code PRs in ~15.
3. **Gates per `Docs/canon/verification-gates.md`** (authoritative): classify the diff first; docs-only owes only the doc gates; tree-diffing freshness gates run last, immediately before push; `lint:plan-doc -- --staged`, never bare; `classify:diff` is vacuous before the commit exists. Every commit that touches a registered authority/dependent carries its `Guidance-sweep: <doctrineId> — <disposition>` line. `Fixes THR-XX` alone on its own line in commit body AND PR body; bare ids elsewhere.
4. **Vault work** is filesystem-only via `OBSIDIAN_VAULT_PATH`, has no git: back up any file you rewrite (to the session scratchpad), prefer dated banners over deletions (delete only 0-byte strays), give every edited Vision file its dated `*last iterated*` signature, append the vault log, and regenerate `Index.md` (`npm run rebuild-index`) after bannering — the generator takes each page's first sentence, so banners placed as the first body line become the index entry. A vault-only ticket closes via its repo-side closeout PR (status fragment + changelog + history carry the `Fixes` line).
5. **Editing a scheduled-task prompt mirror** (`Docs/ops/scheduled-task-prompts/`) means editing the **live copy** at `C:\Users\chris\.claude\scheduled-tasks\<id>\SKILL.md` in the same pass. **Stale worktrees are never removed by the session** — the reaper owns disposition (THR-674).
6. **Closeout per ticket**: status fragment (`Docs/status/YYYY-MM-DD-thr-XXXX.md`), changelog + history appends (via a temp file + `awk`/`cat`, never heredocs), Linear completion comment with evidence, bump `last_validated_against` on skills whose instructions changed. Union-merge files conflict server-side — a `DIRTY` PR is fixed with `git merge origin/main && git push`, then re-run the freshness gates before that push.

### Phase D — Register (what makes the round stick)

End the round by **registering or extending the layer's doctrines in `Docs/guidance-manifest.json`**: authorities (the pages that define), dependents (repo restatement sites), `manualDependents` (`vault:` paths, relative to `TheFantasyWorldSimulator/`). This is the answer to Christian's "how do we do that continuously?" — the change-time gate + `/guidance-audit` + the weekly retro's Step 5d take over maintenance from here. Also: update the audit artifact with the shipped outcome; update the `context-cleanup-program` memory; hand Christian the round summary with every reference linked.
