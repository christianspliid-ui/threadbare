# Intent proposal — THR-430 Schism

## Verbatim user ask (Linear issue THR-430 description)

> Deferred from THR-400 Faction Action Expansion. Schism is the **fracture** verb at tier 3 — it lets the player plant a doctrinal split inside a faction. Within N ticks the faction either reforms (reputation hit + lost members) OR splits into two factions (territory shrinks, war risk between halves). **The player forces the crisis; they do not choose the resolution.**

Coordination block from the issue:
- Suggested model: model:opus-4-6 (prose authoring of the schism resolution encounter is the bulk of the work)
- Mutex with: any work touching `src/data/unified-action-templates.ts`, `src/types/faction.ts`, `src/data/faction-definitions.ts`
- Parallel-safe with: most other work
- Done when: schism casts plant the pending marker, the resolution tick produces a real two-faction split when conditions warrant, member/territory partition is deterministic and tested, `faction.encounter.schism_resolution` ships with prose, traces emitted, `npm test` + `npx tsc --noEmit` clean, screenshot at 1920×1080 of a post-schism world map showing the two halves.

## Vision premise

THR-400 audit (2026-05-11) verdict: *"yes, file"* for the philosophy *"player forces the crisis, doesn't pick the resolution."* This is the design hook — outcome ambiguity matches the "player as god, not protagonist" pillar.

## What the plan doc proposes

1. **New action template** `action.faction.schism` (star/chaos, cost 14, rarity 3) targeting factions.
2. **New GraphOp** `plant_schism` that sets `schismPendingResolutionTick`, `schismPlantedTick`, `schismActorAgentId`, `schismBaselineCohesion` on the faction node.
3. **New tick phase** `phaseSchismResolution` (Phase 6.653, after `phaseFactionActions`).
4. **Decision logic** `decideSchismOutcome` — weighted scalar from leader-cohesion drop + member-axiology spread + dissent score → reform or split via seeded PRNG.
5. **Reform branch** new runtime `applyFactionReform` — reputation penalty + expel K most-misaligned members.
6. **Split branch** reuses existing `faction_splinter` aftermath machinery (already implemented in `encounterAftermath.ts:1611–1726`).
7. **Encounter** `faction.encounter.schism_resolution` planted on most-threaded member at resolution tick, two branches (split / reform) × two steps.
8. **UI** pending-schism banner in faction detail panel, hex-map fractured-ring signifier on controlled hexes during pending window, chronicle highlight on resolution.
9. **9 new tunable constants** in `faction-constants.ts`.
10. **3 new trace categories** with TypeScript interfaces.
11. **7-row fail-soft table** covering dissolved faction, faction-of-one, no leader, decision throw, partial split failure, no expulsion candidates, no encounter host.
12. **Tests** — phase unit, faction-state, fail-soft, reform runtime, action contract, 30-tick CLI smoke.
13. **Suggested model** `model:opus-4-6` for the prose-heavy encounter authoring.

## Specific claims to verdict

1. **Does the plan satisfy the verbatim ask?** Yes — every Done-when condition is addressed: pending marker plants, split produces real two-faction graph mutation, member/territory partition deterministic (reuses tested splinter machinery), schism_resolution encounter ships with prose, traces emitted, screenshot in Definition of Done.
2. **Does the plan preserve the design hook?** Yes — there is *no* UI to cancel a pending schism, no UI to influence outcome. The player casts and observes. Outcome is decided by faction state at resolution, not by player choice.
3. **Three pillars covered?** Engine (action, GraphOp, phase, decision logic, reform runtime, constants, traces, fail-soft). Content (action prose, two outcome chronicles, splinter name table, schism_resolution encounter, three new conditions). UI (banner, action drawer surfacing, hex-map signifier, chronicle highlight, debug bridge).
4. **No new node types invented?** Confirmed — uses existing actor/faction node, existing `member_of` and `controls` edges. New work is properties on faction nodes + a new tick phase. No new edge types.
5. **NFP compliance?** All 7 NFPs marked PASS with rationale.
6. **Scope creep?** No — proposes the minimum subsystem needed. Reform branch is new but necessary (the existing splinter machinery only handles the split outcome). The decision logic is bounded to three signals.
