## scope (what this plan does)

Engine-pillar plan doc for the binder: a scored find/modify/mint board (five weighted terms, one
mint row, modify as a penalized variant row, identity contradiction as veto); per-step
anchoring at the lifecycle seam with a serializable binding ledger; persistence enforcement split
between deferring housekeeping reapers and loud honest breakage via one optional
`WorldGraph.removeNode` hook, with the full verified reaper inventory; broken must-persist
bindings forcing named complications at the next checkpoint; a born-real mint path (full birth
contract, reusing existing generators) queued through the lifecycle valve with a tunable budget
and seed-deterministic instance-unique ids; a version-keyed role census for the scarcity term;
the remote-anchor rule gated at candidate generation (armies-only v1, provider interface for
networks/holdings); and per-template opt-in encounter migration with one migrated exemplar.

## load-bearing decisions touched

- **Everything is a graph node/edge** — respected; the binding ledger is game-state records *about*
  nodes, deliberately not a new edge type (a `bound_by` edge was considered and rejected in favor
  of the ledger + hook: an edge would make bindings visible to `removeNode`'s cascade but would
  also mint a new edge type for transient bookkeeping — the ledger keeps the graph clean and the
  hook provides the visibility). If the judge reads this as requiring the edge instead, that is a
  genuine design question — flag it.
- **No inventing node types without verification** — none invented; `spawn_npc`/`spawn_sublocation`
  create instances of existing types through existing creation code.
- **Agent position three-tier model** — `resolveLocationToHex` used throughout; the plan *fixes*
  the checkpoint module's single-level divergence.
- **Encounter awareness is hex-granular** — the distance term is hex-geometric, honoring the
  rejection of location-hop awareness.
- **Engine caches owned per session** — the census follows the `SimulationRuntime` version-keyed
  discipline verbatim.
- **The world graph is mutated in place / touch discipline** — the mint path calls
  `touchStructure` by contract, closing a measured gap.
- None of these decisions is being *changed*.

## kill criteria

- The golden test on the legacy encounter path fails after the opt-in route lands → the promotion
  changed un-migrated behavior; stop, that is the one thing "opportunistic migration" forbids.
- The Done-when's three-mode evidence shows the board degenerate (one mode wins everywhere
  regardless of scarcity) → the weights are mis-shaped; retune before doc 2 authors against them.
- Mint counts exceed the budget or population growth trends toward the THR-162 stall in a
  150-tick run → the valve routing is broken; the budget is the deliverable, not a hope.
- The removeNode hook shows measurable tick-time cost in the engine smoke → demote to
  lazy-validation-only and file the finding (the hook is an optimization of loudness, not a
  correctness requirement).
- If per-step binding proves impossible without violating the checkpoint module's
  graph-read-only contract, that contradicts the decide/apply split this plan asserts — surface
  rather than patch.

## author notes for the judge

- The five weights are named exactly as ruled (role-fit → `castRoleFit` in code purely to avoid
  colliding with the existing, semantically different `scoreComponents.roleFit` — the *concept*
  is the verdict's role-fit).
- The armies-only v1 remote-anchor set makes remote undertakings rare until networks/holdings
  land. This is stated as honest sequencing, not a gap — the judge should check it against the
  verdict's "T1 networks become the transport layer," which implies exactly this arrival order.
- The plan consumes doc 1's `rebindRequested` contract and widens the `complication` moment class
  beyond critical failure. Both are the review-sanctioned seams (§3 rows for docs 1/3); the
  widening is additive.
- The bound-ledger-vs-`bound_by`-edge call (load-bearing decisions section above) is the one
  place I weighed a graph-purity tradeoff myself; I believe the ledger is right and the
  relationships-are-edges rule governs *entity-to-entity* relationships, not bookkeeping about
  system state — but it is the closest thing in this plan to a judgment the constitution could be
  read against.
