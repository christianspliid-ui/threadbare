# Culture Generator Design (Pass 1 — Generation Only)

**Date:** 2026-03-07
**Status:** Approved
**Scope:** Culture node generation at world seeding time — composite modifier composition, culture-actor/location assignment, identity storage. Defers traits, drift, insider beats, and conquest dynamics.
**Parent design:** `2026-03-06-culture-bounded-context-design.md`

## Overview

This is the first implementation pass of the Culture Bounded Context. It focuses exclusively on getting cultures *into* the world graph with composed identities at world seeding time. Later passes will add the `cultural` trait category, cultural drift per tick, insider beat gating, and conquest classification.

## Decisions

### 1. Separate engine module (`src/engine/cultureGenerator.ts`)

Follows project pattern: each domain has its own engine module (disposition.ts, delivery.ts, contextBuilder.ts). The culture generator is a set of pure functions called from `seedWorld()`.

**Rejected:** Inline culture logic in worldSeed.ts — violates separation of concerns.

### 2. New type file (`src/types/culture.ts`)

Culture identity is a first-class type with its own file. Contains `CultureIdentity` (composed modifier output), `CultureEdgeProperties` (edge data for culture assignment), and tunable constants.

**Rejected:** Adding to existing types/index.ts — culture types are substantial enough to warrant their own file, like disposition.ts and scry.ts.

### 3. Composition: foundation × creation spheres × biome

Each culture is generated by:
1. Selecting a foundation bias (weighted by World-Soul's current foundation balance)
2. Selecting 1–2 venerated creation spheres (random, weighted by cosmology)
3. Selecting primary biome from the origin location's terrain
4. Merging modifier sets from culture-content.ts via lookup functions

The composed identity stores merged keyword pools, material vocabulary, metaphor palette, and trait seed IDs.

**Rejected:** Hand-authored culture profiles — doesn't scale, ignores World-Soul influence.

### 4. Culture count: 2–4 per world

Enough for cultural tension without overwhelming a small world. The first location's terrain determines the first culture's biome; remaining cultures sample from other location terrains to ensure biome variety.

### 5. Actor culture assignment: budget model

Per the bounded context design:
- 70% of individuals get 1 culture (strength 0.5–0.9)
- 20% get 2 cultures (strengths sum ≤1.0)
- 10% get 0 cultures (cultureless)
- Factions always get 1 culture (strength 0.6–0.95)
- Assignment uses `belongs_to` edges with `culturalStrength` property

### 6. Location culture assignment: dual-layer

Each location gets two culture edges:
- `culture_historical` edge — permanent, based on origin culture of that region
- `culture_current` edge — initially same as historical, diverges after conquest (later pass)

Both use the same `belongs_to` edge type with a `cultureLayer` property to distinguish them.

### 7. Culture naming: generated from modifiers

Culture names are composed from foundation + sphere + biome fragments. Examples:
- Chaos + Force + Desert → "The Storm-Born Iron Sands"
- Order + Mind + Mountain → "The Stone Codex of the Peaks"

Name fragments live in culture-content.ts (to be added as a small content extension).

## Type Definitions

```typescript
// src/types/culture.ts

export interface CultureIdentity {
  foundationBias: string;            // 'chaos' | 'order' | 'light' | 'darkness'
  veneratedSpheres: SphereName[];    // 1-2 creation spheres
  primaryBiome: TerrainType;
  socialStructure: string;           // from foundation modifier
  accountability: string;            // from foundation modifier
  behavioralKeywords: string[];      // merged from all 3 layers
  materialVocabulary: string[];      // merged from creation + biome
  metaphorPalette: string[];         // merged from foundation + biome
  formativeTraitSeedIds: string[];   // which formative traits this culture grants
  behavioralTraitSeedIds: string[];  // which behavioral traits this culture carries
}

export interface CultureEdgeProperties {
  culturalStrength: number;          // 0.0–1.0
  cultureLayer?: 'historical' | 'current';  // for locations only
}

// Constants
export const CULTURE_COUNT = { min: 2, max: 4 };
export const CULTURE_STRENGTH_INDIVIDUAL = { min: 0.5, max: 0.9 };
export const CULTURE_STRENGTH_FACTION = { min: 0.6, max: 0.95 };
export const DUAL_CULTURE_PROBABILITY = 0.2;
export const CULTURELESS_PROBABILITY = 0.1;
```

## Engine Functions

```typescript
// src/engine/cultureGenerator.ts

/** Compose a culture identity from foundation + creation sphere + biome modifiers */
composeCultureIdentity(
  foundationId: string,
  spheres: SphereName[],
  biome: TerrainType,
): CultureIdentity

/** Generate a culture name from modifier fragments */
generateCultureName(
  identity: CultureIdentity,
  rng: () => number,
): string

/** Generate all cultures for the world and add as graph nodes */
generateCultures(
  graph: WorldGraph,
  cosmology: CosmologyProfile,
  locationIds: string[],
  rng: () => number,
): string[]  // returns cultureIds

/** Assign a culture to an actor with strength */
assignCultureToActor(
  graph: WorldGraph,
  actorId: string,
  cultureId: string,
  strength: number,
): void

/** Assign culture to a location (historical + current layers) */
assignCultureToLocation(
  graph: WorldGraph,
  locationId: string,
  cultureId: string,
  layer: 'historical' | 'current',
): void

/** Assign cultures to all actors based on location proximity */
assignCulturesToActors(
  graph: WorldGraph,
  individualIds: string[],
  factionIds: string[],
  cultureIds: string[],
  rng: () => number,
): void
```

## World Seed Integration

`seedWorld()` gains a new phase after location creation and before faction creation:

```
Locations → Cultures → Factions → Individuals → Artifacts → Relationships
```

Culture generation needs locations to exist (for biome selection). Factions and individuals need cultures to exist (for assignment). `SeedResult` is extended with `cultureIds: string[]`.
