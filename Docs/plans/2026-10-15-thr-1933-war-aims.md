# Economic war aims — THR-1933

*Armies fight only enemies, defend first, and otherwise march on the enemy town worth most to their purse; monopolies become regional, pay rent, and can embargo.*

## Why this is load-bearing

Today a war is not about anything. `selectArmyObjective` (`src/engine/armySpawning.ts:154-194`) takes the nearest settlement whose first `controls` edge belongs to any other faction:

```ts
// armySpawning.ts:178-179
const controller = graph.getIncomingEdges(loc.id, 'controls')[0]?.source;
if (!controller || controller === factionId) continue;
// :192-193
candidates.sort((a, b) => a.hops - b.hops || (a.id < b.id ? -1 : 1));
return { type: 'conquer', targetNodeId: candidates[0].id, estimatedAttrition: 0 };
```

It reads no rivalry, no war and no `hostile_to`. In the [war-aims sketch](https://github.com/christianspliid-ui/threadbare/blob/proto/thr-1868-war-aims/scripts/proto/war-aims-sketch.output.txt) (seed 42, medium, 50 days), 19 of 20 armies marched on a faction they had no quarrel with, and 200 of 397 siege-ticks were the Civic Guard besieging towns where it keeps its own halls. Two more places treat "a different faction" as "an enemy": the battle start (`battleResolution.ts:639-647`, `areHostile` returns `factionA !== factionB`, commented "simplified — no alliance system yet") and the siege start (`battleResolution.ts:619-629`, any army standing in a settlement another faction controls lays siege). The objective is chosen once, at the raise (`spawnArmy` → `selectArmyObjective`, `armySpawning.ts:306`), and never again, so no army can turn to defend. The `'defend'` objective type exists (`types/army.ts:72`) and battle reads it (`battleResolution.ts:162`, prepared defence), but nothing writes it.

Monopolies never form: the rule needs 60% of every bearing place in the world (`MONOPOLY_CONTROL_FRACTION = 0.6`, `economic-power-config.ts:10`; `economicPower.ts:104-105`), and the best share on any day of the sketch was 14 of 40 stone. `faction.properties.monopolies` (`economicPower.ts:197`) has no reader (`:200-202`, "Nothing reads it yet").

[The faction purse](https://linear.app/threadbare/issue/THR-1931) gives towns a price, and [the crown](https://linear.app/threadbare/issue/THR-1932) promises that a liege defends its sworn. This plan makes armies act on both: it is the third plan of the kingdom economy in Christian's order (purse → crown → war aims) on the [Mortal economy map](https://linear.app/threadbare/issue/THR-1863), and the map's test is his: *"does this give factions something worth fighting over?"* (2026-10-14).

Decided 2026-10-14T16:29Z. Christian kept it on 2026-10-15 (*"Keep all three calls as decided. The plan docs can go ahead."*, recorded on the map).
- **[What the player sees of the economy](https://linear.app/threadbare/issue/THR-1870)** — the Trade lens hover lines (toll holder, embargo with a red dashed road, regional monopoly) and the Purse panel's monopoly chip, used here only. Decided 2026-10-14T22:29Z; its veto day closed 2026-10-15T22:29Z.
- **[The faction purse plan](https://linear.app/threadbare/issue/THR-1931)** ([plan](2026-10-15-thr-1931-faction-purse.md), lane, 2026-10-15 ~10:18Z) — the income helpers this plan prices towns with, and the empty monopoly chip slot it fills.

**How-level choices this plan made** (the decision left them open; reasons in the [brainstorm companion](2026-10-15-thr-1933-war-aims-brainstorm.md)): one shared enemy rule that the targeting, the battle start and the siege start all read; an army defends by marching to the threatened holding, not by chasing the enemy army; armies re-aim once a day; "supply reach" is the existing supply walk from the target town; a regional monopoly is anchored on one place; two slices, with every monopoly piece in the second.

## Engine pillar

### Systems design

New module **`src/engine/warAims.ts`** with pure helpers in `src/engine/warAims/` (`enemy.ts`, `townValue.ts`, `score.ts`, `defence.ts`), constants in `src/data/war-aims-constants.ts`. No new phase: the re-aim runs inline at the top of `phaseArmyMovement`, on its own daily gate.

**1. The enemy rule — `isEnemyFaction(graph, a, b)`** (`warAims/enemy.ts`). True when `a !== b` and any of:

- a `hostile_to` edge either way (this includes the crown's rebellion edge, `reason: 'rebellion'`);
- a `relates_to` edge either way with `isRival === true`, or `basis === 'war'`, or `sentiment < RIVALRY_SENTIMENT_THRESHOLD` (−0.3, the existing constant, imported, not copied);
- either faction has `factionType: 'monster'` (a lair's horde fights everyone, as today).

An alliance (`relates_to.isAlliance`) between the two, either way, overrides the sentiment arm only (allies who quarrel are not at war), never `hostile_to`, `isRival` or `basis:'war'`. Pure, deterministic, no cache. It is the one rule the three readers below use:

- **targeting** (§ 3);
- **battle start**: `areHostile` (`battleResolution.ts:639`) returns `isEnemyFaction(factionA, factionB)` when `WAR_AIMS_ENABLED`, today's different-faction test otherwise. Two armies that are not enemies share a hex in peace;
- **siege start** (`:619-620`), when `WAR_AIMS_ENABLED` (off: today's different-faction test): an army lays siege only if `isEnemyFaction(armyFaction, settlementFaction)` **and** its faction keeps no hall or home in that settlement (`hasHallIn`: a member or the faction itself `located_at` the settlement or one of its sublocations, via `resolveToParentLocation`).

If [THR-1922](https://linear.app/threadbare/issue/THR-1922) ships a local predicate first, this slice hoists it into `isEnemyFaction` and keeps its regression test.

**2. Defence first — `findThreatToDefend(state, armyId)`** (`warAims/defence.ts`). Protected holdings = `protectedHoldingsOf(faction)` from the crown's `crown/crownView.ts` when it exists, else the faction's own `controls` settlements (one call site; the crown plan § Wiring names this switch). A **threat** is an enemy army (by § 1) whose `objective.targetNodeId` is a protected holding. The army defends the threatened holding nearest to it (hex distance from its own Location's hex), if that holding lies within `WAR_AIM_DEFENCE_RADIUS_HEXES` (8); ties by holding id. The objective is `{ type: 'defend', targetNodeId: <holding>, reason: 'defence', againstArmyId }`. The army marches to the holding and stands there; when the enemy arrives, the battle start fights it with the existing prepared-defence bonus (`battleResolution.ts:162`). It does not chase the enemy army across the map (§ brainstorm, alternative B).

**3. The richest enemy town in reach — `pickWarAim(state, armyId)`** (`warAims/score.ts`). Candidates: every place-tier Location (`getLocationNodes`) whose `locationSubtype` is in `SETTLEMENT_TARGET_SUBTYPES` (`types/army.ts:96-98`), whose tax holder (the purse's `taxHolderOf`) is an enemy by § 1, in which the army's faction keeps no hall, that is not a ruin, and that is **in reach**:

- `resolveSupplyLine(state, townId, factionId)` returns a host (an army besieging there could be fed, `armySupply.ts:136`), **and**
- `hexDistance(armyHex, townHex) ≤ WAR_AIM_MAX_REACH_HEXES` (16), a backstop for long road chains.

For each candidate:

```
value    = townValueFor(attacker, town)            // the purse's numbers, § townValue below
bonuses  = monopolyBonusFor(attacker, town)        // S1: 0. S2: +0.5 breaks an enemy's, +1.0 completes own
         + (feedsLackingStaple(attacker, town) ? WAR_AIM_BONUS_FEEDS_STAPLE : 0)   // +0.5
score    = value × (1 + bonuses) ÷ (1 + hexes / WAR_AIM_HALF_VALUE_HEXES)          // 6
```

Highest score wins; ties by lower hexes, then id. No candidate → the army **holds** (`objective: null`, `holdReason: 'no_enemy_in_reach'`). The objective is `{ type: 'conquer', targetNodeId, reason }`, where `reason` is the largest contributor: `'feeds_staple'` if that bonus applied, (S2) `'breaks_monopoly'` / `'completes_monopoly'`, else `'richest'`.

**`townValueFor(attacker, town)`** (`warAims/townValue.ts`) — what the attacker's purse would collect if it held the town, from the purse's pure helpers (`src/engine/factionPurse/`), never a second formula:

1. the purse's **town tax** for the town (`TOWN_TAX_BASE × prosperity / TOWN_TAX_PROSPERITY_PIVOT`);
2. the purse's **place yield** for the town and each of its sublocations with a resource bag;
3. its **field share**: for each unheld resource Place within `WAR_AIM_FIELD_RADIUS_HEXES` (3) of the town, that place's yield ÷ the number of settlements within 3 hexes of it. Fields between two towns are worth half to each.

**`feedsLackingStaple(attacker, town)`** — true when the town or a place it counts in its field share bears a staple (`category === 'staple'`) whose `stockTier` is `'scarce'` in at least one settlement the attacker is tax holder of.

**4. The daily re-aim — `reaimArmies(state)`** (`warAims.ts`), called first inside `phaseArmyMovement` when `tick % WAR_AIM_REAIM_INTERVAL_TICKS === 0` (12, daily), in army id order. Skipped for an army that has an outgoing `participates_in` edge (in a battle or siege), or whose objective `source === 'agenda'` (a notable's war, set by `notableAgendas.ts:671`, keeps its own target; that writer stamps `source: 'agenda'`). Otherwise:

1. a threat (§ 2) → defend it;
2. else, if the current objective is a `conquer` whose target is still an enemy's, in reach, and not yet reached → keep it (no churn mid-march);
3. else → `pickWarAim` (which may hold).

When the objective changes, the army's `movementState` is cleared, so movement's existing Case 2 (`armyMovement.ts:120-160`) paths to the new target on the same tick. `spawnArmy` calls the same pick instead of `selectArmyObjective` when the flag is on, so a fresh army needs no wait.

**5. Ambitions take their target.** When `maybeSpawnArmy` (`factionAmbitions.ts:165`) raises an army for `territorial_expansion` or `revenge`, the army's conquer target is written to that ambition's `targetNodeId`. Each re-aim that changes a conquer target rewrites it. A `revenge` ambition scores towns of the faction it holds the grievance against at `× WAR_AIM_REVENGE_FOCUS` (1.5); a town of another enemy can still win if it is worth more. The existing abandon check (:201-202) then has a target to read.

### S2 — regional monopolies and embargo (its own ticket)

**6. The regional rule** replaces §1 of `phaseEconomicPower` (`economicPower.ts:76-110`), same daily gate, same diff-and-chronicle loop. Bearing places are place-tier only (`getLocationNodes`; today's `getNodesByType('location')` also counts sublocations). For each resource and each faction that holds at least one bearing place: for each of its held bearing places as a candidate **anchor**, count the bearing places within `MONOPOLY_REGION_RADIUS_HEXES` (8) of it and how many the faction holds. The faction holds a regional monopoly on the resource when some anchor has `≥ MONOPOLY_REGION_MIN_PLACES` (3) bearing places in reach and a held share `≥ MONOPOLY_CONTROL_FRACTION` (0.6). The anchor kept is the one with the most held places (ties by id). A faction may hold the same resource in two regions; two factions cannot both hold one region (60% is exclusive within a region, and a second anchor within 8 hexes of a held anchor is the same region). Stored: `regionalMonopolies` (record above) and `monopolies` = their resource ids, deduplicated, so the chronicle diff keeps working. The diff fires `monopoly_broken` only for a record whose `sinceTick` is at least `MONOPOLY_MIN_HOLD_DAYS` old, and `monopoly_established` for a re-formed region only if the last loss was that long ago.

**7. Scarcity rent.** In the purse's place-yield source, a place whose resource the holder monopolises in the region containing that place pays `× MONOPOLY_SCARCITY_RENT` (1.5). One multiplier on one existing line.

**8. The monopoly bonuses go live.** `monopolyBonusFor(attacker, town)`: `+WAR_AIM_BONUS_BREAKS_MONOPOLY` when the town or a place in its field share is one of an **enemy's** regional monopoly places and taking it would drop that holder below 60% in the region; `+WAR_AIM_BONUS_COMPLETES_MONOPOLY` when taking it would lift the attacker to 60% in a region with at least 3 bearing places. Both are recomputed from the record; no cache.

**9. `embargo`** — a faction action (union member, template row, executor `executeEmbargo`, switch case, one prerequisite kind `holds_regional_monopoly`). `treasuryCost 0`, `cooldownTicks EMBARGO_COOLDOWN_TICKS`, weight `EMBARGO_WEIGHT`. On execute: pick the enemy faction (§ 1) whose settlements inside the holder's monopoly region draw most on that resource (highest count of those settlements; ties by id). For `EMBARGO_DAYS`, the holder carries **one record**, `activeEmbargo: { targetFactionId, resourceId, anchorLocationId, untilTick }` (at most one per holder). Nothing is written on the towns or lanes: `embargoedTownsOf(record)` derives the target's settlements within `MONOPOLY_REGION_RADIUS_HEXES` of the anchor, and `embargoedLanesOf(record)` the `trades_with` edges between those towns and the region, so the stock pass, the Trade lens and the debug tab all read one source and cannot disagree. (The record is the faction's own standing order, like an army's `objective.targetNodeId`; the relationship it names is not stored on both ends.) **How the stock drops, measured on main:** lanes do not move goods into stocks today. `deriveLocationStockTiers` (`resourceEconomy.ts:98`) reads only the town's own props and sublocation count, and no stock code reads `trades_with` (grep over `phases/resourceStockTiers.ts` and `resourceEconomy.ts`: no hit). So the embargo is one additive term in the stock pass: an embargoed town's balance for that resource is `computeResourceBalance(…) − EMBARGO_BALANCE_CUT` (0.4, enough to move Adequate to Scarce past `STOCK_SCARCE_THRESHOLD` −0.3). When [the settlement economy](https://linear.app/threadbare/issue/THR-1923)'s goods flow carries goods on lanes, the build that lands second replaces the term with "the embargoed lanes carry none of that resource" and drops the constant. One `encounter_route_embargo` seed is placed on the busiest such lane (the existing seed path, `routeEvents.ts:182-191`). The economic-power phase lifts expired embargoes and fires `embargo_lifted`. An embargo ends early if the holder loses the monopoly.

**10. `resource_acquisition` gets a target:** the best-scoring enemy town (by § 3) whose fields grow a staple the faction is short of, written to the ambition's `targetNodeId`; it counts as met while the faction holds any regional monopoly (the [undertakings in the economy](https://linear.app/threadbare/issue/THR-1937) plan reads that).

### Resolution logic

1. **Order:** defence before value (decision rule 2). A threat inside 8 hexes always wins.
2. **No churn:** a marching army keeps a still-valid conquer target; only defence interrupts it.
3. **Reach before score:** an out-of-reach town is never scored, so a rich town 30 hexes away cannot pull an army off its own map.
4. **Hold is a result:** no enemy in reach writes `holdReason` and a trace, never an error.

### PRNG callouts

None. Every pick is a deterministic argmax with id tie-breaks; no new random stream.

interface WarAimPickedTrace {

  armyId: string;
  factionId: string;
  townId: string;
  reason: 'richest' | 'feeds_staple' | 'breaks_monopoly' | 'completes_monopoly';

  bonuses: number;
  hexes: number;
  score: number;
  candidates: number;   // in-reach enemy towns scored

interface WarAimDefendTrace {
  type: 'war.aim.defend';
  tick: number;
  armyId: string;
  factionId: string;
  holdingId: string;
  againstArmyId: string;
  sworn: boolean;       // the holding belongs to a sworn vassal, not the faction itself
  hexes: number;

interface WarAimHoldTrace {
  type: 'war.aim.hold';
  tick: number;
  armyId: string;
  factionId: string;
  enemiesKnown: number; // enemy factions holding any settlement
  outOfReach: number;   // enemy towns excluded by reach
}

// war.aim.reaim — the daily pass changed an army's objective
interface WarAimReaimTrace {
  type: 'war.aim.reaim';
  tick: number;
  armyId: string;

}

  type: 'war.aim.value_fallback';
  tick: number;
  reason: 'purse_not_built' | 'purse_disabled';
}
