# Brainstorm — realms and areas (THR-1155)

*Companion to `2026-09-10-thr-1155-realms-and-areas.md`. What was weighed, in the order it came up, 2026-09-10.*

**How this started.** Christian, 17 August, while ratifying the chip-anchoring rule: nations and areas have only the rendering implemented; the game-state part is not there; schedule a fix. The ticket sat sequenced third in wave 1 behind the anchor machinery and the hunger seam, both shipped by 28 August, and waited for a design session.

**The survey changed the shape.** The ticket assumed the first question was whether detected regions are graph nodes. They are — 41 of them, named, with `contains` edges, registered as *Area* and already in the hex chronicle. The real defect is that the renderer runs a *second* detector and joins its clusters to the nodes by array index, so the label over a mountain range is the name of whatever unrelated cluster shares its list position. And a nation turned out to be not one gap but two: the red border is provinces grouped by culture, computed once and parked in React state with no setter; the generic factions that could be nations have no definition, so nine subsystems `continue` past them. Promoting either alone fixes nothing.

**The ruling already on the books.** THR-1394's Area row, ratified by Christian on 3 September: *political territory is a faction's `controls` edges, never a second region kind.* The cautious-expansion rule says the nearest registry note records what was decided last time, and this is it. So the question *what node type is a nation?* has an answer that forbids the question: it is a Faction. Rejected on that ruling: a `nation` node type; a `polity` actor type; a second `region` flavour for political areas; a `territory` slice on `GameState`.

**Definition, not type.** The nine skips all key on `factionDefId`. THR-1322 already gives run-founded factions a *dynamic* definition so the static lookup resolves them. A Realm minted at worldgen through the same door is a faction every subsystem admits without a code change of its own — ambitions, quests, encounters, ladders, armies. That is the whole engine pillar for nations, and it is why the plan can say *no new node type* and mean it. Rejected: adding realms to the static `FACTION_DEFINITIONS` catalogue (a per-world object in an authored table).

**The door that was only half-hung.** The first draft said a Realm with a definition enters ambitions, quests, ladders and gates *by construction*. The judge asked where the existing Area reader fit, and answering that meant reading the definition lookup's callers: three, all UI-side. Every engine consumer still reads the static map by id, so a run-founded faction — THR-1322's whole point — has never had an ambition either. Nobody noticed because founding is rare. Decided: the sweep is slice 2's first move, with a tripwire so it stays total, and the finding goes back to THR-1322's thread. Rejected: registering realms into the static catalogue to dodge the sweep (a per-world object in an authored table, and it would leave the founded factions where they are).

**Setting envelopes.** The ticket listed encounter spawn scoping as a minimum consumer. The eight setting classes say what *kind* of place a scene wants; an Area or a Realm says *which*. Decided: Realm scoping needs nothing new — realm content is faction content and faction content already scopes through its meta and the standing gates. Area scoping is marked not-applicable with its reason: what content actually wants from terrain is mountain-versus-marsh, which is the Area's feature type, and a feature-type setting class is a vocabulary decision for THR-884's owner. Rejected: a `regionIds` filter on templates (an axis nobody has asked for, invented on the side of a ticket about objects).

**The word for what a Realm holds.** *Holdings* was the first draft's noun. The catalogue already gave that word to the `owns` edge, player word *freehold*, and THR-1314 spent a ticket moving it there. So a Realm *holds* towns — the verb THR-1449 proposes for the `controls` edge, which is the same edge a mortal's stance sits on — and the sheet's existing *What They Control* section is the surface, unrenamed. Three words, three edges, written into the executor notes so the next reader does not "fix" it back.

**Where the border comes from.** Three candidates. (a) Keep the worldgen provinces and stamp each hex with its realm — the border is pretty and never moves, which is the defect in a new coat. (b) Store a per-hex realm stamp updated on seizure — two truths (`controls` and the stamp) that will disagree. (c) Derive the border from the towns a Realm holds: each hex joins the Realm of the nearest held Location within a radius, farther land is nobody's. Chosen (c). It is the only one where seizing a town moves the border, and it satisfies the fourth ratified distinction literally: rendering reads a projection of canonical state. The cost is blunter shapes than the watershed provinces drew. Accepted: a border that moves when a town falls is a story; a pretty one that never moves is a picture.

**Who owns the projection.** The first draft parked it in the map hook's memo, which is where the old region data sat and the shape of the defect in miniature: `$realm` binds in an engine phase and the CLI has no React. The runtime already owns the encounter cache and the distance matrix with a built-at version each, the binder already demands a runtime, and every headless script constructs one. So the projections are runtime fields behind an `ensure`, and there is one of each for the map, the binder and the CLI to read. Rejected: a second, engine-side copy for the binder (two projections, one eventually wrong).

**The unclaimed wild.** A radius means land far from any held town belongs to no one. That was not asked for and it is right: wilderness that no realm claims is where the ruins and the lairs are, and it gives a Realm somewhere to expand *into* — the expansion ambition the threshold comment says was tuned around nations that could never reach it.

**Provinces.** The thin lines are baronies with no object behind them. Rejected: keep drawing them (the private pipeline the ruling names). Rejected: promote them to objects too (nothing acts on a barony; a second political tier with no consumer is the acted-on test failed one layer down). Decided: provinces stay worldgen scaffolding for culture assignment and naming, and are not drawn. If baronies ever earn a system, that is a new decision.

**One detector.** The flood-fill mints the nodes and is marked deprecated; the watershed feeds the renderer and covers the map the player has been looking at. Chosen: the watershed mints the nodes, every hex is stamped, the index join dies. Rejected: keeping both and fixing the join (the join is the symptom; two partitions is the disease).

**The word.** Christian said *nations*. The code says kingdom, barony, domain, province. The UL says nothing. *Realm* is proposed as the headword with *nation* as the alias — the register argument is in THR-1453 — and the veto is his. The object is the same under either word.

**What the player gets.** A map that moves. A faction sheet for the kingdom their First lives in. *Held by the Realm of the Wild Storm* on a town, with a link. A court ladder a mortal can climb. And the seam THR-1448 needs: a mortal's hold inside a Realm can now be a position in it, because the Realm exists to hold the position.

**The border only shrank.** The fourth judge run pulled the seam none of the others had: who writes a faction's `controls` edge after worldgen? Nobody. A won siege at total severity deletes the defender's edge and leaves the town nobody's — the victor's faction is looked up two lines earlier and spent on sphere pressure. So the projection's promise, a border that moves when a town falls, was half true: it could fall out of a Realm and never into one, and *takes* was a chronicle line with no producer, the parent epic's flaw one layer down. Three shapes. (a) Mark *takes* as design-only and file the producer — honest, and it ships a map that can only lose. (b) A new conquest verb on the undertaking grid — a system, not a producer. (c) The smallest change that makes the promise true: the army that sacks a town takes it for its faction; a host with no faction leaves the vacuum as today. Chosen (c), decided with veto, because armies already march on the nearest hostile-held town and the only thing missing was the last line. Found on the way: the war phases carry no runtime, so nothing on that path could bump the structural version — threaded as an optional parameter in the shape the encounter phase already uses, and the projection got a fingerprint belt so a writer that forgets is a trace line, not a stale map.

**The mirror that was not there.** Writing conquest, the draft dutifully maintained the `controlled_by` edge the vacuum code removes. The sixth judge run checked: it is in no type union, no schema, and no production writer — a fixture invented it and four reads have been falling through to `controls` ever since. Deleted from the design, with a bold note not to "repair" it by registering the type. A lesson the memory already holds: a fixture must not get to define the shape.

**Two words the judge caught.** *Freeholder* as a court rank, one line after the executor note fencing *Freehold* to the `owns` edge — replaced with *yeoman*. And `$realm` falling back to "whoever controls the town": a Realm-held town's own hex is always inside its Realm's projection, so the fallback could only ever have bound a guild, and a template saying *the Realm of $realm* would have named the Merchants' Consortium. The sentinel binds a Realm or nothing.

**Not taken.** A `nation` chip kind (a Realm is a `faction` reference, already linked). Movement or awareness flavour from borders (the ticket said *where cheap*; nothing cheap presented itself, and a border-crossing cost is a design of its own). Realm encounters (content; filed at handoff). Any change to the ascendant's control effects (a different sheet).
