## Why this is load-bearing

The stage is always real and the cast almost never is — measured 38/38 vs ~11%, and the bound few
are mostly template-scoped generics minted on the spot, born with no capabilities, no values, no
home index entry, invisible to the hex actor index. Binding quality *is* moment quality ("the
generic moment is the boring moment"), naming (doc 2) consumes the binder's anchors, grievances
(doc 4) need harmed works with real owners, and the north star fails silently while every gate
stays green if this system underdelivers — the steel-man called it the map's worst measured
baseline. THR-1292 shipped the checkpoint runtime with the binder's seams deliberately empty:
`rebindRequested` is written at `undertakingCheckpoints.ts:572` and consumed by nothing — its doc
comment names this plan as the consumer.

## Engine pillar

### 1. Architecture: three modules, one decision

New directory `src/engine/binding/`:

- **`binder.ts`** — `resolveBinding(request, ctx): BindingDecision`. The scored find/modify/mint
  board ([THR-1290 §2](https://linear.app/threadbare/issue/THR-1290/the-binding-algorithm-where-an-undertaking-plays-and-what-it-touches)).
  Pure with respect to the graph (reads, never writes) — it returns intents (`reuse` / `modify` +
  additive ops / `mint` + queued request), and the caller applies them. This mirrors the
  decide/apply split `resolveUndertakingCheckpoint` already uses.
- **`bindingRegistry.ts`** — the persistence ledger and reverse index. Records live in
  `state.strategicState.bindings` (serializable, additive field); the `Map<nodeId, recordIds>`
  index is a runtime-owned lazy derivation.
- **`mintInhabitant.ts`** — the born-real mint contract + the queue drained through the lifecycle
  valve.

`roleCensus.ts` (a fourth small file) holds the census cache.

### 2. The scored board — five weights, three modes

Per cast slot, the binder enumerates a bounded candidate set and scores each row:

```
bindScore = BINDER_WEIGHT_CAST_ROLE_FIT × castRoleFit
          + BINDER_WEIGHT_SCARCITY      × scarcityTerm
          + BINDER_WEIGHT_STORY_TIES    × storyTies
          + BINDER_WEIGHT_DISTANCE      × distanceTerm
          + BINDER_WEIGHT_IDENTITY      × identityTerm
```

**Candidate enumeration is bounded, never O(all actors):** actors `located_at` the stage, its
parent, and sibling sublocations (edge-indexed, O(local degree)) ∪ the role census's members for
the requested role filtered by `BINDER_DISTANCE_HORIZON_HEXES`. Plus exactly **one mint row**.
An existing candidate contributes up to two rows: **as-is**, and **modified** (identity blanks
filled, at `BINDER_MODIFY_PENALTY`) — so reuse, modify, and mint genuinely compete on one board,
as the verdict requires, with no rules.

The five terms, each 0–1:

- **`castRoleFit`** — `npcRole` ∈ the spec's roles or `encounterSupportRole` match → 1; roleless →
  `BINDER_ROLELESS_ROLE_FIT` (0.4, modify-eligible — see below); wrong role → excluded.
  **Named `castRoleFit`, not `roleFit`:** `StrategicScoreComponents.roleFit`
  (`strategicActionCandidates.ts:361-374`) is a different axis (actor-capability-vs-template) and
  the collision is deliberate to disambiguate, not accidental to inherit.
- **`scarcityTerm`** — from the census: `scarcity01(role) = 1 − min(1, count(role) /
  BINDER_ROLE_COMMODITY_THRESHOLD)`. Reuse rows earn `scarcity01` (the scarce archmage trends
  reuse — converging arcs are worldbuilding); the mint row earns `1 − scarcity01` (the commodity
  sailor trends fresh — shared commodity cast is false coincidence). Weights, never rules;
  story-ties can override either way, exactly as ruled.
- **`storyTies`** — bounded O(deg) reads from the undertaking's actor to the candidate:
  `relates_to` sentiment/trust via `getAgentBonds` (falling back from a reified `relationship`
  node when one names both participants — the established two-tier read), `mentors.bondQuality`
  (graduated/estranged edges persist — the only relationship type with a historical tail),
  `knows_secret_of` / `owes_favor` magnitudes (a secret or a debt is a *reason* for a scene),
  shared `participated_in` events (two-hop Set intersect), faction co-membership via
  `getFactionMembershipEdges` (**never** raw `member_of` — the THR-1288 four-way overload).
- **`distanceTerm`** — `1 − min(1, hexDistance(candidateHex, stageHex) /
  BINDER_DISTANCE_HORIZON_HEXES)` using **`resolveLocationToHex`** (the recursive resolver). The
  distance matrix is deliberately not plumbed in — it measures adjacency hops, not hexes, and
  neither the candidate generator nor the checkpoint signature carries it; `hexDistance` +
  resolver is what `strategicActionCandidates.ts:203-206` already does.
- **`identityTerm`** — the three-way, against the cast spec's declared identity requirement (the
  schema hook `identityRequirement?: { axis: ValuePair; pole: 'virtue' | 'vice'; minStrength }` is
  defined here; **values are doc 2's cast declarations**). Reads `axiologicalProfile` through
  `signedToCanonical01` only (the pole-inversion trap, documented at
  `undertakingCheckpoints.ts:304-309`). Match → 1. Blank → 0 as-is, and the modified row scores as
  match minus the modify penalty. **Contradiction → both rows excluded** (traced as vetoed) — mint
  wins by absence, the "greedy mage does not reuse the generous one" ruling.
  **Stated plainly, per the recon:** `axiologicalProfile` is a protagonist-only signal today —
  worldgen ambients and support mints both lack it — so blank is the *dominant* case and modify's
  additive territory is most of the world. That is the verdict's intent ("the story reveals the
  blank"), recorded here so nobody discovers it in a run and calls it a bug.

**Modify is additive-only** (NFP #6 applied to people): the modify intent may stamp `npcRole` if
absent, write the required identity axis **only when the axis is unset**, set `sphereAffinity`
only when `null`, add one consistent personality trait. It never overwrites a non-null value.
A pleasant consequence found in recon: born-later agents carry no `npcRole` at all and are
therefore permanently ineligible for today's reuse scan — under the binder they become modify
candidates, and the entire born-later population joins the casting pool.

**Determinism:** scoring draws no rng; ties break on candidate-id sort. Every decision emits a
`binding_decision` trace (top rows with the five-term breakdown, winner, mode, vetoes) — **emitted
on refusals and deferrals too**, following `UndertakingCheckpointTrace`'s stated emission rule.

### 3. Per-step anchoring + the bind pass (THR-1290 §3/§4)

**Where it runs:** in `strategicActionLifecycle.ts` immediately before
`resolveUndertakingCheckpoint` (the `:303` seam) — the same slot and shape as the mentorship
bootstrap at `:252-267`, which is this pass's existing prior art (a lazy per-undertaking cast
bind at first checkpoint, returning events). The checkpoint module stays graph-read-only.

The pass fires when a checkpoint is due and the template declares cast/stage specs, and:
- **first bind** — no live bindings for the current step; stage resolves per-step (a step-level
  `anchor` override on the spec; default the undertaking's `targetNodeId`), cast binds with a
  carry-forward preference for already-bound cast (`BINDER_CARRY_FORWARD_BONUS` added to their
  row) — bind at step start, exactly as ruled;
- **re-bind** — `rebindRequested` is set (escalation) or a binding is `broken`: the affected slots
  re-run the same scorer, the flag clears, and the loss is named (below).

Binding records (`state.strategicState.bindings`, additive):

```ts
interface UndertakingBindingRecord {
  projectId: string; castKey: string; nodeId: string;
  kind: 'actor' | 'location';
  persistence: 'must-persist' | 'scene-only';
  boundAtTick: number; stepIndex: number;
  status: 'live' | 'broken' | 'released';
  brokenCause?: 'node_removed' | 'deceased' | 'severed';
}
```

**Validation covers both shapes of gone.** The recon confirmed the checkpoint's actor-loss check
reads node absence only — a `deceased: true` echo or band-slain member passes it. The bind pass
validates every live binding with `!graph.getNode(id) || isAgentGone(node)`, closing that blind
spot for cast (and the same dual test is applied to the undertaking's own actor as a fix in
passing).

**Creation at resolution, banded (THR-1290 §4).** Two new creation-effect kinds join the strategic
mutation vocabulary — `spawn_npc` and `spawn_sublocation` (the recon-confirmed missing kinds) —
declared per template as `creationEffects: { onAdvance?; onAtCost?; onCritFailure? }` (authored
values are doc 2's band tables). Executed by the lifecycle after the checkpoint verdict, gated on
the effect: advance creates, at-cost creates plus its cost-kind, halt creates nothing,
critical-failure creates the problem. `spawn_npc` with `must-persist` routes through the mint
queue (§5); `scene-only` may materialize immediately via the legacy path.

### 4. Persistence enforcement + the reaper inventory (review §3 row 2)

The dormant contract is real at every binding site already — `EncounterSupportBinding` carries
`persistence` per binding (`src/types/encounter.ts:248-255`); it is written 60+ times in the
shipped corpus and read by zero engine consumers. Enforcement splits by the reaper's nature,
which is how the verdict's two sentences ("never silently reaped" and "the world may still kill
them honestly") coexist:

**Detection is centralized, once.** `WorldGraph.removeNode` (`graph.ts:33-42`) is the sole funnel
all ~25 deleting call sites pass through, and it is entirely silent today. It gains one optional
hook — `onNodeRemoved?: (nodeId: string) => void`, registered per session by the orchestrator —
through which the registry marks affected bindings `broken` and emits `binding_severed`. One seam
covers every reaper **including the two back doors named below and any reaper not yet written**;
cost is one Map lookup on removal (removals are rare events, not per-tick work). Fail-soft: hook
unset → the bind pass's lazy validation still catches breakage one checkpoint later.

**The inventory, each loud-or-lazy** (verified against current `main`; the THR-1286 lesson — dead
records poison scorers — is answered by `broken` being a terminal, re-bind-triggering status, never
a value any scorer reads):

| Reaper | Site | Policy |
|---|---|---|
| Sublocation dissolution (temporal/conditional) | `sublocation.ts:614-720` | **defer (lazy)** — housekeeping consults `isNodeBound()` and skips a bound stage, traced; dissolution resumes when released |
| Agent lifecycle death (reputation) | `agentLifecycle.ts:182-234` | **proceed loudly** — honest death; hook marks broken; next checkpoint names the complication |
| Battle commander kill | `battleAftermath.ts:434` | **proceed loudly** — same; note it bypasses the lifecycle and emits nothing today, so the hook is the *only* thing that notices |
| Battle sublocation destruction | `battleAftermath.ts:344-359` | **proceed loudly** — a siege razing a bound stage is narrative, not housekeeping. This is the recon's one *confirmed live* must-persist violation today (the destruction pool never reads persistence in either flavor); after this plan it is loud and consequential rather than silent |
| Content-authored `remove_node` GraphOp | `graphOpExecutor.ts:384` | **proceed loudly** — the unguarded generic deleter; covered by the hook precisely because per-reaper enforcement would route around it |
| Seed-inheritance drop | `encounterSeeding.ts:122-127` | **loud** — the drop keeps its semantics but emits `binding_severed` with its own cause; also aligned to the dual gone-test (today it checks node absence while its sibling uses `isAgentGone` — an inconsistency inherited deliberately no longer) |
| Transit-hex GC (THR-669 precedent) | `strategicAction.ts:250-256` | **already answered by anchoring** — `originLocationId` snapshots are the codebase's accepted remedy; binding records snapshot resolved stage ids the same way |
| Soft deaths (`deceased: true` — aspects, band opposition) | `aspects.ts:288`, `bandOpposition.ts:351-354` | **caught by validation** — no node removal fires the hook, so the dual gone-test at bind/checkpoint time is the detector |

**Honest breakage → named complication (THR-1290 §3).** A `broken` must-persist binding at the
next due checkpoint forces the loss into the story: the checkpoint resolves normally, then an
advance is downgraded to advance-at-cost (`forcedAtCost`), or — when the lost role is singular
(`scarcity01 ≥ BINDER_SINGULAR_SCARCITY_THRESHOLD`) — the checkpoint halts instead. The moment
class `complication` (today produced *only* by critical failure, `undertakingCheckpoints.ts:483`)
widens to cover broken-binding checkpoints — additive, and the moment names the lost cast member.
The slot then re-binds through the same scorer at the following pass.

### 5. Born real: the mint path through the valve (review §3 row 1)

**The contract.** `mintInhabitant(request)` produces a *full ambient inhabitant* — every property
and edge a lifecycle birth writes, plus what the role demands. The gap it closes is measured, not
asserted (recon table): support mints today omit `axiologicalProfile`, `domainCapabilities`
(⇒ they fail *every* reach floor), `locationId` (⇒ invisible to `buildHexActorIndex`),
`narrativeArchetype`, `cooperationStrategy`, `bornTick`, ambitions, and culture-phonetic naming.
The mint writes, reusing existing generators rather than inventing new ones:

- identity: `generateAxiologicalProfile` (the birth generator, cosmology-biased);
- capability: `generateRoleCapabilities(rng, NPC_ROLE_REACH_MAP[role], 'notable')` — the
  graduation-path generator whose scale `computeCapability`'s sigmoid expects; `wealth` from
  `ROLE_WEALTH`; `npcRole` from the spec;
- placement: `located_at` edge **and** the denormalized `locationId` (the hex-index defect closed
  by construction); `spotlightTier: 'ambient'` explicitly (absence defaults readers to
  `'spotlight'` — the recon's accidental-full-fidelity trap);
- culture: place culture with `culturalStrength` (the property the read path actually reads),
  name via `pickCulturalName` from the culture's phonetic signature — no more verbatim
  `spawnName` with no provenance (authored `spawnName` still wins when the spec provides one);
- ambitions via `assignInitialAmbitions`; `generatedBy: 'undertaking_binder'` + the undertaking's
  id for provenance; and `touchStructure` — runtime mints finally invalidate the encounter cache,
  distance matrix, and the UI's `structuralCacheVersion` memo (today neither mint path touches
  anything, which the recon flags as defects #4/#9).

**The valve (the THR-814/THR-162 lesson made mechanical).** Binder mints are **queued**
(`state.strategicState.mintQueue`), never immediate: `phaseAgentLifecycle`'s births block drains
up to `BINDER_MINT_BUDGET_PER_TICK` requests *before* rolling ambient births, inside the existing
gates — never on a death tick, counted against the same one-per-tick shape. A checkpoint whose
bind pass is waiting on a mint defers with `deferred: 'awaiting_mint'` (no halt accrual — the
world being slow to produce a clerk is not the agent failing). Queue-before-valve also dissolves
the phase-ordering problem the recon raised (decision runs before lifecycle in the tick): requests
made at tick T are born at T or T+1, and the checkpoint simply binds when the mint exists.
Scene-only encounter extras keep the legacy immediate path — legal per the verdict.

**Deterministic, instance-unique ids** (review §3 row 3): `mint_<projectId>_<castKey>` — unique
per undertaking instance by construction, seed-deterministic because `projectId` already is. The
mint's own rng derives from `mulberry32(state.seed + hashString(projectId + castKey))` — stable
against *when* the queue drains, so a slow tick cannot change who is born (NFP #3). The old
`enc_support_<templateId>_<locId>_<key>` scheme (self-reuse by design) remains for the un-migrated
encounter path only.

### 6. The remote-anchor rule (THR-1290 §5)

"A remote undertaking must anchor through an entity the agent commands at or near the site; no
anchor → the remote verb is simply not offered."

**Gate placement:** inside `generateStrategicCandidates`' per-target loop (where `targetHex`,
`actorHex`, and `travelDist` are already in scope, `strategicActionCandidates.ts:203-206`),
alongside the control gate — refusing at proposal time exactly like `no_eligible_apprentice`
(:154-158), whose comment states the doctrine and whose history (two drifted eligibility copies)
dictates the rule: **one function**, `findRemoteAnchors`, called at proposal and again at re-bind,
never duplicated. Rejection reason `no_remote_anchor`, counted on the existing rejections list and
traced.

**What counts as commanded, v1:** entities reached by `getIncomingEdges(agentId, 'commanded_by')`
— the edge is army→commander, a direction three separate files carry warnings about, so the
helper encapsulates it. Armies resolve to a hex via their `located_at`; a company's position is
its leader's (`getGroupPosition`), making it a degenerate remote anchor by construction — included
for correctness, noted as such. An anchor is valid within `BINDER_REMOTE_ANCHOR_RANGE_HEXES` of
the site; a target beyond `BINDER_REMOTE_RANGE_HEXES` of the *agent* requires one. The winning
anchor **joins the cast** as `$anchor` (must-persist), so severing it is a complication — exactly
the counter-play seam T1 networks and doc 2's holdings widen ("severing a network un-foots what it
anchored"): the helper is written against an interface (`command-edge providers`) that networks
([THR-1288](https://linear.app/threadbare/issue/THR-1288/network-kind-verify-the-graph-mapping))
and holdings register into when they land. **Deliberately not an anchor source:** `controls`
edges (scheduled deletion, two-population split), `leads` (a faction has no hex), `thread` (the
god's edge, not the agent's), `owes_favor` (leverage, not command — a possible soft tier later,
recorded not built). With armies alone, remote undertakings are *rare* in v1 — honest and stated,
not a defect: the rule's payload arrives with the T1 network kind.

### 7. Encounter opportunistic migration (THR-1290 §1)

No big-bang. `prepareEncounterSupportBundle` gains an opt-in: a template whose bundle sets
`useScoredBinder: true` routes its specs through `resolveBinding` (persistence honored, must-persist
registering in the registry); every other template keeps the legacy find-or-mint path
byte-identically. One shipped template migrates in this plan's final slice as the living proof,
chosen by the executor from the four that carry real bundles today. The corpus-wide sweep stays
where the map put it — the placeholder-encounter audit. Until a template migrates, its authored
`must-persist` declarations remain unenforced; that is today's exact status quo, now stated and
traced rather than silent.

### 8. The role census (review §3 row 3)

`SimulationRuntime.roleCensus: Map<NpcRole, Set<nodeId>>` + `roleCensusBuiltAt`, rebuilt lazily
when `roleCensusBuiltAt < structuralCacheVersion` — copying `ensureEncounterCache`'s discipline
verbatim (version-keyed, traced with duration, fail-soft null on throw). Recon confirmed **no
role index exists anywhere** and `getNodesByType` is a full scan; the census makes scarcity a Set
lookup, rebuilt O(actors) only on structural change, never per step per role. Mint/death sites
already bump the version (and the mint path now calls `touchStructure` by contract), so the
census can never serve a stale world for longer than one structural change.

### Graph nodes / edges

None new, none retyped — the binder honors the no-new-node-types rule by construction (it binds
existing shapes; `spawn_npc`/`spawn_sublocation` create instances of existing types through
existing creation code). `WorldGraph` gains one optional callback field (not an edge).
`identityRequirement` and `creationEffects` are template-data fields, not graph schema.

**Why the binding ledger is state records, not a `bound_by` edge — addressed against the
relationships-are-edges rule, not skipped.** An edge requires two graph endpoints, and the
undertaking side of a binding is **not a graph node**: the ratified substrate verdict
([THR-1280](https://linear.app/threadbare/issue/THR-1280/one-substrate-what-merges-what-inherits)
addendum) put undertakings in the strategic runtime — `StrategicProjectRuntime` records on
`state.strategicState`, with no `project` node type anywhere in `src/types/graph.ts`. A
`bound_by` edge would therefore first require inventing a node type for undertakings, which the
no-new-node-types rule forbids and nothing in the binding ruling requests. The narrower ground
also holds: relationships-are-edges governs *entity-to-entity* relationships, and a binding is
bookkeeping between an entity and a runtime record. Traversal-shaped queries ("is this node
bound?") are served by the registry's runtime index plus the `removeNode` hook — which is
precisely the visibility an edge's cascade would have provided, obtained without one.

### Resolution logic

§2 scoring (deterministic, traced); no dice — the binder decides *who*, the checkpoint dice decide

### PRNG callouts

Binder scoring: zero draws. Mint generation: per-request stream
`mulberry32(seed + hashString(projectId + castKey))` — drain-tick-independent (§5). The lifecycle's
existing birth rng is untouched (queue drain happens before the birth roll and draws from the
request streams, not the phase stream — ambient-birth draw sequences shift only on ticks where a
drain changes the density precondition, which is a real world change, not stream disturbance).

## Content pillar

Minimal by design — this doc defines the **schema seams**; doc 2
([THR-1297](https://linear.app/threadbare/issue/THR-1297/the-action-library-works-holdings-and-naming-proactive-agent-actions))
authors the values: cast declarations with scarcity tiers + `identityRequirement`, per-kind
`creationEffects` band tables, and the ten kinds' stage specs. This plan ships engine-side
defaults so it runs content-free: undeclared cast specs bind nothing (today's behavior), the
migrated exemplar template exercises the full path.
