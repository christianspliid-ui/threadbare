## 1. Procedure followed

Per THR-412 plan doc §Procedure (final), the executor:

1. Reverse-engineered an action proposal for each fixture (`Docs/plans/.intent-proposals/<slug>.eval.md`). For the known-bad fixture (THR-400 original), the proposal was written under fairness discipline: the author wrote each fixture's intent_quote and scope **before** opening the audit doc / post-audit comments for that fixture. The THR-400 proposal acknowledges this discipline limit in its `author notes for the judge` section.
2. Spawned four `general-purpose` Agent subagents with `model: "opus"` per the intent-judge skill's spawn template. Each subagent loaded SKILL.md cold, was given exactly the action proposal path + plan doc path + Linear issue id (where applicable), and returned the structured verdict block.
3. **Calibration discipline for THR-400 specifically:** the spawn prompt told the judge to read the THR-400 description (the pre-audit 8-verb plan, still preserved as the issue body) but **NOT** the post-audit comments and **NOT** the audit doc (`Docs/audits/2026-05-11-thr-400-vision-audit.md`). The judge's metrics block confirms it honored the discipline (read order: action proposal → THR-400 description-only → Vision/ refs → SKILL.md context). The audit doc itself stayed sealed.
4. The Linear-MCP-issue fields were null for two fixtures (`encounter-build-toolkit`, `coordination-protocol`) because both predate or sit outside the Linear ticket system (the latter is the doc that established Linear-as-source-of-truth). The judges were told explicitly that the missing Linear issue is structural and to score Intent Fidelity against the action proposal's intent_quote rather than rejecting on "missing Linear." Both judges respected the override and proceeded.

Latency: each judge ran in ~50–130s (well inside the skill's 90s target for fixtures 1–3; fixture 4 ran longer at ~240s because the Vision audit dimension required loading 4 Vision/ files plus a full read of the THR-400 description body).

## 6. Proposed v1.1 rubric adjustments — **none**

Per the THR-412 plan doc § Verdict 2 escalation trip-wires, a v1.1 rubric proposal escalates to a separate Linear issue only if **any** of:

| Trip-wire | Fires? |
|-----------|--------|
| Changes touch more than one dimension's rubric (cross-dimension aggregation move, or 2+ PASS/GAP/VIOLATION thresholds shift) | No |
| Changes alter the aggregation rubric (first-match-wins ladder turning dimension scores into verdicts) | No |
| A new constant is added to the SKILL.md constants block | No |
| An invocation trigger is added or removed | No |
| The impact-classification table changes | No |

**No trip-wire fires.** This proposal is **inline, here in §6**, per Verdict 2's default-cheap rule.

### The recommendation: no changes for v1.1.

The clean diagonal is consistent with two readings: "the judge works" or "the eval set is too easy." Both readings argue for *not* tightening the rubric on the basis of this calibration alone. If we tighten the rubric to catch the 3 Vision drifts the judge missed on THR-400, we risk over-rejecting good plans in the field — and we don't have field signal yet to know where the rubric currently over-rejects.

The right next step is the field-signal calibration in 30 days. The judge will run against real Cowork handoffs during that window. The metrics it will accumulate are:
- Verdict distribution (should sit between the floor 0.05 and ceiling 0.30 Escalation rate)
- Override rate (how often a Revise or Block is overridden by the user)
- Block-then-revise loops (3+ on same plan = forced Escalate)
- Time-to-judgment (median should stay under 5 min)

Real handoffs will exercise:
- Subtle Vision drifts that don't stack five-deep
- The Revise verdict path (most common verdict in practice expected to be Revise, not Block)
- Reopened-issue handling
- Multi-pass loops

If the override rate on Revise/Block exceeds 50% in the 30-day window, the rubric is too strict. If verdict distribution is ≥95% Allow with zero user overrides, the rubric is rubber-stamping. Both are the kill criteria already named in SKILL.md.

### What the calibration noticed but does not propose

Two observations that may matter for v1.1 *if field signal confirms them* — recorded here as watchlist items, not proposed changes:

1. **Dimension 5 (Vision audit) on multi-verb plans may need a per-verb sub-rubric.** The judge correctly caught one Vision violation on THR-400's `sanction_mission` but missed three others (mortal-loop bridge missing, IPK surface undefined, catalog-surface direction not acknowledged). A plan that adds 8 mechanical entries to a catalog may carry 8 independent Vision-audit obligations; scoring them as one dimension under-resolves. If field signal shows the judge under-Blocks on multi-verb plans, consider an explicit "per-mechanism Vision audit" sub-step on dim 5. Watch but do not act yet.

2. **Dimension 3 (Wiring section) is wear-tested only on game-feature plans.** The judge GAP'd dim 3 on coordination-protocol because the doc doesn't have a `wiring-checklist.md`-style section — but the doc *does* wire itself into agent surfaces (skills, scheduled tasks, hooks). The judge handled this fairly (PASS for process-wiring analog) but a more strict reading could have GAP'd it. If field signal shows dim 3 is producing false-positive GAPs on process docs, consider an explicit "process-wiring analog acceptable" clarification in the rubric.

Neither is acted on. The 30-day field calibration is the decision gate.

## 7. Honest limits of this calibration

Documented for the record so the next calibration run (30 days hence) knows what to test against:

1. **Asymmetric eval set inflates judge specificity.** With 1 bad fixture and 3 good fixtures, a judge biased toward Allow would still get 3/4. The clean diagonal is partly an artifact of the small sample on the bad side. Field calibration in 30 days will broaden the bad side from real handoff signal.
2. **Reverse-engineered action proposals introduce author-side framing bias.** The proposals for all 4 fixtures were written by the calibration author, who knew the ground truth for each. The author wrote each fixture's intent_quote *before* opening the audit/reopen comment for that fixture, but cannot perfectly unsee the ground truth at the time of proposal authoring. This biases the proposals subtly toward whatever framing the author already believed about each plan's trajectory. Real proposals are written by Cowork at the time of plan-doc handoff, with no knowledge of how the plan will turn out — that's the cleaner test.
3. **THR-400 is a fat-pitch fixture.** Five vision/NFP violations stacked on one plan. A passing judgment doesn't prove the judge catches subtle drift. The field-signal calibration is where subtle-drift sensitivity gets tested.
4. **No Revise or Escalate fixtures.** Two of the four rubric verdicts have not been exercised end-to-end. Either ground truth in the wild will provide them, or a follow-up synthetic calibration in 60 days should construct them.
5. **Calibration discipline was honored on THR-400 specifically by spawn-prompt scaffolding.** A judge running in production won't have that scaffolding — it will encounter the full Linear issue (description + comments) and the audit doc (if it exists by then). If the audit doc and post-audit comments are visible at judge time, the judge's verdict will be *more* informed but the calibration is *less* clean. We accept this asymmetry; the calibration's purpose is to test the judge in cold-start conditions, not in informed-runtime conditions.
