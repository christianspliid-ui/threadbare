# Undertaking cells × the 26 subsystems: who is written, who reads (wayfinder research, 2026-09-03)

Sources (all `main`, 2026-09-03): `src/data/undertaking-objects.ts` (42 live cells), `Docs/canon/undertaking-grid.generated.md` (36 open cells), `src/data/world-objects.ts` (`owningSystem`), `Docs/canon/systems-inventory.md` + `scripts/subsystems-registry.ts` (26 subsystems), `scripts/interface-contracts.ts` / `Docs/canon/interface-map.generated.md`, plus the op modules named per row.

**Two framing facts before the table.**

1. **No live cell is reached from the tick loop today.** `src/data/strategic-action-constants.ts:926` — `export const UNDERTAKING_MODEL: UndertakingModel = 'templates';` and the header of `undertaking-objects.ts` (lines 24–26): *"with the flag on `templates` nothing here is reached from the tick loop."* Every "LIVE-TOUCHED" verdict below is a verdict about the wiring the registry declares, not about a write observed in a run.
2. **Op → subsystem mapping is by the substrate the op writes, not by the op's home module.** 15 of the 42 cells call an op in `src/engine/strategicGraphOps.ts` (domain `strategic` → "Strategic Projects & Control"); mapping by home module would put half the grid under one row and hide what actually moves. Each row cites both the op module and the graph artifact it writes.

## 2. Live cells that write into a system nobody reads

Ordered by how much of the cell's effect vanishes.

1. **`cell.observe.area`, `cell.observe.location`, `cell.observe.place`, `cell.observe.route`, `cell.observe.faction` — 5 cells, wholly inert.** Op: `recordIntelligence` (`src/engine/strategicGraphOps.ts:410-430`) writes one key into `actor.properties.strategicIntelligence`. Reader search (`grep -rn strategicIntelligence src/`): two hits, both documentation strings (`buildUndertakingPackage.ts:257`, `undertaking-kinds.ts:67`). Nothing in `intelligence.ts`, `familiarity.ts`, `phaseIntelligenceDecay.ts`, encounter eligibility, or any UI reads it. The registry itself half-knows: `undertaking-kinds.ts:67` describes the observe object as "actor-side `strategicIntelligence` record **plus `knows_of` familiarity**", but the cell never calls `seedKnowsOf`. The absorbed templates (`walk_the_unmapped`, `mount_expedition`, `scout_settlement`) therefore lose whatever their template `graphOps` hints did.
2. **`cell.seize.route` — the toll never collects.** `executeTaxTradeRoute` (`tradeRouteOps.ts:251`) writes `controlledBy` and `taxRate: TRADE_ROUTE_DEFAULT_TAX_RATE` on the `trades_with` edge. `taxRate` is parsed by `tradeRoute.ts:232` and consumed by nobody (`grep -rn "\.taxRate" src/` → that one line). `controlledBy` is read only as a **count** (`phaseEconomicTraits.ts:75`, an economic-trait badge) and in prose (`proseResolvers.ts:912-924`). No gold, stock, or prosperity moves to the seizer. The holding transfer half of the cell (`transferHolding`) is live.
3. **`cell.destroy.location` — the provenance is dead, the ruin is live.** `ruinedFromSubtype` and `ruinedTick` (`undertaking-objects.ts:425-427`) have zero readers outside the registry. `locationSubtype:'ruins'` and the prosperity floor *are* read (`battleAftermath.ts:150,163`, `notableAgendas.ts:233,269`, `phaseMandate.ts:34`, `phaseProsperity.ts`). And the subsystem whose name is Ruins does not notice: `ruins/*` keys on `elder_ruin` / `place_of_power` (`delveVariant.ts:309`, `placeOfPowerStreams.ts:74`), so a settlement a mortal ruins never becomes a delve or a clue site.
4. **`cell.use.power` — two of its costs land nowhere.** `activateSpell` writes `exhaustedUntilTick` (`spellActivation.ts:268`) — no reader anywhere in `src/engine`. It charges `properties.doom` (`:228,275`) — read by exactly one site, the `healthLow/healthHigh` predicate at `effectPredicates.ts:231-235`. The `condition_inflict` and `domainCapability` costs are read (row 23, row 12).
5. **`cell.claim.location` — read, but misread by one consumer.** `claimControl` writes a mortal `controls` edge; `armySupply.ts:204` takes `getIncomingEdges(settlementId,'controls')[0]?.source` as a faction id. A mortal who claims a town will be treated as the provisioning faction of any army that reaches it. Consequential, but the consequence is a type confusion, not a design.

Everything else in the 42 has at least one non-UI engine reader (table column 5).

## 3. The 14 UNTOUCHED subsystems — by design vs gap

**By design (a mortal's own work should not move it) — 9**

| Subsystem | Why | Note |
|---|---|---|
| Rival Gods & Schemes | Rivals act on the god's layer (`rival.ts`, phase 3); the grid marks Ascendant/God as not an object | — |
| Doom Clock & Journey | The run's master clock; Journey is "a record" (grid) | Already a *reader* (`journeyEngine.ts:142`) — fine |
| Mandate | The god's objective | Reader via `'ruins'` list — fine |
| Essence & Divine Economy | Essence is the god's currency; `essenceSources.ts` deliberately walks only the ascendant's `controls` | Reaches it indirectly through economy → source yield |
| Encounters & Dilemmas | The other lane of the same decision board (`decision-board-shadow-telemetry`); an undertaking that *seeds* an encounter would re-open the templates model's catalyst path | Heaviest reader of cell output — that is the intended shape |

| Attention, Chronicle & Narrative | Event is "a record" | Reads every cell through the outcome node |
| Ascendant Beats & Progression | Player-side | Reads `strategicState.controls` |
| Agent Lifecycle | Mortal sovereignty is a Vision non-negotiable (grid); assassination is the one fork left to Christian | — |

| Subsystem | Evidence the substrate wants a hand | Kind × verb that would reach it |
|---|---|---|

If casting is meant to cost the soul, the cost is on the wrong property.

Two registry observations that fell out of the mapping: (a) `world-objects.ts` names `owningSystem` values that are not registry subsystems — `'World generation & terrain'`, `'Sublocations'`, `'Trade routes'`, `'Hex map'`, `'Cosmology'`, `'Reputation & standing'`, `'Traits & attachments'`, `'Agents & decision'` — so the catalogue and `SUBSYSTEM_NAMES` cannot be joined mechanically; (b) the op modules `spellActivation.ts` (`spell`), `traits.ts` (`traits`), `holdings.ts` (`holdings`), `companions.ts` (`companions`), `domainCapability.ts` (`domain`) sit in engine domains no subsystem claims.
