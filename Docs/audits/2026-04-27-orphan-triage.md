## Surprising findings

### 1. `.codesight/` is tracked but auto-regenerated every session
The four `.codesight/` files are committed into git, but the `codesight v1.13.1` session-start hook regenerates them on every conversation. This guarantees a permanently dirty worktree as long as the files stay tracked — the root cause of impediment #59 as a recurring condition. The fix is a one-time gitignore operation (`git rm --cached .codesight/ -r` + add `.codesight/` to `.gitignore`), not a periodic commit. **This is the highest-impact decision in this triage** because it eliminates the dirty-state condition at source.

*Note:* `.codesight/` is not currently in `.gitignore`.

### 2. `scripts/session-end-retro.ts` is a complete Cowork-generated implementation sitting untracked on the THR-214 branch
This is a 257-line, fully functional TypeScript script implementing the session-end retro hook (the "brain" of THR-214). It was apparently authored by Cowork as part of the THR-214 handoff but never staged. The THR-214 implementation branch is the current branch — CC can pick this up and complete the feature with relatively little additional work (the plan doc at row 7 lists exactly what else remains: the hook script wrapper, the README, and the `settings.json` registration).

### 3. Recurring "orphaned Cowork docs" pattern
Commit `9d1cbde3` ("docs: commit orphaned Cowork docs and Sentry integration, Apr 17–24") addressed this same class of problem 9 days ago. The pattern — Cowork produces docs and code that float untracked until a manual cleanup pass — recurs. THR-277 (worktree isolation) and THR-214 (session-end retro) are both in flight and both left artifacts here. If this pattern is expected, a periodic "commit floating Cowork artifacts" housekeeping convention (or a Cowork-side `git add` before handoff) may be worth encoding in the next retro.
