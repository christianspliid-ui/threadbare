# Phase 13 — UI Design Contract

## Color

### Existing Palette (unchanged)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0a0e` (`--bg-abyss`) | Page background, fullscreen overlays |
| Secondary (30%) | `#1a1a1f` (`--bg-surface`) | Cards, panels |
| Accent (10%) | `#d4a040` (`--accent-gold`) | Active states, selected items |
| Destructive | `#f87171` (`--negative`) | Losses, danger, downward trends |

Accent reserved for: active tab indicators, selected hex highlight, identity chip name, primary CTA buttons. Unchanged from existing contract.

### New Visual Layer Colors (Three.js scene, not CSS)

These are Three.js material colors for WebGL rendering on the hex map canvas.

| Element | Color Source | Rendering |
|---------|-------------|-----------|
| Army shield icon fill | Faction heraldic color (indexed from `FACTION_HERALDIC_COLORS`) | InstancedMesh per-instance color attribute |
| Army shield icon outline | `#1a1a1f` (dark border for contrast against terrain) | Baked into texture atlas at 2px stroke |
| Battle crossed-swords icon | `#f87171` (red, matches `--negative` semantic) | Single sprite, no per-instance color |
| Battle pulse glow | `#f87171` at opacity 0.3-0.8 oscillation | Opacity animation on material |
| Siege ring icons | Besieging faction's heraldic color | InstancedMesh per-instance color, same as army |
| Siege hex darkening overlay | `#000000` at opacity 0.25 | Additive color adjustment on hex fill instance |

**Rule:** Army colors MUST use faction heraldic colors (red, blue, purple, magenta, cyan, orange) — never terrain palette colors. This preserves the established distinction between faction elements (saturated/bright) and terrain (muted/earthy) per `AGNT-04`.

## Army Visual Layer Contract

### Army Sprite (Shield Icon)

| Property | Value | Rationale |
|----------|-------|-----------|
| Shape | Shield silhouette (distinct from circular agent dots) | CONTEXT.md decision: "Shield icon...clearly distinguishable from agent circles" |
| Texture atlas | Single 256x256 canvas with 3 size variants (small/medium/large) | Follows SignifierMesh pattern: one atlas, UV rect per instance |
| Icon scale (world units) | Small: 4.0, Medium: 6.0, Large: 8.0 | Proportional to agent dot (3.0) and location icon (8-12) sizes |
| Size thresholds | Small: army size 1-49, Medium: 50-149, Large: 150+ | Named constants: `ARMY_SIZE_SMALL_MAX=49`, `ARMY_SIZE_MEDIUM_MAX=149` |
| Z position | `0.090` (between LOCATIONS 0.080 and TRAILS 0.085 — insert as ARMIES at 0.090) | Above locations, below agent trails |
| Render order | `10` (same as AGENTS — co-planar, Z-separation sufficient) | Armies render at agent level |
| Zoom visibility | hero-local: true, regional: true, continental: true, full-world: false | Armies visible one tier wider than agents — strategic importance visible at continental zoom |
| Positioning | Hex center slot (same as location CENTER slot) | Army occupies the hex — if location also present, army renders on top (higher Z) |

### Battle Indicator (Crossed Swords)

| Property | Value | Rationale |
|----------|-------|-----------|
| Shape | Crossed swords (reuse `battleground` location icon paths from `locationIconRegistry.ts`) | Existing art asset, proven readability |
| Texture | Single 128x128 canvas, red fill (`#f87171`) | One texture shared by all battle indicators |
| Icon scale (world units) | 10.0 (larger than army shields to overlay them) | Must be clearly visible over the two army icons it replaces |
| Z position | `6.050` (between AGENTS 6.000 and EVENTS 6.100) | Above army sprites, below event indicators |
| Render order | `10` (AGENTS level) | Z-separation handles ordering |
| Animation | Opacity oscillation 0.4 to 1.0, period 1200ms, easing `ease-in-out` | CONTEXT.md: "Pulsing animation (opacity oscillation) to draw attention." Uses `breathe` keyframe timing convention (motion.md) |
| Zoom visibility | hero-local: true, regional: true, continental: true, full-world: false | Same as armies — battles are strategically significant |
| Cardinality | One indicator per battle (not per army) | CONTEXT.md decision |

### Siege Indicator (Ring + Overlay)

| Property | Value | Rationale |
|----------|-------|-----------|
| Ring shape | 6 small shield icons placed at hex edge midpoints (N, NE, SE, S, SW, NW) | CONTEXT.md: "Ring of siege icons around the settlement." Uses hex edge positions from composition system |
| Ring icon scale (world units) | 3.0 (smaller than army shields — these are positional markers) | Must not obscure the settlement icon at center |
| Ring icon color | Besieging faction heraldic color | CONTEXT.md: "Faction-colored to match the besieging army" |
| Hex darkening | Reduce settlement hex brightness by 25% (multiply RGB by 0.75) | CONTEXT.md: "Darkened overlay (reduced opacity filter on terrain)." Applied via per-instance color attribute modification on hex fill mesh |
| Z position (ring) | `0.090` (same as ARMIES layer) | Siege ring co-planar with army sprites |
| Z position (darkening) | `0.000` (applied to hex fill mesh directly) | Modifies existing hex fill color, not a separate mesh |
| Zoom visibility | Same as armies: hero-local, regional, continental visible; full-world hidden | Siege status is strategic information |

## Animation Contract

All animations follow `Docs/design-system/motion.md` conventions.

| Animation | Type | Duration | Easing | Notes |
|-----------|------|----------|--------|-------|
| Battle indicator pulse | Continuous opacity oscillation | 1200ms period (600ms half-cycle) | `ease-in-out` | Uses Three.js material opacity in render loop, not CSS. Matches `breathe` keyframe convention. Capped to one pulse animation per battle — never multiple overlapping. |
| Army sprite appear/disappear | Fade in/out on army creation/disbandment | 150ms (`--anim-fast` equivalent) | `ease-out` in, `ease-in` out | Material opacity transition in render loop |
| Siege darkening | Instant application when siege starts, fade out on siege end | 0ms apply, 200ms (`--anim-normal` equivalent) fade out | `ease-out` | Per-instance color attribute modification |

**Forbidden:** No spring/bounce easing. No continuous glow on elements larger than 8px world units (per motion.md). Battle pulse is opacity-only, not glow.
