## Typography

Phase 4 typography covers only the HTML label overlay. All three label tiers use `--font-display` (Cinzel), matching the cartographic Mystara style. No body text is introduced in this phase — there are no panels, forms, or prose elements.

| Role | Size | Weight | Line Height | Font | Transform | Decoration |
|------|------|--------|-------------|------|-----------|-----------|
| Kingdom label | 20px | 700 (bold) | 1.1 | Cinzel (`--font-display`) | uppercase | letter-spacing: 0.08em |
| Barony label | 14px | 400 (regular) | 1.2 | Cinzel (`--font-display`) | title case (JS) | none |
| Geographic feature label | 12px | 400 (regular) | 1.2 | Cinzel (`--font-display`) | sentence case | font-style: italic |
| River label | 12px | 400 (regular) | 1.2 | Cinzel (`--font-display`) | title case (JS) | font-style: italic |

Notes:
- 20px is within the CONTEXT.md locked range of 18-24px for kingdoms. 20px is the prescribed value.
- 14px is within the locked range of 12-16px for baronies. 14px is the prescribed value.
- 12px is within the locked range of 10-14px for geographic features. 12px is the prescribed value.
- All labels use `pointer-events: none` — they are display-only, not interactive.
- `lineHeight: 1.1` on kingdoms prevents multiword all-caps labels from expanding the label bounding box too much.

Source: CONTEXT.md "Label Style: Dark Text with Light Halo" — exact px values derived from midpoints of stated ranges.

## Interaction Contract

Phase 4 introduces visual map layers only. There are no new user interactions. The existing camera pan/zoom interactions from Phase 1 remain unchanged. The label overlay is `pointer-events: none` throughout.

### Label Visibility Triggers (not user interactions — zoom-driven)

| Zoom Tier | Labels Shown | Transition |
|-----------|-------------|-----------|
| Hero-local (~300px/hex) | Current geographic region name + nearby POI names (Phase 6) | CSS opacity: 0→1, 200ms ease |
| Regional (~100px/hex) | Barony names, geographic feature names in viewport | CSS opacity: 0→1, 200ms ease |
| Continental (~30px/hex) | Kingdom names, barony seats of power | CSS opacity: 0→1, 200ms ease |
| Full-world (~10px/hex) | Kingdom names only | CSS opacity: 0→1, 200ms ease |

Transition: CSS `transition: opacity 200ms ease` on each label `<div>`. Labels below their zoom tier threshold have `opacity: 0` (not `display: none`) so transitions animate smoothly. Labels completely outside the viewport use `display: none` for performance skip.

Label collision: AABB sweep in screen space after projection, priority order: kingdom > barony > geographic > river. Hidden labels get `visibility: hidden` (not removed from DOM, to preserve stable rendering).

Label update timing: Position updates run in the Three.js `requestAnimationFrame` callback, not on React state change, to prevent 1-2 frame lag during pan.

Source: CONTEXT.md "Zoom Tiers Serve Player Intent"; RESEARCH.md Pattern 4, Pattern 5, Pitfall 3.

## Copywriting Contract

Phase 4 produces no user-facing copy in panels or modals. All text is cartographic label content generated from worldgen data. The following covers the generated label text conventions.

| Element | Copy Pattern | Example |
|---------|-------------|---------|
| Kingdom label | All-caps proper noun (generated name) | `STONEMARK KINGDOM` |
| Barony label | Title case proper noun (generated name) | `Eastmarch` |
| Geographic feature label | Italic title case with descriptor | *Ashwood Forest* |
| River label | Title case with "River" suffix | *Greyvale River* |
| Capital marker tooltip (hover) | `{name} — {tier} capital` | `Ironhold — Kingdom Capital` |

Empty state (no regions detected): The map renders terrain without any overlay. No user-visible empty state message is shown — region detection failure is an engine concern handled via fail-soft (tiles with no region assignment are skipped silently).

Error state: Not applicable — this phase adds no user-input flows. Region detection errors are logged to console, not shown in UI.

Destructive actions: None.

Source: REQUIREMENTS.md REGN-07; CONTEXT.md label hierarchy decisions; RESEARCH.md Open Question 1 (river name placeholder generation).

## Platform Constraints

| Constraint | Contract |
|-----------|----------|
| Viewport | 1920x1080 locked — `html, body, #root { height: 100dvh; overflow: hidden }` — DO NOT remove |
| Label overlay | `position: absolute; inset: 0; pointer-events: none; z-index: 20` within same container as Three.js canvas |
| Border linewidth | WebGL clamps `linewidth > 1` to 1px — MUST use quad-strip `MeshBasicMaterial` (same as `RiverMesh.ts`) |
| Hex coordinate system | flat-top odd-q offset — always use `hexNeighbors()` from `hexMath.ts`, never hardcoded direction offsets |
| World space units | Always use `HEX_CONSTANTS.HEX_SIZE = 10` for all scene geometry |
| Label projection timing | Update label positions in `requestAnimationFrame` callback, not React state change |
| Collision detection debounce | Recompute AABB layout at most every 60ms (debounce on zoom/pan events) |
| Font availability | `var(--font-display)` (Cinzel) already loaded — no additional font load needed |

Source: CLAUDE.md "Viewport Contract"; RESEARCH.md Pitfalls 1-4; CONTEXT.md decisions.
