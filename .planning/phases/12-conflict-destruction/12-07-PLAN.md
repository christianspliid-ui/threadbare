<objective>
Add army and battle visual presence on HexMapV2 and debug inspection tools.

Purpose: Players need to see armies moving on the map, battles raging at hexes, and siege encirclements around settlements. The debug panel needs an Armies tab for development inspection.

Output: Armies should appear as colored indicators on the hex map. Active battles should show visual indicators. Debug panel Armies tab should list all armies with their state.
</objective>

## Task Breakdown

### 1. Update render layer ordering

**File: `src/components/HexMapV2/scene/RenderLayers.ts`**

Add new render order entries:
```typescript
ARMIES: 10.5,        // Above agents (10), below events (11)
BATTLE_INDICATORS: 10.8,  // Above armies, below events
```

Add Z positions:
```typescript
ARMIES: 5.500,       // Below agents (6.000) but above 3D geometry
BATTLE_INDICATORS: 5.800,
```

### 2. Create army layer

**New file: `src/components/HexMapV2/scene/ArmyLayer.ts`**

Renders army actors on the hex map using the same InstancedMesh pattern as agent sprites.

- Query graph for all actor nodes with `properties.armyState`
- For each army:
  - Get `located_at` hex position
  - Get faction color from `member_of` edge → faction → faction definition color
  - Size indicator: warband=small circle, regiment=medium, host=large
  - Render at hex center with slight offset from agent positions
- Update each frame (armies move)
- Visible at all zoom tiers (armies are always significant)

Use existing patterns from `src/components/HexMapV2/scene/agents/` directory.

### 3. Create battle indicator layer

**New file: `src/components/HexMapV2/scene/BattleIndicatorLayer.ts`**

- Query graph for battle nodes (actors with `properties.battleState`)
- For field battles: render crossed-swords icon or pulsing red glow at hex
- For sieges: render encirclement ring around settlement hex
- Animate: pulse or rotate to indicate active combat
- Visible at all zoom tiers

### 4. Wire layers into HexMapV2

Register new layers in the HexMapV2 scene setup (wherever `AgentLayer`, `LocationLayer` etc. are added to the scene). Follow existing layer registration pattern.

### 5. Create DebugPanel Armies tab

**New file: `src/components/DebugPanel/ArmiesTab.tsx`**

Display:
- **Active Armies** section:
  - Army name, faction, commander, size, headcount
  - Quintessence bar (current/max)
  - Current objective (type + target)
  - Location (hex coordinates)
  - Maintenance cost
  - Ticks active

- **Active Battles** section:
  - Battle type (field/siege)
  - Location
  - Participating armies
  - Current momentum (with visual bar: ← defender ... attacker →)
  - Ticks elapsed
  - Phase (for sieges: opening/early/middle/crescendo)
  - Spotlight history (template IDs + outcomes)

- **Destruction Log** section:
  - Recent destruction events from trace buffer
  - Severity, settlement, consequences summary

### 6. Wire Armies tab into DebugPanel

**File: `src/components/DebugPanel/DebugPanel.tsx`**

Add `ArmiesTab` to the tab list, following existing tab pattern (Spheres, Encounters, Factions, etc.).

### 7. Army notifications

**File: `src/components/NarrativeLog.tsx`** (or wherever notification tiers are handled)

Wire army events to existing tiered notification system:

| Event | Tier | Condition |
|-------|------|-----------|
| Army mobilization (own faction) | Tier 1 (modal) | Thread to commander/faction |
| Army mobilization (foreign) | Tier 2 (toast) | Thread to agent in that faction |
| Battle spotlight | Tier 1 (modal) | Thread to any participant |
| Army attrition threshold | Tier 2 (toast) | Thread to commander |
| Siege established | Tier 1 (modal) | Thread to participant/settlement |
| Battle aftermath | Tier 1 (modal) | Thread to any participant |
| No-thread aftermath | Tier 3 (chronicle) | No threads |

These are wired by reading `army_lifecycle`, `battle`, `siege`, `destruction` traces from the trace buffer and mapping to existing notification components.
