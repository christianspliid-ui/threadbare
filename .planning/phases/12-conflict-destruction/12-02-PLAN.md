<objective>
Define army entity types and build the army spawning pipeline.

Purpose: Armies are faction-level actors that participate in the encounter system. This plan creates the ArmyState data model, the army spawn encounter template, and the spawning logic that fires when a faction's ambition requires military force.

Output: After running `tick 30` in CLI, factions with military ambitions and sufficient Iron+Gold capability should spawn armies visible via `agents` command (filtered to armyState-bearing actors). Army lifecycle traces should appear in trace buffer.
</objective>

## Task Breakdown

### 1. Create army type definitions

**New file: `src/types/army.ts`**

```typescript
export type ArmySizeCategory = 'warband' | 'regiment' | 'host';

export interface ArmyState {
  size: ArmySizeCategory;
  headcount: number;
  objective: ArmyObjective | null;
  quintessence: number;
  quintessenceMax: number;

}

export interface ArmyObjective {
  type: 'raid' | 'conquer' | 'defend' | 'intercept' | 'reinforce_siege';
  targetNodeId: string;

}
```

### 2. Create army spawning engine

**New file: `src/engine/armySpawning.ts`**

Functions:

`isEligibleForArmySpawn(state, factionId): boolean`
- Faction has ambition requiring military force (territorial_expansion, revenge, or defensive_consolidation under threat)
- Faction has member agent at Iron capability ≥ Tier 4
- Faction has Gold capability ≥ Tier 3
- Faction doesn't already have an active army (check `commanded_by` edges from faction members)
- Returns boolean

`selectCommander(state, factionId): string | null`
- Find all agents with `member_of` edge to faction
- Filter to those with Iron capability ≥ ARMY_SPAWN_IRON_TIER_MIN
- Sort by Iron capability descending
- Return highest Iron agent ID (deterministic — no PRNG)
- Return null if none qualify

`determineSizeCategory(state, factionId): ArmySizeCategory`
- Based on faction Gold capability tier:
  - Tier 3-4: warband
  - Tier 5-6: regiment
  - Tier 7+: host
- Deterministic from Gold tier

`spawnArmy(state, factionId, commanderId, ambitionNodeId): string`
- Create actor node: `id = army_{factionId}_{tick}`, `type = 'actor'`, `name` generated from faction name
- Set `properties.actorType = 'group'` (armies are group actors)
- Set `properties.armyState: ArmyState` with size, headcount, quintessence, etc.
- Add `commanded_by` edge: army → commander
- Add `member_of` edge: army → faction
- Get faction's primary settlement (`located_at` of faction or commander) → add `located_at` edge: army → settlement
- Add `pursues` edge: army → ambition node (from faction's active ambition)
- Set objective from ambition type
- Emit `ArmyLifecycleTrace` with event: 'raised'
- Return army node ID

### 3. Create army encounter templates

**New file: `src/data/army-encounter-content.ts`**

Army raise encounter: `mc.army.raise`
- 2-step encounter: Step 1: Muster the troops (Iron test), Step 2: March formation (Gold test — can you pay them?)
- On full success: army spawns
- On failure: recruitment fails, Gold spent but no army

Attrition threshold encounters (used by Plan 03):
- `army.threshold.supply_crisis` — 2-step (Eye to assess + Gold to resupply)
- `army.threshold.desertion` — 2-step (Heart to rally + Iron to drill)
- `army.threshold.mutiny` — 2-step (Heart to negotiate + Iron to assert authority)
- `army.threshold.disbandment` — 1-step (no resolution — army dissolves)

Register in encounter content aggregator.

### 4. Wire army spawn check into orchestrator

The army spawn check doesn't need its own phase — it fires as a **faction encounter** during the faction ambition evaluation (Plan 01's `phaseFactionAmbitions`). When a faction's ambition requires military force and `isEligibleForArmySpawn()` returns true, initiate the army raise encounter.

Add to `phaseFactionAmbitions` (from Plan 01):
```typescript
// After ambition is created/confirmed as military:
if (requiresMilitaryForce(ambition) && isEligibleForArmySpawn(state, factionId)) {
  const commander = selectCommander(state, factionId);
  if (commander) {
    spawnArmy(state, factionId, commander, ambitionNodeId);
  }
}
```

## Fail-Soft Table

| Failure | Fallback |
|---------|----------|
| No eligible commander (none at Iron Tier 4+) | Skip army spawn |
| Faction Gold insufficient | Skip army spawn |
| Commander dies before spawn completes | Cancel spawn, log trace |
| Faction already has max armies | Skip spawn silently |
| Faction primary settlement not found | Use commander's current location |
