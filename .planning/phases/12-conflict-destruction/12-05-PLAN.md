<objective>
Implement siege resolution with accelerating pacing, regional encounter generation, and settlement-specific mechanics.

Purpose: Sieges are slow multi-tick battles that accelerate toward a crescendo. They act as regional encounter generators — pulling nearby entities into the conflict through call-for-aid, smuggling, and negotiation encounters. Sieges are the most narratively rich conflict type.

Output: When an army arrives at a hostile settlement, a siege should initiate with correct pacing. Regional encounters should spawn for entities within range. Siege should accelerate from opening dread to crescendo chaos.
</objective>

## Task Breakdown

### 1. Add siege constants to battle types

**File: `src/types/battle.ts`** (extend)

```typescript
export const SIEGE_INITIAL_INTERVAL = 5;
export const SIEGE_ACCELERATION_RATE = 6;
export const SIEGE_MAX_DURATION = 40;
export const SIEGE_RESOLUTION_THRESHOLD = 12;
export const SIEGE_DEFENDER_MOMENTUM_BONUS = 2;
export const SIEGE_STARVATION_TICK = 15;
export const SIEGE_REGIONAL_ENCOUNTER_RANGE = 5;
export const SIEGE_COMBAT_ATTRITION_ATTACKER = 1.0;
export const SIEGE_COMBAT_ATTRITION_DEFENDER = 0.5;
```

### 2. Create siege resolution engine

**New file: `src/engine/siegeResolution.ts`**

`createSiegeNode(state, attackerArmyId, settlementId, hexId): string`
- Create actor node with `battleState` where `battleType = 'siege'`
- Set `settlementId` in battleState
- Create virtual defender army if settlement has no army (garrison = settlement Iron capability)
- Set `initialMomentumOffset` to `-SIEGE_DEFENDER_MOMENTUM_BONUS` (defenders start ahead)
- Apply fortification modifier based on settlement tier:
  - hamlet: none (PREPARED_DEFENSE_MULTIPLIER only)
  - town: FORTIFICATION_BASIC
  - city/capital: FORTIFICATION_GRAND
- Add `participates_in` edges
- Emit `SiegeTrace` with event: 'established', phase: 'opening'

`getSiegePacingInterval(ticksElapsed: number): number`
```typescript
return Math.max(1, SIEGE_INITIAL_INTERVAL - Math.floor(ticksElapsed / SIEGE_ACCELERATION_RATE));
```

`getSiegePhase(ticksElapsed: number): 'opening' | 'early' | 'middle' | 'crescendo'`
- 0-3: opening
- 4-10: early
- 11-20: middle
- 21+: crescendo

`tickSiege(state, siegeNodeId): void`
- Same as `tickBattle` but with siege-specific:
  - Use `getSiegePacingInterval()` instead of fixed interval
  - Apply `SIEGE_COMBAT_ATTRITION_ATTACKER/DEFENDER` (asymmetric)
  - At `SIEGE_STARVATION_TICK`: check if defender resupplied; if not, spawn `siege_starvation` encounter
  - Check for relief army arrival (new `participates_in` edge → spawn `siege_relief_arrives`)
  - Generate regional encounters each tick
  - Track and emit siege phase in trace

`generateRegionalEncounters(state, siegeNodeId): void`
- Find all actors within `SIEGE_REGIONAL_ENCOUNTER_RANGE` hexes of siege
- For each eligible actor (not already in battle):
  - Shadow-capable + near siege → `siege_smuggle_supplies` eligible
  - Heart-capable + diplomatic → `siege_negotiate_terms` eligible
  - Allied faction with army → `siege_relief_march` eligible
  - Attacker-allied faction → `siege_join_attackers` eligible
- Spawn encounters (one per eligible actor per siege, tracked to avoid duplicates)

### 3. Siege detection in colocation

Extend `phaseColocationDetection` (from Plan 04):
- After hostile army pair detection, also check:
  - Army arrives at hex with hostile settlement (settlement controlled by opposing faction)
  - If so: `createSiegeNode()` instead of `createBattleNode()`

### 4. Breach spotlight integration

When `siege_breach` spotlight resolves successfully:
- Reduce settlement's fortification multiplier by `BREACH_FORTIFICATION_REDUCTION`
- This shifts the momentum calculation dramatically
- Subsequent ticks recalculate effective size with reduced fortification
- IPK keywords shift: "impregnable" → "shattered"

### 5. Create siege encounter templates

**New file: `src/data/siege-encounter-content.ts`**

Siege-specific spotlight templates:
- `siege.spotlight.opens` — 1-step, atmospheric (opening phase only)
- `siege.spotlight.sally_forth` — 2-step (Iron test to break out + Eye to identify weakness)
- `siege.spotlight.negotiate_terms` — 2-step (Heart test)
- `siege.spotlight.starvation` — 1-step (Flesh/Life test)
- `siege.spotlight.breach` — 2-step (Iron + Stone test)
- `siege.spotlight.final_assault` — 3-step (Iron + Iron + Heart)
- `siege.spotlight.relief_arrives` — 1-step (triggered by external event)

Regional encounter templates:
- `siege.regional.call_for_aid` — spawns at allied faction settlements
- `siege.regional.join_attackers` — spawns at attacker-allied settlements
- `siege.regional.smuggle_supplies` — spawns for Shadow-capable agents near siege
- `siege.regional.negotiate_terms` — spawns for Heart-capable agents near siege
- `siege.regional.sabotage` — spawns for Shadow agents with thread to either side

## Fail-Soft Table

| Failure | Fallback |
|---------|----------|
| Siege exceeds max duration | Force resolution — stalemate, attacker withdraws |
| Defender settlement has no prosperity data | Treat as prosperity 0, starvation fires immediately |
| Relief army arrives after siege resolved | Army at settlement normally — no battle |
| Regional encounter range finds no eligible actors | No regional encounters this tick |
| Settlement fortification data missing | Treat as no fortification (prepared defense only) |
