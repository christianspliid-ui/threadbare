<objective>
Implement battle resolution as graph nodes with momentum-based outcomes, spotlight encounters for player-visible narrative beats, and thread-based visibility filtering.

Purpose: When two hostile armies meet at the same hex, a battle node is created. The battle progresses through spotlight encounters that the player can intervene in, shifting momentum until one side wins. This is the core combat loop of TB-073.

Output: After engineering a situation where two armies meet (or using test fixtures), battles should appear as graph nodes. Spotlights should fire for threaded entities. `tick 5` during a battle should show momentum shifts and eventual resolution.
</objective>

### 2. Create battle resolution engine

**New file: `src/engine/battleResolution.ts`**

`calculateInitialMomentum(attackerArmy, defenderArmy, location): number`
- Compute effective sizes with situational modifiers
- `log2(sizeRatio) × SIZE_MOMENTUM_SCALE`
- Clamp to `±(BATTLE_RESOLUTION_THRESHOLD - 2)` so spotlights always matter
- Deterministic — no PRNG

`createBattleNode(state, attackerArmyId, defenderArmyId, hexId): string`
- Create actor node with `battleState` property
- Add `participates_in` edges from both armies to battle
- Add `located_at` edge from battle to hex
- Set initial momentum from size calculation
- Emit `BattleTrace` with event: 'started'
- Return battle node ID

`tickBattle(state, battleNodeId): void`
- Increment `ticksSinceLastSpotlight`
- Apply combat attrition to both armies (BATTLE_COMBAT_ATTRITION from both armies' quintessence)
- Check for newly arrived entities at battle hex → add `participates_in` edges
- Check spotlight eligibility (interval met)
- If spotlight due: call `selectSpotlight()`, initiate as child encounter
- Check resolution: `|momentum| >= BATTLE_RESOLUTION_THRESHOLD` OR `ticksElapsed >= FIELD_BATTLE_MAX_DURATION`
- If resolved: call `resolveBattle()`

`resolveBattle(state, battleNodeId): void`
- Determine resolution type from final momentum
- Remove battle node and `participates_in` edges
- Apply aftermath (calls into Plan 06's destruction system)
- Emit `BattleTrace` with event: 'resolved'

### 3. Create spotlight selection

**New file: `src/engine/battleSpotlights.ts`**

`hasThreadToBattle(state, battleNodeId): boolean`
- Check if player (ascendant) has `thread` edges to any entity connected to battle via `participates_in` or `commanded_by`
- If no threads → return false (chronicle-only battle)

`getEligibleSpotlights(state, battleNodeId): SpotlightTemplate[]`
- Filter spotlight templates by battle state conditions:
  - `spotlight_commander_peril`: momentum < -3 AND commander threaded
  - `spotlight_turning_point`: |momentum| < 2
  - `spotlight_moral_dilemma`: victory possible AND sphere tension
  - `spotlight_betrayal`: unresolved faction grievance
  - `spotlight_artifact_activation`: significant artifact present
  - `spotlight_third_army`: new army arrived this tick
  - `spotlight_divine_counterstrike`: rival ascendant invested
  - `spotlight_last_stand`: army quintessence < 20%
  - `spotlight_champion_duel`: both commanders Iron Tier 5+

`selectSpotlight(state, battleNodeId): string | null`
- Get eligible spotlights
- If none eligible → return null (skip this tick)
- If one → return it
- If multiple → use `state.rng()` to select (seeded PRNG)
- Return template ID

// Check for hostile army colocation → create battle
const armiesAtHex = colocatedActors.filter(a => a.properties.armyState);
if (armiesAtHex.length >= 2) {
  const hostilePairs = findHostileArmyPairs(state, armiesAtHex);
  for (const [attacker, defender] of hostilePairs) {
    if (!isAlreadyInBattle(state, attacker.id) && !isAlreadyInBattle(state, defender.id)) {
      createBattleNode(state, attacker.id, defender.id, hexId);
    }
  }
}

## Fail-Soft Table

| Failure | Fallback |
|---------|----------|
| No eligible spotlight templates | Skip spotlight this tick |
| No threads to either army | No spotlights; chronicle-only resolution |
| Battle exceeds max duration | Force resolution from current momentum |
| Spotlight references destroyed entity | Skip, select next eligible |
| Both armies destroyed simultaneously | Mutual destruction resolution |
