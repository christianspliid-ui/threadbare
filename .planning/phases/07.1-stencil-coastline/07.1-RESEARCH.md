## User Constraints (from CONTEXT.md)

### Locked Decisions
- **Approach:** WebGL stencil buffer to clip land hexes to the organic contour boundary
- **Architecture:** Split `createHexFillMesh` into TWO InstancedMeshes: land mesh (stencil-tested) + water mesh (normal)
- **Stencil pipeline:** Pass 0 (stencil write, renderOrder -1) → Pass 1 (land hexes, EqualStencilFunc) → Pass 2 (water hexes, normal) → Pass 3+ (grid lines, signifiers, etc.)
- **Contour source:** Use `computeCoastline().loops` for stencil write shapes. No earcut holes needed — each loop is a simple filled shape.
- **Threshold tuning:** May need to lower threshold from 0.35 to ~0.30 so contour extends past land hex edges into water territory
- **Lake handling:** Lake hexes go in the water InstancedMesh. Lake fills rendered as simple organic shapes on top.
- **Water depth bands:** `shallowLoops` rendered as filled shapes on top of water hexes (in water area only)
- **Render order:** stencil write = -1, land hexes = 0 (HEX_FILL), water hexes = 0 (HEX_FILL), depth bands = 1 (COASTLINE), grid lines = 2 (GRID)

### Failed Approaches — DO NOT RETRY
- Ocean mask with 65+ land contour holes → earcut triangulation silently fails
- Land contour fill overlay at z > 0 → covers terrain with flat color despite z-ordering
- Depth band fill shapes with land holes → earcut fails
- depthTest tricks → GPU-dependent, not portable
- Coastal hex scaling → creates white/colored gaps

## Summary

Phase 07.1 implements the stencil buffer technique to clip land hex edges to an organic coastline boundary. The approach writes an invisible land-contour shape into the GPU stencil buffer at renderOrder -1, then renders land hexes with `EqualStencilFunc` so only pixels inside that contour appear. Water hexes render normally without stencil testing. This is a pure rendering pass with zero changes to worldgen, terrain coloring, or the coastline engine.

The key architectural change is splitting `createHexFillMesh` from one InstancedMesh into two: land (~40K hexes) and water (~20K hexes). The split uses `isWaterTerrain()` from `coastline.ts` as the canonical classifier. Both meshes share the same `buildHexGeometry()` and `getHexColor()` calls. The stencil write geometry reuses `loopToMesh()` logic from `CoastlineMesh.ts` (Y-flip and winding already correct).

Two critical implementation details uncovered by research: (1) Three.js `WebGLRenderer` defaults `stencil: false` — `HexSceneSetup.ts` MUST pass `{ stencil: true }` or the stencil buffer will not exist at all; (2) the stencil write material should use `AlwaysStencilFunc` + `ReplaceStencilOp` for all three stencil op slots (fail/zfail/zpass) so stencil ref=1 is written regardless of depth.

**Primary recommendation:** Add `stencil: true` to the WebGLRenderer constructor first — all other work depends on this. Then split the fill mesh, then wire the stencil write pass, then re-enable `createCoastlineMesh` with the stencil approach.

### Pattern 2: Stencil Write Material (Pass 0)

**What:** Invisible geometry that writes stencilRef=1 inside the land contour boundary.
**When to use:** Pass 0 — must run before any stencil-tested geometry.

```typescript
// Source: verified against three@0.183.2 Material stencil properties
const stencilWriteMaterial = new THREE.MeshBasicMaterial({
  colorWrite: false,                    // Invisible — writes nothing to color buffer
  depthWrite: false,                    // Don't affect depth buffer
  stencilWrite: true,                   // Write to stencil buffer
  stencilWriteMask: 0xFF,
  stencilFunc: THREE.AlwaysStencilFunc, // Always pass — always write
  stencilRef: 1,                        // Write value 1
  stencilFuncMask: 0xFF,
  stencilFail: THREE.ReplaceStencilOp,  // Replace stencil on all outcomes
  stencilZFail: THREE.ReplaceStencilOp,
  stencilZPass: THREE.ReplaceStencilOp,
  side: THREE.DoubleSide,
  depthTest: false,
});
// renderOrder = RENDER_ORDER.HEX_FILL - 1 (i.e., -1)
```

### Pattern 3: Land InstancedMesh with Stencil Test (Pass 1)

**What:** Land hexes only render where stencil buffer = 1.
**When to use:** Pass 1 — after stencil write.

```typescript
// Source: verified three@0.183.2 InstancedMesh + material stencil properties
const landMaterial = new THREE.MeshBasicMaterial({
  vertexColors: false,
  stencilWrite: false,

The fog system (`buildOriginalColorCache`, `updateFogColors`) references `fillMeshRef.current` — this needs to be updated to reference both meshes. ### Anti-Patterns to Avoid

- **Not enabling stencil in renderer:** The single most likely failure mode. If `stencil: true` is missing from `WebGLRenderer` constructor, all stencil operations silently do nothing — land hexes render as full hexagons.
- **Using `NotEqualStencilFunc` on water mesh:** Water hexes should render with NO stencil test, not `NotEqualStencilFunc`. Stencil-testing water adds fragility (stencil clear order, lakes).
- **Setting stencil write mesh `transparent: true`:** Not needed. `colorWrite: false` with `depthTest: false` is sufficient. Forcing transparent puts the mesh in the transparency render queue which has different sorting behavior.
- **Wrong renderOrder for stencil write:** Stencil write MUST have lower renderOrder than land hexes. Use `RENDER_ORDER.HEX_FILL - 1` = -1. If the stencil write renders after the land hexes, land hexes see stencil=0 and are culled entirely.
- **autoClearStencil interference:** Three.js defaults `autoClearStencil: true` — the stencil buffer is cleared before each frame, which is correct behavior here. Do not set `renderer.autoClearStencil = false`.
- **Forgetting to add stencil write mesh to scene:** The stencil write geometry must be in the scene to be rendered. It is invisible (colorWrite: false) but must be present.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Land/water contour shape | Custom polygon triangulator | `THREE.ShapeGeometry` via existing `loopToMesh()` | Verified handles 5000+ point polygons without earcut failure |
| Hex geometry | Custom vertex buffer | `buildHexGeometry()` (existing) | Shared, tested, correct |
| Water terrain classification | Inline terrain checks | `isWaterTerrain()` from `coastline.ts` | Canonical — already used for scalar field |
| Loop Y-flip + winding | New conversion logic | Existing `loopToMesh()` in `CoastlineMesh.ts` | Already handles Y-flip and CCW winding correctly |
| Stencil constant values | Magic numbers | `THREE.AlwaysStencilFunc`, `THREE.EqualStencilFunc`, `THREE.ReplaceStencilOp`, `THREE.KeepStencilOp` | Named constants, verified in three@0.183.2 |

**Key insight:** ShapeGeometry triangulates simple polygons without holes. The previous approaches failed because they tried to cut holes in larger shapes. The stencil approach avoids holes entirely — each loop is a simple filled shape, which ShapeGeometry handles at any point count.

## Common Pitfalls

### Pitfall 1: stencil: false in WebGLRenderer
**What goes wrong:** No stencil buffer exists. All stencil operations are no-ops. Land hexes render as full hexagons, identical to before.
**Why it happens:** Three.js defaults `stencil: false` to save VRAM on hardware where stencil isn't needed.
**How to avoid:** Pass `stencil: true` in `createHexScene()` → `new THREE.WebGLRenderer({ canvas, antialias: true, stencil: true })`.
**Warning signs:** Land hexes show full hexagonal shape at coast instead of organic clip.

### Pitfall 2: renderOrder -1 for stencil write mesh
**What goes wrong:** If stencil write mesh renders AFTER land hexes (same or higher renderOrder), the stencil buffer is 0 when land hexes are drawn → entire land InstancedMesh invisible.
**Why it happens:** renderOrder must be strictly lower than the stencil-tested geometry.
**How to avoid:** Set stencil write mesh `renderOrder = RENDER_ORDER.HEX_FILL - 1` = -1. Add a named constant: `RENDER_ORDER.STENCIL_WRITE = -1`.
**Warning signs:** All land hexes disappear — black map except water.

### Pitfall 3: Fog system referencing the old single fillMesh
**What goes wrong:** `buildOriginalColorCache` and `updateFogColors` in `FogCulling.ts` and `HexMapV2.tsx` reference a single `fillMeshRef.current`. After splitting, the ref points to only one mesh.
**Why it happens:** The fog system was built assuming one InstancedMesh for all hexes.
**How to avoid:** Update `fillMeshRef.current` logic to store/use both `landMeshRef` and `waterMeshRef`. The fog effect needs to call color updates on both. Water hex fog should show dark regardless of stencil state.
**Warning signs:** Fog of war stops working — explored hexes don't dim, or land hexes don't darken.

### Pitfall 4: updateHexColors called on wrong mesh subset
**What goes wrong:** `updateHexColors(landMesh, allTiles, seed)` iterates all tiles but the land InstancedMesh only has N_land instances. Instance indices misalign.
**Why it happens:** Instance index i in the land mesh corresponds to land tile i, not tile i of the full array.
**How to avoid:** Build explicit index maps during `createHexFillMesh`. Store `landTileIndices: number[]` and `waterTileIndices: number[]` in the return value for use by update functions.
**Warning signs:** Land hex colors are wrong — tiles show wrong terrain colors, or array out-of-bounds.

### Pitfall 5: Threshold too high — land hexes not fully inside stencil contour
**What goes wrong:** The land contour threshold (0.35) means the contour boundary sits just inside the outer land hex edge. Some land hex pixels near the coast fall outside the stencil region and are clipped.
**Why it happens:** Metaball scalar field threshold of 0.35 doesn't extend the contour far enough past the outer hex edges.
**How to avoid:** Lower threshold to ~0.30. The CONTEXT.md decisions flag this explicitly. Make it a named constant: `STENCIL_THRESHOLD_OVERRIDE`.
**Warning signs:** Coastal land hexes appear to have missing corners or edges; organic line cuts through interior of the first land row rather than just the outermost edge.

### Pitfall 6: Lake hexes classified as land
**What goes wrong:** `isWaterTerrain('lake')` returns `true`, but lakeIds override — hexes with `lakeId >= 0` should go in water mesh even if their terrain type is something else.
**Why it happens:** Lake hexes sometimes have terrain type 'lake', sometimes not (classified during worldgen). The canonical lake classifier is `lakeId >= 0`, not `terrain === 'lake'`.
**How to avoid:** In the split logic: `if (isWaterTerrain(tile.terrain) || (lakeIds && lakeIds[i] >= 0))` → water mesh. This mirrors the existing `getHexColor` priority logic.
**Warning signs:** Lake hexes appear inside the organic land boundary, cutting holes in the stencil region.

## Open Questions

1. **Exact threshold value for stencil contour**
   - What we know: CONTEXT.md suggests lowering from 0.35 to ~0.30. The contour must fully enclose all land hex interiors.
   - What's unclear: The exact threshold depends on hex size (10 units) and blobRadius (1.8 × hexSize = 18 units). No definitive value without visual verification.
   - Recommendation: Define as a named constant `STENCIL_THRESHOLD = 0.30`. Make it easy to tune. The implementer should visually verify at ~300px/hex zoom that land hex edges are cleanly clipped.

2. **FogCulling integration with split mesh**
   - What we know: `buildOriginalColorCache` and `updateFogColors` in `FogCulling.ts` operate on a single InstancedMesh. `HexMapV2.tsx` stores `fillMeshRef.current`.
   - What's unclear: The cleanest refactor path — update FogCulling to accept `{ landMesh, waterMesh }`, or maintain two separate refs in HexMapV2.tsx and call fog updates twice.
   - Recommendation: Two separate refs (`landMeshRef`, `waterMeshRef`) in HexMapV2.tsx. Call fog update logic for each. This avoids changing FogCulling.ts signatures and keeps Phase 07.1 scope tight.

3. **updateHexColors index mapping**
   - What we know: The fog system calls `updateHexColors` (or equivalent) to darken/restore fog-state colors. After splitting, tile indices in land/water meshes differ from global tile indices.
   - What's unclear: Whether the fog system needs to know which tiles are land vs water, or whether it can call existing updateHexColors with the full tiles array on each mesh (which would fail on index count mismatch).
   - Recommendation: `createHexFillMesh` returns `landTileIndices: number[]` and `waterTileIndices: number[]` alongside the meshes. The fog system uses these to route color updates correctly.
