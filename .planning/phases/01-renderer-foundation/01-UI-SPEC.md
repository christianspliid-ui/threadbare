# Phase 1 — UI Design Contract: Renderer Foundation

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase scope:** Three.js orthographic renderer displaying a 200×300 hex grid (60K hexes) at 60fps, with correct Tait-derived terrain colors, thin grid lines, camera controls (pan/zoom/jump-to), and an HTML tooltip overlay. This is a canvas-first phase — the dominant visual surface is the Three.js canvas, not React UI chrome.

## Copywriting Contract

Phase 1 introduces one HTML overlay component (tooltip) and one implicit empty/error state. There are no destructive actions in this phase.

| Element | Copy | Notes |
|---------|------|-------|
| Tooltip — terrain name | `{terrain_type_label}` | Display name, not enum key. e.g. "Temperate Forest" not "temperate_forest". Title case. |
| Tooltip — coordinates | `({col}, {row})` | Compact. e.g. "(47, 132)". Below terrain name. |
| Tooltip — water hex | `{water_type_label}` | e.g. "Ocean", "Shallow Waters", "Deep Ocean", "Lake", "River". No coordinate override. |
| Empty state — no world loaded | "The world has not yet been shaped." | Shown if grid data is absent. Italic, `--text-tertiary`, `animate-breathe`. |
| Error state — renderer failure | "The map refuses to render. Check the console." | Shown if Three.js initialization fails. Plain text, `--negative` color. Not themed prose — clarity over fiction for a technical error. |
| Primary CTA | Not applicable | Phase 1 has no user-initiated action buttons. Camera controls are gestural, not button-driven. |
| Destructive confirmation | Not applicable | No destructive actions in this phase. |

**Copywriting rules from `Docs/ui-patterns.md` §14 (empty states):**
- Always italic
- Use `var(--text-tertiary)` — present but not demanding attention
- Apply `animate-breathe` (slow opacity pulse)
- Copy stays in the game fiction ("The world has not yet been shaped" — not "No data available")

## Interaction Contract

These are the interaction behaviors for the Three.js canvas surface.

### Camera Controls

| Gesture | Behavior | Source |
|---------|----------|--------|
| Drag (mouse/touch) | Pan map. d3-zoom drives OrthographicCamera. | CONTEXT.md decision |
| Scroll wheel | Zoom in/out. Continuous, no tier snapping. | CONTEXT.md decision |
| Pinch (touch) | Zoom in/out. d3-zoom pinch normalization. | CONTEXT.md decision |
| `centerOn(hexCoord)` API call | Smooth fly-to animation, ~500ms, ease-in-out quad. | CONTEXT.md decision |
| Edge-of-screen | No edge-pan. Drag only. | CONTEXT.md decision (sidebar conflict prevention) |
| Double-click | No action (not used). | CONTEXT.md decision |

**Zoom range:** `scaleExtent([MIN_ZOOM, MAX_ZOOM])` spanning ~30x (full-world ~10px/hex to hero-local ~300px/hex). Speed tuning is Claude's discretion.

### Hex Interaction

| Event | Behavior | Source |
|-------|----------|--------|
| Click hex | Fire `onHexClick(hexCoord)` callback prop. Outlines selected hex with gold/white ring. | CONTEXT.md decision |
| Hover hex | Show HTML tooltip (terrain name + coordinates). Apply subtle hover highlight to hex. | RNDR-05, CONTEXT.md |
| Hover off hex | Hide tooltip. Remove hover highlight. | |

**Raycasting:** Click/hover translate via Three.js `Raycaster` from mouse screen coords to hex world coords. Implementation detail left to executor.

### Tooltip Behavior

- Positioned via `Vector3.project(camera)` — world space to screen coordinates.
- Absolute-positioned React `<div>` overlaid on canvas.
- Appears on hover, disappears when cursor leaves hex region.
- No animation on show/hide (instantaneous) — tooltip is a data readout, not a dramatic element.
- Clamp to canvas bounds: tooltip must not overflow the map panel edges.
- Z-index above the canvas, below modal overlays.

### Component Interface Contract

`HexMapV2` component MUST expose the same interface as the existing `HexMap` component (`HexMapProps` + `HexMapHandle`) for drop-in swap in Phase 8. This is a hard requirement from CONTEXT.md.

Key props (match existing `HexMap.tsx`):
- `onHexClick: (coord: HexCoord) => void`
- `onHexHover: (coord: HexCoord | null) => void`
- `selectedHex: HexCoord | null`
- Imperative handle: `centerOn(coord: HexCoord, zoom?: number): void`

## Layout Contract

**Viewport:** 1920×1080 (primary target per STYLE.md). Nothing scrolls. `html, body, #root` enforce `height: 100dvh; overflow: hidden`.

**Route:** `?view=hexv2` — new Three.js renderer route alongside existing `?view=game`. Full game chrome from day one: topbar + left sidebar + center canvas + right sidebar.

**Center panel (canvas area):**
- Width: viewport width minus both sidebar widths (currently one sidebar at 280px, plus any left panel)
- Height: viewport height minus topbar height (44px at 1080p)
- Canvas fills 100% of center panel — no internal padding, no scrolling
- Canvas resize: `ResizeObserver` on the container div; renderer resizes canvas and updates camera frustum on container size change

**Overlay layer order (Z-axis, lowest to highest):**
1. Three.js canvas (base)
2. Hex tooltip HTML overlay (above canvas, below panels)
3. Existing sidebar panels (standard game chrome z-order)
4. Modals / full-screen overlays (existing z-order)
