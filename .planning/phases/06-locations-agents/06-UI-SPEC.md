## Typography

### UI Layer (HTML overlays — location labels, count badges)

| Role | Size | Weight | Font | Line Height | Usage | Source |
|------|------|--------|------|-------------|-------|--------|
| Capital label | 13px | 700 | Cinzel | 1.2 | Capital and city location names | CONTEXT.md: font size scales by importance |
| City/town label | 11px | 400 | Cinzel | 1.2 | Town, castle, fort, temple names | CONTEXT.md: importance-based; weight differentiation via size, not boldness |
| Small location label | 9px | 400 | Cinzel | 1.2 | Hamlet, shrine, camp, ruins, mining, battleground names | CONTEXT.md: importance-based; 9px gives 4px separation from city label |
| Count badge | 10px | 700 | Alegreya Sans | 1.0 | Agent count badge (>4 per hex at regional zoom) | RESEARCH.md: AGNT-02 |

Cinzel weight set: **400 (regular)** and **700 (bold)** only. Two weights maximum. Hierarchy between capital (bold, 13px), city/town (regular, 11px), and small (regular, 9px) is communicated through size alone — no intermediate weight.

Note: These sizes apply to HTML overlay elements (`LocationLabelOverlay.tsx`). Three.js CanvasTexture labels are rasterized at a fixed canvas resolution and scale with the camera — not subject to CSS font tokens.

```
  1px 0 0 rgba(240,235,220,0.9),
  -1px 0 0 rgba(240,235,220,0.9),
  0 1px 0 rgba(240,235,220,0.9),
  0 -1px 0 rgba(240,235,220,0.9),
  2px 0 0 rgba(240,235,220,0.6),
  -2px 0 0 rgba(240,235,220,0.6)
```

Source: CONTEXT.md (LOCI-04) + REQUIREMENTS.md (LOCI-04): "Black text with white halo for readability against all terrain colors." Reuse existing `LAND_HALO` constant from `RegionLabelOverlay.tsx`.

## SVG Art Direction Contract

All location icons and activity indicator sprites must conform to the hand-drawn silhouette standard established in Phase 5.

### Style standard

- Color: `#1a1a1a` (not pure black — matches terrain signifiers)
- Shadow technique: sun-from-right baked into SVG path shapes (not CSS drop-shadow)
- Layering: 2–4 path layers per icon, each at distinct opacity (0.2, 0.4, 0.65, 1.0)
- Paths: organic/irregular — no perfectly circular arcs, no mechanical precision
- ViewBox: normalized square (e.g. `0 0 100 100` or `0 0 120 120`)
- No strokes — filled paths only
- No gradients — flat fills at varying opacity only

Source: CONTEXT.md "same hand-drawn silhouette treatment as terrain signifiers", canonical refs to `Design/deepforest-hand-drawn.svg`, `Design/hills-hand-drawn.svg`, `Design/mountain-hand-drawn.svg`, `Design/steppes-hand-drawn.svg`.

### Ruin icon design rule

Ruin variants (ruined_city, ruined_tower, ruined_village) must appear as crumbled/broken versions of their intact counterparts — not generic rubble. A ruined_city reads as a collapsed castle; a ruined_tower reads as a broken tower. Source: CONTEXT.md.

## Interaction Contract

Phase 6 is a visual rendering phase. No user interactions are wired in this phase (click events, hover open panels, etc. are Phase 8 scope). The following passive behaviors apply:

| Behavior | Description |
|----------|-------------|
| Hover tooltip (existing) | Existing hex raycaster tooltip (Phase 1) continues to show hex coordinates and terrain. Location presence is NOT added to tooltip in Phase 6. |
| pointer-events: none | All HTML overlay elements (LocationLabelOverlay, count badges) must have `pointer-events: none`. Same pattern as RegionLabelOverlay. |
| COMP-04 suppression | Major locations (capital, city, town, castle) suppress terrain signifiers on their hex. This is already enforced by compositionResolver. Phase 6 only needs to register location entities with correct priority. |
