## Decisions Made

- phaseLairEscalation uses the same in-place mutation pattern as phaseBattleDetection and phaseFactionAmbitions. This is consistent with TB-073 phases and avoids refactoring the caller.
- Sphere pressure is emitted to the lair node itself (not a separate hex node). The lair IS a location entity in the graph; phaseSpherePressure resolves the accumulated events downstream at phase 6.639.
- A `tick === 0` guard was added to prevent the escalation from running on the initialization tick, which would erroneously process all freshly-seeded lairs.
- `emitTrace` uses `category: 'faction_ambition'` with a summary field because the `trace.ts` TraceEntry discriminated union is truncated (ends with `| HiddenSi`). Adding a 'lair' category would require extending the truncated union — deferred to when trace.ts is completed.
- Minor→major and major→legendary upgrades use `continue` after the minor upgrade, ensuring one tier per escalation tick. This prevents a lair from jumping directly to legendary on a single run.
