**Sphere tinting for lair icons (Claude's discretion — derived from STYLE.md + tokens.md):**

Lair icons on the hex map use the existing `LocationIconMesh` SVG silhouette system. Standard icons render as near-black (`#1a1a1a` fill). Lair icons deviate by receiving a sphere-colored tint via a canvas color overlay applied at texture build time. The tint replaces the silhouette fill color with a darkened version of the dominant sphere color. This creates readable sphere identity without violating the Threadbare "dark world, hidden magic" principle.

| State | Fill color | Outline |
|-------|-----------|---------|
| Active lair | Darkened dominant sphere color (30% lightness, 80% saturation) | `#0a0a0a` outline (existing LOCATION_OUTLINE_COLOR) |
| Cleared lair | `#2a2520` (desaturated, near `--border-subtle`) | `#0a0a0a` |

Sphere color darkening formula: take the sphere's base hex color from `tokens.md §Sphere Colors` and clamp lightness to 30–35% in HSL. Example: Force sphere (`#ff4444`) → lair fill `#5c1010`. This keeps the icon readable as a silhouette at small hex sizes while communicating sphere identity.

Sphere color reference (base colors from `tokens.md`):
- Force `#ff4444` → lair fill `#5c1010`
- Matter `#8b6b4a` → lair fill `#3d2f1f`
- Energy `#ffd700` → lair fill `#5c4e00`

## Lair Icon SVG Design Contract

Lair icons use the existing `LocationIconDef` shape (`paths`, `viewBox`, `sizeClass`). New entries added to `locationIconRegistry.ts`.

### `lair` (active)

- **sizeClass:** `small` — same tier as `camp` and `mining`. Minor lairs are small; major lairs use `medium`; legendary lairs use `full`.
- **viewBox:** `0 0 100 100` (matching existing registry convention)
- **Shape:** Cave entrance silhouette — a jagged downward arch (stalagmite teeth at top, stalactite teeth at bottom) with a dark void interior. The arch implies an opening into the earth. Style matches existing icon set: organic hand-drawn paths, multi-layer opacity, minimal internal detail.
- **Paths:** 2 layers — outer cave arch (opacity 1.0) + inner void fill (opacity 0.7). Same multi-layer compositing as existing icons.
- **Size classes by tier:**
  - Minor lair: `small` (0.40 × HEX_SIZE)
  - Major lair: `medium` (0.60 × HEX_SIZE)
  - Legendary lair: `full` (0.80 × HEX_SIZE)

### `cleared_lair`

- **sizeClass:** `small` (fixed — cleared lairs shrink)
- **Shape:** Cracked/broken version of the cave arch — a partial arch with a horizontal crack bisecting it. The crack communicates "broken, no longer active."
- **Fill color:** `#2a2520` (desaturated — visually muted relative to terrain). Does NOT receive sphere tint.

### Zoom visibility

Lair icons follow the existing zoom visibility matrix:
- Hidden at full-world zoom (same as `unexplored_poi`)
- Visible at continental and regional zoom
- Fully visible at hero-local zoom

Named elites: render as a distinct `named_elite` icon (crossed-bones or crown variant over a lair icon) when a named elite is attached to a major/legendary lair. Uses `medium` sizeClass.

## Interaction States

All interactions use the existing pattern from `Docs/design-system/interactions.md`.

### Lair hex click (HexMapV2)

- Click a hex with an active lair → HexSidebar updates to show lair details panel (same side-panel pattern as clicking any location hex)
- Lair panel shows: lair name, tier badge, sphere badge, danger zone, named elite if present
- Hover on lair hex: standard `cursor: pointer` + existing hex highlight

### ActionDrawer targeting

- Monster lairs (location nodes with `locationSubtype: 'lair'`) surface in ActionDrawer's location targeting category
- Named elites (actor nodes with `isMonsterElite: true`) surface in ActionDrawer's actor targeting category
- No UI changes to ActionDrawer itself — the existing context filter handles new node types. This phase adds no new ActionDrawer UI components.

### HexSidebar lair section

When the selected hex has an active lair:
- Section header: `"MONSTER LAIR"` — `--text-xs`, uppercase, `--text-tertiary`, letter-spacing 0.12em, `--font-display`
- Lair name row: `--text-sm` (17px), `--font-display`, `--text-primary`
- Tier badge: inline chip — text `"MINOR"` / `"MAJOR"` / `"LEGENDARY"`, `--text-xs`, background `--bg-raised`, border `--border-subtle`. Legendary tier uses `--accent-gold` border.
- Sphere badge: inline chip with sphere color dot + sphere name, same pattern as existing sphere chips in AgentInfoCard
- Named elite row (if present): `--text-sm`, `--font-display`, `--text-secondary`, prefixed with "Elite:" label in `--text-tertiary`
- Threat message (if lair is attacking nearby settlements): `--text-xs`, `--negative`, italic — matches existing threat text conventions

### Monster faction in ArmiesTab

Monster factions (`isMonsterFaction: true`) are filtered OUT of the player-facing ArmiesTab and faction list panels. They do not appear as recruitable or manageable factions. This filtering is a UI behavior contract — the planner must task this explicitly.

If a monster army is in battle with a player-aligned army, it appears in battle resolution UI with a skull-prefixed faction name indicator (`--negative` color).

## Debug Panel Contract

New trace category `'lair'` must appear in the debug panel trace list. Lair traces are emitted by `phaseLairEscalation` and `seedMonsterLairs`.

Trace entries to display:
- `lair_seeded` — hex, sphere, danger zone, tick
- `lair_upgraded` — lair ID, old tier, new tier, tick
- `lair_spawned` — parent lair ID, new lair hex, sphere, tick
- `lair_cleared` — lair ID, faction who cleared it, tick
- `lair_reinfested` — lair ID, sphere, tick

These follow the existing DebugPanel trace format — no new debug UI components needed. The planner should task "verify lair traces appear in DebugPanel" as part of wave 3 integration.

## HexChronicle Lair Entry Format

When a lair hex is selected and the HexChronicle panel renders:

**Header section:**
- Region breadcrumb: existing pattern unchanged
- Lair name as location heading: `--text-lg`, `--font-display`, `--text-primary`
- Tier + sphere badges: inline chips, `--text-xs`

**Body sections (in order):**
1. "THREAT LEVEL" section — danger zone, tier description, named elite if present
2. "SPHERE INFLUENCE" section — sphere identity, local sphere pressure reading
3. "RECENT EVENTS" section — lair trace chronicle entries (same format as existing event log)
4. "AVAILABLE ACTIONS" section — ActionDrawer cards filtered for this lair node

Each section uses the existing `.section-heading` utility class for the header label.
