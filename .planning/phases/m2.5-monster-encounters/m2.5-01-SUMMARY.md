## Decisions Made

- Lairs use the existing `location` graph node type with `locationSubtype='lair'` rather than a new node type. This satisfies the architectural rule against new node types without verification and follows the existing location pattern.
- `dominantSphere` is derived from terrain at seeding time via `seedHexSphereAffinity` rather than reading sphereAffinity from the graph (which isn't available on hex tiles). This is correct because lair seeding runs during worldgen before the sphere-to-graph wiring is complete.
- `emitTrace` was not called in lairSeeding.ts to avoid touching `src/types/trace.ts` which ends with a truncated `| HiddenSi` union (pre-existing issue). Trace emission can be added when trace.ts is completed in a future plan.
- `provinceRoles` added to `WorldGenResult` interface so lairSeeding can access danger zone data without requiring the caller to pass extra parameters beyond the worldGenResult.
- Wilderness zone: any province role value outside 0-2 (the defined PROVINCE_ROLE_* constants) is treated as wilderness. This is the correct fail-safe: unassigned hexes default to highest danger.
