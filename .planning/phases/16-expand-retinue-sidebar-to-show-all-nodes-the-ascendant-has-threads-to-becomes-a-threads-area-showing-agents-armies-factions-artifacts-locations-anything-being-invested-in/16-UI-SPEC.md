## Spacing Scale

All values are multiples of 4px. Tokens are already declared in `src/index.css` as `--space-*` variables. This phase uses the subset below.

| Token | Value | CSS Var | Phase Usage |
|-------|-------|---------|-------------|
| xs | 4px | `--space-1` | Icon gaps within compact rows; left border gap |
| sm | 8px | `--space-2` | Compact row horizontal padding; icon-to-label gap |
| md | 16px | `--space-4` | Section header padding; detail view internal padding |
| lg | 24px | `--space-6` | Between section groups in ThreadsPanel |
| xl | 32px | `--space-8` | Detail view top-of-panel padding |

Exceptions:

- **Compact row height target: 40px** — achieved via `py-1` (4px top/bottom) + two text lines at `--text-xs` with `leading-tight`. This is by design — not a spacing token violation. Source: CONTEXT.md "25% of current card height" + RESEARCH.md Pattern 2.
- **Left tier border stripe: 3px** — matches existing RetinuePanel pattern. Not a spacing token; it is a border-width value.
- **Detail view width: `clamp(240px, 280px, 30vw)`** — responsive cap prevents viewport overflow at 1440px. Source: RESEARCH.md Pattern 3 + Pitfall 3.

## Typography

Three sizes in use for this phase. The scale steps from 16px to 18px to 21px — each step is 2–3px, enough for clear role differentiation when combined with weight contrast (400 vs 700) and font-family contrast (Cinzel vs Alegreya Sans).

**Weights declared: 400 (regular) and 700 (bold) only.**

| Role | Size | CSS Var | Weight | Line Height | Usage |
|------|------|---------|--------|-------------|-------|
| Row name | 16px | `var(--text-xs)` | 700 (bold) | 1.2 (tight) | Entity name in compact thread row — weight contrast over secondary line creates hierarchy within the tight row |
| Row secondary | 16px | `var(--text-xs)` | 400 (regular) | 1.2 (tight) | Secondary info line in compact row (location, type info) — same size as name, weight 400 creates subordination |
| Panel heading | 16px | `var(--text-xs)` | 700 (bold) + uppercase | 1 | Section group headers via `.section-heading` class |
| Detail body | 18px | `var(--text-base)` | 400 (regular) | 1.5 | Detail view field values (capabilities, sphere, status) |
| Panel title | 21px | `var(--text-lg)` | 700 (bold) | 1.2 | "Threads" panel title at top of ThreadsPanel |

**Size steps:** 16px (row content + section headings) → 18px (detail body) → 21px (panel title). Each step is meaningful: +2px between detail body and row content, +3px between panel title and detail body.

**Within-row hierarchy:** Row name and secondary share 16px but differ by weight (700 vs 400). This is intentional — compact rows are too small for a size step; weight is the differentiator. Name reads first due to bolder stroke.

**Fonts:**
- Entity names, section headings, and panel title: `var(--font-display)` (Cinzel)
- Secondary info and detail body: `var(--font-body)` (Alegreya Sans)

Source: `src/index.css` type scale + existing RetinuePanel/AgentInfoCard patterns. Revised 2026-03-30: removed weight 500; resolved 16/17/18 scale into 16/18/21 with clear role assignment.

## Layout Contract

### Right sidebar area — restructured

The current pattern (`agentInfoCard ? <AgentInfoCard /> : <RetinuePanel />`) is **replaced** with a side-by-side flex layout.

```
[GameView right edge]
┌─────────────────────────────────────────────────────────┐
│  ← detail view (280px, own scroll)  │ sidebar (280px)   │
│  AnimateMount anim-fade             │ ThreadsPanel      │
│  ThreadDetailView                   │ overflow-y-auto   │
└─────────────────────────────────────────────────────────┘
```

- **Wrapper:** `<div className="flex flex-shrink-0" style={{ alignItems: 'stretch' }}>` — no position:absolute on detail view
- **Detail view:** `width: clamp(240px, 280px, 30vw)` — caps at 30vw to prevent overflow at 1440px
- **Sidebar:** `width: var(--sidebar-width)` — unchanged from current (280px/360px/400px/420px at breakpoints)
- **Viewport total at 1920px:** `360px (sidebar) + 280px (detail) = 640px` — leaves 1280px for map at 1920px. Safe.
- **Detail view render:** Sibling to sidebar `<div>`, NOT child. Sidebar has `overflow-y-auto`; detail view has its own `overflow-y-auto`. Neither scrolls the other.

Source: RESEARCH.md Pattern 3 + Pitfall 1 + Pitfall 3.

### ThreadsPanel internal layout

```
ThreadsPanel (full height, overflow-y-auto)
  ├── Panel title "Threads" [21px, weight 700, Cinzel]
  ├── SectionHeading "Agents" count={n}           [always expanded by default]
  │   ├── CompactThreadRow (agent) × n
  │   └── [collapsed state: header only, chevron]
  ├── SectionHeading "Locations" count={n}        [collapsed by default if n > 0]
  │   └── CompactThreadRow (location) × n
  ├── SectionHeading "Factions" count={n}         [collapsed by default if n > 0]
  │   └── CompactThreadRow (faction) × n
  ├── SectionHeading "Armies" count={n}           [collapsed by default if n > 0]
  │   └── CompactThreadRow (army) × n
  └── SectionHeading "Artifacts" count={n}        [collapsed by default if n > 0]
      └── CompactThreadRow (artifact) × n
```

**Collapse/expand state:** Local `useState` per section — not persisted. Agents section defaults open; all others default collapsed. Source: RESEARCH.md Open Question 4.

**Empty sections:** Sections with `count === 0` are hidden entirely (not rendered as empty headers).

### CompactThreadRow anatomy

```
┌─[3px tier stripe]─────────────────────────────────────┐
│  Name (truncated, 16px weight 700)         [eye icon]  │  ~20px
│  Secondary info (truncated, 16px weight 400)           │  ~16px
└────────────────────────────────────────────────────────┘
total height: ~40px including 4px top/bottom padding
```

- **Tier stripe:** `borderLeftWidth: '3px'`, `borderLeftColor: TIER_COLORS[tier] || TIER_COLOR_DEFAULT`
- **Background:** `var(--bg-raised)` default, `var(--bg-hover)` on hover, `ring-2 ring-amber-400/60` when selected
- **Name:** `var(--font-display)`, `var(--text-xs)`, weight 700, truncate
- **Secondary:** `var(--font-body)`, `var(--text-xs)`, weight 400, `var(--text-tertiary)`, truncate
- **Eye icon:** `IconButton` right-aligned, `onClick: onCenterOnMap`, stops event propagation

**Per-type secondary info:**

| Type | Secondary info |
|------|----------------|
| Agent | Location name + activity label (e.g., "Thornwall · Recruiting") |
| Location | Controlling faction name + prosperity level (e.g., "Ironhold · Prosperous") |
| Faction | Territory count + sphere alignment (e.g., "7 hexes · Flesh sphere") |
| Army | Strength + objective (e.g., "240 strong · Marching north") — from `armyState.size` + `armyState.objective` |
| Artifact | Bearer name or location (e.g., "Carried by Seraphel" or "In Thornwall vaults") |

Source: CONTEXT.md per-type decision data + RESEARCH.md Pattern 5.

## Interaction Contract

| Trigger | Response | Notes |
|---------|----------|-------|
| Click compact row | Opens ThreadDetailView for that node; row enters selected state (gold ring) | Does NOT center map |
| Click eye icon on row | Centers + zooms map to entity's hex | Stops row click propagation |
| Click ✕ in detail view | Closes detail view; row deselects | |
| Click section header | Toggles section collapse/expand | Local state only |
| Click "View Full Profile" in detail view | Opens stub profile modal for node type | Modal via Modal shared component |
| Press Escape | Closes detail view (if open) | Handled by GameView |
| Click thread-creation action card | Executes thread-creation action via ActionDrawer | Existing Generalized Action Targeting flow |

**State model in GameView:**

Replace current `selectedAgentId: string | null` with a discriminated union:
```typescript
type SelectedThread =
  | { nodeId: string; category: 'agent' }
  | { nodeId: string; category: 'location' }
  | { nodeId: string; category: 'faction' }
  | { nodeId: string; category: 'army' }
  | { nodeId: string; category: 'artifact' }
  | null;
```

Route `category === 'agent'` to existing agent detail builder; all others to new lightweight per-type detail builders. Source: RESEARCH.md Pitfall 4.

## Viewport Contract

This phase modifies the right sidebar region of the viewport-locked game layout. All rules from CLAUDE.md apply:

- `html, body, #root` remain `height: 100dvh; overflow: hidden` — untouched
- Detail view uses flex layout (not position:absolute) — participates in normal flow, cannot cause horizontal overflow beyond the flex container
- At 1920px: sidebar 360px + detail view 280px = 640px total right panel. Map retains 1280px. Safe.
- At 1440px: sidebar 280px + detail view capped at `30vw = 432px`. Exceeds safe threshold — detail view width floors at 240px via `clamp(240px, 280px, 30vw)`. Map retains 920px minimum. Acceptable.
- Stub modals use `Modal` shared component — `max-height: 85vh` already enforced.
- Detail view must be a **sibling** of the sidebar div, not a child — to avoid participating in sidebar's `overflow-y-auto` scroll context. Source: RESEARCH.md Pitfall 1.

## Accessibility Contract

- All compact rows: `role="listitem"` inside `role="list"` wrapper (existing pattern from RetinuePanel)
- Section headers: rendered as `<h3>` via `SectionHeading as="h3"` (default)
- Eye icon buttons: `aria-label="Center map on {entity name}"` — unique per row
- Detail view close button: `aria-label="Close detail"`
- Selected row: `aria-selected="true"` on the selected `listitem`
- Stub modals: `aria-label="{Entity Name} profile"` on Modal — uses existing Modal `aria-label` prop
- Keyboard: Escape closes detail view; Tab navigates through interactive elements in reading order
