2. **THR-75 worktree-path conflict — Edit/Write calls silently landed in wrong worktree (#137 git-process variant, 2026-05-15).** Scheduled-task pickup created an isolated worktree but the Opus session's Edit/Write absolute paths targeted the home worktree (which had its own dirty state from `christianspliid/thr-409-...`). All THR-75 edits went to the wrong tree; discovered only when `git commit` from the isolated worktree showed `nothing to commit`. Cost: ~30 minutes recovering, including restoring 9 unrelated files from `origin/main` (changelog, project-status, project-history, wiring-checklist, systemic-wiring-guide, several src/types files) before re-applying only the THR-75 deltas. This is a structural ergonomic hazard: the Bash CWD-reset reminder helps `mcp__workspace__bash` calls but Edit/Write tools take absolute paths verbatim and do not honor CWD. *Next step:* see Consented Experiment #2 — add a path-guardrail warning to `pull-work` SKILL.md.

3. **Pre-commit-hook M-file drop (#138, 2026-05-15).** After `git commit` failed on the skill-sync pre-commit hook and was re-run, only the new files (`A`) were captured — modified files (`M`) were silently dropped from the index by the hook's defensive behaviour. Required a `git commit --amend` round-trip with re-staged M files. Cost ~10 minutes. Small but recurring class — same THR-75 session, paired with #137 above. The workaround is "do the `:sync` BEFORE the initial `git add`" so the hook never needs to fire defensively. *Next step:* see Consented Experiment #3 — document this sequence in `pull-work` SKILL.md as a hard rule, not an optional tip.
