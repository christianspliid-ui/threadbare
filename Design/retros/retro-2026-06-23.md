## Workflow observations

- **Queue imbalance is the live problem.** Cowork's design-and-handoff throughput is high, but it is feeding `Ready for Codex` while Codex is dark (#141). Production into a lane with no consumer isn't progress — it's WIP accumulation. Until the key is set, Cowork should bias mechanical handoffs to `Ready for Dev` (CC lane, which *can* reach Linear) so work doesn't strand. This is a one-line change in Cowork's routing judgment, reversible the moment Codex is unblocked.
- **"This machine" scheduled tasks have no heartbeat.** `weekly-workflow-retro`, `keep-work-flowing`, daily grooming, etc. all run on the user's machine. When it's off, they skip silently — there is no "last-fired-at" marker anywhere a later run can read. The 4-week retro gap is the symptom. A cheap fix: each "This machine" task writes a one-line timestamp to a tracked file on success, so the next retro can detect a dark stretch instead of inferring it.
- **The last retro's biggest fear was a false alarm — and that's a calibration lesson.** It could not tell "everyone OOO" from "automation died" and treated the ambiguity as alarming. The truth was the benign branch (work paused, then resumed hard). Future retros should weight "feature pipeline is visibly active in Linear" as strong evidence against the "automation died" reading before sounding alarms. With Linear reachable this run, that check is now cheap.
- **The cross-executor-collision cluster has gone quiet** (~6 weeks since #134) and the skill-sync CRLF cluster likewise (since THR-420's `.gitattributes`). Two of the most-recurring friction families from spring appear genuinely closed. Worth a formal close next retro rather than carrying them indefinitely.
