## Top 3 impediments this week

1. **`.claude/skills` ↔ `.agents/skills` CRLF/LF drift blocking commits — three hits in 24 hours (#118, #124, #125).** THR-176, THR-292, and THR-360 closeouts each hit the same pre-commit hook failure on 128+ line-ending mismatches. The documented workaround (`npm run check:skill-sync:sync` then bundle the diff into the commit) does *not* stick across executor runs: #125's diagnostic confirms that git's `core.autocrlf` normalizes the staged diff to a no-op, so the mirror commit is silently empty and the `.agents/` working-tree files flip back to CRLF on the next checkout. Each cost roughly 30–45 min of redundant implementation effort and produced an abandoned PR. Linear's `assignee` write is non-atomic, the `model:*` label can route a Codex-handed issue back into CC's queue, and the `In Dev` resume path skips the post-claim shipped-check entirely. The single-day cluster on 2026-05-08 (#121 + #122) was the highest-velocity tax we've paid.
3. **`session-handoff` skill still missing — fourth recurrence (#131, plus #58 / #67 history).** The `keep-work-flowing` and `keep-codex-flowing` scheduled-task SKILL.md files (outside the repo, in the local-agent-mode-sessions config) still instruct Cowork to "Run /session-handoff" after moving an issue to Ready for Dev. ## Workflow observations

- **Shipping velocity is genuinely high.** 50+ issues in 14 days against a backdrop of paid-service blockers all cleared on 2026-04-27 is the strongest week observed. The executor lanes (CC sonnet, CC opus, Codex) are pulling work in parallel and landing it.
- **High velocity multiplied the coordination tax.** Five cross-executor collisions in two weeks vs. one in the prior period. 2026-05-08 alone had two collisions (#121, #122) and three skill-sync drift hits (#118, #124, #125). The same parallelism that produces 50 closures also produces five-figures of wasted CC tokens on redundant work. The collision rate scales with throughput; the mitigations haven't.
- **Linear's `assignee` claim is non-atomic.** Demonstrated definitively by #114 (THR-311 was claim-verified, state confirmed via `get_issue` after `save_issue`, and another worker still shipped first) and #127 (resume-from-In-Dev path entirely bypasses any concurrent-claim guard). The retro-level invariant "claim → exclusive authoring" is broken at the platform level. The mitigation has to be in the executor: shipped-check before commit, not at claim.
- **The `model:*` label and the queue-state can disagree.** #121 (THR-345) is the cleanest example: Cowork handed the issue to Codex via comment, but the issue carried `model:sonnet` which sent CC's lane after the same issue. The label and the queue state must agree on which executor owns the work. This is a Cowork-side discipline gap that compounds the platform-level non-atomicity.
- **Scheduled-task creation from a scheduled-task session is a hard wall.** #90, #111, and #130 all hit the same error. This affects `weekly-retro` (3 cycles missed), `weekly-memory-grooming` (now active via interactive registration in THR-215), and any future cron registration. The constraint is platform-level; the only mitigation is "register in an interactive session."
- **The user-actions.md file (Experiment #1) worked.** Five Christian-owned items resolved on the same day, observable in `Design/user-actions.md` Resolved-this-period block. Of the items that remain, the unresolved Christian-owned set is now smaller and more focused: scheduled-task registration (#111, #130), session-handoff SKILL re-authoring (#67, #131), Slack auth (#131), and the orphan-changes triage (#59). The retro → user-actions board pipeline is the one new thing from last retro that demonstrably shipped value.
- **The Obsidian MCP fallback landed.** vault-log skill now writes to filesystem when MCP is unreachable (#75 et al). This was the right answer to the "auto-start vs filesystem-mount" decision from last retro — the team picked the latter implicitly and the impediment count for that cluster is now lower per occurrence.
- **`drift-scan` integration into the retrospective skill landed (THR-274), but the *scheduled-task* SKILL.md upstream of THIS run still doesn't include the Step 0 drift-scan read.** Same observation as last retro. The scheduled-task SKILL.md is the outside-repo governance artifact that can't self-heal. This is item #5 in the user-actions board and the fix is the same shape as #67 + #131.
