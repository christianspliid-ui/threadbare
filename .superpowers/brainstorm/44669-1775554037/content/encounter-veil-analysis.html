3. The Hard Parts (Risks & Complexity)

Two data paths must become one
TieredEncounterModal builds prose inline from raw EncounterTemplate + WorldGraph (lines 699-722). EncounterStage receives a pre-built EncounterStageModel. The Veil needs one contract. This means either: (a) all encounters go through an adapter, or (b) the Veil accepts both formats.
Mitigation: New buildSimpleEncounterStageModel adapter. One-time work, then all encounters use the same contract.
EncounterStageModel is missing fields the Veil needs
EncounterStageChoiceModel has: id, label, intent, essenceCost, affordable, costLabel, likelyBurden. But the Veil needs: interventionType (supportive/coercive/withdrawn), godVoice, probabilityBoost. These exist on EncounterInterventionChoice but NOT on EncounterStageChoiceModel.
Mitigation: Extend EncounterStageChoiceModel with 3 optional fields. Adapters populate them from source data.
Narration has two different patterns
TieredEncounterModal: NarrateButton uses .chronicle-prose CSS selector via containerRef. EncounterStage: per-paragraph + per-choice buttons with activeNarrationId state. The Veil needs to pick one approach.
Mitigation: Use the EncounterStage pattern (per-paragraph buttons) — more granular, works better with the Veil's floating prose layout.
GameView is 3000+ lines and fragile
The encounter rendering block (lines 2809-2853) depends on shouldUseEncounterStage routing, encounterStageModel memo, and 8+ handler callbacks. Changing this routing is the riskiest edit.
Mitigation: Phase 1 adds the Veil alongside existing modals with a feature flag. Only after validation do we remove old paths.

4. Implementation Phases

Phase 1 — Foundation
Core EncounterVeil + strongly threaded
New EncounterVeil.tsx component. Full-screen overlay, dissolved art, prose renderer, choice blocks with type glow, god-voice reveal. Wire into GameView alongside existing modals (feature-flag or illustration-present gate). Strongly threaded tier only.
Phase 2 — Adapter bridge
buildSimpleEncounterStageModel + model extensions
New adapter for "simple" encounters. Extend EncounterStageChoiceModel with interventionType, godVoice, probabilityBoost. All encounters can now produce a model the Veil consumes.
Phase 3 — All tiers
Lightly threaded + watched + no-art fallback
Auto-resolve timer bar. Peek gate with essence cost. Boost slider. Lighter art treatment for non-strong tiers. Centered content layout for encounters without illustrations.
Phase 4 — Aftermath + narration
Post-resolution view + TTS integration
Aftermath with actor moments, changes, highlights in the dissolved aesthetic. Per-paragraph narration buttons. Aftermath reactions.
Phase 5 — Migration
Route all encounters through EncounterVeil
Remove shouldUseEncounterStage routing. All encounters go through EncounterVeil. Old modals become dead code.
Phase 6 — Cleanup
Delete old modals + update tests
Remove TieredEncounterModal.tsx (973 lines) and EncounterStage.tsx (925 lines). Update/rewrite tests. Net code reduction despite new component.
