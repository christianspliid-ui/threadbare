Divine Premonition System — Approaches

How should Whisper and Compulsion integrate into the tick loop and UI?

A

Hook into existing phase pipeline

Whisper fires as a new sub-phase after idle detection in phaseAgentDecision. Compulsion fires between scoring and commitment — a pause point injected into the existing decision flow.

Pros: Tight integration, no new orchestrator phases. Scoring data already in scope for Compulsion.

Cons: Makes phaseAgentDecision more complex. Both types coupled to one phase.

B

Dedicated orchestrator phase + scoring hook (Recommended)

New phaseDivinePremonition runs before phaseAgentDecision. Checks idle agents for Whisper eligibility, emits premonition events. Compulsion hooks narrowly into phaseAgentDecision between score and commit.

Pros: Clean separation. Whisper is self-contained. Compulsion stays close to scoring data. Easy to test independently.

Cons: Two integration points. Minimal tick overhead.

C

Event-driven with notification queue

Both types emit events into a premonitionQueue on GameState. UI reads the queue and pops modals. No new phase — piggybacks on existing hooks.

Pros: Decoupled. Easy to add new premonition types later.

Cons: Queue management adds state. Risk of stale events if agent state changes between emit and display.

Recommendation: B — Whisper is narratively and mechanically distinct enough for its own phase. Clean boundaries, testable, extensible for future premonition types.
